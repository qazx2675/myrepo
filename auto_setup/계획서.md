## 3. 원 요구사항 (원문 요약 — §8 과 충돌 시 §8 우선)

1. OS 설치 스크립트 실행 시 auto_setup 으로 호스트명(4번째 필드)을 전달. 시점은 (all)yaml 까지 실행된 시점(awx 스크립트 끝나는 시점).
2. 전달 시점엔 ping O → dd 로 ping X → anaconda 진입 ping O (10~20분 ssh 22 refused, 접속되면 `hostname@anaconda`) → 재부팅 ping X → OS 부팅 ping O → 모든 대상 접속 확인 시 체크스크립트 실행. 최초 OS 부팅 후 7분 내 다른 서버가 안 올라오면 부팅불가로 간주하고 부팅된 서버만 설정체크.
3. 툴 서버는 일부 대역 접속 불가 → 모든 대역 접근 가능한 `os6_mgmt` 로 재확인. 필요하면 os6_mgmt 에서 짧은 주기 ping 하는 Go.
4. os_check 비대화형 옵션: user 는 1번에서 전달, 체크 진행 y, 환경설정은 대상에 p/d 로 시작하는 호스트가 하나 이상이면 `set`, 아니면 `y`. 7분 규칙으로 먼저 처리된 서버는 중복 실행 금지, 접속 불가 서버가 나중에 살아나면 재실행.
5. 완료 시 관리서버 모든 접속자에게 메시지: 완료 hostname 가로 출력 + 4자리 code. `auto_setup code NNNN` 으로 알맞은 코멘트 출력.
6. 사용 흐름: `bash 01.AWX_nodeinfo_V2.sh` → auto_setup 전달·내부 과정 → 조건 만족 시 `os_check_final_annotated.sh -auto …` → 메시지.

```

                         │   (데몬이 죽어 있어도 파일은 남음 → cron 이 데몬 기동 후 수거)
                         ▼
[auto_setup daemon]  queue 수거(5초 주기 readdir) → jobs/<jobid>.json
   ① 경로 판별: 로컬 ICMP 로 ping → 응답 없는 호스트는 route=os6 (os6_mgmt 비어 있으면 전부 local)
   ② 감시 루프 (10초 주기)
        local 호스트 : 데몬 raw ICMP
        os6  호스트 : ssh os6_mgmt "<os6_autosetup>/auto_setup probe" 장기 세션 (stdin=목록, stdout=변화)
      ping X 2회 연속 → seen_down=true (설치 시작으로 간주)
   ③ 준비 확인 (30초 주기, 후보만): ping O && (seen_down || 데몬 기동 직후 1회)
        gossh -pm -script -w <후보> "cat /proc/uptime"   (os6 경로는 ssh os6_mgmt "<os6_gossh> …")
        READY = 응답 있음 && anaconda 아님(_os_install 에 없음) && uptime초 < (지금 − 전달시각)
   ④ 실행 시점
        1차: 전부 READY → 즉시 / 아니면 첫 READY + 7분(boot_wait) 이 지나면 READY 인 것만
        늦게 올라온 서버: 첫 늦은 READY + 3분(late_wait) 모아서 1회
   ⑤ os_check 실행 (동시 1개): /tmp/auto_setup/runs/<code>/ 에서
        bash "$os_check_sh" -auto <user> <목록>   (1차=작업 전체 목록, 재실행=늦게 READY 된 목록)
        목록에 os6 호스트가 있으면 PATH 앞에 /tmp/auto_setup/bin/gossh(os6 전달 래퍼)
   ⑥ 처리 완료 = 그 run 의 check.res_<user>_postapply 에 나온 호스트 → processed (재실행 제외)
   ⑦ codes/<code>.txt 생성 → wall "완료 호스트(가로) (N대) + code"
   ⑧ 남은 호스트는 무기한 감시 (cancel 전까지), 모두 processed 면 작업 종료
```

### 5-2. main.go 최상단
```go
// auto_setup - OS 설치(01) → OS 설정체크(os_check) 자동 연계 데몬
package main

var (
	os6_mgmt      = "" // 모든 대역 접근 가능한 서버 (비우면 os6 경로 미사용)
	os6_gossh     = "" // os6_mgmt 위 gossh 실행 파일 전체 경로
	os6_autosetup = "" // os6_mgmt 위 auto_setup(os6 빌드) 이 있는 디렉터리
	os_check_sh   = "" // 이 서버의 os_check_final_annotated.sh 전체 경로
)

// 조정 가능한 값 (빈 변수 아님)
var (
	pingInterval  = 10 * time.Second
	downMisses    = 2               // 연속 무응답 횟수 → ping X
	checkInterval = 30 * time.Second
	bootWait      = 7 * time.Minute // 최초 READY 후 대기
	lateWait      = 3 * time.Minute // 늦게 올라온 서버 묶음 대기
	queuePoll     = 5 * time.Second
)
```
- 기동 시 빈 변수 검사: `os_check_sh` 가 비면 데몬은 기동하되 run 단계에서 로그 `[X] os_check_sh 가 비어 있습니다` 남기고 해당 작업 대기(데이터 유실 없음). `os6_mgmt` 가 비면 os6 경로 미사용.
- `AUTO_SETUP_DIR` 환경변수(기본 `/tmp/auto_setup`)만 테스트용 오버라이드.

### 5-3. CLI
| 명령 | 동작 |
|---|---|
| `auto_setup daemon` | 포그라운드 루프 (ensure 가 백그라운드로 띄움) |
| `auto_setup ensure` | `auto_setup.lock` flock 시도 → 잡혀 있으면 즉시 종료(살아 있음), 아니면 `setsid auto_setup daemon` 백그라운드 기동(stdin/stdout=/dev/null, 로그는 파일) |
| `auto_setup code NNNN` | `codes/NNNN.txt` 출력 (없으면 `[X] code 없음`) |
| `auto_setup status` | 작업별: jobid, user, 전달시각, 호스트 상태별 대수(대기/설치중/READY/처리완료), 남은 호스트 가로 출력 |
| `auto_setup cancel <jobid>` | 무기한 감시 중인 작업 종료(jobs → jobs/done) |
| `auto_setup probe [-i 10s]` | (os6_mgmt 쪽) stdin 으로 호스트 목록을 받고, 첫 결과 전체 + 이후 변화만 `host up|down` 출력. stdin EOF 시 종료 |
| 인자 없음/잘못된 인자 | 사용법 출력 후 exit 1 |

tmpfiles (setup.sh): `/etc/tmpfiles.d/auto_setup.conf` 에 `x /tmp/auto_setup` — 무기한 감시 작업이 10일 tmp 정리로 지워지지 않도록.

### 5-4. 상태 (jobs/<jobid>.json)
```json
{ "id":"20261002-153000-user1", "user":"user1", "submitted":1759386600,
  "first_ready":0, "late_first_ready":0, "first_run_done":false,
  "hosts": { "host01": {"ip":"10.0.0.1","route":"local","seen_down":false,
                        "ready_at":0,"processed":"","miss":0} },
  "runs": [ {"code":"4821","hosts":["host01"],"at":1759387000} ] }
```
- 상태 변화 시에만 저장(tmp 파일 → rename). 재기동 시 jobs/*.json 전부 로드 → 각 비처리 호스트에 "기동 직후 1회 준비확인" 플래그.
- 중복 전달: 새 job 수거 시 같은 호스트가 다른 진행 중 job 에 있으면 **이전 job 에서 제거**(새 전달이 가져감). 이전 job 이 비면 종료.
- 호스트명→IP: job 수거 시 1회 `net.LookupHost`(동시 32개 제한), 실패 시 다음 주기에 재시도, 그동안 ping X 로 취급하지 않음(미해결 표시).

### 5-5. 감시 (icmp.go / probe.go)
- raw 소켓 `net.ListenPacket("ip4:icmp","0.0.0.0")` 1개, echo id=pid&0xffff, seq 로 호스트 매핑. 주기마다 local 호스트 전체에 1패킷씩 송신(5천대=500pps 수준), 수신 고루틴이 응답 기록. 다음 주기 시작 시 무응답이면 miss++ (≥ downMisses → down), 응답이면 miss=0/up.
- os6 경로: os6 호스트 집합이 바뀌거나 세션이 죽으면 `ssh -o BatchMode=yes -o ServerAliveInterval=30 <os6_mgmt> "<os6_autosetup>/auto_setup probe -i 10s"` 재시작. probe 는 같은 icmp.go 사용.
- 무기한 감시 비용: 남은 호스트당 10초마다 ICMP 1개 + ssh 세션 1개 → 무시 가능 수준이므로 **무기한**(사용자 결정: 영향이 적으면 무기한).

### 5-6. 준비 확인 (check.go)
- 후보 = 처리 안 됨 && ping up && (seen_down || 기동 직후 1회 플래그). 30초마다 후보가 있을 때만 실행.
- local: 임시 목록 파일 → `gossh -pm -script -w <f> "cat /proc/uptime"`; stdout `host: 123.45 …` 파싱, `<f>_os_install` 에 있으면 anaconda → 미준비. 사용 후 `<f>*` 결과 파일 삭제.
- os6: `ssh os6_mgmt "f=\$(mktemp); cat > \$f; <os6_gossh> -pm -script -w \$f 'cat /proc/uptime'; echo ==OSI==; cat \${f}_os_install 2>/dev/null; rm -f \$f \${f}_*"` (stdin 으로 목록 전달).
- READY 판정: uptime 초 < (현재 − submitted) && anaconda 아님 → 시계가 틀린 신규 서버여도 안전(uptime 은 상대값). **dd 전 기존 OS 를 READY 로 오판하지 않음**.
- 첫 OS 부팅 후 추가 재부팅 없음(사용자 확인: dd → 재부팅 → anaconda → 재부팅 → 완료) → 안정 대기 없이 첫 READY 를 인정.

### 5-9. os_check 실행·code·wall (runner.go)
- run 디렉터리 `/tmp/auto_setup/runs/<code>/`: `targets.txt`, `dhcp.sh` → `$(dirname os_check_sh)/dhcp.sh` 심볼릭 링크, 실행 출력 `os_check.log`.
- 실행: `cd runs/<code> && bash "$os_check_sh" -auto <user> targets.txt > os_check.log 2>&1` (tty 아님 → 색 자동 off). 동시에 1개만(큐).
- os6 래퍼 `/tmp/auto_setup/bin/gossh` (데몬이 생성, 0755): 인자 중 `-w <file>` 을 찾아 파일 내용을 stdin 으로 보내고 `ssh os6_mgmt "f=\$(mktemp); cat > \$f; <os6_gossh> <나머지 인자 printf %q> -w \$f; rc=\$?; rm -f \$f \${f}_*; exit \$rc"` 실행, stdout/stderr 그대로. 목록에 os6 호스트가 하나라도 있으면 그 run 전체를 `PATH=/tmp/auto_setup/bin:$PATH` 로 실행.
- code: 4자리(0000~9999) 랜덤, `codes/` 에 없는 값.
- `codes/<code>.txt` 구성 (순서 확정):
  1. **담당자 문구**: os_check.log 의 `############### 결과 리포트 ###############` ~ 마지막 `###########################################` 블록 그대로 (case6~9 벤더 규칙, dhcp/usb0/pice/ev 포함)
  2. **설정체크 (설정 수정 후 재점검)**: `check.res_<user>_postapply` 에서 호스트별로 FAIL 포함 줄만 출력, FAIL 이 없는 호스트는 `NO FAIL : host1 host2 … (N대)` 한 줄. 전부 FAIL 없으면 그 한 줄만.
  3. **LDAP / SPLUNK / 커널 요약**: os_check.log 의 `===== LDAP 정보`, `===== SPLUNK 정보`, `===== 커널 버전`, `===== <infra> infra 커널 버전` 블록을 그대로 발췌 (전체 호스트 기준 요약 형식)
  4. 마지막 줄: `원본 : /tmp/auto_setup/runs/<code>/os_check.log`
- wall (root):
  ```
  [auto_setup] OS 설치 + 설정체크 완료 (user=<user>)
  host01 host02 host03 (3대)
  code : 4821   →  auto_setup code 4821
  ```
  완료 호스트 = 이 run 에서 processed 된 호스트.
- processed 판정: `check.res_<user>_postapply` 에 나온 호스트. 1차 run 에서 READY 였는데 postapply 에 없는 호스트는 미처리로 남겨 늦은 묶음에서 재시도.
- os_check 가 비정상 종료(로그에 결과 리포트 블록 없음)해도 code 는 만들고(있는 것만 발췌) wall 에 `[!] os_check 비정상 종료` 1줄 추가, 호스트는 processed 처리 안 함 → 다음 주기 재시도는 하지 않고 늦은 묶음 규칙으로만 재시도(무한 반복 방지: 같은 호스트 연속 실패 3회면 status 에 `실패` 표시 후 제외).

## 8. 결정 사항 (§3 원문보다 우선)

1. 전달: 01 `[14]` 루프 직후, `${AUTO_SETUP_DIR:-/tmp/auto_setup}/queue/<epoch>_<user>_<pid>.job` (user=, time=, 호스트명 줄). 프롬프트·옵션 추가 없음, 실패해도 경고만.
2. 설치 진행 판정은 **ping 순서를 엄격히 세지 않는다**: ping X 2회 연속(seen_down) 이후 ping O 인 호스트만 ssh 확인, READY = gossh 응답 + anaconda 아님 + `uptime < 지금−전달시각`. 데몬이 죽어 있던 사이 전환을 놓쳐도 기동 직후 1회 확인으로 복구.
3. 7분: **첫 READY 시각 기준 고정**(연장 없음). 그 전에 전부 READY 면 즉시. 늦은 서버는 첫 늦은 READY + 3분 묶음.
4. 1차 run 은 **작업 전체 목록**을 넘겨 os_check 가 내려간 서버를 그대로 분류(부분 완료 담당자 문구가 나옴). 재실행 run 은 **새로 READY 된 미처리 호스트만** 넘김. processed = postapply 결과에 나온 호스트.
5. os_check `-auto <user> <목록>`: 체크 y, 목록에 p/d 시작 호스트 ≥1 → set, 아니면 y. 인자 없으면 기존과 동일.
6. 원격 대역: route=os6 호스트는 ping 을 os6_mgmt probe 로, 준비확인을 os6 gossh 로. 그런 호스트가 포함된 os_check run 은 gossh 래퍼로 전체를 os6_mgmt 에서 실행.
7. code 출력 = 결과 리포트 블록 → 설정체크 FAIL/NO FAIL → LDAP/SPLUNK/커널 블록 → 원본 경로. wall = 완료 호스트 가로 + 대수 + code.
8. 저장은 전부 `/tmp/auto_setup`, tmpfiles `x` 등록으로 자동 정리 제외. 무기한 감시, `auto_setup cancel` 로만 종료.
9. 리소스: GOMAXPROCS=1, 외부 의존성 0, raw ICMP 1소켓, ssh/gossh 는 후보만, os_check 동시 1개, 주기 로그 없음.
10. os6 빌드: Go 1.20 호환 코드, `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o auto_setup_os6`, .60 에서 `build_os6.sh` 실행.

## 9. 검증 기준

1. `go vet ./...`, `gofmt -l .` 결과 없음, `bash -n` (01/os_check/setup.sh/build_os6.sh/test), `shellcheck -S warning` 신규 경고 0. Go 1.20(.60)에서 `build_os6.sh` 빌드 성공, `file auto_setup_os6` 가 statically linked.

   - 정상: O→X→O(anaconda, 미준비)→X→O(READY) 전원 → 즉시 1회 run, 전체 목록 전달

## 14. 2차 설계

### 14-1. 토폴로지·원격 클라이언트 (양방향 동일)
```
os8_mgmt (rhel8) : auto_setup 데몬 + 상태(/tmp/auto_setup) + 01/os_check 도 실행 가능
os6_mgmt (rhel6) : 데몬 없음. 01/os_check 실행 가능, `auto_setup`(os6 빌드) 은 "원격 클라이언트 모드"
```
- main.go 최상단 **빈 변수 추가**: `os8_mgmt = ""`(비어 있지 않으면 **원격 클라이언트 모드** — os6 빌드 때 `-ldflags -X` 로 채움), `os8_autosetup = ""`(os8_mgmt 위 auto_setup 경로, 비면 `/usr/local/bin/auto_setup`), `os6_os_check_sh = ""`(os6_mgmt 위 os_check 경로 — 2차 체크용, 비면 2차 체크 생략). 기존 4개 변수 유지.
- 원격 클라이언트 모드 전송: 임시 목록 파일에 `<os8_mgmt>` 를 쓰고 `gossh -pm -script -w <f> "<os8_autosetup> <하위명령…>"` 로 단발 실행, gossh 출력 형식(`host: …`) 접두를 제거해 **로컬 실행과 바이트 단위로 같은 stdout** 을 만든다. 지원: `status`, `snapshot`(JSON), `code NNNN`, `cancel`, `request …`, `done …`, TUI(= snapshot 폴링 2~5초 + 키 입력 시 request). `--start/--stop/--restart` 는 원격 모드에서 거부(`[X] 데몬은 os8_mgmt 에서만`).
- os8→os6 방향의 기존 경로(probe 장기 ssh 세션, os6 gossh 래퍼, 준비확인)는 **그대로**.
- 01: 최상단 **빈 변수 `auto_setup_host=""`** 추가. 비어 있으면 지금과 동일(로컬 queue). 채워진 서버(os6_mgmt)에서는 queue 파일을 만든 뒤 gossh 로 os8_mgmt 의 `${AUTO_SETUP_DIR:-/tmp/auto_setup}/queue/` 에 1회 전송. 실패해도 경고 1줄만(진행 영향 없음).

### 14-2. queue/job 포맷 확장 (하위 호환)
- `.job`: 기존 `user=`/`time=`/호스트 줄 유지 + **그룹 줄 추가**: `yml=<파일명> infra=<> os=<> boot=<> splunk=<> hosts=<h1,h2,…>`, 전체 yml 은 `all=<파일명>`. 그룹 줄이 없으면(구버전 01) 단일 그룹 `(all)` 로 처리. 01 `[14-1]` 은 `yml_opt`/`group_yml`/`all_yml` 에서 그룹 줄을 추가로 기록(기존 줄·순서 불변, 추가분만).
- Job JSON: `groups: {<yml>: {infra,os,boot,splunk,hosts:[…]}}`, `all_yml`, 호스트별 `stage`/`stage_at`(단계 진입 절대시각)/`ldap`(backup:none|ok, bindpw:same|diff|na, applied:bool, 사유)/`second`(2차 체크 상태)/`done_src`(run|external|manual) 추가. 기존 키 유지(역방향 호환).

### 14-3. 호스트 단계(stage) 모델
`대기(queued)` → `배포중(deploying: ping X, seen_down)` → `설치중(installing: anaconda 확인)` → `부팅확인(booting: ping O, 미READY)` → `READY` → `LDAP확인` → `체크중(checking: run 진행)` → `완료(done)`; 부가: `정체(stuck)` = seen_down 후 `installStuck`(기본 **60분**)을 넘겨도 READY 가 안 된 호스트(빨강, 설치중 표시는 그 전까지 유지), `실패(failed)` = fails≥3, `2차대기/2차체크중(second)`. 단계·진입시각은 상태 변화 때만 저장. 조정 변수: `installStuck = 60*time.Minute`, 그 외 1차 값 유지.

### 14-4. 완료기록 (os_check ↔ auto_setup)
- 위치: `<AUTO_SETUP_DIR>/done/<host>` (한 줄: `epoch user sha256 source`; sha256 = 해당 run 의 `check.res_<user>_postapply` 중 그 호스트 줄의 해시). 쓰기는 임시파일→mv 원자 기록.
- os_check 변경(추가분만): 최상단 빈 변수 2개 `auto_done_dir=""`(로컬 기록 디렉터리 — os8_mgmt 에서 채움), `auto_done_host=""`(os8_mgmt — 다른 서버에서 채움; gossh 원샷으로 `<AUTO_SETUP_DIR>/done/` 에 기록). **둘 다 비면 아무 동작 없음.** 기록 대상 = 이번 실행에서 postapply 결과에 정상적으로 나온 호스트. 기록 실패는 경고 1줄만(os_check 결과·종료코드 불변).
- auto_setup 인정 규칙: `record.epoch >= max(job.submitted, now − host.uptime)` (마지막 부팅 이후). 인정되면 해당 호스트 processed(`done_src=external`), run 대상에서 제외(중복 실행 금지). 기록은 인정 후 `done/applied/` 로 이동.
- CLI `auto_setup done <host...>`: 수동 완료 처리(출처=manual, 경고 로그).

### 14-5. LDAP 백업/복원 (`ldapbk.go`)
- **수집(전달 시점)**: job 수거 직후 ping O 인 호스트(아직 seen_down 아님)에 대해 gossh 로 백업 수집. 대상 파일은 `ldap_check.sh`/`ldap_setting` 의 OS 분기·s4 규칙을 읽어 동일하게 결정 — 공통: `ldap.conf`(경로는 ldap_check 참조), `resolv.conf`, OS8+ `sssd.conf`+`chrony.conf` / OS7 이하(및 s4 호스트) `nslcd.conf`+`ntp.conf`. 저장: `<AUTO_SETUP_DIR>/ldapbak/<jobid>/<host>/<파일>` (**디렉터리 0700·파일 0600**, bindpw 는 로그·code·wall·TUI 어디에도 출력 금지 — 마스킹). 백업을 못 만든 호스트(이미 dd 진행, 접속 불가)는 `backup:none` → 이후 단계 생략.
- **비교·적용(READY 직후, os_check 전)**: READY 인 백업 보유 호스트마다 새 OS 의 `ldap.conf` bindpw 를 읽어 백업 bindpw 와 비교(해시만 비교). 같으면 `same`→생략. 다르면 `diff`→백업 파일 세트를 gossh 로 복원(원 권한·소유 유지, `restorecon`, `sssd|nslcd` 재시작·`chronyd|ntpd` 재시작은 OS 분기대로), 복원 결과 재확인 후 `applied`. 실패 시 로그·상태(`ldap: 적용실패`)만 남기고 run 은 진행(os_check 가 FAIL 로 보고).
- 1차 run·늦은 묶음 모두 READY 인 호스트에 대해서만 적용, run 호출 전에 완료. os_check/설정 스크립트 쪽은 **변경 없음**.

### 14-6. 2차(이중) 체크
- 1차 run 의 결과에서 **route=local** 호스트 중 (a) 접속불가(결과 파일에 없음/무응답) 또는 (b) postapply 에 FAIL 이 있는 호스트 = 2차 대상. `os6_mgmt` 와 `os6_os_check_sh` 가 비어 있으면 생략. route=os6 호스트(이미 os6 경유)는 제외.
- 실행: os6_mgmt 에서 `os_check -auto <user> <목록>`(원격 작업 디렉터리, ssh 로 목록 전달·실행, 결과 파일 tar 로 회수 → `runs/<code>/second/`). 1회만, 같은 run 의 code 에 이어 붙임(`### 2차 체크(os6_mgmt)` 섹션: 대상·결과·병합 후 최종 FAIL/NO FAIL). 호스트 최종 처리 = 1차 OK 또는 2차 OK. 2차는 1차 run 직후 같은 큐에서 수행(동시 1개 유지).
- os6_mgmt 에서 시작된 작업도 데몬이 os8_mgmt 에 있으므로 동일 흐름(역방향 재시도 없음).

### 14-7. CLI·TUI
- `auto_setup`(무인자): tty 면 TUI, 아니면 `--plain` 텍스트 표. `-h|--help` 사용법. `--start`(없으면 기동·이미 있으면 안내), `--stop`(pid 파일 + SIGTERM, 확인 대기), `--restart`. 데몬은 lock+pid 파일 사용(1차 flock 유지). `ensure`(cron)는 그대로.
- TUI(표준 라이브러리만, 직접 raw tty — 저장소 `.claude/VM/Network_Change_Integration_Script/projects/*/internal/monitor/tty_linux.go` 패턴 참고, 정적·RHEL6 호환): **화면 1** — 상단 총계(전체/완료/진행/정체/실패, 갱신 시각, 데몬 상태), 집합(yml 그룹) 행: 이름·infra/os/boot/splunk·호스트 수·단계별 건수 막대·최장 경과시간. **화면 2(Enter)** — 호스트별 표(호스트·단계·경과·비고[anaconda/uptime/LDAP/체크결과/2차/출처]), `f` 정체·실패만 필터, 모든 호스트 완료 시 하단에 `[c] OS 체크 수동 실행(이중체크)` 활성 → 확인(y/n) → run 요청 → 진행·code 실시간 표시. 키: ↑↓ 행, ←→ 작업(job) 전환/화면 복귀, Enter 진입, Esc/q 종료·복귀, r 새로고침(기본 2초 자동), `?` 도움말. 색: 완료 초록·진행 청록·대기 회색·경고 노랑·정체/실패 빨강(굵게), `NO_COLOR`/비 tty 에서 자동 off. 화면 그리기는 **순수 함수(상태→문자열)** 로 분리해 골든 테스트.
- 요청 채널: `<AUTO_SETUP_DIR>/requests/<epoch>_<kind>.req`(kind=manual-run 등, 원자 기록) → 데몬 5초 주기 수거. 스냅샷: `auto_setup snapshot` = jobs/*.json + 파생 stage 를 JSON 으로 출력(로컬·원격 동일).
