## 0. 불변 조건 (모든 단계 공통)

1. **기존 동작 불변.** 새 명령은 conf 에서 꺼져 있으면(기본) 화면·키·동작이 v0.6.2 와 같아야 한다 (안내 줄에도 안 나옴).
2. **대상 노드·auto_setup 데몬의 서비스 재시작 금지.** ip_change 는 네트워크 재시작 없음, ldap apply 도 재시작 없음. **ldap 원복은 엔진 기본이 재시작이므로 auto_setup 이 호출할 때 항상 `-no-restart`** (S1 에서 엔진에 추가, 기본값은 종전 동작).
3. bindpw 는 화면·로그·기록 파일·snapshot·code 어디에도 남기지 않는다 (엔진 `-print-script` 는 호출 금지). `ldap_config.conf` 는 퍼미션 600.
4. gossh 계정·인증은 기존 auto_setup 과 같다 (비밀번호 인자 없음, `-p` 금지).
5. 변수는 비어 있는 채로 커밋 (`conf/auto_setup.conf` 는 git-ignore, `.example` 만). RHEL6 바이너리 `auto_setup_os6` + 새 엔진 os6 바이너리는 소스 변경 때마다 .60 에서 재빌드해 커밋 (+x).
6. Go 1.20 호환, stdlib 만. Go/bash 는 랩(.58, .60)에서만 빌드·검증. Windows 에서 실행 금지.
7. 변경 부분만 테스트하되 범위를 넓히면 이유를 적는다. 요약 줄 `PASS=/FAIL=` 까지 확인한다.
8. 커밋 메시지 끝: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## 2. 엔진 사실 (조사 결과)

- `ip-change-engine`: 플래그 `-config -targets -gossh -u -p -i -P -c -t -remote-path -rollback -rollback-to -monitor`. 결과줄 `RESULT|OK|host|기존IP|변경IP|GW` / `RESULT|FAIL|host|사유`. `-rollback` 은 hostname 한 컬럼만 있어도 됨.
- `ldap-config-engine`: `-config -assets -infra(필수) -site -host -host-file -dry-run -print-script -root -gossh -u -p -i -P -c -t -remote-path -list-backups -rollback -rollback-to -monitor`. 종료코드 0/1/2. apply 는 서비스 재시작 안 함(auto.appl 은 `/etc/auto.appl.bak` 대기 + `/root/auto_appl_restore.sh`), **rollback 은 `lib_common.sh restart_for_changed` 로 sssd/nslcd/autofs/chronyd/ntpd 를 systemctl restart**.
- 두 도구 `go.mod` 의 `go 1.26.5` 는 Go 1.25/1.20 이 거부 → `go 1.20` 으로 낮추면 .60 의 Go 1.20.14 로 vet/test/빌드 모두 통과 (확인 완료). 바이너리는 `CGO_ENABLED=0` 정적이라 os6·os8 공용.

## 3. 단계 (jev-plan-router 로 모델 라우팅)

### S0. 준비 (직접 수행)
작업 트리·브랜치·백업 태그, 이 계획서. (완료)

### S1. ldap_setting `-no-restart` + go.mod
- `.claude/HPC/ldap_setting`: 플래그 `-no-restart`(기본 false) → 엔진이 apply/rollback 스크립트 헤더에 `NO_RESTART=1` 삽입 → `lib_common.sh restart_svc` 가 `SKIP-RESTART (NO_RESTART)` 로그만 남기고 반환. **플래그를 안 주면 바이트 단위로 종전과 같은 스크립트**(골든/테스트로 확인). `sss_cache -E` 도 NO_RESTART 면 생략.
- `go.mod` 두 곳(`ip_change`, `ldap_setting`) `go 1.20`. CHANGELOG·README(옵션표)·ARCHITECTURE 갱신, 단위 테스트 추가.
- 검증: .58 에서 `go test ./...`(Go 1.25 로 빌드 가능해야 함), `test_all.sh`, .60 에서 Go 1.20 vet/test.

### S2. 설치·conf·--admin
- `setup.sh`: 두 엔진을 `GOPROXY=off CGO_ENABLED=0` 로 빌드해 `/usr/local/bin` 에 설치(없는 소스 경로면 건너뜀+안내). `conf/ip_change.conf.sample`·`ldap_config.conf.sample`·`assets.txt.sample` 을 `/etc/auto_setup/` 로 복사하되 **기존 파일은 덮어쓰지 않음**, ldap_config.conf 는 600.
- `auto_setup.conf.example` 키(전부 빈 값): `enable_ip_change`, `enable_ldap_change`, `ip_engine`(비면 `<exe dir>/ip-change-engine` → PATH), `ldap_engine`(동일).
- `--admin` 플래그(main.go): TUI 모드에서만 의미. `auto_setup --admin` 으로 켜지고, 데몬 서브커맨드·`--plain` 에는 영향 없음. os6 원격 TUI 로 전달.
- 레포에 os6 용 엔진 바이너리 커밋 위치: `ip_change/bin/ip-change-engine_os6`, `ldap_setting/bin/ldap-config-engine_os6`(+x). `build_os6.sh` 가 같이 빌드.

### S3. 변경 흐름 코어 (신규 `change.go`, `changerun.go`)
- 상태기계 `changeState`: menu → user → (infra) → input → preview → confirm(yes) → run → result. 원복·auto.appl 원복은 input 이 "기록 자동 채움 + 수정". `oneoff.go` 의 `newUserStep`·`normalizeHosts`·실행기 주입 패턴을 따라 `changeExec` 주입 변수로 테스트 가능하게.
- 엔진 실행기: 경로 해석, 임시 디렉터리(0700)에 targets/host-file 작성, 종료 시 삭제, 출력은 라인 단위로 화면에만(결과 파싱 후 호스트별 구조체). bindpw 를 담는 출력은 버림.
- 경유 규칙: os8 에서 먼저 → 응답 없음 호스트만 os6 경유로 재시도. os6 경유는 엔진 `-gossh` 에 **임시 래퍼 스크립트**를 넘겨 `ssh <os6_mgmt> <os6_gossh> "$@"` 로 전달(이스케이프 주의). 이미 route=os6 인 호스트는 처음부터 래퍼 사용.
- IP+LDAP: IP 실행 → OK 호스트만 `-host-file` 로 LDAP. 결과표는 호스트별 `IP`/`LDAP` 두 칸.
- 미리보기: IP = hostname→기존(조회 가능하면)→새 IP/GW 표, LDAP = 엔진 `-dry-run` 결과 요약(CHANGED/NOCHANGE/WARN, bindpw 마스킹), 진행 중 job 경고, "서비스 재시작 안 함 / IP 는 재시작·재부팅 후 반영" 문구.
- 기록: `changes/<user>/..json`(퍼미션 0600), `auto_setup.log` 요약. `appl_pending` 플래그는 LDAP 적용 OK 호스트에 true, auto.appl 원복 성공 시 false.
- 취소: x 와 같은 Ctrl+X→y, 프로세스 그룹 SIGTERM(3초 후 SIGKILL).

### S4. TUI 연결·표시
- `tui.go`: `m` 키(화면 1·2), `st.admin`/conf 로 항목 가시성, 꺼져 있으면 키 무반응이고 안내 줄에도 없음. 안내 줄에는 `m 변경` 한 항목만 추가(색 별도).
- `render.go`: 메뉴·입력·미리보기·결과 화면(제목 `IP 변경`/`LDAP 변경`/…, 위험 문구는 빨강), 도움말(`?`) 갱신, 안내 줄 hintSegs 항목.
- 사용자에게 보이는 문구는 한국어.

### S5. 레이아웃 (좁은 화면에서 안 잘림)
- 스크린샷 문제: 폭이 줄면 안내 줄·job 헤더(`all=infra_inventory-….yml`)·그룹 행(yml 이름 `…`)·호스트표 비고가 `…` 로 잘림. **60칼 이상에서 잘림 없이 줄바꿈**.
- 규칙: ① 헤더/job 줄은 항목 단위로 다음 줄로, ② 그룹 행은 폭이 부족하면 2줄 카드형(1줄: `> yml 전체 이름`, 2줄: 스펙·대수·막대·경과·%), ③ 호스트 행은 비고를 다음 줄(들여쓰기)로 줄바꿈, ④ 변경 화면의 표도 같은 규칙. `window()` 스크롤·선택 행 반전은 줄바꿈된 행 전체를 하나의 행으로 취급.
- 창 크기 변경(SIGWINCH) 때 즉시 다시 그리는지 확인하고, 안 하면 고친다 (스크린샷의 안내 줄 색 블록은 리사이즈 직후 재그리기 전 reflow 로 추정 — 80칼 pty 에서 안내 줄 raw 에 `\x1b[7m` 가 없는지 테스트로 고정).
- 골든: 폭 60/80/120 × 색 on/off.
