사내 설치 경로: /root/server_vm_python/redhfish/V2

[중요 — 실제 BMC 미검증] redfish(biostool)는 실제 물리 BMC 하드웨어에 접속해 검증된 적이 없습니다. 모든 동작 검증은 합성 testdata/ 기반 모의 BMC(mockbmc)와 -from-dump 덤프에서만 수행되었습니다. 속성 이름·허용값·Settings 경로·Dell Job 동작은 실제 응답으로 확정해야 합니다.

모델을 처음 만나면 1대부터 5장의 절차(프로젝트 루트의 FIRST_RUN.md 요약)를 따르십시오. 본 도구는 100% 신뢰하기보다 참고용(보조 도구)으로 사용하고, 설정 변경·계정 생성·비밀번호 변경 뒤에는 랜덤한 서버 몇 대를 직접 골라 실제로 반영되었는지 확인하십시오 (9장).

안전 설계 원칙:

  • 재부팅(Reset)·즉시(Immediate) 적용을 하지 않습니다. 설정은 BMC의 Pending Settings(다음 재부팅 때 반영)까지만 예약합니다. 로그 조회·ClearLog·Reset 같은 경로는 전송 전에 코드가 차단합니다.
  • 쓰기는 Dell·HPE·Lenovo 에 한하고, 프로파일에서 모델을 지정한 verified=Y 행에만 허용합니다. Cisco·Supermicro 는 점검 전용입니다. 와일드카드(*) 행에 verified=Y 를 쓰면 프로파일 로드가 막힙니다.
  • 서버 고유값·부팅·보안·RAID·PXE·NIC 속성(IQN, IP, ServerName, BootMode, SecureBoot 등)은 어떤 경우에도 설정하지 않습니다(코드에 고정된 보호 목록, 설정 파일로 해제 불가).
  • TUI 의 수정 단계는 미리보기 → 확인(y) → 적용 순서이고, n·Esc·Ctrl+X 면 아무것도 쓰지 않습니다. -plain·-auto·-from-dump 는 읽기 전용입니다.
  • BMC 비밀번호는 평문으로 디스크·명령행·로그에 남지 않습니다(AES-256-GCM 암호화 파일).

2.1 사전 빌드 바이너리 배치

외부 의존성 없는 정적 바이너리(bin/biostool)가 이미 포함되어 있으므로 폐쇄망에서도 별도 빌드 없이 바로 실행합니다. bios.sh 가 uname -r 를 보고 알맞은 바이너리를 자동 선택하며, 실행 권한이 없으면 chmod +x 를 시도합니다. 바이너리가 없으면 안내 후 종료코드 2 로 끝납니다.

2.2 처음 한 번 준비할 것

bash
  • bios.conf: user= 필수. 비밀번호 키(pass·password·passwd·pw)가 하나라도 있으면 보안 오류로 즉시 실패합니다 — 비밀번호는 반드시 bash bios.sh encrypt 로 암호화합니다. 알 수 없는 키도 오류입니다 (키 전체는 6.2절).
  • user.txt: 한 줄에 대상 하나. IP / hostname-m / hostname(+ 선택 :포트). hostname 은 /etc/hosts 에서 hostname-m 의 IP 를 찾습니다. 빈 줄·# 주석은 무시, 중복은 한 번만 처리합니다.
  • 호스트 태그(선택): 호스트 뒤에 공백(또는 탭) + 한 단어를 적으면 태그입니다(예: 192.168.1.1 gold). 태그가 있는 호스트는 결과 화면에서 태그별로 묶이고, 전체비교에서는 같은 태그끼리만 비교합니다. 엑셀의 IP<Tab>태그 를 그대로 붙여넣어도 됩니다.
  • profiles/*.tsv: 탭 구분 프로파일(컬럼: vendor model std_name attribute value verified). 표준 4항목(system_profile, hyper_threading, llc_prefetch, sub_numa_cluster)은 행이 없어도 항상 점검 대상이며, 행이 없으면 MAPPING_MISSING 입니다. value 는 A|B 형식의 허용 표기 여러 개를 쓸 수 있고, verified 는 Y/N 입니다.
  • bios.conf, pass.enc, key.bin, user.txt, results/, dumps/ 에는 실제 호스트·계정 정보가 들어갑니다. 저장소 커밋·메신저 공유를 하지 마십시오.

2.3 암호화 파일 3종과 key.bin (벤더 암호화 키 포함)

비밀번호는 모두 bash bios.sh encrypt 로 암호화합니다. 비밀번호는 명령행 인자로 받지 않고 화면에도 표시하지 않으므로 ps·쉘 히스토리에 남지 않습니다. 세 암호화 파일은 하나의 key.bin(AES-256 키)을 공유합니다.

명령 만드는 파일 무슨 비밀번호인가 입력 방식
bash bios.sh encrypt pass.enc (+ key.bin) 1순위 공용 BMC 계정(bios.conf 의 user)의 비밀번호. 점검·설정 접속에 사용 숨김 입력 2회, 같을 때만 저장
bash bios.sh encrypt 2 pass2.enc 두 번째 공용 계정(user2)의 비밀번호. 계정 생성에서만 사용 숨김 입력 2회
bash bios.sh encrypt rf
bash bios.sh encrypt rf <벤더>		 rf.enc (벤더별 한 줄) 벤더 admin(2순위) 계정의 비밀번호. 1순위 계정이 BMC 에 없을 때 접속·계정 생성에 사용 글자마다 * 표시, 붙여넣기 거부, 터미널에서 직접 입력 2회

2.3.1 벤더 암호화 키(rf.enc) 생성 절차

벤더: dell hpe lenovo supermicro cisco cray. 계정명은 /etc/rf_tool/rf.conf 에 적고, 비밀번호는 rf.enc 에 벤더별로 암호화해 둡니다.

  1. 계정명 파일 작성(루트만 읽도록): 비밀번호는 적지 않고 계정명만 적습니다.
  2. 벤더별 비밀번호 암호화: bash bios.sh encrypt rf 는 rf.conf 에 <vendor>_user 가 있는 벤더를 차례로 묻고, bash bios.sh encrypt rf dell 처럼 벤더를 주면 그 벤더 항목만 갱신합니다 (rf.enc 의 다른 벤더 항목은 그대로 남습니다).
  3. 생성 확인: rf.enc·key.bin 의 권한이 600 인지 확인합니다. 아니면 도구가 600 으로 보정하고 안내를 출력합니다.
  4. 평문 줄 제거: rf.conf 에 예전 형식의 평문 <vendor>_pass= 줄이 남아 있으면 경고가 나옵니다. rf.enc 가 우선하지만 평문 줄은 지우십시오.
bash
  • key.bin 과 pass.enc/pass2.enc/rf.enc 는 짝입니다. key.bin 이 이미 있으면 그 키를 그대로 씁니다. key.bin 을 지우거나 바꾸면 기존 암호화 파일을 풀 수 없어(키 불일치 오류) 모두 다시 만들어야 합니다. 업데이트(bios.sh update)는 이 파일들을 지우지 않습니다.
  • 둘이 함께 유출되면 비밀번호가 풀리므로 둘 다 권한 600 을 유지하고 저장소·백업·티켓·메신저에 올리지 마십시오. 벤더별 예비 비밀번호는 서로 다르게 두고, 예비 계정은 가능한 한 권한이 낮은 계정(BIOS 설정만 가능)으로 만드십시오.
  • 2순위 계정은 1순위 로그인이 401 인증 실패일 때만 호스트당 1회 시도합니다. 벤더는 인증 전 ServiceRoot 응답으로 식별하므로 신뢰하는 관리망에서만 쓰십시오.

3.2 TUI 진행 순서

  1. 대상 입력 — 대상 파일을 지정하거나 hostname / hostname-m / IP 를 붙여넣습니다(한 줄에 hostname 또는 hostname 태그, Ctrl+D 완료, Ctrl+X 취소). -user 를 주면 묻지 않습니다. 대상에 IP 가 있으면 이어서 Cisco(XML) 대상을 따로 묻습니다(비워 두면 없음).
  2. 프로파일 선택 — profiles/*.tsv 중에서 고릅니다(-profile 로 지정하면 생략).
  3. 접속·조회 — 호스트당 로그인 1회로 BIOS 전체 속성을 읽어 프로파일 판정과 전체비교에 함께 씁니다. Ctrl+X 로 중단할 수 있습니다.
  4. [프로파일 점검] — 프로파일 항목의 결과를 색상 줄로 보여 줍니다. Tab 으로 [전체 설정 비교] 와 오갑니다.
  5. [전체 설정 비교] — 처음 Tab 을 누르면 비교 기준을 고릅니다(3.4절). 같은 모델끼리만 비교합니다.
  6. 수정 — e 키로 들어가 수정 방법을 고르고(3.5절), 미리보기 → 확인(y) 후 BMC Pending 까지만 설정합니다. 설정을 보낸 호스트는 자동으로 재점검해 결과 화면에 반영합니다.
  7. 요약 — q 를 두 번 눌러 종료하면 OK / difference / N/A / 오류 건수, 결과 폴더, CSV 목록을 출력합니다.
  8. 계정 생성 질문 — 1순위 계정이 거부되어 2순위(rf.conf)로 점검한 호스트가 있으면 계정을 만들까요? [Y/n] 을 묻습니다(4장).

3.6 프로파일에 설정 행 추가 — profile add (TUI p 키)

bash
  • 행은 프로파일의 # [redfish] 구역 끝에 추가되며 쓰기 전에 <이름>.tsv.bak.<일시> 로 백업합니다. 결과를 다시 읽어 검증한 뒤 교체합니다.

3.7 비대화형 자동화 (-auto / -auto-check)

  • 묻지 않고 점검만 합니다(설정 없음). 프로파일은 -profile 또는 bios.conf 의 auto_profile 입니다.
  • targets.txt 와 check.res_<user>(-auto 는 _postapply 도)는 호출한 폴더 기준입니다.
  • 점검을 끝냈다면 FAIL 이 있어도 종료코드 0 입니다. conf 오류·대상 없음·프로파일 없음 같은 치명적 오류만 0 이 아닙니다.

3.8 Cisco(XML) 혼합 대상

hostname 이 bios.conf 의 xml_host_prefix(기본 c)로 시작하는 대상과 -user-xml 목록은 Cisco UCSM/CIMC XML API(읽기 전용) 로 점검하고 나머지는 Redfish 로 점검합니다. XML 대상은 프로파일 점검만 하고 전체비교·설정에서는 빠집니다. 기대값은 프로파일의 # [xml] 구역입니다.

4.1 계정 생성 — bash bios.sh account

1순위 계정(bios.conf 의 user + pass.enc)이 일부 BMC 에 없을 때, 벤더 admin(2순위, rf.enc)으로 접속해 같은 id/pw 의 관리자 계정을 만듭니다. bios.conf 에 user2 가 있으면 권한이 다른 두 번째 계정도 같은 호스트에 만듭니다(권한은 user2_role / user2_role_<벤더>, 없으면 생성 직전에 Administrator / Operator / 직접 입력 중 고르라고 묻습니다).

bash
  • bash bios.sh(TUI·-plain) 도 점검 끝에 같은 질문을 합니다(1순위가 거부되어 2순위로 접속한 호스트가 있을 때. 기본 Y). 만든 뒤에는 1순위 계정을 만든 호스트만 1순위 계정으로 자동 재점검해 결과를 합쳐 보여 줍니다.
  • 같은 id 가 이미 있으면 덮어쓰지 않고(SKIP_EXISTS), 만든 뒤 새 계정으로 로그인 1회 검증합니다. 인증 거부면 이번 실행이 만든 계정만 롤백합니다(VERIFY_FAIL_ROLLED_BACK). 통신 오류로 확인하지 못하면 롤백하지 않고 VERIFY_UNKNOWN(수동 확인), 롤백도 실패하면 ROLLBACK_FAILED(수동 조치)입니다.

4.2 비밀번호 변경 — bash bios.sh passwd

BMC 공용 계정(bios.conf 의 user)의 비밀번호를 바꾸는 명령입니다. 1순위 계정으로 로그인되는 호스트에서만 바꿉니다(admin 세션으로 남의 계정 비밀번호를 바꾸지 않음). bash bios.sh passwd 는 bin/biostool account change 를 바로 실행합니다.

bash
  1. 새 비밀번호 입력: 터미널에서만 받습니다(파이프·파일 거부). 글자마다 * 로 보이며 붙여넣기는 거부되므로 키보드로 직접 입력합니다. @ ! # $ < & " 같은 특수문자도 그대로 전송합니다.
  2. 확인: 기본이 N 입니다(명시적 y 필요).
  3. 검증·롤백: 새 비밀번호로 1회 로그인하고, 인증 거부면 열려 있는 세션으로 이전 비밀번호를 되돌립니다(VERIFY_FAIL_ROLLED_BACK). 되돌리기도 실패하면 ROLLBACK_FAILED.
  4. pass.enc 는 자동으로 바뀌지 않습니다. 모든 호스트가 성공한 것을 확인한 뒤, 도구가 안내하는 대로 bash bios.sh encrypt 로 새 비밀번호를 다시 암호화합니다. 일부 호스트가 변경되지 않았다면 그 호스트는 이전 비밀번호가 유지되므로, 모두 성공한 뒤에 pass.enc 를 바꾸는 것이 안전합니다.

이 명령은 BMC 계정의 비밀번호만 다룹니다. 서버 OS(SSH root) 비밀번호 변경은 별도의 비밀번호 변경 스크립트(pwreset)가 담당하며 이 도구와 무관합니다. 변경 후에는 bash bios.sh -plain -profile VM -user user.txt 로 1~2대를 점검해 새 비밀번호로 로그인되는지 확인하십시오.

대량 서버에 곧바로 실행하지 마십시오. 처음 만나는 모델은 아래 9단계로 1대부터 확인합니다. auth_fail_stop(기본 3)을 0 으로 끄면 BMC 계정 잠금 위험이 있습니다. 계정(비밀번호)이 틀린 채 같은 서버에 반복 접속하지 마십시오(AUTH_FAIL 은 자동 재시도하지 않습니다).

7.1 새 버전 반영 — bash bios.sh update

bash
  • 그대로 둠: bios.conf pass.enc pass2.enc rf.enc key.bin user.txt diff.txt ignore_attrs.txt refs/ results/ dumps/ (현장에서만 만드는 파일).

8. 백업 및 롤백 방법

  • 작업 전 Redfish 트리 백업(권장): 설정 전에 bash bios.sh dump <대상...> 로 현재 BIOS 상태를 dumps/ 에 저장해 두십시오. 재부팅 후 원복이 필요할 때 값 대조의 근거가 됩니다.
  • Pending 설정 취소(재부팅 전 롤백): 도구는 자동 재부팅을 하지 않으므로 APPLIED 직후(재부팅 전)에 잘못된 변경이 발견되면 해당 서버 BMC 웹 콘솔·벤더 CLI(iDRAC/iLO/XCC)에서 Pending BIOS Settings / BIOS Job Queue 를 수동 삭제해 반영을 막습니다.
  • 재부팅 후 값 원복: 이미 반영된 경우, 사전에 채집한 덤프를 대조해 되돌릴 값을 정하고 bash bios.sh 의 e → “BIOS 값 직접 입력”으로 다시 Pending 설정하거나 BMC 콘솔에서 수동 원복한 뒤 재부팅합니다.
  • 프로파일 롤백: profile add 는 쓰기 전에 profiles/<이름>.tsv.bak.<일시> 를 만들므로 그 파일로 되돌립니다.
  • 계정 생성·변경 롤백: 도구가 검증에 실패한 서버에서 자동으로 롤백합니다. ROLLBACK_FAILED 는 결과 파일 detail 의 안내대로 수동 조치합니다.
  • 배포본 롤백: bios.sh update 가 만든 backup/V2_<일시>.tgz 로 복원합니다.

9. 작업 완료 후 랜덤 서버 실접속 교차검증 필수

[필수 검증] BIOS 설정·계정 생성·비밀번호 변경을 한 뒤에는 반드시 랜덤 서버를 직접 확인하십시오.

이 도구는 실제 BMC 로 검증되지 않았고, APPLIED 는 “BMC 의 Pending 에 기대값이 들어간 것을 재조회로 확인했다”는 뜻일 뿐 BIOS 에 실제로 반영되었다는 뜻이 아닙니다. 펌웨어별 Pending 반영 지연, Job 미생성, 속성 의존성(DEPENDS_ON_PROFILE) 등으로 실제 값이 다를 수 있습니다. 벤더·모델별 랜덤 1~3대 에 직접 접속해 다음을 확인하십시오.

  • BMC 웹 UI / BIOS 화면에서 system_profile, hyper_threading, llc_prefetch, sub_numa_cluster 등 적용 값과 Job Queue 잔여 상태 (재부팅 후에는 bash bios.sh 재점검 OK 와 정상 POST/OS 부팅 여부)
  • 계정을 만들었거나 비밀번호를 바꿨다면 해당 BMC 에 실제로 로그인되는지 (벤더별 계정 생성·권한 방식은 문서 근거이며 실제 장비 미확인)
  • bash bios.sh account·passwd 는 항상 -dry-run 으로 대상과 요청 본문을 먼저 확인

결과(results/)에는 호스트 이름·모델·BIOS 설정값이 들어 있고 pass.enc·pass2.enc·rf.enc·key.bin 은 비밀번호와 직결됩니다. 저장소 커밋·공유를 금지하고 필요 없으면 직접 삭제하십시오. 입력 목록에 같은 서버를 다른 표기(host 와 host-m)로 중복해 넣지 마십시오(DUPLICATE_TARGET).
