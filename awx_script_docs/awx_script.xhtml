  • 원본 저장소 경로 (origin/master): .claude/HPC/awx_script
  • 대상 브랜치: confluence (awx_script_docs/)
  • 주요 스크립트 및 구성요소: 01.AWX_nodeinfo_V2.sh (메인 오케스트레이터), 02.source_dhcp_pxe.sh (yml별 인벤토리/DHCP/PXE 등록), 내장 awxkit/ (7종 Go 바이너리·래퍼), setup/ (가이드·현장 사본 업데이트 스크립트), test/ (검증 하네스 — 랩/CI 전용)

1. Suite 전체 개요 및 단계별 전체 흐름

awx_script는 HPC 서버 대량 OS 배포 전처리를 위해 노드정보 수집 및 검증(01.AWX_nodeinfo_V2.sh), AWX 인벤토리 동기화 및 DHCP/PXE 등록(02.source_dhcp_pxe.sh), 실제 AWX API 호출(내장 awxkit/), 그리고 OS 설치 완료 후 자동 감시(auto_setup queue 전달)를 하나로 묶은 파이프라인 Suite입니다.

4. 통합 실행(01 · AWX_AUTO) vs 02 단독 실행법

4.1 입력 파일 (${user}.txt) 준비 및 13번째 분류 태그

  • Y (nodeinfo 사용): ${user}.txt에 호스트명을 한 줄에 하나씩 작성합니다. awxkit/nodeinfo.sh 성공 시 결과가 ${user}.txt를 덮어씁니다(실패 시 기존 파일 보호).
  • N (nodeinfo 미사용): "msg": "..." 형식 또는 12필드(vendor model infra hostname ip mac nic disk part 용량 os boot)여야 합니다.
  • 13번째 필드 (분류 태그, 선택): 12필드 뒤에 공백 없는 한 단어(예: ... os boot rhel810(TEST/SR))를 붙이면 yml 그룹 분할 키로만 사용됩니다(검사·치환 없이 원형 유지, repohost 전송 시 12필드만 전송). 먼저 Y로 실행해 정렬된 ${user}.txt가 생성되면 Ctrl+C로 중단 후 줄 끝에 태그를 붙이고 N으로 재실행하는 방식을 사용합니다(12 또는 13필드만 허용).

5. 핵심 규칙 · 옵션 및 연계 상세

5.1 yml 분할 키 및 splunk 값 자동 결정 규칙

규칙 구분 기준 / 조합 적용 규칙 및 치환 사항
yml 분할 키 (7+1) infra + nic + disk + 용량 + os + boot + splunk + (선택)13번째 태그 part(9번째 필드)는 분할 키에서 제외. 1~12필드에 1.1T→1200, 7T→7600, test1234→offchip, boot 레거시→legacy 치환. 모든 줄을 담은 _all yml도 생성되나 02의 DHCP/PXE에서는 제외됨
splunk 자동 결정 호스트명 패턴 우선순위 ① 호스트명에 ev 포함 → no (최우선) / ② s로 시작 → Cloud / ③ 그 외 → On-premise (예: spice01ev02→no, spice01→Cloud, node01→On-premise)
02 OS 버전 및 번호 변환 1) 2024, 2) 2025, 3) 2026, 4) 2026-OPC_MDP, 5) 2026-ECAD_TCAD(기본) 01이 넘긴 os 값은 무시하고 02에서 다시 선택(또는 AWX_AUTO_OS). 숫자형(2024 등)은 awxkit이 번호로 오인하므로 s4_osver_choices 순번으로 자동 변환해 전달

5.2 [4-1] DNS 점검 · [12] 접속 확인 · 02 파티션 확인 · auto_setup 연계

  • [4-1] dns_check: /etc/resolv.conf의 nameserver(최대 3)에 직접 A 레코드 질의(dig +short +time=2 +tries=1 우선 → nslookup, xargs -P 32). 일치/불일치/판단 불가/미등록/조회 실패 5종 판정 + PTR 역조회 중복 경고 출력. 대화형은 a/n/s/q 선택(IP 교체 시 5번째 필드만 갱신, LOG/${user}.log에 [DNS] 기록), AWX_AUTO=1은 /dev/tty로 [y/N] 확인, AWX_DNS_CHECKED=1이면 표만 출력 후 자동 진행.
  • [12] LDAP/LACP & 02 파티션 확인: 실행 전 [Y/n] 확인(AWX_CHECK=y|n 우선, AWX_AUTO=1에서는 기본 건너뜀). 파티션 표준(lsblk): 물리 파티션(LVM 금지), OS 디스크(/)가 sda 또는 nvme0n1, /boot(또는 /boot/efi) 500M~512M, / 30G, /var 20G, swap 및 /tmp(나머지) 존재.
  • [14-1] auto_setup queue 전달: 02 성공 직후 프롬프트 없이 ${AUTO_SETUP_DIR:-/tmp/auto_setup}/queue/<epoch>_<user>_<pid>.job 작성(그룹 yml 2개 이상 시 yml=..., all=... 포함). auto_setup_host 설정 시 gossh로 원격 원자 전송. 실패해도 경고 1줄만 내고 등록 종료코드엔 영향 없음.

6. 통합 주의사항 · 롤백 및 알려진 한계

  • sed 's/7T/7600/g' 부작용: 용량 치환 시 17T 등 7T가 포함된 문자열도 치환될 수 있음(원문 동작 유지).
  • custom_inventory.sh 동시 실행 충돌: 같은 초에 동일 infra 그룹을 생성하면 덮어쓸 수 있으므로(sleep 1로 완화), 생성 전후 차이를 확인하십시오.
  • 대소문자/선택지 불일치: 02는 infra를 소문자로 변환해 전달하므로 awxkit conf의 *_choices와 일치해야 하며, 차이가 있으면 02 확인표(N) 또는 dhcp_infra_alias/pxe_infra_alias로 맞추십시오.
  • 임시/결과 파일 정리: 종료 시 trap cleanup EXIT로 임시 디렉터리 및 gossh 결과 파일(_res_off 등)을 삭제하며, 임시 파일은 /tmp/auto_setup/tmp(권한 1777) 하위를 우선 사용합니다.
