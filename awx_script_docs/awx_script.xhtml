2. 처음 사용하기 전에 무엇을 준비하나?

  1. 실행 권한을 줍니다: chmod +x 01.AWX_nodeinfo_V2.sh 02.source_dhcp_pxe.sh awxkit/*.sh
  2. awxkit/conf/${user}_setting.conf 를 만듭니다(권한 600). awxkit/ 에는 빌드된 바이너리가 들어 있습니다. 빌드는 필요 없습니다.
  3. bash setup/setup_guide.sh 로 최상단 변수를 채웁니다. 또는 스크립트를 직접 편집합니다 (2.1절).
  4. 다른 폴더에서 실행해도 됩니다: bash /path/to/awx_script/01.AWX_nodeinfo_V2.sh. 스크립트가 자기 폴더로 이동합니다. /usr/local/bin 에 심볼릭 링크를 두지 마십시오. 대신 alias awx-nodeinfo='cd /path/to/awx_script && bash 01.AWX_nodeinfo_V2.sh' 를 쓰십시오.

2.2 입력 파일 ${user}.txt

  • nodeinfo 사용(Y): 호스트 이름을 한 줄에 하나씩 씁니다. awxkit/nodeinfo.sh 가 성공하면 결과로 ${user}.txt 를 덮어씁니다. 실패하면 기존 파일을 지킵니다.
  • nodeinfo 미사용(N): "msg": "..." 형식, 또는 12필드(vendor model infra hostname ip mac nic disk part 용량 os boot)를 씁니다.
  • 13번째 분류 태그(선택): 12필드 뒤에 공백 없는 한 단어(예: rhel810(TEST/SR))를 붙이면 yml 그룹을 나누는 키로만 씁니다. repohost 에는 12필드만 보냅니다.
  • 태그를 붙이는 방법: 먼저 Y 로 실행해 정리된 ${user}.txt 를 만듭니다. Ctrl+C 로 멈춥니다. 줄 끝에 태그를 붙입니다. N 으로 다시 실행합니다.

3. 01.AWX_nodeinfo_V2.sh 는 어떤 순서로 진행하나?

  1. [1] user 선택: LOG/${user}.log 에 기록을 시작합니다.
  2. [2] nodeinfo 사용 여부(Y/N): Y 면 awxkit/nodeinfo.sh 로 노드정보를 받습니다.
  3. [3~4] 정리: 메시지를 해석하고 infra 이름을 바꾸고 MAC 을 보정합니다(짝수 보정).
  4. [4-1] DNS 점검: /etc/resolv.conf 의 nameserver(최대 3)에 A 레코드를 직접 묻습니다. 결과는 일치·불일치·판단 불가·미등록·조회 실패 5종입니다. PTR 중복도 경고합니다. 대화형은 a/n/s/q 로 고릅니다. IP 를 바꾸면 5번째 필드만 바꾸고 로그에 [DNS] 로 기록합니다.
  5. [5~6] 대상 표시와 진행 확인: 대상 목록을 보여 주고 작업진행여부 (Y/N) 를 묻습니다. 필수 변수를 검사합니다.
  6. [7] 인벤토리 삭제: delhost_${user} 를 실행합니다. 되돌릴 수 없습니다.
  7. [8~11] 분할·등록 준비: 사양별 yml 과 _all yml 을 만듭니다. DHCP 정보를 모읍니다. repohost 로 보내 custom_inventory.sh 를 실행합니다. 인벤토리 YAML 을 업로드(동기화)합니다.
  8. [12] 접속 확인(선택, [Y/n]): gossh 로 LDAP URI·LACP 를 점검합니다. os8 에서 안 되는 서버는 os6_mgmt 에서 다시 조사합니다.
  9. [13] 메뉴: su(등록 진행) / exit / ls / <yml 파일명>
  10. [14] 02.source_dhcp_pxe.sh 실행: 4절을 보십시오.
  11. [14-1] auto_setup 전달: 02 가 성공하면 ${AUTO_SETUP_DIR:-/tmp/auto_setup}/queue/<epoch>_<user>_<pid>.job 을 씁니다. auto_setup_host 가 있으면 gossh 로 원격에 보냅니다. 실패해도 경고만 하고 등록 결과에는 영향이 없습니다.
  12. [15] 등록 후 확인: 등록 대상 서버 목록을 붙여 넣고 검증합니다(AWX_VERIFY_FILE 로 대신 가능).

4. 02.source_dhcp_pxe.sh 는 무엇을 하나?

  1. OS 버전을 고릅니다: 1) 2024, 2) 2025, 3) 2026, 4) 2026-OPC_MDP, 5) 2026-ECAD_TCAD(기본). 01 이 넘긴 os 값은 쓰지 않습니다. AWX_AUTO_OS 로 지정할 수 있습니다.
  2. 옵션 확인표를 봅니다. 고치려면 N 을 입력합니다. 13번째 태그 열도 보여 줍니다.
  3. yml 마다 차례로 invsync.sh 를 실행하고, 이어서 dhcp.sh 와 pxe.sh 를 동시에 실행합니다.
  4. 그룹 yml 이 2개 이상이고 모두 성공하면 _all yml 로 invsync.sh 를 1번 실행합니다. _all yml 은 DHCP·PXE 에 쓰지 않습니다.
  5. 최종 수량을 합산합니다 (On-premise=HPC, Cloud=SDS).
  6. (선택, [Y/n]) 파티션 표준을 gossh lsblk 로 확인합니다.

배치 인자 형식: <yml>=<infra>,<os>,<boot>,<splunk>[,<tag>]. 인자가 없으면 현재 폴더의 yml 1개로 대화형 실행합니다.

4.1 파티션 표준은 무엇인가?

  • 물리 파티션만 씁니다. LVM 은 안 됩니다.
  • OS 디스크(/)는 sda 또는 nvme0n1 입니다.
  • /boot(또는 /boot/efi)는 500M~512M 입니다.
  • / 는 30G, /var 는 20G 입니다.
  • swap 과 /tmp(나머지 전부)가 있어야 합니다.

5. yml 은 어떻게 나누고 splunk 값은 어떻게 정하나?

규칙내용
yml 분할 키infra + nic + disk + 용량 + os + boot + splunk + (선택) 13번째 태그. part 는 키가 아닙니다.
값 바꾸기1.1T→1200, 7T→7600, test1234→offchip, boot 레거시→legacy
splunk 자동 결정① 호스트 이름에 ev 가 있으면 no (가장 우선) ② s 로 시작하면 Cloud ③ 그 밖에는 On-premise. 예: spice01ev02→no, spice01→Cloud, node01→On-premise

7. 문제가 생기면?

  • DHCP/PXE 가 infra 선택지 오류를 낸다: 02 는 infra 를 소문자로 넘깁니다. awxkit conf 의 *_choices 와 같아야 합니다. 확인표에서 N 으로 고치거나 dhcp_infra_alias/pxe_infra_alias 를 쓰십시오.
  • 용량 값이 이상하다: 7T→7600 치환은 17T 같은 값에도 적용될 수 있습니다. 결과를 확인하십시오.
  • yml 이 덮어써졌다: 같은 초에 같은 infra 그룹을 만들면 custom_inventory.sh 가 덮어쓸 수 있습니다. 생성 전후를 비교하십시오.
  • user 값이 없다고 끝난다: user() 의 user_route 를 채우십시오. 또는 AWX_USER 를 쓰십시오.
  • 임시 파일이 남았다: 정상 종료 때 임시 폴더와 gossh 결과 파일(_res_off 등)을 지웁니다. 임시 파일은 /tmp/auto_setup/tmp 를 먼저 씁니다.

8. 자주 묻는 질문 (FAQ)

Q. awx_script 는 무엇을 하는 도구인가요?
A. HPC 서버를 AWX OS 설치에 등록하는 스크립트 묶음입니다. 노드정보 수집부터 인벤토리 동기화, DHCP·PXE 등록, auto_setup 감시 전달까지 합니다.

Q. 새 서버에 OS 를 설치하려면 무엇부터 하나요?
A. ${user}.txt 에 호스트 이름을 적고 bash 01.AWX_nodeinfo_V2.sh 를 실행합니다. 등록이 끝나면 auto_setup 이 설치 완료를 감시합니다.

Q. 작업 진행에 y 를 누르면 무엇이 삭제되나요?
A. inventory_delete_host 에서 delhost_${user} 를 실행해 기존 인벤토리 호스트를 지웁니다. 되돌릴 수 없습니다.

Q. OS 버전은 어디서 고르나요?
A. 02.source_dhcp_pxe.sh 에서 고릅니다. 기본은 5) 2026-ECAD_TCAD 입니다. AWX_AUTO_OS 로 미리 정할 수 있습니다.

Q. 서로 다른 사양을 한 번에 등록할 수 있나요?
A. 예. 사양(infra·nic·disk·용량·os·boot·splunk·태그)별로 yml 을 나눠 차례로 등록합니다.

Q. 등록 후 OS 설치가 끝났는지 어떻게 아나요?
A. auto_setup 이 자동으로 감시합니다. 직접 판정하려면 setup_check 나 pm_monitor 를 쓰십시오.
