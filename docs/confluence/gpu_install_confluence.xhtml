안녕하세요.

폐쇄망 GPU 서버들에 지정한 NVIDIA 드라이버(.run)를 설치하고, 설치된 드라이버의 CUDA 버전(nvidia-smi 기준)에 맞는 DCGM 4를 일괄 설치·활성화하는 gpu_install 도구의 초기 설정 방법과 실행 화면 기준 항목별 사용법을 안내드립니다.

한눈에 보는 전체 사용 흐름
  1. 초기 1회 준비: 관리 서버 같은 폴더에 gpu_install.sh·gpu_install_os8·list를 배치하고 gpu_install.sh 상단 변수(AUTOFS_PATH, MOUNT_USER, GOSSH) 확인
  2. 버전 확인 및 시작 경고: 버전이 비어 있는 줄이 있으면 .run 목록에서 1회 선택 후, 빨간 경고 대상 목록을 확인하고 y 입력
  3. 현황 수집 및 재설치 확인: gossh로 드라이버·CUDA·사전점검 항목 및 mount/scp 방식을 판정한 뒤 기존 드라이버 보유 서버의 재설치 여부(a/s/n) 선택
  4. 드라이버·DCGM 4·/etc/rc.local 병렬 실행: 최대 -p N대씩 동시 설치 (드라이버 실패 시 서비스 중지·모듈 언로드 후 1회 자동 재시도)
  5. 결과 표 및 실패 목록 생성: HOST | 방식 | 이전→설치버전 | CUDA | DCGM | dcgm상태 | 결과 출력 및 실패 건 fail_list·fail_list.retry 저장
  6. 장애 확인 및 재시도: 호스트별 상세 로그(logs/<날짜시각>/<호스트>.log)로 원인 확인 후 fail_list.retry를 그대로 지정해 재실행

0. 설치·실행 및 초기 설정 (폐쇄망 · gpu_install.sh · list)

구성 항목설정 및 동작 설명
gpu_install_os8RHEL 8 / Rocky 8 관리 서버용 Linux amd64 정적 바이너리(CGO_ENABLED=0)입니다. gpu_install.sh와 같은 폴더에 두고 실행 권한(chmod +x gpu_install_os8)을 부여합니다.
gpu_install.sh인자(autofs경로, list파일, -p 동시대수)와 상단 설정 변수를 정리해 gpu_install_os8을 실행하는 래퍼 스크립트입니다.
필수 의존 도구 (관리/대상 서버)관리 서버에 gossh(gossh_os8)와 scp가 있어야 하며 대상 서버에 root로 키 접속이 가능해야 합니다. 대상 서버에는 현재 커널의 kernel-devel·gcc와 DCGM RPM이 포함된 /etc/yum.repos.d/rhel.repo(baseurl=file://..., enabled=0)가 준비되어 있어야 합니다.
설치 파일 규칙 (.run)<autofs경로>/NVIDIA-Linux-x86_64-<버전>.run 형태여야 하며, list에 적힌 버전의 .run 파일이 없으면 시작 전에 오류를 내고 중단합니다.

3. 현황 수집 · 방식 판정 · 재설치 확인

solid#cbd5e1#f8fafc

▲ 1회 gossh 현황 수집 표(방식·비고 포함) → 기존 드라이버 재설치 여부(a/s/n) → 동일 버전 DCGM 단독 복구
번호항목설명
①호스트별 현황 수집 표대상마다 gossh를 1회 실행해 hostname, 현재 설치된 드라이버 버전, CUDA 버전, 요청 버전을 한눈에 비교합니다.
②설치 방식 자동 판정 (mount / scp)대상 서버에서 /user/<MOUNT_USER> 접근과 .run 파일 읽기가 모두 가능하면 mount, 아니면 scp 방식으로 자동 분류합니다. (MOUNT_USER가 비어 있으면 전체 scp)
③비고 (사전점검 · 경고 · 응답 실패)GPU 없음, kernel-devel 없음, gcc 없음, nouveau 로드됨, fabricmanager 버전 맞춤 필요(NVSwitch 장비 경고), fail: 응답 없음 등 주의 항목을 표시합니다.
④기존 드라이버 재설치 확인 (a/s/n)이미 드라이버가 설치된 서버를 현재버전 → 요청버전으로 보여 주고 a(전체 재설치)·s(번호 골라서)·n(건너뛰기) 중 선택합니다. 현재와 요청 버전이 같은 서버는 a를 선택해도 기본 건너뛰며, s로 직접 고른 경우에만 재설치합니다.
⑤동일 버전 DCGM 단독 복구 안내드라이버 버전이 같아 건너뛴 서버 중 GPU가 있고 DCGM 서비스가 비정상(inactive·패키지 누락·GPU 0대)인 호스트는 드라이버를 건너뛰고 DCGM만 자동으로 다시 맞춥니다.

4. 드라이버 · DCGM 4 · /etc/rc.local 병렬 실행

solid#cbd5e1#f8fafc

▲ 호스트별 로그 디렉토리 생성 → 드라이버 설치 및 1회 재시도 → DCGM 4 설치 → /etc/rc.local 실행
번호항목설명
①호스트별 실행 로그 경로현재 디렉토리 아래 logs/<날짜시각>/<호스트>.log가 생성되어 서버별 원격 명령 출력 전체가 기록됩니다.
②NVIDIA 드라이버 설치 & 1회 자동 재시도mount는 대상에서 sh <autofs경로>/<run> -s를 바로 실행하고, scp는 대상 /tmp/gpu_install로 전송·실행 후 삭제합니다. 1차 실패 시 nvidia-dcgm·nvidia-persistenced·nvidia-fabricmanager를 중지하고 커널 모듈(rmmod)을 내린 뒤 1회 재시도합니다.
③DCGM 4 설치 및 서비스 활성화설치 후 nvidia-smi의 CUDA 12/13 버전에 맞는 datacenter-gpu-manager-4 패키지 4종을 설치(CUDA 12↔13 변경 시 교체)하고 nvidia-dcgm을 enable·start한 뒤 dcgmi로 GPU 인식을 확인합니다. mount는 설치 중만 rhel.repo를 enabled=1로 전환 후 성공·실패·중단 모두 0으로 복구하며, scp는 관리 서버 baseurl 경로에서 RPM과 부족한 의존성 RPM을 전송해 설치합니다. (CUDA 12/13 외는 DCGM 건너뜀)
④/etc/rc.local 실행 (성공 서버)드라이버·DCGM까지 성공한 서버에서 /etc/rc.local을 최대 10분 제한으로 실행합니다. 파일이 없으면 건너뛰며, 실행 권한이 없으면 bash로 실행하고 실패 시 rc.local failed(rc=N)로 실패 처리합니다.

번호항목설명
①최종 결과 표 컬럼 (7열)모든 병렬 작업이 끝나면 HOST | 방식 | 이전→설치버전 | CUDA | DCGM | dcgm상태 | 결과 표가 출력됩니다.
②성공(ok) 및 건너뜀(skip) 표시정상 완료는 ok, CUDA 12/13이 아닌 드라이버는 DCGM 칸에 skip(CUDA ...), 동일 버전으로 건너뛴 서버는 기존 DCGM 상태와 함께 skip: 같은 버전 설치됨으로 표시됩니다.
③실패(fail) 및 fail_list / fail_list.retry실패한 호스트가 있으면 사유(dcgm inactive, 응답 없음, install failed(retry after unload) 등)와 함께 빨간색 목록을 출력하고, 현재 디렉토리에 fail_list(호스트 버전 사유)와 fail_list.retry(호스트 버전)를 생성합니다. 실패가 0대면 이전 실행의 두 파일을 자동 삭제합니다.

▲ -h 도움말 · 호스트 로그(lsof 점유 프로세스 진단) · fail_list.retry 재실행
번호항목설명

③fail_list.retry 그대로 재실행점유 프로세스 정리 등 조치 후 생성된 fail_list.retry를 두 번째 인자로 넘겨 실패 호스트만 즉시 재실행할 수 있습니다.
사용 시 참고 팁
  • 재부팅 미수행 원칙: gpu_install은 대상 서버를 자동으로 재부팅하지 않습니다. 모듈 교체만으로 nvidia-smi가 새 버전을 보고하지 않거나 언로드가 불가능한 경우에는 점유 프로세스를 정리한 뒤 필요 시 직접 재부팅하세요.
  • NVSwitch / fabricmanager 장비 주의: NVSwitch가 감지되거나 nvidia-fabricmanager가 있는 서버는 현황 표에 경고만 표시되며 자동 설치하지 않습니다. 드라이버 버전에 맞춰 별도로 버전을 일치시켜 주세요.
  • 프로세스 강제 종료 금지: GPU 장치를 점유 중인 프로세스가 있어 모듈을 내리지 못해도 도구가 임의로 kill하지 않고 lsof 내역만 로그에 남긴 뒤 실패 처리합니다.
  • MOUNT_USER를 비운 경우: gpu_install.sh의 MOUNT_USER가 비어 있으면 마운트 판정을 하지 않고 모든 서버를 scp 방식으로 처리합니다.
  • 작업 후 교차 확인: 도구는 참고용 보조 수단이므로, 일괄 작업 완료 후 대표 서버 몇 대에 직접 접속해 nvidia-smi와 systemctl status nvidia-dcgm을 최종 확인하시기 바랍니다.
