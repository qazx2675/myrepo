copy — ETX · AWX · Windows 단방향 클립보드 브릿지

요약: ETX 리눅스 환경과 로컬 Windows PC 간 직접 SSH/네트워크 연결이 없는 망분리 환경에서, 양쪽이 공통으로 접근 가능한 AWX Job Template의 description 필드를 중계 버퍼로 삼아 텍스트를 Windows 클립보드로 안전하게 전달하는 경량 Go 도구 세트(copy-send + copy-widget.exe)입니다.

저장소 기준: origin/master · .claude/HPC/copy (외부 의존성 0개 · Go 표준 라이브러리 전용)

전용 더미 템플릿 및 보안 주의사항
  • 전용 더미 Job Template만 사용: AWX Job Template의 description 필드를 덮어쓰고(PATCH), 수신 즉시 비웁니다. 실제 운영 설명이 들어 있는 템플릿을 지정하면 기존 설명이 유실됩니다.
  • 기밀·개인정보 전송 금지: AWX에서 해당 템플릿 읽기 권한이 있는 사용자는 모두 description을 열람할 수 있으므로 비밀번호·토큰·개인정보를 절대 전송하지 마세요.
  • 설정 파일 권한: conf/copy_setting.conf에는 AWX 계정의 평문 password가 저장됩니다. Git 커밋 제외 대상(.gitignore)이며 Linux는 chmod 600, Windows는 본인만 읽기 권한을 설정하세요.

1. 개요 및 아키텍처 · 통신 경로

copy는 ETX 측 CLI 송신기(copy-send / send.sh)와 Windows 측 Win32 항상-위 미니 위젯(copy-widget.exe)으로 구성됩니다. 두 지점은 서로 직접 통신하지 않고, 양쪽에서 모두 HTTP/HTTPS Basic Auth로 접근 가능한 AWX REST API(Job Template description)만 경유합니다.

text ETX → AWX Job Template description → Windows 클립보드 릴레이 경로

1.1 안전한 전송/정리 순서 보장

  • 송신 측 보호 (-force 기본 false): copy-send는 PATCH 전 AWX 템플릿 description을 조회하여 공백 제외 기존 내용(strings.TrimSpace(tpl.Description) != "")이 남아 있으면 Windows에서 아직 수거하지 않은 데이터로 간주하고 덮어쓰기를 거부합니다(종료 코드 1).
  • 수신 측 원자적 순서: copy-widget.exe는 setClipboardText가 CF_UNICODETEXT 기록에 성공한 이후에만 ClearDescription(PATCH 빈 문자열)을 호출합니다. 클립보드 복사가 실패하면 AWX 데이터를 비우지 않고, 반대로 복사는 성공했으나 비우기에 실패한 경우 "경고" 다이얼로그를 띄워 운영자가 인지할 수 있게 합니다.

2. 사전준비 · 폐쇄망 빌드 · 권한 및 환경설정

2.1 Go 버전 및 표준 라이브러리 전용 구조

이 프로젝트는 Go 표준 라이브러리만 사용하며 외부 패키지 의존성(require)과 vendor/가 전혀 없습니다. 따라서 ETX 폐쇄망에서도 인터넷·모듈 프록시 없이 빌드됩니다(go.mod 기준 go 1.26.5, 저장소 README 표기 1.27.0). Windows 위젯은 //go:build windows 태그와 syscall Win32 DLL(user32.dll, kernel32.dll, gdi32.dll)을 직접 호출하며, 비-Windows 빌드용 스텁(main_other.go)이 분리되어 있습니다.

bash ETX(Linux) 폐쇄망 빌드 및 검증 (setup.sh) powershell Windows(amd64) 위젯 빌드 (build.bat) Windows에서 go vet ./... 실행 시 오탐 참고

Windows 환경에서 go vet ./... 전체를 실행할 경우 cmd/copy-widget/main_windows.go의 Win32 GlobalLock 포인터 변환부에서 Go vet의 possible misuse of unsafe.Pointer 오탐 경고가 발생할 수 있습니다. ETX/Linux용 정적 검사 시에는 go vet ./cmd/copy-send/... ./internal/... 경로를 사용하세요.

2.2 설정 파일 탐색 순서 (ResolvePath)

copy-send와 copy-widget.exe는 아래 4단계 우선순위로 copy_setting.conf를 자동 탐색하며, ETX와 Windows 양쪽에 동일한 설정 내용을 둡니다.

  1. 명령줄 -conf <경로> 플래그로 직접 지정한 경로
  2. 현재 작업 디렉터리 기준 ./conf/copy_setting.conf
  3. 실행 바이너리 위치 기준 <exe_dir>/conf/copy_setting.conf
  4. 사용자 홈 디렉터리 ~/.copy-bridge/copy_setting.conf

3. 기동 및 표준 사용 흐름

3.1 ETX 송신 → Windows 수신 표준 절차

bash ETX 표준 전송 명령
  1. ETX 텍스트 작성 및 전송: ${USER}_copy.txt를 작성한 뒤 ./send.sh를 실행하면 copy-send가 줄 수(max_lines)와 기존 템플릿 잔여 데이터를 검증한 후 AWX description에 업로드합니다.
  2. Windows 위젯 실행 및 수신: PC에서 dist\copy-widget.exe를 실행하면 우상단 등 원하는 위치로 드래그할 수 있는 110×90 크기의 항상-위 창(제목: "복사 브릿지", 버튼 라벨: "📋 불러오기")이 뜹니다.
  3. 클립보드 로드 및 확인: 위젯을 좌클릭하면 AWX에서 텍스트를 가져와(CF_UNICODETEXT, TrimSpace 없이 원본 그대로) Windows 클립보드에 넣고 AWX description을 비운 뒤 미리보기 메시지 창을 띄웁니다.
  4. 첫 붙여넣기 육안 검증: 첫 사용 시 또는 특수문자·탭·다중 줄이 포함된 경우 메모장 등에 Ctrl+V로 붙여넣어 줄바꿈과 인코딩을 육안으로 확인하세요.

4. CLI · 위젯 조작 · 설정키 표

4.1 copy-send CLI 플래그 및 종료 코드

플래그 기본값 설명
-conf 자동 탐색 (ResolvePath) 사용할 copy_setting.conf 경로 지정
-file {user}_copy.txt 전송할 텍스트 파일 경로. 미지정 시 -user(또는 $USER) 기반 파일명 사용
-user $USER -file 미지정 시 {user}_copy.txt 파일명을 결정하는 사용자명
-force false AWX Job Template description에 아직 비워지지 않은 데이터가 있어도 덮어쓰기 허용

종료 코드: 성공 시 0, 설정 로드 실패·파일 읽기 실패·max_lines 초과·미수신 데이터 잔존(-force 미사용)·AWX HTTP API 오류 시 1.

4.2 copy-widget.exe 플래그 및 마우스 조작

copy-widget.exe는 CLI 플래그로 -conf <경로>(copy-send와 동일한 ResolvePath 순서)만 지원합니다.

마우스 조작 판정 조건 동작
좌클릭 이동 거리 abs(dx) <= 3 && abs(dy) <= 3 AWX GET(15s 타임아웃) → 비어 있으면 "새로 등록된 데이터가 없습니다." 안내 → CF_UNICODETEXT 클립보드 기록 → ClearDescription 호출 → 미리보기 MessageBox 표시
드래그 좌클릭 이동 거리 초과 드래그 항상 위(WS_EX_TOPMOST | WS_EX_TOOLWINDOW) 상태를 유지한 채 위젯 창 위치 이동
우클릭 창 위에서 마우스 오른쪽 클릭 위젯 즉시 종료 (DestroyWindow)

4.3 copy_setting.conf 설정 키 (6개)

키 이름 필수 여부 기본값 / 형식 설명
awx_url 필수 URL (예: https://awx.example.local) ETX와 Windows가 공통으로 접근 가능한 AWX 서버 주소
username 필수 문자열 AWX HTTP Basic Auth 사용자명
password 선택(실사용 권장) 문자열 AWX HTTP Basic Auth 비밀번호 (평문 저장 주의)
insecure_tls 선택 false true / yes / y / 1 / on(대소문자 무관) 설정 시 사설 인증서 TLS 검증 생략
template 필수 ID(숫자) 또는 Job Template 이름 데이터 중계 버퍼로 사용할 AWX 전용 더미 Job Template
max_lines 선택 200 1회 전송 허용 최대 줄 수 (strings.Count(text, "\n") + 1). 0 이하 지정 시 줄 수 제한 비활성화

5. 장애/로그 확인 및 운영 제약사항 · 주의사항

  • 미리보기 다이얼로그 잘림 현상: 수신 텍스트가 2,000바이트를 초과하면 Windows MessageBox 화면에는 ...(이하 생략, 클립보드에는 전체가 복사됨)으로 요약 표시됩니다. 실제 클립보드(CF_UNICODETEXT)에는 원본 전체가 손실 없이 들어가므로 그대로 Ctrl+V 하면 됩니다.
  • description 잔존 오류로 송신 실패: 이전 데이터를 Windows에서 아직 불러오지 않았거나 이전 위젯 비우기(PATCH)가 권한 부족으로 실패한 경우 copy-send가 종료 코드 1로 중단됩니다. Windows에서 먼저 불러오기를 수행하거나 ./send.sh -force로 강제 덮어씁니다.
  • AWX ClearDescription 경고 창: 클립보드 복사는 성공했으나 AWX API로 description 비우기에 실패하면 "경고" 다이얼로그가 표시됩니다. AWX 계정에 해당 Job Template 수정(PATCH) 권한이 있는지 확인하세요.
  • 대용량 텍스트 분할 전송: 기본 max_lines = 200 초과 시 copy-send가 업로드를 거부합니다. 대용량 로그는 200줄 단위로 나누어 전송하거나, 불가피한 경우에만 ETX·Windows 설정의 max_lines를 조정(또는 0)하세요.
  • 줄바꿈·인코딩 보존: 위젯은 수신 본문을 TrimSpace로 가공하지 않고 원형 그대로 UTF-16(CF_UNICODETEXT) 클립보드에 넣으므로 앞뒤 공백과 빈 줄도 유지됩니다. 첫 운영 시 Ctrl+V 결과를 반드시 육안 확인하세요.
