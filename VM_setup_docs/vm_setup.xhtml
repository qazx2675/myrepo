Suite 요약 및 문서 기준

VM_setup (V1)은 vSphere / ESXi 초기 호스트 연결부터 라이선스 할당, vSwitch, VM 생성(ev01~ev03), 성능/토폴로지 파라미터 설정, MAC/프로비저닝 정보 수집 및 CSV 기반 사후 보정까지 수행하는 레거시 V1 CLI 도구 모음입니다.

  • 원본 저장소 경로 (origin/master 기준): .claude/VM/VM_setup
  • 문서 대상 브랜치: confluence (VM_setup_docs/)
  • 구성 요소: Go 소스 기반 하위 도구 9종(*-source), CSV 기반 보정 오케스트레이터(vm-param-fix), 소스 미보유 단독 바이너리(vm-param-fix/power_setting)
  • 후속 버전 안내: 신규 구축에는 V2 Suite(.claude/VM/V2)를, 파라미터 점검 및 보정에는 단일 바이너리 vm-param-check -fix를 사용하는 것이 권장됩니다.

1. Suite 전체 개요 및 단계별 전체 흐름

VM_setup은 V2와 달리 원스톱 통합 구축 스크립트(vm_setup.sh), 중앙 스펙 디렉터리(SPEC_DIR), 암호화된 비밀번호 관리(passwd_update.sh)가 없는 V1 수동 실행 체계입니다. 운영자가 worklist.txt 등의 입력 파일과 환경변수(VC_PASSWORD)를 직접 준비하여 각 하위 도구를 단계별로 실행합니다.

3. 일괄 오프라인 빌드 및 배치

V1 저장소에는 루트 통합 setup.sh나 공유 govendor/ 디렉터리가 없습니다. 대신 9개의 *-source/ 디렉터리와 vm-param-fix/ 디렉터리 각각에 독립적인 vendor/ 및 setup.sh가 포함되어 있어 폐쇄망에서 GOFLAGS=-mod=vendor 방식으로 개별 오프라인 빌드를 수행합니다.

절대 삭제/덮어쓰기 금지: power_setting 바이너리 전용 보존 경고

vm-param-fix/power_setting 파일은 컴파일된 바이너리 형태로만 보관되어 있으며, Rocky Linux 원본 빌드 환경(/root/pro/main.go 등)을 전수 확인한 결과에서도 해당 플래그(-vcTargetIP, -worklistFile, 기본값 -worklistBmFile)와 일치하는 Go 소스를 확인할 수 없었습니다.

  • 이 바이너리는 재빌드가 불가능한 유일한 원본 사본이므로 절대 삭제하거나 덮어쓰지 마십시오.
  • 후속 도구인 vm-param-check는 호스트 전원 정책을 점검만 수행하며 자동 수정 기능은 제공하지 않습니다. 따라서 CSV 기반 전원 정책 자동 보정이 다시 필요하다면 기존 power_setting 바이너리를 vm-param-fix를 통해 재사용하거나 신규 구현해야 합니다. (참고: V2의 VMsetup/power_setting-source는 High Performance 전원 정책을 단독으로 일괄 적용하는 별도 도구입니다.)

4. 통합 보정(vm-param-fix) vs 하위 도구 단독 실행법

VM_setup에는 V2의 vm_setup.sh와 같은 구축 단계 통합 실행기가 없으므로, 초기 구축 시 각 *-source 바이너리를 순서대로 단독 실행해야 합니다. 반면 구축/점검 이후 발생한 파라미터 불일치 보정은 레거시 오케스트레이터인 vm-param-fix로 일괄 수행합니다.

4.1 vm-param-fix 기반 일괄 보정 동작 구조

  • 사전 안전 게이트(Safety Gates): 입력된 상세 점검 CSV(-checkResult)를 기반으로 ① 호스트 간 하드웨어/구성 동질성(Homogeneity) 검사, ② 호스트별 ev01/ev02/ev03 VM 수량 일치 검사, ③ 보정 대상 VM 전원 OFF 상태를 먼저 검증합니다.
  • 점검 항목 태그 분류(Tag Mapping):
    • sched.vcpuN.affinity → affinity 그룹 (-affinityTool, 기본값 ./affinity_setting 호출)
    • HugePage 및 CPU 토폴로지 관련 8개 키 → lpage 그룹 (-lpageTool, 기본값 ./lpage_setting 호출)
    • host power policy → power 그룹 (-powerTool, 기본값 ./power_setting 바이너리 호출)
    • 그 외 모든 불일치 항목 → manual 분류 (자동 수정 제외, 운영자 수동 조치)
  • 모의 테스트(Mock) 및 재검증: 외부 도구 경로 플래그(-affinityTool, -lpageTool, -powerTool, -recheckTool)를 Mock 스크립트로 대체해 동작 검증이 가능하며, 보정 완료 후 -recheckTool(기본 ./vm-param-check)을 호출해 결과를 -out으로 기록합니다.

6. 통합 주의사항, 롤백/실서버 확인 및 레거시/대체 관계

운영 실서버 무작위 표본 검증 및 롤백 불가 주의
  • 면책 및 실서버 확인 필수: 본 문서의 절차와 자동 실행 도구는 편의와 반복 작업 절감을 위해 작성되었으나, 대상 인프라 상태에 따라 의도치 않은 장애를 유발할 수 있습니다. 작업 완료 후에는 반드시 무작위로 선정한 실서버(ESXi 호스트 및 VM)에 직접 접속하여 호스트 등록, vSwitch, VM 스펙, Affinity/HugePage/NUMA 값, 전원/라이선스 상태를 육안 및 명령어로 재확인하십시오.
  • 자동 롤백 미지원: VM_setup의 모든 도구는 실패 시 이전 상태로 되돌리는 롤백(Rollback) 기능을 제공하지 않습니다. 실행 전 worklist.txt 대상 범위를 최소화해 검증하고 기존 vCenter/VM 설정을 백업하십시오.
 V1 개별 도구 운용 시 주의사항 및 제약 사항
  • tag_setting 병렬 폭주 위험: 동시성 제어 세마포어가 구현되어 있지 않으므로 대량 호스트/VM에 한 번에 실행하면 vCenter API 부하가 급증할 수 있습니다. 또한 vCenter에 DEPT_NAME, PURPOSE, VM_TYPE Custom Attributes가 미리 존재해야 오류가 발생하지 않습니다.
  • vm-param-fix의 ev03 한계: 레거시 외부 도구 호출 구조상 ev03 관련 자동 보정에 제약이 있습니다.
  • numa_preferht_setting 전원 상태 조건: 전원이 꺼진(PoweredOff) VM만 변경하며, 일괄 검증에서 단 1건이라도 불일치하거나 오류가 발생하면 종료 코드 2를 반환합니다.
  • mac_info 출력 식별자 주의: VMware Tools 또는 DNS 정보가 조회되지 않는 VM은 출력 파일(Provisioning_List_*.txt)의 IP 자리에 <VM>_DNS_AND_TOOLS_NOT_FOUND 문자열이 기록되므로 후속 자동화 파싱 전 확인이 필요합니다.

6.1 레거시 V1(VM_setup) vs V2(.claude/VM/V2) 및 vm-param-check -fix 전환 비교

VM_setup은 초기 V1 도구 모음이며, 이후 유지보수성·보안·다중 VM 확장을 위해 V2 및 vm-param-check -fix로 대체되었습니다.
