2. 처음 사용하기 전에 무엇을 준비하나?

2.1 실행 파일 확인

  1. 관리 서버의 ldap_setting 폴더로 이동합니다.
  2. 실행 권한을 줍니다: chmod +x bin/ldap-config-engine bin/ldap-config-engine_os6 scripts/*.sh
  3. gossh 가 v2 인지 확인합니다: gossh -h 출력에 -cf 와 -b 가 있어야 합니다.

2.2 입력 파일 준비

  1. 샘플을 복사합니다: cp conf/ldap_config.conf.sample conf/ldap_config.conf, cp conf/assets.txt.sample conf/assets.txt
  2. conf/ldap_config.conf 에 인프라·사이트 값을 채웁니다 (7.3절 참고).
  3. 권한을 600 으로 바꿉니다: chmod 600 conf/ldap_config.conf. 이 파일에는 bindpw 가 평문으로 들어 있습니다.
  4. conf/assets.txt 에 hostname<TAB>site 를 한 줄에 하나씩 적습니다.
text
  • conf/ldap_config.conf 는 ldap_check 의 ldap_config.conf 와 같은 내용이어야 합니다.
  • 사이트는 항상 assets.txt 에서 찾습니다. -host-file 로 준 목록({계정명}.txt)은 호스트 이름만 담습니다.
  • 자산현황에 없는 VM 은 이름 끝의 ev01~ev03 을 떼고 BM 이름으로 다시 찾습니다. 그래도 없으면 default_site 를 씁니다. default_site 도 없으면 경고하고 건너뜁니다.

3. ldap_setting 은 어떤 파일을 바꾸나?

#파일바꾸는 내용
1/etc/openldap/ldap.confURI(사이트별 순서), BINDDN, BINDPW
2/etc/autofs_ldap_auth.confuser=, secret= (권한 600)
3/etc/autofs.confldap_uri="..." (ldap.conf 와 같은 순서). 다른 설정은 그대로 둡니다.
4/etc/nslcd.conf 또는 /etc/sssd/sssd.confRHEL 7 이하와 s4 예외 서버는 nslcd.conf, RHEL 8 이상은 sssd.conf (권한 600). sssd.conf 에 [domain/...] 섹션이 없으면 FAIL 입니다. 새 파일을 만들지 않습니다.
5/etc/resolv.confnameserver 줄
6/etc/ntp.conf 또는 /etc/chrony.confRHEL 7 이하와 s4 예외 서버는 ntp.conf, RHEL 8 이상은 chrony.conf. server 줄을 바꾸고 pool 줄을 지웁니다.
7/etc/auto.appl.bak (원복 뒤 /etc/auto.appl)/appl 줄의 스토리지·마운트 경로를 새로 씁니다. 새 내용은 /etc/auto.appl.bak 에서 대기합니다. 4절을 보십시오.

/etc/sudo-ldap.conf 는 파일이 있을 때만 URI 줄을 바꿉니다.

4. auto.appl 은 왜 바로 바뀌지 않나? (대기와 원복)

  1. 적용하면 기존 /etc/auto.appl 을 .bak.<시각> 으로 백업합니다. 참고용 사본 /etc/auto.appl_back 도 남깁니다.
  2. 새 내용은 /etc/auto.appl.bak 에 씁니다. 기존 /etc/auto.appl 은 치웁니다. 이유: 적용 중에 autofs 가 멈출 수 있기 때문입니다.
  3. 네트워크 설정이 끝나면 대기 내용을 반영합니다. 서버에서 /root/auto_appl_restore.sh 를 실행하거나, auto_setup 에서 m → 5 auto.appl 원복 을 실행합니다.
  4. ./scripts/deploy_ldap.sh -infra <인프라> -check-only 로 다시 검증합니다.

원복 전에는 ldap_check.sh 가 auto.appl 기준 판별에서 FAIL 을 출력합니다. 정상입니다. 원복한 뒤 다시 검증하십시오.

5. 표준 적용 절차는 무엇인가? (안전 순서)

5.1 deploy_ldap.sh 로 적용

  1. 미리 봅니다: ./scripts/deploy_ldap.sh -infra zxcv -dry-run. 서버 파일을 바꾸지 않습니다.
  2. (선택) 서버에서 실행될 스크립트를 봅니다: ./bin/ldap-config-engine -config conf/ldap_config.conf -infra zxcv -site a1 -print-script
  3. 1대에 먼저 적용합니다: ./bin/ldap-config-engine -config conf/ldap_config.conf -assets conf/assets.txt -infra zxcv -host svr001
  4. 그 서버에 로그인하고 id <계정>, ls /appl 을 확인합니다.
  5. 전체에 적용합니다: ./scripts/deploy_ldap.sh -infra zxcv. 적용 뒤 ldap_check.sh 로 자동 검증합니다.
  6. auto.appl 을 원복합니다 (4절).
  7. 다시 검증합니다: ./scripts/deploy_ldap.sh -infra zxcv -check-only

검증 스크립트는 공유 경로 /user/asdf/ldap_check.sh(SHARED_CHECK)를 씁니다. 공유 경로가 마운트되지 않은 서버에는 CHECK_LOCAL(../../ldap_check/ldap_check.sh)을 /root/ldap_check.sh 로 보내 실행하고 지웁니다.

5.2 메뉴 래퍼 run.sh 로 적용

  1. ./scripts/run.sh 를 실행합니다. 플래그는 필요 없습니다.
  2. 메뉴에서 실행 계정을 고릅니다. 계정의 서버 목록은 scripts/{계정명}.txt 입니다.
  3. 메뉴에서 인프라를 고릅니다. ldap_config.conf 에 있는 인프라만 나옵니다.
  4. DRY-RUN 결과를 확인합니다.
  5. 정확히 yes 를 입력합니다. 적용합니다.
  6. run.sh 는 검증을 하지 않습니다. 끝난 뒤 ./scripts/deploy_ldap.sh -infra <인프라> -check-only 를 실행하십시오.

5.3 auto_setup 의 m 메뉴로 적용 (os8_mgmt 전용)

  1. /etc/auto_setup/auto_setup.conf 에 enable_ldap_change=y 를 씁니다. 필요하면 ldap_engine 경로도 씁니다.
  2. /etc/auto_setup/ldap_config.conf(권한 600)와 /etc/auto_setup/assets.txt 를 준비합니다.
  3. auto_setup 화면에서 m → 2 LDAP 변경(또는 3 IP+LDAP 변경)을 고릅니다.
  4. user 와 인프라를 고릅니다.
  5. 대상 서버 목록을 붙여 넣고 Ctrl+D 를 누릅니다. -dry-run 결과가 먼저 나옵니다.
  6. 정확히 yes 를 입력합니다. os8_mgmt 에서 먼저 실행합니다. 응답하지 않은 서버만 os6_mgmt 를 거쳐 다시 실행합니다.
  7. m → 5 auto.appl 원복 을 실행합니다.
  8. ldap_check.sh 로 검증합니다.

auto_setup 은 항상 -no-restart 를 붙입니다. 그래서 서비스를 재시작하지 않습니다.

6. 잘못 적용했으면 어떻게 되돌리나? (롤백)

파일을 직접 복사하지 마십시오. 서비스 재시작을 빠뜨리기 쉽습니다. 내장 롤백을 쓰십시오.

  1. 백업 시점을 봅니다: ./scripts/deploy_ldap.sh -list-backups
  2. 복원될 파일을 미리 봅니다: ./scripts/deploy_ldap.sh -rollback -dry-run
  3. 되돌립니다: ./scripts/deploy_ldap.sh -rollback -infra zxcv (최근 시점) 또는 ./scripts/deploy_ldap.sh -rollback-to 20260907153012 -infra zxcv (지정 시점)
  4. -infra 를 같이 주면 되돌린 뒤 검증까지 합니다.
복원한 파일재시작하는 서비스 (-no-restart 가 없을 때)
ldap.conf, resolv.conf없음
nslcd.confnslcd
sssd.confsss_cache -E 실행 후 sssd
autofs.conf, autofs_ldap_auth.conf, auto.applautofs
ntp.confntpd
chrony.confchronyd
  • 한 번 실행에서 만든 백업은 모두 같은 14자리 시점을 씁니다. 파일마다 처음 바꾸기 전에 한 번만 백업합니다.
  • 롤백은 새 백업을 만들지 않습니다. 같은 시점으로 두 번 되돌리면 NOCHANGE 를 출력합니다.
  • 적용 때 새로 만든 파일(예: autofs_ldap_auth.conf)은 백업이 없습니다. 롤백은 그 파일을 지우지 않고 NO-BACKUP 으로 보고합니다. 필요하면 직접 지우십시오.
  • 백업 파일은 자동으로 지우지 않습니다. 주기적으로 정리하십시오.

8. 문제가 생기면?

  • 적용 뒤 로그인이 안 된다: 6절의 롤백을 실행하십시오. ./scripts/deploy_ldap.sh -rollback -infra <인프라>
  • 검증에서 auto.appl 이 FAIL 이다: auto.appl 원복 전이면 정상입니다. 4절대로 원복하고 -check-only 로 다시 검증하십시오.
  • DNS 가 원래대로 돌아왔다: NetworkManager 가 재시작하면서 /etc/resolv.conf 를 덮어쓸 수 있습니다. NetworkManager 설정은 이 도구가 다루지 않습니다.
  • 서버가 "건너뜀" 경고로 빠졌다: 그 서버가 assets.txt 에 없고 default_site 도 없습니다. assets.txt 에 서버를 추가하십시오.
  • sssd.conf 가 FAIL 이다: [domain/...] 섹션이 없는 서버입니다. SSSD 가 구성되지 않은 서버이므로 먼저 SSSD 를 구성하십시오.

비밀번호 노출 주의: 서버에 보내는 적용 스크립트(/root/ldap_apply.sh, 권한 600, 실행 뒤 삭제)에 bindpw 가 들어 있습니다. 전송하는 순간 관리 서버의 ps 에 base64 문자열이 잠깐 보일 수 있습니다.

9. 자주 묻는 질문 (FAQ)

Q. ldap_setting 은 무엇을 하는 도구인가요?
A. 여러 서버의 LDAP · DNS · NTP · autofs 설정 파일 7종을 인프라·사이트 기준값으로 한 번에 바꾸는 도구입니다. 표준 명령은 ./scripts/deploy_ldap.sh -infra <인프라> 입니다.

Q. 처음 적용할 때 어떤 순서로 하나요?
A. -dry-run 으로 미리 보고, -host 로 1대에 먼저 적용하고, 로그인을 확인한 뒤 전체에 적용합니다.

Q. 적용하면 서비스가 재시작되나요?
A. 아니요. 적용 때는 재시작하지 않습니다. 롤백 때만 복원한 파일의 서비스를 재시작합니다. auto_setup 에서 실행하면 롤백 때도 재시작하지 않습니다.

Q. 적용이 끝났는지 어떻게 확인하나요?
A. ./scripts/deploy_ldap.sh -infra <인프라> -check-only 로 ldap_check 검증을 실행합니다. 그리고 서버 몇 대에 직접 접속해 id <계정> 과 ls /appl 을 확인합니다.

Q. -infra 를 빼면 어떻게 되나요?
A. 실행하지 않습니다. 잘못된 인프라에 적용하는 사고를 막기 위해 기본값이 없습니다.

Q. IP 와 LDAP 을 같이 바꾸려면?
A. auto_setup 에서 m → 3 IP+LDAP 변경 을 씁니다. IP 만 바꾸려면 ip_change 도구를 쓰십시오.

Q. AWX 가 있는데 이 도구를 써도 되나요?
A. AWX 표준 프로세스를 먼저 쓰십시오. AWX 로 실행할 수 없거나 너무 바쁠 때만 ldap_setting 을 쓰십시오.
