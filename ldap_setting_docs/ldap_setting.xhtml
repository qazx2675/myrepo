도구명: ldap_setting (bin/ldap-config-engine + scripts/deploy_ldap.sh · scripts/run.sh) — LDAP · DNS · NTP · autofs 설정 일괄 적용 엔진

양식 유형: T3 (설정 변경 · 적용 엔진형)

원본 경로 (origin/master): .claude/HPC/ldap_setting/

동작 환경 및 의존성: 관리 노드 Go 1.26.5(외부 의존성 없음, 폐쇄망 bin/ldap-config-engine_os6 내장) + gossh v2 필수 / 대상 노드 bash · awk · sed (jq · Go 불필요)

연계 도구: ldap_check (사후 3중 교차검증 짝), gossh v2 (base64 + spaceOut 전송), auto_setup (TUI m 변경 메뉴 2 LDAP 변경 · 3 IP+LDAP 변경 · 4 원복 · 5 auto.appl 원복)

한 줄 요약: 자산현황(hostname<TAB>site)을 기준으로 사이트별 스크립트를 생성해 7종 인증·이름해석·마운트 설정 파일을 키 단위로 갱신하고 ldap_check로 검증하는 엔진입니다.

표준 변경-검증 쌍: ldap_setting은 설정 생성·적용(dry-run → canary → apply)을 전담하고, 사후 검증은 짝 도구인 ldap_check가 담당합니다. apply 직전 파일별 자동 백업(<파일명>.bak.<YYYYmmddHHMMSS> 및 참고용 /etc/auto.appl_back)이 생성되며, auto_setup의 m 메뉴와 직접 연동됩니다.

1. 개요 및 변경 대상 (실제 수정하는 파일·서비스 동작)

ldap_setting은 RHEL 노드들의 인증(LDAP/SSSD/NSLCD), 이름해석(DNS), 시각 동기화(NTP/Chrony), 자동 마운트(autofs) 설정을 인프라·사이트별로 일괄 적용하는 도구입니다. 관리 노드에서 자산현황(conf/assets.txt)을 사이트별로 묶어 사이트당 1개의 적용 스크립트를 생성한 뒤, gossh v2를 통해 base64 파이프(echo <b64> | tr -d ' ' | base64 -d | bash)로 원격 실행합니다. 따라서 gossh 호출 횟수가 노드 수가 아닌 사이트 수로 끝나며, 대상 노드의 로그인 셸이 csh/tcsh여도 안전하게 동작합니다.

1.1 실제 변경하는 7종 설정 파일 (노드 OS·s4 예외 분기 포함)

# 대상 파일 경로 갱신 내용 및 동작 방식
1 /etc/openldap/ldap.conf URI(사이트별 순서), BINDDN, BINDPW 키 단위 갱신
2 /etc/autofs_ldap_auth.conf user=, secret= (XML 형식, 퍼미션 600)

4 /etc/nslcd.conf 또는 /etc/sssd/sssd.conf RHEL 7 이하 또는 s4 예외는 nslcd.conf, RHEL 8 이상은 sssd.conf (퍼미션 600). 단, sssd.conf에 [domain/...] 섹션이 없으면 미구성 노드로 보고 FAIL 처리(새 파일 미생성)

6 /etc/ntp.conf 또는 /etc/chrony.conf RHEL 7 이하 또는 s4 예외는 ntp.conf, RHEL 8 이상은 chrony.conf (server 줄 갱신, pool 줄 제거)
7 /etc/auto.appl.bak
(원복 후 /etc/auto.appl)		 다른 파일과 달리 /appl 줄의 storage·mountpoint를 통째 작성해 /etc/auto.appl.bak에 대기시킴 (기존 /etc/auto.appl은 .bak.<시각> 백업 + 참고용 /etc/auto.appl_back 남긴 뒤 치움). 네트워크 설정 완료 후 노드에서 /root/auto_appl_restore.sh(또는 auto_setup m→5)로 원복

(참고: sudo-ldap.conf는 파일이 존재할 때만 URI 줄을 교체하고 나머지 줄과 대소문자를 유지합니다.)

1.2 적용(Apply) vs 롤백(Rollback) 시 서비스 재시작 정책 및 연계

  • 적용 시에는 서비스를 재시작하지 않음: auto.appl 변경 중 autofs가 행(hang) 걸릴 수 있으므로, 적용 단계에서는 파일만 수정하고 데몬을 재시작하지 않습니다. 필요 시 운영자가 직접 재시작하거나 원복 시점 규칙에 따릅니다.
  • 롤백 시에는 복원된 파일 대응 서비스만 재시작: -no-restart를 주지 않은 단독 롤백에서는 lib_common.sh의 표에 따라 복원된 파일에 해당하는 서비스만 재시작합니다(5장 표 참고).
  • auto_setup m 메뉴 연계: auto_setup의 m 메뉴(2 LDAP 변경, 3 IP+LDAP 변경, 4 원복, 5 auto.appl 원복)는 ldap-config-engine을 호출할 때 항상 -no-restart를 전달해 노드 서비스를 재시작하지 않으며, 5 auto.appl 원복을 통해 대기 중인 /etc/auto.appl.bak을 반영합니다.
  • ldap_check와 짝 구조: 적용 로직(apply_body.sh)과 검증 로직(../ldap_check/ldap_check.sh)이 동일한 ldap_config.conf 스키마를 공유합니다.

3. 표준 안전 절차 (Dry-run → 소수 선행검증 → 전체 적용 → ldap_check 검증 · auto_setup 연계)

ldap_setting은 인증 및 이름해석 파일을 직접 수정하므로 반드시 아래 4단계 순서대로 진행하십시오. (참고로 -infra에는 실수 방지를 위해 기본값이 없으므로 항상 명시해야 합니다.)

bash 5로 /root/auto_appl_restore.sh 반영 후 실행) ./scripts/deploy_ldap.sh -infra zxcv -check-only]]>

3.1 대화형 래퍼(scripts/run.sh) vs deploy_ldap.sh

  • ./scripts/deploy_ldap.sh: -infra 지정 후 적용부터 ldap_check.sh 실행 검증까지 한 번에 수행합니다(SHARED_CHECK=/user/asdf/ldap_check.sh가 마운트되지 않은 노드는 CHECK_LOCAL=../../ldap_check/ldap_check.sh를 base64로 /root/ldap_check.sh에 넣어 실행 후 삭제).
  • ./scripts/run.sh: 플래그 없이 메뉴로 실행 계정을 선택하고(select_user_context()의 # TODO 두 곳을 채워 사용, scripts/{계정명}.txt 참조), ldap_config.conf에 정의된 인프라만 메뉴에 띄운 뒤 DRY-RUN → 정확히 yes 입력 → 적용 순서로 진행합니다. 단, run.sh는 검증까지 자동 실행하지 않으므로 끝난 뒤 deploy_ldap.sh -infra <이름> -check-only를 따로 실행하십시오.

3.2 auto_setup m 메뉴 통합 워크플로우 (os8_mgmt 전용)

  1. /etc/auto_setup/auto_setup.conf에 enable_ldap_change=y(필요 시 ldap_engine 경로) 설정 후 /etc/auto_setup/ldap_config.conf(600) · /etc/auto_setup/assets.txt를 준비합니다(--admin 실행 시에도 활성화).
  2. auto_setup TUI에서 m → 2 LDAP 변경(또는 3 IP+LDAP 변경)을 선택하고 user 및 인프라(infra.<이름>.*)를 고릅니다.
  3. 대상 호스트 목록을 붙여넣고 Ctrl+D를 누르면, 자동으로 -dry-run 결과를 먼저 표시합니다.
  4. 미리보기를 확인하고 정확히 yes를 입력하면 os8_mgmt 우선 실행 후 미응답 호스트만 os6_mgmt 경유로 재시도합니다. (항상 -no-restart가 붙어 서비스 미재시작)
  5. auto.appl 대기분(/etc/auto.appl.bak) 반영이 필요할 때 m → 5 auto.appl 원복을 실행합니다. 이후 ldap_check.sh로 정합성을 검증하십시오.

4. CLI 플래그 · 설정 키 · 입력 파일 상세 표

4.1 bin/ldap-config-engine CLI 플래그 (종료코드: 0 정상 / 1 설정·인자 오류 / 2 일부 노드 FAIL·무응답)

플래그 기본값 설명
-infra (없음, 필수) 대상 인프라 이름 (오적용 사고 방지를 위해 기본값 없음)
-config ./ldap_config.conf 설정 파일 경로
-assets ./assets.txt 자산현황 파일 경로 (hostname<TAB>site)
-site (전체) 지정한 사이트만 처리
-host (전체) 지정한 호스트 1대만 처리 (소수 선행검증용)
-host-file (전체) 파일에 나열된 호스트만 처리 (한 줄에 hostname 하나, site 정보 없음 — site는 항상 -assets 조회)
-default-site (conf 값) 자산현황에서 못 찾은 호스트에 적용할 site (ldap_config.conf의 default_site를 덮어씀)
-dry-run false 파일 수정 및 서비스 재시작 없이 변경될 내용(diff)만 보고
-print-script false 생성될 적용 스크립트를 표준출력으로 출력 후 종료 (-site 필요)
-root (빈값 = /etc) 테스트용 기록 루트 경로. 값이 있으면 서비스 재시작을 생략
-no-restart false 서비스 재시작(sss_cache -E 포함) 생략, SKIP-RESTART로만 기록 (auto_setup이 적용/원복 시 사용)
-list-backups false 각 노드에 남아 있는 백업 시점 목록만 조회 (변경 없음)
-rollback false 가장 최근 백업 시점으로 되돌리기
-rollback-to (없음) 지정한 백업 시점(숫자 14자리 YYYYmmddHHMMSS)으로 되돌리기
-monitor false 60초 초과 시 /dev/tty 진행 화면 표시, Ctrl+C 5초 내 3회 종료(종료코드 130)
-gossh / -u / -p / -i / -P / -c / -t gossh / root / 없음 / 없음 / 22 / 0 / 0 gossh 실행 경로 및 SSH 접속·동시성·타임아웃 옵션
-remote-path /root/ldap_apply.sh 원격에 잠시 떨어뜨릴 스크립트 경로 (실행 후 삭제)

5. 백업 및 롤백 방법

한 번의 적용 실행이 남기는 백업은 전부 동일한 14자리 시점 값(<파일명>.bak.<YYYYmmddHHMMSS>)을 사용하며, 한 실행 안에서는 파일당 최초 수정 직전 1회만 백업(commit_file 가드)을 남깁니다. 잘못 적용된 경우 수동으로 파일을 복사하면 서비스 재시작을 누락하기 쉬우므로 반드시 내장 롤백 기능을 사용하십시오.

  • 100% 신뢰 금지 & 무작위 실서버 직접 확인: 본 도구는 /etc/openldap/ldap.conf, /etc/sssd/sssd.conf, /etc/nslcd.conf, /etc/resolv.conf 등 로그인 인증과 이름해석에 직결되는 파일을 수정합니다. 잘못 적용되면 해당 노드에 로그인이 불가능해질 수 있습니다. 적용 및 롤백 이후 반드시 무작위로 서버 몇 대에 직접 접속해 id <계정>, ls /appl, systemctl status sssd(또는 nslcd) 및 실제 파일 내용을 눈으로 검증하십시오.
  • auto.appl 대기 상태 주의: 적용 시 새 내용은 /etc/auto.appl.bak에 대기하므로, 노드에서 /root/auto_appl_restore.sh(또는 auto_setup m→5)로 원복하기 전에는 ldap_check.sh의 auto.appl 기반 인프라 판별이 FAIL로 출력됩니다.
  • NetworkManager resolv.conf 덮어쓰기: NetworkManager가 재기동 시 /etc/resolv.conf를 덮어쓸 수 있으며, NM 관리 제외 설정은 이 도구의 범위 밖입니다.
  • auto_setup m 메뉴 사용 시 주의: auto_setup은 항상 -no-restart로 엔진을 호출하므로 원복 후에도 서비스가 자동 재시작되지 않습니다.
