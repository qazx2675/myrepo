문서명: gossh 사용 가이드

한 줄 요약: 수백 대의 서버에 한 번에 같은 명령을 내리고, 그 결과를 한눈에 모아서 정상/이상을 자동으로 분류해 주는 병렬 SSH 일괄 작업 도구(pdsh 스타일 출력 호스트명: 출력줄 지원)입니다.

1. gossh 개요: 이게 무엇이고 왜 쓰는가?

gossh는 수백 대의 서버에 한 번에 같은 명령을 내리고, 그 결과를 한눈에 모아서 정상/이상을 자동으로 분류해 주는 병렬 SSH 일괄 작업 도구입니다. (pdsh 스타일의 출력 형식인 호스트명: 출력줄을 지원합니다.)

비운영 담당자(PM·기획·타부서)를 위한 직관적 이해

  • 일괄 점검: 서버 200대의 디스크 용량이나 서비스 상태를 1대씩 접속해 확인하면 몇 시간이 걸리지만, gossh를 쓰면 한 번에 조회하고 정상 서버는 하나로 묶어(-b) 문제가 있는 2~3대만 즉시 골라낼 수 있습니다.
  • 기준 비교: 기준이 되는 서버(Golden Image)와 다른 서버들의 설치 패키지(-rpm)나 시스템 설정(-tmp, -limit)이 다른지 자동으로 대조해 차이점만 리포트로 뽑아냅니다.
  • 사고 방지 안전장치: 실수로 전체 서버를 재부팅(reboot 등)하는 대형 사고를 막기 위해 위험 명령어는 기본적으로 차단되어 있습니다.

2. 설치 및 기본 사용법

2.1 설치 및 배포

  • 오프라인 빌드: 폐쇄망 환경에서도 vendor/ 디렉토리를 포함해 바로 빌드할 수 있습니다. bash
  • RHEL / CentOS 구버전·신버전 지원: 로컬 저장소에는 RHEL/CentOS 6용 정적 빌드 바이너리 gossh_os6가, gossh-standalone 브랜치에는 gossh_os8 바이너리가 함께 제공됩니다.
  • 배포/업데이트 (update.sh): 스크립트 상단의 TARGET_SERVER, DEST1, DEST2, DEST3 변수를 설정한 뒤 대상 서버에서 실행하면, 일반 빌드 및 gossh_os6 바이너리를 지정된 경로에 gossh / pdsh 이름으로 복사합니다.

2.2 기본 실행 형식

bash [옵션] "<실행할_명령어>"]]>
  • 호스트 지정 (-w, 필수):
    • 파일 지정: -w hosts.txt (또는 -w^hosts.txt, -whosts.txt)
    • 범위(NodeSet) 지정: -w esxi[0001-0020] 또는 -w web[01-20] (중복 호스트는 자동 제거)

2.3 주요 옵션 (플래그)

옵션 설명 기본값 / 비고
-w <대상> 대상 호스트 파일 또는 NodeSet 범위 필수
-u <계정> SSH 접속 계정 root
-p <비밀번호> SSH 비밀번호 키 인증 우선 시도 후 실패 시 사용
-i <키경로> SSH 개인키 경로 미지정 시 ~/.ssh/id_ed25519 → id_ecdsa → id_rsa 순 자동 탐색
-P <포트> SSH 포트 22
-c <개수> 동시 접속(병렬) 수 1000 (단, /user/ 경로 감지 시 450으로 자동 제한)
-cf <개수> 동시성 제한을 무시하고 강제 지정 autofs 부하 주의
-t <초> 로그인 타임아웃 15초
-b 동일한 실행 결과를 하나로 묶어 출력 (그룹화) 이상 서버 식별에 유용
-m 60초 이상 응답 없는 행(Hang) 호스트 실시간 확인 Linux 전용
-pm 작업 전 OS 설치 중/autofs 이상 호스트 사전 점검 _os_install, _nosvrauto 생성
-script 요약 및 색상 출력 숨김 (자동화 스크립트용) 실행 파일명이 pdsh면 기본 활성화
-rpm 기준 서버와 대상 서버 간 설치된 RPM 패키지 비교 명령어 없이 실행
-sv 여러 명령어를 대화형으로 입력받아 실행 후 호스트|결과 표로 저장 gossh-standalone 브랜치 전용
-tmp, -limit, -tl /tmp 정리 및 limits.conf 표준 설정 일괄 적용 명령어 없이 실행
-dnlgjawkrdjqghkrdls 차단된 위험 명령어(reboot 등) 강제 실행 확인 오타/실수 방지용

3. 직급별 실무 활용 사례

3.1 주니어 실무자 (사원~대리): 일상 점검 및 1차 장애 확인

  • 다수 서버 일일/수시 상태 점검 (-w, -b, -sv)
    • gossh -w web[01-20] -b "uptime" 또는 df -h, free -m, systemctl is-active <서비스> 등을 일괄 실행합니다.
    • -b 옵션으로 정상 응답을 하나로 묶어 수십~수백 대 중 이상 징후가 있는 서버만 빠르게 식별합니다.
    • 여러 항목을 한꺼번에 조사해 보고서용 표로 정리해야 할 때는 -sv 옵션(gossh-standalone 브랜치)으로 명령어를 대화형 입력받아 호스트|결과 표로 저장할 수 있습니다.
  • 장애 시 로그 일괄 조회 및 미응답 서버 파악 (_res_off, _res_refsed)
    • gossh -w web.txt "grep -i error /var/log/messages | tail -n 10"으로 여러 서버의 로그를 동시에 확인합니다.
    • 접속 불가(_res_off) 및 접속 거부(_res_refsed) 서버는 별도 파일로 자동 분리되므로, 장애 보고 시 미응답 호스트 목록을 즉시 추려낼 수 있습니다.

3.2 시니어 실무자 (과장~차장): 형상 표준화 및 대규모 배치 작업

  • 패키지 표준화 감사 (-rpm)
    • 기준 서버(Golden Image) 대비 대상 서버들의 rpm -qa 차이를 비교해 _rpm_report.txt, _rpm_tab.txt, _rpm_diff 파일을 생성하고, 패치 누락이나 임의 설치된 패키지를 감사합니다.
  • 표준 시스템 설정 일괄 적용 (-tmp, -limit, -tl)
    • /etc/tmpfiles.d/custom-tmp.conf 설정 및 기준 서버의 /etc/security/limits.conf 백업·복사·무결성 검증을 한 번에 처리합니다.
  • 작업 전 사전 필터링 (-pm)
    • 대규모 작업 전 -pm으로 OS 설치 중인 호스트(_os_install)나 autofs 접근 불가 호스트(_nosvrauto)를 먼저 걸러내어 본 작업의 실패율을 줄입니다.
  • 행(Hang) 모니터링 및 단계별 중단 (-m, Ctrl+C)
    • Linux 환경에서 -m으로 60초 이상 응답이 없는 호스트를 실시간으로 확인합니다. 필요 시 Ctrl+C(1·2·3회 단계별 중단)로 작업을 멈춘 뒤 _res_cancel 파일로 미완료 호스트만 재추적합니다.
  • 자동화 파이프라인 연동 (-script)
    • 쉘 스크립트나 배치 파이프라인에 연동할 때는 -script 옵션(또는 pdsh 심볼릭 링크)으로 색상과 요약을 끄고 호스트: 결과 형식만 깔끔하게 파싱합니다.

4. 주의사항 및 팁

  1. 일반 파일 전송(SCP/SFTP) 기능은 없습니다.

    gossh는 원격 명령 실행 및 전용 설정 동기화(-limit 등) 도구입니다. 일반 파일이나 바이너리 배포는 scp, rsync 등 별도 도구를 사용하세요.

  2. 위험 명령어는 기본 차단됩니다.

    reboot, poweroff, shutdown, halt, init 0, init 6, ddc 명령은 실수 방지를 위해 기본 차단됩니다. 정말 필요한 경우에만 -dnlgjawkrdjqghkrdls 플래그를 명시해 실행하세요.

  3. 행(Hang) 모니터링(-m)은 Linux 전용입니다.

    Linux 외의 OS에서는 -m 옵션의 터미널 제어 기능이 동작하지 않습니다.

  4. 동시성 제한(-c)을 무리하게 우회하지 마세요.

    기본 동시성은 1000이지만, 경로에 /user/가 감지되면 autofs 부하 방지를 위해 자동으로 450으로 제한됩니다. 특별한 사유가 없다면 -cf로 강제 상향하지 않는 것을 권장합니다.

  5. 실행 후 생성되는 결과 파일을 적극 활용하세요.

    실행 결과에 따라 _res_off(접속 불가), _res_refsed(접속 거부), _res_cancel(중단된 호스트) 등의 파일이 생성되므로, 후속 점검이나 재작업 대상으로 바로 활용할 수 있습니다.
