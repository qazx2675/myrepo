2. 처음 사용하기 전에 무엇을 준비하나?

  1. 스크립트를 백업합니다: cp -p os_check_final_annotated.sh "os_check_final_annotated.sh.bak.$(date +%Y%m%d_%H%M%S)"
  2. 스크립트 위쪽의 [수정필요] 변수를 사내 경로로 바꿉니다 (7.1절).
  3. 대화형으로 쓰려면 select_user() 를 구현합니다 (6절).
  4. gossh 가 설치되어 있는지 확인합니다.
  5. 설정을 적용하기 전에 대상 서버의 설정 파일을 백업합니다. 이 스크립트는 원격 설정을 백업하지 않습니다.

스크립트 주석 태그의 뜻:

  • [수정필요]: 사내 경로·명령·user 선택·FAIL 기준. 사용 전에 확인하고 고칩니다.
  • [수정금지]: -auto/-auto-check 처리. auto_setup 연계를 위해 고치지 않습니다.
  • [연계]: auto_setup 완료 마커 기록 같은 외부 연계 부분입니다.

4. 표준 작업 절차는 무엇인가? (안전 순서)

  1. 점검만 합니다: ./os_check_final_annotated.sh -auto-check testuser ./canary_hosts.txt. OS·커널·LDAP·Splunk·ping·SSH 상태를 확인합니다.
  2. 1~2대에 적용합니다: ./os_check_final_annotated.sh -auto canary_op ./canary_hosts.txt. 또는 대화형으로 실행하고 질문에 y, y(또는 set)를 입력합니다.
  3. 그 서버를 직접 확인합니다: 적용 스크립트가 의도대로 동작했는지, gossh 안전장치 메시지로 차단된 것이 없는지 확인합니다.
  4. 전체에 적용합니다: ./os_check_final_annotated.sh -auto admin ./all_hosts.txt
  5. 결과 리포트를 확인합니다 (5절).
  6. 무작위로 직접 확인합니다: y 적용 서버, set 적용 서버(p/d), ev 서버에서 각각 1~3대를 골라 직접 접속합니다.

8. 문제가 생기면? (롤백 포함)

  • 대화형 실행이 바로 끝난다: select_user() 가 구현되지 않았습니다. 구현하거나 -auto/-auto-check 를 쓰십시오.
  • 적용이 잘못되었다: 자동 롤백이 없습니다. 미리 만든 백업으로 그 서버에서 직접 되돌리거나 역적용 스크립트를 실행하십시오.
  • 판단 근거를 남기고 싶다: 적용 전후의 check.res_* 와 ldap_case*_* 파일을 지우지 말고 보관하십시오.
  • 잘못된 완료 마커가 기록되었다: os8_mgmt 의 ${AUTO_SETUP_DIR:-/tmp/auto_setup}/done/ 마커를 auto_setup 운영 절차대로 정리하십시오.

9. 자주 묻는 질문 (FAQ)

Q. OS 환경설정 체크는 무엇을 하는 도구인가요?
A. 여러 서버의 OS 환경설정을 점검하고, 고르면 설정 스크립트를 적용하고, 다시 점검하는 Bash 스크립트입니다. 실행 파일은 os_check_final_annotated.sh 입니다.

Q. 설정을 바꾸지 않고 점검만 하려면?
A. ./os_check_final_annotated.sh -auto-check <user> <호스트파일> 를 실행합니다.

Q. 바로 운영 서버에 써도 되나요?
A. 아니요. [수정필요] 경로를 먼저 바꾸고, 6절의 구현되지 않은 부분을 확인하십시오.

Q. config_check 와 무엇이 다른가요?
A. 흐름은 같습니다(점검 → 적용 → 재점검). config_check 는 사내 경로·벤더 코멘트·setup_check 연계가 들어간 운영용 버전입니다.

Q. 되돌리기 기능이 있나요?
A. 없습니다. 적용 전에 대상 서버의 설정을 백업하십시오.
