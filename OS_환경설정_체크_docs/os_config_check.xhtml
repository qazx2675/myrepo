1. 개요 및 변경 대상 (실제 수정하는 파일 및 실행 스크립트)

OS 환경설정 체크(os_check_final_annotated.sh)는 신규 구축되거나 재설치된 다수의 HPC 리눅스 서버에 대해 OS 기본 환경설정을 원격 일괄 점검하고, 필요 시 설정 스크립트를 원격 적용한 뒤 사후 재점검 및 요약 리포트를 출력하는 순수 Bash 오케스트레이션 스크립트입니다.

이 스크립트는 자체적으로 /etc/* 설정 파일을 직접 파싱·편집하지 않고, gossh를 통해 각 대상 호스트에 설치되어 있거나 지정된 점검/적용 스크립트를 원격 호출하여 상태를 판정하고 구성을 반영합니다.

1.1 실제 실행 및 변경 대상

구분 호출 위치 / 대상 스크립트 실제 수행 내용 및 변경 영향
원격 OS 사전·사후 점검 대상 서버: ${RUN_SH_DIR}/run.sh, ${INFO_CHECK_SH}, ${CLASSIFY_CMD} (기본 hostname), ${KERNEL_CMD} (기본 uname -r) 읽기 전용 점검(gossh -pm 병렬 실행)을 수행하고 로컬 작업 디렉터리에 check.res_${user}*, ldap_case*_${user} 결과 파일을 생성
원격 OS 설정 적용 (y 선택 시) 대상 서버: ${SETTING_DIR}/setting_insert.sh, ${RCLOCAL_SH}, ${SETTING_DIR}/appl_change.sh gossh를 통해 대상 서버의 OS 환경설정, rc.local 관련 설정, 애플리케이션 구성을 실제로 수정 (쓰기 작업)
원격 OS 설정 전체 적용 (set 선택 시) 대상 서버: 위 y 대상 + ${SETTING_DIR}/setting.sh 호스트 목록에 p 또는 d로 시작하는 호스트가 포함된 경우(-auto 기준) 또는 사용자가 set 입력 시 기본 setting.sh까지 추가 적용 (쓰기 작업)
로컬 DHCP 조회 (v21 기준) 로컬 관리서버: ${DHCP_SH} (기본 ./dhcp.sh) PINGX_HOSTS(핑 미응답 호스트) 대상에 한해 로컬에서 DHCP 정보를 조회 (단, README.md 및 구 주석에는 TODO로 남아 있음)
auto_setup 완료 마커 로컬 ${auto_done_dir} 또는 원격 ${auto_done_host}의 ${AUTO_SETUP_DIR:-/tmp/auto_setup}/done/ -auto 정상 완료 시 대상 호스트별 완료 기록 생성 (500대 단위 배치 gossh 원샷 전송, sha256sum 필요). -auto-check 시에는 기록하지 않음

1.2 주석 태그 규약

스크립트 내부 주석은 운영 환경 이관 시 수정 가능 여부를 명확히 구분하기 위해 아래 3가지 태그로 관리됩니다.

  • [수정필요]: 회사 내부 실제 경로, 명령어, user 선택 방식, FAIL 판정 기준, TODO 함수를 배포 전 반드시 확인·수정해야 하는 구간
  • [수정금지]: -auto / -auto-check 인자 파싱 및 자동 프롬프트 제어 등 auto_setup 연동 프로토콜을 유지하기 위해 변경하면 안 되는 구간
  • [연계]: auto_setup 완료 마커 기록(auto_record_done) 등 외부 자동화 파이프라인과 맞물리는 구간

2.1 빌드 여부 및 배치 방법 (순수 Bash — 빌드 불필요)

이 프로젝트는 별도 바이너리나 설치 과정 없이 실행하는 순수 Bash 스크립트이므로 별도 빌드가 전혀 불필요합니다.

  • 원본 실행 파일: os_check_final_annotated.sh (또는 회사 표준 운영 파일명으로 복사 후 권한 부여)
  • 필수 의존 도구: gossh (원격 접속 및 -pm 병렬 실행), bash, sha256sum (auto_record_done 완료 마커 해시 계산용)
  • autofs 공유 배포 시 주의: 여러 관리서버가 autofs 공유 경로의 스크립트를 함께 쓰는 경우, auto_done_dir는 반드시 비워 두고(auto_done_dir="") auto_done_host에만 os8_mgmt 호스트명을 지정해야 합니다. auto_done_dir에 로컬 경로를 넣으면 다른 서버에서 실행 시 원격 os8_mgmt가 아닌 실행 서버 로컬에 기록됩니다.

2.2 입력 파일 및 인증/암호화 정책

  • 대화형 호스트 목록 파일 (${user}.txt): 스크립트 실행 작업 디렉터리에 위치한 대상 호스트 목록 파일입니다. select_user() 구현을 통해 결정된 user 값으로 ${user}.txt를 읽습니다(현재 select_user()는 user="" 미구현 상태이므로 4.3절 참고).
  • 비대화형 호스트 목록 파일 (<호스트목록파일>): -auto <user> <호스트목록파일> 또는 -auto-check <user> <호스트목록파일> 실행 시 3번째 인자로 직접 전달되는 파일입니다.
  • 계정 및 암호화: 스크립트 자체에 평문 비밀번호를 저장하거나 입력받지 않으며, 모든 원격 인증은 사전에 구성된 gossh 세션·인증 체계(예: 키 기반 인증 또는 svrauto 계정 컨텍스트)에 위임합니다.

3. 표준 안전 절차 (사전 점검 → 소수 선행검증 → 전체 적용 → 사후 검증)

이 스크립트는 별도의 -dry-run 플래그를 제공하지 않는 대신, 대화형 단계별 프롬프트(체크 진행 여부 y/n → 결과 확인 후 설정 수정 여부 y/n/set)와 읽기 전용 모드인 -auto-check를 통해 변경 전 미리보기/검증 절차를 수행합니다.

3.1 단계별 표준 운영 절차

  1. 1단계 — 사전 점검 및 미리보기 (읽기 전용 / Dry-run 성격 검증):

    설정 변경을 전혀 수행하지 않는 -auto-check 모드로 대상 호스트의 현재 OS 상태, 커널, LDAP/SPLUNK 상태, 핑/SSH 접속 상태를 먼저 확인합니다. (auto_setup의 t 테스트 모드, request manual-run ... check, x 옵션이 이 모드를 호출합니다.)

    bash
  2. 2단계 — 소수 선행검증 (Canary 1~2대):

    선별한 소수 테스트/카나리 호스트 목록(1~2대)에 대해 먼저 적용을 수행합니다. 적용 스크립트(setting_insert.sh, rclocal.sh, appl_change.sh, 필요 시 setting.sh)가 의도한 대로 동작하는지, GOSSH_SAFETY_FILTER(\[안전장치\]|autofs 마운트) 관련 오탐/차단이 없는지 확인합니다.

    bash y # 프롬프트 2: OS 환경설정을 수정하시겠습니까? (y/n/set) -> y (또는 p/d 호스트 포함 시 set) # 방법 B: 카나리 호스트 파일로 -auto 실행 검증 ./os_check_final_annotated.sh -auto canary_op ./canary_hosts.txt]]>
  3. 3단계 — 전체 적용 (대화형 또는 auto_setup 연계 -auto):

    카나리 검증이 통과되면 전체 대상 목록에 적용합니다. -auto <user> <호스트목록파일> 모드에서는 OS 체크를 진행하시겠습니까?에 자동으로 y가 선택되며, 목록 내 앞 공백 제거 후 호스트명이 대소문자 구분 없이 p 또는 d로 시작하는 호스트가 하나라도 있으면 set, 그렇지 않으면 y가 자동 선택됩니다.

    bash
  4. 4단계 — 사후 검증 및 결과 리포트 확인:

    설정 적용 후 스크립트는 SETTING_TARGET_LIST를 대상으로 run_post_apply_check를 자동 재실행하여 check.res_${user}_postapply에 저장하고 FAIL 항목만 추려 출력한 뒤, ############### 결과 리포트 ############### 블록에 LDAP case 6~9, DHCP(PINGX_HOSTS), usb0, PCIe(pice) BIOS, ev 호스트 상태를 요약합니다. -auto 모드에서는 완료 후 auto_record_done을 호출하여 done/ 마커를 기록합니다.
