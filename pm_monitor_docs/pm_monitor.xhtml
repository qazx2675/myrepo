pm_monitor — 대규모 베어메탈 OS 설치 모니터링 TUI

요약: 폐쇄망 HPC 베어메탈 노드의 OS 설치 진행 상태를 최대 8,000대 규모까지 단일 TUI 화면에서 주기 추적하는 도구입니다. Raw ICMP Ping, TCP 22번 포트, gossh -pm, /tmp/anaconda.log 디스크 미인식 점검을 5단계로 수행하며, c(현황 코멘트)·r(지연 점검 요청)·d(DHCP 조회)·l(LDAP·DNS·NTP·autofs·H/T 점검) 패널을 제공합니다.

저장소 기준: origin/master · .claude/HPC/pm_monitor (Go 1.20 정적 바이너리 install_mn_os8 포함)

면책 및 검증 권고 (Disclaimer)

pm_monitor는 OS 설치 현황 파악과 점검 업무를 보조하기 위한 참고용 보조 도구입니다. 최종 구축 완료 판단이나 장애 조치 전에는 반드시 무작위 선정된 실서버(Live Server)에 직접 접속하여 anaconda.log, ldap_check.sh, 네트워크·스토리지 구성을 직접 교차 검증하시기 바랍니다.

1. 개요 및 아키텍처 · 통신 경로

pm_monitor(실행 명령: install_mn / install_mn_os8)는 관리자 노드에서 대상 서버 목록(<호스트파일>)을 읽어 백그라운드 goroutine으로 수집 주기를 반복하면서 실시간 TUI 상태를 갱신하고, 변경분이 발생했을 때만 <호스트파일>.pm_state.json에 상태를 원자적으로 기록합니다. 8,000대 동시 추적 시 메모리 사용량을 억제하기 위해 debug.SetGCPercent(25)가 적용되어 있습니다.

1.1 5단계 수집 파이프라인 및 외부 도구 연동

단계 수행 내용 연동 대상 / 통신 경로 판정 및 다음 단계 조건
1단계 · Raw ICMP Ping 단일 raw socket으로 ping_pps(기본 500 pps), ping_timeout_ms(기본 1500ms) 기준 일괄 ping 송수신 대상 노드 전체 (단, 이미 설치완료 또는 완료후꺼짐 상태는 주기 내 생략) 미응답 → ping X. 응답(Ping O) 노드만 2단계로 전달
2단계 · TCP 22 포트 확인 tcp_parallel(기본 100개) 동시성 제한으로 SSH 포트 연결 시도 1단계 Ping O이면서 미완료인 노드 연결 거부(Refused/Timeout) → 설치중 판정 후 3·4단계 생략. 열림(SSH 가능) 시 3단계 진행
3단계 · gossh -pm 연동 임시 디렉터리 pm_monitor_*를 생성·자동 정리하며 nice -n 10으로 gossh -pm -script -w <tmp> "echo PM_OK" 실행 (타임아웃 2m + len(hosts)*50ms, childMu로 자식 프로세스 1개씩 직렬 실행) gossh 바이너리 → 대상 노드 SSH stdout host: PM_OK → 설치완료.
stderr host: OS 설치중 ... → 설치중.
그 외 stderr 첫 줄 또는 "응답 없음" 기록
4단계 · 디스크 미인식 점검 설치중 이면서 SSH 접속 가능한 호스트 대상으로 gossh -script -w <tmp>로 /tmp/anaconda.log 읽기 및 disk_pattern 검색(csh/tcsh 호환 구문) 대상 노드의 /tmp/anaconda.log NS_DISK 마커 감지 → 디스크미인식 (NS_NOLOG, NS_DONE 마커로 로그 미존재·완료 구분)
5단계 · 지연 판정 및 상태 저장 설치중 최초 관측 시각으로부터 delay_min(기본 60분) 경과 시 지연 승격, 변경 시에만 상태 파일 저장 <호스트파일>.pm_state.json 상태 우선순위: 디스크미인식 > 지연 > 설치중

1.2 온디맨드 연동 경로 (gossh · ldap_check.sh · dhcp_server)

  • gossh -pm 연동 특징: gossh는 실행 디렉터리에 *_os_install 로그/임시 파일을 남길 수 있으므로, pm_monitor는 runGosshList에서 매번 OS 임시 디렉터리(pm_monitor_*)를 만들어 작업 디렉터리 오염 없이 실행 후 즉시 삭제합니다.
  • ldap_check.sh 연동 (l 키): 설치완료 또는 재부팅됨 상태 중 캐시(Check.Ver = 3)가 없는 호스트에 대해 gossh -script 단일 세션으로 bash <ldap_check_sh>, lscpu | grep -i 'per core', /etc/resolv.conf, /etc/chrony.conf, /etc/ntp.conf, timeout 5 getent hosts, /etc/auto.appl 수집 스크립트를 일괄 수행하고 결과를 pm_state.json에 캐시합니다.
  • DHCP 서버 조회 (d 키): 정렬된 ping X 호스트 목록을 ssh -o ConnectTimeout=10 <dhcp_server> 표준 입력으로 파이프 전달하여 원격 임시 파일(/root/off_server_list_<user>) 생성 → bash /root/a.sh 실행 → 즉시 rm -f 삭제(타임아웃 2m) 방식으로 조회하며 로컬·원격에 잔여 파일을 남기지 않습니다.
text pm_monitor 수집 및 온디맨드 연동 경로 → /root/a.sh (ping X 목록) 2) TCP 22 Check (tcp_parallel=100) [c] 설치완료 대상 ping 재확인 → 코멘트 생성 3) gossh -pm -script "echo PM_OK" (tmp: pm_monitor_*) [r] 지연 호스트 벤더별 점검 요청 생성 4) gossh -script → /tmp/anaconda.log (disk_pattern 검사) [l] gossh -script → bash + DNS/NTP/autofs/HT 5) 변경 시 <호스트파일>.pm_state.json 원자적 저장]]>

2.2 전역 명령 등록 (심볼릭 링크 방식 필수)

install_mn.sh는 readlink -f로 실제 디렉터리를 찾아 install_mn_os8을 실행하므로 파일 복사(cp)가 아니라 반드시 심볼릭 링크로 등록해야 합니다. 또한 root 권한이 필요합니다(Raw ICMP 소켓 생성 때문; 비-root 실행 시 종료 코드 1).

bash 전역 명령 등록 및 설정 파일 준비 cron / 백그라운드 실행 시 주의

pm_monitor는 대화형 TUI 데몬(포그라운드 실행)으로 설계되었으며, 백그라운드 수집 루프(interval_sec)가 바이너리 내부에서 자체 실행되므로 별도의 cron 등록이 필요하지 않습니다. -c를 생략한 경우 install_mn을 호출한 현재 작업 디렉터리(CWD)에서 pm_monitor.conf를 찾습니다.

3. 기동 및 표준 사용 흐름

3.1 호스트 목록 파일 형식

대상 호스트 파일은 한 줄에 호스트명 하나씩 작성합니다. 빈 줄과 #으로 시작하는 주석 줄은 무시되며, 중복 호스트명은 최초 등장 1건만 유지됩니다.

bash 호스트 파일 예시 및 실행 명령

3.2 종료 코드 (Exit Codes)

종료 코드 발생 원인
0 q 또는 Ctrl+C로 정상 종료 (TTY 상태 복원 완료)
1 비-root 사용자 실행(os.Geteuid() != 0), 호스트 파일 읽기 실패, 설정 파일 파싱/검증 오류
2 필수 인자 누락·잘못된 옵션, 호스트 파일이 디렉터리이거나 접근 불가(사용법 출력), 또는 install_mn.sh 실행 시 install_mn_os8과 go가 모두 없음

3.3 표준 운영 절차

  1. 호스트 파일 준비 및 기동: 작업 폴더에 설치 대상 호스트 파일과 pm_monitor.conf를 배치한 뒤 root 권한으로 install_mn <호스트파일> 실행 (이전 실행 기록이 있으면 <호스트파일>.pm_state.json 자동 복원).
  2. 실시간 모니터링: 상단에서 상태별 대수·마지막 갱신 시각·현재 주기 진행률을 확인하고, 하단 테이블에서 1~7 필터·/ 검색으로 이상 노드 추적.
  3. 조치 대상 파악 및 보고: c로 설치 현황/벤더별 문제 목록을 정리하고, 지연 노드는 r로 벤더별 점검 요청 코멘트 확인.
  4. 전원 미응답(ping X) 및 완료 노드 검증: ping X 노드는 d로 DHCP 서버의 /root/a.sh를 조회하고, 설치완료·재부팅됨 노드는 l을 눌러 LDAP·DNS·NTP·autofs·H/T 설정 이상 유무를 검증.

ping_timeout_ms 1500 1단계 Raw ICMP Ping 응답 대기 시간(밀리초)
ping_pps 500 Raw ICMP 송신 속도 제한(packets per second)
tcp_parallel 100 2단계 TCP 22 포트 동시 접속 검사 고루틴 상한

5. 장애/로그 확인 및 운영 제약사항 · 주의사항

  • 원격 노드의 *_os_install 잔여 파일 걱정 없음: gossh -pm 호출 시 매번 os.MkdirTemp("", "pm_monitor_*") 임시 디렉터리를 -w <tmp>로 넘기고 종료 시 삭제하므로 현재 작업 디렉터리에 임시 결과가 누적되지 않습니다.
  • 상태 초기화/재수집: 캐시된 l 점검 결과나 지연 최초 시각을 초기화하려면 TUI 종료(q) 후 <호스트파일>.pm_state.json을 백업·삭제하고 재실행합니다(l 점검은 Check.Ver = 3 캐시가 없는 설치완료·재부팅됨 호스트에 대해서만 수행).
  • Root 권한 필수: Raw ICMP 송수신을 위해 반드시 root로 실행해야 합니다. 일반 계정으로 실행하면 종료 코드 1로 즉시 실패합니다.
  • 외부 스크립트 전제 조건: d 패널은 대상 dhcp_server에 Passwordless SSH 접속 및 /root/a.sh 존재를 전제로 하며, l 패널은 ldap_check_sh 경로에 스크립트가 존재하고 INFO\tLDAP\t<infra>\t<site> 형식을 출력해야 정상 판정됩니다.
  • NTP 이름 풀이 지연/실패: /etc/chrony.conf·/etc/ntp.conf에 IP가 아닌 호스트명이 등록된 경우 노드 내부에서 timeout 5 getent hosts(이름당 최대 5초)로 해석하며, DNS 미응답 시 비고란에 NTP 이름 풀이 실패 <이름>이 기록됩니다.
  • OS6 미지원: pm_monitor는 install_mn_os8(RHEL8+ linux/amd64)만 제공하며 OS6 정적 바이너리는 포함되지 않습니다.
