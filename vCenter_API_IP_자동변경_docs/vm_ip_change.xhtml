2. 처음 사용하기 전에 무엇을 준비하나?

  1. vcenter.txt 에 vCenter 주소를 한 줄에 하나씩 씁니다. # 주석과 빈 줄은 무시합니다. 쓴 순서대로 VM 을 찾습니다.
  2. list.txt 에 VM이름 새IP 를 한 줄에 하나씩 씁니다. VM 이름은 vCenter 인벤토리에 보이는 이름입니다. 게스트 OS 호스트명이나 도메인을 쓰지 마십시오.
  3. 환경변수 4개를 설정합니다. 하나라도 비어 있으면 종료코드 1 로 멈춥니다.
  4. 대상 VM 이 전원 ON 이고 VMware Tools 가 실행 중인지 확인합니다.

3. 안전하게 실행하는 순서는?

  1. VM 1대로 확인: 테스트 VM 1대만 canary_list.txt 에 넣고 실행합니다. 새 IP 로 접속되는지 확인합니다.
  2. 전체 실행: ./bin/vm-ip-change -vcenter vcenter.txt -list list.txt
  3. 진행 확인: 처음 60초는 한 줄 진행률(진행: 12/40 (30%))을 보여 줍니다. 60초가 지나면 진행 화면(TUI)으로 바뀝니다.
  4. 실패 처리: 진행 화면에서 f 로 실패 목록을 저장합니다. 원인을 조치하고 그 파일로 다시 실행합니다.
  5. 사후 확인: 종료코드를 확인합니다. VM 1~3대에 새 IP 로 접속해 확인합니다 (6절).

4. VM 안에서 무엇을 바꾸나?

  1. nmcli con show --active 에서 lo 가 아닌 첫 번째 활성 연결을 찾습니다. 지금 설정을 /tmp/vm-ip-change/<호스트네임>.revert.sh 에 백업합니다.
  2. 그 연결에 ipv4.addresses <새IP>/24, ipv4.gateway <대역>.1, ipv4.method manual 을 설정합니다.
  3. 그 연결만 nmcli con up 으로 다시 올립니다. 네트워크 서비스 전체는 재시작하지 않습니다.

NIC 가 여러 개이면 첫 번째 활성 연결만 바꿉니다.

4.1 ev02 VM 은 왜 기다리나?

VM 이름이 ev02 로 끝나면, 짝 VM(ev01)의 1분 부하 평균과 BM 의 물리 코어 수를 비교합니다. 부하가 코어 수 이상이면 바로 진행하지 않고 2분마다 다시 확인합니다. ev01 이나 BM 코어 수를 확인할 수 없으면 바로 진행합니다.

5. IP 를 이전 값으로 되돌리려면?

  1. vCenter 의 VM 콘솔(VMRC)로 VM 에 접속합니다. 새 IP 로 SSH 가 되면 SSH 를 써도 됩니다.
  2. cat /tmp/vm-ip-change/$(hostname -s).revert.sh 로 내용을 확인합니다.
  3. bash /tmp/vm-ip-change/$(hostname -s).revert.sh 를 실행합니다.

중단은 Ctrl+C 3회로만 하십시오. Ctrl+C 로 중단하면 진행 중이던 VM 목록과 복구 방법을 출력합니다. kill 이나 pkill(SIGTERM)로 끝내면 아무 안내도 출력하지 않습니다.

6. 실행 뒤에 무엇을 확인하나?

종료코드가 0 이어도 다른 NIC, 방화벽, VLAN, ARP 캐시 문제는 확인하지 않습니다. 완료된 VM 1~3대에 새 IP 로 접속해 아래를 확인하십시오.

  • ip -4 addr show, ip route: 새 IP(/24)와 게이트웨이(.1)가 적용되었는지
  • nmcli con show <연결명>: ipv4.method manual 이 저장되었는지 (재부팅 뒤에도 유지되는지)
  • ev02 대상이면 짝 VM(ev01)의 서비스와 부하가 정상인지

7. 문제가 생기면?

  • 바로 종료코드 1 로 끝난다: 환경변수 4개(VC_USER, VC_PASSWORD, GUEST_USER, GUEST_PASSWORD)가 모두 있는지 확인하십시오.
  • VM 을 찾지 못한다: list.txt 의 이름이 vCenter 인벤토리의 VM 이름과 같은지 확인하십시오. 도메인을 붙이지 마십시오. vcenter.txt 에 해당 vCenter 가 있는지 확인하십시오.
  • VM 이 [FAIL] 이다: VM 전원이 ON 인지, VMware Tools 가 실행 중인지, GUEST_USER 암호가 맞는지 확인하십시오.
  • ev02 VM 이 오래 대기한다: 짝 VM ev01 의 부하가 높습니다. 부하가 내려가면 진행합니다.
  • 새 IP 로 통신이 안 된다: VM 콘솔로 접속해 revert.sh 로 되돌리거나 VLAN·포트그룹을 확인하십시오.

8. 자주 묻는 질문 (FAQ)

Q. vm-ip-change 는 무엇을 하는 도구인가요?
A. SSH 로 접속할 수 없는 RHEL 8.10 VM 의 IP 를 vCenter API 와 VMware Tools 를 통해 바꾸는 도구입니다. 실행 명령은 ./bin/vm-ip-change -vcenter vcenter.txt -list list.txt 입니다.

Q. vm-ip-change 와 ip_change 는 무엇이 다른가요?
A. ip_change 는 SSH(gossh)로 접속되는 서버의 ifcfg 파일을 수정합니다. vm-ip-change 는 SSH 가 안 되는 VM 을 vCenter 를 거쳐 nmcli 로 수정합니다. 서버에 SSH 가 되면 ip_change, VM 에 SSH 가 안 되면 vm-ip-change 를 쓰십시오.

Q. 미리보기(dry-run)가 있나요?
A. 없습니다. VM 1대만 넣은 목록으로 먼저 실행해 확인하십시오.

Q. 한 번에 몇 대를 바꾸나요?
A. 최대 16대를 동시에 처리합니다. 목록의 나머지는 순서대로 처리합니다.

Q. 실패한 VM 만 다시 하려면?
A. 진행 화면에서 f 로 실패 목록을 저장하고, 그 파일을 -list 로 다시 실행합니다.

Q. 이전 IP 로 되돌리려면?
A. VM 콘솔로 접속해 bash /tmp/vm-ip-change/$(hostname -s).revert.sh 를 실행합니다.

Q. 넷마스크나 게이트웨이를 지정할 수 있나요?
A. 아니요. 넷마스크는 항상 /24, 게이트웨이는 항상 <대역>.1 입니다.
