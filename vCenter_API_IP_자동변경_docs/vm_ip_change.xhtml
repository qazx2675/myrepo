문서 분류: T3. 설정 변경 / 프로비저닝 엔진 (사전 빌드 바이너리 CLI/TUI)

대상 프로젝트: vm_ip_change (bin/vm-ip-change, 모의 서버 bin/fake-vcenter)

대상 OS / 통신 경로: RHEL 8.10 VM / vCenter API → ESXi → VMware Tools(vmtoolsd) Guest Operations API → 게스트 내 nmcli

1. 개요 및 변경 대상 (SSH 기반 ip_change와의 명확한 대조)

vm-ip-change는 초기 IP 오할당이나 네트워크 설정 오류로 인해 SSH·네트워크 통신 자체가 완전히 불가능한 RHEL 8.10 가상머신(VM)에 대하여, 네트워크 연결 없이도 vCenter 및 ESXi를 경유해 VMware Tools(vmtoolsd)의 Guest Operations API로 게스트 내부 nmcli 명령을 직접 실행해 IP를 재설정하는 도구입니다.

1.1 SSH 기반 ip_change vs vCenter API 기반 vm_ip_change 비교

비교 항목 ip_change vm_ip_change
핵심 사용 시나리오 현재 SSH 접속이 가능한 HPC 물리/가상 서버의 운영 IP·게이트웨이 일괄 전환 IP 오할당 등으로 SSH·네트워크 접속이 불가한 RHEL 8.10 VM의 IP 복구·자동 변경
실행 경로 / 프로토콜 관리서버 → gossh (SSH)로 대상 호스트 접속 관리서버 → vCenter API → ESXi → VMware Tools(vmtoolsd) Guest Operations API
실제 수정 대상 및 방법 /etc/sysconfig/network-scripts/ifcfg-*의 IPADDR, GATEWAY 등 텍스트 편집 게스트 내 첫 번째 비-lo 활성 연결(nmcli con show --active) 대상 nmcli로 수정 후 해당 연결만 nmcli con up 재기동
대상 식별 기준 SSH 접속 호스트명(targets.txt) vCenter 인벤토리 VM 표시 이름 (list.txt — 게스트 OS 호스트명·도메인 아님)
공통 규칙 /24 (255.255.255.0) 넷마스크 및 게이트웨이 .1 자동 산출, 전체 network 서비스 재시작 미수행 동일하게 /24 및 .1 게이트웨이 산출, 전체 네트워크 서비스 재시작 대신 해당 활성 NIC 연결만 재기동

1.2 게스트 내부 3단계 실행 및 실제 변경 파일

  1. 1단계 (연결 확인 및 백업 스크립트 생성): nmcli con show --active에서 lo가 아닌 첫 번째 활성 연결을 조회하고, 변경 전 기존 네트워크 설정을 게스트 내부 /tmp/vm-ip-change/<호스트네임>.revert.sh로 저장합니다.
  2. 2단계 (IP 설정 적용): 해당 활성 연결(다중 NIC 환경에서도 첫 번째 활성 NIC만 대상)에 ipv4.addresses(<새IP>/24), ipv4.gateway(<대역>.1), ipv4.method manual을 설정합니다.
  3. 3단계 (연결 재기동): 대상 연결에 대해서만 nmcli con up을 실행해 새 IP를 즉시 활성화합니다.

ev02 페어 부하 분산 스케줄링: VM 이름이 ...ev02로 끝나는 경우 짝(pair)인 ...ev01 VM 및 BM ESXi 호스트명(ev01/ev02 접미 제외)을 판별합니다. 워커 슬롯(최대 16개)을 점유하기 전에 ev01의 1분 uptime 부하 평균과 BM 물리 코어 수를 비교하여 load >= cores이면 슬롯을 잡지 않고 대기(2분 간격 재확인)하며, ev01 또는 BM 코어 수를 확인할 수 없으면 즉시 진행합니다.

5. 백업 및 롤백 방법

자동 롤백 미지원 및 Ctrl+C 중단 주의: vm-ip-change는 중단이나 실패 시 이전 IP로 자동 롤백하지 않습니다. 작업 중 5초 이내에 Ctrl+C를 3회 누르면 종료 코드 130으로 중단되며, 이미 진행 중(in-flight)이던 VM 목록과 게스트 내부 /tmp/vm-ip-change/<호스트네임>.revert.sh 복구 안내만 출력합니다. 반면 SIGTERM이나 pkill로 강제 종료하면 요약·복구 안내조차 출력되지 않고 즉시 종료되므로 강제 시그널 전송을 피하십시오.
  • 자동 생성되는 게스트 내 백업 스크립트: 1단계(연결 확인)에서 기존 IP/게이트웨이 설정을 게스트 OS 내부의 /tmp/vm-ip-change/<호스트네임>.revert.sh에 자동 기록합니다.
  • 단일/소수 VM 롤백 방법:
    1. 새 IP로도 통신이 안 되거나 이전 IP로 복구해야 할 경우, vCenter Web Client의 VM 콘솔(VMRC)로 접속하거나 아직 새 IP로 SSH가 가능하면 SSH로 접속합니다.
    2. 게스트 내부에 생성된 /tmp/vm-ip-change/<호스트네임>.revert.sh 내용을 확인한 뒤 실행하여 기존 nmcli 설정을 복원합니다.
  • 실패 목록 기반 재시도: TUI에서 f 키로 저장한 vm-ip-change-failed-<TS>.txt는 호스트 IP # 사유 포맷이므로 원인 조치 후 곧바로 -list 인자로 넘겨 실패분만 재실행할 수 있습니다.

6. 작업 완료 후 랜덤 서버 실접속 교차검증 필수

[필수 검증 경고] 작업 완료 후 반드시 랜덤 VM 실접속 교차검증을 수행하십시오.

vm-ip-change가 종료 코드 0을 반환하더라도 다중 NIC 환경에서 첫 번째 활성 연결 외 다른 NIC 영향, 외부 방화벽/VLAN/ARP 캐시 불일치, 또는 게스트 내부 nmcli 영구 프로필 적용 상태를 완전히 보장하지는 않습니다. 배치 작업 완료 후에는 반드시 완료된 VM(ev01/ev02 포함) 중 랜덤 1~3대에 새 IP로 직접 SSH(또는 콘솔) 접속하여 아래 항목을 교차검증하십시오.

  • ip -4 addr show 및 ip route로 새 IP(/24)와 기본 게이트웨이(.1)가 실제 적용되었는지 확인
