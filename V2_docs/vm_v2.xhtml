Suite 개요 및 메타 정보

  • 원본 저장소 경로 (origin/master): .claude/VM/V2
  • 대상 브랜치: confluence (V2_docs/)
  • 주요 구성: 통합 빌드/배치(setup.sh, build_os6.sh, bin_os6/, bin_os8/), 암호화(passwd_update.sh, secret_lib.sh), 공유 자산(govendor/, SPEC_DIR/), VM 생성·설정 오케스트레이터(VMsetup/vm_setup.sh + 12종 Go 도구 + 3종 보조 .sh), 통합 체크·교정(vm-param-check-usability-improvement/vm-param-check)
  • 동작 환경: OS8(Rocky/RHEL 8: Go 1.26.5+ & Bash, 완전 오프라인 govendor/ 빌드) / OS6(RHEL/CentOS 6: Go 불필요, bin_os6/*.gz Go 1.20 정적 바이너리 + Bash 4.1 + openssl)
  • 한 줄 요약: BM당 ev01~ev99 VM 생성·리소스·포트그룹·PCI 패스스루 설정(VMsetup)과 설정 검증·자동교정(vm-param-check)이 하나의 SPEC_DIR을 공유하는 차세대 VM 자동화 통합 Suite

주의사항 (Disclaimer) — vCenter 실제 변경 및 무작위 실검증 필수

  • 변경 후 실검증: 본 Suite의 각 도구는 vCenter/ESXi 호스트 및 VM 설정(VM 생성, 포트그룹, CPU 토폴로지, affinity, HugePage, PCI 패스스루, 전원정책, 라이선스)을 실제로 변경합니다. 실행 완료 후 반드시 무작위로 VM·호스트 몇 대를 골라 vSphere Client 및 게스트 OS에서 실제 반영 여부를 직접 확인하십시오.
  • -fix -yes 안전 설계: vm-param-check의 -yes 플래그는 -specRoot 스펙 매칭 확인만 생략하며, -fix 실제 설정 변경 직전의 (y/N) 승인은 생략할 수 없습니다.
  • 암호 키 보안: secret/key 파일이 있으면 누구나 secret/*.enc를 복호화할 수 있으므로 root 전용 권한을 유지하고 Git에 절대 커밋하지 마십시오.

1. Suite 전체 개요 및 단계별 전체 흐름

V2는 기존 V1(.claude/VM/VM_setup의 ev01~ev03 개별 도구 + vm-param-fix)을 대체·확장한 차세대 통합 Suite입니다. 핵심 설계는 단일 SPEC_DIR 공유와 ev01~ev99 지원입니다. VMsetup/vm_setup.sh는 내부적으로 vm-param-check -specExport를 호출해 스펙을 해석하므로 생성 측과 체크 측의 파서가 한 벌로 통일됩니다.

3.1 폴더 통째 배치 및 setup.sh 오프라인 빌드 (OS8 vs OS6)

V2 폴더 내부 도구는 상대 경로(../SPEC_DIR, ../govendor, ../secret_lib.sh 등)로 서로를 참조하므로 V2 폴더를 통째로 복사해 배치해야 합니다. 의존성은 govendor/govmomi-0.55.1-standard(VMsetup 12종)와 govendor/govmomi-0.39.0(vm-param-check)에 들어 있으며, setup.sh는 GOPROXY=off, GOFLAGS=-mod=vendor, GOTOOLCHAIN=local, GOSUMDB=off, CGO_ENABLED=0을 강제합니다.

bash

Go 없는 OS8 서버 패치 (bin_os8/) 및 OS6 빌드 서버 (build_os6.sh):

  • bin_os8/: Go가 설치되지 않은 OS8 운영 서버에 PCI 패스스루 등 최근 변경분(pci_passthrough, vm-param-check, affinity_setting, lpage_setting)만 반영할 때 gzip -dc로 수동 해제합니다(UPDATE_PCI_PASSTHROUGH.md 참고). 주의: setup.sh는 bin_os8/을 읽지 않습니다.
  • build_os6.sh: RHEL6 커널(2.6.32)은 Go 1.21+ 실행파일을 구동할 수 없으므로 소스 수정 시 Go 1.20 빌드 서버에서 bash build_os6.sh로 bin_os6/*.gz를 재생성합니다.

3.3 공유 SPEC_DIR 규칙 및 스펙 매칭

  • 탐색 순서: SPEC_DIR은 -s <dir> → vm-param-check/SPEC_DIR(있으면 우선) → V2/SPEC_DIR 순으로 찾습니다. vcenter.txt는 V2/vcenter.txt → vm-param-check/vcenter.txt 순입니다.
  • 4분할 폴더명 매칭 규칙: <1>-<2>-<3>-<4>(하이픈 4조각) 중 1·3·4번째 조각이 완전 일치하고 2번째 조각의 접두어(CAE 또는 LSI) 뒤 숫자(차수)만 다른 경우 동일 스펙으로 인정합니다(예: TST-CAE001-SAMP48c-QRST ↔ TST-CAE003-SAMP48c-QRST; 단 CAE vs LSI는 다른 스펙).
  • _spec.txt 주요 키: ht, cpu/mem/disk/shares-ev01(쉼표 허용 예: disk=1024,1026, shares-ev01=4000,normal), cores, numa, affinity-ev01(파일명, ev마다 필수), cpu-ev02~99/..., pci-ev01~99(mellanox|nvidia|VendorId|장치이름일부), tag-DEPT_NAME/tag-PURPOSE/tag-VM_TYPE(값, evNN:값, evNN-evMM:값), evNN_del_affinity=y/evNN_del_lpage=y/all_del_affinity=y/all_del_lpage=y.

6. 통합 주의사항 · 알려진 한계 및 V1 대비 대체 관계

  • ev 상한 99대: VM 이름이 ev%02d 두 자리 규칙이므로 최대 ev01~ev99까지만 지원됩니다(ev100 이상 불가).
  • pci_passthrough BIOS 펌웨어 및 QueryConfigTarget 제약: NVIDIA GPU 등 큰 BAR 장치는 EFI 펌웨어 필수(BIOS면 실패). vCenter 클러스터 환경에서 호스트 지정 QueryConfigTarget이 거부될 경우 4단계 폴백 조회를 시도하며, 모두 실패 시 ESXi 직접 접속(-vcTargetIP <ESXi> -id root)이 필요합니다.
  • lpage_setting 한계: numa.vcpu.maxPerVirtualNode는 코어 수 기준으로 기록되므로 vm-param-check에서 FAIL 시 -fix로 교정하십시오.
  • mac_info 단독 실행: 단독 실행 시 IP가 _DNS_AND_TOOLS_NOT_FOUND로 채워지므로 필요 시 mac_ip_resolve.sh를 사용하십시오(vm_setup.sh는 자동 해석 수행).
  • V1(VM_setup) 대비 변경 요약: ① ev01~ev03 → ev01~ev99 확장 ② affinity_setting의 AUTO 1:1 계산 폐지(ev별 파일 필수) ③ vm-param-fix/(외부 바이너리 오케스트레이터) 제거 및 vm-param-check -fix 단일 바이너리 통합 ④ vm_setup.sh·SPEC_DIR 공유·passwd_update.sh·nic_assign·pci_passthrough·bin_os6/ 신설.
