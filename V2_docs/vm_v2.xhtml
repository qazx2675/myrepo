2. 처음 사용하기 전에 무엇을 준비하나?

  1. V2 폴더 전체를 서버에 둡니다. 바이너리에 실행 권한(chmod +x)이 있는지 확인합니다. OS6 는 bin_os6/*.gz 의 압축을 풉니다.
  2. ./passwd_update.sh 로 vCenter 암호를, ./passwd_update.sh -esxi 로 ESXi 암호를 등록합니다.
  3. VMsetup/<user>.txt(BM 목록)를 만듭니다.
  4. VMsetup/vswitch_<user>.txt(BM 별 포트그룹·VLAN)를 만듭니다.
  5. (선택) vcenter.txt 에 vCenter 목록을 씁니다.
  6. SPEC_DIR/ 에 스펙 폴더가 있는지 확인합니다. 없으면 vm_setup.sh 가 새 스펙을 만들도록 안내합니다.

2.1 암호는 어떻게 저장되나?

  • passwd_update.sh 는 secret/key(권한 600)로 암호를 암호화해 secret/*.enc 에 저장합니다 (openssl aes-256-cbc). OS6 와 OS8 에서 같이 읽습니다.
  • 기본 vCenter 계정은 lscsystems@vsphere.local 입니다. 다른 계정은 ./passwd_update.sh -id <계정> 으로 등록합니다.
  • vm_setup.sh 는 시작할 때 VC_PASSWORD, VC_PASS, VCENTER_PASS, ESXI_PASSWORD 환경변수를 지웁니다. 그 다음 암호 파일을 읽고, 없으면 직접 입력을 받습니다.

secret/key 를 공유하지 마십시오. 이 파일이 있으면 누구나 secret/*.enc 를 풀 수 있습니다. 권한 600(root 전용)을 유지하십시오.

3. vm_setup.sh 는 어떤 순서로 진행하나?

  1. user 를 고릅니다 (-u 가 없으면 <user>.txt 번호 메뉴).
  2. SPEC_DIR 에서 포트그룹 폴더 이름과 맞는 스펙을 자동으로 찾습니다. 없으면 번호로 고르거나 vim 으로 새 스펙을 만듭니다.
  3. VM 마다 네트워크 어댑터 1 의 포트그룹을 정하고, VM-스펙 표를 y/n 으로 확인합니다.
  4. (선택) CAE 번호를 바꿉니다. vCenter 를 고릅니다 (Enter 는 지난번 vCenter).
  5. 실행 계획을 확인합니다. -n 이면 여기서 끝납니다 (vCenter 변경 없음).
  6. 진행 화면에서 아래 단계를 실행합니다.
순서단계(하위 도구)하는 일
1main_connESXi 호스트를 vCenter 폴더(기본 Task)에 등록합니다.
2vswitch_setting표준 vSwitch(기본 vSwitch0)에 포트그룹·VLAN 을 만듭니다.
3vm_create스펙대로 ev01 ~ ev99 VM 을 만듭니다 (EFI, vmxnet3, 메모리 100% 예약). 이미 있는 VM 은 건너뜁니다.
4mac_infoVM 의 MAC 을 조회해 Kickstart 목록(mac_all.txt)을 만듭니다. 읽기 전용입니다.
5power_settingESXi 호스트 전원 정책을 고성능(static)으로 바꿉니다.
6affinity_settingVM 마다 vCPU affinity 파일을 적용합니다. V2 에서는 ev 마다 파일이 꼭 필요합니다.
7lpage_settingHugePage 와 CPU 토폴로지(cores/sockets/numa)를 설정합니다.
8pci_passthrough스펙에 pci-evNN 이 있을 때만 PCI 패스스루를 설정하고 VM 전원을 켭니다.
9license_assign평가판 호스트를 찾아 라이선스를 할당합니다 (BM 전체 1회, q 로 건너뜀).
10tag_setting스펙에 tag-* 가 있을 때만 사용자 지정 특성(DEPT_NAME, PURPOSE, VM_TYPE)을 씁니다.
11vm-param-check만든 VM 이 스펙과 같은지 자동으로 체크합니다 ([일치] / [차이]).

3.1 진행 화면은 어떻게 조작하나?

  • ↑ ↓ (k j): 단계를 고릅니다.
  • Enter: 단계 로그를 봅니다.
  • 모두 끝나면 [종료] 에서 Enter 를 2회 누릅니다.
  • 중단하려면 5초 안에 Ctrl+C 를 3회 누릅니다.
  • 파이프·nohup 이거나 VMSETUP_MONITOR=0 이면 진행 화면 대신 일반 로그를 출력합니다.

3.2 결과는 어디에 저장되나?

VMsetup/run_<user>/ 에 저장합니다: logs/, run.log, plan.txt, mac_all.txt, check_*.csv, pci_resume_*.sh

3.3 PCI 패스스루 뒤 재부팅이 필요하면?

  1. pci_passthrough 가 종료코드 3(재부팅 필요)을 내면 run_<user>/pci_resume_<번호>.sh 가 생깁니다.
  2. 해당 ESXi 호스트를 재부팅합니다.
  3. bash run_<user>/pci_resume_<번호>.sh 를 실행합니다. PCI 연결과 전원 ON 을 이어서 합니다.

4. 스펙(SPEC_DIR)은 어떻게 쓰나?

  • 찾는 순서: -s <dir> → vm-param-check/SPEC_DIR → V2/SPEC_DIR
  • 폴더 이름 규칙: <1>-<2>-<3>-<4> (하이픈 4조각). 1·3·4번째가 같고 2번째의 차수 숫자만 다르면 같은 스펙입니다. 예: TST-CAE001-SAMP48c-QRST 와 TST-CAE003-SAMP48c-QRST 는 같은 스펙입니다. CAE 와 LSI 는 다른 스펙입니다.
  • 새 스펙 만들기: vm-param-check -initFolder=<새 폴더> -template=<기존 폴더>, 또는 folder_setup.sh(대화형), 또는 vm_setup.sh 의 vim 편집

5. vm-param-check 로 체크·교정하려면?

  1. cd vm-param-check-usability-improvement/vm-param-check
  2. 체크만 합니다: ./vm-param-check -vcenterList=../../vcenter.txt -f=<목록> -specRoot=../../SPEC_DIR -out=result.csv -user=<user>
  3. 결과 CSV(result.csv, _summary.csv)를 확인합니다. 판정은 OK / FAIL / 설정없음 / 미지원 / 정보 입니다.
  4. 교정하려면 -fix 를 추가합니다. 순서: 게이트(같은 스펙인지 + 전원 OFF 인지) → dry-run → y/N 확인 → Reconfigure → 재검증 CSV(_recheck_*.csv)
  • -yes 는 스펙 매칭 확인만 건너뜁니다. -fix 의 y/N 확인은 건너뛸 수 없습니다.
  • 교정하려면 VM 전원이 꺼져 있어야 합니다.
  • vCenter 계정은 VC_USER/VC_PASS (또는 VCENTER_USER/VCENTER_PASS) 환경변수로 줍니다.

7. 문제가 생기면?

  • 로그인에 실패한다: ./passwd_update.sh -list 로 암호가 등록되어 있고 복호화되는지 확인하십시오.
  • 스펙을 찾지 못한다: 폴더 이름이 하이픈 4조각 규칙에 맞는지 확인하십시오. -specExport 로 해석 결과를 보십시오.
  • affinity 단계가 실패한다: V2 는 ev 마다 affinity 파일이 필요합니다. affinity-evNN 키와 파일을 확인하십시오.
  • NVIDIA GPU 패스스루가 실패한다: VM 펌웨어가 EFI 인지 확인하십시오. BIOS 이면 실패합니다.
  • 클러스터에서 PCI 장치 조회가 거부된다: ESXi 에 직접 접속해 실행하십시오 (-vcTargetIP <ESXi> -id root).
  • numa.vcpu.maxPerVirtualNode 가 FAIL 이다: vm-param-check -fix 로 교정하십시오.
  • -fix 가 VM 을 건너뛴다: VM 전원이 OFF 인지, 같은 스펙인지 확인하십시오.
  • 진행 기록을 보려면: VMsetup/run_<user>/run.log 와 logs/ 를 보십시오.

8. 자주 묻는 질문 (FAQ)

Q. V2 는 무엇을 하는 도구인가요?
A. ESXi 호스트에 VM(ev01 ~ ev99)을 만들고 CPU·메모리·HugePage·affinity·PCI·포트그룹 등을 한 번에 설정한 뒤, 설정이 스펙과 같은지 체크하는 VM 자동화 도구입니다. 실행 명령은 VMsetup/vm_setup.sh 입니다.

Q. VM 을 만들려면 무엇을 실행하나요?
A. ./passwd_update.sh 로 암호를 등록하고, VMsetup/<user>.txt 와 vswitch_<user>.txt 를 만든 뒤 cd VMsetup && ./vm_setup.sh 를 실행합니다.

Q. 실제로 바꾸기 전에 무엇이 바뀌는지 보려면?
A. ./vm_setup.sh -u <user> -v <vCenter> -n 을 실행합니다. 계획만 보여 주고 vCenter 를 변경하지 않습니다.

Q. 이미 만든 VM 의 설정이 맞는지 확인하려면?
A. vm-param-check 를 -specRoot 와 함께 실행합니다. 다른 항목은 -fix 로 교정합니다. 직전 vm_setup.sh 대상이면 bash 01.vm_setting_check_insert.sh -u <user> -fromSetup 을 씁니다.

Q. VM 을 몇 대까지 만들 수 있나요?
A. BM 당 ev01 ~ ev99, 최대 99대입니다.

Q. V2 와 VM_setup(V1) 은 무엇이 다른가요?
A. VM_setup(V1) 은 ev01 ~ ev03 만 지원하고 도구를 하나씩 실행합니다. V2 는 ev01 ~ ev99 를 지원하고, vm_setup.sh 한 번으로 전체를 실행하며, 생성과 체크가 같은 SPEC_DIR 을 씁니다. 새 작업에는 V2 를 쓰십시오.

Q. VM 의 IP 를 바꾸려면?
A. V2 는 IP 를 바꾸지 않습니다. VM 게스트 OS 의 IP 변경은 vm-ip-change(vCenter API IP 자동변경) 도구를 쓰십시오.
