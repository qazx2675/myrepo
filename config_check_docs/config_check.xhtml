동시성 및 -auto-check 지원 안내: config_check.sh는 원격 실행 명령에 /user/ 경로가 포함되어 있어 gossh v2의 동시 접속 350대 제한을 준수하며 범위 압축 출력(host[01-03])을 EXPAND_AWK로 자동 확장합니다. 또한 -auto-check 모드를 내장하고 있어 setup_check(new_setup) 및 auto_setup(t/x)과 별도 수정 없이 즉시 연동됩니다.

1. 개요 및 변경 대상 (실제 수정하는 파일 및 실행 스크립트)

config_check.sh는 다수의 HPC 서버를 대상으로 gossh v2 병렬 실행을 통해 OS 설정 상태를 일괄 점검(run.sh pd)하고, y 또는 set 적용을 통해 원격 설정 스크립트를 실행한 뒤 사후 재점검 및 벤더·상태별 결과 리포트를 출력하는 순수 Bash 오케스트레이션 스크립트입니다.

기존 os_config_check와 달리 회사 실제 경로·벤더 코드(D/S/L/J/T/W/X)·gossh v2 범위 압축 출력(host[01-03]) 확장 및 auto_setup / setup_check -run 연계가 통합되어 있습니다. 또한 사내 기존본을 안전하게 패치하기 위한 apply_auto_mode.sh + auto_mode.patch를 함께 제공합니다.

1.1 실제 실행 및 변경 대상

구분 호출 위치 / 대상 파일·스크립트 실제 수행 내용 및 변경 영향
사용자 정보 사전 갱신 로컬: ${user_info_mn} ($home/INFO/USER/info_mn.sh) → ${user_info_output} (info.sh) 실행 전 사용자 정보 목록을 참조·갱신하고 ${user}.txt 호스트 목록을 로드
원격 OS 사전/사후 점검 원격 대상: ${check_script} (bash /user/svrauto/SA/check/os/run.sh pd; :) 및 ${ai_server_script} gossh -pm -script -w로 병렬 점검 수행 (명령 내 /user/ 포함으로 gossh 동시성 350대 제한 준수). 읽기 전용 점검 및 로컬 결과 파일(check.res_*, check.info_${user}) 생성
원격 OS 설정 적용 (y) 원격 대상: ${insert_file} (setting_insert.sh), ${appl_setting_file} (appl_change.sh) 1회 gossh 호출로 설정 삽입 및 애플리케이션 설정 변경 스크립트 실행 (쓰기 작업)
원격 OS 설정 전체 적용 (set) 원격 대상: 위 y 대상 + ${setting_file} (setting.sh) -auto에서 p/d 접두 호스트 포함 시 또는 대화형 set 입력 시 기본 setting.sh 추가 실행 (fail|error|fatal|denied|not found 최대 50줄 로깅, 쓰기 작업)
보조 조회 (DHCP / VWP) ${dhcp_server} (SSH + /root/a.sh), ${vm_inventory} (vcenter_vm_inventory_status.txt) pingX > 0 시 dhcp_server 조회, ev 호스트에 대해 VWP 인벤토리 대조 수행

2. 사전준비 / 배치(빌드 불필요) · 입력파일 · 계정/암호화

2.1 빌드 여부 및 배치 방법 (순수 Bash — 빌드 불필요)

config_check는 순수 Bash 스크립트이므로 컴파일이나 Go 빌드가 전혀 필요하지 않습니다(빌드 불필요). 단, 원격 병렬 실행 엔진으로 반드시 gossh v2(-pm, -script, -w 및 범위 압축 파일 출력 지원)가 설치되어 있어야 합니다.

사내 기존본 덮어쓰기 금지: 운영 중인 사내 config_check.sh를 이 저장소 파일로 직접 덮어쓰지 마십시오. 기존본에 사내 고유 주석·벤더 메시지가 있을 수 있으므로, 반드시 apply_auto_mode.sh를 사용해 코드 라인만 패치해야 합니다. 이 스크립트는 주석이나 벤더 메시지가 수정되면 즉시 중단하고, 적용 전 <대상>.bak 백업을 자동 생성합니다.

2.2 입력 파일 및 계정/암호화 정책

  • 대화형 호스트 목록 (${user}.txt): 일반 실행 시 현재 작업 디렉터리에 있는 ${user}.txt를 읽습니다. 30행 다단 정렬 목록, 접두어별 대수, 총 N EA 요약 후 진행 여부를 묻습니다.
  • 비대화형 호스트 목록 (<호스트목록파일>): -auto <user> <호스트목록파일> 또는 -auto-check <user> <호스트목록파일> 호출 시 전달합니다.
  • 임시 디렉터리 및 동시성 제약: $TMPDIR/config_check.XXXXXX 또는 ${AUTO_SETUP_DIR:-/tmp/auto_setup}/tmp를 임시 작업 공간으로 사용합니다. 또한 원격 실행 명령에 /user/ 경로가 포함되어 있어 gossh의 동시 실행 제한(350대)을 스크립트가 그대로 준수합니다.
  • 계정/암호화: 별도의 비밀번호 파일이나 암호화 키를 두지 않으며, gossh 및 관리서버 SSH(dhcp_server 조회 등)의 기존 운영 계정/키 인증 체계를 그대로 사용합니다.

3. 표준 안전 절차 (사전 점검 → 소수 선행검증 → 전체 적용 → 연계/사후 검증)

config_check.sh는 -auto-check 모드를 통한 읽기 전용 사전 점검, 대화형 단계 확인 프롬프트, 소수 카나리 적용, 그리고 적용 직후 OK 호스트 재점검 및 외부 도구 연계를 통해 안전하게 배포합니다.

    -auto-check 모드로 대상 호스트에 설정 변경 없이 run.sh pd 점검만 수행합니다. setup_check(new_setup) 및 setup_check -run의 1단계도 이 모드를 호출해 읽기 전용 상태(check.res_new_setup)를 먼저 판정합니다.
