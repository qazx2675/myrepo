Confluence Intelligence 사용 권장: 이 문서는 Confluence Intelligence(질문형 AI)가 정확하게 답하도록 작성했습니다. 궁금한 점은 Confluence Intelligence 에게 질문하십시오.

이 문서는 질문-답변(Q&A) 형식입니다. 각 절은 다른 절을 읽지 않아도 이해되도록 도구 이름·명령·파일 이름을 반복해서 적었습니다. 도구 이름은 config_check 이고, 실행 파일은 config_check.sh 입니다.

0. 도구 요약 (핵심 사실)

항목내용
도구 이름config_check (실행 파일 config_check.sh, Bash)

2. 처음 사용하기 전에 무엇을 준비하나?

  1. gossh v2 가 설치되어 있는지 확인합니다.
  2. config_check.sh 위쪽의 설정 블록 경로가 맞는지 확인합니다 (7.1절). 기본 경로는 /user/siy/MGMT, /user/svrauto/SA/check/SETTING 입니다.
  3. 대화형 실행은 ${user}.txt 호스트 목록을 씁니다. -auto·-auto-check 는 호스트 파일을 인자로 줍니다.
  4. 설정을 적용하기 전에 대상 서버의 설정 파일을 백업하십시오. config_check.sh 는 원격 설정을 백업하지 않습니다.

4. 표준 작업 절차는 무엇인가? (안전 순서)

  1. 점검만 합니다: bash config_check.sh -auto-check canary_user ./canary_hosts.txt. FAIL 항목, LDAP 요약, 상태 줄을 확인합니다.
  2. 1~2대에 적용합니다: ${user}.txt 에 1~2대만 적고 bash config_check.sh 를 실행합니다. "작업을 진행하시겠습니까?"에 y, "환경설정을 수정하시겠습니까?"에 y(또는 set)를 입력합니다. 또는 bash config_check.sh -auto canary_user ./canary_hosts.txt 를 씁니다.
  3. 그 서버를 직접 확인합니다: 서버에서 bash /user/svrauto/SA/check/os/run.sh pd 를 직접 실행하고 리포트와 비교합니다.
  4. 전체에 적용합니다: bash config_check.sh -auto opuser ./all_hosts.txt
  5. 결과 리포트를 확인합니다 (5절).
  6. 무작위로 직접 확인합니다: y 적용 서버와 set 적용 서버(p/d 접두)에서 각각 1~3대를 골라 직접 접속하고 확인합니다.

6. auto_setup·setup_check 와는 어떻게 연결하나?

  • auto_setup: auto_setup.conf 의 os_check_sh 에 config_check.sh 경로를 씁니다. auto_setup 은 OS 설치가 끝난 서버에 -auto <user> <파일> 을 실행합니다. 시험 키 t/x 는 -auto-check 를 실행합니다.
  • setup_check(new_setup): new_setup.conf 의 OS_CHECK_SH 에 config_check.sh 경로를 씁니다(선택: OS_CHECK_EXCLUDE, CHECK_TIMEOUT). 1단계에서 bash <OS_CHECK_SH> -auto-check new_setup targets.txt 로 판정합니다. -run 2단계에서 "설치상태=완료, 설정체크≠O" 서버에 -auto 를 실행하고 다시 판정합니다.
  • OS_CHECK_SH 로 지정한 스크립트가 -auto-check 를 지원하지 않으면 setup_check 와 연결할 수 없습니다. config_check.sh 는 지원합니다.

8. 문제가 생기면? (롤백 포함)

  • 적용이 잘못되었다: config_check.sh 에는 롤백 기능이 없습니다. 미리 만든 백업으로 그 서버에서 직접 되돌리십시오.
  • setting.sh 오류가 일부만 보인다: 오류 줄은 최대 50줄만 기록합니다. 서버에 접속해서 직접 확인하십시오.
  • 범위 표기 서버가 리포트에서 빠졌다: gossh v2 의 범위 출력(host[01-03])은 스크립트가 펼칩니다. 빠진 서버가 있으면 직접 확인하십시오.
  • 실행이 느리다: 원격 명령에 /user/ 경로가 있어서 gossh 가 동시 실행 수를 줄입니다. 정상입니다.
  • 재작업할 서버를 찾고 싶다: check.info_${user}, check.res_${user}_postapply, 완료 마커를 보고 실패 서버를 고르십시오.

결과를 직접 확인하십시오. NO FAIL 이나 재판정 결과가 모두 정상이라도 일부 실패가 가려질 수 있습니다. 작업 뒤에는 y 적용 서버와 set 적용 서버에서 각각 1~3대를 골라 직접 접속하십시오. 그 서버에서 run.sh pd 를 실행하고 리포트와 비교하십시오. LDAP·Splunk 같은 설정이 실제로 반영되었는지 확인하십시오.

9. 자주 묻는 질문 (FAQ)

Q. config_check 는 무엇을 하는 도구인가요?
A. 여러 서버의 OS 설정을 점검하고, 고르면 설정을 적용하고, 다시 점검해서 결과 리포트를 출력하는 Bash 스크립트입니다.

Q. 설정을 바꾸지 않고 점검만 하려면?
A. bash config_check.sh -auto-check <user> <호스트파일> 를 실행합니다.

Q. y 와 set 은 무엇이 다른가요?
A. y 는 setting_insert.sh 와 appl_change.sh 를 실행합니다. set 은 여기에 기본 설정 스크립트 setting.sh 를 추가로 실행합니다.

Q. -auto 는 y 와 set 중 무엇을 고르나요?
A. 호스트 목록에 p 또는 d 로 시작하는 서버가 있으면 set, 없으면 y 를 고릅니다.

Q. 잘못 적용하면 되돌릴 수 있나요?
A. 자동 롤백은 없습니다. 적용 전에 대상 서버의 설정을 백업하고, 문제가 생기면 그 서버에서 직접 되돌리십시오.

Q. config_check 와 OS 환경설정 체크는 무엇이 다른가요?
A. 둘 다 점검 → 적용 → 재점검을 합니다. config_check 는 운영용 버전이며 auto_setup·setup_check 연계와 벤더 코멘트를 포함합니다. OS 환경설정 체크 는 이 연계가 없는 단독 스크립트(os_check_final_annotated.sh)입니다.

Q. 벤더 코멘트의 D, S, L 은 무엇인가요?
A. 호스트 이름 앞글자로 나눈 벤더 그룹입니다. 5절의 벤더 코드 표를 보십시오.
