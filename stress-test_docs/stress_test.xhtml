2. 처음 사용하기 전에 무엇을 준비하나?

  1. 실행 권한을 줍니다: chmod +x stress_run.sh setup.sh stress-test
  2. bash setup.sh 를 실행하고 질문에 답합니다. conf/${user}_setting.conf 를 만듭니다(권한 600). 기존 파일은 .bak 으로 백업합니다.
  3. ./stress-test -inspect -user <u> 로 AWX 템플릿 survey·인벤토리 설정을 점검합니다. 추천 값을 보여 줍니다.
  4. AWX 에 username 과 같은(또는 포함하는) 이름의 인벤토리가 있어야 합니다.
  5. 호스트 입력 파일(user.txt)을 만듭니다 (2.1절).

예전 설정 키가 있으면 실행하지 않습니다. cpu_intel_* / cpu_amd_* 키가 남아 있으면 종료 코드 2 로 멈춥니다. bash setup.sh 를 실행하면 값을 cpu_template / cpu_hostname_key / cpu_extra_vars 로 자동으로 옮깁니다.

3. stress-test 는 어떤 순서로 동작하나?

  1. AWX 사전 확인: cpu_template, stress_template, username 인벤토리, default_inventory 가 있는지 확인합니다.
  2. 접속·CPU 벤더 확인: gossh 로 vendor_id 를 읽습니다. 결과는 Intel / AMD / unknown / 접속불가 입니다.
  3. (선택) 기존 인벤토리 삭제: inventory_delete_host 가 있으면 첫 등록 전에 delhost_<user> 를 1번 실행하고 삭제를 확인합니다.
  4. 등록: yaml 을 만들고 repohost 로 보낸 뒤 custom_inventory.sh 를 실행합니다. 새 *.yml 을 확인하고, 인벤토리를 동기화하고, 대상 호스트가 정확히 같은지 확인합니다.
  5. (cpu 단계만) 인벤토리 바꾸기: CPU 템플릿 인벤토리가 DEFAULT 인지 확인합니다. 다른 사람이 쓰고 있으면 질문합니다. 내 인벤토리로 바꾸고 실행한 뒤 바로 DEFAULT 로 되돌립니다.
  6. AWX job 완료 대기: job 은 부하 프로세스를 띄우고 끝납니다.
  7. 부하 감시: monitor_interval(기본 10초)마다 1분 로드를 읽습니다. load_threshold(기본 3) 이상이면 실행 입니다. monitor_sec(기본 120초)가 지나도 낮으면 미실행 입니다.
  8. 재실행: 미실행 서버를 다시 실행할지 묻습니다(y/N). 비대화형은 -retry N 을 씁니다.
  9. 결과표: 화면에 출력하고 <output_dir>/${user}_stress_result.txt 에 저장합니다.

단계를 두 개 고르면(ab 또는 ba) 앞 단계의 감시가 끝난 뒤 다음 단계를 실행합니다.

4. 대화형 실행(stress_run.sh)은 어떻게 하나?

  1. bash stress_run.sh user.txt 를 실행합니다.
  2. user 를 고릅니다.
  3. 단계를 고릅니다: a(cpu), b(stress-ng), ab, ba
  4. b 를 골랐으면 stress-ng 종료 시각을 입력합니다.
  5. 감시 화면을 봅니다.
  6. 미실행 서버가 있으면 재실행 질문에 y 또는 N 을 입력합니다.

6. setup_check 와는 어떻게 연결되나?

  • setup_check(new_setup -run, -run -auto)가 stress-test -user <u> -hosts <목록> -steps a|b -batch [-end ...] [-conf ...] [-ignore-offline] 를 실행합니다.
  • -batch 는 감시 화면 대신 [감시] ... 한 줄 요약을 출력합니다. setup_check 는 이 줄을 등록·실행 완료 신호로 씁니다.
  • CPU 템플릿 인벤토리가 DEFAULT 가 아니면 [인벤토리사용중] ... 을 출력하고 입력 1줄을 기다립니다. setup_check 화면이 사용자에게 묻습니다(r 다시 확인 / x 묶음 중단).
  • new_setup -run -auto 는 실행 전에 -yaml-state 로 다른 사용자가 yml 을 덮어썼는지 확인합니다.
  • setup_check 는 [제외], [job], [결과], [삭제확인], [등록] 줄로 시도 횟수와 결과를 추적합니다.

8. 문제가 생기면?

  • 부하가 걸렸는데 미실행 이다: 1분 로드는 천천히 오릅니다. 템플릿이 부하를 늦게 띄우면 monitor_sec 안에 기준에 못 미칩니다. 장비에 맞게 monitor_sec 이나 load_threshold 를 조정하십시오. 또는 재실행하십시오.
  • 인벤토리 복원에 실패했다: AWX 에서 CPU 템플릿의 인벤토리를 DEFAULT 로 직접 바꾸십시오.
  • 종료 코드 2 로 멈춘다: 설정 파일·입력 파일·인자를 확인하십시오. ./stress-test -inspect -user <u> 로 AWX 설정을 점검하십시오.
  • 다른 사람과 동시에 실행했다: 같은 인벤토리 소스를 동시에 바꾸면 마지막 값이 남습니다. 동시에 실행하지 마십시오.
  • 부하를 멈추고 싶다: 이 도구에는 부하 프로세스를 끝내는 기능이 없습니다. stress-ng 는 -end 시각에 끝납니다.

현장 확인이 필요한 부분: 실제 운영 AWX 의 survey 구조, 템플릿 인벤토리 변경 권한, custom_inventory.sh 의 실제 파일 이름 규칙, AMD 장비의 vendor_id 응답은 현장에서 확인하십시오.

9. 자주 묻는 질문 (FAQ)

Q. stress-test 는 무엇을 하는 도구인가요?
A. AWX 로 cpu·stress-ng 부하테스트를 실행하고, 서버의 1분 로드를 감시해서 부하가 실제로 걸렸는지 판정하는 도구입니다.

Q. 부하테스트를 어떻게 실행하나요?
A. bash stress_run.sh user.txt 를 실행하고 메뉴에서 단계를 고릅니다.

Q. 미실행 은 무슨 뜻인가요?
A. 감시 시간(기본 120초) 동안 1분 로드가 기준(기본 3)보다 낮았다는 뜻입니다. 재실행하거나 서버에 직접 접속해 확인하십시오.

Q. AWX 템플릿 설정을 바꾸나요?
A. cpu 단계에서만 CPU 템플릿의 인벤토리를 잠시 바꾸고, 실행 직후 DEFAULT 로 되돌립니다.

Q. 설정 파일은 어떻게 만드나요?
A. bash setup.sh 를 실행하고 질문에 답합니다.

Q. stress-ng 는 언제 끝나나요?
A. 입력한 종료 시각(-end 연,월,일,시,분)에 끝납니다.

Q. 신규 설치 점검과 부하테스트를 한 번에 하려면?
A. setup_check -run 을 쓰십시오. setup_check 가 stress-test 를 자동으로 실행합니다.
