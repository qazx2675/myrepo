# RHEL 서버 Current Password 자동 대응 스크립트 — 계획서

작성일: 2026-09-29 (최종 업데이트)
작성자: Claude (요청자: aisoki2675@gmail.com)
대상 환경: 록키 리눅스(Rocky Linux, 192.168.0.58) 등 본인이 관리하는 RHEL 계열 서버 **최대 3대**
목적: 평소에는 별도 비밀번호 롤테이션 스크립트로 서버 비밀번호가 자동 갱신되지만, 대상 리스트 누락 등으로
간혹 갱신되지 않은 서버가 SSH 접속 시 `Current password` 변경 프롬프트를 띄우는 경우가 있음. 이런 소수의
누락 서버에 대해, 관리 중인 과거/현재 비밀번호 후보(`old_password.txt`, 약 20개) 중 유효한 것을 찾아 로그인하고,
지정된 새 비밀번호로 맞춰주는 소규모 복구 자동화 도구. 기존에는 `expect`로 처리하던 것을 Go로 재작성.

> ⚠️ 전제: 본인이 직접 관리/소유하고 있으며 비밀번호 이력을 알고 있는 서버(최대 3대)에 한해 사용.
> `list.txt`에 명시되지 않은 서버, 본인 관리 범위를 벗어난 서버에는 사용하지 않음.

> 📌 **구현은 다른 세션에서 진행 예정.** 이 문서는 그 세션이 바로 코딩을 시작할 수 있도록
> 요구사항·설계·확정 사항을 정리한 핸드오프 스펙입니다.

---

## 1. 요구사항 정리

1. **실행 위치**: Go 코드는 이미 Go가 설치된 록키 리눅스(192.168.0.58)에서 빌드/실행.
2. **대상 서버**: `list.txt`에 줄바꿈으로 IP만 나열 (최대 3대 수준). 계정은 **root 고정**.
3. **셸 환경 다양성**: 로그인 셸이 `csh`(대부분) 또는 `bash`(일부)로 다를 수 있음 → 프롬프트 패턴을 셸 무관하게 흡수해야 함.
4. **비밀번호 변경 플로우 2가지 패턴**:
   - **패턴 A (3단계)**: `Current password` → `New password` → `Retype new password`
   - **패턴 B (2단계)**: (Current 단계 없이) `New password` → `Retype new password` 바로 진행
   - → 스크립트가 매 단계 프롬프트를 보고 **동적으로 분기**해야 함 (고정 스텝 수로 가정 금지).
5. **프롬프트 발생 경로**: SSH 인증 단계(keyboard-interactive)에서 뜨는 경우와, 로그인 성공 후 셸에서
   `passwd` 계열 명령이 자동 실행되어 뜨는 경우 **모두 가능** → 두 경로 모두 지원.
6. **변경 후 세션 동작 차이**: 비밀번호 변경 완료 직후 세션이 즉시 종료되는 경우와 유지되는 경우가 모두 있음
   → 둘 다 정상 성공으로 판단해야 함 (연결 종료를 실패로 오판 금지).
7. **old_password.txt**:
   - 실제 관리 대상 서버들이 사용 중인 비밀번호 후보를 줄 단위로 기록 (약 20개), **최신이 맨 위**.
   - 맨 위(최신)부터 순서대로 시도, 실패 시 다음 줄로 진행.
   - 모두 실패하면 "접속불가"로 기록.
   - **자동 갱신 없음**: 스크립트가 성공한 비밀번호를 이 파일에 자동으로 추가/재기록하지 않음 (수동 관리, 보안 유지 목적).
8. **새 비밀번호 적용**:
   - 적용할 새 비밀번호는 평문으로 두지 않고 **암호화 파일**로 저장, 실행 시 복호화해서 사용.
   - 예: `asdf`를 암호화한 파일을 두면, 이를 이용해 실제 계정 비밀번호가 `asdf`로 바뀌어야 함.
9. **암호화 키 위치**: 스크립트/설정과 **동일 경로**(같은 디렉터리)에 키 파일 보관.
10. **동시 실행**: 계정 잠금(lockout) 정책 없음 → 시도 간 딜레이 불필요, 서버 간 병렬 처리 가능.
11. **우선순위**: 1순위 속도, 2순위 위 모든 케이스(셸 종류·2단계/3단계·프롬프트 경로·세션 종료 방식)에서 current password 탐색 성공.

## 2. 전체 아키텍처

```
run.sh  (실행 편의용 bash 래퍼)
  └─ go build → ./pwreset
  └─ ./pwreset -list list.txt -oldpw old_password.txt -newpw newpass.enc -key key.bin -out result.csv

pwreset (Go 바이너리)
  ├─ list.txt 로딩 (IP만, 계정은 root 고정)
  ├─ 새 비밀번호 파일 복호화 (key.bin 사용, 메모리에만 보관)
  ├─ old_password.txt 로딩 (순서 유지, 약 20줄)
  ├─ 서버별 goroutine (병렬 처리, lockout 정책 없어 딜레이 불필요)
  │    └─ SSH 접속 시도 (최신 비번부터 순차)
  │         ├─ 인증 단계에서 Current/New password 프롬프트 감지 (keyboard-interactive) → 상태머신 처리
  │         ├─ 로그인 성공 후 셸에서 passwd류 프롬프트 감지 (pty 세션) → 상태머신 처리
  │         ├─ 인증 실패(Permission denied) → old_password.txt 다음 줄로 재시도
  │         └─ 모든 비번 실패 → "접속불가" 기록
  └─ 결과를 result.csv로 저장 (old_password.txt는 건드리지 않음)
```

### 핵심 설계 포인트

- **두 가지 프롬프트 경로를 모두 지원**:
  1. **SSH 인증 단계**: `golang.org/x/crypto/ssh`의 `KeyboardInteractiveChallenge` 콜백에서
     `Current password:` / `New password:` / `Retype new password:` 류 질의에 순서대로 응답.
  2. **로그인 후 셸 단계**: 인증 성공 후 `session.RequestPty()` + stdin/stdout 파이프로 pty 세션을 열고,
     출력 스트림에서 동일한 프롬프트 패턴을 정규식으로 매칭해 stdin에 응답 (expect가 하던 방식과 동일한 접근).
  - 실행 시 먼저 keyboard-interactive 경로로 시도하고, 인증이 일반 password 방식으로만 성공하면
    pty 셸 경로의 상태머신을 이어서 대기시키는 방식으로 **둘 다 자동 커버**.
- **상태머신 기반 프롬프트 매칭** (고정 스텝 대신):
  ```
  상태: WAIT_CURRENT_OR_NEW
    "Current password" 매치 → 시도 중인 비번 재입력 → 상태: WAIT_NEW
    "New password" 매치      → 새 비번 입력           → 상태: WAIT_RETYPE   (패턴 B로 전환)
  상태: WAIT_NEW
    "New password" 매치 → 새 비번 입력 → 상태: WAIT_RETYPE
  상태: WAIT_RETYPE
    "Retype new password" / "Retype" 매치 → 새 비번 재입력 → 상태: DONE_OR_CLOSED
  상태: DONE_OR_CLOSED
    셸 프롬프트($/#/%) 감지 → 성공 (세션유지형)
    EOF/커넥션 종료 감지    → 성공 (세션종료형)
    "passwd: all authentication tokens updated" 류 문구 → 성공 마킹 후 위 둘 중 하나 대기
  ```
  csh/bash 프롬프트 정규식은 별도 목록으로 관리(`% `, `# `, `\$ `, 커스텀 PS1 등 확장 가능).
- **타임아웃**: 각 read 단계마다 짧은 타임아웃(5~8초)으로 "세션 종료 vs 응답 없음" 구분, 전체 세션 타임아웃(30초)으로 행 방지.
- **병렬 처리**: lockout 정책이 없으므로 서버 3대 모두 동시에 goroutine으로 처리 (속도 우선).
- **비밀번호 암호화 파일**:
  - AES-256-GCM 대칭키 암호화. 키는 스크립트와 동일 폴더의 `key.bin`(권한 0600)에 보관.
  - `pwreset -encrypt -in plain.txt -out newpass.enc -key key.bin` 서브커맨드로 사전에 새 비번을 암호화.
  - 실행 바이너리는 파일+키를 읽어 메모리에서만 평문 복호화, 로그/디스크에 평문 비번을 남기지 않음.

## 3. 파일 구성

```
.claude/패스워드변경자동화/
  계획서.md                 (본 문서)
cmd/pwreset/
  main.go                   실행 진입점, 플래그 파싱, encrypt 서브커맨드
  sshclient.go               ssh 접속 (keyboard-interactive + pty 셸 양쪽 지원)
  promptfsm.go                Current/New/Retype 상태머신 (경로 공통)
  cryptutil.go                 AES-GCM 암복호화
  targets.go                   list.txt 로딩 (IP 목록, root 고정)
  report.go                     결과 기록 (result.csv만; old_password.txt는 read-only)
run.sh                        (사용자 편의) 빌드 + 실행 래퍼, 인자 검증, 사용법 출력
list.txt                      [입력] 대상 서버 IP, 줄바꿈 구분 (최대 3줄)
old_password.txt              [입력] 비밀번호 후보 이력 (약 20줄, 최신이 맨 위, read-only)
newpass.enc / key.bin         [입력] 새 비번 암호화 파일 + 키 (스크립트와 동일 경로)
result.csv                     [출력] ip,found_password_index,status(성공/접속불가),새비번적용여부
```

`run.sh`는 "실행 편의용 bash 스크립트"로 `go build`, 인자 유효성 검사, `pwreset` 호출만 담당하고,
실제 로직은 전부 Go 쪽(`pwreset`)에 둡니다.

## 4. 검증 가능한 성공 기준

1. csh 로그인 셸 + 패턴 A(3단계, 인증 단계 프롬프트) 서버에서 current password 탐색 및 비번 변경 성공.
2. bash 로그인 셸 + 패턴 B(2단계, 셸 단계 프롬프트) 서버에서도 동일하게 성공.
3. 변경 직후 세션이 즉시 끊기는 서버 / 유지되는 서버 둘 다 "성공"으로 정확히 분류.
4. `old_password.txt`의 모든 후보(약 20개)가 실패하는 서버는 `result.csv`에 "접속불가"로 명확히 기록.
5. `newpass.enc`에 `asdf`를 암호화해 넣고 실행하면, 실제 서버 비밀번호가 `asdf`로 바뀌는 것을 재로그인으로 확인 가능.
6. 실행 후 `old_password.txt`는 변경되지 않고 그대로 유지됨 (수동 관리 원칙 준수).
7. 3대 서버를 동시에 병렬 실행해도 각 서버의 결과가 독립적으로 정확히 기록됨.

## 5. 더 나은 대안 제안

- **expect 대신 Go**: `golang.org/x/crypto/ssh`로 인증 단계는 keyboard-interactive 콜백으로,
  셸 단계는 pty 세션으로 각각 처리 — expect 한 가지 방식보다 커버리지가 넓고 병렬 처리도 쉬움.
- **드라이런 모드**: `-dry-run` 플래그로 실제 비번 변경 없이 "어떤 비번으로 로그인되는지"만 확인하는 모드를 추가하면
  운영 중 실수 방지에 도움이 됩니다.
- **result.csv 분리 유지**: old_password.txt는 순수 이력(읽기 전용)으로 두고, 실행 결과는 별도 `result.csv`에만
  남기는 현재 설계를 그대로 권장.

## 6. 구현 세션을 위한 다음 단계

1. `list.txt`(대상 IP 최대 3개), `old_password.txt`(비번 후보 약 20개), `newpass.enc`+`key.bin` 준비.
2. `cmd/pwreset` 패키지 생성 후 위 설계대로 구현 (SSH 인증 단계 + pty 셸 단계 상태머신 공통화).
3. `run.sh` 작성 (빌드 + 인자 검증 + 실행).
4. 실제 3대 서버 중 한 대에서 패턴 A/B, csh/bash, 세션종료/유지 조합을 최소 1회씩 실제 테스트.
5. 완료 후 본 폴더(`.claude/패스워드변경자동화/`)에 작업 기록을 추가.
