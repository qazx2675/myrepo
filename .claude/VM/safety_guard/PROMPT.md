# 안전장치 추가 프롬프트

다른 Go 도구에 이 안전장치를 붙일 때 아래 블록을 Claude 에게 그대로 주십시오. `<…>` 부분만 채웁니다.

```text
<프로젝트 경로> 의 Go 도구 <도구명> 에, 위험 작업(<예: 전원 끄기 / 삭제 / 설정 변경>) 직전에 실행되는
안전장치 5단계를 추가해줘.

[재사용할 것]
- /…/safety_guard 패키지(safetyguard)를 그대로 쓴다. 로직을 새로 짜거나 단계 규칙을 바꾸지 않는다.
- 폐쇄망 빌드가 되도록 패키지를 프로젝트 안(vendor 또는 하위 패키지)에 복사해 넣고 외부 접속 없이 빌드되게 한다.

[붙이는 위치]
- 대상 목록(<대상이 뭔지>)을 확정·검증한 뒤, 실제 작업을 실행하기 직전에 sg.RunGuard 를 호출한다.
- 대상은 사용자가 3단계에서 전체 이름으로 입력할 문자열 목록으로 넘긴다(중복·공백 없는 고유 이름).
- 취소(err != nil)면 아무 작업도 하지 않고 exit 1. 통과 후에만 작업을 시작한다.
- 특수 대상(<예: 담당자 확인이 필요한 대상>)이 있으면 RunGuard 앞에 sg.ConfirmCode 로 별도 6자리 코드를 한 번 더 받는다.
- stdin 은 sg.NewLineReader(os.Stdin) 하나만 만들어 비밀번호 등 모든 입력에 같이 쓴다.

[지켜야 할 것]
- 5단계: 6자리 코드 → 대상·총 대수 → Enter(60초 안내) → 60초 안에 대상 이름 전체 입력(순서 자유, 중복/누락/초과 취소) → YeS(대소문자 구분) → 10..1 가로 카운트다운.
- 모든 취소는 사유 출력 + exit 1, Ctrl+C 처리.
- 감사 로그를 남기되 확인 코드·비밀번호는 기록하지 않는다.
- 요청한 것만 수정하고 기존 코드 스타일을 따른다.

[검증]
- go vet / go test -race 통과, 취소 경로(코드 틀림·이름 누락·중복·YeS 소문자·시간 초과·Ctrl+C) 시험 추가.
- test/guard_scenarios.sh 형태의 파이프 입력 시나리오로 PASS/FAIL 확인.
- README 에 사용법과, 작업 후 무작위 서버 몇 대를 직접 확인하라는 주의사항(Disclaimer)을 넣는다.
```
