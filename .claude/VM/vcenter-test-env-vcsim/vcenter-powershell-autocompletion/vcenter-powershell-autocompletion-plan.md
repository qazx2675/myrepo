# [프로젝트 계획서] vCenter 조작용 PowerShell 실습 환경 구축 및 CLI 자동완성 보조 시스템

## 1. 프로젝트 개요

**프로젝트명 (가칭):** vCenter 조작용 PowerShell 명령어 자동완성 및 최적화 가이드 시스템

**추진 배경:**
- PowerShell 및 VMware PowerCLI를 처음 접하는 초심자/교육생의 진입 장벽 완화
- 터미널 환경에서도 IDE(VS Code 등)와 유사한 수준의 명령어·API 자동완성 및 힌트 제공 필요
- 대규모 vCenter 환경에서 비효율적인 순차 조회 명령어로 인한 지연을 예방하고, 초기 학습 단계부터 고성능 조회 패턴(Get-View, 병렬 처리)을 체득하도록 유도
- 교육생이 실 vCenter를 직접 건드리며 연습할 수 없으므로, 안전하게 반복 연습할 수 있는 테스트 환경 필요

**프로젝트 목표:**
- 터미널 기반의 직관적인 PowerCLI 명령어·API 자동완성 환경 구성
- 기존 검증된 PowerShell 생태계 도구(PSReadLine, TabExpansion 등)의 적극적인 연계 및 활용 — **자체 CLI/셸 개발은 지양**
- 순차 조회 명령(Get-VM 등) 입력/실행 시 고성능 조회(Get-View, 병렬 쿼리) 권장 가이드 출력
- 외부 인터넷이 차단된 폐쇄망 환경을 고려한 오프라인 설치 및 실습 배포 체계 수립
- `vcsim` 기반 테스트 환경과 연동하여, 실 vCenter와 동일한 구조에서 안전하게 반복 실습 가능하도록 구성

**(사전 조사 결론, 계획에 반영):** PowerShell 7+에 기본 포함된 `PSReadLine`은 Windows/Linux/macOS 완전 크로스플랫폼이며 인라인 예측, ListView 메뉴, 구문 강조를 이미 제공한다. 또한 PowerShell의 네이티브 멤버 완성(dot-completion, `TabExpansion2`)은 `Get-View`가 반환하는 `VMware.Vim.*` 강타입 .NET 객체에 대해 **리플렉션 기반으로 속성/메서드(API)까지 자동완성**해 준다. 즉 "명령어는 되는데 조회한 API 결과의 속성/메서드는 자동완성이 안 되는" 문제는 기존 pwsh 자체 기능으로 이미 해결되며, 별도 프로그램 개발이 필요 없다. 리눅스 pwsh에서도 동일하게 동작하므로, 계획서상 "차선책(대체 CLI 셸 자체 제작)" 시나리오는 사실상 발생하지 않는다.

## 2. 핵심 기능 및 기술 아키텍처 계획

### 2.1. CLI 자동완성 및 사용자 경험(UX) 고도화 — 기존 도구 조합 전략

- **PSReadLine**: 인라인 예측(Inline Prediction) 및 ListView 채택. 과거 실행 이력(History) 기반 예측 활성화
- **PowerShell 네이티브 멤버 완성**: `Get-View`, `Get-VM` 등이 반환하는 객체에 대해 `.` 입력 후 Tab으로 속성/메서드(API)까지 자동완성 — 별도 개발 불필요, PowerCLI 모듈의 타입 어셈블리가 오프라인 배포판에 정상 포함되는지만 검증하면 됨
- **Register-ArgumentCompleter**: vCenter 인벤토리 객체(VM명, 호스트명, 클러스터명 등)를 명령어 인자 위치에서 실시간 완성하도록 커스텀 Argument Completer 등록 (이 부분이 이 프로젝트의 실제 개발 대상)
- **IDE 수준 편의 기능**: 구문 강조, 괄호/따옴표 자동완성(PSReadLine 기본 제공), 단축키 기반 도움말/파라미터 힌트 매핑

### 2.2. 고성능 명령어 권고 엔진 — PowerShell 프록시 함수 방식

- **구현 방식**: `Get-VM`, `Get-VMHost`, `Get-Datastore` 등 순차 조회 성향 cmdlet을 **PowerShell 프록시 함수(Proxy Function)** 로 감싸서, 실행 시점에 경고 메시지 출력
  - (참고: `ICommandPredictor` 기반 정식 예측 플러그인은 C#/.NET 어셈블리로 작성해야 하며 20ms 응답 제약이 있어, 이 프로젝트의 목적(안내 메시지 출력)에는 과한 방식으로 판단 — 프록시 함수로 충분)
- **피드백 메시지 예시**: `Get-VM` 입력 시 "해당 명령어는 대규모 인프라에서 순차 조회를 수행하여 성능이 저하될 수 있습니다. Get-View -ViewType VirtualMachine 또는 필터 기반 쿼리 사용을 권장합니다."
- **병렬 실행 패턴 권장**: 대량 객체 변경 작업 시 `ForEach-Object -Parallel` 또는 비동기 태스크 처리 방식 힌트 표기
- **억제(Bypass) 옵션**: 단순 디버깅/단일 객체 조회 등 정당한 사유가 있는 경우 스위치 파라미터(`-SkipAdvisory` 등)로 안내 메시지 무시 가능

## 3. 폐쇄망(Air-Gapped) 인프라 구축 및 배포 계획

### 3.1. 오프라인 패키지 사전 번들링 전략
- PowerShell 7.6.4 오프라인 설치 아카이브: 타겟 리눅스 배포판용 바이너리 및 필수 종속성(OpenSSL, LibICU 등) 사전 수집
- 모듈 오프라인 저장소: VMware PowerCLI 전체 모듈, PSReadLine 최신 모듈, 본 프로젝트의 커스텀 프로필/프록시 함수/ArgumentCompleter 모듈 패키징

### 3.2. 오프라인 설치 스크립트(setup.sh) 설계
- 설치 전 검증: OS 버전/아키텍처/기존 PowerShell 설치 여부/필수 라이브러리 검사, 실행 권한 확인
- 배치: 번들 압축 해제 및 `/opt/microsoft/powershell/7/` 등 지정 경로 배포, 전역 심볼릭 링크 생성
- 설정: 공용 모듈 경로에 PowerCLI/PSReadLine 복사, 인증서 경고 무시/CEIP 비활성화 등 PowerCLI 기본 설정 적용, `$PROFILE`에 자동완성/권고 가이드 초기화 로직 등록
- (설치/검증 스크립트 자체는 bash로 충분 — Go 도입은 필수 아님. 다만 여러 배포판/아키텍처를 대상으로 하나의 정적 바이너리로 사전 점검·번들 무결성 검증 도구를 배포하고 싶다면 이 영역에 한해 Go 활용을 검토 가능)

## 4. 실습 환경: 기존 `vc-test-env`(vcsim) 연동

교육생이 실 vCenter를 직접 조작하며 연습할 수 없으므로, 실 vCenter와 이름·구조가 동일한 안전한 테스트 환경이 필요하다. 이 요구사항은 같은 저장소(`myrepo`)의 형제 프로젝트인 **`../vc-test-env`**(`.claude/VM/vcenter-test-env-vcsim/`)가 이미 해결해 놓은 문제이므로, 새로 만들지 않고 그대로 연동한다.

- **연동 방식**: `vc-test-env`를 실행하면 실 vCenter의 인벤토리(데이터센터/클러스터/호스트/VM/네트워크)와 주요 설정값을 추출해 로컬 `vcsim`(`127.0.0.1:54321` 고정 포트) 위에 동일한 구조로 재현한다. 교육생은 이 vcsim 주소로 `Connect-VIServer -Server 127.0.0.1:54321 -Force`로 접속해 실습하면 되고, 자동완성/권고 엔진 쪽 코드는 대상이 실 vCenter든 vcsim이든 손댈 필요가 없다(PowerCLI 입장에서는 동일한 vSphere API 엔드포인트).
- **폐쇄망 배포와의 결합**: `vc-test-env`도 `vendor/`에 의존성이 포함되어 있어 인터넷 없이 빌드 가능하므로, 3장의 오프라인 번들에 `vc-test-env` 실행 파일과 사전 추출된 레시피(`~/.vc-test-env/recipes/`)를 함께 포함시켜 배포한다.
- **역할 분리**: `vc-test-env`는 "실습 대상 인프라를 안전하게 복제"하는 역할만 담당하고, 본 프로젝트(자동완성/권고 엔진)는 그 위에서 "PowerShell 사용 경험"을 다루는 역할로 명확히 분리한다. 두 프로젝트는 독립적으로 유지보수하되, 설치 스크립트/실습 시나리오 문서에서는 함께 안내한다.
- **알려진 한계 계승**: `vc-test-env`의 README에 정리된 한계(씨드 호스트 하나 더 표시, 다중 데이터센터 미지원, 네트워크 VLAN ID 미재현, 호스트 전원정책 미적용 등)는 실습 시나리오 설계 시 그대로 고려해야 한다 — 예를 들어 다중 데이터센터를 다루는 실습은 현재 구성으로는 지원되지 않는다.

## 5. 교육 및 실습 시나리오 구성 계획

- **Step 0 (사전 준비)**: `vc-test-env` 실행으로 실습용 vcsim 기동 → 실 vCenter와 동일한 구조 확인(트리 출력)
- **Step 1**: 환경 진입 및 기본 편의 기능 체득 — PowerShell 구동 즉시 명령어/속성 자동완성 확인, vcsim 접속 후 Tab 완성으로 탐색 속도 향상 경험
- **Step 2**: 순차 조회 vs 고성능 조회 비교 실습 — `Get-VM` 실행 시 안내 메시지 확인, 동일 작업을 `Get-View`로 수행했을 때 속도·API 호출 구조 차이 분석 (vcsim 위에서 반복 실행해도 실 인프라에 영향 없음)
- **Step 3**: 실무 스크립팅 모범 사례 정착 — 대규모 가상화 환경에 부하를 주지 않는 효율적 자동화 스크립트 작성 습관 체득

## 6. 단계별 추진 일정 (마일스톤)

| 단계 | 주요 추진 내용 | 산출물 |
|---|---|---|
| Phase 1: 요구사항 정의 및 도구 조사 | PSReadLine/네이티브 멤버완성 동작 검증, PowerCLI 주요 명령어별 성능 지표 분석 및 대체 명령어 매핑 | 명령어 권고 규칙 정의서, 활용 도구 목록 정의서 |
| Phase 2: 폐쇄망 배포 체계 수립 | PowerShell 7.6.4 및 PowerCLI 오프라인 번들 구성, setup.sh 설치 로직/예외 처리 설계, `vc-test-env` 번들 포함 | 오프라인 설치 패키지 구조도, setup.sh 상세 설계서 |
| Phase 3: 자동완성 및 가이드 모듈 설계 | ArgumentCompleter 설계, 프록시 함수 기반 Get-View 권고 로직 설계 | 모듈 아키텍처 명세서, 터미널 UI/UX 출력 가이드 |
| Phase 4: vcsim 실습 환경 통합 | `vc-test-env`로 실습용 vcsim 기동 절차 문서화, 자동완성/권고 엔진을 vcsim 대상으로 스모크테스트 | vcsim 연동 가이드, 실습 시나리오 스크립트 |
| Phase 5: 통합 테스트 및 교육 환경 검증 | 폐쇄망 모의 환경 설치 스크립트 무결성 검증, 학생 대상 모의 실습 및 사용성 피드백 수집 | 테스트 결과 보고서, 실습 환경 배포 매뉴얼 |

## 7. 기대 효과

- **교육 효율성 극대화**: 명령어 오타/문법 오류로 인한 실습 지연을 줄이고 핵심 인프라 제어 로직 이해에 집중 가능
- **실무형 인재 양성**: 단순 기능 동작에 만족하지 않고, 대규모 환경에서의 성능과 확장성을 고려하는 엔지니어링 감각 조기 습득
- **환경 의존성 제거**: 폐쇄망/보안 환경에서도 단일 스크립트 실행으로 일관된 고품질 실습 인프라 신속 배포 가능
- **안전한 반복 실습**: 실 vCenter를 건드리지 않고 `vc-test-env`/vcsim 위에서 자유롭게 반복 연습 가능

## 8. 리스크 및 제약사항

- 프록시 함수/ArgumentCompleter가 PowerCLI 버전 업데이트 시 cmdlet 시그니처 변경에 영향받을 수 있음 — 버전 고정 또는 호환성 테스트 필요
- `vc-test-env`가 이미 정리한 한계(4장 참고)는 이 프로젝트에서 새로 해결하지 않고, 실습 시나리오 범위에서 제외하거나 별도로 안내
- 오프라인 번들에 PowerShell/PowerCLI/PSReadLine/`vc-test-env`까지 여러 구성요소가 들어가므로, 버전 조합별 호환성 검증(Phase 4)이 지연 요인이 될 수 있음
