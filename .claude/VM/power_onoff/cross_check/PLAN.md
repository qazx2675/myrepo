# 📋 [계획서] 원격 2인 1조 교차검증 데몬 (`cross_check`) 구축

## 1. 개요 및 목적
* **도입 배경:** 2인 1조 크로스체크(확인자가 작업 대상을 직접 붙여넣어 검증) 진행 시, 확인자(Checker)가 작업자(User)의 자리로 직접 이동해야 하는 물리적 불편함과 피로도를 해소하기 위함.
* **핵심 목표:**
  1. 작업자와 확인자가 각자의 터미널에서 `cross_check` 데몬을 통해 원격으로 작업 대상을 대조·승인하는 체계 구축.
  2. 모든 교차검증 요청에 대해 대기/승인/중단 등의 상태를 데몬에 정확히 기록 및 관리.
* **대상 환경:** Red Hat Enterprise Linux (RHEL) 계열

---

## 2. 작업 환경 및 스킬(Skill) 활용 기준
* **코드 탐색 및 TUI/기타 참고:** `/grafify auto_setup` 스킬을 실행하여 기존 `auto_setup`의 TUI 조작 방식 및 구조를 참고하여 개발한다.
* **Git 업로드 방식:** 작업 완료 후 업로드 양식은 `git-upload-sk` 스킬을 따른다.
* **브랜치 및 경로:** `safety_guard` 브랜치 내에 `cross_check` 폴더를 생성하여 구성한다.

```text
safety_guard (branch)
└── cross_check/
    ├── README.md              # 사용법 및 승인 후 2분 타임아웃 정책 명시
    ├── cmd/
    │   └── cross_check/       # CLI 및 TUI 진입점 (--run, --user, --admin 등)
    ├── internal/
    │   ├── daemon/            # 상시 거주 데몬, 세션/프로세스 감지, 상태 관리
    │   ├── tui/               # TUI 화면 및 커맨드 조작 (auto_setup 참고)
    │   ├── verify/            # 대상 목록 붙여넣기 파싱(줄바꿈/탭/공백) 및 대조

```

## 3. 실행 방법 및 상세 동작 프로세스

### 0. 기본 실행 및 데몬 상시 거주 (공통)
* **기본 실행:** `cross_check --user {user}` 형태로 실행하며, 실행 시 항상 사용자를 지정한다.
* **데몬 상시 거주:** `cross_check` 데몬이 RHEL 시스템에 상시 거주하도록 `crontab`에 등록하여 유지한다. (데몬이 종료되어 있을 경우 자동 기동)

### 1. 작업 스크립트 내부 실행 (`--run`)
* **실행 구문:**
  ```bash
  cross_check --run --user {user} --checker {check_user}
  ```
  *(※ 스크립트 내부에서 호출되는 단계이며, 플래그 오타 방지를 위해 `--checker`와 `--cechker` 모두 처리 가능하도록 구현)*
* **동작 규칙:**
  1. **동일인 검증:** `user`와 `check_user`가 같으면 즉시 취소 처리한다.
  2. **대기 및 연동:** 데몬에 작업을 등록(`대기` 상태)하고, 지정된 `check_user`가 승인할 때까지 대기한다.
  3. **작업자 스크립트 종료 감지 (중단 처리):** 대기 중 작업자의 스크립트가 종료(Ctrl+C, 세션 끊김, 강제 종료 등)되면 데몬은 이를 감지하여 해당 작업을 즉시 **`중단`** 표시로 변경한다.

### 2. 사용자/확인자 TUI 접속 및 검증 (`--user`)
* **실행 구문:**
  ```bash
  cross_check --user {user}
  ```
* **작업 목록 표시:**
  * 실행한 `{user}`가 **작업자인 작업(내 작업)** 또는 **확인자(`check_user`)로 지정된 작업(내가 체크인인 작업)**이 있을 경우, `해당 작업 + user명` 리스트가 TUI 화면에 출력된다.
* **확인자(Checker) 조작 프로세스:**
  1. 확인자가 TUI 환경에서 커맨드로 해당 작업에 진입한다. *(※ 이 단계에서는 별도의 입력 시간제한을 두지 않는다.)*
  2. 확인자가 전달받은 작업 대상을 붙여넣기 한다.
     * **구분자 허용:** 줄바꿈(`\n`), 탭(`\t`), 스페이스(` `)를 모두 구분자로 허용하여 파싱한다.
  3. **작업 승인:** 붙여넣은 작업 대상이 일치하면 작업자에게 작업 승인이 전달되어 작업자의 스크립트가 다음 단계를 진행한다.
  4. **작업 취소:** 지정된 `checker`는 TUI 내에서 해당 작업을 직접 **취소(중단)**할 수 있으며, 취소 시 작업자의 스크립트도 취소 처리된다.

### 3. 관리자 수동 처리 모드 (`--admin`)
* **실행 구문:**
  ```bash
  cross_check --admin
  ```
* **동작 규칙:**
  * 관리자 모드로 접속하여 잘못된 기록이나 비정상 상태의 작업 내역 등을 수동으로 변경·정리·삭제 처리할 수 있는 기능을 제공한다.

## 4. 작업 상태 기록 및 필수 문서화 정책

### 1) 작업 상태 기록 관리
데몬을 거치는 모든 작업은 진행 상황에 따라 아래 상태가 기록되어야 한다.
* **대기:** 작업자 스크립트에서 `--run`이 실행되어 확인자의 처리를 기다리는 상태
* **승인:** 확인자가 작업 대상을 정확히 붙여넣어 승인이 완료된 상태
* **중단:** 
  * `user`와 `check_user`가 동일하여 취소된 경우
  * 확인자(`checker`)가 작업을 취소한 경우
  * 확인자가 붙여넣은 대상이 일치하지 않는 경우
  * **작업자의 스크립트가 대기 중 종료된 경우**
  * 승인 완료 후 2분 내에 후속 작업이 진행되지 않아 취소된 경우

### 2) 문서 필수 명시 사항 (승인 유효시간 2분 제한)
* `cross_check` 관련 문서(README 및 가이드)에 다음 규칙을 반드시 명시하고 구현에 반영한다.
  > **[필수 정책]** `cross_check` 데몬을 사용하는 작업의 경우, 확인자의 **승인 완료 후 2분 내에 본 작업을 진행하지 않으면 해당 작업 승인은 자동으로 취소(중단)** 처리된다.
