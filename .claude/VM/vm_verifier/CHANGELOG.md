## 2026-08-25 — 조회 속도 개선 + `-f` 목록 자동 정규화

### 1. 조회 속도 개선

대상이나 vCenter 인벤토리가 커질수록 급격히 느려지던 지점 네 군데를 고쳤습니다. 검증 판정 로직 자체는 그대로입니다.

- **vCenter 조회를 2단계로 분리 (`vc/vc.go`)** — 가장 큰 원인. 예전에는 `FetchAll`이 인벤토리 **전체 VM**에 대해 `config.hardware.device`를 받아왔다. 이 속성은 디스크·컨트롤러·NIC·비디오카드까지 다 들어있는 아주 무거운 값이라, 실제로 필요한 건 대상 몇 대뿐인데도 응답 크기가 전체 VM 수에 비례해 커졌다. 이제 ① 전체에서 `name`만 가볍게 훑고 ② 대상 접두어에 매칭된 VM의 MoRef에 대해서만 장치 정보를 배치 조회한다. 새 `FetchMatching(ctx, client, match)`이 이를 담당하고, 기존 `FetchAll`/`FetchByNames`는 그 위의 얇은 래퍼로 남겼다.
- **접두어 매칭 방향 반전 (`main.go`)** — 예전에는 접두어마다 정규식 `^<접두어>ev\d+$`를 컴파일해 전체 VM 이름에 하나씩 돌려서 (대상 수 × 전체 VM 수)만큼 정규식 매칭이 일어났다. 이제 VM 이름에서 접두어를 직접 떼어내(`splitBase`) 맵으로 분류하므로 VM 수에만 비례한다(정규식도 쓰지 않는다). 판정 조건은 기존 정규식과 동일함을 테스트로 고정했다.
- **DHCP 대역 파일 캐시 (`dhcp/dhcp.go`)** — `Resolve`는 hostname마다 불리는데 보통 많은 hostname이 같은 대역 파일에 속한다. 예전에는 그 파일을 hostname 수만큼 반복해서 읽고 정규식으로 다시 파싱했다. 이제 경로 기준으로 파싱 결과를 캐시해 대역당 한 번만 읽는다(`parseFileCached`, 뮤텍스로 보호). 공개 API인 `ParseFile`은 캐시 없는 그대로라 기존 동작·테스트는 영향 없다.
- **DNS 조회의 그룹 배리어 제거 (`main.go`)** — 예전 `buildJobs`는 그룹마다 `wg.Wait()`로 막았다. 그룹당 VM이 2~3대뿐이면 동시성 슬롯 대부분이 노는 채로 그룹 수만큼 대기가 직렬로 쌓였다(그룹이 많을수록 그대로 느려짐). 이제 전체 hostname을 한 번에 병렬 조회한 뒤 그룹별 교차설치 판정을 한다.
- **동시 실행 수 옵션화 (`main.go`)** — 예전에는 `min(CPU 수, 16)` 고정이었는데, 이 작업은 CPU가 아니라 DNS·파일 I/O 대기가 대부분이라 CPU 수에 맞출 이유가 없다. `-concurrency` 플래그로 빼고 기본값을 32로 올렸다.

### 2. `-f` 목록 자동 정규화

- `-f` 목록에 BM 접두어 대신 **VM 이름을 그대로 적어도** 되게 했다. 예를 들어 `hostnameaev01 / hostnameaev02 / hostnamebev01 / hostnamebev02`를 적으면 접두어 `hostnamea`, `hostnameb`로 자동 변환하고 **중복 제거 + 이름순 정렬** 후 실행한다(`normalizeTargets`).
- 정리가 일어나면 시작할 때 `[INFO] 대상 목록 정리: 4줄 -> BM 접두어 2개 (...)`로 알려준다.
- `ev` + 숫자로 끝나지 않는 줄은 손대지 않고 그대로 접두어로 쓴다.
- 접두어별로 찾은 VM 목록도 이름순 정렬해서, 실행할 때마다 출력 순서가 동일하도록 했다(예전에는 맵 순회 순서라 매번 달라졌다).

### 3. 검증

- `go build` / `go vet` / `go test -race` 전부 통과.
- **기존 매칭 규칙과의 동등성**을 테스트로 고정(`main_test.go`의 `TestSplitBaseMatchesOldRegex`): 접두어 13종 × VM 이름 18종의 모든 조합에 대해 새 `splitBase` 방식과 기존 정규식 `^<접두어>ev\d+$`의 판정이 완전히 일치함을 확인.
- 목록 정규화는 `TestNormalizeTargets`로 6가지 경우(VM 이름만/접두어만/혼재 중복/미정렬/`ev숫자` 아님/접두어가 비는 `ev01`) 확인.
- DHCP 캐시는 `dhcp/cache_test.go`로 확인 — 첫 파싱 뒤 파일을 지워도 같은 결과가 나오는지(캐시 적중), 50개 goroutine 동시 접근이 안전한지.
- vcsim으로 E2E 확인: 사용자가 말한 그대로 `hostnameaev01/hostnameaev02/hostnamebev01/hostnamebev02`를 순서까지 섞어 `-f`에 넣고 실행 → 접두어 2개로 정리되고 VM 4대를 자동 탐색, MAC이 맞는 그룹은 PASS, 일부러 MAC을 뒤바꾼 그룹은 교차 설치(역설치)로 정확히 탐지.
