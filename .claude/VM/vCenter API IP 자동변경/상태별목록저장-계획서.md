# vm-ip-change 상태별 목록 저장 키(s/f/l) 계획서

## 목표 및 범위
- 진행 화면(60초 이후 목록 화면)에서 `s`(완료) / `f`(실패) / `l`(진행중)을 눌러 상태별 목록을 각각 파일로 저장한다. 기존 `s`(전체 저장)는 완료 전용으로 바뀐다.
- 포함: `internal/tui/tui.go` 키 처리·저장 함수, 단위 테스트, README·CHANGELOG·사용법.txt 갱신.
- 제외: 60초 이전 구간의 키 입력, 종료 시 최종 결과 자동 저장, 저장 폴더/파일명 옵션, 대기 목록 저장.

## 주요 기능
1. `s` → `vm-ip-change-done-<시각>.txt`: 줄마다 `호스트명 새IP 경과시간`(앞 두 열은 list.txt 형식).
2. `f` → `vm-ip-change-failed-<시각>.txt`: `호스트명 새IP # 실패 사유` (앞 두 열은 그대로 `-list` 재실행 입력 가능, `#` 뒤는 주석).
3. `l` → `vm-ip-change-running-<시각>.txt`: `호스트명 새IP # 현재 단계 경과시간`.
4. 저장 직후 안내줄에 "저장됨: 파일명 (N건)", 도움말 줄은 `s 완료 저장  f 실패 저장  l 진행중 저장`.

## 단계별 마일스톤
1. 저장 함수 분리(상태별 필터 + 공통 파일 쓰기).
2. 키 연결(s/f/l, 대소문자 동일, 기존 s 전체 저장 제거).
3. 단위 테스트.
4. fake-vcenter + Rocky 랩 pty 하네스로 로컬 검증(`-vms 200 -slow 30 -fail 10`).
5. README/CHANGELOG/사용법.txt 갱신, master 푸시, `vm-ip-change-standalone` 재분할.

## 기술 스택 / 아키텍처
- 변경은 `tui.go`/`tui_test.go`뿐. 상태 판정은 기존 `countAll`과 같은 기준(Outcome/Phase)을 써서 화면 숫자와 파일 내용이 어긋나지 않게 한다.
- 파일명에 시각을 넣어 여러 번 눌러도 시점별로 남는다(같은 초 재입력은 덮어쓸 수 있음 — 허용).
- 기존 raw 모드 키 리더 재사용. s/f/l은 ESC 시퀀스와 겹치지 않는다.

## 리스크 및 제약사항
- 기존 `s`의 의미가 바뀐다(전체 → 완료만). CHANGELOG에 명시. (가정: 전체 저장은 더 필요 없음)
- 진행중 목록은 저장 순간의 스냅샷이라 파일 간 경계 대상이 겹치거나 빠질 수 있다. 대상당 상태를 한 번만 읽어 한 파일 안에서는 일관되게 쓴다.
- 60초 이전에는 키가 동작하지 않는다(기존 제약).
- Windows 로컬에서는 키 입력 자동 검증이 어려워, 단위 테스트 + Rocky 랩 pty 시험으로 나눈다. 실제 vCenter 검증은 별도.
