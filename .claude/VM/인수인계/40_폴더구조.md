## 4. ⚠️ 같은 이름이 여러 개

**`vm-param-check`는 여러 벌입니다.** AI에게 수정을 요청할 때 반드시 전체 경로를 적으세요.

| 경로 | 정체 | 쓰나 |
|---|---|---|
| `V2/vm-param-check-usability-improvement/vm-param-check/` | **현행** (ev01~ev99, `-specExport`) | ✅ |
| `vm-param-check-usability-improvement/vm-param-check/` | V1 (ev01~ev03) | ❌ |
| `integrated-vm-param-check-test-tool/vm-param-check/` | 사본 | ❌ |
| `vm-param-setting-check/` | 점검 전용 구버전 | ❌ |

**VMsetup 도구(`vm_create` 등)도 2벌**: `V2/VMsetup/*-source`(현행) / `VM_setup/*-source`(V1).

**`vm-network-migration`도 2벌**: `Network_Change_Integration_Script/projects/vm-network-migration/`(통합본에서 사용) / `vm-network-migration/`(원본). 자동 동기화되지 않습니다.

> 원본을 고치면 사본은 자동으로 바뀌지 않습니다. 버그 수정은 복사본에도 필요한지 판단하세요(예: 2026-09-23 `vcenter.txt` 줄 끝 주석 버그는 V2·V1·vm-param-setting-check·integrated에 함께 적용).

## 5. Go 프로젝트 공통 구조

```
<도구 폴더>/
├── README.md          # 1차 자료 (빌드·사용·옵션)
├── CHANGELOG.md       # 변경 이력 (최신이 위) ← 수정 시 반드시 갱신
├── ARCHITECTURE.md    # 파일별 역할, 수정 요청별 진입점
├── WORKFLOW.md        # 흐름도 (mermaid) + workflow.svg
├── PR_CHECKLIST.md    # 수정·배포 전 점검 목록
├── main.go / cmd/     # 진입점, 옵션(flag) 정의
├── setup.sh           # 오프라인 빌드 (-mod=vendor, GOPROXY=off)
└── vendor/            # 의존성 (또는 govendor 로의 링크) — 건드리지 말 것
```
