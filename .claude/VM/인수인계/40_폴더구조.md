## 3. ⚠️ 같은 이름이 여러 개 — 헷갈리지 마세요

**`vm-param-check`라는 이름이 저장소에 3벌 있습니다.** AI에게 수정을 요청할 때 반드시 전체 경로를 적어야 하는 이유입니다.

| 경로 | 정체 | 쓰나 |
|---|---|---|
| `vm-param-check-usability-improvement/vm-param-check/` | **현행 주력 버전** (자동교정 + 스펙 자동매칭) | ✅ 이걸 쓰세요 |
| `integrated-vm-param-check-test-tool/vm-param-check/` | 폐쇄망 테스트 패키지 안에 넣어둔 **사본** | 테스트할 때만 |
| `vm-param-setting-check/` | 체크 전용 **구버전** (바이너리 이름만 `vm-param-check`) | ❌ 레거시 |

**`vc-test-env`도 2벌**입니다.

| 경로 | 정체 |
|---|---|
| `vcenter-test-env-vcsim/` | 원본 |
| `integrated-vm-param-check-test-tool/vc-test-env/` | 테스트 패키지 안의 사본 |

**`vm_create`도 2벌**입니다.

| 경로 | 정체 |
|---|---|
| `VM_setup/vm_create-source/` | 개별 도구 버전 |
| `vm-setting-go-lang/main_vm_create.go` | 병렬화된 v2 버전 |

> **원본을 고치면 사본은 자동으로 안 바뀝니다.** 테스트 패키지 쪽 사본도 함께 고쳐야 하는지 판단하세요. (예: 2026-08-23 NUMA 버그는 `vm-param-check`와 `vm-param-setting-check` 양쪽에 같이 적용했습니다.)

## 4. Go 프로젝트 공통 구조

거의 모든 폴더가 같은 모양입니다.

```
<도구폴더>/
├── README.md        # 1차 자료 — 가장 정확한 설명
├── PLAN.md          # (있으면) 설계 배경, 왜 이렇게 만들었는지
├── CHANGELOG.md     # (있으면) 날짜순 변경 이력 ← 수정 시 반드시 갱신
├── 계획서.md          # (있으면) 설계 결정과 검증 근거
├── main.go          # ★ CLI 진입점 — flag 정의가 여기 있습니다
├── go.mod / go.sum  # Go 모듈 정의
├── setup.sh         # ★ 폐쇄망 빌드 (go build -mod=vendor)
├── run.sh           # (있으면) 대화형/통합 실행 스크립트
├── internal/ 또는 <패키지>/  # 실제 로직
└── vendor/          # ★ 의존성 소스 통째로 — 절대 건드리지 말 것
```

### 어느 파일을 봐야 하나

| 알고 싶은 것 | 볼 파일 |
|---|---|
| **이 옵션의 정확한 기본값과 설명** | `main.go`의 `flag.String(...)` / `flag.Int(...)` / `flag.Bool(...)` 정의 |
| 이 도구가 무엇을 하는지 | `README.md` |
| 왜 이렇게 설계했는지 | `PLAN.md` 또는 `계획서.md` |
| 최근에 무엇이 바뀌었는지 | `CHANGELOG.md` |
| 빌드가 어떻게 되는지 | `setup.sh` |
| 판정 기준을 고치려면 | `checker/` 아래 |
| 교정 로직을 고치려면 | `fixer/` 아래 |
| 출력 형식을 고치려면 | `report/` 아래 |
| vCenter 조회를 고치려면 | `vcenter/` 또는 `internal/vsphere/` |

> **옵션의 정확한 사실을 확인할 때는 README가 아니라 `main.go`의 `flag` 정의를 보세요.** README가 갱신되지 않았을 가능성이 있습니다.

## 7. git에 올리지 않는 파일

각 프로젝트의 `.gitignore`에 등록되어 있습니다. **저장소를 받은 뒤 직접 만들어야 합니다.**

| 파일 | 왜 |
|---|---|
| `vcenter.txt` | 실제 vCenter IP |
| `targets.txt`, `{user}.txt`, `worklist.txt` | 실제 서버 이름 |
| `vswitch_{user}.txt` | 실제 네트워크 구성 |
| `state_{user}.json`, `failed_*.txt` | 실행 중 생성되는 상태 |
| `LOG/` | 감사 로그 |
| 빌드된 바이너리 | 각자 빌드 |
| `*.csv` (결과) | 실행 결과 |

**반대로 git에 올리기를 권장하는 것**: `SPEC_DIR/` 아래 스펙 정의 파일(`*_spec.txt`). 인증정보가 아니라 CAE 스펙 값이라 민감정보가 아니고, 팀이 함께 쓰는 게 낫습니다.
