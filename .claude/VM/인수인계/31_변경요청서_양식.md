# 31. 변경 요청서 양식

> 이 문서의 양식을 **복사해서 채운 뒤 AI에게 그대로 주면** 됩니다.
> 작성 요령과 예시는 [30_유지보수_AI_활용가이드](./30_유지보수_AI_활용가이드.md)에 있습니다.

---

## A. 기본 양식

```markdown
아래 변경 요청을 처리해줘.
시작하기 전에 대상 경로의 README.md → 계획서.md/PLAN.md(있으면) → CHANGELOG.md → ARCHITECTURE.md 를 이 순서로 읽고
기존 구조와 컨벤션을 파악한 뒤에 착수해.
"제약/유지할 것"에 적힌 항목은 요청에 없어도 임의로 바꾸지 마.
변경 범위가 합의한 것보다 커지면 진행 전에 먼저 알려줘.

## 변경 요청

- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/____________________
- 참고 문서: README.md, 계획서.md, CHANGELOG.md (이 순서로 먼저 읽고 시작할 것)

### 요청 내용
(무엇을 바꾸고 싶은지 한두 문장. 버그면 "재현 방법"도 함께)

### 재현 방법 (버그일 때만)
1.
2.
→ 기대 동작:
→ 실제 동작:

### 제약 / 유지할 것
- 오프라인 빌드가 계속 되어야 함 — 새 외부 의존성 추가 금지 (vendor/govendor 사용 중)
- 기존 안전장치(게이트, 확인 프롬프트, 롤백)는 건드리지 말 것
- 기존 옵션의 이름·기본값·미지정 시 동작(스킵 등)은 그대로 유지
- 비밀번호는 환경변수로만 받는 방식 유지
- 요청한 파일 외에는 건드리지 말 것
- (도구별 추가 제약을 여기에)

### 완료 기준
- bash setup.sh (오프라인 빌드) / go vet 통과
- 대상 폴더 PR_CHECKLIST.md 항목 확인
- 실 vCenter 대상 2대로 최소 1개 시나리오 재현 확인
- CHANGELOG.md 에 오늘 날짜로 항목 추가 (무엇을/왜/영향범위/확인)
- README.md 의 옵션표·설명 갱신
- .claude/VM/인수인계/ 의 해당 도구 문서(바로 쓰는 명령어·옵션표·주의사항) 갱신
```

### B-1. vm-param-check (11번)

```markdown
- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/V2/vm-param-check-usability-improvement/vm-param-check
- 참고 문서: README.md → 계획서.md → ../CHANGELOG.md

### 제약 / 유지할 것
- -fix 의 게이트(같은 스펙·같은 그룹 동질성, 전원 OFF)는 절대 제거/우회하지 말 것
- -yes 가 "실제 설정 변경 확인"까지 생략하게 만들지 말 것 (스펙 자동매칭 확인만 생략)
- 옵션 미지정 시 해당 체크를 스킵하는 기존 동작 유지
- VM 1대당 Reconfigure 를 한 번만 호출하는 구조 유지
- 새 기대값 옵션을 추가하면 스펙 파일에서도 지정 가능하게(specSettableFlags) 등록할 것
  (단, -fix/-out 같은 동작 플래그는 스펙 파일에서 지정 불가여야 함)
- SPEC_DIR 스펙 형식은 VMsetup/vm_setup.sh 도 읽는다 — 형식을 바꾸면 양쪽을 함께 맞출 것
- 그룹 이름 ev%02d (ev01~ev99) 규칙 유지
- 오프라인 빌드 유지 (../../govendor/govmomi-0.39.0)

### 완료 기준
- bash setup.sh / go vet 통과, .claude/VM/V2/PR_CHECKLIST.md 확인
- 실 vCenter 대상 2대로 점검 1회, (교정 관련이면) -fix 1회
- ../CHANGELOG.md, README.md 옵션표 갱신
- 인수인계 문서 11번의 1절 명령어 / 4절 옵션표 / 7절 한계 갱신
```

### B-2. V2 VMsetup (10번)

```markdown
- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/V2/VMsetup/<도구폴더명>-source   (전체 흐름이면 .claude/VM/V2/VMsetup/vm_setup.sh)
- 참고 문서: 해당 폴더 README.md → ../README.md → ../CHANGELOG.md → ../../WORKFLOW.md

### 제약 / 유지할 것
- 다른 -source 폴더는 건드리지 말 것 (각 폴더는 독립 모듈)
- 비밀번호는 VC_PASSWORD 환경변수로만 받는 방식 유지
- 계정 기본값(개별 도구 lscsystems@vsphere.local, vm_setup.sh administrator@vsphere.local)을 바꾸지 말 것
- ev01 필수·ev 번호 연속·값 없는 ev 는 만들지 않음·ev99 상한 규칙 유지
- affinity 는 ev 마다 파일 필수 (자동 계산 되살리지 말 것)
- 실패 시 [오류] 출력 + 종료코드 1, 이미 있는 VM/포트그룹은 성공으로 건너뛰는 동작 유지
- vm_setup.sh 는 실패한 단계에서 멈추고 [완료]를 출력하지 않는 동작 유지
- 적용 후 재조회로 확인하는 동작 유지
- 오프라인 빌드 유지 (../../govendor, Go 1.26.5)

### 완료 기준
- cd /home && bash setup.sh <도구> 성공, go vet 통과, .claude/VM/V2/PR_CHECKLIST.md 확인
- vm_setup.sh -n 으로 계획 출력 확인, 실 vCenter 에서 호스트 1대로 실행 확인
- ../CHANGELOG.md, 해당 README.md 갱신
- 인수인계 문서 10번의 해당 옵션표 갱신
```

### B-5. Network_Change_Integration_Script (14번)

