# 31. 변경 요청서 양식

> 이 문서의 양식을 **복사해서 채운 뒤 AI에게 그대로 주면** 됩니다.
> 작성 요령과 예시는 [30_유지보수_AI_활용가이드](./30_유지보수_AI_활용가이드.md)에 있습니다.

---

## A. 기본 양식 (복사해서 쓰세요)

```markdown
아래 변경 요청을 처리해줘.
시작하기 전에 대상 경로의 README.md → 계획서.md(있으면) → CHANGELOG.md 를 이 순서로 읽고
기존 구조와 컨벤션을 파악한 뒤에 착수해.
"제약/유지할 것"에 적힌 항목은 요청에 없어도 임의로 바꾸지 마.
변경 범위가 처음 합의한 것보다 커지면 진행 전에 먼저 알려줘.

## 변경 요청

- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/____________________
- 참고 문서: README.md, 계획서.md, CHANGELOG.md (이 순서로 먼저 읽고 시작할 것)

### 요청 내용
(무엇을 바꾸고 싶은지 한두 문장. 버그면 "재현 방법"도 함께)

### 재현 방법 (버그일 때만)
1.
2.
→ 기대 동작:
→ 실제 동작:

### 제약 / 유지할 것
- 오프라인 빌드가 계속 되어야 함 — 새 외부 의존성 추가 금지 (vendor/ 사용 중)
- 기존 안전장치(게이트, 확인 프롬프트, 롤백)는 건드리지 말 것
- 기존 옵션의 이름·기본값·미지정 시 동작(스킵 등)은 그대로 유지
- 비밀번호는 환경변수로만 받는 방식 유지
- 요청한 파일 외에는 건드리지 말 것
- (도구별 추가 제약을 여기에)

### 완료 기준
- go build -mod=vendor / go vet / go test ./... 전부 통과
- 가능하면 vcsim 또는 실 vCenter로 최소 1개 시나리오 재현 검증
- CHANGELOG.md 에 오늘 날짜로 항목 추가 (기존 형식 그대로: 무엇을/왜/영향범위/검증)
- README.md 의 옵션표·설명 갱신
- .claude/VM/인수인계/ 의 해당 도구 문서(옵션표·주의사항) 갱신
```

## B. 도구별로 미리 채워둔 양식

대상 경로와 제약이 도구마다 다릅니다. 해당 도구 것을 복사해 쓰세요.

### B-1. vm-param-check (11번)

```markdown
- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/vm-param-check-usability-improvement/vm-param-check
- 참고 문서: README.md → 계획서.md → ../CHANGELOG.md

### 제약 / 유지할 것
- -fix 의 게이트(그룹 동질성 검증, 전원 OFF 확인)는 절대 제거/우회하지 말 것
- -yes 가 "실제 설정 변경 확인"까지 생략하게 만들지 말 것 (스펙 자동매칭 확인만 생략)
- 옵션 미지정 시 해당 체크를 스킵하는 기존 동작 유지
- VM 1대당 Reconfigure 를 한 번만 호출하는 구조 유지
- 새 기대값 옵션을 추가하면 specSettableFlags 에도 등록할 것
  (단, -fix/-out 같은 동작 플래그는 스펙 파일에서 지정 불가여야 함)
- 오프라인 빌드 유지 — 새 외부 의존성 추가 금지

### 완료 기준
- go build / go vet / go test -mod=vendor ./... 전부 통과
- ./vm-param-check -demo 가 정상 동작
- vcsim 으로 시나리오 1개 이상 재현
- ../CHANGELOG.md 갱신, README.md 옵션표 갱신
- 인수인계 문서 11번의 6절 옵션표 / 11절 한계 갱신
```

### B-2. vm-network-migration (14번, **수정 진행 중 폴더**)

```markdown
- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/vm-network-migration
- 참고 문서: README.md → ARCHITECTURE.md → CHANGELOG.md → PR_CHECKLIST.md

### 제약 / 유지할 것
- 롤백 안전장치(state_{user}.json 기반 원복)의 스키마와 동작을 바꾸지 말 것
- "부분 실패 시 실패분만 원복하고 나머지로 계속 진행" 동작을 유지할 것
- 종료 코드 규약(0=성공 / 1=일부실패 / 2=입력오류·미변경 / 3=롤백실패)을 바꾸지 말 것
- run.sh(제어)와 Go 바이너리 6종(실행)의 역할 분리를 유지할 것
- 6개 바이너리의 공통 플래그 이름 일관성 유지
- 생성한 포트그룹을 롤백에서 삭제하지 않는 현재 동작 유지
- 오프라인 빌드 유지 (GOFLAGS=-mod=vendor, GOPROXY=off)

### 완료 기준
- gofmt / go vet / go build / go test ./... 전부 통과
- dry-run → 실행 → 롤백 시나리오 1회 재현
- CHANGELOG.md 에 항목 추가, PR_CHECKLIST.md 전 항목 확인
- README.md 옵션표 갱신
- 인수인계 문서 14번의 5절 옵션표 / 8절 한계 갱신
```

### B-3. VM_setup 하위 개별 도구 (10번)

```markdown
- 대상 저장소: qazx2675/myrepo
- 대상 경로: .claude/VM/VM_setup/<도구폴더명>-source

### 제약 / 유지할 것
- 다른 -source 폴더는 건드리지 말 것 (각 폴더는 독립 모듈)

- 계정 기본값(lscsystems@vsphere.local)을 바꾸지 말 것
- 설정 적용 후 재조회 검증하는 동작(affinity 도구)을 유지할 것
- 오프라인 빌드 유지

### 완료 기준
- 해당 폴더에서 bash setup.sh 성공
- go vet 통과
- ../CHANGELOG.md 갱신, 해당 폴더 README.md 갱신
- 인수인계 문서 10번의 해당 절 갱신
```

- [ ] "제약/유지할 것"에 그 도구의 **안전장치**를 적었는가?

## D. 받은 결과를 확인할 때 체크리스트

- [ ] `bash setup.sh`로 **폐쇄망 방식 빌드**가 되는가?
- [ ] `go vet -mod=vendor ./...` 통과하는가?
- [ ] `go test -mod=vendor ./...` 통과하는가? (테스트가 있는 프로젝트)
- [ ] `git diff --stat`에서 **`vendor/`가 안 바뀌었는가?**
- [ ] `git diff`에서 **요청과 무관한 파일이 안 바뀌었는가?**
- [ ] 안전장치 코드(게이트, 확인 프롬프트)가 그대로인가?
- [ ] 기존 옵션의 기본값이 그대로인가?
- [ ] `CHANGELOG.md`에 항목이 추가되었는가?
- [ ] `README.md`와 인수인계 문서가 갱신되었는가?
- [ ] 문서를 고쳤다면 `python3 build_handbook.py`를 돌렸는가?
