# 02. 공통 실행환경 — 모든 도구에 공통으로 필요한 것

도구마다 하는 일은 달라도 **빌드 방법, 인증 방법, 입력 파일 형식은 거의 같습니다.** 여기서 한 번 익히면 나머지 도구 문서는 옵션표만 보면 됩니다.

---

## 1. 실행할 서버 준비

### 요구 사항

| 항목 | 값 | 확인 명령 |
|---|---|---|
| OS | Linux (Rocky Linux 8 / RHEL 8.10에서 사용) | `cat /etc/redhat-release` |
| Go | **1.26.5 이상** (V2 `setup.sh`가 강제). 망변경 통합 1.25.0+, vm-ip-change 1.25+, 나머지 1.21+ | `go version` |
| 네트워크 | vCenter로 **443/tcp** 접근 가능 | `curl -k -I https://<vCenter IP>` |
| 인터넷 | **불필요** (빌드는 오프라인) | — |

> 실무에서는 vCenter에 접근 가능한 관리용 Rocky Linux 서버 한 대를 정해 두고 거기서 모든 도구를 실행합니다.
> 기존 운영 서버는 `192.168.0.58`, `192.168.0.60` 등이 문서에 등장합니다 — 인수 시 실제 서버 주소를 확인하세요.

### Go 설치 (인터넷 없는 서버)

```bash
# 1) 인터넷 되는 PC에서 go1.26.5.linux-amd64.tar.gz 를 받아 서버로 복사(USB/scp)
# 2) 서버에서:
sudo tar -C /usr/local -xzf go1.26.5.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' | sudo tee /etc/profile.d/go.sh
source /etc/profile.d/go.sh
go version   # go version go1.26.5 linux/amd64
```

## 2. 빌드 방법

### 기본: `setup.sh` 실행

모든 도구 폴더에 `setup.sh`가 있습니다. **이걸 쓰세요.** 직접 `go build`를 치면 `-mod=vendor`를 빼먹기 쉽고, 그러면 폐쇄망에서 실패합니다.

| 도구 | 빌드 명령 | 의존성 위치 |
|---|---|---|
| V2 (12종 전체) | `cd /home/V2 && bash setup.sh` (`-l` 목록, `-c` 정리, `bash setup.sh vm_create` 하나만, OS6 는 `bin_os6/` 설치 — [10번 4절](./10_V2.md)) | `V2/govendor/` → 각 도구 `vendor`로 링크 |
| vm_verifier | `bash setup.sh` | `.claude/공통/govendor/govmomi-0.39.0` → `vendor`로 링크 |
| lpage_search | `bash setup.sh` | 없음 (표준 라이브러리만) |
| Network_Change_Integration_Script | `./setup.sh` | `projects/*/` 안에 자체 보관 |
| vm-ip-change | `./setup.sh` | `project/vendor/` |

`setup.sh`는 공통으로 `GOPROXY=off`, `-mod=vendor`로 빌드하므로 **인터넷에서 라이브러리를 받으려 하지 않습니다.**

### 폐쇄망으로 옮기기

```bash
# 1) 인터넷 되는 곳에서 — 필요한 폴더를 통째로 압축
cd myrepo
tar czf 도구.tar.gz ".claude/VM/<도구 폴더>"          # vm_verifier 는 .claude/공통/govendor 도 함께

# 2) USB / scp / 사내 파일서버로 복사
scp 도구.tar.gz <계정>@<폐쇄망서버>:/tmp/

# 3) 폐쇄망 서버에서 풀고 빌드
cd /tmp && tar xzf 도구.tar.gz
cd ".claude/VM/<도구 폴더>" && bash setup.sh
```

> ⚠️ **폴더 일부만 복사하면 빌드가 실패합니다.** `vendor/`·`govendor/`는 파일이 수천 개라 실수로 빼기 쉽습니다.
> ⚠️ **V2는 폴더를 통째로 둡니다** (예: `/home/V2`). 각 스크립트가 폴더 안의 상대경로(`../../govendor`, `../SPEC_DIR`, `../secret_lib.sh`)로 서로를 찾습니다. 비밀번호 암호 파일을 쓰려면 `V2/secret/`(키 포함)도 함께 옮깁니다.

### 이미 배포된 폴더 갱신

| 도구 | 방법 | 보존되는 것 |
|---|---|---|
| Network_Change_Integration_Script | `bash update.sh <새 버전 폴더>` → `./setup.sh` | `integration.conf`, `conf/*.conf`, `vcenter.txt`, `<계정>.txt`, `vswitch_<계정>.txt`, `bin/`, `logs/ work/ results/ incidents/` |
| V2 vm-param-check (폐쇄망) | 인터넷 되는 곳에서 `bash make_update_package.sh` → 폐쇄망에서 패키지를 풀고 `bash update.sh -n <사용중 디렉터리>`(미리보기) → `bash update.sh <사용중 디렉터리>` | `01.*`, `vcenter.txt`, `SPEC_DIR/`, `*.csv`, `*.log`. 바뀌는 파일은 `<디렉터리>.update_backup.<시각>/`에 백업 |

## 3. 인증 정보

### 원칙: 비밀번호는 환경변수로만

```bash
read -rsp 'vCenter 비밀번호: ' VC_PASSWORD; export VC_PASSWORD; echo
```

`read -rsp`는 입력을 화면에 표시하지 않습니다. **명령행에 비밀번호를 직접 쓰면 셸 히스토리와 `ps` 출력에 그대로 남습니다.**

### 도구별 환경변수 (틀리면 "인증 정보 로드 실패")

| 도구 | 계정 | 비밀번호 |
|---|---|---|
| vm-param-check (11번) | `VC_USER` 또는 `VCENTER_USER` | `VC_PASS` 또는 `VCENTER_PASS` |
| vm_verifier (12번) | `VC_USER` 또는 `VCENTER_USER` | `VC_PASS` 또는 `VCENTER_PASS` |
| V2 `vm_setup.sh` (10번) | `-id` (기본 `lscsystems@vsphere.local`) | V2 암호 파일(`passwd_update.sh`) → 직접 입력. **셸의 `VC_PASSWORD`는 지우고 시작** |
| V2 `vm_setting_check_insert.sh` (11번) | `-id` (기본 `lscsystems@vsphere.local`) | V2 암호 파일 → 직접 입력 (바이너리에는 `VC_USER`/`VC_PASS`로 넘김) |
| V2 `*-source` 개별 도구 (10번) | `-id` (기본 `lscsystems@vsphere.local`) | `VC_PASSWORD` |
| power_setting (17번) | `-id` (기본 `lscsystems@vsphere.local`) | `VC_PASSWORD` |
| 망변경 IP·LDAP 단계 (14번) | 노드 SSH 계정 (gossh) | `GOSSH_PW` |
| 망변경 포트그룹 단계 (14번) | `integration.conf`의 `vc_id` | `VC_PASSWORD` |
| vm-ip-change (15번) | `VC_USER` + 게스트 `GUEST_USER` | `VC_PASSWORD` + 게스트 `GUEST_PASSWORD` |
| lpage_search (13번) | 없음 | 없음 |

> **헷갈리기 쉬운 지점**: `VC_PASS`(점검 계열)와 `VC_PASSWORD`(설정변경 계열)는 다른 변수입니다. 세션 시작 시 둘 다 넣어 두세요. V2 `vm_setup.sh`·`vm_setting_check_insert.sh`는 이 변수를 쓰지 않고 암호 파일을 씁니다(`cd /home/V2 && ./passwd_update.sh`).
>
> ```bash
> export VC_USER='<계정>'
> read -rsp 'vCenter 비밀번호: ' P; echo
> export VC_PASS="$P" VC_PASSWORD="$P"; unset P
> ```

### 필요한 vCenter 권한

| 작업 | 필요 권한 |
|---|---|
| 점검만 | 읽기 전용 (Read-Only) |
| VM 설정 변경 (`-fix`, affinity, lpage 등) | **Virtual machine > Configuration > Reconfigure** |
| VM 생성 | Virtual machine > Inventory > Create new |
| 포트그룹 생성 | **Host > Configuration > Network configuration** |
| 호스트 전원정책 | Host > Configuration > Power |
| 호스트 등록 | **Host > Inventory > Add standalone host / Add host to cluster** |
| 라이선스 할당 | **Global > Licenses** |
| 게스트 명령 실행 (vm-ip-change) | Virtual machine > Guest operations |

> 점검만 할 때는 **읽기 전용 계정**을 쓰면 실수로 `-fix`를 붙여도 권한이 없어 막힙니다.

## 4. 공통 입력 파일

전부 **한 줄에 하나**, `#` 뒤는 주석입니다.

### `vcenter.txt` — vCenter 주소 목록

```
192.168.0.50
192.168.0.51   # 줄 끝 주석도 됨 (vm-param-check 2026-09-23 수정)
```

여러 개를 적으면 도구가 전부 접속해서 대상 VM을 찾습니다. V2 `vm_setup.sh`는 이 목록을 번호로 보여 주고 고르게 합니다.

### BM 목록 — `<user>.txt` / `worklist.txt`

**물리 서버(BM) 이름**을 적습니다. 도구가 여기에 `ev01`~`ev99`를 붙여 대상 VM 이름을 만듭니다. FQDN(`esxi01.domain`)과 짧은 이름(`esxi01`) 모두 됩니다(V2 `vm_create`, `vswitch_setting`).

```
esxi-node-001.domain
esxi-node-002.domain
```

### 대상 VM 목록 — `targets.txt` (`-f`로 지정)

| 도구 | 적는 것 |
|---|---|
| vm-param-check | **VM 이름** |
| vm_verifier | BM 접두어 또는 VM 이름 (자동으로 접두어로 변환) |
| numa_preferht_setting | VM 이름 |

### `SPEC_DIR/` — 스펙 폴더 (V2)

V2 `vm_setup.sh`(VM 생성)와 `vm-param-check`(점검)가 **같이 읽습니다.**

```
SPEC_DIR/                                  # (vswitch_<user>.txt 는 VMsetup/ 으로 옮겨짐)
└── TST-CAE001-SAMP48c-QRST/               # vCenter VM 폴더 이름과 같은 규칙
    ├── TST-CAE001-SAMP48c-QRST_spec.txt   # ht, cpu, mem, disk, shares, cores, numa, affinity (ev별)
    ├── affinity_ev01.txt
    └── affinity_ev02.txt
```

형식은 [10. V2](./10_V2.md) 4절, 매칭 규칙은 [11. vm-param-check](./11_vm-param-check.md) 3절에 있습니다. SPEC_DIR 은 `vm-param-check/SPEC_DIR`가 있으면 그쪽이 먼저 쓰입니다.

### `affinity_evNN.txt` — affinity 파일

`sched.vcpuN.affinity=물리CPU목록` 형식입니다 (키가 그대로 VM ExtraConfig 에 들어감).

```
sched.vcpu0.affinity=0,1
sched.vcpu1.affinity=2,3
sched.vcpu2.affinity=4,5
```

V2 `affinity_setting`은 **ev마다 파일이 필수**입니다(자동 계산 삭제, `AUTO` 불가). 여러 ev가 같은 파일을 써도 됩니다.

### 인프라 정보 파일은 git에 올리지 않습니다

`vcenter.txt`, `targets.txt`, `<user>.txt` 등에는 실제 IP와 서버명이 들어가므로 `.gitignore`에 등록되어 있습니다. 저장소에는 `.example`만 있습니다.

```bash
cp vcenter.txt.example vcenter.txt
```

## 5. 공통 옵션 규칙

Go 표준 `flag` 패키지를 쓰는 도구는 모두 같은 규칙을 따릅니다.

| 규칙 | 예시 |
|---|---|
| 하이픈 1개든 2개든 동일 | `-cpu=16` == `--cpu=16` |
| `=` 없이 띄어 써도 됨 | `-cpu 16` |
| **불리언 플래그는 붙여야 함** | `-fix` (O) / `-fix true` (X — 뒤 값이 인자로 먹힘) |
| 도움말 | `./tool -h` |

bash 스크립트(`vm_setup.sh`, `change.sh`)는 자체 규칙입니다 — 각 도구 문서의 옵션표를 보세요.

### 자주 나오는 옵션

| 플래그 | 뜻 | 비고 |
|---|---|---|
| `-id` | vCenter 로그인 계정 | V2 개별 도구·power_setting 기본값 `lscsystems@vsphere.local`. 다른 계정이면 **반드시 명시** |
| `-vcTargetIP` / `-vc` / `-vcenterList` / `-vcenter` | vCenter 지정 | 도구마다 이름이 다릅니다 |
| `-concurrency` | 동시 처리 개수 | 기본 20~32. 크게 잡으면 vCenter 부하 ↑ |
| `-f` | 대상 목록 파일 | |
| `-out` | 결과 파일 경로 | 미지정 시 타임스탬프로 자동 생성 |
| `-n` / `--dry-run` | **변경 없이 예정만 보기** | 🔴 도구는 항상 이걸 먼저 |

## 7. 결과물이 남는 위치

| 도구 | 결과 |
|---|---|
| vm-param-check | 실행 디렉터리에 상세 CSV + `_summary` 요약 CSV, `-fix` 시 `_recheck_<시각>` CSV |
| vm_verifier | FAIL만 `LOG/vm-verifier-YYYYMMDD.log`에 append, 종료코드 1 |
| V2 `vm_setup.sh` | `VMsetup/run_<user>/` (입력 사본, `last_vcenter`, 생성 후 스펙 체크 `check_<번호>.log`/`.csv`) |
| mac_info | `Provisioning_List_<vCenterIP>.txt` |
| Network_Change_Integration_Script | `results/`(성공·실패 목록), `incidents/`(롤백용), `logs/` |
| vm-ip-change | 화면 결과표, `s` 키 저장 시 `vm-ip-change-snapshot-<시각>.txt`, 종료코드 0/1/130 |

CSV는 UTF-8입니다. 엑셀에서는 "데이터 > 텍스트/CSV 가져오기"로 **UTF-8**을 지정해 여세요.
