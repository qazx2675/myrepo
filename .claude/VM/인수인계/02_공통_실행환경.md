# 02. 공통 실행환경 — 모든 도구에 공통으로 필요한 것

도구마다 하는 일은 달라도 **빌드 방법, 인증 방법, 입력 파일 형식은 거의 같습니다.** 여기서 한 번만 익히면 나머지 도구 문서는 옵션표만 보면 됩니다.

---

## 1. 실행할 서버 준비

### 요구 사항

| 항목 | 값 | 확인 명령 |
|---|---|---|
| OS | Linux (Rocky Linux 8 / RHEL 8.10에서 검증) | `cat /etc/redhat-release` |
| Go | **1.21 이상** (실제 검증은 1.26.5) | `go version` |
| 네트워크 | vCenter로 **443/tcp** 접근 가능 | `curl -k -I https://<vCenter IP>` |
| 인터넷 | **불필요** (빌드는 오프라인으로 됨) | — |

> 실무에서는 vCenter에 접근 가능한 관리용 Rocky Linux 서버 한 대를 정해 두고 거기서 모든 도구를 실행합니다.
> 기존 운영 서버는 `192.168.0.58`, `192.168.0.60` 등이 문서에 등장합니다 — 인수 시 실제 서버 주소를 확인하세요.

### Go 설치 (인터넷 없는 서버)

Go가 없으면 **tar.gz 파일 하나만 있으면 됩니다.**

```bash
# 1) 인터넷 되는 PC에서 go1.26.5.linux-amd64.tar.gz 를 받아 서버로 복사(USB/scp)
# 2) 서버에서:
sudo tar -C /usr/local -xzf go1.26.5.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' | sudo tee /etc/profile.d/go.sh
source /etc/profile.d/go.sh
go version   # go version go1.26.5 linux/amd64
```

## 2. 빌드 방법 (모든 Go 도구 공통)

### 기본: `setup.sh` 실행

거의 모든 폴더에 `setup.sh`가 있습니다. **이걸 쓰세요.**

```bash
cd <도구 폴더>
bash setup.sh
```

`setup.sh`가 하는 일은 딱 한 줄입니다:

```bash
go build -mod=vendor -o <바이너리이름> .
```

`-mod=vendor`가 핵심입니다 — **인터넷에서 라이브러리를 새로 받지 않고 `vendor/` 폴더 안의 것만 씁니다.** 직접 `go build`를 치면 이 플래그를 빼먹기 쉽고, 그러면 폐쇄망에서 실패합니다.

### 예외인 폴더 3곳

| 폴더 | 이유 | 방법 |
|---|---|---|
| `lpage_search` | 외부 의존성이 아예 없음 (`vendor/`도 없음) | `bash setup.sh` (내부는 `go build main.go`) |
| `vm-setting-go-lang` | 한 폴더에 `main()`이 4개 있음. `go build .`은 **실패함** | `bash setup.sh` (파일명을 지정해 4개를 각각 빌드) |
| `gemini_vcsim-pipeline-test` | 바이너리가 아니라 테스트 코드 | `go test -mod=vendor -v ./...` |

### 폐쇄망으로 옮기기 (3단계)

```bash
# 1) 인터넷 되는 곳에서 — 폴더를 통째로 압축 (vendor/ 포함이 핵심)
cd myrepo
tar czf 도구.tar.gz ".claude/VM/<도구 폴더>"

# 2) USB / scp / 사내 파일서버로 폐쇄망 서버에 복사
scp 도구.tar.gz user@폐쇄망서버:/tmp/

# 3) 폐쇄망 서버에서 풀고 빌드
cd /tmp && tar xzf 도구.tar.gz
cd ".claude/VM/<도구 폴더>"
bash setup.sh
```

> ⚠️ **폴더 일부만 복사하면 빌드가 실패합니다.** `vendor/` 폴더가 수천 개 파일이라 실수로 빼기 쉽습니다. 반드시 폴더 통째로.

### 빌드한 바이너리를 어디서나 쓰기 (선택)

```bash
sudo cp vm-param-check /usr/local/bin/
# 이후 어느 경로에서든 vm-param-check 로 실행
```

단, **입력 파일(`vcenter.txt` 등)은 현재 디렉터리에서 읽습니다.** 그리고 `run.sh` 계열 스크립트는 자기 위치 기준으로 `bin/`을 찾으므로, 전체 워크플로우를 돌릴 때는 프로젝트 폴더 안에서 실행하세요.

## 3. 인증 정보 (아주 중요)

### 원칙: 비밀번호는 환경변수로만

```bash
read -rsp 'vCenter 비밀번호: ' VC_PASSWORD; export VC_PASSWORD; echo
```

`read -rsp`는 입력을 화면에 표시하지 않습니다. **명령행에 비밀번호를 직접 쓰면 셸 히스토리와 `ps` 출력에 그대로 남습니다.**

### 도구별 환경변수 (틀리면 "인증 정보 로드 실패"가 납니다)

| 도구 | 계정 ID | 비밀번호 |
|---|---|---|
| `vm-param-check` (11번) | `VC_USER` 또는 `VCENTER_USER` | `VC_PASS` 또는 `VCENTER_PASS` |
| `vm_verifier` (12번) | `VC_USER` 또는 `VCENTER_USER` | `VC_PASS` 또는 `VCENTER_PASS` |
| `vm-param-setting-check` (16번) | `VC_USER` 또는 `VCENTER_USER` | `VC_PASS` 또는 `VCENTER_PASS` |
| `vc-test-env` (18번) | `VC_USER` | `VC_PASS` |
| `vm-network-migration` (14번) | **`-id` 플래그** (기본 `lscsystems@vsphere.local`) | `VC_PASSWORD` (대체: `VC_PASS`, `VCENTER_PASS`) |
| `VM_setup/*` (10번) | **`-id` 플래그** (기본 `lscsystems@vsphere.local`) | `VC_PASSWORD` |
| `vm-setting-go-lang/*` (17번) | **`-id` 플래그** | `VC_PASSWORD` (+ `vm_connect`는 `ESXI_PASSWORD`도 필요) |
| `lpage_search` (13번) | 없음 (접속 안 함) | 없음 |

> **헷갈리기 쉬운 지점**: `VC_PASS`(체크 계열)와 `VC_PASSWORD`(설정변경 계열)는 다른 변수입니다.
> 안전하게 하려면 세션 시작 시 **둘 다** 설정해 두세요.
>
> ```bash
> read -rsp 'vCenter 비밀번호: ' P; echo
> export VC_PASS="$P" VC_PASSWORD="$P" VC_USER='administrator@vsphere.local'
> unset P
> ```

### 필요한 vCenter 권한

| 작업 | 필요 권한 |
|---|---|
| 점검(체크)만 | 읽기 전용 (Read-Only) |
| VM 설정 변경 (`-fix`, affinity, lpage 등) | **Virtual machine > Configuration > Reconfigure** |
| 포트그룹 생성 | **Host > Configuration > Network configuration** |
| 호스트 등록 | **Host > Inventory > Add standalone host / Add host to cluster** |
| 라이선스 할당 | **Global > Licenses** |

> 처음에는 **읽기 전용 계정**으로 시작하는 것을 강력히 권합니다. 실수로 `-fix`를 눌러도 권한이 없어 막힙니다.

## 4. 공통 입력 파일

도구들이 반복해서 쓰는 텍스트 파일 형식입니다. 전부 **한 줄에 하나**, `#`으로 시작하는 줄은 주석입니다.

### `vcenter.txt` — vCenter 주소 목록

```
192.168.0.50
192.168.0.51
```

여러 개를 적으면 도구가 **전부 병렬로 접속**해서 대상 VM을 찾습니다. 어느 vCenter에 있든 알아서 찾아갑니다.

### `worklist.txt` — 물리 호스트(BM) 목록

`VM_setup`, `vm-setting-go-lang` 계열이 씁니다. **물리 서버 이름**을 적습니다. 도구가 여기에 `ev01`/`ev02`/`ev03`을 붙여 대상 VM 이름을 만듭니다.

```
svr01
svr02
svr03
```

→ `-vm_cnt 2`면 `svr01ev01`, `svr01ev02`, `svr02ev01`, ... 이 대상이 됩니다.

### `targets.txt` (`-f`로 지정) — 대상 VM 목록

`vm-param-check`, `vm_verifier`, `numa_preferht_setting`이 씁니다. 도구에 따라 **VM 이름**을 직접 적거나 **BM 접두어**를 적습니다.

```
svr01ev01
svr01ev02
# 이 줄은 주석
```

> `vm_verifier`는 접두어(`svr01`)든 VM 이름(`svr01ev01`)이든 다 받습니다 — 자동으로 접두어로 변환합니다.
> `vm-param-check`는 **VM 이름**을 적습니다.

### `hostgroup.txt` — 호스트↔포트그룹 매핑

`vm_create` 계열이 씁니다.

```
svr01 PORTGROUP_A
svr02 PORTGROUP_B
```

> ⚠️ **알려진 버그**: 구분자를 공백/콤마로 자르기 때문에 **포트그룹 이름에 공백이 있으면 깨집니다** (예: vSphere 기본값 `VM Network`). 공백 없는 포트그룹 이름을 쓰세요.

### `affinity_evNN.txt` — affinity 기대값 파일

`key=value` 형식입니다.

```
0=0,1
1=2,3
2=4,5
```

또는 전체를 `AUTO`로 두면 `-ht` 옵션(ON/OFF)에 따라 도구가 자동 계산합니다.

### 인프라 정보 파일은 git에 올리지 않습니다

`vcenter.txt`, `targets.txt` 같은 파일에는 실제 IP와 서버명이 들어갑니다. 각 프로젝트의 `.gitignore`에 등록되어 있습니다. **저장소에는 `.example` 파일만 있으니 확장자를 떼고 실제 값으로 채워 쓰세요.**

```bash
cp vcenter.txt.example vcenter.txt
```

## 5. 공통 옵션 규칙

Go의 표준 `flag` 패키지를 쓰기 때문에 모든 도구가 같은 규칙을 따릅니다.

| 규칙 | 예시 |
|---|---|
| 하이픈 1개든 2개든 동일 | `-cpu=16` == `--cpu=16` |
| `=` 없이 띄어 써도 됨 | `-cpu 16` |
| **불리언 플래그는 붙여야 함** | `-fix` (O) / `-fix true` (X — 뒤 값이 인자로 먹힘) |
| 옵션은 위치 인자보다 앞에 | `./tool -a=1 -b=2` |
| 도움말 | `./tool -h` 또는 `./tool --help` |

### 자주 나오는 공통 옵션

| 플래그 | 뜻 | 비고 |
|---|---|---|
| `-id` | vCenter 로그인 계정 | 기본값이 대부분 `lscsystems@vsphere.local`. 다른 계정이면 **반드시 명시** |
| `-vcTargetIP` / `-vc` / `-vcenterList` | vCenter 지정 | 도구마다 이름이 다릅니다. 표를 확인하세요 |
| `-concurrency` | 동시 처리 개수 | 기본 20~32. 크게 잡으면 vCenter 부하 ↑ |
| `-f` | 대상 목록 파일 | |
| `-out` | 결과 파일 경로 | 미지정 시 타임스탬프로 자동 생성 |
| `-dry-run` / `-demo` / `-scale` | **아무것도 안 바꾸고 예정 내용만 보기** | 🔴 도구를 처음 쓸 때는 항상 이걸 먼저 |

## 6. 실행 전 체크리스트 (🔴 설정변경 도구용)

설정을 바꾸는 도구를 돌리기 전에 매번 확인하세요.

- [ ] **dry-run으로 먼저 돌려봤는가?** (`--dry-run`, `-demo`, `-fix` 없이 체크만)
- [ ] 대상 목록 파일에 **의도한 VM만** 들어 있는가? (`wc -l targets.txt`로 개수 확인)
- [ ] `-id`가 맞는 계정인가? (기본값이 `lscsystems@vsphere.local`이라 무심코 쓰면 엉뚱한 계정)
- [ ] vCenter 주소가 맞는가? (운영 vCenter와 테스트 vcsim을 헷갈리지 않기)
- [ ] CPU 토폴로지를 바꾸는 작업이면 **대상 VM이 전부 꺼져 있는가?**
- [ ] 작업 시간대가 맞는가? (VM 재구성은 서비스 영향이 있을 수 있음)
- [ ] 실행 후 **랜덤 표본 몇 대를 vSphere Client에서 눈으로 확인**할 계획이 있는가?

## 7. 결과물이 남는 위치

| 도구 | 결과 |
|---|---|
| `vm-param-check` | 실행 디렉터리에 상세 CSV + `_summary` 요약 CSV |
| `vm_verifier` | FAIL만 `LOG/vm-verifier-YYYYMMDD.log`에 append |
| `vm-network-migration` | `state_{user}.json`(롤백용 원본 — **지우면 원복 불가**), `failed_{user}.txt` |
| `esxi-log-check` | `-out`으로 지정한 파일(text/html/json) 또는 웹서버 |
| `mac_info` | `Provisioning_List_<vCenterIP>.txt` |

CSV는 엑셀에서 열면 한글이 깨질 수 있습니다. 엑셀에서 "데이터 > 텍스트/CSV 가져오기"로 **UTF-8**을 지정해 여세요.
