## 독립 브랜치 `vm-param-check-standalone` 다시 맞추는 방법

master의 이 폴더를 고칠 때마다 아래를 반복해야 한다. **Windows에서 `git archive`를 그대로 쓰면 안 된다**(아래 함정 참고). 록키(Linux)에서 조립한다.

```bash
P=.claude/VM/vm-param-check-usability-improvement
V=.claude/공통/govendor/govmomi-0.39.0
HOST=root@192.168.0.58; WORK=/tmp/standalone-src

# (myrepo에서, master에 커밋을 마친 뒤)
ssh $HOST "rm -rf $WORK && mkdir -p $WORK/vm-param-check/vendor"
git -c core.autocrlf=false archive HEAD "$P" | ssh $HOST "tar -x -C $WORK --strip-components=3"
git -c core.autocrlf=false archive HEAD "$V" | ssh $HOST "tar -x -C $WORK/vm-param-check/vendor --strip-components=4"
# 링크를 걸지 않는 옛 setup.sh (vendor 공유화 직전 커밋)
git show "f8a2e7e^:$P/vm-param-check/setup.sh" | ssh $HOST "cat > $WORK/vm-param-check/setup.sh && chmod +x $WORK/vm-param-check/setup.sh"
# .gitignore 의 vendor 줄 제거
ssh $HOST "cd $WORK/vm-param-check && sed -i '/^vendor\r\?\$/d' .gitignore"
# orphan 커밋
ssh $HOST "cd $WORK && git init -q -b vm-param-check-standalone && git add -A && git commit -q -m '...'"
# myrepo로 가져와서 푸시
git fetch root@192.168.0.58:$WORK vm-param-check-standalone:refs/heads/vm-param-check-standalone
git push --force-with-lease origin vm-param-check-standalone   # 히스토리를 새로 만들면 force 필요
```

조립 뒤 반드시 숫자로 확인: `vendor/` 파일 162개가 **커밋**됐는지(`git ls-files vm-param-check/vendor | wc -l`), `.sh`/`.go`/`.gitignore`에 CR이 없는지.

### 실제로 밟은 함정

1. **`git archive`가 `core.autocrlf=true` 때문에 CRLF로 내보낸다.** 리눅스에서 `bash`로 실행하는 스크립트가 CRLF면 깨진다. `git -c core.autocrlf=false archive`로 막는다.
2. **CRLF 때문에 `sed '/^vendor$/d'`가 매칭 실패**했고, 검증 명령(`grep -qx vendor`)도 같은 이유로 "통과"처럼 보였다. 결과는 vendor가 `.gitignore`에 남아 **vendor가 0개 커밋**됨. → 통과처럼 보이는 검증 대신 파일 개수를 직접 센다.
3. master의 도구 폴더 `.sh` 파일은 대부분 모드 `100644`(실행권한 없음)로 기록돼 있다. `bash x.sh`로 실행하는 한 문제는 없다.

## 후속: 폐쇄망용 `update.sh` (같은 날 추가)

`update_deploy.sh`를 실제 회사 환경에서 돌려보니 안 됐다 — 폐쇄망이라 GitHub에 접속할 수 없었다(내가 서버가 GitHub에 접속 가능한지 확인하지 않고 설계한 잘못). 그래서 **인터넷 없이 실행파일만 교체**하는 방식을 추가했다. 이번 변경은 Go 코드(게이트)뿐이라 실행파일만 바꾸면 충분하다.

| 파일 | 역할 |
|---|---|
| `update.sh` | 폐쇄망 서버에서 `bash update.sh "사용중인디렉토리"`. payload의 바뀐 파일만 반영, 나머지는 안 건드림 |
| `make_update_package.sh` | 빌드 서버(Go)에서 정적 빌드 후 `dist/vm-param-check-update-YYYYMMDD.tar.gz` 생성 |

패키지 만드는 법(록키에서 실제로 쓴 절차): master의 프로젝트 폴더와 `.claude/공통/govendor/govmomi-0.39.0`을 같은 상대경로로 풀고(`git -c core.autocrlf=false archive`), 프로젝트 폴더에서 `TZ=Asia/Seoul SOURCE_COMMIT=<커밋> bash make_update_package.sh`. `setup.sh`가 상대경로로 vendor 링크를 거므로 govendor를 같이 풀어야 한다.

주의: 록키 시계는 UTC라 `TZ=Asia/Seoul`을 주지 않으면 패키지 이름·VERSION.txt의 날짜가 하루 어긋난다.

검증 중 FAIL이 한 건 나왔는데 **시험 순서 문제**였다(시험이 사용 중인 디렉토리 안에서 `-demo`를 직접 실행한 뒤 "CSV가 안 생겼는지" 검사). 검사를 update 직후로 옮겨 통과를 확인했다 — `update.sh`가 만든 게 아니다.

## 발견 사항 (이번 요청 범위 밖, 손대지 않음)

- 같은 이름의 `gates.go`가 `vm-param-setting-check/fail-based-param-fix/`, `integrated-vm-param-check-test-tool/vm-param-check/`, `VM_setup/vm-param-fix/`에 더 있다. 이 도구(`vm-param-check-usability-improvement`)의 `update_deploy.sh`가 배포하는 것만 수정했다.
