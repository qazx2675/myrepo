saccae 실패 테스트 사용법 (192.168.0.58, root)
=====================================================================
각 케이스를 실행하기 전에 가상 vCenter 를 초기화하면 결과가 섞이지 않는다:
  /home/saccae/testenv/vcsim.sh restart

공통 규칙 (모든 케이스에서 확인할 것)
  - 실패하면 그 단계에서 멈추고 "[오류] 실패: <도구> (종료코드 1)" 이 나오며 [완료] 는 나오지 않는다. 스크립트 종료코드도 1.
  - 멈추기 전까지 만든 포트그룹/VM 은 남는다. 원인을 고친 뒤 같은 명령을 다시 실행하면 이미 있는 것은 건너뛰고 이어서 진행한다.
  - 종료코드 확인: 실행 직후 echo $?

cd /home/saccae/VMsetup


F1. vCenter 에 없는 BM 이 섞임 — 포트그룹 단계(vswitch_setting)에서 중단
---------------------------------------------------------------------
./vm_setup.sh -u fail_nohost              # VM 표 y → CAE Enter → vCenter 1 → 실행 y
  기대: [에러] 호스트 'hostname0100' 를 vCenter 전체 인벤토리에서 찾을 수 없습니다.
        [오류] 실패: vswitch_setting (종료코드 1)  — VM 은 하나도 만들지 않음 (hostname0000 포트그룹만 생김)
  복구: fail_nohost.txt 와 vswitch_fail_nohost.txt(같은 VMsetup 폴더) 에서 hostname0100 줄을 지우고 다시 실행 → [완료]


F2. affinity 줄이 없는 스펙 (예전 vm-param-check 스펙) — 실행 전에 묻는다
---------------------------------------------------------------------
./vm_setup.sh -u fail_noaff -n
  기대: [경고] 스펙 SAC-CAE105-NOAFF-TEST 에 affinity 파일이 없는 ev 가 있습니다 ...
        지금 ev 별 affinity 를 골라 이 스펙에 추가할까요? (y/n)
          n → [경고] ... 쓸 수 없습니다 — affinity-ev01 이 스펙에 없습니다 → 스펙 번호 선택으로 넘어감 (Ctrl+C 로 끝냄)
          y → ev01: 2(기존 파일)/3(vim) 선택, ev02: Enter(ev01 과 같은 파일) → 스펙 파일에 affinity-ev01/02 가 추가되고 계속 진행
  원상복구(y 로 추가했을 때): bash /root/myrepo/".claude/VM-10대-확장-및-SPEC_DIR-공유/검증/saccae/install.sh" (스펙을 다시 복사)


F3. 값이 잘못된 스펙 (cpu 6 이 cores 4 로 안 나누어짐) — 자동 할당하지 않음
---------------------------------------------------------------------
./vm_setup.sh -u fail_badspec -n
  기대: [경고] hostname0002: 자동 매칭된 스펙 SAC-CAE106-BADSPEC-TEST 을(를) 쓸 수 없습니다 — ev01: cpu(6)가 cores(4)로 나누어떨어지지 않습니다
        → 스펙 번호 선택 화면 (다른 스펙을 고르거나 Ctrl+C)


F4. 비밀번호가 틀림 — 로그인 실패로 첫 단계에서 중단
---------------------------------------------------------------------
VC_PASSWORD=wrong ./vm_setup.sh -u lsh
  기대: vCenter 접속 실패: ServerFaultCode: Login failure
        [오류] 실패: vswitch_setting (종료코드 1)
  (암호 파일 쪽을 틀리게 하려면: /home/saccae/passwd_update.sh 로 다른 비밀번호 등록 → 실행 → 다시 Saccae1! 로 등록)


F5. vCenter 에 접속할 수 없음
---------------------------------------------------------------------
./vm_setup.sh -u lsh -v 192.168.0.58:8443      # VM 표 y → CAE Enter → 실행 y
  기대: vCenter 접속 실패: ... connect: connection refused
        [오류] 실패: vswitch_setting (종료코드 1)
  (또는 /home/saccae/testenv/vcsim.sh stop 후 ./vm_setup.sh -u lsh)


F6. 없는 가상 스위치 — 포트그룹 생성 실패
---------------------------------------------------------------------
./vm_setup.sh -u lsh -w vSwitch9
  기대: -> [hostname00xx] 실패: 포트그룹(...) 생성 에러: ServerFaultCode: NotFound  (40건)
        [에러] 실패 40건 ... / [오류] 실패: vswitch_setting (종료코드 1)


F7. 데이터스토어가 없는 BM — VM 생성 단계(vm_create)에서 중단
---------------------------------------------------------------------
./vm_setup.sh -u fail_nods                 # BM hostname9000 (가상 vCenter 의 실패 전용 호스트)
  기대: 포트그룹은 생성 성공 → [오류] [hostname9000] 호스트에 데이터스토어가 없습니다 — 건너뜁니다
        [오류] 실패: vm_create (종료코드 1) — affinity/lpage 는 실행하지 않음


F8. affinity 파일 내용 오류 — VM 은 만들어지고 affinity 단계에서 중단 (중간 실패)
---------------------------------------------------------------------
./vm_setup.sh -u fail_badaff
  기대: vm_create 성공(hostname0004ev01, ev02 생성) → affinity_setting:
        ev01 설정 파일 오류 (.../affinity_bad.txt): AUTO(1:1 자동 계산)는 삭제된 기능입니다 ...
        [오류] 실패: affinity_setting (종료코드 1) — lpage 와 스펙 체크는 실행하지 않음
  복구: printf 'sched.vcpu0.affinity=0\nsched.vcpu1.affinity=1\n' > /home/saccae/SPEC_DIR/SAC-CAE107-BADAFF-TEST/affinity_bad.txt
        ./vm_setup.sh -u fail_badaff   → "이미 모두 생성" 으로 VM 은 건너뛰고 affinity/lpage/체크까지 [완료]
  원상복구: install.sh 다시 실행


F9. 스펙과 다른 VM — 끝의 스펙 체크에서 [차이]
---------------------------------------------------------------------
./vm_setup.sh -u lsh                                       # 먼저 정상 생성
/home/saccae/testenv/fail_inject.sh mem hostname0000ev02 4096
./vm_setup.sh -u lsh                                       # 재실행 (VM 표 y → CAE Enter → vCenter Enter(=이전) → 실행 y)
  기대: 새로 생성할 VM 없음 → 스펙 체크
        [차이] 스펙 1 SAC-CAE101-VM06-HPC — VM 240대 중 ... FAIL ...
             1   [FAIL]        config.hardware.memoryMB (GB 환산)
        [완료] (체크 차이는 중단 사유가 아님) + -fix 명령 안내


F10. 전원이 켜진 VM 이 있을 때 -fix — 전원 OFF 게이트에서 중단
---------------------------------------------------------------------
/home/saccae/testenv/vcsim.sh restart && ./vm_setup.sh -u lsh
/home/saccae/testenv/fail_inject.sh poweron hostname0000ev01
cd /home/saccae/vm-param-check-usability-improvement/vm-param-check
export VC_USER=lscsystems@vsphere.local VC_PASS="$(. /home/saccae/secret_lib.sh; secret_get vcenter lscsystems@vsphere.local)"
./vm-param-check -vcenterList /home/saccae/vcenter_vcsim.txt -specRoot /home/saccae/SPEC_DIR -yes -onlyFail -out /tmp/check.csv -fix
  기대: [전원 OFF 검증 실패] 아래 VM이 켜져 있어 작업할 수 없습니다: hostname0000ev01   (종료코드 1, 아무것도 바꾸지 않음)
  (F9 처럼 같은 스펙의 VM 값이 서로 다르면 그 전에 [동질성 검증 실패] 로 멈춘다)
  복구: govc vm.power -off hostname0000ev01 (사용법.txt 4번의 govc 설정 후) → 다시 -fix → [OK] 게이트 통과 → 교정
