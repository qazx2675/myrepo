## 1. 현재 상태 분석 (코드 확인 결과)

| 도구 | ev 개수 한계 | 입력 방식 | 병렬 | 비고 |
|---|---|---|---|---|
| `vm_create` | `-vmCount` 1~3 하드코딩, ev01~ev03 플래그 개별 선언 | 플래그 + `worklist.txt` + `hostgroup.txt`(BM→포트그룹 1개) | ✅ 워커풀 | **ev02Cpu가 0이면 vmCount=1이어도 종료**, ev03는 기본값(1/1/20/1000)이 있음 |
| `affinity_setting` | `-vm_cnt` 1~3, `affinityFile01~03` | 플래그 | ✅ | |
| `lpage_setting` | `ev01~03 Cores/Sockets/Numa` | 플래그 | ✅ | 이미 "지정한 그룹만 처리" 구조 |
| `tag_setting` | `-vmCount` + 콤마 목록 | 플래그 | 확인 필요 | 목록 방식이라 개수 제한이 약함 |
| `vswitch_setting` | 해당 없음 | `worklist.txt` (`BM PG VLAN`) | ❌ **호스트 순차 처리** | |
| `vm-param-check` | ev01~ev03 (`cores-ev02`, `shares-ev03` 등) | 플래그 + SPEC_DIR(`-specRoot`, 폴더명 자동매칭) | ✅ | |

- **SPEC_DIR 구조**: `SPEC_DIR/<CAE폴더명>/<CAE폴더명>_spec.txt`. vm-param-check는 **VM이 들어 있는 vCenter 폴더명**으로 스펙을 찾는다(`CAE001`/`CAE003`처럼 차수만 다르면 같은 스펙). 폴더가 규칙 밖이면 **포트그룹 이름 `<폴더명>-cae-a-b-c-d`에서 폴더명을 역추출**하는 로직도 이미 있다(`config/portgroup.go`).
- **`spec_list_${user}`**: 저장소 안에서는 찾지 못했다 → 이번 범위에서 제외(D1).
- **Shares `normal`** (요청 5): 이미 지원됨.
  - `vm_create`: `nomal`/`normal`(대소문자 무시) → `SharesLevelNormal` (2026-08-25 vcsim 검증 기록 있음)
  - `vm-param-check`: `normal` 및 `4000,normal` 혼합 허용
  - → 코드 변경 없음. SPEC_DIR 경유 경로(스펙 파일의 `shares-evNN=normal` → vm_create)로 넘어갈 때 값이 그대로 전달되는지만 테스트에 포함.
- **vswitch 다중 포트그룹** (요청 9): 코드상 이미 동작한다. 호스트마다 `worklist`의 **모든 줄**을 돌면서 `AddPortGroup`을 호출하므로, 같은 BM에 줄이 2개면 2개 생성된다. 단 호스트를 순차 처리해서(병렬 아님) 요청 7과 어긋난다 → 랩에서 실측 확인 후 병렬화만 추가.
- **주의**: `vm-network-migration`의 `vswitch_{user}.txt`는 "한 호스트에 한 줄만" 규칙이다(여러 줄이면 백업 단계에서 멈춤). SPEC_DIR의 `vswitch_${user}.txt`는 다중 포트그룹을 허용하므로 **두 도구가 같은 파일을 같이 쓰면 안 된다** → README에 명시.

## 2. 설계

### 2.1 ev01~ev10 일반화 (요청 1, 4 / 결정 D4·D5)
- 플래그를 반복문으로 등록: `for n := 1..10 { flag.Int(fmt.Sprintf("ev%02dCpu", n), ...) }`
  - 기존 `-ev01Cpu`~`-ev03Share` **이름은 그대로** 유지, ev04~ev10 추가
- 범위 검증 `1~3` → `1~10`
- **규칙**: ev01 필수. ev02~ev10은 값이 있는 것만 실행하고, **값이 없는 ev는 실행하지 않는다**(D5)
  - `vm_create`의 ev03 기본값(1 CPU/1GB/20GB/1000)은 **제거** → ev03 값을 안 주면 ev03는 만들지 않음
  - 현재 `vm_create`가 ev02 값이 없으면 vmCount=1이어도 종료하던 제한도 같이 풀린다
- **연속만 허용**(D4): ev01..evN 사이에 빈 번호가 있으면(예: ev02 없음 + ev03 있음) 실행 전에 에러로 종료
- 적용 도구(D8): `vm_create`, `affinity_setting`(`affinityFile01~10`, `-vm_cnt` 1~10), `lpage_setting`(`evNNCores/Sockets/Numa`), `tag_setting`(한계 검사), `vm-param-check`(`cores/numa/cpu/mem/disk/shares/affinity-evNN`, 체커·fixer·CSV의 ev 그룹 목록)

### 2.2 SPEC_DIR 공유 (요청 2, 3 / 결정 D2·D3)
- **배포 구조**(D2) — 세 폴더가 같은 부모 아래 나란히 있다
  ```
  /home/SPEC_DIR/                                   # 공유 (git에 없음, 사용자 데이터)
  ├── vswitch_${user}.txt                           # BM  포트그룹  VLAN (BM당 여러 줄 허용)
  └── <CAE폴더명>/<CAE폴더명>_spec.txt                # cpu/mem/disk/shares/cores/numa/affinity (ev01~ev10)
  /home/VMsetup/                                    # 저장소의 VM_setup
  ├── ${user}.txt                                   # BM 목록 (한 줄에 하나)
  └── vm_setup.sh                                   # 신규 래퍼
  /home/vm-param-check-usability-improvement/
  ```
  - 두 도구 래퍼의 기본값을 **상대경로 `../SPEC_DIR`**로 맞춘다(폴더 이름이 `VMsetup`/`VM_setup` 어느 쪽이어도 동작)
  - vm-param-check의 `vm_setting_check_insert.sh`/`folder_setup.sh`: 도구 폴더 안에 `SPEC_DIR`이 이미 있으면 그걸 쓰고(기존 설치 그대로 동작), 없으면 `../SPEC_DIR`
- **BM별 스펙 결정**(D3)
  1. **자동 할당**: BM의 포트그룹 이름(`<폴더명>-cae-a-b-c-d`)에서 기존 `ExtractFolderFromPortgroup`로 폴더명을 뽑아 SPEC_DIR에서 같은 스펙 폴더를 찾는다
  2. **확인**: `BM → 스펙 경로` 표 출력 후 `맞습니까? (y/n)`
  3. **n → 수동 선택**: SPEC_DIR 스펙 폴더 목록을 번호로 보여주고 선택
  4. **목록에 없음 → vim 수동 입력**: 모든 키가 `키=""` 형태이고 설명이 주석으로 달린 템플릿이 열린다
     ```bash
     # 스펙 수동 입력 — 비워 둔 ev02~ev10 값은 실행하지 않는다 (ev01은 필수, 번호는 연속이어야 함)
     folder=""        # [필수] 새로 만들 스펙 폴더명 (예: TST-CAE001-SAMP48c-QRST)
     ht=""            # on/off
     # --- ev01 (필수) ---
     cpu=""           # vCPU 수
     mem=""           # 메모리 GB
     disk=""          # 디스크 GB
     shares-ev01=""   # ratio 숫자(예: 4000) 또는 normal
     cores=""         # 소켓당 코어 수
     numa=""          # NUMA 노드당 최대 vCPU 수
     # --- ev02 (선택) ---
     cpu-ev02=""
     ...              # ev10 까지 같은 형식
     # affinity는 이 파일에 적지 않는다 — 저장 후 다음 단계(5)에서 ev별로 지정
     ```
     → 스펙 파서가 `키=""`(따옴표) 형식과 빈 값을 "미지정"으로 받도록 소폭 수정
  5. **ev별 affinity 지정 (수동 입력일 때만)**: 4에서 값이 채워진 ev01~evN 개수만큼 차례로 묻는다
     ```
     [ev01] affinity 지정 방법: 1) 자동(ht 기준 1:1)  2) 기존 파일 선택  3) vim 직접 입력
     ```
     - `1` → affinity 키를 적지 않음 (affinity_setting이 `-ht`로 자동계산 — 기존 동작)
     - `2` → SPEC_DIR 안의 `affinity_*.txt` 목록을 번호로 보여주고 선택 → 새 스펙 폴더로 복사
     - `3` → 그 ev의 vCPU 수만큼 줄이 미리 만들어진 템플릿을 vim으로 연다
       ```bash
       # [ev02] affinity 수동 입력 — vCPU 4개 기준. 값은 물리 CPU 번호(HT on이면 "0,1" 형태)
       sched.vcpu0.affinity=""
       sched.vcpu1.affinity=""
       sched.vcpu2.affinity=""
       sched.vcpu3.affinity=""
       ```
       저장하면 따옴표를 떼고 `affinity_ev02.txt`로 저장, 빈 값이 남아 있으면 다시 연다
     - 결과는 스펙 파일에 `affinity-evNN=affinity_evNN.txt`로 기록된다(상대경로 → vm-param-check `-template` 복사 규칙과 호환)
  6. **저장**: `folder`에 적은 이름으로 **새 폴더 `SPEC_DIR/<folder>/`가 만들어지고** 그 안에 `<folder>_spec.txt`와 `affinity_evNN.txt`가 저장된다. 다음부터는 이 폴더가 자동 할당·수동 선택 목록에 나타나고, vm-param-check도 같은 스펙으로 체크한다
     - `folder`가 비어 있거나 CAE 폴더 규칙에 안 맞으면 → 사유를 주석으로 맨 위에 붙여 vim을 다시 연다
     - 이미 같은 스펙(차수만 다른 폴더 포함)이 있으면 → 덮어쓰지 않고 "기존 폴더를 쓸지(y) / 다른 이름(n)"을 묻는다 (기존 `InitFolder` 중복 검사 재사용)
- **스펙 → 플래그 변환**: 파서를 두 벌 만들지 않도록 `vm-param-check`에 `-specExport=<스펙경로>` 모드를 추가해 `KEY=VALUE`를 출력 → `vm_setup.sh`가 받아 각 도구 플래그로 넘긴다
- **Bash+Go 짝 규칙**: `vm_setup.sh` 흐름 — 스펙 결정 → vswitch → NIC(포트그룹) 결정 → vm_create → affinity/lpage/tag

### 2.3 병렬 처리 (요청 7)
- 기존 워커풀 도구는 구조 그대로, 대상 VM 개수만 늘어남
- `vswitch_setting`: 호스트 단위 워커풀(`-concurrency`) 추가. 같은 호스트의 포트그룹 여러 개는 **호스트 안에서는 순차**(같은 HostNetworkSystem에 동시 AddPortGroup 충돌 방지). 출력 문구 유지, 순서만 완료순

### 2.4 포트그룹 → VM 네트워크 어댑터 할당 (요청 10, 11 / 결정 D6·D7)
- **NIC는 VM당 1개(네트워크 어댑터 1)**(D6). 포트그룹이 여러 개인 BM이면 VM(evNN)마다 그중 하나를 고른다
- 할당표 `nic_map_${user}.txt` (`VM이름 포트그룹`)
  1. **자동 할당**: BM에 포트그룹 1개 → 그 BM의 모든 VM. 여러 개 → 2.2에서 정해진 스펙 폴더명과 이름이 맞는 포트그룹
  2. **확인**: 표 출력 후 `(y/n)`
  3. **n → 수동 선택**: VM별로 해당 BM의 포트그룹 목록을 번호로 선택
  4. **목록에 없음 → vim**: 아래 템플릿(주석 설명 포함). 포트그룹 신규 생성(VLAN 입력)은 **이번 범위에서 제외**(D7)
     ```bash
     # 네트워크 어댑터 수동 지정 (네트워크 어댑터 1에 적용)
     # - hostname  : VM 이름 (예: bm001ev03). vCenter 표시 이름과 정확히 같아야 함
     # - portgroup : 연결할 표준 vSwitch 포트그룹 이름 (해당 VM이 올라간 BM에 이미 있어야 함)
     # - 여러 VM을 지정하려면 아래 두 줄을 복사해서 이어 적는다. 값을 비워 둔 블록은 무시된다
     hostname=""
     portgroup=""
     ```
- **적용**
  - 생성 단계: `vm_create -mapFile`이 **VM 이름 키**도 받도록 확장(VM 이름 매칭 → 없으면 기존 BM 이름 매칭). 기존 `hostgroup.txt`(BM 키)는 그대로 동작
  - 이미 만들어진 VM 변경(요청 10): 신규 `nic_assign` 도구(Go, 워커풀) — `vm-network-migration` Step 3의 `SetPortgroup` → `EnsureConnectState`를 가져와 네트워크 어댑터 1의 포트그룹 교체 + **연결됨 + 전원 켤 때 연결** 체크, API로 재확인
  - 전원 꺼진 VM은 vSphere 특성상 "연결됨"이 켜질 수 없으므로 "전원 켤 때 연결"만 확인 (nm-verify와 같은 기준)

### 2.5 데이터센터가 2개 이상일 때 정상 동작 (추가 요청 / D9)

vCenter 인벤토리 최상위 아래 **Datacenter(예: `CloudLocal`)가 2개 이상**이면 일부 도구가 실패한다. 코드 확인 결과:

| 도구 | 현재 방식 | 다중 DC일 때 | 조치 |
|---|---|---|---|
| `lpage_setting` | `finder.DefaultDatacenter()` (에러 무시) | **실패** — 기본 DC를 못 정해 VM 조회가 안 됨 | RootFolder `ContainerView`로 VM 1회 배치 조회 |
| `mac_info` | 동일 | **실패** | 동일 |
| `main_conn` | `DefaultDatacenter()` + 클러스터 이름 조회 | **실패** (에러로 종료) | RootFolder `ContainerView`로 클러스터 이름 조회 |
| `vm_create` | DC 1개면 자동, 여러 개면 `-datacenter` 필수 | **종료** | 호스트가 속한 DC를 자동 판별(아래) |
| `affinity_setting`, `numa_preferht_setting` | DC별 goroutine 병렬 | 정상 | 변경 없음 |
| `tag_setting`, `vswitch_setting`, `license_assign`, `vm-param-check` | RootFolder `ContainerView` | 정상 | 변경 없음 |

- **`vm_create` 자동 판별**: DC 목록을 1회 조회한 뒤, DC마다 HostSystem/VM `ContainerView`를 **DC별 goroutine으로 병렬** 조회해서 `호스트 → (DC, vmFolder, 리소스풀)` 맵을 만든다. 이후 사전조사·생성 단계는 지금과 같다(맵 조회만 하므로 vCenter 왕복 증가 없음)
  - VM 이름 중복 검사는 **모든 DC**를 대상으로 한다
  - `-datacenter`를 주면 지금처럼 그 DC로만 한정 (기존 동작 유지)
  - 같은 이름의 호스트가 두 DC에 있으면 → 그 호스트만 에러로 건너뛰고 나머지는 진행
- **데이터센터 1개 + 그 아래 폴더가 여러 단계인 경우**(DC → 폴더 → 폴더 → 클러스터 → 호스트, VM 폴더도 동일): 코드상 **정상 동작**
  - `ContainerView`(recursive=true) 기반 도구(vm_create, vswitch, tag, license, vm-param-check)는 폴더 깊이와 무관하게 전부 조회한다
  - `finder` 기반 도구(lpage, mac_info, main_conn, affinity, numa_preferht)는 경로에 `/`가 없는 이름(`"*"`, 클러스터명)으로 찾는데, govmomi 0.55.1은 이 경우 "find 모드"로 **폴더를 끝까지 재귀 탐색**한다(`find/recurser.go`의 `Find` → `traversable`이 Folder를 항상 통과시킴)
  - 단, finder는 폴더를 한 단계씩 열어보므로 폴더가 많을수록 왕복이 늘어난다 → 이번에 lpage/mac_info/main_conn을 `ContainerView`로 바꾸면 폴더 수와 무관하게 1회 조회가 된다
  - 실측 전이므로 vcsim에서 **중첩 폴더(호스트 폴더 3단계 + VM 폴더 3단계)** 환경을 만들어 모든 도구를 돌려 확인한다
- **속도**: 추가 왕복은 "DC 수만큼의 배치 조회 1회씩"(병렬)뿐이라 DC 1개 환경에서는 지금과 같고, 여러 개여도 수 초 이내 차이. vcsim에서 DC 1개/3개 환경 실행 시간을 비교해 기록
- **검증**: vcsim `-dc 3`(DC 3개)에서 각 도구 실행 → 모든 DC의 대상이 처리되는지 확인. 랩에서는 테스트용 DC를 하나 더 만들어 실측 후 삭제
