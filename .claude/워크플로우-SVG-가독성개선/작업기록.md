# 작업기록 — VM/V2 흐름도 SVG 가독성 개선

## 2026-09-25

### 문제

`.claude/VM/V2/`의 세 흐름도 SVG가 부자연스러웠음:

- `VMsetup/workflow.svg` (674×7513)
- `vm-param-check-usability-improvement/workflow.svg` (736×6732)
- `vm-param-check-usability-improvement/workflow-deploy.svg` (1226×690)

원인: 각 노드 라벨 `<div>`에 `max-width:120px`가 인라인으로 박혀 있어, 노드 박스(최대 353px)가 이미 넓은데도 텍스트만 120px 폭으로 강제 줄바꿈되고 있었음. 노드 하나당 6~7줄까지 쪼개지면서 세로로 지나치게 길고(최대 7513px), 흰 배경도 콘�텐츠 폭에 딱 맞게 잘려 있어 여백이 거의 없었음.

### 원본 mermaid 소스가 없었음

세 SVG 모두 사전 렌더링된 정적 파일만 있고 `.mmd`/mermaid 코드블록 원본이 저장소에 없었음. SVG 안의 `id="L_A_B_0"`(엣지), `class="node"` + `id="flowchart-A-0"`(노드), `data-id="L_A_B_0"`가 붙은 `edgeLabel`(y/n 라벨)을 파이썬으로 파싱해 노드 텍스트·도형(사각형/마름모)·엣지·분기 라벨을 역추출, `flowchart TD` mermaid 소스로 재구성함.

### 조치

1. 역추출한 내용으로 `workflow.mmd` / `workflow.mmd` / `workflow-deploy.mmd` 작성 (각 폴더에 SVG와 함께 보관 — 이후 유지보수 시 이 소스를 고치고 재렌더링)
2. `@mermaid-js/mermaid-cli`(mmdc)를 스크래치패드에 설치, 이미 설치돼 있던 Playwright Chromium(`/opt/pw-browsers/chromium`)을 `--no-sandbox`로 지정해 렌더링
3. `wrappingWidth: 300`(기존 120 → 300), `useMaxWidth: false`로 재렌더링
4. 결과 확인 (PNG 스크린샷): 줄바꿈이 어절 단위로 자연스러워지고, 높이가 절반 가까이 줄었으며(예: 7513→3513), 흰 배경도 내용에 맞게 더 넓어짐
5. 기존 세 SVG를 결과물로 교체 (링크된 파일명은 그대로 유지, `README.md`/각 폴더 `README.md`의 링크 수정 불필요)

### 결과

| 파일 | 이전 | 이후 |
|---|---|---|
| `VMsetup/workflow.svg` | 674×7513 | 718×3513 |
| `vm-param-check-usability-improvement/workflow.svg` | 736×6732 | 933×3388 |
| `vm-param-check-usability-improvement/workflow-deploy.svg` | 1226×690 | 804×358 |

### 참고

- 렌더링에 쓴 `mermaidconfig.json`(`{"flowchart":{"htmlLabels":true,"wrappingWidth":300,"useMaxWidth":false}}`)은 저장소에 커밋하지 않음 — 필요하면 이 파일을 참고해 재구성
- 앞으로 이 세 흐름도를 고칠 때는 SVG를 직접 만지지 말고 옆의 `.mmd`를 고친 뒤 위 방식으로 재렌더링할 것
