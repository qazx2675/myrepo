# HP 서버 관리망(iLO) IP·VLAN USB 자동설정 계획서

> 작성일: 2026-09-25 · 상태: **계획 (코드 미작성)**
> 흐름도: [`흐름도.svg`](./흐름도.svg) · 할당 풀/되돌리기: [`할당풀-되돌리기.svg`](./할당풀-되돌리기.svg)

## 1. 결론: 가능하다 (단, 방식은 “메뉴 조작”이 아니라 “부팅 USB + 인밴드 설정”)

요구사항: USB에 IP·VLAN 목록을 미리 저장 → USB를 꽂으면 관리망(iLO) IP·VLAN을 **정의된 순서대로** 할당 →
쓴 항목은 기록은 남기되 다시 할당하지 않음 → 재부팅. 잘못 진행 시 **특정 순번으로 되돌리기**.

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 부팅 USB + `hponcfg`/`ilorest` (권장)** | USB로 경량 리눅스를 부팅 → 호스트 내부 채널(CHIF)로 iLO에 직접 IP/VLAN 기록 → iLO 리셋 → 서버 재부팅 | 계정/네트워크 불필요, 결과 검증 가능, 안정적 |
| B. USB 키보드 에뮬레이터(Pi Pico 등)로 RBSU 메뉴 자동 입력 | F9 → System Utilities → iLO 설정 메뉴를 키 입력으로 흉내 | 펌웨어/화면 구성 차이에 취약, 성공 여부 확인 불가 → **비권장** |

> 요청하신 “관리망 IP 설정 및 VLAN 설정 메뉴 진입 후 설정”은 방식 A에서 **메뉴를 거치지 않고 같은 설정값을
> 직접 기록**하는 것으로 대체됩니다. 결과는 RBSU 메뉴에서 입력한 것과 동일합니다.

### 전제/가정 (확인 필요)
1. 대상은 **iLO 4/5/6** 탑재 ProLiant (Gen9 이상). VLAN 설정은 iLO 4 이상에서 지원.
2. 서버에서 USB 부팅 허용 (F11 원타임 부트 또는 부팅 순서). **Secure Boot가 켜져 있으면** 서명된 부트로더(shim) 기반 이미지 필요.
3. 한 번에 **서버 1대에 USB 1개**를 꽂는 순차 작업 (동시에 여러 USB 복제 사용 시 순번 충돌 → 7장 참고).

## 2. USB 구성

```
USB (FAT32 또는 ext4, 라벨: ILOCFG)
├── boot/                  # 부팅 이미지 (RHEL/Rocky 기반 live 또는 HPE Scripting Toolkit)
├── ilocfg/
│   ├── pool.csv           # ★ 사전 정의 IP/VLAN 목록 (순서 = 할당 순서)
│   ├── state.json         # 다음 할당 순번(pointer) + 버전
│   ├── history.log        # 모든 할당/되돌리기 이력 (삭제 안 함, append-only)
│   ├── ilocfg.sh          # 메인 스크립트 (부팅 시 자동 실행)
│   └── bin/hponcfg, ilorest  # 오프라인 실행 바이너리
```

### pool.csv 형식
```
seq,ip,netmask,gateway,vlan_id,status,serial,assigned_at
1,10.10.1.11,255.255.255.0,10.10.1.1,100,USED,SGH123ABC,2026-09-25T10:01:22
2,10.10.1.12,255.255.255.0,10.10.1.1,100,USED,SGH123ABD,2026-09-25T10:09:40
3,10.10.1.13,255.255.255.0,10.10.1.1,100,FREE,,
4,10.10.1.14,255.255.255.0,10.10.1.1,100,FREE,,
```
- `status`: `FREE`(할당 가능) / `USED`(할당됨, 재할당 불가) / `VOID`(되돌리기로 무효화, 이력 보존용)
- 사용한 행은 **지우지 않고** `status`/`serial`/`시각`만 채워 기록을 남김

## 3. 동작 흐름 (흐름도.svg)

1. **USB 부팅** → `ilocfg.sh` 자동 실행
2. **서버 식별**: `dmidecode -s system-serial-number` 로 시리얼 확인
3. **중복 검사**: 이 시리얼이 이미 `USED`로 기록돼 있으면 → “이미 N번(IP x) 할당됨. 같은 값 재적용?[Y/n]” (재할당으로 순번 낭비 방지)
4. **다음 FREE 항목 선택**: `state.json`의 pointer 이후 첫 번째 `FREE` 행
5. **확인 화면** (10초 후 자동 진행, 아무 키나 누르면 메뉴):
   ```
   서버 SGH123ABE  →  #3  10.10.1.13 / VLAN 100
   [Enter] 진행   [G] 순번 이동   [U] 직전 할당 되돌리기   [L] 목록 보기   [Q] 중단
   ```
6. **iLO 설정 기록** (둘 중 하나, 서버 세대에 맞게):
   - `hponcfg -f net.xml` (RIBCL `MOD_NETWORK_SETTINGS`: `IP_ADDRESS`, `SUBNET_MASK`, `GATEWAY_IP_ADDRESS`, `DHCP_ENABLE=N`, `VLAN_ENABLED=Y`, `VLAN_ID`)
   - 또는 `ilorest` 인밴드 로그인 후 `EthernetInterface`의 IPv4/VLAN 값 설정
7. **pool.csv 갱신 먼저, 그다음 적용 확정**: 해당 행 `USED` + 시리얼 + 시각 기록, pointer+1, `history.log` 추가, `sync`
8. **iLO 리셋** (네트워크 설정 반영) → iLO 재기동 후 값 **재조회 검증** (IP/VLAN 일치 확인, 불일치 시 경고 + 로그)
9. **서버 재부팅** (USB 제거 안내 후 `reboot`)

## 4. 순번 되돌리기 (할당풀-되돌리기.svg)

| 기능 | 키/명령 | 동작 |
|---|---|---|
| 직전 할당 취소 | `[U]` / `ilocfg.sh undo` | 마지막 `USED` 행 → `VOID`로 표시하고 **동일 값의 새 FREE 행을 되살림**(pointer를 해당 순번으로) |
| 특정 순번으로 이동 | `[G] 5` / `ilocfg.sh goto 5` | pointer를 5로 설정. 5 이후 `USED` 행이 있으면 목록을 보여주고 “VOID 처리 후 재사용?” 확인 |
| 특정 항목 재사용 | `ilocfg.sh reuse 3` | 3번 행을 `FREE`로 되돌림 (이전 기록은 `history.log`에 보존) |
| 목록/이력 보기 | `[L]` / `ilocfg.sh list` | 순번·상태·시리얼 표 출력 |

- 원칙: **데이터는 절대 삭제하지 않음**. 되돌리기는 상태값 변경 + `history.log` 기록으로만 처리 → 언제든 추적 가능
- 되돌린 서버의 iLO에는 이미 값이 들어가 있으므로, 해당 서버는 USB를 다시 꽂아 **올바른 값으로 재설정**(3번 중복검사 단계에서 처리)

## 5. 안전장치
- `pool.csv` 쓰기 전 `pool.csv.bak` 백업, 임시파일에 쓰고 `mv`(원자적 교체) → USB 뽑힘/정전 시 파일 손상 방지
- 설정 전 iLO 현재 값 `history.log`에 저장 (원복용)
- 동일 IP가 두 행에 존재하거나 형식 오류 시 시작 단계에서 중단
- 적용 실패 시 `USED`로 확정하지 않고 pointer 유지

## 6. 작업 단계 / 완료 기준

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 대상 서버 세대/iLO 버전·Secure Boot 여부 확인 | 부팅 가능한 이미지 결정 |
| 2 | 부팅 USB 이미지 제작 (자동 실행, `hponcfg`/`ilorest` 포함, 오프라인) | 테스트 서버에서 USB 부팅 → 스크립트 자동 실행 |
| 3 | `ilocfg.sh` 작성 (풀 관리 + 적용 + 검증 + 되돌리기) | 서버 없이 `--dry-run`으로 순번 할당/undo/goto 동작 확인 |
| 4 | 실서버 1대 적용 테스트 | iLO 웹에서 IP·VLAN 반영 확인, pool.csv USED 기록 |
| 5 | 되돌리기 시나리오 테스트 | 순서 틀리게 꽂은 뒤 goto/undo로 복구 → 재설정 성공 |

## 7. 결정이 필요한 사항
1. 여러 명이 **USB 여러 개를 복제해 동시에** 작업하는가? → 그렇다면 USB별로 풀 구간을 나눠야 함(예: USB-A는 1~50, USB-B는 51~100)
2. 서버 세대(Gen9/10/11) 혼재 여부 → `hponcfg`(RIBCL) 단일로 갈지, Gen10+ 전용 `ilorest`로 갈지
3. 할당 순서 기준: “꽂는 순서” 그대로 vs “시리얼 → IP 매핑표”(순서 무관, 실수 원천 차단) — **후자가 더 안전**하며 시리얼 목록을 미리 알 수 있으면 권장
