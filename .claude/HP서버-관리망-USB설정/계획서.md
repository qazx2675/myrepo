# HP 서버 관리망(iLO) IP·VLAN USB 자동설정 계획서

> 작성일: 2026-09-25 · 상태: **계획 (코드 미작성)**
> 흐름도: [`흐름도.svg`](./흐름도.svg) · 할당 풀/되돌리기: [`할당풀-되돌리기.svg`](./할당풀-되돌리기.svg)

## 1. 결론: 가능하다 (단, 방식은 “메뉴 조작”이 아니라 “부팅 USB + 인밴드 설정”)

요구사항: USB에 IP·VLAN 목록을 미리 저장 → USB를 꽂으면 관리망(iLO) IP·VLAN을 **정의된 순서대로** 할당 →
쓴 항목은 기록은 남기되 다시 할당하지 않음 → 재부팅. 잘못 진행 시 **특정 순번으로 되돌리기**.

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 부팅 USB + `hponcfg`/`ilorest` (권장)** | USB로 경량 리눅스를 부팅 → 호스트 내부 채널(CHIF)로 iLO에 직접 IP/VLAN 기록 → iLO 리셋 → 서버 재부팅 | 계정/네트워크 불필요, 결과 검증 가능, 안정적 |
| B. USB 키보드 에뮬레이터(Pi Pico 등)로 RBSU 메뉴 자동 입력 | F9 → System Utilities → iLO 설정 메뉴를 키 입력으로 흉내 | 펌웨어/화면 구성 차이에 취약, 성공 여부 확인 불가 → **비권장** |

> 요청하신 “관리망 IP 설정 및 VLAN 설정 메뉴 진입 후 설정”은 방식 A에서 **메뉴를 거치지 않고 같은 설정값을
> 직접 기록**하는 것으로 대체됩니다. 결과는 RBSU 메뉴에서 입력한 것과 동일합니다.

### 전제/가정 (확인 필요)
1. 대상은 **iLO 4/5/6** 탑재 ProLiant (Gen9 이상). VLAN 설정은 iLO 4 이상에서 지원.
2. **F11 없이 자동 USB 부팅**: 부팅 순서에서 USB가 디스크/PXE보다 먼저이거나, 디스크가 비어 있는 신규 서버여야 함 (8장 참고). **Secure Boot가 켜져 있으면** 서명된 부트로더(shim) 기반 이미지 필요.
3. 한 번에 **서버 1대에 USB 1개**를 꽂는 순차 작업 (동시에 여러 USB 복제 사용 시 순번 충돌 → 7장 참고).

## 2. USB 구성

```
USB (FAT32 또는 ext4, 라벨: ILOCFG)
├── boot/                  # 부팅 이미지 (RHEL/Rocky 기반 live 또는 HPE Scripting Toolkit) — 전체를 RAM에 적재(toram)
├── ilocfg/
│   ├── pool.csv           # ★ 사전 정의 IP/VLAN 목록 (순서 = 할당 순서)
│   ├── state.json         # 다음 할당 순번(pointer) + 버전
│   ├── history.log        # 모든 할당/되돌리기 이력 (삭제 안 함, append-only)
│   ├── ilocfg.sh          # 메인 스크립트 (부팅 시 자동 실행)
│   └── bin/hponcfg, ilorest  # 오프라인 실행 바이너리
```

### pool.csv 형식
```
seq,rack_pos,ip,netmask,gateway,vlan_id,status,serial,assigned_at
1,R01-U40,10.10.1.11,255.255.255.0,10.10.1.1,100,USED,SGH123ABC,2026-09-25T10:01:22
2,R01-U38,10.10.1.12,255.255.255.0,10.10.1.1,100,USED,SGH123ABD,2026-09-25T10:09:40
3,R01-U36,10.10.1.13,255.255.255.0,10.10.1.1,100,FREE,,
4,R01-U34,10.10.1.14,255.255.255.0,10.10.1.1,100,FREE,,
```
- 할당 기준은 **랙 내 꽂는 순서** (시리얼을 미리 알 필요 없음). `seq` 순서 = 랙에서 USB를 꽂는 순서
- `rack_pos`: **랙 위치 표시용** (예: `R01-U36`). 화면에 표시되고, 작업 후 점검 목록(`ilocfg.sh list`)에서 서버 앞 시리얼 태그와 대조하는 데 사용
- `serial`: 사전 입력하지 않음. 할당 시 서버에서 **자동으로 읽어 기록**만 함 (같은 서버 재삽입 감지·이력 추적용)
- `status`: `FREE`(할당 가능) / `USED`(할당됨, 재할당 불가) / `VOID`(되돌리기로 무효화, 이력 보존용)
- 사용한 행은 **지우지 않고** `status`/`serial`/`시각`만 채워 기록을 남김

## 3. 동작 흐름 (흐름도.svg) — 꽂고 → 파란불 → 뽑고 → 다음 서버

작업자는 **USB 꽂고 전원 ON → 서버 UID LED(파란불)가 켜지면 USB 뽑고 다음 서버로** 이동만 한다. 키 입력 없음.

1. **USB 꽂고 전원 ON (또는 재부팅)** → 부팅 순서에 따라 **F11 없이 USB로 자동 부팅**
2. **RAM 적재**: 부팅 이미지 전체를 RAM으로 복사(toram) → 이후 USB가 없어도 동작
3. **3초 관리모드 대기**: 화면에 “아무 키 → 관리 메뉴(U/G/L)” 표시. 입력 없으면 자동 진행 (평소에는 무시)
4. **서버 식별**: `dmidecode -s system-serial-number` 로 시리얼 자동 확인
5. **할당 항목 결정**
   - 이 시리얼이 이미 `USED` → **같은 값 자동 재적용** (순번 소모 없음, 6단계 건너뛰고 7단계로, 재삽입해도 안전)
   - 아니면 `state.json` pointer 이후 첫 번째 `FREE` 행 (없으면 오류 표시)
6. **USB에 먼저 기록 (예약)**: 해당 행 `USED` + 시리얼 + 시각, pointer+1, `history.log` 추가, `sync`
   → USB에 쓸 일은 여기서 끝
7. **UID LED 켜기 = “USB 빼도 됨” 신호** → 작업자는 USB를 뽑아 다음 서버로 이동
8. **RAM에서 iLO 설정 기록** (서버 세대에 맞게 하나):
   - `hponcfg -f net.xml` (RIBCL `MOD_NETWORK_SETTINGS`: `IP_ADDRESS`, `SUBNET_MASK`, `GATEWAY_IP_ADDRESS`, `DHCP_ENABLE=N`, `VLAN_ENABLED=Y`, `VLAN_ID`)
   - 또는 `ilorest` 인밴드 로그인 후 `EthernetInterface`의 IPv4/VLAN 값 설정
9. **iLO 리셋 → 값 재조회 검증**
   - 성공: **UID LED 끄고 서버 재부팅** (USB가 없으므로 정상 부팅, 무한 반복 없음)
   - 실패: **UID LED 켠 채로 유지** + 화면에 빨간 오류, 재부팅 안 함
10. **한 바퀴 끝난 뒤 점검**: 파란불이 남아 있는 서버 = 실패. 노트북에 USB를 꽂고 `ilocfg.sh verify` → `USED` IP 전체 ping, `ilocfg.sh list` → 순번·랙위치·시리얼 목록으로 서버 앞 시리얼 태그와 대조

> 예상 시간(서버당): POST 2~5분 + USB 부팅·RAM 적재 30초~1분 → 파란불. 작업자가 기다리는 건 여기까지이고,
> iLO 설정·리셋·재부팅(수 분)은 USB를 뺀 뒤 서버가 혼자 진행한다.
> 확인 화면이 없어 할당 전에 순서 착오를 막을 수는 없으므로, 착오는 10단계 점검에서 찾아 4장 되돌리기로 복구한다.

## 4. 순번 되돌리기 (할당풀-되돌리기.svg)

| 기능 | 키/명령 | 동작 |
|---|---|---|
| 직전 할당 취소 | `[U]` / `ilocfg.sh undo` | 마지막 `USED` 행 → `VOID`로 표시하고 **동일 값의 새 FREE 행을 되살림**(pointer를 해당 순번으로) |
| 특정 순번으로 이동 | `[G] 5` / `ilocfg.sh goto 5` | pointer를 5로 설정. 5 이후 `USED` 행이 있으면 목록을 보여주고 “VOID 처리 후 재사용?” 확인 |
| 특정 항목 재사용 | `ilocfg.sh reuse 3` | 3번 행을 `FREE`로 되돌림 (이전 기록은 `history.log`에 보존) |
| 목록/이력 보기 | `[L]` / `ilocfg.sh list` | 순번·상태·시리얼 표 출력 |

- 실행 방법: ① 서버 부팅 시 **3초 안에 아무 키** → 관리 메뉴(`[U]`/`[G]`/`[L]`) 또는 ② **노트북에 USB를 꽂고** `ilocfg.sh <명령>` 실행
- 원칙: **데이터는 절대 삭제하지 않음**. 되돌리기는 상태값 변경 + `history.log` 기록으로만 처리 → 언제든 추적 가능
- 되돌린 서버의 iLO에는 이미 값이 들어가 있으므로, 해당 서버는 USB를 다시 꽂아 **올바른 값으로 재설정** (VOID 처리된 시리얼이라 새 항목을 받음)

## 5. 안전장치
- `pool.csv` 쓰기 전 `pool.csv.bak` 백업, 임시파일에 쓰고 `mv`(원자적 교체) → USB 뽑힘/정전 시 파일 손상 방지
- 설정 전 iLO 현재 값 `history.log`에 저장 (원복용)
- 동일 IP가 두 행에 존재하거나 형식 오류 시 시작 단계에서 중단
- **USB를 일찍 빼도 안전하도록 기록을 먼저 하고(6단계) 적용은 나중에(8단계)**. 그래서 적용이 실패해도 해당 행은 `USED`로 남음 → 파란불이 남은 서버를 확인해 USB 재삽입(같은 값 재적용) 또는 `undo`
- UID LED가 켜지기 전에 USB를 뽑으면 기록이 안 됐을 수 있음 → 그 서버는 USB를 다시 꽂으면 됨 (기록됐으면 같은 값 재적용, 안 됐으면 그 순번 할당)

## 6. 작업 단계 / 완료 기준

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 대상 서버 세대/iLO 버전·Secure Boot 여부 확인 | 부팅 가능한 이미지 결정 |
| 2 | 부팅 USB 이미지 제작 (RAM 적재, 자동 실행, `hponcfg`/`ilorest` 포함, 오프라인) | 테스트 서버에서 **F11 없이** USB 부팅 → 스크립트 자동 실행 → 파란불 후 USB 뽑아도 끝까지 진행 |
| 3 | `ilocfg.sh` 작성 (풀 관리 + 적용 + 검증 + 되돌리기) | 서버 없이 `--dry-run`으로 순번 할당/undo/goto 동작 확인 |
| 4 | 실서버 1대 적용 테스트 | iLO 웹에서 IP·VLAN 반영 확인, pool.csv USED 기록 |
| 5 | 되돌리기 시나리오 테스트 | 순서 틀리게 꽂은 뒤 goto/undo로 복구 → 재설정 성공 |
| 6 | UID LED 동작 확인 | iLO 리셋 후에도 실패 시 파란불 유지, 성공 시 꺼짐 |

## 7. 결정이 필요한 사항
1. 여러 명이 **USB 여러 개를 복제해 동시에** 작업하는가? → 그렇다면 USB별로 풀 구간을 나눠야 함(예: USB-A는 1~50, USB-B는 51~100)
2. 서버 세대(Gen9/10/11) 혼재 여부 → `hponcfg`(RIBCL) 단일로 갈지, Gen10+ 전용 `ilorest`로 갈지
3. ~~할당 순서 기준~~ → **결정됨 (2026-09-25): 시리얼 미확보, 랙 내 순서대로 꽂아 할당**. 순서 착오 대비책은 `rack_pos` 확인 화면 + 4장 되돌리기 기능

4. ~~확인 화면 자동 진행 여부~~ → **결정됨 (2026-09-25): 키 입력 없이 완전 자동**. 꽂고 파란불 → 뽑고 다음 서버
5. 대상 서버가 **디스크가 비어 있는 신규 서버**인가, **OS가 이미 설치된 서버**인가? → 8장

## 8. F11 없이 USB로 부팅되는 조건

| 서버 상태 | 결과 | 조치 |
|---|---|---|
| 신규 서버 (디스크 비어 있음) | 부팅할 디스크가 없어 USB로 넘어갈 가능성 높음. 단 PXE가 앞이면 PXE 대기(NIC당 수십 초~1분) 후 USB | **실서버 1대로 먼저 확인** (단계 2) |
| 부팅 순서에 USB가 디스크보다 앞 | 자동 USB 부팅 | 없음 |
| OS 설치 서버, 디스크가 USB보다 앞 | USB 무시하고 OS 부팅 | 부팅 순서 변경 필요 (iLO로 원격 일괄 변경 가능하지만 iLO IP가 아직 없어 이번 작업에선 불가) → 이 경우만 F11 필요 |
