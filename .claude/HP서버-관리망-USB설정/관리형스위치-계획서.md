# 노트북 + 관리형 스위치 방식 계획서 (포트 위치 = 할당 순서)

> 작성일: 2026-09-25 · 상태: **계획 (코드 미작성)**
> 그림: [`관리형스위치-흐름도.svg`](./관리형스위치-흐름도.svg) · 비교 검토: [`노트북-DHCP-방식검토.md`](./노트북-DHCP-방식검토.md) · USB 방식: [`계획서.md`](./계획서.md)

## 1. 요약

서버 iLO 전용 포트를 **랙 순서대로 스위치 1번, 2번, 3번… 포트에 한꺼번에 꽂고**, 노트북에서 스크립트를 한 번 실행하면
**스위치 포트 번호 → pool.csv 행 → 최종 IP·VLAN**으로 자동 설정한다. 쓴 행은 `USED`로 남아 다시 할당되지 않는다.

| 항목 | 일반 허브 | **관리형 스위치** |
|---|---|---|
| 포트 위치 파악 | 불가 (MAC만 보임) | **SNMP로 "MAC ↔ 포트" 표 조회 가능** |
| 연결 방식 | 한 대씩 순서대로 꽂기 | **전부 한 번에 꽂아도 됨** |
| 순서 착오 | 꽂는 순서를 틀리면 착오 | 케이블 위치만 맞으면 착오 없음 |
| 최종 IP·VLAN 검증 | 불가 (VLAN 태그가 붙으면 노트북에서 안 보임) | **가능** (스위치에 VLAN을 같이 열어두면 노트북에서 최종 IP로 ping) |
| 서버 전원 | 불필요 (전원 코드만) | 불필요 (전원 코드만) |

## 2. 구성

```
서버1 iLO ─ 포트1 ┐
서버2 iLO ─ 포트2 ├─ 관리형 스위치 ─ 포트24(업링크) ─ 노트북
서버3 iLO ─ 포트3 ┘   (관리 IP 192.168.100.2)          (192.168.100.1 + VLAN100 서브인터페이스)
```

### 스위치 설정 (작업 전 1회)
| 설정 | 값 (예) | 목적 |
|---|---|---|
| 서버 포트(1~23) | untagged VLAN 1 (임시망) + **tagged VLAN 100** (관리망) | 임시 IP 수신 + 설정 후 최종 IP 확인 |
| 노트북 포트(24) | untagged VLAN 1 + tagged VLAN 100 | 노트북이 두 망 모두 접근 |
| 스위치 관리 IP | 192.168.100.2 | SNMP 조회용 |
| SNMP | v2c, 읽기 전용 community (예: `ilocfg`) | MAC 테이블 조회 |

- VLAN 태그 설정을 못 하는 스위치라도 **SNMP만 되면 할당은 가능**. 최종 검증(ping)만 빠지고 결과는 iLO 응답으로 확인

### 노트북 구성 (Linux 기준, 오프라인 설치)
| 구성요소 | 역할 |
|---|---|
| `dnsmasq` | DHCP 서버, 임시 대역 `192.168.100.100~199`, 임대 목록 파일(`dnsmasq.leases`) 생성 |
| `snmpwalk` (net-snmp) | 스위치 MAC 테이블 조회: `dot1qTpFdbPort`(또는 `dot1dTpFdbPort`) + `dot1dBasePortIfIndex` → 포트 번호 |
| `curl` + `jq` | iLO Redfish API 호출 (iLO 5/6). iLO 4는 RIBCL XML POST |
| `ilonet.sh` | 메인 스크립트 (아래 흐름) |
| VLAN 서브인터페이스 | `ip link add link eth0 name eth0.100 type vlan id 100` + 관리망 IP 1개 → 최종 IP 검증용 |

## 3. 파일

```
ilonet/
├── pool.csv        # ★ 포트별 IP/VLAN 목록
├── cred.csv        # iLO 기본 비밀번호 (serial 또는 MAC → 비밀번호). 없으면 실행 중 입력
├── state.json
├── history.log     # append-only
└── ilonet.sh
```

### pool.csv (USB 방식에 `port` 칸 추가)
```
seq,port,rack_pos,ip,netmask,gateway,vlan_id,status,mac,serial,assigned_at
1,1,R01-U40,10.10.1.11,255.255.255.0,10.10.1.1,100,USED,94:40:c9:aa:00:01,SGH123ABC,2026-09-25T10:01:22
2,2,R01-U38,10.10.1.12,255.255.255.0,10.10.1.1,100,FREE,,,
3,3,R01-U36,10.10.1.13,255.255.255.0,10.10.1.1,100,FREE,,,
```
- `port`: 스위치 포트 번호. 스위치가 여러 대면 `sw1:5` 형식
- `mac`/`serial`: 사전 입력 안 함. 할당 시 자동 기록

## 4. 동작 흐름 (`ilonet.sh run`)

1. **사전 점검**: pool.csv 형식·중복 IP, 스위치 SNMP 응답, dnsmasq 동작 확인
2. **감시 루프** (예: 5초 간격) — 새 임대(MAC·임시IP)가 생길 때마다:
   1. SNMP MAC 테이블에서 이 MAC의 **포트 번호** 조회 (업링크 포트는 제외)
   2. pool.csv에서 그 포트의 행을 찾음
      - `FREE` → 진행
      - `USED`이고 **같은 MAC** → 같은 값 재적용 (재시도 안전)
      - `USED`이고 **다른 MAC** → **충돌: 중단하고 표시** (케이블을 다른 서버로 바꿔 꽂았음 → `reuse --port N`으로 판단)
      - 행 없음 → 경고 (pool에 없는 포트)
   3. 임시 IP로 iLO Redfish 로그인 (`cred.csv` 또는 입력) → **시리얼 읽기**
   4. **pool.csv 먼저 기록**: `USED` + MAC + 시리얼 + 시각, `history.log` 추가
   5. Redfish PATCH `Managers/1/EthernetInterfaces/1`: DHCP 끄기, IPv4 고정 주소·마스크·게이트웨이, `VLAN{VLANEnable:true, VLANId}`
   6. iLO 리셋 (`Manager.Reset`) → 60~90초 후 **VLAN 서브인터페이스에서 최종 IP ping + Redfish 재조회**로 검증
3. **실시간 표** 출력:
   ```
   포트 랙위치   시리얼      최종IP        상태
   1    R01-U40  SGH123ABC   10.10.1.11   완료 ✔
   2    R01-U38  SGH123ABD   10.10.1.12   iLO 리셋 대기…
   3    R01-U36  -           -            DHCP 대기
   ```
4. 여러 포트를 **병렬 처리** (서버 20대도 수 분 내)

## 5. 위치 확인 / 되돌리기

| 명령 | 동작 |
|---|---|
| `ilonet.sh blink 5` | 5번 포트 서버의 **UID LED(파란불) 켜기** → 랙에서 케이블 위치가 맞는지 눈으로 확인 |
| `ilonet.sh list` | 포트·랙위치·시리얼·IP·상태 표 |
| `ilonet.sh undo` | 마지막 할당 `VOID` + 같은 값 FREE 행 복원 |
| `ilonet.sh reuse --port 5` | 5번 포트 행을 FREE로 되돌림 (케이블 바꿔 꽂은 경우) |
| `ilonet.sh goto N` | pointer 이동 (포트 기반에서는 거의 불필요, USB 방식 호환용) |

- 데이터는 삭제하지 않고 상태 변경 + `history.log` 기록만 (USB 방식과 동일)
- 이미 최종 IP로 바뀐 iLO를 다른 값으로 고치려면 최종 IP(VLAN 서브인터페이스)로 접속해 재설정: `ilonet.sh fix --port 5`

## 6. 전제 / 제약
1. **iLO 비밀번호**: 공장 기본 비밀번호는 서버마다 다름(시리얼 태그 인쇄). 납품 목록으로 `cred.csv`를 만들면 완전 자동, 없으면 서버마다 입력
2. iLO **전용 포트**에 케이블 연결, iLO가 **DHCP 켜짐(공장 기본)** 상태여야 함. DHCP를 끈 재사용 서버는 USB 방식으로
3. 서버 **전원 코드만 연결**하면 됨 (전원 ON 불필요)
4. 스위치가 **SNMP BRIDGE-MIB/Q-BRIDGE-MIB MAC 테이블**을 제공해야 함 (대부분의 관리형 스위치 지원, 기종 확인 필요)

## 7. 작업 단계 / 완료 기준

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 스위치 기종 확인, SNMP·VLAN 설정 | 노트북에서 `snmpwalk`로 MAC↔포트 표가 보임 |
| 2 | 노트북 오프라인 패키지 구성 (dnsmasq, net-snmp, curl, jq) | 폐쇄망 노트북에 설치 완료 |
| 3 | `ilonet.sh` 작성 + dry-run (가짜 leases/SNMP 출력으로) | 포트→행 매칭, 충돌 감지, undo/reuse 동작 확인 |
| 4 | 실서버 1대 | 최종 IP·VLAN으로 ping 성공, pool.csv USED 기록 |
| 5 | 실서버 여러 대 동시 | 병렬 처리, `blink`로 위치 확인 |

## 8. 결정이 필요한 사항
1. 사용할 스위치 기종 (SNMP·VLAN 태그 지원 여부)
2. `cred.csv`를 만들 수 있는 **iLO 기본 비밀번호 목록** 유무
3. 노트북 OS (Linux 권장. Windows면 WSL 또는 Tftpd64 + PowerShell로 재구성)
4. 서버 세대 (iLO 4면 Redfish 대신 RIBCL)
