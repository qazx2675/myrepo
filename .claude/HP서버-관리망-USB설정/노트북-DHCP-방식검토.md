# 노트북 + 허브(스위치) + DHCP 방식 검토

> 작성일: 2026-09-25 · 상태: **검토 (코드 미작성)** · 기존 USB 방식: [`계획서.md`](./계획서.md)
> 관리형 스위치 상세 계획: [`관리형스위치-계획서.md`](./관리형스위치-계획서.md)

## 1. 질문별 결론

| 질문 | 답 |
|---|---|
| 허브 자체가 DHCP를 할 수 있나 | **아니오.** 일반 허브·스위치(비관리형)는 DHCP 서버 기능이 없다. 노트북에 DHCP 서버를 띄우면 된다 |
| 노트북 DHCP만으로 iLO에 임시 IP 주기 | **가능.** iLO 전용 포트는 공장 기본값이 DHCP 켜짐 → 허브에 꽂으면 노트북에서 임시 IP를 받아감 |
| 허브 **포트 위치별로** 순서대로 할당 | **일반 허브로는 불가.** DHCP 요청에는 MAC 주소만 있고 "몇 번 포트인지" 정보가 없다. **관리형 스위치**가 있어야 가능 (3장) |
| 쓴 IP는 사용 처리해 재할당 안 함 | **가능.** USB 방식과 같은 `pool.csv`(USED/FREE/VOID)를 노트북에서 관리 |

## 2. 전체 흐름 (노트북 방식)

```
[서버 iLO 전용포트] ─┐
[서버 iLO 전용포트] ─┼─ 허브/스위치 ─ 노트북 (DHCP 서버 + 설정 스크립트 + pool.csv)
[서버 iLO 전용포트] ─┘
```

1. 노트북에 DHCP 서버 실행 (Linux: `dnsmasq`, Windows: `Tftpd64`의 DHCP 기능 등) — 임시 대역 예: `192.168.100.100~200`
2. iLO가 임시 IP를 받으면 스크립트가 감지 → **pool.csv 다음 FREE 항목 할당**, 즉시 USED 기록
3. 임시 IP로 iLO에 접속해 **최종 고정 IP + VLAN 설정** (iLO 5/6: Redfish API, iLO 4: RIBCL XML) → iLO 리셋
4. iLO는 최종 IP/VLAN으로 바뀌면서 임시망에서 빠짐 → 다음 서버

**USB 방식 대비 장점**
- **서버 전원을 켤 필요가 없음** (iLO는 전원 코드만 꽂혀 있으면 대기전원으로 동작) → POST 2~5분 대기 없음
- 부팅 순서·Secure Boot·F11 문제 자체가 없음
- 여러 대를 동시에 처리 가능, 결과를 노트북 화면에서 바로 확인
- 시리얼은 Redfish로 읽어 자동 기록

**단점 / 반드시 확인할 것**
- **iLO 로그인 계정이 필요.** 공장 기본 `Administrator` 비밀번호는 **서버마다 다르고** 서버 앞 시리얼 태그(풀탭)에 인쇄돼 있음
  → 납품 시 받은 "시리얼·iLO MAC·기본 비밀번호" 목록이 있으면 완전 자동, 없으면 서버마다 비밀번호 입력 필요
  (USB 방식은 서버 내부 채널을 쓰므로 비밀번호가 필요 없음 — 이 점이 USB 방식의 가장 큰 장점)
- iLO **전용 포트**에 케이블을 꽂아야 함 (공유 NIC는 기본 꺼짐)
- 이미 DHCP를 끈 iLO(재사용 서버)는 임시 IP를 안 받음 → USB 방식으로 처리

## 3. "포트 위치 → 순서" 할당 방법 3가지

| 방법 | 필요 장비 | 원리 | 판단 |
|---|---|---|---|
| **A. 연결 순서 = 할당 순서** | 일반 허브도 가능 | 케이블을 **한 대씩 순서대로 꽂음** → 새 MAC이 나타난 순서대로 할당 | 가장 간단. 지금까지의 "랙 순서대로" 방식과 동일. 한 대 끝나고 다음 꽂기 |
| **B. 스위치 MAC 테이블 조회** | **관리형 스위치** (SNMP 지원, 소형 8~24포트) | 노트북이 SNMP로 스위치의 "MAC ↔ 포트번호" 표를 읽음 → **1번 포트 = 1번 IP** | **포트 위치별 할당 권장안.** 한꺼번에 다 꽂아도 됨. 포트↔랙위치 대응표만 지키면 순서 착오 없음 |
| C. DHCP Option 82 | 관리형 스위치 (DHCP Snooping + Option 82 지원) | 스위치가 DHCP 요청에 포트번호를 붙여 보냄 → DHCP 서버가 포트별로 IP 지정 | 스위치 기종마다 설정·형식이 달라 B보다 번거로움 |

**B 방식 동작**
1. `pool.csv`에 `port` 칸 추가 (`seq,port,rack_pos,ip,...`) — 스위치 1번 포트 ↔ 랙 R01-U40 ↔ 10.10.1.11
2. 서버 iLO 포트를 스위치 포트에 랙 순서대로 한 번에 모두 연결
3. 노트북: DHCP 임대 목록(MAC·임시IP) + 스위치 MAC 테이블(MAC·포트) 결합 → 포트번호로 pool.csv 행 결정
4. 해당 행 USED 기록 → Redfish로 최종 IP/VLAN 설정 → iLO 리셋 → 새 IP로 ping 확인
5. 한 번 쓴 행은 USED로 남아 다시 할당 안 됨. 같은 MAC(시리얼)이 다시 나타나면 같은 값 재적용

## 4. 권장 진행

| 상황 | 권장 |
|---|---|
| 기본 비밀번호 목록이 있음 + 관리형 스위치 있음 | **노트북 + B 방식** (전원 ON 불필요, 한꺼번에 연결, 포트=순서) |
| 비밀번호 목록 없음 | **USB 방식** (비밀번호 불필요). 노트북 방식은 서버마다 태그 비밀번호 입력 필요 |
| 일반 허브만 있음 | 노트북 + A 방식 (한 대씩 꽂기) 또는 USB 방식 |

## 5. 결정이 필요한 사항
1. 납품 자료에 **iLO 기본 비밀번호(또는 시리얼·MAC) 목록**이 있는가?
2. **관리형 스위치**(SNMP 지원)를 쓸 수 있는가, 일반 허브뿐인가?
3. 서버 세대 (iLO 4면 Redfish 대신 RIBCL 사용)
