# CLAUDE.md — 빗썸 코인 자동매매 프로젝트 작업 규칙

이 문서는 이 프로젝트에서 Claude가 지켜야 할 규칙이다.
**철학: "돈을 버는 시스템"이 아니라 "잃지 않는 시스템"을 만든다.**

---

## 1. 안전 규칙 (최우선 — 위반 금지)

### 1.1 실계좌 보호

- **기본값은 항상 `DRY_RUN = True` 다.**
- `DRY_RUN = False` 전환은 **사용자가 명시적으로 요청할 때만.** 임의 전환 금지.
- **실주문 3중 게이트** (`src/trader.py`): `DRY_RUN=False` + `.env` `LIVE_TRADING=1` + 주문권한 키.
  셋 다 아니면 `trader.Trader()` 가 `RuntimeError`. 이 게이트를 약화시키는 코드 금지.
- **M1 ~ M6 기간에는 주문 권한이 없는 "조회 전용" 빗썸 API 키만 사용한다.**
  소프트웨어 플래그는 버그로 뚫릴 수 있으므로, 거래소 레벨에서 막는다.
- 주문 권한 키는 **M7에서 신규 발급**한다. 그 전에 발급하지 않는다.
- 실주문 관련 코드 작성 시 반드시 사용자에게 확인받는다.

### 1.2 비밀정보 하드코딩 금지

- 빗썸 **API Key / Secret**, **ntfy 토픽 / 토큰** 은 반드시 `.env` 로 분리.
- `.env` 는 `.gitignore` 에 포함. 코드/로그/커밋에 키가 노출되지 않도록 한다.
- 로그 출력 시 키는 마스킹한다.

### 1.3 금지 사항

- **24시간 루프 안에서 유료 API 호출 금지.** 뉴스는 RSS 키워드 필터로 처리한다.
  런타임에 LLM(Claude 등) API를 부르는 코드를 작성하지 않는다. (계획서 13장)
- **선물 / 레버리지 / 마진 거래 코드 작성 금지.** 현물만.
- **모드 자동 전환 로직 구현 금지.** (수익이 나면 aggressive로 바꾸는 로직 = 파산 경로)
- **물타기 자동 실행 금지.** 사람 승인 절차를 반드시 거친다.
- **지정가 손절 금지.** 손절은 시장가로 확실히 나간다. (24시간 시장, 가격제한폭 없음)
- **최소 주문금액 5,000원 미검증 주문 발주 금지.**

## 2. 코드 작성 규칙

### 2.1 요청된 것만 구현

- 추측성 기능 추가 금지.
- 단일 사용 코드에 추상화 넣지 않기.
- 요청되지 않은 유연성/설정 옵션 만들지 않기.
- 일어날 수 없는 시나리오에 대한 예외 처리 넣지 않기.

### 2.2 외과적 수정

- 기존 코드 수정 시 인접 코드를 "개선"하지 않는다.
- 깨지지 않은 것은 리팩토링하지 않는다.
- 기존 스타일에 맞춘다.
- 사용자 요청과 직접 연결된 줄만 변경한다.

### 2.3 가정을 말한다

- 불확실하면 질문한다. 조용히 선택하지 않는다.
- 여러 해석이 가능하면 제시한다.
- 더 간단한 방법이 있으면 언급하고, 필요하면 반박한다.

## 3. 매매 로직 규칙

### 3.1 모드 무관 불변 규칙 (7개)

1. **손절은 기계적으로 집행한다.** "조금 더 기다리기" 같은 예외 코드 금지.
2. **물타기 자동 실행 금지.** 사람 승인 필수.
3. **선물/레버리지/마진 금지.**
4. **M6 페이퍼 검증 통과 전 실주문 금지.**
5. **일일 손실 한도 도달 시 당일 신규 매수 중단.**
6. **모드 자동 전환 구현 금지.**
7. **투자유의종목 지정 시 모드 무관 즉시 전량 시장가 청산.**

### 3.2 모든 주문은 최소금액 검증을 통과해야 한다

```python
if 주문금액 < settings.MIN_ORDER_KRW:   # 5000
    # 분할 매도 -> 전량 매도로 승격
    # 신규 진입 -> 스킵 + 로그
```

이 검증 없이 주문을 만드는 코드는 리뷰에서 반려한다.

### 3.3 알림은 사후 통지다

**손절/청산은 알림 성공 여부와 무관하게 집행한다.**
`notifier` 예외가 매매 로직을 막는 구조로 짜지 않는다.

## 4. 백테스트 / 페이퍼 트레이딩 규칙

빗썸에는 모의투자 계좌도 과거 호가 스냅샷도 없다. 두 갈래로 나눈다.

**백테스트 (M3-a 완료)** — `src/fills.py` 캔들 기반 체결
- 신호는 **다음 봉 시가**에 체결 (룩어헤드 금지). 전략은 `df.iloc[:i+1]` 만 본다.
- 시장가 슬리피지 `FILL_SLIPPAGE_BPS`, 수수료 `BACKTEST_FEE_RATE` **끄지 않는다.**
- 손절은 갭다운 시 시가 체결(더 불리하게). 유리하게 계산하지 않는다.
- 홀드아웃 기간(`HOLDOUT_*`)에서 결과를 보고 파라미터를 만지지 않는다. `data/.holdout_used` 가 증인.

**실시간 페이퍼 (M5.5, `src/paper.py`)** — 실시간 호가로 체결
- 시세/호가는 **실제 빗썸 API**. 체결은 **호가 잔량 순차 소진** (`PAPER_USE_ORDERBOOK = True`).
- 수수료 + 지연(300ms) 반드시 반영. **끄거나 단순화하지 않는다.**

### 4.1 M6는 두 단계다

| 단계 | `PAPER_CAPITAL` | 목적 |
|---|---|---|
| M6-a | `100_000_000` | 전략 검증 (거래 횟수 확보) |
| M6-b | `100_000` | **제약 검증 (최소주문/수수료 비중)** |

**M6-a만 하고 실전 전환하지 않는다.** 1억에서는 5,000원 최소주문 제약이 보이지 않는다.

## 5. ntfy 알림 규칙

### 5.1 전송

```python
requests.post(f"{settings.NTFY_SERVER}/{topic}",
              data=msg.encode("utf-8"),
              headers={"Title": title, "Priority": prio, "Tags": tags},
              timeout=5)          # 짧게. 실패는 로그만.
```

- 토픽/토큰은 `.env` (`NTFY_TOPIC`, `NTFY_TOKEN`). 코드/로그에 노출 금지.
- 카카오 같은 OAuth·토큰 갱신 로직 없음. 만들지 말 것.

### 5.2 하트비트 필수

매일 `HEARTBEAT_HOUR`(09시)에 생존 신호 1회 발송.
**알림이 안 오는 것 자체가 장애 신호가 되어야 한다.**

### 5.3 알림 실패가 매매를 막지 않는다

`notifier` 예외는 삼키고 로그만 남긴다. 손절/청산은 알림과 무관하게 집행.

## 6. 수수료 감시 규칙

```python
실효_수수료율 = 지불_수수료 / 체결금액     # 체결 내역에서 역산

if 실효_수수료율 > settings.FEE_ALERT_ABOVE:   # 0.0005
    notify("수수료 쿠폰 만료 의심")
    신규_진입_중단()                            # 청산 로직은 계속 동작
```

쿠폰은 무료지만 **30일마다 만료**된다. 사람의 기억에 의존하지 않는다.

## 7. 차트 패턴 규칙

- 차트 패턴은 **결정론적 코드**다. **M2(스크리닝)**에 넣는다. M5가 아니다.
- **엔진 A**(추세선 2개 회귀) / **엔진 B**(스윙 시퀀스) 두 개로만 구현한다.
  패턴마다 별도 함수를 20개 만들지 않는다.
- **M2-a: 하락형 회피 필터로만 시작한다.** (③⑤⑦⑨⑪⑭)
  틀린 회피는 기회비용이지만, 틀린 진입은 실손실이다.
- **M2-b: 상승형은 가산 가중치.** **단독 진입 신호로 쓰지 않는다.**
- ⑯컵앤핸들 ⑰역컵앤핸들 ⑲원형바닥 ⑳다이아몬드 는 **보류.** (검증 기간에 사례가 안 잡힘)
- **패턴 탐지 결과는 반드시 차트 PNG로 저장한다.** 육안 검증 없이 튜닝하지 않는다.
- 백테스트는 **튜닝 기간 / 홀드아웃 기간을 분리**한다. 홀드아웃은 **한 번만** 돌린다.
