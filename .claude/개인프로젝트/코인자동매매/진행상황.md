# 진행상황 / 인수인계 문서

> **용도:** 일일 사용량 소진 등으로 다른 환경(다른 PC, 다른 세션, 다른 AI 도구)에서
> 이어서 작업할 때, 이 문서 하나만 읽으면 맥락이 복원되도록 만든 파일이다.
>
> **최종 갱신:** 2026-08-30 (M5 공지감시 + 뉴스필터 + ntfy 완료)

## 0. 다른 곳에서 이어서 시작하는 방법

새 세션에 아래 3개 파일을 넣고 시작하면 된다.

| 파일 | 역할 |
|---|---|
| `계획서.md` | 전체 설계 (무엇을 왜 이렇게 만드는가) |
| `CLAUDE.md` | 작업 규칙 (하지 말아야 할 것) |
| `진행상황.md` | 지금 어디까지 왔고 다음에 뭘 하는가 (이 문서) |

**새 세션 첫 프롬프트 예시:**

> 첨부한 `계획서.md`, `CLAUDE.md`, `진행상황.md` 를 읽어줘.
> 빗썸 코인 자동매매 프로젝트를 이어서 진행할 거다.
> 진행상황.md 의 "다음 작업" 부터 시작해줘.

## 2. 현재 상태

| 항목 | 상태 |
|---|---|
| 계획 수립 | **완료** |
| 문서화 | **완료** (본 문서 3종) |
| 코드 구현 | **M1 + M3-a + M2-a + M2-b + M4 + M5 완료.** M1 인증부만 사용자 키 대기 |

**작성 완료 파일** (프로젝트 루트 = 이 문서 폴더):

```
setup.bat  run_m1  run_backtest  run_m2a  run_m2b  run_m4  run_m5  (.bat, 전부 CRLF)
config/settings.py                # 상수 (M1 + 백테스터 + 패턴 + 스크리너 + 포트폴리오)
src/bithumb_client.py             # M1: 공개/인증 조회 + probe_readonly()
src/candles.py                    # M3-a: 캔들 로더 + CSV 캐시 + align()
src/fills.py                      # M3-a: 캔들 기반 체결 (시장/지정/손절/갭)
src/backtest.py                   # M3-a: 단일종목 백테스터 (룩어헤드 방지)
src/metrics.py                    # M3-a: 수익률/MDD/실효수수료율/노출/승률
src/patterns/engine_a.py         # M2-a: 추세선 2개 회귀 12패턴. is_bearish/is_bullish/pattern_score
src/patterns/debug_chart.py      # M2-a: 탐지 PNG (맑은고딕)
src/screener.py                  # M2-b+M4: 유동성 + base_score(모멘텀/이평/RSI) + 패턴 combine
src/risk.py                      # M4: 모드 프로파일, 사이징, 손절/추적/익절, 일일한도, 최소주문검증, 수수료감시
src/portfolio_backtest.py        # M4: 다코인·동시보유2 백테스터 (+ M5 liquidate_provider 훅)
src/notice.py                    # M5: 빗썸 공지/경보 → 청산/진입금지 마켓 (결정론적)
src/news.py                      # M5: RSS 키워드 필터 (LLM 없음, strong=제목매칭 청산 / weak=보류)
src/notifier.py                  # M5: ntfy POST (실패해도 매매 안 막음) + alert/heartbeat
src/run_backtest.py run_m2a run_m2b run_m4 run_m5      # 각 마일스톤 데모/실측
tests/test_m1,m3a,m2a,m2b,m4a,m4b,m5.py                # 점검 (pytest 불필요)
```

**M1 검증:** [1] 조회 성공, [4] .env 없으면 RuntimeError. **대기:** [2][3][5] → 사용자 키 필요.
**M3-a 검증:** `test_m3a` 8개 통과. BTC 튜닝기간 MA10/30: +143%, MDD -17.75%, 실효수수료 0.0400%.
**M2-a 검증:** `test_m2a` 7개 통과. 엔진은 전 기간 봉의 약 15~30%에서 패턴을 잡는다.
**M2-b 검증:** `test_m2b` 4개 통과. `run_m2b` 진입규칙 비교 (튜닝, 5코인 평균):

| 규칙 | 내용 | 수익률 | MDD | 거래 |
|---|---|---|---|---|
| A 무필터 | 크로스업이면 매수 | +265.7% | -29.7% | 45 |
| B 하락회피 | + not is_bearish | +265.7% | -29.7% | 45 |
| C 약가중치 | + combine≥0.45 | +265.7% | -29.7% | 45 |
| D 상승확인 | + combine≥0.60 (상승형 패턴 필수) | **+81.5%** | -25.3% | 11 |

**B·C 효과 0, D 는 교환비 나쁨** → 하드 게이트 비활성.

**M4 검증:** `test_m4a`(8) + `test_m4b`(4) 통과. `run_m4` 포트폴리오 백테스트 (튜닝, 8코인):

| 모드 | 패턴 | 수익률 | MDD | 거래 | 청산 |
|---|---|---|---|---|---|
| conservative | 없음 | +94.1% | **-9.0%** | 102 | stop 76, TP 26 |
| conservative | 하락veto | +89.6% | -12.0% | 98 | stop 74, TP 24 |
| conservative | 가중치 | +91.1% | -11.8% | 102 | stop 76, TP 26 |
| aggressive | 없음 | +128.5% | -21.9% | 65 | stop 49, TP 16 |
| aggressive | 하락veto | +132.8% | -19.7% | 64 | stop 48, TP 16 |

**결론:**
1. **리스크 규칙 정상 작동** — 손절·익절 청산이 골고루, conservative MDD -9% (목표 10% 이내 ✓), aggressive 보다 낮음 ✓.
2. **패턴 필터는 진짜 진입 로직 위에서도 중립~약간 손해.** (M2-a·M2-b 결과와 일치)
   → **패턴은 게이트로 채택하지 않는다.** 엔진은 라벨링 신호로만 유지 (`PATTERN_SCORE_WEIGHT=0.20` 소프트).
3. **손절률 75% (102건 중 76건)** — 데모 스크리너 + 고정 -7% 손절이 너무 예민.
   스크리너 지표/손절폭 튜닝은 M6 페이퍼 전에 홀드아웃으로.

**M5 검증:** `test_m5` 6개 통과 + `run_m5` 실 API 확인:
- 빗썸 공지: `거래유의`/`거래지원종료` → 즉시 청산 마켓, `입출금`/`마켓추가` + `virtual_asset_warning`(WARNING↑) → 진입금지 마켓. 실행 시점에 ICX/SNX 청산 대상으로 잡힘.
- 뉴스 RSS(Cointelegraph/CoinDesk/TheBlock): 청산은 **제목에 정식명칭+청산키워드** 동시일 때만(파괴적 행동 보수적), 보류는 제목+요약 아무 별칭+키워드. 짧은 티커는 단어경계 매칭(‘Canada’의 ada 오탐 차단).
- `portfolio_backtest` 에 `liquidate_provider` 훅 추가 → 유의종목 즉시 청산 동작 테스트 통과.
- `notifier`: `NTFY_TOPIC` 미설정이면 조용히 False, 발송 실패해도 예외 안 냄.

### 실행

```
run_backtest.bat  run_m2a.bat  run_m2b.bat  run_m4.bat   [--holdout]
run_m5.bat  [--ntfy]     # 빗썸 공지/경보 + 뉴스 RSS 실조회. --ntfy 면 테스트 알림 1건
```
홀드아웃은 1회만. `data/.holdout_used` 에 기록됨.

### 실행 방법 (Windows)

```
setup.bat               # 최초 1회: venv + 의존성 + .env 생성
run_m1.bat              # 공개 조회만 (키 불필요)
run_m1.bat --private    # .env 채운 뒤: 잔고 + 권한 검증
```

`.bat` 은 CRLF 라인엔딩이어야 한다 (LF 면 cmd 가 파싱 실패). 수정 시 주의.

## 3. 확정된 의사결정 (재논의 불필요)

이미 검토를 마친 항목들이다. 새 세션에서 다시 논의하지 말 것.

| 항목 | 결정 | 근거 |

### 3.6 마일스톤 순서 (계획서 표와 다름 — 이쪽이 맞음)

계획서 9장은 M2 → M3 순서지만, **M2-a 패턴 필터를 튜닝하려면 측정 도구(백테스터)가
먼저 필요**하다. 실제 진행 순서:

```
M1 ✅ → M3-a ✅ → M2-a ✅ → M2-b ✅ → M4 ✅ → M5 ✅ → M5.5 → M6-a → M6-b → M7   (M3-b 보류)

  (M3-b 를 M4 뒤로: 진짜 진입 로직이 있어야 엔진 B 패턴도 의미 있게 검증됨)
```

M4·M5(공지 감시)는 M3-a 이후 어디든 병렬 가능. M1은 전부의 하드 전제.

## 5. 다음 작업

### 5.1 M1 마무리 — 사용자가 직접 해야 할 일

1. **빗썸 API 키 발급 — 반드시 "조회 전용" 권한으로.**
   - 마이페이지 → API 관리 → **주문 권한 체크하지 말 것**
   - `.claude/개인프로젝트/코인자동매매/.env.example` 을 `.env` 로 복사, Key/Secret 채우기
2. `cd .claude/개인프로젝트/코인자동매매 && .venv/Scripts/python -m tests.test_m1 --private` 실행
   - `[3] OK — 조회 전용 키 확인됨` 이 나오면 M1 완료
   - `[3] FAIL` 이면 그 키는 주문 가능 → 폐기하고 조회 전용으로 재발급
