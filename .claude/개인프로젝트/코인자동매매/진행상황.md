## 0. 다른 곳에서 이어서 시작하는 방법

새 세션에 아래 3개 파일을 넣고 시작하면 된다.

| 파일 | 역할 |
|---|---|
| `계획서.md` | 전체 설계 (무엇을 왜 이렇게 만드는가) |
| `CLAUDE.md` | 작업 규칙 (하지 말아야 할 것) |
| `진행상황.md` | 지금 어디까지 왔고 다음에 뭘 하는가 (이 문서) |

**새 세션 첫 프롬프트 예시:**

> 첨부한 `계획서.md`, `CLAUDE.md`, `진행상황.md` 를 읽어줘.
> 빗썸 코인 자동매매 프로젝트를 이어서 진행할 거다.
> 진행상황.md 의 "다음 작업" 부터 시작해줘.

## 2. 현재 상태

| 항목 | 상태 |
|---|---|
| 계획 수립 | **완료** |
| 문서화 | **완료** (본 문서 3종) |
| 코드 구현 | **M1 + M3-a + M2-a + M2-b 완료.** M1 인증부만 사용자 키 대기 |
| 현재 마일스톤 | **M2-b 완료 → 다음 M4** (M3-b 엔진 B 는 M4 뒤로 미룸, 아래 참고) |

**작성 완료 파일** (프로젝트 루트 = 이 문서 폴더):

```
setup.bat  run_m1.bat  run_backtest.bat  run_m2a.bat   # Windows 실행 (전부 CRLF)
config/settings.py                     # 상수 (M1 + 백테스터 + 패턴 엔진)
src/bithumb_client.py                  # M1: 공개/인증 조회 + probe_readonly()
src/candles.py                         # M3-a: 캔들 로더 + CSV 캐시
src/fills.py                           # M3-a: 캔들 기반 체결 (시장/지정/손절/갭)
src/backtest.py                        # M3-a: 백테스터 (룩어헤드 방지, 다음봉 체결)
src/metrics.py                         # M3-a: 수익률/MDD/실효수수료율/노출/승률
src/run_backtest.py                    # M3-a: MA크로스 데모 + 홀드아웃 가드
src/patterns/engine_a.py              # M2-a: 추세선 2개 회귀 → 12패턴. is_bearish/is_bullish/pattern_score
src/patterns/debug_chart.py          # M2-a: 탐지 결과 PNG (맑은고딕)
src/run_m2a.py                        # M2-a: 하락형 필터 A/B + 탐지 빈도 스캔
src/screener.py                       # M2-b: combine(base_score, det) — 패턴을 가산 가중치로
src/run_m2b.py                        # M2-b: 진입규칙 A/B/C/D 비교
tests/test_m1,m3a,m2a,m2b.py         # 점검 스크립트 (pytest 불필요)
```

**M1 검증:** [1] 조회 성공, [4] .env 없으면 RuntimeError. **대기:** [2][3][5] → 사용자 키 필요.
**M3-a 검증:** `test_m3a` 8개 통과. BTC 튜닝기간 MA10/30: +143%, MDD -17.75%, 실효수수료 0.0400%.
**M2-a 검증:** `test_m2a` 7개 통과. 엔진은 전 기간 봉의 약 15~30%에서 패턴을 잡는다.
**M2-b 검증:** `test_m2b` 4개 통과. `run_m2b` 진입규칙 비교 (튜닝, 5코인 평균):

| 규칙 | 내용 | 수익률 | MDD | 거래 |
|---|---|---|---|---|
| A 무필터 | 크로스업이면 매수 | +265.7% | -29.7% | 45 |
| B 하락회피 | + not is_bearish | +265.7% | -29.7% | 45 |
| C 약가중치 | + combine≥0.45 | +265.7% | -29.7% | 45 |
| D 상승확인 | + combine≥0.60 (상승형 패턴 필수) | **+81.5%** | -25.3% | 11 |

**B·C 효과 0** (하락형이 크로스업 시점과 안 겹침). **D 는 거래 76%↓ MDD 4.4%p↓ 지만 수익 184%p 버림** — 교환비 나쁨.
→ `screener.combine()` + `PATTERN_SCORE_WEIGHT=0.20`(사실상 무해) 은 유지, **D 식 하드 게이트는 기본 비활성.**
실제 가중치 보정은 M4 스크리너 + 홀드아웃에서.

### 실행

```
run_backtest.bat  [--holdout]     # 백테스터 데모
run_m2a.bat       [--holdout]     # 하락형 필터 A/B + 탐지빈도 + 차트
run_m2b.bat       [--holdout]     # 진입규칙 A/B/C/D 비교
```
홀드아웃은 1회만. `data/.holdout_used` 에 기록됨.

### 실행 방법 (Windows)

```
setup.bat               # 최초 1회: venv + 의존성 + .env 생성
run_m1.bat              # 공개 조회만 (키 불필요)
run_m1.bat --private    # .env 채운 뒤: 잔고 + 권한 검증
```

`.bat` 은 CRLF 라인엔딩이어야 한다 (LF 면 cmd 가 파싱 실패). 수정 시 주의.

### 3.6 마일스톤 순서 (계획서 표와 다름 — 이쪽이 맞음)

계획서 9장은 M2 → M3 순서지만, **M2-a 패턴 필터를 튜닝하려면 측정 도구(백테스터)가
먼저 필요**하다. 실제 진행 순서:

```
M1 ✅ → M3-a ✅ → M2-a ✅ → M2-b ✅ → M4 → M3-b(엔진 B) → M5 → M5.5 → M6-a → M6-b → M7

  (M3-b 를 M4 뒤로: 진짜 진입 로직이 있어야 엔진 B 패턴도 의미 있게 검증됨)
```

M4·M5(공지 감시)는 M3-a 이후 어디든 병렬 가능. M1은 전부의 하드 전제.

**결론**: 소프트 가산(C)은 효과 0, 하드 게이트(D)는 이 표본에서 교환비 나쁨(수익 -184%p / MDD -4.4%p).
→ 메커니즘만 남기고 **하드 게이트 비활성.** M4 에서 진짜 스크리너 위에 얹어 홀드아웃으로 보정.

### 5.5 그 다음: M4 (리스크/자금관리) — 여기서 패턴도 실측정

- `src/risk.py`: 모드 프로파일(conservative/aggressive), 손절/추적손절/일일손실한도, **최소주문 5,000원 검증**,
  실효 수수료율 감시(`FEE_ALERT_ABOVE`)
- `src/screener.py` 확장: 유동성 필터(24h 거래대금) + 기술적 base_score + 패턴 `combine`
- **이때 M2-a/M2-b 필터·가중치를 진짜 진입 로직 위에서 A/B 재측정** → 채택/기각 결정
- M3-b(엔진 B) 는 M4 뒤로. 진짜 진입 로직이 있어야 엔진 B 도 의미 있게 검증됨
- 모델: Sonnet 으로 가능. 손절/자금관리 규칙은 짧지만 틀리면 손실 → 테스트 촘촘히
