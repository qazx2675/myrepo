# license_assign-source

물리 호스트(BM) 목록 중 **평가판(eval) 라이선스 상태인 호스트**를 찾아내고, vCenter에
등록된 라이선스 중 하나를 대화형으로 선택해 **실제로 할당(assign)** 하는 도구입니다.

> ⚠️ **이 도구는 실제로 호스트의 라이선스 할당을 변경(write)합니다.**
> 또한 **대화형(interactive) 도구**라서 표준입력(stdin)으로 라이선스 번호를 직접
> 입력해야 하며, 사람이 지켜보지 않는 자동화 파이프라인/크론에 그대로 넣으면 프롬프트
> 대기 상태로 멈춥니다.

## 1. 빌드 방법

`vendor/`를 포함하고 있어 폐쇄망에서도 오프라인 빌드가 됩니다(`license` 패키지 포함).

```bash
cd "myrepo/.claude/VM 업무/레거시 vm-param-fix (외부 도구 오케스트레이션)/license_assign-source"
bash setup.sh
# 빌드 완료: .../license_assign-source/license_assign
```

## 2. 사용 방법

### 준비물

- 환경변수 `VC_PASSWORD`: vCenter 로그인 비밀번호 (필수)
- `worklist.txt` (기본 파일명, `-worklistFile`로 변경 가능): 대상 물리 호스트(BM) 이름을
  한 줄에 하나씩. `#` 주석/빈 줄 무시.

### 실행 예시

```bash
export VC_PASSWORD='실제_비밀번호'

./license_assign \
  -vcTargetIP=192.168.0.50 \
  -id=administrator@vsphere.local \
  -worklistFile=worklist.txt
```

## 3. 옵션 상세 설명

| 플래그 | 기본값 | 필수 | 설명 |
|---|---|---|---|
| `-vcTargetIP` | (없음) | ✅ | vCenter 접속 IP. |
| `-id` | `lscsystems@vsphere.local` | | vCenter 로그인 계정 ID. |
| `-worklistFile` | `worklist.txt` | | 대상 물리 호스트(BM) 목록 파일. |

## 4. 동작 순서

1. `VC_PASSWORD` 로드, `worklist.txt` 읽기, vCenter 접속 후 License Manager /
   License Assignment Manager 초기화.
2. `ContainerView`로 vCenter 전체 `HostSystem`(이름 + CPU 코어 수)을 1회 조회.
3. `worklist.txt`의 각 줄을 호스트 인벤토리와 매칭(짧은 이름 대소문자 무시 비교
   또는 완전 일치)해서 대상 호스트 목록 확정.
4. **[1단계: 점검]** 대상 호스트마다 `assignmentMgr.QueryAssigned()`로 현재 할당된
   라이선스를 조회:
   - 라이선스 키가 `00000-00000-00000-00000-00000`(평가판 자리표시자)이거나,
     Edition Key에 `eval`이 포함되어 있으면(대소문자 무시) **평가판으로 판정**하고
     작업 대상에 추가(필요 코어 수 누적).
   - 그 외(정식 키가 붙어 있고 `eval`이 아님)에는 스킵 처리.
   - 점검 결과 요약(총 호스트 수 / 스킵 수 / 작업 대상 수 / 필요 총 코어 수) 출력.
   - 평가판 호스트가 하나도 없으면 여기서 정상 종료(코드 0).
5. **[2단계: 대화형 할당 루프]** 평가판 호스트가 남아있는 동안 반복:
   1. vCenter에 실시간으로 등록된 라이선스 전체 목록을 표(Index/제품명/키/총량/
      사용중/잔여)로 출력.
   2. 남은 대상 호스트 수와 필요 코어 수를 보여주고, **라이선스 Index 번호 입력**을
      요청(`q` 입력 시 작업 중단하고 종료).
   3. 선택한 라이선스의 잔여 코어(`Total - Used`)가 허용하는 한, 대상 호스트를
      순서대로 `assignmentMgr.Update()`로 실제 할당(코어 소모량만큼 잔여량 차감).
   4. 잔여량이 부족해 못 받은 호스트는 다음 라운드로 이월되고, 다시 1번부터 반복해서
      **다른 라이선스**를 추가로 선택하도록 안내.
6. 모든 대상 호스트가 처리되면 완료 메시지 출력.

## 5. 알려진 한계

- 완전한 대화형 도구입니다 — 라이선스 선택을 사람이 매 라운드 직접 입력해야 하며,
  비대화형(무인) 실행을 지원하지 않습니다.
- 평가판 판정 기준이 "라이선스 키가 평가판 자리표시자이거나 Edition Key에 eval 포함"
  으로 고정되어 있어, 이 두 조건에 해당하지 않는 다른 형태의 미할당/만료 라이선스는
  정식으로 오판될 수 있습니다.
- 한 라이선스로 감당 가능한 호스트부터 순서대로(목록 순서) 소모하는 단순 방식이라,
  코어 낭비를 최소화하는 최적 배분(예: 빈 패킹)은 하지 않습니다.
- 호스트 매칭이 이름 기준(짧은 이름 대소문자 무시 또는 완전 일치)이라, 동일 짧은
  이름을 가진 호스트가 여러 개면 모두 대상에 중복 포함될 수 있습니다.
