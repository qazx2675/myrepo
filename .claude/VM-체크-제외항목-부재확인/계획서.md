# 체크 스크립트 개선 계획서 (확정): 제외 항목은 "정말 제외됐는지" 검사

## 문제와 목표
- `-del_lpage`/`-del_affinity` 로 지운 VM 도 체크가 값을 기대해 [설정없음]/FAIL 이 나온다.
- 제외 옵션을 준 항목은 값이 **없어야** OK, 남아 있으면 FAIL. 나머지 항목은 기존과 동일. `vm_setup.sh` 체크 단계와 단독 체크 스크립트 모두 동작.

## 결정
- `-expectNoLpage`: HugePage 4개 키(`sched.mem.lpage.enable1GPage`, `sched.mem.prealloc`, `sched.mem.prealloc.pinnedMainMem`, `sched.swap.vmxSwapEnabled`)가 없거나 빈 값이면 OK. `sched.mem.pin` 은 지금처럼 체크 안 함.
- `-expectNoAffinity`: affinity 키가 하나도 없으면 OK, 남은 키는 FAIL. 스펙의 affinity 기대값은 비교하지 않고 나머지 설정만 평소대로 체크. 두 옵션은 따로/함께 사용 가능.
- "삭제됨" = 키 없음 또는 빈 문자열.
- `-fix` 는 이 FAIL 을 되살리지 않고 수동 조치로만 표시.
- 전달: `vm_setup.sh` 가 옵션과 `run_<user>/check_del_*` 표시 파일을 남기고, 단독 스크립트가 표시 파일을 읽는다. 옵션 없으면 기존 동작.

## 검증 기준
- 옵션 없이 기존 결과 동일, 단위 테스트 통과.
- vcsim: 값이 남은 VM 에 옵션 → FAIL, 삭제 후 → OK, `vm_setup.sh` 체크 단계 정상.
