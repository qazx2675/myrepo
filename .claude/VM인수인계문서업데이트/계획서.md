## 0. Claude Code 지시문 (이 블록을 그대로 따를 것)

```
첨부한 VM_인수인계_핸드북.html 은 기존 인수인계 문서의 배포본이고,
원본 .md 들은 저장소의 .claude/VM/인수인계/ 에 있다.
이 계획서대로 문서 세트를 최신 저장소 기준으로 다시 만들어라.

1. git pull 로 qazx2675/myrepo 최신 상태를 받는다.
2. 작업 전에 이 계획서의 "2. 대상 폴더"에 있는 폴더를 전부 읽는다.
   README.md → 계획서.md/PLAN.md → CHANGELOG.md → main.go(및 cmd/*/main.go)의 flag 정의
   → run.sh / setup.sh 순서.
3. 옵션표는 반드시 소스의 flag 정의(및 run.sh 의 case 분기) 기준으로 쓴다.
   README 와 다르면 소스를 따르고, 차이는 "5. 소스–README 불일치 목록"에 기록한다.
4. 작업 계획(대상 파일 목록, 삭제·신규 문서 목록)을 먼저 보여주고 승인 후 작성한다.
5. 완료 후 python3 build_handbook.py 로 HTML 을 다시 생성하고 커밋·푸시한다.
6. 작업 기록은 .claude/VM인수인계문서업데이트/ 폴더에 계획서.md, 작업기록.md 로 남긴다.
```

## 3. 문서 작성 규칙

### 3-1. 사용법은 "실제로 쓰는 명령어"가 맨 위

모든 도구 문서의 첫 절은 **"바로 쓰는 명령어"** 로 한다.

- 실무에서 실제로 치는 명령을 **사용 빈도 순서**로 나열한다.
- 각 명령 위에 한 줄로 "언제 쓰는지"만 적는다.
- 복사해서 값만 바꾸면 되게, 바꿀 부분은 `<vCenter IP>` 처럼 꺾쇠로 표시한다.
- 인증 설정(비밀번호 환경변수)도 이 블록 안에 포함한다.

형식 예:

```markdown
## 바로 쓰는 명령어

# 1) 인증 (세션마다 1회)
export VC_USER='<계정>'
read -rsp 'vCenter 비밀번호: ' VC_PASS; export VC_PASS; echo

# 2) 설정 점검 — 정기 점검 시
./vm-param-check -vcenterList=vcenter.txt -f=targets.txt -specRoot=./SPEC_DIR -out=result.csv

# 3) 점검 후 틀린 항목 교정 — VM 전원 OFF 상태에서
./vm-param-check -vcenterList=vcenter.txt -f=targets.txt -specRoot=./SPEC_DIR -out=result.csv -fix
```

### 3-2. 문서 순서 (도구 문서 공통 템플릿)

1. 한눈에 보기 (위험도 🟢/🔴, 하는 일, 폴더, 바이너리)
2. **바로 쓰는 명령어** (위 3-1)
3. 흐름도 (3-3)
4. 준비물 (입력 파일 형식, 권한)
5. 옵션 상세표 (플래그 / 기본값 / 필수 / 설명) — 자주 쓰는 옵션이 위
6. 결과 확인 방법 (출력·CSV·종료코드 읽는 법)
7. 자주 나는 오류와 해결
8. 주의사항과 한계
9. 파일 구조

### 3-3. 흐름도

- **전체 작업 흐름도 1개**: 신규 서버 구축부터 네트워크 변경까지 도구 간 순서
  (예: 호스트 등록 → VM 생성 → MAC 검증(vm_verifier) → 설정 적용(V2) → 설정 점검·교정(vm-param-check) → 네트워크 변경(Network_Change_Integration_Script) → vCenter IP 변경)
  실제 순서는 소스와 README를 보고 확정한다.
- **도구별 흐름도**: 각 도구 문서의 3절. 입력 → 처리 단계 → 확인 프롬프트 → 결과/롤백 분기까지.
- 표기는 Mermaid(```mermaid 코드블록)로 작성한다.
  `build_handbook.py`가 Mermaid를 렌더하도록 수정하되, **폐쇄망에서 열려야 하므로 mermaid.min.js 를 HTML 안에 인라인으로 포함**한다(CDN 금지).
  인라인이 어렵다면 흐름도를 SVG로 미리 렌더해 HTML에 넣는다.

### 3-4. 빼야 할 것

- **테스트 방법 전부**: `-demo`, `-scale`, `-scaleMismatch`, vcsim, `go test`, testkit, real_test.sh/scale_test.sh, "검증 이력" 절
- **표현**: "초보", "처음 보는", "처음 접하는", "처음 오셨다면" 같은 단어와 문장
- 제외 대상 폴더의 상세 설명

### 3-5. 유지할 것

- 🟢/🔴 위험도 표기
- 비밀번호는 환경변수로만 받는 안내
- 설정 변경 후 표본 확인 권고 (한 줄로 간결하게)
- 옵션표는 소스 기준
- 유지보수 AI 가이드와 변경요청서 양식(30/31번). 단 대상 경로를 새 폴더 구성에 맞게 갱신하고, 제외 폴더용 양식은 삭제
