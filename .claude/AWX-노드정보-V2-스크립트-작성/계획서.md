## 1. 목표 및 범위

- 새 스크립트 `01.AWX_nodeinfo_V2.sh` 작성 (HPC 서버 등록 전처리 → yaml 생성 → 배포 → 인벤토리/DHCP/PXE 등록 진입)

## 3. 원 요구사항 정리 (사용자 원문 요약 — 새 세션은 이 절을 기준으로 함)

1. `user(){}` 빈 함수, 변수명 `user`
2. user 별 실행 로그 (`./LOG`)
3. 아래 함수 포함 (원문)
   ```bash
   inventory_delete(){
   	inventory_delete_host=""
   	ssh $inventory_delete_host "bash /root/server/delhost_${user}
   }   # user 선택 후 진행되어야 하는 함수  ← 닫는 따옴표 누락 → 보정 필요
   download_txt(){
   read -p " awx nodeinfo 사용여부 Y|N : " awx_yn
   	if [y 이면]
   		bash awxkit/nodeinfo.sh -user ${user}
   		cat awxkit/output/${user}_nodinfo.yaml > ${user}.txt
   	fi
   	sed -i 's/1.1T/1200/g' ${user}.txt
   	sed -i 's/7T/7600/g' ${user}.txt
   	sed -i 's/test1234/offchip/g' ${user}.txt
   }
   ```
4. 등록 대상 출력: **세로로 20개씩**, 20줄이 차면 공백으로 구분해 오른쪽 열에 이어서 (1행: 1번째, 21번째, 41번째 …)
5. `${user}.txt` 에 `msg` 가 있으면 `"msg": "…"` 의 값만 남기도록 **모든 줄** 변환
   - 필드(1-base, 공백 구분): `$1 vendor(dell) $2 model(r660) $3 infra $4 hostname $5 ip $6 mac $7 nic $8 disk[sda|nvme0n1] $9 part[sda5|nvme0n1p8] $10 disk용량 $11 os버전 $12 boot[uefi|레거시]`
   - 기존: `cat ${user}.txt | grep msg | awk -F'"' '{print $4}' > ${user}.txt` → **같은 파일을 읽으며 `>` 로 비우므로 결과가 빈 파일이 되는 버그**. 대체안 §5-3
   - 5-1. hostname 이 `spice|pice|dspr|pspr` 이고 `ev` 를 포함하지 않으면, mac 마지막 자리가 홀수 → 짝수 (`…:01` → `…:00`). 그 외 호스트는 변경 없음
   - 5-2. `infra + nic + disk + disk용량 + os버전 + boot` 조합으로 그룹을 나눠 **그룹별 yaml 파일** 생성 (awxkit 작업 등록 단위)
   - 5-3. 5-2 완료 후 **전체 정보 yaml 1개** 추가 생성
6. 생성 yaml 전체를 `scp` → `$repohost:/root/Inventory/`, 파일별로 `ssh $repohost "bash /root/Inventory/custom_inventory.sh /root/Inventory/$i"`. yaml 은 `svr_dir` 에 저장, 메뉴 `ls` 시 `파일명.yaml [boot]` 형태 출력
7. git 업로드 — **원문 그대로 사용**
   ```bash
   now_pwd=`pwd`
   for x in `echo $yaml`
   do
   	cd /root/user/${user}/myrepo
   	cp $svr_idr/$x /root/user/${user}/myrepo/$x
   	bash .git_upload.sh ${user} $x
   done
   ```
8. DHCP 삭제 정보 기록: `./dhcp_pool/dhcp_pool_delete_info.txt` 에 `tmp tmp SEC $4 $5 $6 eth0 sda sda5 960 7.9` 형식
9. 점검 단계
   - `ai_server_list=""` (`|` 구분 호스트명) 에 해당하는 호스트가 있으면 "AI GPU서버는 power limit설정이 필요합니다. cat .power_limit_setting.txt를 참고하세요." 출력 후 `cat .power_limit_setting.txt`
   - `gossh -script -w [호스트명만 있는 파일] "bash $ldap_check_script;cat /proc/net/bonding/bond0 |grep -i mod" > tmp/all_${user}`
   - LACP 사용 호스트가 있으면 `$lacp_comment` 출력, LDAP 정보가 전부 같으면 `모든 호스트의 LDAP이 xx으로 동일함` 한 줄 요약
10. 메뉴 `while true` — 프롬프트 `AWX 인벤토리 소스 : su exit : 종료 ls : yaml 파일출력`
    - `su` → 루프 탈출, `exit` → 종료, `ls` → 생성 yaml 목록, `yaml 파일명` → `cat $svr_dir/<파일>`
    - 탈출 후:
      ```bash
      for ((;;)); do
      	echo "작업 리스트"
      	호스트이름이 | 로 가로 나열
      	bash 02.source_dhcp_pxe.sh ${user}
      done
      ```
11. `02.source_dhcp_pxe.sh` 현재 내용 (원문)

## 5. 단계별 구현 설계

### 5-1. 최상단 변수
```bash
#!/bin/bash
# AWX nodeinfo V2 - HPC 서버 등록 전처리 및 인벤토리/DHCP/PXE 등록
repohost=""
svr_dir=""
ai_server_list=""            # 예: "host01|host02"
ldap_check_script=""
lacp_comment=""
inventory_delete_host=""     # 함수 안 빈 변수 → 최상단으로 이동(C2, Q8)
svr_idr="$svr_dir"           # 7번 git 블록 원문(svr_idr 오타)을 그대로 쓰기 위한 별칭 (Q9)
```
- 빈 값이면 해당 단계 시작 시 `[X] repohost 가 비어 있습니다` 로 종료 (설정 누락 가드).

### 5-2. user / 로그
```bash
user(){
	:
}
user
if [[ -z $user ]]; then
	read -p ".txt를 제외한 user 입력 : " user
fi
mkdir -p LOG
exec > >(tee -a "LOG/${user}.log") 2>&1
log(){ echo "[$(date '+%F %T')] $*"; }
log "===== 01.AWX_nodeinfo_V2.sh 시작 (user=${user}) ====="
```
- 주의: tee 경유 시 자식 프로그램의 stdout 이 TTY 가 아니게 됨 → gossh 진행률·색상 비활성(결과에는 무해).

### 5-3. msg 파싱 (임시파일 없이 in-place)
```bash
if grep -q 'msg' "${user}.txt"; then
	sed -i -n 's/^.*"msg"[[:space:]]*:[[:space:]]*"\([^"]*\)".*$/\1/p' "${user}.txt"
fi
```
- `-n …p` 로 msg 줄만 남기고 나머지(yaml 헤더 등)는 제거 → 기존 `grep|awk` 와 동일 결과, 파일 비우기 버그 없음.

### 5-4. MAC 짝수 보정 (5-1)
- 마지막 16진 **한 글자**만 보면 홀짝 판정 가능: `1 3 5 7 9 b d f` → 각각 `0 2 4 6 8 a c e` (대소문자 유지).
- gawk 전용 기능(`strtonum`, `-i inplace`) 사용 금지(RHEL 구버전 호환), 결과는 변수로 받아 덮어씀:
```bash
content=$(awk '
($4 ~ /^(spice|pice|dspr|pspr)/) && ($4 !~ /ev/) {
	c = substr($6, length($6), 1); i = index("13579bdfBDF", c)
	if (i) $6 = substr($6, 1, length($6)-1) substr("02468aceACE", i, 1)
}
{ print }' "${user}.txt") && printf '%s\n' "$content" > "${user}.txt"
```
  (계획 작성 시 샘플로 검증 완료: `spice01 …:01→…:00`, `dspr05 …:FF→…:FE`, `pspr02 …:0b→…:0a`, `spice01ev02`·`node01` 불변. §5-3 파싱·§5-5 다단 출력도 45대 샘플로 확인)
- 매칭 규칙(접두어 vs 포함)은 Q5.
- 테스트 케이스: `…:01→…:00`, `…:0b→…:0a`, `…:FF→…:FE`, `…:02` 불변, `spice01ev02` 불변, `node01` 불변.

### 5-5. 등록 대상 20개 단위 세로 다단 출력 (4)
```bash
awk '{print $4}' "${user}.txt" | awk '
{ a[NR]=$0; if (length($0)>w) w=length($0) }
END{
	rows = (NR<20 ? NR : 20); cols = int((NR+19)/20)
	for (r=1; r<=rows; r++) {
		line = ""
		for (c=0; c<cols; c++) { i = c*20 + r; if (i<=NR) line = line sprintf("%-" w "s ", a[i]) }
		sub(/ +$/, "", line); print line
	}
	print "총 " NR "대"
}'
```
- msg 가 없는(이미 가공된/호스트명만 있는) 경우 출력 대상 필드는 Q4.

### 5-6. yaml 분할 / 전체 (5-2, 5-3)
- 그룹 키: `$3_$7_$8_$10_$11_$12` (infra, nic, disk, 용량, os, boot). **part($9)는 키에서 제외**(원문 기준, Q10).
- 파일명(기본안): `${user}_${infra}_${nic}_${disk}_${size}_${os}_${boot}.yaml`, 전체: `${user}_all.yaml` (Q11).
- 생성 파일명 목록을 `yaml` 변수에 공백 구분으로 누적 → 7번 git 블록의 `for x in \`echo $yaml\`` 이 그대로 동작.
- **yaml 내부 포맷은 미확정(블로커)** — `custom_inventory.sh` / AWX 인벤토리 소스가 요구하는 형식 샘플 필요 (Q12).
- 같은 이름 파일이 `svr_dir` 에 이미 있으면 덮어씀(기본안).

### 5-7. DHCP 삭제 정보 (8)
```bash
mkdir -p dhcp_pool
awk '{print "tmp","tmp","SEC",$4,$5,$6,$7,$8,$9,$10,$11}' "${user}.txt" >> dhcp_pool/dhcp_pool_delete_info.txt
```
- 예시 `tmp tmp SEC $4 $5 $6 eth0 sda sda5 960 7.9` 의 뒤 5개를 `$7~$11`(nic disk part 용량 os)로 해석 (Q13). 누적(`>>`) vs 덮어쓰기(`>`)도 Q13.

### 5-8. scp / custom_inventory (6)
```bash
for i in $yaml; do scp "$svr_dir/$i" "$repohost:/root/Inventory/"; done   # 또는 한 번에 scp
for i in $yaml; do ssh "$repohost" "bash /root/Inventory/custom_inventory.sh /root/Inventory/$i"; done
```
- 실패 시 해당 파일명 로그 후 계속/중단 여부: 기본 **중단**(이후 git/등록이 잘못된 데이터로 진행되는 것 방지).

### 5-9. git 업로드 (7)
- 원문 블록을 **한 글자도 바꾸지 않고** 삽입. 블록 직후 `cd "$now_pwd"` 한 줄만 추가(원문은 `now_pwd` 를 저장만 하고 복귀하지 않아 이후 상대경로(`02.source_dhcp_pxe.sh`, `LOG`, `tmp`)가 깨짐) — Q9.

### 5-10. AI / LDAP / LACP 점검 (9)
```bash
hostfile=$(mktemp)                       # trap 으로 종료 시 삭제
awk '{print $4}' "${user}.txt" > "$hostfile"
if [[ -n $ai_server_list ]] && grep -Eqx "($ai_server_list)" "$hostfile"; then
	echo "AI GPU서버는 power limit설정이 필요합니다. cat .power_limit_setting.txt를 참고하세요."
	cat .power_limit_setting.txt
fi
mkdir -p tmp
gossh -script -w "$hostfile" "bash $ldap_check_script;cat /proc/net/bonding/bond0 |grep -i mod" > "tmp/all_${user}"
# LACP: "Bonding Mode: IEEE 802.3ad Dynamic link aggregation"
lacp_hosts=$(grep -i 'Bonding Mode' "tmp/all_${user}" | grep -i '802.3ad' | cut -d: -f1 | sort -u)
[[ -n $lacp_hosts ]] && { echo "$lacp_hosts"; echo "$lacp_comment"; }
# LDAP: Bonding Mode 줄 제외, "호스트: " 접두어 제거 후 고유값 개수
ldap_vals=$(grep -vi 'Bonding Mode' "tmp/all_${user}" | sed 's/^[^:]*: //' | sort -u)
if [[ $(printf '%s\n' "$ldap_vals" | grep -c .) -eq 1 ]]; then
	echo "모든 호스트의 LDAP이 ${ldap_vals}으로 동일함"
else
	grep -vi 'Bonding Mode' "tmp/all_${user}" | sort -t: -k2   # 값별로 호스트 나열
fi
```
- gossh 결과에 없는 호스트(접속불가) 는 `comm` 으로 찾아 "응답 없음" 별도 출력.
- `ai_server_list` 정확일치(`-x`) vs 부분일치 — Q15. `tmp/all_${user}` 보존 여부 — Q16.

### 5-11. 메뉴 (10)
```bash
while true; do
	read -p "AWX 인벤토리 소스 : su exit : 종료 ls : yaml 파일출력 : " sel
	case $sel in
		su)   break ;;
		exit) exit 0 ;;
		ls)   for i in $yaml; do echo "$i [$(boot_of "$i")]"; done ;;   # boot = 그룹키 $12
		"")   ;;
		*)    if [[ -f $svr_dir/$sel ]]; then cat "$svr_dir/$sel"; else echo "[!] $sel 없음"; fi ;;
	esac
done
```
- boot 값은 yaml 생성 시 `파일명→boot` 를 연관배열(`declare -A`)로 보관(파일 추가 생성 없음).

### 5-12. 02 실행 루프 + 02 변경 (10, 11)
- 01 쪽: 원문 `for ((;;))` 는 **종료 조건이 없어 02(등록)를 무한 반복**함 → 기본안: 02 성공 시 `break`, 실패 시 `재시도(Y|N)` 질문 (Q17).
- 작업 리스트: `paste -sd'|' "$hostfile"` 로 호스트명 `|` 가로 나열.
- 02 쪽 (기본안):
  ```bash
  user=$1; shift
  if [[ -z $user ]]; then read -p ".txt를 제외한 user 입력 : " user; fi
  yaml_list="$*"                                   # 01 이 인자로 넘김 (Q18)
  [[ -z $yaml_list ]] && 대화형 fallback (기존 방식 유지)
  for yaml in $yaml_list; do
  	infra/os/boot = 파일명(또는 yaml 내용)에서 추출
  	bash awxkit/invsync.sh -user ${user} -file $yaml           || 실패 기록
  	bash awxkit/dhcp.sh    -user ${user} -infra $infra         || 실패 기록
  	bash awxkit/pxe.sh     -user ${user} -infra $infra -os $os -boot $boot -splunk $splunk || 실패 기록
  done
  성공/실패 요약 출력, 실패 있으면 exit 1
  ```
  - 01 호출부는 `bash 02.source_dhcp_pxe.sh ${user} $yaml` 로 변경 (원문은 `${user}` 만 전달 — Q18).
  - 전체 yaml(`${user}_all.yaml`)은 등록 대상에서 제외(그룹 yaml 만 등록)가 기본안 (Q19).
  - nodeinfo 값 → awxkit 선택지 매핑(예: `레거시→legacy`, `7.9→?`), splunk 값 (Q20).

## 9. 검증 기준

1. `bash -n`, `shellcheck` 경고 0 (의도적 원문 블록 제외 표시)
2. **목업 E2E**: 스크래치 디렉터리에 `awxkit/{nodeinfo,invsync,dhcp,pxe}.sh` 스텁, PATH 에 `ssh/scp/gossh` 스텁(호출 인자 기록) → 샘플 msg 파일로 01 전체 실행
   - `${user}.txt` 가 12필드 줄로 변환, MAC 보정 케이스(§5-4) 전부 일치
   - 20/21/45대 입력 시 다단 출력 행·열 정확
   - 그룹 수 = 고유 키 수, 전체 yaml 1개, `yaml` 변수에 모두 포함
   - scp/ssh/git 스텁 호출 횟수 = yaml 수
   - LDAP 동일/상이/LACP 혼재/응답없음 4케이스 출력
   - 02 가 yaml 수만큼 invsync→dhcp→pxe 순서로 호출, 중간 실패 시 요약·종료코드 1
3. **잔여 파일 검사**: 실행 전후 `find . -newer <marker>` 결과가 허용 목록(`${user}.txt`, `svr_dir/*.yaml`, `LOG/${user}.log`, `dhcp_pool/…`, `tmp/all_${user}`)과 일치, `/tmp` 에 mktemp 잔여 없음 (Ctrl+C 중단 시에도)
