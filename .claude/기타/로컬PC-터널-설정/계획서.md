# 계획서 — 로컬PC 터널 설정

## 배경

클라우드 세션(Claude Code 원격 컨테이너)은 외부 인터넷(google.com 등)에는 접근 가능하지만,
사용자 LAN의 사설 IP(`192.168.0.58`, `192.168.0.50`, `192.168.0.60`)에는 라우팅 경로가 없어 접근할 수 없다
(실측: `curl http://192.168.0.58` → 프록시 403).

## 목표

로컬 PC에서 실행하는 PowerShell 스크립트 하나로 사설 IP의 HTTP(S) 서비스를 공인 HTTPS 주소로 노출하고,
그 주소를 클라우드 세션에서 사용할 수 있게 한다.

## 방식

| 항목 | Cloudflare Quick Tunnel (기본) | ngrok (선택) |
|---|---|---|
| 계정 | 불필요 | 무료 계정 authtoken 필요 |
| 주소 | `https://*.trycloudflare.com` (실행마다 변경) | `https://*.ngrok-free.app` 등 |
| 다중 대상 | 대상마다 cloudflared 프로세스 1개 | 설정파일 1개로 `start --all` |
| 제약 | HTTP(S)만 | 무료 플랜 엔드포인트 수 제한, 브라우저 경고 페이지 |

## 범위

- 포함: 바이너리 자동 다운로드, 대상 사전 연결 점검, 터널 시작/상태/중지, 결과 파일(`tunnels.txt`) 생성
- 제외: TCP 서비스(SSH/RDP/DB), 고정 도메인(Named Tunnel), 인증(Cloudflare Access) — 필요 시 별도 작업

## 산출물

- `Start-LocalTunnel.ps1` — 스크립트 (UTF-8 BOM, Windows PowerShell 5.1 / PowerShell 7 호환)
- `지침.md` — 로컬 세션이 따라 할 절차
- `.gitignore` — `tunnel-work/`(바이너리, 로그, ngrok 토큰) 커밋 방지

## 성공 기준

1. 스크립트가 PowerShell 파서 오류 없이 로드된다
2. 로컬 PC에서 실행 시 대상별 공인 주소가 `tunnels.txt`에 기록된다
3. 클라우드 세션에서 해당 주소로 HTTP 응답을 받는다
