# 작업기록 — 로컬PC 터널 설정

## 2026-09-25

### 확인 사항 (클라우드 세션)

- `https://www.google.com` → HTTP 200 (외부 인터넷 접근 가능)
- `http://192.168.0.58` → HTTP 403 (프록시에서 사설 IP 차단, 라우팅 경로도 없음)
- cloudflared / ngrok Windows 바이너리 다운로드 URL → HTTP 200
- 클라우드 → `*.trycloudflare.com` 도달 여부는 실제 터널 주소가 생긴 뒤 확인 필요 (미확인)

### 작업 내용

- `Start-LocalTunnel.ps1` 작성
  - `-Target`(여러 개), `-Provider cloudflare|ngrok`, `-NgrokAuthToken`, `-Status`, `-Stop`
  - 대상별 `Test-NetConnection` 사전 점검 후 접속 불가 대상 제외
  - 상태는 `tunnel-work\state.json`, 결과는 `tunnel-work\tunnels.txt`
  - 한글 깨짐 방지를 위해 UTF-8 BOM으로 저장 (Windows PowerShell 5.1 대응)
- `지침.md` 작성 (로컬 세션 절차, 제약, 문제 해결, 완료 기준)

### 검증 (Linux PowerShell 7.4.6)

- 파서 검사: `PARSE OK`
- `ConvertTo-TargetUri`: `192.168.0.58:80` / `https://192.168.0.60:443` / `192.168.0.50` 정상 변환, `ssh://` 거부
- 로그 공유 읽기 + trycloudflare 주소 정규식 추출 정상
- `-Status`, `-Stop` (기록 없음 상태) 정상
- 미검증: Windows에서의 실제 cloudflared/ngrok 실행 (로컬 세션에서 확인 필요)

### 다음 단계

1. 로컬 세션에서 `지침.md` 절차 수행 → `tunnels.txt` 내용을 클라우드 세션에 전달
2. 클라우드 세션에서 `curl`로 도달 확인 후 결과를 이 파일에 추가
