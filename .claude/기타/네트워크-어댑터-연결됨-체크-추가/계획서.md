# 네트워크 어댑터 "연결됨(Connected)" 체크 반영

작업일: 2026-09-15
브랜치: `claude/vm-network-adapter-check-jel6b2`

## 1. 문제

`VM/vm-network-migration` 을 실행하면 포트그룹 변경 자체는 정상 동작하지만,
vSphere 편집 설정 화면에서 네트워크 어댑터의 **"연결됨(Connected)"** 체크가
켜지지 않는다. ("전원을 켤 때 연결(StartConnected)" 만 켜진 상태)

## 2. 원인

### (1) 한 번의 Reconfigure 로 백킹 + 연결 상태를 같이 보냄

`internal/vsphere/nic.go` 의 `SetPortgroup` 은 `ReconfigVM_Task` 한 번으로
`card.Backing` 교체와 `card.Connectable.Connected = true` 를 같이 보낸다.
전원이 켜진 VM 에서 이렇게 하면 vCenter 가 **백킹만 반영하고 런타임 연결은
끊긴 채로 두는** 경우가 있다. 그 결과 `nm-verify` 가 `connected=false` 로
실패한다.

### (2) 재연결 대상 판정이 `orig_connected` 만 봄

`cmd/connect` 는 `rec.OrigConnected` 만 보고 재연결 여부를 정했다. 백업
(`nm-backup`) 당시 VM 전원이 꺼져 있었으면 `orig_connected` 는 **항상 false**
로 기록되므로, 그 사이 전원이 켜진 VM 은 재연결 대상에서 빠진다. 반면
`nm-verify` 는 `orig_start_connected` 가 true 이고 지금 전원이 켜져 있으면
`connected` 를 요구하므로, 두 단계의 판정이 서로 어긋나 있었다.

## 3. 해결 방안

`internal/vsphere/nic.go` 에 `EnsureConnected` 를 추가한다.

- 전원이 꺼진 VM 은 `Connected` 가 구조적으로 항상 false 이므로 대상에서 제외
  (기존대로 `start_connected` 만 확인).
- NIC 를 다시 읽어 `Connected` 가 false 면, **연결 상태만 담은 Reconfigure**
  를 따로 한 번 더 보낸다.
- 런타임 반영에 시간이 걸리므로 2초 간격으로 다시 읽어 확인하고, 최대 5회까지
  재시도한다. 그래도 안 되면 에러로 보고한다(조용히 성공 처리하지 않는다).

호출 지점:
- `cmd/connect` (Step 3) — `rec.OrigConnected || rec.OrigStartConnected` 일 때
- `cmd/rollback` (Step 1-Undo) — 원복도 연결 상태까지 되돌아야 완료

## 6. 유지할 것 / 제약

- 원래 끊겨 있던 NIC 는 끊긴 채로 둔다. 이관이 설정 변경이 되면 안 된다.
- 멱등성 유지 — 이미 연결돼 있으면 Reconfigure 를 보내지 않는다.
- `SetPortgroup` / `SetConnected` 의 기존 시그니처와 동작은 그대로 둔다.
