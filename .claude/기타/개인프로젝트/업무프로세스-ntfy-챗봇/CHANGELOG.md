## [v2.1.1] - 2026-10-11

### 수정 (Fixed)
- **앱에서 긴 답변이 중간에서 잘려 `��` 로 보이던 문제**: ntfy.sh 는 푸시(FCM) 메시지의 직렬화 크기가 4000바이트를 넘으면 `message` 를 바이트 단위로 잘라 보낸다. 직렬화에는 message 가 2회(안드로이드/iOS 복사본), 제목 3회, 버튼 2회 들어가므로 1,982바이트 조각도 약 5,640바이트로 계산되어 약 326바이트만 남았다. 서버에는 전체가 저장되어 있었으나 앱이 푸시로 받은 잘린 본문을 표시했다
- 조각 분할 기준을 글자 수(1,200자)에서 **UTF-8 바이트 기준 1,000바이트**(`CHUNK_MAX_BYTES`, 300~1300)로 변경. 한도보다 긴 한 줄은 글자 단위로 분할. 안내문이 있는 첫 조각도 한도 안에서 계산
- 결과적으로 긴 답변은 이전보다 조각 수가 늘어난다(한글 2,100자 답변 기준 약 5조각)

## [v2.1.0] - 2026-10-11

### 변경 (Changed)
- **긴 답변 표시 형식**: 여러 조각으로 나뉠 때 제목을 `답변 (1/N) - 질문 첫 줄(최대 30자)` 로 표시. 한 개면 `답변 - 질문 첫 줄`
- **조각 순서 보장**: 조각 사이 발행 간격 0.8초 → `CHUNK_INTERVAL_SEC`(기본 1.2초, 최소 1.1초). ntfy 메시지 시각이 1초 단위라 같은 초에 들어간 조각의 순서가 뒤바뀌는 문제 방지
- **안내문은 첫 조각(1/N)에만**: 안내문이 단독 조각이 되거나 중간에서 잘리지 않도록 첫 조각 분량에서 미리 차감
- **👍/👎 버튼은 마지막 조각(N/N)에만** (기존 동작을 테스트로 고정)
- **터미널 출력**: 질문이 들어오는 즉시 `[질문 수신] 사용자 | 시각 | 질문` 출력(큐 대기 중에도 표시), 처리 시작 시 `[질문 처리 시작]`, 발행 로그에 조각 번호와 제목 표시(토픽·토큰 미출력)

### 추가 (Added)
- `수동테스트.py`, `[6] 수동테스트.bat`, `사용법.txt`: 사용자가 직접 실행하는 수동 테스트 절차와 전송 스크립트
- 자기 답변 무시 보강: 제목이 `답변 …` 형식이면 tags 가 없어도 봇 발행으로 간주

## [v2.0.0] - 2026-10-11

### 추가 (Added)
- **사용자별 개인 토픽 모드 (기본)**:
  - `users.json` 을 최초 실행 시 자동 생성 (`USER_NAMES` 또는 사용자1~사용자7). 토픽은 `proc-` + 128bit 무작위 값
  - 질문·답변·피드백을 사용자 토픽으로만 주고받아 사용자 간 노출 차단
  - 로그에는 토픽 대신 사용자 이름을 기록
- **선입선출 큐와 대기 안내**: 단일 워커가 도착 순서대로 처리. 앞에 대기가 있으면 `접수되었습니다. 앞에 N건 대기 중입니다` 를 해당 토픽으로 발행
- **사용자별 3턴 맥락**: 최근 3턴(질문·답변) 유지. `CONTEXT_TTL_SEC`(기본 600초) 경과 시 자동 초기화. `/reset` 은 큐를 거치지 않고 즉시 처리
- **문서 로더**:
  - 질문마다 해시 비교, 변경 시에만 재적재 (봇 재시작 불필요)
  - `logs/doc_changes.jsonl` 에 적재·변경 이력 기록
  - 토큰 예산 가드 (`ANSWER_RESERVE`): 초과 시 `##`/`###` 단위 절 선택 모드로 전환, 용어 표 절은 항상 포함
  - 문서의 `| 약어 | 정의 |` 표를 자동 파싱하여 질문에 용어 참고 추가
  - 여러 문서 지원: `DOC_PATHS`(세미콜론 구분), `DOC_DIR`(폴더 내 `.md`)
- **새 설정 키**: `THINK`, `CONTEXT_TTL_SEC`, `ANSWER_RESERVE`, `USER_NAMES`, `DOC_PATHS`, `DOC_DIR`, `TOP_P`, `TOP_K`, `NO_ANSWER_TEXT`
- **답변 후처리**: 본문의 `§` 조항 표기 자동 제거 (`strip_clause_refs`), `<think>` 블록 제거
- **테스트**: `test_bot_mock.py` 에 큐 순서·사용자 분리·3턴·TTL·`/reset`·문서 교체·예산 초과·다중 문서·`users.json` 생성/유지 케이스 추가
- **실험 하네스**: `experiment.py` (모델 × 프롬프트 변형 매트릭스, 안전 게이트 요약, 비교표). v2 42문항 테스트셋 `tests/테스트케이스_v2.txt` 와 문항별 기대 근거 `tests/테스트케이스_v2_기대.md`

### 변경 (Changed)
- **프롬프트**: 추출형("핵심 절차만 번호 목록") → 동료 엔지니어가 설명하듯 서술하는 방식. 문서에 없는 내용은 거절, 일부만 근거가 있으면 빠진 부분을 명시
- **기본 모델**: `qwen3.5:9b-q8_0` (실험 임시 1위, 사용자 품질 판정 전). 이전 기본값 `qwen3:8b`
- **thinking 기본 끔**: `THINK=false`. 응답 시간 측정 근거는 README 3.2
- **토픽 모드 우선순위**: `users.json` 또는 `USER_NAMES` 가 있으면 개인 토픽 모드, 둘 다 없고 `NTFY_TOPIC` 이 있으면 단일 토픽 모드(하위 호환), 그 외 분리 토픽 모드
- **`.env.example`**: 신규 키 반영, `MODEL` 기본을 `qwen3.5:9b-q8_0` 으로 변경, `NTFY_TOPIC` 예시를 주석 처리 (활성 상태면 단일 토픽 모드로 동작하기 때문)

### 수정 (Fixed)
- 테스트 실행이 운영 로그(`logs/feedback.jsonl`)에 기록하던 문제: 테스트는 임시 데이터 폴더(`BOT_DATA_DIR`)를 사용
- `run_tests.py` 결과 CSV 위치를 `TESTS_OUT_DIR` 환경변수로 지정 가능 (운영 `tests\` 를 건드리지 않고 실행 가능)

### 알려진 한계 (Known limitations)
- 공개 ntfy.sh 사용: 토픽 이름이 비밀번호 역할을 하며, 메시지는 ntfy.sh 서버를 거쳐 전달됨 (README 4 참고)
- 폐쇄망 구동은 검증하지 않음. 자체 ntfy 서버 가이드는 범위에서 취소
- 모델 선정은 임시. 최종 모델은 사용자 품질 판정 후 확정 (`실험/사용자판정가이드.md`)
- 2명 이상 동시 질문은 단일 워커로 직렬 처리 (병렬 처리 미구현)
- 절 선택 모드는 키워드 점수 기반이라 관련 절을 놓칠 수 있음. 겹치는 절이 없으면 문서 첫 절의 앞부분을 넣음

## [v0.2.0] - 2026-10-11

### 추가 (Added)
- **단일 토픽 모드 (Single Topic Chat Mode)**:
  - 휴대폰 ntfy 앱에서 **단 1개 토픽(방)**만 구독하여 메신저 대화방처럼 질문 전송과 답변 수신, 피드백을 모두 통합 처리할 수 있는 기능 추가
  - 봇 자체 발행 메시지(태그 `bot`, 타이틀 `🤖 답변`) 자동 필터링을 통한 무한 루프 방지
  - 단일 방 내에서 👍/👎 버튼 피드백 이벤트 분기 디스패치 (`handle_single_topic_event`)
  - `.env`에 `NTFY_TOPIC` 지정 시 단일 토픽 모드로 자동 전환되며, 기존 3개 분리 토픽과의 하위 호환성 유지
- **안정성 및 사용성 개선**:
  - ntfy 스트림 재연결 시 만료된 메시지 ID로 인한 HTTP 400 Bad Request 자동 복구 로직 강화
  - Windows 콘솔 및 로그 파일 실시간 플러시(`line_buffering=True`, `-u`) 적용
  - `run.bat`에서 Python 실행 경로 다중 폴백 자동 탐색 지원
