# 업무프로세스 ntfy 챗봇 (v2.1.2)

휴대폰(ntfy 앱 또는 웹앱)으로 질문하면 집 PC의 로컬 LLM(Ollama)이 업무프로세스 표준 지침서(`D:\업무프로세스\업무프로세스.md`)를 근거로 답하고, 답변마다 👍/👎 피드백을 수집하는 경량 챗봇입니다. 여러 사용자가 각자 개인 토픽으로 질문하며, 요청은 도착 순서대로 한 건씩 처리합니다.

### v2 주요 변경
- **사용자별 개인 토픽**: 사용자마다 토픽이 따로 있어 서로의 질문과 답변이 보이지 않습니다 (기본 최대 7명).
- **선입선출 큐와 대기 안내**: 처리 중인 질문이 있으면 `접수되었습니다. 앞에 N건 대기 중입니다` 를 먼저 보냅니다.
- **3턴 맥락과 `/reset`**: 사용자별 최근 3턴을 기억하고, 일정 시간 질문이 없으면 자동 초기화합니다.
- **서술형 답변**: 문서를 그대로 발췌하지 않고 설명하듯 답하며, 문서에 없는 내용은 지어내지 않고 거절합니다.
- **thinking 기본 끔**: 응답 시간을 줄이기 위해 `THINK=false` 가 기본입니다.
- **문서 변경·확장 대응**: 문서를 고치면 다음 질문부터 자동 반영되고, 커지면 질문과 관련된 절만 넣습니다. 여러 문서도 읽을 수 있습니다.
- **기본 모델**: `qwen3.5:9b-q8_0` (실험 임시 1위, 사용자 품질 판정 전).

## 1. 빌드 및 설치 방법

### 1.1 필수 환경 요구사항
- **운영체제**: Windows 10/11 (64-bit)
- **하드웨어 권장사양**: NVIDIA RTX 3060 12GB 이상 VRAM, RAM 16GB 이상
  - 참고: `qwen3.5:9b-q8_0` 적재 시 VRAM 사용량은 실측 약 11.4GB입니다 (`실험/S4_stage2/게이트요약.md`).
- **Python**: Python 3.12 이상 (`py` 런처 포함)
- **LLM 엔진**: [Ollama](https://ollama.com/) 및 기본 모델 `qwen3.5:9b-q8_0`

### 1.2 설치 절차

1. **Python 설치** (기본 설치되지 않은 경우):
   ```powershell
   winget install Python.Python.3.12 --accept-package-agreements --accept-source-agreements
   ```
   설치 시 `py` 런처 및 PATH 등록이 활성화됩니다.
   외부 추가 라이브러리(`pip install`) 설치가 전혀 필요 없으며, Python 표준 라이브러리만으로 구동됩니다.

2. **Ollama 모델 준비**:
   ```bash
   ollama pull qwen3.5:9b-q8_0
   ```

3. **데이터 및 문서 폴더 준비**:
   근거 문서(`업무프로세스.md`)와 설정 파일(`.env`)은 `D:\업무프로세스`에 둡니다. 저장소 파일은 `bot\` 아래에 둡니다.
   ```
   D:\업무프로세스\
   ├── 업무프로세스.md        # 근거 문서 (저장소에 올리지 않음)
   ├── .env                   # 설정 (.env.example 을 복사해 수정, 저장소에 올리지 않음)
   ├── users.json             # 사용자별 개인 토픽 (최초 실행 시 자동 생성, 저장소에 올리지 않음)
   ├── state.json             # 마지막 처리 메시지 ID (자동 생성)
   ├── bot\                   # 저장소 파일: bot.py, run.bat, run_tests.py, test_bot_mock.py 등
   ├── logs\                  # qa / unanswered / feedback / errors / doc_changes .jsonl (자동 생성)
   ├── tests\                 # 테스트케이스와 결과 CSV
   └── 백업\                  # 자동 생성 디렉터리
   ```

4. **설정 파일 만들기**: 저장소의 `.env.example` 을 `D:\업무프로세스\.env` 로 복사한 뒤 값을 확인합니다. 토픽명은 직접 적지 않아도 됩니다 (첫 실행 때 `users.json` 에 자동 생성).

### 1.3 폐쇄망 주의
- 현재 구성은 휴대폰과 집 PC를 **공개 ntfy.sh 서버로 연결**하므로, 봇 PC와 휴대폰이 모두 인터넷에 연결되어 있어야 합니다.
- 회사 폐쇄망에서는 ntfy.sh에 접속할 수 없으므로 이 구성을 그대로 쓸 수 없습니다. `NTFY_SERVER` 로 사내 ntfy 서버 주소를 지정하는 코드 경로는 있지만, 폐쇄망에서 동작을 **검증하지 않았습니다** (자체 ntfy 서버 가이드는 범위에서 취소).
- `ollama pull` 에도 인터넷이 필요합니다. 모델 파일을 오프라인으로 옮기는 방법은 확인하지 않았습니다.

## 2. 사용 방법

### 2.1 챗봇 실행
운영 폴더(`D:\업무프로세스`)에서 `[3] 챗봇_시작.bat` 을 실행합니다. 이 배치 파일은 Ollama 가 떠 있는지 먼저 확인한 뒤 봇을 시작합니다. 직접 실행하려면 같은 폴더에서 아래 명령을 씁니다.
```bash
py -u bot\bot.py
```

시작하면 콘솔에 설정과 사용자별 토픽이 출력되고, 워밍업 요청을 보낸 뒤 대기 상태가 됩니다. 토픽은 각 사용자에게만 전달하세요.
```
============================================================
 [업무프로세스 ntfy 챗봇 시작 - 워밍업]
 문서 경로: D:\업무프로세스\업무프로세스.md
 모델: qwen3.5:9b-q8_0 | 컨텍스트: 24576 | 온도: 0.2 | think: False
 ntfy 서버: https://ntfy.sh
 [운영 모드] 사용자별 개인 토픽 모드 (7명)
 아래 토픽을 각 사용자의 휴대폰 ntfy 앱에서 구독하게 하세요 (타인에게 알려주지 마세요):
    사용자1  ->  proc-<22자 무작위>
    ...
============================================================
```
종료는 Ctrl+C 또는 `[4] 챗봇_중지.bat` 입니다.

### 2.2 사용자별 개인 토픽 배포
1. **최초 실행**: `users.json` 이 없으면 `USER_NAMES` 에 적힌 이름(없으면 사용자1~사용자7)으로 토픽을 만들어 `users.json` 에 저장합니다. 이때 콘솔에 토픽 목록이 한 번 출력됩니다.
2. **전달**: 각 사용자의 토픽을 그 사용자에게만 알려줍니다. 단체방이나 공용 채널에 올리지 마세요.
3. **구독**: 사용자는 휴대폰 ntfy 앱에서 **자기 토픽 1개만** 구독합니다.
4. **동작**: 질문, 답변, 👍/👎 피드백이 모두 그 토픽 안에서 오갑니다. 다른 사용자의 토픽에는 아무것도 발행되지 않습니다.
5. **추가·교체**: `users.json` 을 직접 편집(`{"이름": "토픽"}` 형식)한 뒤 봇을 재시작합니다. `USER_NAMES` 는 `users.json` 이 없을 때만 쓰이므로, 이미 있는 파일에서는 무시됩니다. 토픽을 바꾸면 해당 사용자는 새 토픽을 구독해야 합니다.
6. **유출 시**: 토픽 이름은 비밀번호 역할을 합니다. 노출이 의심되면 `users.json` 에서 그 토픽을 새 값으로 바꾸고 다시 구독하게 하세요.

> `users.json` 을 만들기 전에 `.env` 에 `NTFY_TOPIC` 이 활성화되어 있으면 **단일 토픽 모드**로 동작합니다. 개인 토픽 모드를 쓰려면 `NTFY_TOPIC` 줄을 주석 처리하세요 (`.env.example` 은 주석 처리된 상태입니다).

### 2.3 질문하기

- **질문 순서**: 봇은 한 번에 한 건씩 도착 순서대로 처리합니다. 앞에 처리할 질문이 있으면 `접수되었습니다. 앞에 N건 대기 중입니다` 를 먼저 보냅니다.
- **응답 시간**: 목표는 답변 1건당 10초 이내입니다. 실험 42문항에서 `qwen3.5:9b-q8_0` 의 평균 응답은 5.2초, 최대는 14.9초였습니다 (`실험/S4_stage2/비교표.md` 와 `runs.jsonl` 기준).
- **답변 형식**: 답변 맨 앞에 `AI 답변은 100% 정확하지 않습니다` 안내가 붙습니다. 긴 답변은 약 1,000바이트(한글 약 330자) 단위로 나누어 보내며(ntfy.sh 푸시 한도 4,000바이트 대응, `CHUNK_MAX_BYTES`), 앱에서 위에서 아래로 `답변 (1/2) - 질문 첫 줄`, `답변 (2/2) - 질문 첫 줄` 순서로 보입니다 (한 개면 `답변 - 질문 첫 줄`). 안내문은 첫 조각(1/N)에만, `👍`/`👎` 버튼은 마지막 조각(N/N)에만 붙습니다. 조각 사이 발행 간격은 `CHUNK_INTERVAL_SEC`(기본 1.2초)입니다. 답변은 마크다운으로 발행되어 앱에서 `**굵게**`, 목록, `###` 제목이 서식으로 보입니다(`MARKDOWN=false` 로 끄기). 근거 문서와 절 제목은 보통 답변 마지막 줄에 `📌 참고:` 로 표시됩니다.
- **터미널 표시**: 질문이 들어오면 봇 창에 `[질문 수신] 사용자 | 시각 | 질문` 이 즉시 출력됩니다. 수동 테스트 절차는 `사용법.txt`, `수동테스트.py show` 를 참고하세요.
- **문서 밖 질문**: `문서에 없는 내용입니다` 로 짧게 거절합니다. 질문 일부만 근거가 있으면 확인된 부분을 답하고, `문서에 규정이 없는 부분:` 으로 빠진 부분을 밝힙니다.
- **맥락 (3턴)**: 같은 사용자의 최근 3턴(질문과 답변)을 기억해 이어서 답합니다. 마지막 질문 후 `CONTEXT_TTL_SEC` 초(기본 600초 = 10분)가 지나면 자동으로 초기화됩니다.
- **`/reset`**: 새 주제를 시작할 때 보냅니다. 큐를 기다리지 않고 바로 `대화 맥락을 초기화했습니다` 로 답합니다. 처리 중이던 이전 질문의 답변은 맥락에 저장되지 않습니다.
- **피드백**: 답변 아래 `👍 좋음` / `👎 나쁨` 버튼을 누르면 `logs/feedback.jsonl` 에 기록됩니다.

### 2.4 테스트 실행
```bash
py run_tests.py                 # tests\테스트케이스.txt 60문항, 결과는 tests\결과_YYYYMMDD.csv
py test_bot_mock.py             # 단위 테스트 (Ollama·ntfy 는 모의 객체, 데이터는 임시 폴더 사용)
py experiment.py run --models qwen3.5:9b-q8_0 --variants P1_nothink --cases v2 --out 실험\결과폴더
                                # 모델×프롬프트 변형 실험 (v2 42문항, 안전 게이트 요약과 비교표 생성)
```
`run_tests.py` 의 결과 CSV 위치는 `TESTS_OUT_DIR` 환경변수로 바꿀 수 있습니다.

## 3. 옵션별 상세 설명

설정은 `D:\업무프로세스\.env` 에서 수정합니다. 값이 없으면 아래 기본값을 씁니다. 봇은 누락된 키를 채워 `.env` 를 다시 쓰므로, 그때 주석이 지워집니다.

| 환경변수 키 | 기본값 | 상세 설명 |
|---|---|---|
| `NTFY_SERVER` | `https://ntfy.sh` | ntfy 서버 주소 (공용 서버 기본) |
| `USER_NAMES` | 없음 (사용자1~사용자7) | 쉼표로 구분한 사용자 이름. `users.json` 이 없을 때 토픽을 만드는 기준 |
| `NTFY_TOPIC` | 없음 | 지정하면 **단일 토픽 모드**(하위 호환). 개인 토픽 모드에서는 비워 둡니다 |
| `NTFY_QUESTION_TOPIC` / `NTFY_ANSWER_TOPIC` / `NTFY_FEEDBACK_TOPIC` | 없음 | **분리 토픽 모드** (`NTFY_TOPIC` 을 비울 때) |
| `NTFY_TOKEN` | 공란 | 보호된 ntfy 토픽의 인증 토큰 |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama REST API 주소 |
| `MODEL` | `qwen3.5:9b-q8_0` | Ollama 모델 태그. 환경변수 `MODEL` 이 있으면 `.env` 보다 우선 |
| `NUM_CTX` | `24576` | 컨텍스트 토큰 수. gemma 계열은 16384 (3.1 참고) |
| `KEEP_ALIVE` | `30m` | 마지막 질문 후 모델을 VRAM 에 둘 시간 |
| `TEMPERATURE` | `0.2` | 생성 온도 |
| `TOP_P` / `TOP_K` | `0.8` / `20` | 샘플링 옵션 |
| `THINK` | `false` | `true` / `false` 만 요청에 보냅니다. 빈 값이면 보내지 않습니다. 모델이 이 옵션을 거부하면 봇이 자동으로 빼고 재시도합니다 |
| `CONTEXT_TTL_SEC` | `600` | 사용자별 맥락 자동 초기화 시간(초) |
| `ANSWER_RESERVE` | `3000` | 문서 주입 예산에서 답변용으로 남겨 둘 토큰 수 (3.3 참고) |
| `DOC_PATH` | `D:\업무프로세스\업무프로세스.md` | 기본 근거 문서 |
| `DOC_PATHS` | 공란 | 세미콜론(`;`)으로 구분한 여러 문서. `DOC_DIR` 과 `DOC_PATH` 보다 우선 |
| `DOC_DIR` | 공란 | 폴더 안의 `.md` 파일 전부 (파일명 순). `DOC_PATHS` 가 비었을 때 사용 |
| `NO_ANSWER_TEXT` | `문서에 없는 내용입니다.` | 문서 밖 질문에 대한 거절 문구 |

### 3.1 모델 교체 방법 (`MODEL=` 한 줄)
1. 새 모델을 받습니다: `ollama pull <모델태그>`
2. `D:\업무프로세스\.env` 에서 `MODEL=` 줄만 바꿉니다. (변경 전에 `.env.bak` 으로 복사해 둡니다.)
   - `gemma3:12b-it-qat` 는 실험 조건대로 `NUM_CTX=16384` 를 함께 바꿉니다. 24576 에서는 실험하지 않았습니다.
3. 봇을 재시작합니다: `[4] 챗봇_중지.bat` 후 `[3] 챗봇_시작.bat`
4. 워밍업 출력의 `모델:` 값과 `ollama ps` 의 `100% GPU` 를 확인합니다.

> 환경변수 `MODEL` 이 설정돼 있으면 `.env` 값이 무시되므로, 교체 후 워밍업 출력에서 모델명이 바뀌었는지 꼭 확인하세요.

후보 비교와 판정 방법은 `실험/사용자판정가이드.md` 를 보세요.

### 3.2 thinking(추론)을 끈 이유 (`THINK=false`)
- 같은 질문, 문서 전체 주입, 동일 옵션으로 한 번 측정했을 때 thinking 을 지정하지 않은 경우 82초, `think:false` 에서는 22초였습니다. 생성 토큰도 2,418개에서 629개로 줄었습니다 (`실험/00_현황.md` §3). 한 번 측정한 값이므로 참고용입니다.
- 이후 `think:false` 로 실행한 v2 42문항 실험에서 평균 응답은 4.2~5.3초였습니다 (`실험/S4_stage2/게이트요약.md`).
- 응답 시간 목표(10초)를 맞추기 위해 기본값을 끔으로 두었습니다. thinking 을 켜려면 `THINK=true` 로 바꾸되, 목표 시간을 넘을 수 있습니다.

### 3.3 문서가 바뀌거나 커질 때
- **내용 변경**: 봇은 질문을 받을 때마다 문서 파일의 해시를 확인합니다. 바뀌었으면 다시 읽고, **봇 재시작 없이 다음 질문부터** 새 내용을 씁니다. 변경 이력은 `logs/doc_changes.jsonl` 에 남습니다 (시각, 파일명, 바이트 수, 토큰 추정, 해시, 예산 초과 여부).
- **예산 가드**: 토큰은 UTF-8 바이트 수 ÷ 3 으로 대략 추정합니다. 문서 전체 + 고정 문구 + `ANSWER_RESERVE` 가 `NUM_CTX` 이하이면 문서 전체를 넣습니다.
- **절 선택 모드**: 넘으면 `##` / `###` 제목 단위로 나눠, 질문과 관련 있는 절만 넣습니다.
  - 용어 표(`| 약어 | 정의 |`)가 있는 절은 항상 넣습니다.
  - 나머지는 질문 단어와 제목·본문이 겹치는 정도가 높은 순으로 예산이 찰 때까지 넣습니다.
  - 겹치는 절이 하나도 없으면 문서 첫 절을 앞부분만 잘라 넣습니다. 이 경우 답이 빗나갈 수 있습니다.
  - 전환 사실은 콘솔과 `logs/errors.jsonl` 에 경고로 남습니다.
- **여러 문서**: `DOC_PATHS`(세미콜론) 또는 `DOC_DIR`(폴더)로 여러 파일을 읽습니다. 각 파일은 `[문서 파일: 이름]` 으로 구분되며, 답변의 `📌 참고` 에 파일명과 절 제목이 쓰입니다.
- **용어 사전**: 문서의 `| 약어 | 정의 |` 표를 자동으로 읽습니다. 질문에 나온 약어의 뜻을 모델 입력에만 덧붙입니다. 로그에는 원문 질문이 남습니다.
- **코드에 업무 내용 없음**: 절 번호나 업무명은 코드와 프롬프트에 넣지 않습니다. 문서를 바꿔도 코드를 고칠 필요가 없습니다.

### 공개 ntfy.sh 사용 시 한계
- ntfy.sh 공개 서버에서는 토픽 이름만 알면 구독하고 메시지를 보낼 수 있습니다. 토픽 이름(`proc-` + 128bit 무작위)이 비밀번호 역할을 합니다.
- 질문과 답변 내용은 ntfy.sh 서버를 거쳐 전달되며, 서버 정책에 따라 일정 기간 보관될 수 있습니다. 민감한 개인정보나 비공개 내용은 질문하지 마세요.
- 토픽이 유출되면 제3자가 질문을 보거나 가짜 피드백을 보낼 수 있습니다. 2.2의 6번 절차로 토픽을 바꾸세요.
- `NTFY_TOKEN` 은 인증이 필요한 ntfy 서버에서만 의미가 있습니다. 공개 ntfy.sh 에서 인증을 쓰는 방법은 이 문서에 없습니다.
- `logs/qa.jsonl` 에는 사용자 이름과 질문·답변 원문이 남습니다. 로그를 외부에 공유하기 전에 검토하세요.

## 5. 전역 명령어로 사용하기 (선택 사항)

### Windows 시작 시 자동 실행 (작업 스케줄러 등록)
재부팅 후에도 백그라운드에서 상시 실행되도록 작업 스케줄러에 등록할 수 있습니다:

```powershell
$action = New-ScheduledTaskAction -Execute "py.exe" -Argument "D:\업무프로세스\bot\bot.py" -WorkingDirectory "D:\업무프로세스\bot"
$trigger = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "NtfyProcessChatbot" -Action $action -Trigger $trigger -Description "업무프로세스 ntfy 챗봇 자동 실행"
```

### 전역 실행 배치 스크립트 등록 (System32 또는 PATH 등록)
터미널 어디서나 `ntfy-proc-bot`으로 실행하려면 PATH가 지정된 디렉터리(예: `C:\Windows\System32` 또는 사용자 전용 bin)에 심볼릭 링크나 배치 파일을 생성합니다:
```cmd
echo @py "D:\업무프로세스\bot\bot.py" %%* > "C:\Users\%USERNAME%\AppData\Local\Programs\Python\Launcher\ntfy-proc-bot.cmd"
```
등록 후에는 아무 터미널에서나 `ntfy-proc-bot`을 입력하여 즉시 봇을 실행할 수 있습니다.
