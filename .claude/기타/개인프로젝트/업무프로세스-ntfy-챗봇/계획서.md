# 업무프로세스 ntfy 챗봇 — 계획서

휴대폰(ntfy 앱)으로 질문하면 **집 PC의 로컬 LLM**이 **업무프로세스 문서만 근거로** 답하고, 답변마다 👍/👎 피드백을 남길 수 있게 한다.

> 상태: **계획만 작성**. 코드는 아직 만들지 않았다.

---

## 1. 배경과 전제

| 항목 | 내용 |
|---|---|
| 사용 이유 | 사내망에서는 외부 통신이 불가 → 업무프로세스 문서는 **집 PC**에 있고, 여기서 LLM을 돌린다 |
| 질문 위치 | 휴대폰 (회사·외부, LTE 등) |
| 채팅 수단 | **ntfy** (Android/iOS 앱, 웹앱) |
| 문서 | 텍스트 1개, **712줄 / 15,782자** |
| PC | Windows, RTX 3060 12GB, DDR4 48GB, NVMe(DRAM리스) |
| LLM 실행 | Ollama |

---

## 2. 전체 구조

```
[휴대폰 ntfy 앱]
   │  ① 질문 발행 (질문 토픽)
   ▼
[ntfy 서버 (ntfy.sh)] ◀────────────────────────────┐
   │  ② 구독 스트림                                   │ ④ 답변 발행 (답변 토픽)
   ▼                                                │    + [👍 좋음] [👎 나쁨] 버튼
[집 PC: bot.py] ──③ 문서 전체 + 질문──▶ [Ollama] ──┘
   │
   └─ ⑤ 버튼 클릭 → 피드백 토픽 → bot.py → logs/feedback.jsonl
```

- 집 PC는 **바깥으로 나가는 연결만** 쓴다 (ntfy 구독·발행). 포트 개방·공유기 설정 불필요.
- 토픽 3개
  - 질문 토픽 (`…-q`): 휴대폰 → 봇
  - 답변 토픽 (`…-a`): 봇 → 휴대폰 (휴대폰은 이것을 구독)
  - 피드백 토픽 (`…-fb`): 답변의 버튼 → 봇

## 3. 핵심 결정

### 3.1 RAG 없이 "문서 전체를 매번 넣기"

- 문서가 15,782자로 작아서 **통째로 프롬프트에 넣을 수 있다**. 임베딩·벡터DB·청킹이 필요 없다.
- 장점: 검색 누락이 없음, 구성 단순, 문서 수정 시 재색인 불필요.
- 문서는 **system 메시지 맨 앞**에 고정 → Ollama가 질문 사이에 문서 부분을 재계산하지 않아(프롬프트 캐시) 두 번째 질문부터 빠르다.
- 문서는 **질문마다 다시 읽는다** → 파일을 고치면 재시작 없이 반영.
- 문서가 나중에 수만 자 이상으로 커지면 그때 RAG로 전환한다.

### 3.2 모델과 컨텍스트 크기

| 항목 | 값 | 이유 |
|---|---|---|
| 기본 모델 | `qwen3:14b` (Q4_K_M, 약 9GB) | 한국어·지시 따르기 우수 |
| 대안 | `gemma3:12b`, 속도 우선 시 `qwen3:8b` | config 한 줄로 교체 |
| num_ctx | **24576** (시작값) | 한글 15,782자 ≈ 대략 1만~1.6만 토큰(추정) + 질문·답변 여유 |
| KV 캐시 | `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0` | 24K 컨텍스트를 12GB VRAM 안에 넣기 위함 |
| thinking | 끔 (`think: false`) | 답변 지연 감소 |
| temperature | 0.2 | 문서 그대로 답하도록 |

- **주의**: Ollama는 num_ctx를 넘으면 **프롬프트 앞부분(=문서 앞쪽)을 조용히 잘라낸다.**
  → 봇 시작 시 "워밍업 호출"로 실제 토큰 수(`prompt_eval_count`)를 측정해 출력하고, num_ctx의 90%를 넘으면 경고한다. 질문마다 같은 검사를 해서 로그에 남긴다.
- `ollama ps` 에서 **100% GPU** 인지 확인. CPU 비율이 보이면 num_ctx를 줄이거나 `qwen3:8b`로 바꾼다.

### 3.3 거절 규칙 (문서 밖 질문)

system 프롬프트 규칙:
1. 문서에 근거가 없거나 문서만으로 판단할 수 없으면 추측하지 말고 정확히 **"문서에 없는 내용입니다."** 한 문장만 답한다.
2. 일반 상식·외부 지식으로 보충하지 않는다.
3. 간결하게, 절차는 번호 목록.
4. 마지막 줄에 `(근거: 문서의 항목/제목)`.
5. 1000자 이내.

봇은 답변에 거절 문구가 들어 있으면 **미답변**으로 분류해 따로 기록한다 → 문서에 무엇을 보충해야 하는지 알 수 있다.

### 3.4 ntfy 사용 방식

- 발행은 **JSON 본문**으로 서버 루트에 POST (헤더 방식은 한글 제목이 깨짐 — 코인자동매매 프로젝트에서 확인한 사항).
- 메시지 한도 4096바이트(한글 약 1,300자) → 넘으면 `(1/2)`, `(2/2)`로 나눠 보내고 버튼은 마지막 조각에만.
- 피드백 버튼은 ntfy **http 액션**: 누르면 피드백 토픽으로 `good <질문ID>` / `bad <질문ID>` 를 POST.
- 봇이 꺼져 있던 동안 온 질문도 처리: 마지막 처리한 메시지 ID를 `state.json`에 저장하고 재연결 시 `since=<ID>`로 이어 받는다 (ntfy.sh 보관 12시간).
- 연결이 끊기면 5초부터 최대 5분까지 늘려 가며 재연결.

## 4. 보안·개인정보 (결정 필요)

| 항목 | 내용 |
|---|---|
| 경유 서버 | ntfy.sh 공용 서버를 쓰면 **질문과 답변(문서 내용 일부)이 ntfy.sh를 거친다** |
| 토픽 = 비밀번호 | ntfy.sh 공개 토픽은 이름을 아는 사람이면 읽기·쓰기 가능 → **추측 불가능한 긴 무작위 이름** 사용 (봇이 처음 실행 시 자동 생성) |
| 더 안전한 대안 | ① 집 PC에 ntfy 서버 직접 운영 + Tailscale로 휴대폰만 접속 ② ntfy.sh 계정 + 보호 토픽 + 액세스 토큰 (`ntfy_token` 설정) |

→ 1단계는 **ntfy.sh + 무작위 토픽**으로 시작하고, 문서가 민감하면 대안 ①로 옮긴다. 코드에서는 `ntfy_server`, `ntfy_token`만 바꾸면 되게 한다.

## 5. 구현 계획

### 5.1 기술 선택

- **Python 3.11 표준 라이브러리만** (`urllib`, `json`) → pip 설치 불필요. 집 PC에 이미 Python 3.11이 있음.
- 실행: `run.bat` (`chcp 65001` + `py bot.py`). Windows `python3`는 스토어 스텁이라 쓰지 않는다.

### 5.2 파일 구성 (예정)

```
업무프로세스-ntfy-챗봇/
├── 계획서.md            # 이 문서
├── README.md            # 설치·사용법
├── bot.py               # 봇 본체
├── run.bat              # 실행
├── config.json          # 첫 실행 시 자동 생성 (git 제외 — 토픽이 비밀번호)
├── 업무프로세스.txt     # 문서 (git 제외)
├── state.json           # 마지막 처리 메시지 ID (git 제외)
└── logs/                # (git 제외)
    ├── qa.jsonl         # 모든 질문·답변·토큰 수
    ├── unanswered.jsonl # 미답변 질문
    ├── feedback.jsonl   # 👍/👎 + 해당 질문·답변
    └── errors.jsonl     # LLM 호출 실패
```

### 5.3 config.json 항목

| 키 | 기본값 | 설명 |
|---|---|---|
| ntfy_server | `https://ntfy.sh` | 자체 서버로 바꿀 수 있음 |
| ntfy_token | `""` | 보호 토픽용 |
| topic_question / topic_answer / topic_feedback | 자동 생성 | 무작위 이름 |
| ollama_url | `http://127.0.0.1:11434` | |
| model | `qwen3:14b` | |
| num_ctx | `24576` | |
| keep_alive | `30m` | 마지막 질문 후 VRAM 유지 시간 |
| think | `false` | |
| doc_path | `업무프로세스.txt` | UTF-8 / 메모장 ANSI(cp949) 모두 읽음 |
| no_answer_text | `문서에 없는 내용입니다.` | 거절 문구 |

### 5.4 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | Ollama 설치, `ollama pull qwen3:14b`, 환경변수 2개 설정 | `ollama run qwen3:14b` 응답 |
| 2 | bot.py 작성 (설정·워밍업·구독·답변·피드백·로그) | 모의 ntfy/Ollama 서버로 로컬 테스트 통과 |
| 3 | 첫 실행 → config.json·토픽 생성, 문서 배치 | 워밍업 로그에 토큰 수 출력, 90% 경고 없음 |
| 4 | 휴대폰 ntfy 앱에 답변 토픽 구독, 질문 토픽으로 발행 | 질문 → 답변 알림 수신 |
| 5 | 검증 질문 세트 실행 (아래 6절) | 기준 충족 |
| 6 | 윈도우 시작 시 자동 실행 (작업 스케줄러) | 재부팅 후 질문 응답 |

## 6. 검증 기준

1. **문서 안 질문 10개** → 모두 문서 내용과 일치하고 `(근거: …)` 표시.
2. **문서 밖 질문 5개** (예: 일반 상식, 다른 회사 규정) → 모두 "문서에 없는 내용입니다." + `unanswered.jsonl`에 기록.
3. 👍/👎 버튼 → `feedback.jsonl`에 질문·답변과 함께 기록.
4. 1,300자 넘는 답변 → 나눠서 순서대로 도착.
5. 봇 종료 중 보낸 질문 → 재시작 후 답변 도착.
6. 응답 시간: 첫 질문(모델 적재 포함)과 이후 질문 각각 측정해 기록. 목표는 이후 질문 30초 이내.
7. `qwen3:14b` vs `gemma3:12b` 같은 질문 세트로 비교 → 더 나은 쪽을 기본값으로.

## 7. 휴대폰에서 쓰는 법 (예정)

1. ntfy 앱 설치 → 서버 `ntfy.sh` 그대로 → **답변 토픽** 구독.
2. 질문 보내기: ntfy 웹앱(`https://ntfy.sh/app`, 홈 화면에 추가 가능)에서 **질문 토픽**으로 발행. 앱에서 바로 발행되는지는 버전에 따라 다르므로 구현 시 확인한다.
3. 답변 알림의 👍/👎 버튼으로 평가. (iOS 앱의 http 액션 지원 여부는 구현 시 확인)

## 8. 범위 밖 / 나중에

- 질문마다 모델 선택 (예: `/gemma 질문`) — 필요하면 추가
- 대화 맥락 이어가기 (지금은 질문 하나씩 독립 처리)

- 여러 문서(docx/pdf/hwp) 지원

## 9. 확인 필요

- 휴대폰 OS (Android/iOS) — 버튼 동작·발행 방법 확인 범위가 달라짐
