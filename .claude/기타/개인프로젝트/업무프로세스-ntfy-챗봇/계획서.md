# 업무프로세스 ntfy 챗봇 — 계획서

휴대폰(ntfy)으로 질문하면 **집 PC의 로컬 LLM(qwen3:8b)**이 **업무프로세스 문서만 근거로** 답하고, 답변마다 👍/👎 피드백을 남길 수 있게 한다.

> 상태: **계획만 작성**. 코드는 아직 만들지 않았다.

---

## 1. 배경과 전제

| 항목 | 내용 |
|---|---|
| 사용 이유 | 사내망에서는 외부 통신이 불가 → 업무프로세스 문서는 **집 PC**에 있고, 여기서 LLM을 돌린다 |
| 질문 위치 | 휴대폰 (회사·외부, LTE 등) |
| 채팅 수단 | **ntfy** — 공용 서버 **ntfy.sh 사용 (확정)** |
| 문서 | 텍스트 1개, **712줄 / 15,782자** |
| PC | Windows, RTX 3060 12GB, DDR4 48GB, NVMe(DRAM리스) |
| LLM | Ollama + **qwen3:8b** |

---

## 2. 전체 구조

```
[휴대폰 (Android / iPhone)]
   │  ① 질문 발행 (질문 토픽)
   ▼
[ntfy.sh] ◀────────────────────────────────────────┐
   │  ② 구독 스트림                                   │ ④ 답변 발행 (답변 토픽)
   ▼                                                │    + [👍 좋음] [👎 나쁨] 버튼
[집 PC: bot.py] ──③ 문서 전체 + 질문──▶ [Ollama] ──┘
   │
   └─ ⑤ 버튼 클릭 → 피드백 토픽 → bot.py → logs/feedback.jsonl
```

- 집 PC는 **바깥으로 나가는 연결만** 쓴다 (ntfy 구독·발행). 포트 개방·공유기 설정 불필요.
- 토픽 3개
  - 질문 토픽 (`…-q`): 휴대폰 → 봇
  - 답변 토픽 (`…-a`): 봇 → 휴대폰 (휴대폰은 이것을 구독)
  - 피드백 토픽 (`…-fb`): 답변의 버튼 → 봇

## 3. 핵심 결정

### 3.1 RAG 없이 "문서 전체를 매번 넣기"

- 문서가 15,782자로 작아서 **통째로 프롬프트에 넣을 수 있다**. 임베딩·벡터DB·청킹이 필요 없다.
- 장점: 검색 누락이 없음, 구성 단순, 문서 수정 시 재색인 불필요.
- 문서는 **system 메시지 맨 앞**에 고정 → Ollama가 질문 사이에 문서 부분을 재계산하지 않아(프롬프트 캐시) 두 번째 질문부터 빠르다.
- 문서는 **질문마다 다시 읽는다** → 파일을 고치면 재시작 없이 반영.

### 3.2 모델: qwen3:8b — RTX 3060 12GB 구동 가능 확인 → 설치 진행

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | **`qwen3:8b`** (Q4_K_M) | Ollama 라이브러리 기준 다운로드 **5.2GB** |
| 구동 가능 여부 | **가능** | 모델 5.2GB + KV 캐시 약 3.4GB(24K 토큰) + 여유 ≈ 10GB 이하 → 12GB 안에 들어감 |
| 설치 | `ollama pull qwen3:8b` | 단계 1에서 진행 |
| num_ctx | **24576** (시작값) | 아래 3.3 참고 |
| thinking | 끔 (`think: false`) | 답변 지연 감소 |
| temperature | 0.2 | 문서 그대로 답하도록 |

- `ollama ps` 에서 **100% GPU** 인지 확인한다. CPU 비율이 보이면 num_ctx를 줄인다.
- KV 캐시 양자화(`OLLAMA_KV_CACHE_TYPE=q8_0`)는 8b에서는 **필수 아님**. VRAM이 부족할 때만 쓴다.

### 3.3 num_ctx 24576 이란? (질문에 대한 답)

- **글자 수가 아니라 토큰 수**다. 모델이 한 번에 보는 입력+출력의 최대 길이.
- 한글은 대략 1글자 ≈ 0.7~1토큰 수준이라, 문서 15,782자는 **약 1만~1.6만 토큰으로 추정**한다 (정확한 값은 첫 실행 때 측정).
- **qwen3:8b에도 유효한 값이다.**
  - Qwen3-8B의 기본 컨텍스트는 32,768 토큰(설정상 최대 위치 40,960) → 24,576은 그 안이다.
  - VRAM 계산: Qwen3-8B는 36층 × KV 헤드 8 × 헤드 크기 128 → 토큰당 KV 캐시 약 144KB(fp16) → 24,576토큰 ≈ 3.4GB. 모델 5.2GB와 합쳐도 12GB 안이다.
- 배분: 문서(약 1만~1.6만) + 규칙·질문(수백) + 답변(최대 약 1천) → 24,576이면 여유가 있다.
- **주의**: Ollama는 num_ctx를 넘으면 **프롬프트 앞부분(=문서 앞쪽)을 조용히 잘라낸다.**
  → 봇 시작 시 "워밍업 호출"로 실제 토큰 수(`prompt_eval_count`)를 측정해 출력하고, num_ctx의 90%를 넘으면 경고한다. 질문마다 같은 검사를 해서 로그에 남긴다. 측정값이 작으면 num_ctx를 줄여 VRAM을 아낀다.

### 3.4 거절 규칙 (문서 밖 질문)

system 프롬프트 규칙:
1. 문서에 근거가 없거나 문서만으로 판단할 수 없으면 추측하지 말고 정확히 **"문서에 없는 내용입니다."** 한 문장만 답한다.
2. 일반 상식·외부 지식으로 보충하지 않는다.
3. 간결하게, 절차는 번호 목록.
4. 마지막 줄에 `(근거: 문서의 항목/제목)`.
5. 1000자 이내.

봇은 답변에 거절 문구가 들어 있으면 **미답변**으로 분류해 따로 기록한다 → 문서에 무엇을 보충해야 하는지 알 수 있다.

### 3.5 ntfy 사용 방식

- 발행은 **JSON 본문**으로 서버 루트에 POST (헤더 방식은 한글 제목이 깨짐 — 코인자동매매 프로젝트에서 확인한 사항).
- 메시지 한도 4,096바이트(한글 약 1,300자, 넘으면 첨부파일로 바뀜) → 넘으면 `(1/2)`, `(2/2)`로 나눠 보내고 버튼은 마지막 조각에만.
- 피드백 버튼은 ntfy **http 액션**: 누르면 피드백 토픽으로 `good <질문ID>` / `bad <질문ID>` 를 POST.
- 봇이 꺼져 있던 동안 온 질문도 처리: 마지막 처리한 메시지 ID를 `state.json`에 저장하고 재연결 시 `since=<ID>`로 이어 받는다 (ntfy.sh 보관 12시간).
- 연결이 끊기면 5초부터 최대 5분까지 늘려 가며 재연결.
- **토픽 이름 = 비밀번호**: ntfy.sh 공개 토픽은 이름을 아는 사람이면 읽고 쓸 수 있으므로, 추측 불가능한 긴 무작위 이름을 쓴다 (첫 실행 시 자동 생성).

### 3.6 Android·iPhone 공통 사용 — 확인 결과: 가능

봇은 **하나만** 만들면 된다. 봇은 ntfy 토픽만 다루고, 휴대폰 종류는 ntfy 앱이 처리한다.

| 기능 | Android | iPhone | 확인 근거 |
|---|---|---|---|
| 답변 알림 수신 | ntfy 앱 | ntfy 앱 | 공식 앱 둘 다 있음 |
| 👍/👎 버튼 (http 액션) | ✓ | ✓ | ntfy 문서 "Action buttons — Supported on: Android, Apple, Firefox", http 액션 Android 전용 표시 없음 (Android 전용은 broadcast 액션뿐) |
| 질문 보내기 | ntfy 앱 토픽 화면 하단 입력창 | **ntfy 웹앱** (`https://ntfy.sh/app`) — Safari에서 "홈 화면에 추가" | Android 앱 발행 기능은 문서 확인. iOS 앱 발행 기능은 문서에서 확인 못 함 → 웹앱 사용 (웹앱은 구독·발행 모두 지원, iOS 16.4 이상) |

- iPhone은 **받기 = ntfy 앱, 보내기 = ntfy 웹앱**으로 나눠 쓴다. iOS 앱에서 바로 발행이 되면 그것만 써도 된다 (구현 단계에서 실기 확인).
- 웹앱 알림에서는 버튼이 Chrome/Edge/Opera에서만 표시되므로, iPhone의 버튼은 **ntfy 앱 알림**에서 누른다.

## 4. 설정 — 코인자동매매의 ntfy 설정을 참고

코인자동매매 프로젝트(`../코인자동매매`)에서 ntfy를 이미 운영했으므로 **같은 구조·규칙을 그대로 따른다.**

| 코인자동매매 | 이 프로젝트 | 비고 |
|---|---|---|
| `NTFY_SERVER = "https://ntfy.sh"` (config/settings.py) | `ntfy_server` | 동일 |
| `NTFY_TOPIC` (.env, git 제외) | 답변 토픽 | 폰이 구독하는 토픽 |
| `NTFY_APPROVAL_TOPIC` (폰 버튼 → 루프) | 피드백 토픽 | 같은 원리: 알림 버튼이 별도 토픽으로 발행 |
| — | 질문 토픽 | 새로 추가 |
| `NTFY_TOKEN` (보호 토픽만, 공개 토픽이면 비움) | `ntfy_token` | ntfy.sh 공개 토픽이므로 비워 둠 |
| JSON 본문 발행, 실패 시 예외 없이 로그만 | 동일 | |
| 비밀값(토픽·토큰)은 git 제외 | 동일 | 토픽이 곧 비밀번호 |

나머지 LLM 관련 항목:

| 키 | 기본값 | 설명 |
|---|---|---|
| ollama_url | `http://127.0.0.1:11434` | |
| model | `qwen3:8b` | |
| num_ctx | `24576` | 토큰 수 |
| keep_alive | `30m` | 마지막 질문 후 VRAM 유지 시간 |
| think | `false` | |
| doc_path | `업무프로세스.txt` | UTF-8 / 메모장 ANSI(cp949) 모두 읽음 |

## 5. 구현 계획

### 5.1 기술 선택

- **Python 3.11 표준 라이브러리만** (`urllib`, `json`) → pip 설치 불필요. 집 PC에 이미 Python 3.11이 있음.
- 실행: `run.bat` (`chcp 65001` + `py bot.py`). Windows `python3`는 스토어 스텁이라 쓰지 않는다.

### 5.2 파일 구성 (예정)

```
업무프로세스-ntfy-챗봇/
├── 계획서.md            # 이 문서
├── README.md            # 설치·사용법
├── bot.py               # 봇 본체
├── run.bat              # 실행
├── 설정 파일            # 4절 항목 (토픽·토큰은 git 제외)
├── 업무프로세스.txt     # 문서 (git 제외)
├── state.json           # 마지막 처리 메시지 ID (git 제외)
└── logs/                # (git 제외)
    ├── qa.jsonl         # 모든 질문·답변·토큰 수
    ├── unanswered.jsonl # 미답변 질문
    ├── feedback.jsonl   # 👍/👎 + 해당 질문·답변
    └── errors.jsonl     # LLM 호출 실패
```

### 5.3 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | Ollama 설치, **`ollama pull qwen3:8b`** | `ollama run qwen3:8b` 응답, `ollama ps` 100% GPU |
| 2 | bot.py 작성 (설정·워밍업·구독·답변·피드백·로그) | 모의 ntfy/Ollama 서버로 로컬 테스트 통과 |
| 3 | 첫 실행 → 토픽 생성, 문서 배치 | 워밍업 로그에 토큰 수 출력, 90% 경고 없음 |
| 4 | 휴대폰에 답변 토픽 구독, 질문 토픽으로 발행 (Android 앱 / iPhone 웹앱) | 질문 → 답변 알림 수신 |
| 5 | 검증 질문 세트 실행 (아래 6절) | 기준 충족 |
| 6 | 윈도우 시작 시 자동 실행 (작업 스케줄러) | 재부팅 후 질문 응답 |

## 6. 검증 기준

1. **문서 안 질문 10개** → 모두 문서 내용과 일치하고 `(근거: …)` 표시.
2. **문서 밖 질문 5개** (예: 일반 상식, 다른 회사 규정) → 모두 "문서에 없는 내용입니다." + `unanswered.jsonl`에 기록.
3. 👍/👎 버튼 → `feedback.jsonl`에 질문·답변과 함께 기록. **Android 앱·iPhone 앱 각각** 확인.
4. 1,300자 넘는 답변 → 나눠서 순서대로 도착.
5. 봇 종료 중 보낸 질문 → 재시작 후 답변 도착.
6. 응답 시간: 첫 질문(모델 적재 포함)과 이후 질문 각각 측정해 기록. 목표는 이후 질문 30초 이내.

## 7. 검토 후 제외한 항목

### 대화 맥락 이어가기 — 제외

| 영향 | 크기 | 이유 |
|---|---|---|
| 속도 | 작음 | 앞부분(문서+이전 대화)은 Ollama 캐시를 재사용하므로 새로 붙은 부분만 계산 |
| 컨텍스트 여유 | **큼** | 문서가 이미 24K 중 약 1만~1.6만 토큰을 차지 → 대화 5~10턴이면 가득 차서 오래된 대화를 버리는 처리가 필요 |
| 답변 정확도 | **큼** | 8b 모델은 입력이 길어질수록 지시 준수가 약해지고, 이전 답변을 문서 내용처럼 인용해 "문서 근거만" 규칙이 깨질 위험 |
| 구현 | 중간 | ntfy에는 대화방 개념이 없어 "새 대화" 구분 규칙을 따로 만들어야 함 |

→ 성능 영향이 커서 **제외**. 질문은 하나씩 독립 처리한다.
