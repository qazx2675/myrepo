## 4. KV 캐시·VRAM 추정

식: KV bytes = 레이어 x KV헤드 x 헤드차원 x 2(K,V) x 2B(f16) x 토큰.

- gemma3: 48x8x256x2x2 = 393,216 B/토큰 (0.375MiB)
  - SWA 미적용(전 레이어 전체 캐시) 가정: 16k = 6.0GiB, 24k = 9.0GiB
  - SWA 적용(글로벌 8레이어 전체 + 로컬 40레이어 1024토큰): 16k = 1.0 + 0.31 = 약 1.3GiB, 24k = 1.5 + 0.31 = 약 1.8GiB
- exaone: 32x8x128x2x2 = 131,072 B/토큰 (0.125MiB): 16k = 2.0GiB, 24k = 3.0GiB

총 VRAM 추정 = 가중치 + (gemma3만 비전 projector 약 0.85GB) + KV + 컴퓨트 버퍼 약 0.5GB. (GB 단위, 반올림)

| 모델 | 가중치 | 16k 총합 | 24k 총합 | 12GB 판정(예상) |
|---|---|---|---|---|
| gemma3:12b-it-qat (SWA 적용) | 8.9 + 0.85 | 약 11.7GB | 약 12.2GB | 16k 빠듯, 24k 초과 가능 |
| gemma3:12b-it-qat (SWA 미적용) | 8.9 + 0.85 | 약 16.7GB | 약 19.9GB | 부분 CPU 오프로드 불가피 |
| exaone3.5:7.8b q8_0 | 8.3 | 약 11.0GB | 약 12.0GB | 16k 빠듯하게 가능, 24k 초과 가능 |

참고: 12GB 카드는 Windows 디스플레이/다른 프로세스가 약 0.5~1GB를 쓰므로 실사용 가능 약 11GB 가정. 두 모델 모두 16k에서 여유가 거의 없다. OLLAMA_KV_CACHE_TYPE=q8_0 + OLLAMA_FLASH_ATTENTION=1 사용 시 KV 절반 -> 후속 검증에서 시험할 것(gemma3 비전 projector는 텍스트 전용이면 영향만 있고 제거 불가).
8.5k 토큰 프롬프트면 num_ctx 12288~16384로도 충분하므로 16k 기준을 우선 검증한다.

## 5. 한계·판단

- 사용자 조건("Q4 14B 제외, 기존 9B Q8보다 확실히 나아야 함")에 맞는 qwen3 14b Q5/Q6, phi4 Q5/Q6 은 라이브러리에 없다. 그 이상(Q8, 13~16GB)은 12GB VRAM에 들어가지 않는다.
- exaone3.5 7.8B Q8은 파라미터 수가 qwen3.5 9B보다 작아 "확실히 낫다"는 보장이 없고 한국어 특화 이점에 기대는 후보다. gemma3 12B QAT가 크기 면에서 유일한 12B급 대안이다.
- 둘 다 품질 우위는 미검증이다. 후속 단계(S3 이후): 100% GPU 적재 여부(`ollama ps`), 16k/24k 실제 VRAM, 응답 10초 이내 여부, 25KB 문서 꼬인 질문 정확도를 qwen3.5:9b-q8_0 과 비교.
