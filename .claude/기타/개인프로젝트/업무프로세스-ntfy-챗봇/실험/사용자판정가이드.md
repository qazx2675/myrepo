## 1. 무엇을 판정하나

- 자동 게이트(속도, 적재, 문서 밖 거절, 미답변율)는 **안전 항목만** 봅니다. 답변이 정확한지, 자연스러운지는 게이트가 판단하지 않습니다.
- 최종 모델은 사용자가 비교표를 보고 직접 고릅니다 (계획서 §7).
- 게이트 결과와 임시 선정 근거는 `실험/04_임시선정.md` 에 있습니다.

## 2. 비교표 위치

| 파일 | 내용 |
|---|---|
| `실험\S4_stage2\비교표.md` | 질문마다 후보 답변이 나란히 있습니다. 각 답변 블록 아래의 `- 판정:` 줄과 `- 메모:` 줄에 기호를 적습니다. |
| `실험\S4_stage2\비교표.csv` | 같은 내용을 표로 정리한 파일입니다. 4행이 열 제목(ID, 질문, 모델, 변형, 답변, 소요초, 오류, 판정, 메모)이고, 판정과 메모 열에 적습니다. 1~3행은 문서 정보입니다. |

- 한 행이 "질문 1개 × 후보 1개" 입니다. ID 열의 값(예: `G1`)으로 질문을 찾습니다.
- `.md` 와 `.csv` 는 별개 사본입니다. 한쪽에 적은 판정은 다른 쪽에 자동 반영되지 않으니 **한 파일에만** 적으세요.
- **주의**: 비교표는 14:01:36에 만들어졌습니다. 그 뒤 `qwen3.5:9b-q8_0 / P1_nothink_ctx16k` 실행이 42건 모두 끝났지만(14:02:41), 비교표에는 그 변형이 **26건만** 들어 있습니다. 나머지 16건은 `실험\S4_stage2\runs.jsonl` 에서 확인하거나 비교표를 다시 만든 뒤 판정하세요.

## 3. 판정 기호

| 기호 | 뜻 |
|---|---|
| ◎ | 매끄러움: 문서 내용에 맞고 자연스럽게 읽힙니다. |
| ○ | 정확하나 딱딱함: 내용은 맞지만 문장이 기계적이거나 문서를 옮겨 적은 것에 가깝습니다. |
| △ | 일부 오류: 대체로 맞지만 틀린 부분이나 빠진 부분이 있습니다. |
| × | 오답·지어냄: 틀린 답이거나, 문서에 없는 내용을 있는 것처럼 답했습니다. |

- 문서 밖 질문에 `문서에 없는 내용입니다.` 로 거절한 것은 정상입니다.
- 문서에 답이 있는 질문을 거절했다면 △ 이상으로 적는 것을 권장합니다. (이 기준은 이 문서의 제안이며, 계획서에 정해진 규칙은 아닙니다.)
- 거절 여부는 문장 패턴으로 세었으므로, 거절 문구의 의미는 직접 읽고 판단하세요.

## 5. 판정 후 모델 교체

1. 판정 기호를 후보별로 세어 가장 나은 후보를 고릅니다. 기호를 점수로 바꾸는 규칙은 정해 두지 않았으므로, 개수를 나란히 놓고 직접 판단하세요.
2. `D:\업무프로세스\.env` 를 메모장으로 엽니다. 수정 전에 같은 폴더에 `.env.bak` 으로 복사해 둡니다.
3. `MODEL=` 줄만 선택한 모델 태그로 바꿉니다. 예: `MODEL=qwen3.5:9b-q6_K`
   - gemma3 를 고르면 `NUM_CTX=16384` 도 함께 바꿉니다.
   - 모델이 Ollama 에 없으면 먼저 `ollama pull <태그>` 를 실행합니다.
4. 챗봇을 재시작합니다: `[4] 챗봇_중지.bat` 실행 후 `[3] 챗봇_시작.bat` 실행.
5. 확인: 시작 로그의 `모델:` 과 `컨텍스트:` 값을 보고, `ollama ps` 의 PROCESSOR 열이 `100% GPU` 인지 확인합니다.

**주의**
- 환경변수 `MODEL` 이 설정돼 있으면 `.env` 의 값은 무시됩니다. 시작 로그의 모델명이 바뀌었는지 반드시 확인하세요.
- 봇은 누락된 설정 키를 채우면서 `.env` 를 다시 씁니다. 그때 주석이 지워질 수 있습니다.
- 교체 후에는 실제 질문 몇 개를 직접 보내 답변을 확인하세요.
