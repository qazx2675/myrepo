## 4. 설계 방향

```
[개인 토픽 A..G] ──▶ bot.py ──▶ [FIFO 큐] ──▶ 질문 정리(약어/오타/후속 보정)
                                                 │
                              시스템 프롬프트(문서 전체, 접두 캐시 재사용)
                                                 │
                         사용자별 최근 3턴 + 질문 ──▶ Ollama ──▶ 개인 토픽으로 답변
```

1. **프롬프트 재설계**: 추출형 → "문서를 이해한 동료 엔지니어" 서술. 규칙은 최소화(근거 밖 금지, 부분 근거 명시, 조항 기호 비노출). 고정 예시 1개가 답을 오염시키는지 변형 실험(예시 제거/유형별 예시).
2. **질문 정규화**: 용어사전(ITOM/CF/AWX 등)과 약어(`lpage`, `os설치`)를 질문에 보강. 단순 사전 치환 우선, 모델 호출 추가는 속도 게이트 통과 시에만.
3. **문서 전체 주입 유지**: 8.5k 토큰이므로 RAG 불필요. 시스템 프롬프트를 고정 접두로 유지해 Ollama KV 접두 캐시 재사용 → 응답 속도 확보. (RAG는 문서가 3배 이상 커질 때 재검토)
4. **thinking 제어**: `think:false`(또는 짧은 예산) vs 허용을 모델별로 측정.
5. **num_ctx 축소 검토**: 24,576 → 12~16k(문서 8.5k + 3턴 + 답변). 14B 후보의 VRAM 여유 확보 수단. 필요 시 `OLLAMA_KV_CACHE_TYPE=q8_0`.
6. **큐/동시성**: 단일 워커 직렬. 3명 동시 = 답변 10초 × 3 ≈ 30초이므로 **단일 답변 10초 이내**가 모델 채택 조건.

### S7 — (취소) 자체 ntfy 서버
- 내 PC가 곧 서버가 된다. ntfy 서버는 Go 단일 바이너리로 **유휴 RAM 수십 MB, CPU 무시, GPU 사용 없음** → 48GB(평균 30GB) 환경에서 영향 없음.
- 실제 문제는 자원이 아니라 **외부 접속**: 휴대폰이 집 밖에서 접속하려면 포트 개방/DDNS+HTTPS 또는 VPN(Tailscale 등)이 필요하다. iOS 즉시 푸시는 `ntfy.sh` 업스트림 릴레이 설정이 필요(내용이 아닌 폴링 ID만 전달).
- Windows 네이티브 서버 지원 여부는 S7에서 확인(안 되면 WSL2/Docker).
- 코드는 이미 `NTFY_SERVER`·`NTFY_TOKEN`을 지원 → 이 단계는 **가이드 + 측정**까지만 수행하고 운영 전환은 사용자 결정.

## 12. 추가 요구사항: 문서 변경·확장 대응 (2026-10-11)

> `업무프로세스.md`는 내용이 바뀌고 커질 수 있다. 봇은 문서 내용에 의존하지 않게 만든다.

| # | 요구 | 설계 |
|---|---|---|
| E1 | 문서가 바뀌어도 **코드·프롬프트 수정 없이** 반영 | 질문마다 파일 mtime/해시 확인 후 재적재(현재는 매번 읽음 → 해시 캐시로 접두 캐시 보존). 프롬프트에서 특정 절 번호·업무명(예: "7.3절", "limit/nofile") 하드코딩 **전부 제거**, 고정 예시는 문서 비의존 문구로 교체 |
| E2 | 문서가 **num_ctx를 넘도록 커져도** 동작 | 토큰 예산 가드: `문서토큰 + 맥락 3턴 + 답변 ≤ NUM_CTX×0.9`. 초과 시 `##`/`###` 제목 단위로 분할해 질문 관련 절만 선택(제목+키워드 점수, 용어사전 절은 항상 포함)하는 **절 선택 모드**로 자동 전환. 경계 이하에서는 전체 주입 유지 |
| E3 | 문서를 **여러 개**로 늘릴 수 있음 | `DOC_PATH`를 다중 경로/폴더 지원(`DOC_PATHS=파일;파일` 또는 `DOC_DIR`). 각 문서의 출처(파일명)를 근거 표기에 사용. 기존 단일 `DOC_PATH`는 호환 유지 |
| E4 | 용어·약어 사전도 문서에서 가져옴 | 질문 정규화용 사전은 문서의 용어 표(`| 약어 | 정의 |`)를 파싱해 생성. 코드에 사전 상수를 두지 않음 |
| E5 | 문서가 바뀌어도 테스트를 **재생성** 가능 | 테스트셋은 `tests/`의 파일 + `기대.md`(절 번호 근거). 문서 변경 시 기대.md의 절 번호가 깨지면 하네스가 "근거 절 소실" 경고. 문서 해시를 결과 CSV 헤더에 기록해 결과와 문서 버전을 묶음 |
| E6 | 문서 변경을 사용자가 알 수 있음 | 문서 해시 변경 시 로그(`logs/doc_changes.jsonl`)에 시각·크기·토큰수 기록, 가드 임계 도달 시 콘솔·`errors.jsonl` 경고 |
| E7 | 확장 가능한 모듈 경계 | `bot.py` 내부를 함수 단위로 분리(문서 로더 / 프롬프트 빌더 / 큐 / 사용자 / ntfy I/O). 단일 파일 유지(표준 라이브러리만)하되 외부 의존 추가 없음 |

### 단계 반영
- **S3**: 하네스에 문서 해시·토큰 수 기록, 절 선택 모드 on/off 변형(`P4`) 추가.
- **S4**: 문서를 인위적으로 3배(약 25k 토큰)로 늘린 **확장 테스트**에서 전체 주입 대비 절 선택 모드의 정확도·속도를 비교해 전환 임계 결정.
- **S5**: E1~E4, E6, E7 구현. `test_bot_mock.py`에 문서 교체·초과·다중 문서·사전 파싱 케이스 추가.
