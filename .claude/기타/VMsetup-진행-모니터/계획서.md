## 1. 요청

1. 실행 단계의 출력이 한꺼번에 쏟아져서 확인이 어렵다. **단계별 요약 모니터**로 바꾼다.
   - 세로로 단계 목록(작업 시작, 포트그룹 생성, VM 생성, …)과 각 단계 상태가 보인다.
   - **↑/↓** 로 커서 이동, **Enter** → 그 단계의 실행 결과(출력) 보기, **Enter 한 번 더** → 목록(홈)으로.
   - 참고: "vCenter VM IP 병렬 변경 및 진행 모니터링" 채팅의 진행 화면 방식.
2. **라이선스 선택**(라이선스를 골라야 하는 단계)에서는 모니터가 **잠시 종료**되고 선택 화면이 평소처럼 나온다. 끝나면 **다시 모니터로 돌아온다**.
3. 모든 작업이 끝난 뒤 **Enter 두 번** → 최종 종료.
4. 모델을 바꾸면 캐시를 처음부터 다시 읽는다는 메시지 → 모델을 바꿔도 영향이 없게(8장).

## 3. 설계

### 3-1. 적용 범위

- **모니터는 "실행 확인 y" 이후(4) 실행 단계)에만** 쓴다. 그 전의 대화형 단계(user·설치 정보·스펙·VM 표·CAE·vCenter·비밀번호·실행 확인)는 지금 그대로(스크롤 출력).
- 모니터가 켜지는 조건: 표준입력·표준에러가 둘 다 터미널이고 `VMSETUP_MONITOR=0` 이 아닐 때. 파이프 입력(`vmsetup_test.sh`)·nohup·cron 은 **지금과 똑같이 줄줄이 출력**(자동 꺼짐).
- **도구(Go) 는 한 줄도 고치지 않는다.** 전부 `vm_setup.sh`(bash) 안에서 처리 → OS6 재빌드 불필요.

- 상태: `[대기]` `[진행]`(경과 시간 증가) `[완료]`(걸린 시간) `[실패]` `[건너뜀]` `[중단]`(앞 단계 실패로 실행 안 함) `[취소]`(라이선스 `q`).
- 오른쪽 요약: 그 단계 로그의 **마지막 의미 있는 줄**(도구가 이미 "완료: 성공 N / 실패 N" 식으로 끝줄을 찍음). 스펙 체크는 `[일치]`/`[차이] FAIL n` 요약을 따로 적는다.
- 한글 폭 정렬 문제를 피하려고 **고정폭(ASCII) 칸을 앞에, 한글 이름을 뒤에** 둔다.
- 1초마다, 또는 키 입력 때 다시 그린다. 단계 수가 화면보다 많으면 커서를 따라 목록이 스크롤된다.
- 끝나면 맨 아래에 `[종료] Enter 두 번 누르면 종료` 줄이 생기고 **커서가 자동으로 그 줄로** 간다.

### 3-3. 조작

| 화면 | 키 | 동작 |
|---|---|---|
| 홈 | ↑/↓ (k/j 도) | 커서 이동 (구분선 줄은 건너뜀) |
| 홈 | Enter | 커서 단계의 **실행 결과 보기** 화면으로 |
| 결과 보기 | ↑/↓, PgUp/PgDn | 로그 스크롤(처음엔 맨 끝이 보임). 진행 중 단계면 새 줄이 계속 붙음 |
| 결과 보기 | Enter | 홈으로 |
| 홈(작업 끝) | `[종료]` 줄에서 Enter | "한 번 더 Enter 하면 종료" 안내 |
| 홈(작업 끝) | 이어서 Enter | 모니터 종료 → 원래 화면에 **최종 요약** 출력 후 종료 |
| 어디서나 | Ctrl+C 3번(5초 안) | 실행 중인 도구 종료 → 터미널 복원 → 요약 출력, 종료코드 130 (선례와 동일) |

- 작업이 끝났을 때 커서가 `[종료]`에 있으므로 **Enter 두 번이면 바로 종료**, 다른 단계 결과를 보고 싶으면 ↑ 로 올라가서 Enter.

### 3-4. 실행 구조 (bash)

- 단계 목록을 먼저 만든다: `STEP_LABEL[i]`, `STEP_FN[i]`(함수 이름), `STEP_ARG[i]`(스펙 번호 등), `STEP_TTY[i]`(1 = 사용자 입력이 필요한 단계).
  단계 함수: `step_vswitch`, `step_vm_create k`, `step_mac_info k`, `step_power k`, `step_affinity k`, `step_lpage k`, `step_license`, `step_check`, `step_mac_copy`.
  → **모니터 모드와 기존(줄줄이) 모드가 같은 단계 목록·같은 함수를 쓴다**(로직 두 벌 안 만듦).
- 각 단계 출력은 `run_<user>/logs/NN_<단계>.log` 에 저장, 전체는 `run_<user>/run.log` 에도 순서대로 이어붙임. 실행 계획 텍스트도 `run_<user>/plan.txt` 로 저장("작업 시작" 줄에서 Enter 하면 보임).
- 모니터 모드 실행 루프:
  1. 일반 단계: `"$fn" $arg > log 2>&1 &` 로 백그라운드 실행 → 전경에서 모니터 루프(그리기 + `read -rsn1 -t 0.5 < /dev/tty` 로 키 처리) → 끝나면 `wait` 로 종료코드 받음.
  2. **입력이 필요한 단계(라이선스)**: 대체 화면을 닫고(`tput rmcup`, `stty sane`) `=== 라이선스 할당 (모니터를 잠시 끕니다) ===` 안내 후 **전경에서** 실행(`2>&1 | tee log`, 표준입력은 터미널 그대로) → 끝나면 대체 화면을 다시 열고 모니터 복귀.
  3. 실패(종료코드 ≠ 0): 그 단계 `[실패]`, 남은 단계 `[중단]`, 커서를 실패 단계로 → 사용자가 로그 확인 후 Enter 두 번으로 종료, 종료코드 1. 최종 요약에 지금과 같은 "원인을 고친 뒤 다시 실행하면 이미 만든 것은 건너뜁니다" 안내.
- 백그라운드는 서브셸이라 부모로 값이 안 돌아옴 → 부모가 알아야 하는 것(스펙 체크 `CHECK_FAIL`, 요약 줄)은 **파일로** 전달(`run_<user>/logs/NN.note`, `run_<user>/check_fail`).
- 터미널 복원은 `trap ... EXIT INT TERM` 한 곳에서(`tput rmcup; tput cnorm; stty sane`) — 어떤 경로로 끝나도 화면이 깨진 채 남지 않게.
- OS6(bash 4.1) 호환: `read -t` 소수 초(4.0+), `tput smcup/rmcup/cup/el`, 방향키는 `ESC [ A/B`, `ESC [ 5~/6~` 를 `read -rsn1` + 짧은 타임아웃으로 조립. `mapfile`/연관배열은 이미 쓰는 중(4.0+).

### 3-5. license_assign 편입

- 위치: 스펙별 단계가 모두 끝난 뒤 **1회**(모든 BM 대상), 스펙 체크 전 — master `workflow.mmd` 의 위치.
  스펙마다 돌리면 라이선스를 스펙 수만큼 여러 번 고르게 되므로 1회로 한다.
- 평가판 호스트가 없으면 도구가 묻지 않고 끝남 → 이 경우도 모니터를 잠깐 닫았다 여는 것은 같음(7장 ② 참고).
- `q`(중단)는 도구 종료코드가 0 이라 로그의 "라이선스 할당 작업을 중단합니다." 줄로 `[취소]` 표시, **다음 단계는 계속**.
- `ensure_bin` 목록에 `license_assign` 추가, 실행 계획에 `라이선스 할당 : license_assign (BM N대, 평가판 호스트만 — 선택이 필요하면 입력)` 줄 추가.

1. `bash -n`, 모니터 끈 상태(`VMSETUP_MONITOR=0` 및 파이프 입력)로 `vm_setup.sh -u lsh` → **지금과 같은 출력·결과**(회귀 없음).

### 계획과 달라진 점 (시험 중 발견해 고친 것)

| 항목 | 계획 | 실제 |
|---|---|---|
| Ctrl+C 받는 방법 | raw 모드(`-isig`)로 0x03 키만 받음 | bash `read -n` 이 키를 기다리는 동안 ISIG 를 다시 켜서 Ctrl+C 가 **SIGINT** 로도 옴 → INT 를 trap 해 키와 똑같이 셈. 그런데 trap 때문에 백그라운드 서브셸의 SIGINT 가 기본 동작으로 돌아가 **첫 번째 Ctrl+C 에 `vm_create` 가 죽는 것**을 확인 → 백그라운드 단계를 `set -m` 으로 자기 프로세스 그룹에서 실행(안에서는 `set +m`), 강제 종료는 그룹 전체에 TERM |
| 화면 다시 그리기 | 줄 끝만 지움(`CSI K`) | 열 이동(`CSI n G`)만 하면 로그 보기 → 목록으로 돌아올 때 이전 글자가 칸 사이에 남음 → 줄마다 `CSI 2K` 로 지우고 그림 |
| 포트그룹 생성 요약 | 로그 마지막 줄 | 도구 마지막 줄이 "세션을 안전하게 종료했습니다" 라 의미 없음 → 호스트별 줄을 세어 `성공 N / 스킵 N / 실패 N`(실패는 도구의 "실패 N건"). 다른 단계는 마지막 줄에서 인사말·구분선을 빼고 사용 |
| 표준입력이 파이프일 때 라이선스 | (계획에 없음) | 입력이 끝나면 `license_assign` 이 빈 입력을 "잘못된 번호"로 보고 **끝없이 다시 묻는다** → 남은 입력 뒤에 `q` 를 붙여 넘김 |
