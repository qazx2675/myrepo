# git-upload-sk 개선 요구사항 (원문 정리)

> 상태: **인터뷰 진행 중** → 인터뷰 완료 → 계획서 작성 → 사용자 승인 후 기존 `git-upload-sk` 스킬에 반영(이 문서와 계획서는 스킬을 아직 수정하지 않음).
> 실행은 계획서 확정 후 `/jev-plan-router` 로 단계별 모델 배정.

## 0. 최우선 목표 (0순위)

**신규 작성이든 업데이트든, 아래 스크립트를 한 번 실행하는 것만으로 폐쇄환경 세팅이 끝난다.**

| 상황 | 흐름 |
|---|---|
| 신규 프로젝트 | 가이드 스크립트 실행 → 안내대로 빈 변수 입력 → 셋업 완료 |
| 기존 프로젝트 업데이트 | 패치 스크립트 적용 → (빈 변수를 건드려야 하거나 새로 추가되면) 신규와 같은 가이드 진행 → 패치 완료 |

## 1. 배경: 이번 작업에서 겪은 문제 (개선 동기)

폐쇄망이라 실제 경로·호스트·비밀번호를 개발 시점에 넣을 수 없어서, 세팅 때 아래에서 시간이 걸렸다.

| # | 문제 | 원인 |
|---|---|---|
| 1 | 빈 변수의 위치·의미 파악 | 변수가 여러 파일에 흩어짐 (Go 9개, os_check 2, 01 스크립트 1, config_check 2) |
| 2 | 체크 스크립트 연결 | 실제 쓰는 스크립트(`config_check.sh`)가 `-auto`·완료기록 미지원 |
| 3 | 패치 적용 실패 | 회사 사본이 저장소 사본과 다름 (줄·주석·마스킹된 값) |
| 4 | Go 바이너리 | 폐쇄망에 Go 없음, 값을 빌드 때만 주입 가능 |
| 5 | os8_mgmt 전달 실패 | gossh 키 인증 불가 → `-p` 비밀번호 필요 (변수 누락) |
| 6 | 현장 값 검증 | 실제 경로·서버로 테스트 불가, 스텁 검증만 |

공통 원인: **현장에서만 알 수 있는 값이 한눈에 정리돼 있지 않고, 업데이트가 현장 수정본을 덮거나 거부함.**

## 2. 신규 프로젝트: 빈 변수 입력 가이드 스크립트

- 빈 변수마다 **`read -p` 로 값을 물어보고** 적용하는 대화형 스크립트를 만든다.
- 변수마다 `echo` 로 **무엇을 설정하는 변수인지 설명 + 예시**를 먼저 보여준다.
  - 예) 체크 스크립트 경로 변수 → `예: /path/config_check.sh`
- 헷갈렸던 변수는 **정확한 동작**을 설명에 포함한다. 예: 아래 두 변수.

### 2-1. `auto_done_dir` / `auto_done_host` 정확한 동작

완료기록 = 호스트별 파일 1개에 한 줄 `epoch user sha256 source` (`source` 예: `config_check`). auto_setup 데몬이 `${AUTO_SETUP_DIR:-/tmp/auto_setup}/done/<호스트>` 를 읽어 "체크 스크립트가 끝낸 호스트"로 인정한다.

| 변수 | 누가 기록하나 | 어디에 기록하나 | 언제 채우나 |
|---|---|---|---|
| `auto_done_dir` | 스크립트가 **자기 서버의 로컬 디렉터리**에 직접 기록 (임시파일→`mv` 원자 기록) | `<auto_done_dir>/<호스트>` — **데몬이 읽는 `done/` 디렉터리와 같은 경로**여야 함 (보통 os8_mgmt 에서 `/tmp/auto_setup/done`) | 스크립트가 **데몬이 있는 서버(os8_mgmt)에서 실행**될 때 |
| `auto_done_host` | 스크립트가 **gossh 로 해당 서버에 접속해** 대신 기록 | `<auto_done_host>` 서버의 `${AUTO_SETUP_DIR:-/tmp/auto_setup}/done/<호스트>` | 스크립트가 **다른 서버(os6_mgmt 등)에서 실행**되어 데몬 서버로 보내야 할 때 |
| 둘 다 빈 값 | 아무 동작 없음 (출력·파일 없음) | — | 완료기록을 쓰지 않을 때 |

- **autofs 로 한 스크립트를 os8_mgmt·os6_mgmt 가 공유**하면 서버별로 값을 다르게 못 채우므로 `auto_done_host` 만 채운다 (os8_mgmt 에서 실행돼도 자기 자신에게 gossh).
- `auto_done_dir` 을 채운 채 os6_mgmt 에서 실행하면 os6 로컬에 기록돼 **데몬이 못 본다**.
- 기록 대상: 설정 적용 후 재체크 결과에 **에러 없이 나온 호스트**만. ERROR·접속불가 호스트는 기록하지 않음.
- gossh 인증이 키로 안 되면 `auto_setup_gossh_pw` (gossh `-p`) 도 필요.

## 3. 기존 프로젝트: 업데이트 패치 스크립트

이번에 **패치 적용 스크립트가 큰 도움**이 되었다. 이를 표준으로 만든다.

1. **마스킹된 항목 불변**: 현장 사본에서 `OO` 처럼 마스킹·수정해 둔 값(벤더 문자열, 경로, 주석, 코멘트 문구)은 건드리지 않고 업데이트 내용만 반영한다. 바뀌게 되면 **적용하지 않고 중단**한다 (대상 파일 불변).
2. **현장 작업 방식에 맞춘 줄바꿈 처리**: 사용자는 쉘 스크립트를 **복사해 vim 에 붙여 넣고 줄바꿈(`\r`)을 모두 제거**해서 쓴다. 패치 스크립트는 이 방식으로 만든 사본(LF)에 그대로 적용되어야 하고, CRLF 입력도 처리해야 한다.
3. **빈 변수 연동**: 업데이트에 **빈 변수 변경·추가**가 포함되면 2장과 같은 **가이드(설명·예시·`read -p`)** 를 띄워 값 입력을 돕는다.
4. 실패 시 **어느 줄이 달라서 못 넣었는지** 화면에 출력한다 (이번에 추가한 진단 출력).

## 4. 스킬 반영 방침

- 위 내용은 기존 `git-upload-sk` 스킬에 **추가**한다 (기존 README 순서·Disclaimer·CI·ARCHITECTURE·PR_CHECKLIST·WORKFLOW·setup.sh·사용법.txt 규칙은 유지).
- 순서: 이 문서 → **인터뷰**(완벽해질 때까지 반복) → **계획서** → 사용자 최종 승인 → 스킬 업데이트.
- 실제 환경 값은 저장소에 커밋하지 않는다 (빈 변수는 빈 값으로 커밋, 비밀번호 포함).

## 6. 인터뷰 결정 사항 (1~4라운드)

| # | 주제 | 결정 |
|---|---|---|
| 1 | 스크립트 구조 | **변수 목록(manifest) 1개 + 공용 스크립트**. 프로젝트에는 manifest 만 두고 가이드/패치 스크립트는 스킬이 만드는 같은 틀을 사용 |
| 2 | 디렉터리 | **conf 가 있으면 `conf/` 안, 없으면 새 `setup/`**. 이 디렉터리에는 **가이드/패치 스크립트(+ conf 의 경우 설정파일·예시)만** 둔다. 프로젝트 루트는 깨끗하게 유지 |
| 3 | 값 적용 방식 | 쉘 스크립트의 `var=""` 는 **소스에 직접 치환**, Go 등 빌드 언어는 **conf 파일**(이번 auto_setup 방식과 동일) |
| 4 | 업데이트 보존 방식 | **앵커 기반 삽입·치환**. 마스킹된 현장 수정·주석·코멘트는 건드리지 않고, 앵커를 못 찾으면 중단하고 위치 안내 |
| 5 | 입력 사본 | **vim 으로 `\r` 제거한 LF 사본**(CRLF 가 섞여도 자동 제거 후 처리, 결과는 LF) |
| 6 | 패치 형태 | **버전별 자체포함 단일 스크립트**(복사·붙여넣기 1회 반입). 엔진+이번 변경 명세를 한 파일에 포함 |
| 7 | 패치 생성 | 스킬이 제공하는 **생성기(`make_update.sh`)로 이전→신규 변경 + manifest 에서 자동 생성**, 사람 검토 단계 포함 |
| 8 | 가이드 동작 | **현재값 표시 + Enter 유지**, **비밀번호 입력 마스킹(`read -s`)**, **값 검증(경로 존재·호스트 응답·형식)** |
| 9 | 점검 범위 | **정적 검증 + 연결 점검**(변수별 정상/이상(이유) 표, 이상 변수만 재입력·건너뛰기). **전체 dry-run 은 프로젝트가 안전한 `--dry-run` 을 지원할 때만** (설정 적용 스크립트는 그대로 돌리지 않음) |
| 10 | 변수 관계 | manifest 에 **택일(하나만)·의존(A 가 있으면 B 필수) 그룹** 선언. 가이드는 `auto_done_dir`/`auto_done_host` 처럼 **상황 질문**("이 스크립트는 어느 서버에서 실행?")으로 하나만 채움 |
| 11 | 역할 프로필 | **역할(os8/os6/공통) 선택 후 그 역할의 변수만 질문** |
| 12 | 업데이트 시 변수 변경 | **신규·변경된 변수만 질문**, 기존 값 자동 이전(이름 변경은 rename map), 삭제된 변수는 유지하되 경고 |
| 13 | 지원 환경 | **bash + sed/awk/grep 만, RHEL6 bash 4.1 호환** (python·perl 없음) |
| 14 | 롤백 | **자동 `.bak`(타임스탬프) + 실패 시 자동 복구 + `--undo`** |
| 15 | 실행 범위 | 변수 적용 → 점검 → **`setup.sh`(빌드·설치·cron) 자동 이어서 실행(y/n 확인)** → 요약 출력 |
| 16 | 색상 | 가독성을 위한 **색상 적용**. 이 내용을 **스킬 규칙에도 포함** (가이드/패치 출력의 색 규칙) |
| 17 | 비밀번호 저장 | **소스에 평문 기록 + 파일 권한 600 + "저장소 커밋 금지" 경고**. 화면·로그·백업 출력에는 마스킹 |
| 18 | 파일럿 | **config_check 하나만** 예시로 제작. 이번 인터뷰는 스킬 제작이 목적이며, 앞으로 프로젝트를 만들 때 세팅 시간을 줄이기 위함 |
| 19 | 완료 기준 | 신규(가이드 1회로 설치까지) + 업데이트 보존 + 입력 이상 + RHEL6 bash 4.1 호환 (4가지 모두) |
| 20 | 색 규칙 | 의미별 고정 색 + `NO_COLOR`/비tty 면 끔 |
| 21 | 디렉터리 내용 | `setup/`·`conf/` 에는 **패치에 필요한 스크립트와 파일만** (manifest 허용, 그 외 금지) |
| 22 | 빈 변수 5개 이하 | 실제로 가이드를 실행할지 `y/n` 으로 먼저 묻는다 (n 이면 변수 목록·위치만 안내) |
| 23 | setup.sh 없음 | 설치 단계 건너뜀 (보통 `setup.sh` 는 Go 프로젝트에만 있음) |
