# 계획서 — 스펙(SPEC_DIR)으로 affinity / lpage 제외 (전체·ev별)

- 대상: `.claude/VM/V2` (VMsetup + vm-param-check)
- 작성일: 2026-10-30

## 요청

- 지금은 affinity / lpage 를 안 쓰려면 `vm_setup.sh -del_affinity -del_lpage` 로 실행한다. 이 옵션은 **그대로 둔다**.
- 스펙 파일에 아래 키를 넣으면 알아서 제외된다.
  - `all_del_affinity=y`, `all_del_lpage=y` → 그 스펙의 모든 ev
  - `evNN_del_affinity=y`, `evNN_del_lpage=y` → 그 ev 만
- 예: `ev01_del_affinity=y` 이고 ev03 까지 있으면 ev01 은 affinity 제외·lpage 적용, ev02~ev03 은 스펙대로 모두 적용.
- vm-param-check(단독 체크 포함)에도 같은 규칙이 적용돼야 한다.

## 인터뷰로 확정한 것

| 항목 | 결정 |
|---|---|
| 제외 동작 | 기존 `-del_affinity` / `-del_lpage` 와 같다. affinity 값 삭제. lpage 는 HugePage 5개 키 삭제, CPU 토폴로지(cores/socket/numa, `numa.vcpu.maxPerVirtualNode`)는 계속 적용 |
| 체크 | ev별 부재 확인 — 제외된 ev 만 "값이 없어야 OK", 나머지 ev 는 평소대로 |
| affinity 파일 | 제외된 ev 는 `affinity-evNN` 이 없어도 된다 |
| 키 문법 | 네 형태만, 값은 `y` 만 (범위·`n` 없음). 그 외 값, 그룹 수보다 큰 ev 번호는 오류 |
| 명령줄 옵션 | `-del_affinity` / `-del_lpage` 를 주면 스펙과 상관없이 모든 ev 제외(지금과 같음) |

## 단계

1. **vm-param-check 스펙 해석(config)** — `ParseSpecFile` 결과에서 `all_del_*` / `evNN_del_*` 를 인식(값 `y` 만). `applySpecOptions` 는 이 키를 플래그로 넘기지 않고 건너뜀. `-specExport` 는 ev 로 펼쳐 `del_affinity-evNN=y`, `del_lpage-evNN=y` 로 내보냄(그룹 수 넘는 ev 는 오류). 제외된 ev 는 `affinity-evNN` 이 없어도 됨. 단위 테스트.
2. **vm-param-check 체크(checker/main)** — 스펙에서 읽은 제외 ev 를 `expectSet` 에 담아, 그 ev 의 VM 만 lpage/affinity 부재 확인(`CheckFixed` 와 affinity 분기). 전역 `-expectNoLpage` / `-expectNoAffinity` 는 지금처럼 전체 적용. 단위 테스트.
3. **affinity_setting / lpage_setting** — ev 를 골라 삭제하는 옵션 추가(`-del_affinity_evs=ev01,ev03`, `-del_lpage_evs=...`). 목록의 ev 는 삭제 모드, 나머지는 평소 설정. 기존 `-del_affinity` / `-del_lpage`(전체)는 그대로. 제외된 ev 는 affinity 파일 검사 안 함.
4. **vm_setup.sh** — `build_flags` 가 내보낸 `del_*-evNN` 을 읽어 위 옵션을 만든다. 명령줄 `-del_*` 가 있으면 전체. 제외 ev 는 `affinity-evNN` 필수 검사에서 뺀다. 실행 계획 출력에 제외 ev 를 보여준다. 체크 단계는 스펙 기반이라 추가 인자 없이 vm-param-check 가 처리.
5. **랩 검증(.58 vcsim)** — `ev01_del_affinity=y` + ev03 스펙, `all_del_lpage=y`, 키 없음(기존과 동일), 잘못된 값 오류. 설정 결과와 체크 결과 확인.
6. **마무리** — OS6 재빌드(affinity_setting, lpage_setting, vm-param-check) 바이너리 커밋, CHANGELOG·README 반영, master push, V2 브랜치 갱신. (workflow.svg 는 요청 시)
