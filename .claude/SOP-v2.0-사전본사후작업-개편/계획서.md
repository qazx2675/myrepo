# SOP(표준운영절차서) 자동 생성 프로그램 수정 마스터 계획서 (v2.0 최종본)

> **문서 목적:** 본 계획서는 사람의 중간 개입 없이(Zero-Human-Intervention) 기존 v1.2 소스코드를 v2.0 실전 양식(`사전작업`·`본작업`·`사후작업` 3단 구조 및 8개 컬럼 체제)에 맞게 전면 개편하고, 단일 `.exe` 파일 빌드 및 One-Shot 통합 자동 검증까지 완수하기 위한 자율 실행형 기술 명세서입니다.

---

## 1. 핵심 아키텍처 변경 및 동작 원리

### 1.1 폐쇄망 제약 준수 및 `Target` 파일 단독 베이스 복제 방식
1. **외부 표준 양식(Template) 파일 개념 폐기:**
   * 기존 v1.2의 기본 양식 생성 및 별도 양식 파일 업로드 기능을 완전히 제거함.
   * `target` 엑셀 파일의 **각 시트 안에는 이미 `사전작업`, `본작업`, `사후작업` 3개 섹션과 8개 컬럼 표 구조가 모두 완비**되어 있음.
2. **새 통합문서 기반 100% 동일 양식·글꼴 복제:**
   * 폐쇄망(DRM) 환경에서 기존 파일을 직접 수정(In-place Modify)하지 않고, `target` 엑셀을 Read-Only로 연 뒤 **첫 번째 선택된 시트(기준 시트)를 새 통합문서(`newWb`)의 첫 시트로 통째로 복사(`baseSheet.Copy(nil, newWb.Sheets(1))`)**함.
   * 복사된 새 시트에서 `사전작업`, `본작업`, `사후작업`의 데이터 병합 셀 내부 기존 값과 도형/이미지만 초기화(ClearContents & 기존 데이터 영역 내 Shape 제거, 단 **셀의 글꼴 이름, 글꼴 크기(예: 11pt, 14pt 등), 테두리, 정렬, 열 너비, 병합 상태는 100% 보존**)한 뒤, 선택된 시트들의 내용을 순서대로 쌓아 올리고 프로그램(`.exe`) 폴더에 지정한 파일명으로 `SaveAs` 저장함.

### 1.2 시트 내부 구조 및 유동적 탐색(Dynamic Discovery) 명세
각 `target` 시트 내부에는 고정된 셀 주소가 아닌 유동적인 행/열 위치에 아래 3개 섹션이 순서대로 존재함:
1. **섹션 타이틀 병합 행:** 셀 텍스트(공백 제거 기준)가 각각 **`사전작업`**, **`본작업`**, **`사후작업`** 인 병합 셀 행.
2. **컬럼 헤더 행:** 각 섹션 타이틀 아래쪽에 위치하며 아래 8개 열 헤더를 가짐.
   * `Step` | `작업내용` | `작업자에 의한 사전 작업 내용` | `작업대상` | `검증방법` | `작업자` | `검증자` | `작업결과`
3. **데이터 병합 셀 블록 (`DataMergeRange`):**
   * 각 섹션의 **컬럼 헤더 행 바로 아래 행(`HeaderRow + 1`)**부터 시작하는 세로 병합 셀 블록 (예: `B11:B16`, `C11:C16`, `D11:D16`, `E11:E16`, `F11:F16`, `G11:G16`, `H11:H16`, `I11:I16`).
   * `사전작업`, `본작업`, `사후작업` 모두 동일하게 각자의 컬럼 헤더 바로 아래에 데이터 병합 셀 블록을 가짐.

## 2. 데이터 매핑 및 병합 셀 적재(Stacking) 상세 규칙

### 2.1 8개 컬럼별 데이터 처리 규칙

| 컬럼명 | 데이터 소스 및 동작 방식 | 비고 |
| :--- | :--- | :--- |
| **`Step`** | **자동 고정 생성:** `사전작업` = **`1`**, `본작업` = **`2`**, `사후작업` = **`3`** | 선택된 시트 개수와 무관하게 각 섹션에 `1`, `2`, `3` 고정 기입 |
| **`작업내용`** | 선택한 시트들의 해당 섹션(`사전`/`본`/`사후`) 내 `작업내용` 병합 셀 내용을 선택 순서대로 적재 | **`1. [시트이름]`**, **`2. [시트이름]`** 헤더 자동 부착 후 원본 텍스트·글꼴·서식·이미지 복사 |
| **`작업자에 의한 사전 작업 내용`** | 선택한 시트들의 해당 섹션(`사전`/`본`/`사후`) 내 `작업자에 의한 사전 작업 내용` 병합 셀 내용을 선택 순서대로 적재 | **`1. [시트이름]`**, **`2. [시트이름]`** 헤더 자동 부착 후 원본 텍스트·글꼴·서식·이미지/도형 복사 |
| **`작업대상`** | UI의 **`작업대상` 텍스트 상자**에 사용자가 입력한 값을 그대로 기입 | `사전`/`본`/`사후` 각 섹션의 `작업대상` 병합 셀에 기입 |
| **`검증방법`** | 선택한 시트들의 해당 섹션(`사전`/`본`/`사후`) 내 `검증방법` 병합 셀 내용을 선택 순서대로 적재 | **`1. [시트이름]`**, **`2. [시트이름]`** 헤더 자동 부착 후 원본 텍스트·글꼴·서식·이미지 복사 |
| **`작업자`** | `config.json`에 저장된 **`작업자` 이름**을 그대로 기입 | `사전`/`본`/`사후` 각 섹션의 `작업자` 병합 셀에 기입 |
| **`검증자`** | UI의 **`검증자` 텍스트 상자**에 사용자가 입력한 값을 그대로 기입 | `사전`/`본`/`사후` 각 섹션의 `검증자` 병합 셀에 기입 |
| **`작업결과`** | 빈칸(공란) 유지 (원본 시트에 기본 텍스트가 없다면 비워둠) | 서식 및 병합 유지 |

### 2.2 다중 시트 선택 시 섹션별 단일 병합 셀 내 순서 적재 알고리즘
사용자가 예를 들어 **[시트A] → [시트B]** 순서로 2개 시트를 선택했을 때:
1. **섹션 단위 루프 (`Section` $\in$ `["사전작업", "본작업", "사후작업"]`):**
   * 결과 시트에서 현재 `Section`의 데이터 병합 영역(`DataStartRow ~ DataEndRow`)을 찾음.
   * **`Step` 열 기입:** `사전작업`이면 `"1"`, `본작업`이면 `"2"`, `사후작업`이면 `"3"`을 기입 (원본 셀의 폰트 이름 및 크기 그대로 유지).
   * **`작업대상`, `작업자`, `검증자` 열 기입:** 입력된 텍스트를 각 병합 셀의 좌상단 셀에 기입 (원본 셀의 폰트 이름 및 크기 그대로 유지).
2. **고정 3개 열(`작업내용`, `작업자에 의한 사전 작업 내용`, `검증방법`)의 다중 시트 적재 루프:**
   * 각 대상 열(`Col` $\in$ `[TaskNameCol, PreTaskDetailCol, VerifyMethodCol]`)에 대해:
     * 선택된 시트 순서(`idx = 1..N`, `sheetName`)대로 순회하며:
       1. 해당 원본 시트에서 동일 `Section`(`사전작업`/`본작업`/`사후작업`)의 동일 열(`Col`) 데이터 병합 셀(`srcMergeArea`)을 찾음.
       2. **텍스트 및 글꼴 크기 보존 적재:**
          * 블록 헤더 **`"{idx}. {sheetName}"`**와 `srcMergeArea`의 본문 텍스트를 조합하여 결과 병합 셀(`dstMergeArea`)에 누적 기록함.
          * 이때 **원본 `srcMergeArea`의 글꼴 이름(`Font.Name`), 글꼴 크기(`Font.Size` — 예: 14pt면 14pt, 11pt면 11pt), 굵기(`Font.Bold`), 색상(`Font.Color`)을 `Characters(start, length).Font` 속성으로 정확히 복제**하여 원본과 100% 동일한 글꼴/크기가 유지되도록 함.
       3. **셀 내부 이미지/도형(`Shapes`) 수직 적재(Vertical Stacking):**
          * `srcMergeArea`의 경계(`Left`, `Top`, `Width`, `Height`) 안에 포함된 모든 `Shape`(이미지, 도형, 텍스트박스 등)를 추출함.
          * 현재 시트 순서(`idx`)의 텍스트 블록 시작 Y 오프셋(`cumulativeOffsetY`)을 기준으로, 원본 셀 내에서의 상대 좌표(`relX = shape.Left - srcMergeArea.Left`, `relY = shape.Top - srcMergeArea.Top`)를 계산하여 `dstMergeArea.Left + relX`, `dstMergeArea.Top + cumulativeOffsetY + headerHeight + relY` 위치에 정확히 복사·배치함.
          * 다음 시트(`idx + 1`)의 내용이 이전 시트의 텍스트나 이미지와 절대 겹치지 않도록 `max(텍스트 높이, 이미지 하단 Y좌표) + 여백(Padding)`만큼 `cumulativeOffsetY`를 누적 증가시킴.
   * **행 높이(`RowHeight`) 자동 확장:**
     *当該 섹션(`사전`/`본`/`사후`)의 3개 열 중 가장 큰 `cumulativeOffsetY` 총 높이를 수용할 수 있도록, 해당 섹션의 병합된 데이터 행들(`DataStartRow ~ DataEndRow`)의 행 높이를 균등 분할(또는 하단 행 확장)하여 모든 텍스트와 이미지가 병합 셀 테두리 안에 잘리지 않고 들어가도록 자동 조정함.

## 3. 유동적 섹션 및 컬럼 스캐너 상세 구현 명세 (`excel_com.go`)

고정 셀 주소를 일절 사용하지 않고 모든 위치를 찾아내는 스캐너 구조체 및 로직입니다.

```go
type SectionColumns struct {
    StepCol          int // "Step"
    TaskNameCol      int // "작업내용"
    PreTaskDetailCol int // "작업자에 의한 사전 작업 내용"
    TargetObjCol     int // "작업대상"
    VerifyMethodCol  int // "검증방법"
    WorkerCol        int // "작업자"
    VerifierCol      int // "검증자"
    ResultCol        int // "작업결과"
}

type SectionInfo struct {
    Name         string         // "사전작업" | "본작업" | "사후작업"
    StepNumber   string         // "1" | "2" | "3"
    TitleRow     int            // 섹션 타이틀 행
    HeaderRow    int            // 8개 컬럼 헤더가 위치한 행
    DataStartRow int            // 데이터 병합 셀 시작 행 (HeaderRow + 1)
    DataEndRow   int            // 데이터 병합 셀 끝 행
    Cols         SectionColumns // 각 컬럼의 열 번호 (1-based)
}

탐색 알고리즘 (FindSections(ws *ole.IDispatch) ([]SectionInfo, error))
UsedRange의 행(r = 1 .. maxRow)과 열(c = 1 .. maxCol)을 순회하며, 공백을 제거한 텍스트가 "사전작업", "본작업", "사후작업"인 셀을 찾음.

찾은 TitleRow 바로 아래 행(TitleRow + 1 ~ TitleRow + 5)을 스캔하여 "Step"과 "작업내용"이 포함된 행을 HeaderRow로 확정함. (만약 아래쪽에 유효한 HeaderRow 및 병합 데이터 행이 없는 더미 타이틀이 있을 경우 자동으로 건너뛰고 실제 헤더+데이터 블록이 있는 섹션을 매핑함).

HeaderRow의 각 열 텍스트(공백 제거 후 비교)를 읽어 SectionColumns의 8개 열 인덱스를 기록함.

DataStartRow = HeaderRow + 1로 설정하고, (DataStartRow, StepCol) 셀의 MergeArea.Rows.Count를 조회하여 DataEndRow = DataStartRow + mergeRowCount - 1로 데이터 병합 범위를 확정함.

4. 모듈별 코드 수정 명세
4.1 config.go
삭제: MajorCategories, MinorCategories, Templates 관련 필드 및 함수 전체 삭제.

구조체 정의:

Go
type Config struct {
    WorkerName   string `json:"worker_name"`
    VerifierName string `json:"verifier_name"`
    TargetObject string `json:"target_object"`
    LastTarget   string `json:"last_target"`
}
WorkerName은 최초 실행 시 모달로 입력받아 저장하며, VerifierName과 TargetObject도 입력 시 자동 저장하여 사용자 편의성 제공.

4.2 handlers.go
유지 및 수정 API:

GET /api/config, POST /api/config: 작업자 이름 조회 및 변경 저장.

POST /api/target/load: 사용자가 업로드하거나 경로 지정한 target 엑셀 파일을 분석하여 시트 목록(각 시트 이름 및 사전작업/본작업/사후작업 섹션 존재 여부, 글꼴 크기, 포함된 이미지 개수 요약) 반환.

POST /api/generate:

입력 파라미터: TargetPath, SelectedSheets []string (체크된 순서대로 정렬된 시트명 배열), WorkerName, VerifierName, TargetObject, OutputFileName.

동작: excel_com.go의 GenerateSOP()를 호출하여 프로그램 폴더에 결과 엑셀 생성 후 성공 응답 반환.

삭제 API:

/api/categories (대/중분류 관련 API 전체)

/api/templates/* (기본 양식 생성 및 양식 목록 관리 API 전체)

4.3 web/index.html, web/app.js, web/style.css
제거:

대분류/중분류 선택 드롭다운 및 직접 입력창 제거.

상세내용 입력란 제거.

기본 양식 생성 버튼 및 양식 파일 업로드/선택 UI 제거.

구성할 화면 레이아웃:

상단 헤더: 현재 작업자 이름 표시 + [작업자 변경] 버튼 (최초 실행 시 작업자 이름 입력 모달 팝업).

작업 기본 정보 입력 카드:

작업대상 입력 텍스트 상자 (<input type="text" id="targetObject" placeholder="작업대상을 입력하세요">)

검증자 입력 텍스트 상자 (<input type="text" id="verifierName" placeholder="검증자를 입력하세요">)

Target 엑셀 파일 선택 및 시트 순서 지정 카드:

Target 엑셀 파일 선택(업로드 또는 경로 지정) 버튼.

로드된 시트 체크리스트: 사용자가 체크한 순서대로 1순위, 2순위, 3순위 배지가 부여되며, 선택된 순서대로 각 시트의 사전작업, 본작업, 사후작업 내용이 결과 파일의 사전작업(Step 1), 본작업(Step 2), 사후작업(Step 3) 병합 셀에 순서대로 들어간다는 안내 표시.

결과 파일 생성 바:

생성할 엑셀 파일명 입력 상자 (예: SOP_결과본.xlsx)

[SOP 엑셀 생성] 실행 버튼.

5. 단계별 자율 실행 및 원샷(One-Shot) 검증 계획
Step 1 (config.go 개편): 대/중분류 및 양식 목록 로직 제거, 작업자·검증자·작업대상 설정 구조 반영.

Step 2 (excel_com.go 전면 재작성):

FindSections() 유동적 섹션(사전작업, 본작업, 사후작업) 및 8개 컬럼 스캐너 구현.

기준 시트 통째 복제를 통한 원본 서식·테두리·열너비·글꼴 크기(11pt/14pt 등) 100% 보존 로직 구현.

Step (1, 2, 3) 고정 기입, 작업대상/작업자/검증자 기입 구현.

다중 시트 선택 시 사전작업, 본작업, 사후작업 각각의 작업내용, 작업자에 의한 사전 작업 내용, 검증방법 병합 셀 내에 1. [시트명], 2. [시트명] 헤더와 함께 원본 텍스트(글꼴/크기 보존) 및 이미지/도형(Shapes)을 수직 적재(Vertical Stacking)하는 엔진 구현.

Step 3 (handlers.go & web/* 개편): 불필요 API/UI 제거, 작업대상·검증자 텍스트 상자 및 시트 순서 선택 UI 연동.

Step 4 (단일 .exe 빌드): go build -ldflags="-H windowsgui -s -w" -o sop-generator.exe 빌드 수행.

Step 5 (One-Shot End-to-End 자동 검증 테스트):

테스트 스크립트를 통해 14pt 글꼴과 이미지/도형이 포함되고 사전작업·본작업·사후작업 위치가 서로 다른 커스텀 행에 배치된 복수 시트짜리 테스트용 target.xlsx를 생성.

빌드된 엔진으로 2개 이상의 시트를 순서대로 선택해 결과 파일을 생성한 뒤, Excel COM으로 결과 파일을 다시 열어 조건정의서.md의 모든 체크리스트(파일 생성 위치, Step 1/2/3 고정값, 작업자/검증자/작업대상 기입값, 1. [시트명] 순서 적재, 14pt 글꼴 크기 보존 여부, 이미지/도형 개수 및 비겹침 좌표)를 단 한 번의 실행으로 100% 통과하는지 자동 검증함.
