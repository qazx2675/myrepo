# 자산 조사 스크립트 프로젝트 계획서

## 목표 및 범위

리눅스(RHEL) 서버 목록을 입력하면 각 호스트에 `gossh`로 병렬 접속해 자산대장(표2) 항목을
자동 수집하고, **엑셀에 바로 붙여넣을 수 있는 탭 구분 결과 파일**로 저장한다.

### 입력

- `표1` 자산양식 텍스트 (사전작업으로 RHEL에 생성): `자산ID  hostname  상태  위치`
  - 여기 적힌 hostname 전체가 곧 조사 대상. 별도 목록 파일을 손으로 만들지 않는다.
- `conf/conf.toml` : 원격 실행 커맨드, 인프라 조사 스크립트 경로, mountpoint별 정상 위치
  (실행 파일 옆 `conf/` 디렉터리의 단일 파일. 옵션으로 경로 지정하지 않음)

### 출력 (탭 구분, 결과 파일로 저장. 최대 2개)

```
hostname	위치	상태	설정값	인프라망	appl설정유무	특이사항
```

- `result_YYYYMMDD_HHMM.tsv` — 표1 전체 (항상)
- `result_vm_YYYYMMDD_HHMM.tsv` — ESXi 로 판별된 호스트의 VM (ESXi ≥ 1대, 행 있을 때만)
- `result_sdc_YYYYMMDD_HHMM.tsv` — 인프라망 값이 `SDC` 인 호스트 (A·B 에서 이동, 있을 때만)
- 호스트는 세 파일 간 **중복 없음** (SDC 는 이동, VM 은 이름이 다름)

- 셀 구분은 **오직 탭**. 필드 안의 탭·개행은 스페이스로 치환.
- 표1의 모든 hostname은 접속 실패·수집 실패와 무관하게 **반드시 1행** 출력.
  실패 시 채우지 못한 항목은 공란, 사유는 `특이사항`에 기록.

### 범위 포함

- 표1 파싱 → hostname 기준 `위치` / `상태` 매핑
- 표1의 hostname 열을 뽑아 gossh용 임시 hostfile로 자동 변환
- `gossh -w <hostfile> -script "<cmd>"` 로 `설정값` 병렬 수집
- 설정값에서 mountpoint 추출 → conf 정상 위치와 표1 위치 비교 → `O` / `X`
- conf에 지정된 인프라 조사 스크립트 실행 → `인프라망`
- 접속불가 / 수집불가 시 `특이사항` 기록

### 범위 제외

- 표2 파일(엑셀·DB)에 직접 반영 — 사람이 결과 파일을 복사해 붙여넣음
- `자산ID` 수집·출력 (표2에 불필요)
- 서버 설정 변경 (읽기 전용 조사)
- 입력 파일 인코딩/구분자 대응 — 터미널 출력을 복사해 쓰므로 불필요, 결과 파일만 저장되면 됨
- 손으로 만드는 대상 목록 파일 — 표1에서 자동 추출

### 가정

- 도구는 표1을 직접 읽어 hostname 열 전체를 조사 대상으로 삼는다.
  중간 목록 파일(hostfile)은 gossh 호출용으로 내부에서 자동 생성한다.
- `gossh`는 pdsh와 동일한 실행 규칙을 따르며 출력은 `hostname: 명령어결과` 형식이다.

## 주요 기능

### 필수

1. **표1 로더** — 표1 텍스트(**탭 `\t` 구분**)를 읽어 각 행에서 `hostname` / `상태` / `위치` 추출.
   상태·위치에 공백이 들어가도 탭으로만 나누므로 안전. 헤더 행·빈 줄 자동 스킵.
   hostname 열이 비었거나 파싱 불가한 행은 건너뛰고 stderr에 경고. 이 hostname 목록이 곧 조사 대상.
2. **hostfile 자동 생성** — 추출한 hostname을 임시 파일에 기록(gossh `-w` 용), 실행 후 삭제.
3. **gossh 수집기** — 임시 hostfile로
   `gossh -c <concurrency> -w <hostfile> -script "<conf.scripts.config_value>"` 를 1회 실행,
   `hostname: 결과` 형식 출력을 hostname 기준으로 파싱.
   pdsh 규칙상 접속 실패 호스트는 ssh 오류 라인으로 나타나므로 감지해 `특이사항 = 접속불가`.
4. **설정값 추출** — auto.appl 매칭 행(**`/` 로 시작**)의 마지막 필드(`mountpoint:/appl2/appl2`)만
   `설정값`으로 기록. `/` 로 시작하지 않는 줄(gossh/grep 에러 등)은 무시.
   해당 호스트 **출력이 아예 없거나** 매칭 행이 없으면 `설정값 = 없음`.
5. **appl 설정유무 판정** —
   - `설정값`이 `없음` → `없음`
   - `설정값`에서 `:` 앞부분(mountpoint 이름)만 분리 → conf `[[mountpoint]]`에서 정상 `location` 조회
   - 표1의 해당 hostname `위치` 와 비교 → 같으면 `O`, 다르면 `X`
   - mountpoint가 conf에 없으면 `X` + `특이사항` = "mountpoint 미정의"
   - 접속 실패 → 공란
6. **인프라망 수집** — `gossh -w <hostfile> -script "bash <conf.scripts.infra_net>"` 를
   설정값 조사와 **별도로** 1회 실행(`-c` 없음). 출력값에 `infra_regex`(캡처 그룹 1) 적용.
   - 출력값(`hostname:` 뒤)은 앞뒤 공백 제거 후 `infra_regex` 적용. `\s` 는 공백·탭 모두 매칭.
   - 매칭 실패(예: `FAIL LDAP 확인필요`/`undefined`) → `infra_fallback_cmd`(binddn) 재조사 →
     `infra_fallback_regex` 로 값 추출.
   - `infra_net` 은 조사 대상 호스트에 배포된 스크립트/명령.
   - **인프라망 값 == `SDC` → 해당 호스트는 A·B 에서 빠져 `result_sdc_*.tsv` 로만 기록.**
7. **ESXi 판별 + VM 2차 조사** —
   - `설정값 = 없음` 호스트에 `gossh ... -script "uname"` → 출력에 `VMkernel` → ESXi.
     1차 결과의 `특이사항` 에 `esxi` 기록.
   - ESXi ≥ 1대면 각 ESXi 마다 `<esxi>ev01` `<esxi>ev02` `<esxi>ev03` (규칙 고정, conf 없음)을 만든다.
   - **만든 이름을 `survey` 가 직접 `net.LookupHost` 로 DNS 조회** → 해석 안 되는 VM(존재하지 않음)은
     조사에서 빼고 어떤 행도 남기지 않는다 (gossh 에러 파싱에 의존 안 함).
   - 해석되는 VM 만 1차와 **같은** `config_value`/`infra_net`/O·X 로직으로 조사.
     `위치`·`상태`·O·X 기준 위치는 소속 ESXi(표1) 값을 상속.
   - 조사 가능한 VM 이 하나도 없는 ESXi 는 그 이름으로 `접속불가` 1행.
   - `타임아웃` VM 만 모아 **1회** 재조사(무한 루프 방지).
8. **TSV 출력기** — 항상 7컬럼 고정. `result_*.tsv`(A) + (ESXi & 행 있으면) `result_vm_*.tsv`(B)
   + (SDC 호스트 있으면) `result_sdc_*.tsv`. 헤더 포함, 파일 간 호스트 중복 없음.
9. **특이사항 처리** — "접속불가" / "타임아웃" / "DNS 미등록" / "gossh 실행 실패" /
   "mountpoint 미정의" / "인프라 스크립트 없음" / "esxi".

### 하지 않는 것 (과설계 방지)

- 설정값 다중 행 처리 옵션 — auto.appl `/appl` 행이 실제로 여러 개로 확인되면 그때 추가
- 인프라망 정규식/매핑 테이블 — 인프라 조사 스크립트가 전담하므로 불필요
- 출력 헤더 on/off, stdout 토글 등 — 요청은 "결과 파일 1개"

## conf 설계

추후 스크립트 교체·정상값 변경을 코드 수정 없이 하기 위해 conf로 분리한다. (TOML — 주석 지원, 배열 테이블)

```toml
[input]
asset_file = "/root/HPC/조사/asset_list.txt"   # 표1 텍스트 경로

[gossh]
bin         = "/usr/local/bin/gossh"
concurrency = 4000                             # gossh 동시 실행 수 (-c). 설정값 조사에만 적용
timeout     = 10                               # gossh 타임아웃 초 (-t). 지우면 gossh 기본값
extra_args  = ""                               # 필요 시 추가 플래그

[scripts]
# 원격 실행 커맨드 (gossh -script 로 전달) — 교체 자유
config_value = "cat /etc/auto.appl | grep -v '#' | grep -w '/appl'"
# 인프라망 조사: gossh -w <hosts> -script "bash <이 값>" 으로 원격 실행
infra_net    = "/usr/local/bin/infra_survey.sh"
# 출력값에 적용 (캡처 그룹 1). 매칭 실패 시 아래 fallback 재조사. \s = 공백/탭
#   "INFO ldap infra site match" -> "infra"   /   "FAIL LDAP 확인필요" -> fallback
infra_regex          = '^INFO\s+\S+\s+(\S+)'
infra_fallback_cmd   = "cat /etc/openldap/ldap.conf | grep -i binddn"
infra_fallback_regex = 'ou=([^,[:space:]]+)'   # binddn 의 ou= 부분 (예: SDC)

# 설정값 mountpoint 이름별 "정상 위치" — 표1의 위치와 비교해 O/X 판정
[[mountpoint]]
name     = "nas-a"        # 설정값 "nas-a:/appl2/appl2" 의 ':' 앞부분
location = "A센터"

[[mountpoint]]
name     = "nas-b"
location = "B센터"

[[mountpoint]]
name     = "nas-dr"
location = "DR"
```

## 항목별 수집 로직

| 표2 항목 | 출처 | 처리 |
|---|---|---|
| hostname | 표1 hostname 열 | 그대로 (조사 대상 기준) |
| 위치 | 표1 같은 행 | 비었으면 공란 |
| 상태 | 표1 같은 행 | 비었으면 공란 |
| 설정값 | `gossh -c <concurrency> -w file -script "<config_value>"` 1회 | `/` 로 시작하는 매칭 행의 마지막 필드. 출력 없음/매칭 없음 → `없음`. 접속불가 → 공란 |
| 인프라망 | `gossh -w file -script "bash <infra_net>"` 1회 (`-c` 없음, 설정값과 별도) | 출력값에 `infra_regex`. 매칭 실패 → `infra_fallback_cmd`(binddn) 재조사 후 `infra_fallback_regex` |
| (SDC 분리) | 인프라망 값 == `SDC` | 해당 호스트를 A·B 에서 빼서 `result_sdc_*.tsv` 로 |
| appl 설정유무 | 설정값 mountpoint vs conf 정상 위치 vs 표1 위치 | `O` / `X` / `없음`(설정값 없음) / 공란(접속불가) |
| 특이사항 | 실행 중 예외 | 접속불가 / 타임아웃(`gossh -t <conf.timeout>`) / gossh 실행 실패 / mountpoint 미정의 / 인프라 스크립트 없음 |

### O/X 판정 예시

- auto.appl 행: `/appl -ro,soft nas-a:/appl2/appl2`
- 마지막 필드 → `설정값` = `nas-a:/appl2/appl2`
- `:` 앞부분 → mountpoint 이름 = `nas-a`
- conf `[[mountpoint]] name="nas-a"` → 정상 위치 `A센터`
- 표1의 해당 hostname `위치` = `A센터` → **O** (다르면 **X**)

## 단계별 마일스톤

1. **골격 + conf/표1 파싱**
   Go 프로젝트 구조, TOML conf 로드, 표1 파서(hostname/상태/위치 추출).
   → 검증: 표1만으로 `hostname / 위치 / 상태` 3컬럼 TSV 출력, 행 수 == 표1 유효 행 수.
2. **gossh 연동 + 설정값**
   임시 hostfile 생성, `gossh -w file -script "cmd"` 실행, `hostname: 결과` 파싱, 마지막 필드 추출.
   → 검증: 실서버 대상 `설정값` 컬럼이 `mountpoint:/path` 형태로 채워짐. 접속 실패 host는 특이사항.
3. **인프라망 + O/X 판정**
   `conf.scripts.infra_net` 호출, mountpoint 이름 분리 후 conf 정상 위치 ↔ 표1 위치 비교.
   → 검증: 7컬럼 완성. 정상 host는 `O`, 위치 불일치 host는 `X`, conf 미정의 mountpoint는 `X`+특이사항.
4. **예외·특이사항 + TSV 안정화**
   접속불가/타임아웃/명령실패 분기, 필드 내 탭·개행 치환, hostname당 1행 불변식 검증.
   → 검증: 정상+실패 host가 섞여도 행 수 == 표1 유효 행 수, 엑셀 붙여넣기 시 셀 정상 분리.
5. **bash 래퍼 + 문서화 + 유지보수 자산**
   `run_survey.sh`, `README.md`(아래 목차), `ARCHITECTURE.md`, `CHANGELOG.md`,
   `PR_CHECKLIST.md`, `.github/workflows/ci.yml`, `go mod vendor` 커밋, 샘플 `conf.toml`,
   샘플 `infra_survey.sh`.
   → 검증: 저장소를 zip으로 받아 `go build -mod=vendor ./...` 만으로 오프라인 빌드 성공.

## 기술 스택 / 아키텍처

- **Go (메인 조사 스크립트)** — 병렬 결과 취합·구조화 파싱·단일 바이너리 배포.
  폐쇄망 서버에 바이너리 1개만 복사하면 실행(런타임 의존성 없음).
- **bash (보조 스크립트)** — 프로젝트 규칙상 Go 구현에 항상 래퍼 동반.
  - `run_survey.sh` : conf/목록 경로 인자 전달, 바이너리 존재·실행권한 확인, 결과 파일 저장 위치 관리
  - `infra_survey.sh` : 인프라망 판별 로직 (conf에서 경로 지정, 교체 가능)
- **gossh (병렬 실행)** — 보유 중인 pdsh 유사 사내 도구. 권한 문제 없이 전 호스트 접속 가능.
  `gossh -w <hostfile> -script "<cmd>"` 로 1회 호출하고 `hostname: 결과` 출력을 파싱해
  세션 관리·동시성을 gossh에 위임(구현 단순화).
- **TOML conf** — 주석 지원, `[[mountpoint]]` 배열 테이블로 정상 위치 정책 표현.
  실행 커맨드·스크립트 경로·정상값을 코드 밖으로 분리해 향후 자유 변경.
- **출력** — `strings.Join(fields, "\t")`, 셀 구분은 오직 탭.

### 패키지/파일 구성 (단일 패키지, 소규모 유지)

```
cmd/survey/
  main.go      CLI 진입점, 전체 흐름 조립
  config.go    conf/conf.toml 로드 (infra_regex 컴파일 포함)
  asset.go     표1 파서(탭 구분), 조사 대상 hostname 목록 + hostname -> (상태, 위치)
  collect.go   runGossh(hostfile+gossh 1회), Collect(설정값, -c), CollectInfra(인프라망, "bash <infra_net>")
  rule.go      applyInfraRegex(출력값에 정규식), ApplStatus(O/X)
  vm.go        DetectESXi(uname), SurveyVMs(<esxi>ev01~03 조사, DNS 제외, 타임아웃 1회 재조사)
  output.go    TSV 행 조립, 필드 정규화, 결과 파일 저장
  main.go      splitSDC(인프라망==SDC 행 분리) 포함 흐름 조립
update.sh      폐쇄망 증분 업데이트 (변경분만, conf/result/asset 보존)
```

### 흐름

```
run_survey.sh ──> survey (Go binary)
                    ├── conf.toml 로드
                    ├── asset_list.txt(표1) 파싱  -> 대상 hostname 목록 + hostname -> (위치, 상태)
                    ├── 임시 hostfile 자동 작성 (표1 hostname 열)
                    ├── gossh -c N -w hostfile -script "<config_value>"       (설정값)
                    ├── gossh    -w hostfile -script "bash <infra_net>"       (인프라망, 별도)
                    ├── 호스트별:
                    │     설정값 = '/' 시작 매칭 행 마지막 필드 (없으면 '없음')
                    │     mountpoint 이름 분리 -> conf 정상 위치 -> O/X = (정상 위치 == 표1 위치)
                    │     인프라망 = 출력값에 infra_regex 적용
                    ├── 설정값 없음 호스트 -> gossh "uname" -> VMkernel? -> esxi 표시
                    ├── ESXi 있으면 <esxi>ev01~03 -> net.LookupHost 로 DNS 필터 -> 해석되는 것만 조사 (타임아웃 1회 재조사)
                    ├── 인프라망 == "SDC" 행 -> A/B 에서 빼서 result_sdc_*.tsv 로
                    ├── result_YYYYMMDD_HHMM.tsv       (A, 항상)
                    ├── result_vm_YYYYMMDD_HHMM.tsv    (B, ESXi & 행 있을 때)
                    └── result_sdc_YYYYMMDD_HHMM.tsv   (SDC 호스트 있을 때)
```

## 산출물 문서 구조 (git 업로드 기준)

폐쇄망에서 폴더를 통째로 받아 빌드 가능해야 하므로 **Go 의존성은 `go mod vendor`로 벤더링**하여
저장소에 포함한다. 빌드는 `go build -mod=vendor ./...`.

`README.md` 목차 순서(고정):

### 1. 빌드 및 설치 방법

- 사전 요구: Go `<go.mod 버전>`, `gossh` 바이너리 (경로는 conf에 지정)
- 온라인: `git clone` → `go build -mod=vendor -o survey ./cmd/survey`
- 폐쇄망: 저장소 zip 다운로드 → 압축 해제 → `go build -mod=vendor -o survey ./cmd/survey`
  (vendor/ 포함이라 네트워크 불필요)
- 설치: 빌드된 `survey` 와 `conf.toml`, `run_survey.sh`, `scripts/infra_survey.sh` 를
  작업 디렉터리에 배치

### 2. 사용 방법

- 사전작업: RHEL 터미널에서 표1 출력 → 텍스트로 저장(`asset_list.txt`).
  조사할 hostname은 표1에 넣기만 하면 됨(별도 목록 파일 불필요)
- 실행: `./run_survey.sh` (인자 없음, `conf/conf.toml` 자동 사용)
- 결과: 같은 폴더에 `result_YYYYMMDD_HHMM.tsv` 생성 (표1의 모든 hostname이 1행씩)
- 활용: 결과 파일을 열어 전체 복사 → 엑셀에 붙여넣기(탭 구분으로 셀 자동 분리)

### 3. 옵션별 상세 설명

- `run_survey.sh` : 인자 없음. 항상 실행 파일 옆 `conf/conf.toml` 사용
- `conf/conf.toml` 항목표
  - `[input].asset_file` : 표1 텍스트 경로
  - `[gossh].bin` / `[gossh].extra_args` : gossh 실행 파일 / 추가 플래그
  - `[scripts].config_value` : 원격 실행 커맨드 (교체 시 이 값만 수정)
  - `[scripts].infra_net` : 인프라망 조사 대상 (`gossh -script "bash <이 값>"`)
  - `[scripts].infra_regex` : 인프라 출력값에서 값 추출용 정규식 (캡처 그룹 1)
  - `[scripts].infra_fallback_cmd` / `infra_fallback_regex` : infra_regex 매칭 실패 시 재조사 커맨드 + 추출 정규식
  - `[[mountpoint]].name` / `.location` : 설정값 mountpoint 이름별 정상 위치

### 4. 문서별 설명

- `README.md` : 본 문서
- `ARCHITECTURE.md` : 폴더/파일별 역할 표 (수정 지점 빠르게 찾기용)

## 리스크 및 제약사항

- **gossh 출력 파싱** — pdsh 규칙(`hostname: 결과`)을 전제로 파서를 만든다.
  다중 행 결과·접속 실패 라인의 실제 표기는 마일스톤 2에서 `gossh -w file -script "echo test"`
  및 일부러 실패시킨 호스트로 샘플을 확보해 확정한다.
- **auto.appl `/appl` 매칭 행 다중** — 현재 1개로 가정하고 첫 줄만 사용.
  여러 개로 확인되면 conf 옵션을 추가한다(지금은 만들지 않음).
- **설정값 마지막 필드 가정** — `mountpoint:/path` 토큰이 항상 행의 마지막 공백 필드라는 전제
  (마지막 필드에 `:` 없으면 `:` 포함 토큰을 뒤에서부터 탐색하도록 보정 로직 있음).
- **표1 위치 표기 일관성** — 표1의 `위치` 문자열과 conf `[[mountpoint]].location` 이 정확히
  일치해야 `O` 판정. 로더에서 앞뒤 공백 제거, 편차 발견 시 별칭 매핑 검토.
- **인프라 조사 스크립트 미제공** — 판별 로직은 사용자 측 스크립트에 있음. 저장소에는
  인터페이스(각 호스트에서 `bash` 로 실행, 출력 1줄)만 맞춘 샘플 `infra_survey.sh` 를 넣는다.
  실제 스크립트는 **조사 대상 호스트에 배포**돼 있어야 한다.
- **조사 대상 = 표1 hostname 열 전체** — 도구가 표1을 읽어 자동으로 대상 목록을 만든다.
  표1에서 빼면 조사 대상에서도 빠진다. hostname 열이 빈 행은 건너뛰고 stderr에 경고를 남긴다.

## 구현 메모 (2026-08-27)

구현 위치: `.claude/HPC/조사/survey/`

- 마일스톤 1~5 코드/문서 작성 완료.
- **검증 완료**: Rocky Linux(192.168.0.58, go 1.26.5)에서 `go build`/`go vet`/`go test` 통과.
  가짜 gossh + 접속불가 host 섞은 스모크 테스트로 TSV 출력·특이사항·O/X 정상 확인.
- **v0.2.0~v0.3.0 변경**(사용자 피드백 반영):
  - 표1 파싱 탭(`\t`) 구분 — 상태·위치 공백 허용.
  - 설정값 없음 = 해당 호스트 gossh 출력이 없는 상태 → 설정값·appl설정유무 모두 `없음`.
    `/` 로 시작하지 않는 에러 라인은 설정값 후보에서 제외(`ERROR: X` 로 나오던 문제 해결).
  - 인프라망 조사도 gossh 배치: `gossh -w hosts -script "bash <infra_net>"` (설정값과 별도, `-c` 없음).
    출력 `hostname: 출력값` 의 출력값에 `[scripts].infra_regex` 적용(conf 에서 자유 변경).
  - `infra_net` 은 조사 대상 호스트에 배포된 스크립트/명령.
  - **ESXi 판별 + VM 2차 조사**: `설정값=없음` 호스트에 `uname` → `VMkernel` → 1차 특이사항 `esxi`.
    ESXi 마다 `<esxi>ev01~ev03` (고정)을 별도 파일 `result_vm_*.tsv` 로 조사. DNS 미등록 VM 제외,
    타임아웃 1회 재조사, VM 전부 실패 시 ESXi 이름으로 `접속불가` 1행. 출력 파일은 최대 2개.
  - `gossh -t <timeout>` (conf `[gossh].timeout`) 두 조사 모두 적용.
  - **인프라망 fallback**: `infra_regex`(`\[([^\]]+)\]`, 대괄호 안) 매칭 실패 시
    `infra_fallback_cmd`(binddn) 재조사 → `infra_fallback_regex` 로 값 추출.
  - **SDC 분리**: 인프라망 값이 `SDC` 인 호스트는 A·B 에서 빠져 `result_sdc_*.tsv` 로만. 세 파일 호스트 중복 없음.
  - **`update.sh`**: 폐쇄망에서 `/root/HPC/조사` 를 변경분만 갱신 (conf/result/asset 보존, 오래된 *.go 제거, 멱등).
- **계획 대비 1건 변경**: "TOML 라이브러리 + `go mod vendor`" → **표준 라이브러리만 사용**하고
  conf 는 고정된 하위집합 자체 파서로 처리. 이유:
  (1) 폐쇄망 빌드에 의존성 반입/vendor 과정이 아예 불필요해짐,
  (2) conf 스키마가 작고 고정적,
  (3) CLAUDE.md "Simplicity First".
  이에 따라 CI 도 `-mod=vendor` 없이 `go build ./...` 사용.
- **설정 파일**: 옵션 없이 실행 파일 옆 `conf/conf.toml` 단일 파일만 사용
  (`main.go` 가 `os.Executable()` 기준으로 경로 해석).
- **실행 분리**: 설정값 조사 = `gossh` 1회 배치(`-c` 동시 실행 수, 기본 4000, conf 조정 가능).
  인프라망 조사 = gossh 와 무관하게 로컬 스크립트를 호스트마다 실행(기본 스크립트 유지).
- 여전히 미확정(코드에 가정으로 반영, 실측 후 조정):
  `gossh` 실제 출력 형식(`collect.go: parsePdshLine/detectError`),
  인프라망 판별 규칙(`scripts/infra_survey.sh` 샘플 교체).
