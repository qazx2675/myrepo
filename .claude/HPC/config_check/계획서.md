# OS 체크 및 환경설정 스크립트 (config_check.sh) 계획서

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | OS 배포 후 상태 체크 → 환경설정 적용 → 재체크 → 벤더 코멘트 생성까지 한 번에 처리 |
| 문제점 | 기존 스크립트는 수백 대에서는 괜찮지만 2천 대 이상에서 느림 |
| 목표 | ① 속도 개선 (0순위) ② 상태값 체크 정확도 향상 |
| 언어 / 병렬도구 | bash 단일 스크립트 / gossh v2 |
| 사용자 조작 | `bash config_check.sh` → user 번호 입력 → 작업 진행(y/n) → 설정 수정(y/n/set). 이 외의 입력은 없음 |

## 2. 속도 개선 설계

기존 스크립트는 전체 대상에 gossh를 4번 실행했다(분류 → 커널 → run.sh → LDAP 정보). 이 부분을 줄인다.

| # | 방식 | 효과 |
|---|---|---|
| A | `gossh -pm -script -w 목록 "bash run.sh"` **1회 실행**으로 분류·FAIL·LDAP·usb0를 모두 얻는다. 분류는 gossh가 남기는 결과 파일에서, 나머지는 stdout에서 파싱한다 | 전체 대상 순회 4회 → 1회 |
| B | 환경설정은 스크립트를 `;`로 묶어 **gossh 1회**로 적용한다 (y는 2개, set은 3개) | 설정 스크립트 개수만큼 돌던 순회 → 1회 |
| C | 설정 적용과 재체크는 **OK 호스트만** 대상으로 한다 | 접속불가 대상의 타임아웃 대기 제거 |
| D | DHCP 조회는 scp+ssh 대신 `ssh ... < 목록` **1회**로 처리하고 결과는 파일 없이 바로 출력한다 | 왕복 1회 절감, 로컬 파일 미잔류 |
| E | VWP 점검은 ev 호스트 전체를 `grep -wFf` 1회로 처리한다 | 호스트 수와 무관하게 1회 |
| F | 호스트 파싱, prefix 집계, 30행 출력, LDAP 집계를 awk로 처리한다 (bash 루프 없음) | 대량일수록 체감 |

- `/user/` 경로 때문에 gossh가 동시 접속을 350으로 제한한다. 이 안전장치는 **유지**한다.
- gossh 옵션 순서: `-pm`은 `-w`보다 앞에 둔다. Go flag 특성상 명령 인자 뒤의 옵션은 무시되기 때문이다.

## 4. 프로세스 진행 단계

```
[1] user 선택 ─ info_mn.sh 출력 → "input Number: " → info.sh로 user 확정
      │
[2] 리스트 확인 ─ ./${user}.txt 파싱 (공백/줄바꿈 무관, 중복 제거, 원래 순서 유지)
      │          30행 단위 열(column) 출력 + prefix별 수량 + 총 N EA
      │
[3] 작업 진행 (y/n) ─ n → 종료
      │   └ user가 uptime_enable_user에 해당하면: gossh -script -w 목록 "uptime"
      │
[4] 체크 ─ gossh -pm -script -w 목록 "bash run.sh"  (전체 대상 1회)
      │   ├ FAIL 줄만 출력 (없으면 NO FAIL). os_install/nosvrauto 호스트 줄은 제외
      │   ├ LDAP 요약 (상태줄 위)
      │   └ 상태줄: total OK pingX pingO_sshx nosvrauto os_install
      │
[5] 환경설정 수정 (y/n/set)
      ├ n   ───────────────────────────────┐
      ├ y   → OK 호스트에 "bash insert_file; bash appl_setting_file"
      └ set → OK 호스트에 "bash insert_file; bash appl_setting_file; bash setting_file"
             │
             └→ [4] 재체크 (OK 호스트만) ────┤
                                            │
[6] 마무리 (5-n) ◄──────────────────────────┘
      ├ AI 서버 점검 (대상 ∩ ai_server_list가 있을 때만)
      ├ 벤더별 코멘트 / 전체 정상 공통 코멘트
      ├ DHCP 정보 (접속불가 서버가 있을 때, 접속불가 코멘트 바로 아래)
      ├ 기타 상태 서버 요약 (pingO_sshx / nosvrauto / os_install)
      ├ usb0 disabled 필요 서버
      └ VWP 사용 서버 (ev 호스트)
      → 종료 (설정 여부를 다시 묻지 않음)
```

## 5. 단계별 상세

### [2] 리스트 확인

- 호스트 파싱: 공백·탭·줄바꿈을 모두 구분자로 보고, 빈 토큰은 버리며, 중복은 제거한다(처음 나온 순서 유지). 정리된 목록은 임시 디렉터리에 만들어 이후 모든 gossh `-w` 입력으로 사용한다.
- 출력: 1열 = 1~30번, 2열 = 31~60번 … 형태로 탭 구분 출력.
- 집계: prefix는 호스트명 앞쪽의 숫자가 아닌 부분이다 (`a1` → `a`, `hostname0001ev01` → `hostname`). `a * 3ea` 형태로 출력하고 마지막에 `총 N EA`를 출력한다.

### [4] 체크 결과 파싱

gossh 출력 형식은 `hostname: 내용`이다. 체크 스크립트 결과는 `hostname: OK\t...`, `hostname: FAIL\t...`, `hostname: INFO\tLDAP\t<값>` 형태다.

| 상태 | 근거 (gossh 결과 파일) | 색상 |
|---|---|---|
| total | 정리된 대상 수 | 기본 |
| OK | total − 아래 4종 | 초록 |
| pingX (접속불가) | `_res_off` (SSH 타임아웃 / DNS 실패) | 빨강 |
| pingO_sshx | `_res_refsed` (22번 포트 refused 등) | 노랑 |
| nosvrauto | `_nosvrauto` | 노랑 |
| os_install | `_os_install` | 노랑 |

- gossh 결과 파일은 `host[0001-0003]`처럼 압축되어 있으므로, 다차원 범위까지 풀어서 집계한다.
- 이 스크립트에서 "접속불가"는 **pingX(타임아웃)만** 뜻한다.
- 실행 명령은 `bash run.sh; :` 이다. run.sh가 0이 아닌 값으로 끝나면 gossh가 출력 전체를 stderr(`host: ERROR: ...`)로 보내 파싱이 비므로, 종료 코드를 0으로 고정한다(검증 중 발견).
- gossh의 stderr(접속 실패 메시지)는 수천 줄이 될 수 있어 임시 파일로 돌리고 화면에는 내지 않는다. 대신 소요 시간을 출력한다.
- gossh 결과가 병렬이라 순서가 섞이므로 호스트명 기준으로 안정 정렬한 뒤 분석한다.
- Ctrl+C: gossh 실행 구간에서는 스크립트가 INT를 무시하여 gossh의 자체 동작(1회 진행 호스트 표시 / 2회 걸린 호스트 취소 / 3회 중단)을 그대로 살린다. 프롬프트 대기 중에는 종료하며 임시 파일을 정리한다.

**LDAP 요약** (상태줄 바로 위에 출력, OK 호스트 기준)

- 값이 1종류면: `LDAP : infra`
- 값이 2종류 이상이면 노란색으로 출력한다.
  ```
  [경고] LDAP infra가 2개 이상입니다
  LDAP : infra(1980ea) / infra2(20ea)
    infra2 : host1 host2 ...        ← 다수값을 제외한 나머지 값의 호스트 나열
  ```
- OK 호스트 중 LDAP INFO 줄이 없으면: `LDAP 미확인 N대 : host...` (노란색)

### [5] 환경설정

- 대상: OK 호스트
- `/user/` 경로가 포함되므로 gossh가 동시 접속을 350으로 제한한다.
- 설정 스크립트의 출력은 화면에 쏟지 않고 임시 파일에 받아, `fail|error|fatal|denied|not found`가 들어간 줄만 최대 50줄 보여준다. 최종 확인은 재체크 결과로 한다.
- 적용 후 같은 OK 호스트만 [4]를 다시 실행한다. FAIL, LDAP, 상태줄은 재체크 결과 기준으로 출력한다.
- 코멘트의 접속불가 목록은 1차 체크 결과를 사용한다(재체크 대상에 포함되지 않았으므로).

### [6] 마무리

**AI 서버**: 대상 중 `ai_server_list`와 완전 일치하는 호스트가 있으면 노란색으로 `AI GPU 서버있음, 따로 설정확인필요/GPU power limit`를 출력한다. 스크립트 실행(`gossh -script -w check_list_${user} "bash $ai_server_script"`)은 그중 **OK 호스트만** 대상으로 한다(접속불가 호스트의 타임아웃 대기를 피하기 위함). `check_list_${user}`는 임시 파일이다.

**벤더 판별** (시작 일치)

| 벤더 | 패턴 |
|---|---|
| D | `^c`, `^h`, `^sh`, `^s2h`, `^s3h`, `^s4h` |
| L | `^p` |
| J | `^l` |
| T | `^d` |
| W | `^m` |

**코멘트 규칙**

| 상황 | 출력 |
|---|---|
| D벤더에 접속불가가 있음 | D 템플릿 1: 접속불가 목록 + 접속완료(OK) 목록 |
| D벤더가 모두 접속가능 | D 템플릿 2: 접속완료(OK) 목록 |
| L/J/T/W에 접속불가가 있음 | 해당 벤더 템플릿: `안녕하세요 X 담당자님` + 접속불가 목록 |
| 전체 대상이 모두 접속가능 | 공통 템플릿 (D 템플릿 2와 함께 출력) |

- 서버 목록은 가로(공백 구분)로 나열하고, `@대`에는 해당 목록의 대수가 들어간다.
- "접속완료 서버"는 OK 호스트만 뜻한다. pingO_sshx / nosvrauto / os_install 서버는 코멘트에 넣지 않고 아래 "기타 상태 서버 요약"으로 따로 출력한다.
- 어느 벤더에도 해당하지 않는 호스트는 공통 코멘트와 집계에만 포함된다.

**DHCP** (접속불가가 있을 때, 코멘트 바로 아래에 출력)

```bash
ssh $dhcp_server "cat > /root/off_server_list_${user}; bash /root/a.sh; rm -f /root/off_server_list_${user}" < 접속불가목록
```

기존 scp + ssh 두 번을 한 번으로 합친 방식이다. 원격에 생성되는 파일 이름은 기존과 같다. 결과는 파일로 저장하지 않고 바로 출력하며, 로컬에도 파일을 남기지 않는다.

- 접속불가 목록은 gossh의 압축 표기(`host[01-03]`)를 풀어서 **한 줄에 호스트 하나씩** 기록한다.

**기타 상태 서버 요약**: 코멘트 대상은 아니지만 확인이 필요한 서버들이다. 해당 상태의 서버가 있을 때만 노란색으로 출력한다.

```
[기타 상태 서버]
pingO_sshx(3대) : host1 host2 host3
nosvrauto(1대)  : host4
os_install(2대) : host5 host6
```

**usb0**: 체크 결과 중 `FAIL`, `usb0`, `interface`가 모두 들어간 줄에서 hostname만 뽑아 중복 없이 출력한다.

```
하기서버들은 usb0 disabled가 필요합니다.
host1 host2 ...
```

**VWP**: 호스트명에 `ev`가 들어간 대상을 `vm_inventory`에서 찾아 `vwp`가 포함된 줄이 있으면, `VWP를 사용하는 서버가 존재함`을 빨간색 깜빡임으로 출력하고 해당 줄을 출력한다.

## 6. 파일 관리

- 모든 중간 파일(정리된 목록, gossh 결과 파일, `check_list_${user}`, 접속불가 목록)은 `mktemp -d` 안에 만들고, 종료 시(`trap EXIT`, Ctrl+C 포함) 삭제한다.
- 체크 결과 원본만 실행 디렉터리의 `check.res_${user}`로 남긴다. 재체크를 하면 이 파일을 덮어쓴다.

## 7. 검증 계획 (.58 Rocky, gossh v2)

1. lab VM에 고정 경로와 똑같이 가짜 스크립트를 만든다 (`info_mn.sh`, `info.sh`, `run.sh`, 설정 스크립트 3개, inventory 파일, DHCP용 `a.sh`). 스크립트 본체에는 테스트용 코드를 넣지 않는다.
2. 대상: 실제 접속 가능한 호스트 + 존재하지 않는 호스트(pingX) + 22번 포트가 닫힌 호스트(pingO_sshx)를 섞는다.
3. 확인 항목

| 항목 | 기대 결과 |
|---|---|
| 호스트 파싱 | 공백/줄바꿈 혼합 파일에서 중복 없이 정확히 집계 |
| 30행 출력 | 31번째 호스트가 2열 1행에 위치 |
| 상태줄 | 각 수치가 gossh 결과 파일과 일치하고 색상이 맞음 |
| FAIL | FAIL 줄만 출력, 없으면 NO FAIL |
| LDAP | 1종이면 `LDAP : infra`, 2종 이상이면 노란 경고 + 대수 + 소수 호스트 |
| y / set | gossh 1회로 2개 / 3개 스크립트 실행 확인, 재체크 수행 |
| 코멘트 | D·L·J·T·W 및 전체 정상 케이스 각각 템플릿 일치 |
| DHCP / usb0 / VWP / AI | 조건이 맞을 때만 출력 |
| DHCP 전송 목록 | 압축이 풀린 상태로 한 줄에 호스트 하나 |
| 기타 상태 요약 | pingO_sshx / nosvrauto / os_install 서버가 상태별 대수와 함께 나열됨 |
| 잔여 파일 | 종료 후 `check.res_${user}` 외에 남는 파일 없음 (원격 DHCP 서버 포함) |
| 속도 | 동일 대상 기준 기존 방식 대비 gossh 실행 횟수 비교 |
