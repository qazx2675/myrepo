[ -r /tmp/anaconda.log ] || echo NS_NOLOG
[ -r /tmp/anaconda.log ] && grep -qF -e '<DISK_PATTERN1>' ... /tmp/anaconda.log && echo NS_DISK
[ -r /tmp/anaconda.log ] && grep -qF -e '<ERROR_PATTERN1>' ... /tmp/anaconda.log && echo NS_ERR
# 변수·중괄호·exit 를 쓰지 않는다 — root 로그인 셸이 csh 여도 돌게 하려는 것(랩 .60 에서 확인)# new_setup — 신규 OS 배포 후 설치 상태 판정 도구 (계획서)

> 상태: **계획 확정, 구현 미착수** (2026-11-04 인터뷰 결과 반영)
> 위치: `.claude/HPC/setup_check/`  /  실행 이름: `new_setup`

## 1. 목적

신규 OS 배포 후 대상 장비 전체를 한 번에 점검해, 장비마다 아래 상태 하나를 판정해 출력한다.

```
hostname<TAB>상태
```

- 상태값: `완료` | `디스크미인식` | `설치정지` | `OS설치중` | `접속불가`
- 헤더 없음, **입력 파일 순서 그대로**, 구분자는 탭 1개 → 터미널에서 복사해 엑셀에 붙이면 바로 2열로 들어감
- stdout 에는 위 줄만 나간다. 진행 안내·요약은 전부 stderr

## 2. 사용법

```bash
new_setup <호스트파일>          # 예: new_setup a
new_setup <호스트파일> > result.tsv
```

- `<호스트파일>` 은 gossh `-w` 에 그대로 넘기는 파일(한 줄에 hostname 하나)
- 설정 파일: 실행 파일 옆 `new_setup.conf` (없으면 기본값으로 동작)

```ini
# gossh 경로. 비우면 PATH 에서 찾는다.
GOSSH=
# 디스크미인식 판정 문구(고정 문자열, 여러 줄 가능)
DISK_PATTERN=Disk "" given in clearpart command does not exist
# 설치정지 판정 문구(고정 문자열, 여러 줄 가능). 처음엔 비워 두고 현장에서 채운다.
#ERROR_PATTERN=
```

## 3. 판정 흐름 (2단계 실행)

```
[0] 호스트파일 읽기 (출력 순서용, gossh 와 같은 규칙)
[1] gossh -w <파일> -pm -script "uptime"
      ├ <파일>_res_off, <파일>_res_refsed       → 접속불가
      ├ <파일>_os_install                        → [2] 로 (설치중 후보)
      └ 나머지 (접속·명령 실행됨)                → 완료
[2] 설치중 후보만 임시 목록으로 gossh -w <임시> -script "<로그 확인 명령>"
      ├ DISK_PATTERN 일치                        → 디스크미인식
      ├ ERROR_PATTERN 일치                       → 설치정지
      └ 둘 다 없음 / 로그 없음 / 2차 접속 실패   → OS설치중
[3] 입력 순서대로 "hostname<TAB>상태" 출력, stderr 에 상태별 대수 요약
```

판정 우선순위(한 장비에 여러 문구가 있을 때): 디스크미인식 > 설치정지 > OS설치중.

### gossh 동작 근거 (소스 `.claude/공통/gossh/main.go` 확인)

| 항목 | gossh 동작 | 도구에서의 처리 |
|---|---|---|
| `-pm` | `~/.profile` 에 anaconda 가 있으면 "OS 설치중" 으로 보고 **명령(uptime)을 실행하지 않고 종료** (main.go:1009) | 그래서 2단계로 다시 접속해 로그를 본다 |
| 결과 파일 | 호스트파일(앞의 `^` 제거) 옆에 `_res_off`(타임아웃·DNS 실패·세션 실패), `_res_refsed`(포트 닫힘), `_os_install`, `_nosvrauto`, `_res_cancel` 생성. 목록이 비면 파일을 안 만들지만, gossh 가 시작할 때 이 5개를 지우도록 돼 있으나 **랩의 실제 gossh 는 항상 지우지 않았다**(그래서 도구가 1차 전에 직접 삭제) | 이 파일로 분류. 파일이 없으면 해당 0대로 본다 |
| 출력 | 원격 stdout → `host: 내용` (stdout), 접속 실패·원격 stderr·`host: ERROR: 종료코드 N` → stderr. `-script` 면 요약·색상 없음 | gossh 출력은 화면에 섞지 않고 로그 파일(`<파일>_new_setup.log`)에 모아 둔다 |
| 재검증 | 1차 실패 호스트는 gossh 가 스스로 최대 8초 제한으로 한 번 더 시도 | 도구는 따로 재시도하지 않는다 |
| 위험어 | 명령 문자열에 reboot/poweroff/shutdown/halt/init 0/init 6/ddc 가 들어가면 실행 거부 | 설정 문구에 위험어가 있으면 시작 시 오류로 알려 준다 |

### 2차 로그 확인 명령 (개요)

원격에서 문구를 고정 문자열로 찾아 표시만 찍는다 (MOTD 등과 섞여도 구분되게 접두어 사용).

```sh
f=/tmp/anaconda.log; [ -r "$f" ] || { echo NS_NOLOG; exit 0; }
grep -qF -e '<DISK_PATTERN1>' ... "$f" && echo NS_DISK
grep -qF -e '<ERROR_PATTERN1>' ... "$f" && echo NS_ERR
```

문구는 작은따옴표 이스케이프(`'` → `'\''`) 후 넣는다. ERROR_PATTERN 이 비면 해당 줄 자체를 넣지 않는다.

### 구현 인터페이스 (병렬 작업 공통 약속)

- 실행: `new_setup [-c <설정파일>] <호스트파일>`. `-c` 기본값 = 실행 파일과 같은 폴더의 `new_setup.conf`, 없으면 기본값 사용
- 설정 키: `GOSSH=`, `DISK_PATTERN=`(여러 줄), `ERROR_PATTERN=`(여러 줄). `#` 주석·빈 줄 무시. `DISK_PATTERN` 이 하나도 없으면 기본 문구 1개 사용
- gossh 위치: `GOSSH` 값 → 비면 `exec.LookPath("gossh")`. 없으면 stderr 오류 후 종료코드 2
- 1차: `<gossh> -w <호스트파일> -pm -script uptime` (작업 폴더 = 호스트파일 폴더 그대로)
- 2차: 설치중 후보를 `<호스트파일>_new_setup_retry` 임시 파일에 써서 `<gossh> -w <그 파일> -script '<로그확인명령>'`, 끝나면 임시 파일과 그 결과 파일들 삭제
- 2차 stdout 파싱: `host: NS_DISK` / `host: NS_ERR` / `host: NS_NOLOG` (콜론+공백 뒤 값)
- gossh 의 stdout·stderr 는 `<호스트파일>_new_setup.log` 에 이어 붙임 (실행 시작 시 비움)
- 종료코드: 0 = 정상 판정 완료(장비 상태와 무관), 1 = 사용법 오류, 2 = 설정/gossh 실행 오류
- 바이너리 이름: `bin/new_setup`(os8, linux/amd64), `bin/new_setup_os6`(.60 의 go1.20 으로 빌드)
- 래퍼 `new_setup.sh`: `/etc/redhat-release` 가 6.x 이면 `bin/new_setup_os6`, 아니면 `bin/new_setup` 실행, 인자 그대로 전달
- fake gossh(`test/fake_gossh.sh`): 환경변수 `FAKE_GOSSH_SCENARIO=<파일>` 의 `host<TAB>시나리오` 로 동작. 시나리오 = `ok` | `off` | `refused` | `install_disk` | `install_err` | `install_none` | `install_nolog` | `install_retry_off` | `cancel`. `-pm` 이 있으면 1차, 없으면 2차로 보고 결과 파일·출력을 gossh 와 같은 형식으로 만든다

## 5. 검증 기준

랩(.58)에서만 실행한다.

1. `go test` 통과
2. `test/run_tests.sh` 에서 fake_gossh 로 아래 경우가 모두 기대 상태로 나오는지 확인
   - 정상 접속 → `완료`
   - `_res_off` / `_res_refsed` → `접속불가`
   - 설치중 + 디스크 문구 → `디스크미인식`
   - 설치중 + 오류 문구(설정에 넣은 경우) → `설치정지`
   - 설치중 + 문구 없음 / 로그 없음 / 2차 접속 실패 → `OS설치중`
   - 이전 실행의 `_os_install` 이 남아 있어도 이번 결과에 섞이지 않음
3. 출력 검증: stdout 각 줄이 정확히 탭 1개로 2필드(`awk -F'\t' 'NF!=2'` 결과 없음), 입력 순서와 동일, 헤더 없음
4. 실제 gossh 로 랩 VM 몇 대에 실행해 `완료`/`접속불가` 확인 (설치중 상태는 랩 재현이 어려우면 fake 로만 확인 — 결과 보고 때 명시)
5. os6 바이너리를 .60 에서 빌드해 실행 확인

## 8. 가정·미확인 (구현 전에 확인할 것)

- 호스트파일 형식(확인됨, main.go:1505-1535): 줄 앞뒤 공백 제거, 빈 줄·`#` 시작 줄 무시, 한 줄 안의 쉼표/공백으로 분리, `node[01-10]` 범위 확장(0 패딩 유지, 괄호 여러 개 재귀; 파일에서는 쉼표 분리가 먼저라 `a[1,3,5-7]` 은 gossh 도 깨지므로 똑같이 둔다), 먼저 나온 순서로 중복 제거. 출력 순서용 목록도 이 규칙 그대로 구현한다
- `_res_cancel`(Ctrl+C 취소) 호스트는 `접속불가` 로 출력한다고 가정
- 2차 접속에서 실패한 설치중 장비는 1차에서 접속이 됐으므로 `OS설치중` 유지 + stderr 경고
- `-pm` 은 `/user/svrauto` 점검도 같이 하지만 이 도구에서는 무시(`_nosvrauto` 미사용)
- 설치 중 sshd 환경에서 `/tmp/anaconda.log` 를 root 로 읽을 수 있다고 가정 (사용자 경험상 확인 가능했음)
- 범위 밖: 로드에버리지 판정, 자동 재설치·조치, AWX 연동 (awxkit/awx_script 는 호스트 목록 형식 참고용으로만 봄)
