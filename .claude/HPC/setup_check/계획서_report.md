# 계획서: -run 화면의 리포트 (벤더별 진행 보고 글)

작성 2026-11-12. 대상: `new_setup -run` 의 TUI(tui.go, render.go)와 설정 해석(main.go `parseConf`).
상태: 구현 완료(2026-11-12). 구현 결과는 문서 끝의 8장에 적었다. 5장 이후의 "기본값" 항목 중 현장 확인이 필요한 것은 8장의 "확인하지 못한 것"에 다시 적었다.
문체: ASD-STE100 의 원칙(용어 하나에 뜻 하나, 한 문장에 한 동작, 짧은 문장)을 한국어에 맞춰 적용했다. 영어 전용 규칙은 적용하지 않았다.
표기: 이 문서에서 `(신규)` 가 붙은 이름은 아직 코드에 없다. 붙지 않은 이름은 지금 코드에 있다.

## 0. 요약과 범위

`new_setup -run` 화면에서 `p` 키를 누르면 벤더별 리포트를 만든다. 리포트는 OS 설치 대수, 부하테스트 대수, 접속불가 서버를 벤더마다 같은 양식으로 적는다. 벤더는 설정 파일의 `VENDOR_<이름>=<패턴 목록>` 줄로 정한다. 전일대비 값은 사용자가 고른 기준과 비교해 만든다. 기준은 전일 저장본(방식 1) 또는 사용자가 넣은 전날 코멘트(방식 2)다. 리포트는 화면에 보이고 상태 폴더의 `report_YYYYMMDD.txt` 에도 저장된다.

범위는 다음과 같다.

- 리포트만 만든다. TUI 가 state.json 을 읽어 혼자 처리한다.
- 워커 규약(`state.json`, `answer.json`, `stop.req`)은 바꾸지 않는다. `stateVersion` 도 그대로 둔다.
- 워커(worker.go, auto.go)는 고치지 않는다.
- stress-test 는 고치지 않는다.
- 새 외부 의존성은 없다. 표준 라이브러리만 쓴다.

하지 않는 것은 다음과 같다.

- 명령줄 옵션으로 리포트를 만드는 것(`-report` 등).
- tty 가 아닐 때의 리포트.
- 기준을 자동으로 고르는 것.
- 리포트를 메일·메신저로 보내는 것.
- 리포트를 만들기 전에 판정을 새로 돌리는 것.
- `-doctor` 보고서에 벤더 규칙을 보이는 것.
- `setup.sh` 의 대화형 설정에 벤더 규칙 질문을 더하는 것.
- 워커, state.json, stress-test 를 바꾸는 것.

## 1. 용어 (이 문서에서 한 가지 뜻으로만 쓴다)

| 용어 | 뜻 |
|---|---|
| 리포트 | 벤더별 진행 상황을 정해진 양식으로 적은 글. 이 기능의 결과물이다 |
| 벤더 규칙 | 설정 파일의 `VENDOR_<이름>=<패턴 목록>` 한 줄 |
| 벤더 | 벤더 규칙의 `<이름>` 부분. 규칙에 맞지 않는 호스트의 벤더는 `기타` 다 |
| 현재 | 리포트를 만드는 순간의 state.json 내용(`runState.Hosts`) |
| 기준 | 전일대비를 계산할 때 현재와 비교하는 전날 값. 방식 1 또는 방식 2 로 얻는다 |
| 스냅샷 | 리포트를 만들 때마다 상태 폴더에 저장하는 `report_YYYYMMDD.json`. 방식 1 의 기준이 된다 |
| 코멘트 | 사용자가 넣는 전날 리포트 글. 사람이 조금 고쳤을 수 있다. 방식 2 의 기준이 된다 |
| OS 완료 | 호스트의 상태 열이 `완료`(`stDone`)인 것 |
| OS 설치 중 | 호스트의 상태 열이 `OS설치중`(`stInstall`)인 것 |
| 부하 완료 | OS 완료 호스트 중 stress-ng 열이 `O` 인 것 |
| 접속불가 | 호스트의 상태 열이 `접속불가`(`stUnreach`)인 것 |
| 접속불가서버 | 상태가 `접속불가` 이거나 `디스크미인식`(`stNoDisk`)인 호스트. 리포트의 `접속불가서버 N대` 와 명단은 이 호스트를 센다 |
| 조치완료 | 기준에서는 접속불가서버였고 현재는 접속불가서버가 아닌 호스트 |
| 전일대비 | 현재 값에서 기준 값을 뺀 수. 부호를 붙여 적는다 |
| 완료예정일 | 오늘 날짜에 `REPORT_ETA_DAYS` 일을 더한 날짜 |

## 2. 확정한 정책 (인터뷰 결과)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 실행 방법 | `-run` TUI 안의 키. 별도 명령줄 옵션은 만들지 않는다 |
| 1 | 키 | `p`. 근거는 3.6 에 적었다 |
| 1 | 출력 | 화면에 보인다. 상태 폴더의 `report_YYYYMMDD.txt` 에도 쓴다(파일 출력은 계획 작성자가 고른 기본값이다. 빼기 쉽다) |
| 2 | 벤더 규칙 | 벤더마다 한 줄. `VENDOR_<이름>=<패턴>,<패턴>`. 패턴은 호스트 이름에 대한 glob 이다 |
| 2 | 대소문자 | 패턴 비교는 대소문자를 구분하지 않는다 |
| 2 | 겹침 | 설정 파일에서 먼저 나온 벤더가 이긴다 |
| 2 | 규칙에 없는 호스트 | 벤더 `기타` 로 묶는다. 같은 양식으로 적는다 |
| 3 | 줄 1 분모 | 그 벤더의 호스트 수(이번 작업의 호스트 목록 기준) |
| 3 | 줄 2 | `부하테스트 A대 중 B대 완료`. A = OS 완료 대수, B = 부하 완료 대수 |
| 3 | 완료예정일 | 오늘 + `REPORT_ETA_DAYS`(신규 설정 키, 기본 2). A = N(OS 완료 대수가 호스트 수와 같음)이고 B = A 이면 날짜 대신 `완료` 를 적는다. A < N 이면 B = A 여도 날짜를 적는다 |
| 4 | 접속불가 블록 | 현재 접속불가서버(디스크미인식 포함)가 1대 이상일 때 적는다. 대수, 전일대비, 조치완료 목록, 현재 접속불가 목록 순서다 |
| 4 | 현재 0대, 기준 1대 이상 | 리포트를 두 본으로 출력한다. 본 A 는 `접속불가서버 0대 (전일대비 -N대)` 줄과 조치완료 줄을 적는다. 본 B 는 접속불가 블록을 모두 적지 않는다(3.5 의 "두 본" 참고) |
| 6 | 방식 1 과 `-new` | `-new` 가 상태 폴더를 옮기면 방식 1 은 기준을 찾지 못한다. 그때 사용자는 방식 2 를 쓴다. `.old-*` 폴더는 찾지 않는다 |
| 5 | 기준 고르기 | 사용자가 매번 고른다. 자동으로 고르지 않는다. `1 전일 저장본 / 2 코멘트 입력` |
| 5 | 방식 1 | 오늘보다 앞 날짜의 가장 최근 스냅샷. 호스트 목록이 같을 때만 비교한다 |
| 5 | 방식 2 | 코멘트를 느슨하게 읽는다. 읽은 내용을 보여 주고 `y` 를 받은 뒤 리포트를 만든다 |
| 5 | 스냅샷 저장 | 리포트를 만들 때마다 오늘 스냅샷을 저장한다. 같은 날 파일은 덮어쓴다 |
| 6 | 양식 | 사용자가 준 틀 그대로(들여쓰기 4칸). 벤더는 설정 파일 순서, `기타` 는 마지막, 벤더 사이에 빈 줄 하나 |

## 3. 설계

### 3.1 자료의 흐름

현재 값은 모두 state.json 에서 온다. TUI 는 이미 이 파일을 읽고 있다.

| 필요한 값 | 지금 코드의 위치 |
|---|---|
| 호스트 목록 | `runState.Hosts` (`[]hostRow`, 호스트파일 순서) |
| 호스트 이름 | `hostRow.Host` |
| 상태 | `hostRow.Status`. 값은 `완료` `디스크미인식` `설치정지` `OS설치중` `접속불가` (main.go 의 `stDone` `stNoDisk` `stStopped` `stInstall` `stUnreach`) |
| stress-ng 열 | `hostRow.Stress`. 값은 `O` / `NOTRUN` / `-` |
| 상태 폴더 | `runTUI(dir)` 의 `dir`. `stateDirFor` 와 `runState.runDir` 가 같은 값을 만든다 |
| 설정 파일 경로 | `runState.ConfPath`(절대 경로. 빈 값이면 기본값을 쓴 작업이다) |
| 읽은 상태 | `runTUI` 의 `refresh` 가 `stateCache.load(dir)` 로 얻은 `st` |

순서는 다음과 같다.

1. 사용자가 `p` 를 누른다.
2. TUI 가 `runState.ConfPath` 의 파일을 읽고 `parseConf` 로 벤더 규칙과 `REPORT_ETA_DAYS` 를 얻는다.
3. TUI 가 기준을 묻는다(`1` / `2`).
4. TUI 가 기준을 만든다(스냅샷 읽기 또는 코멘트 해석).
5. `buildReport`(신규)가 현재와 기준으로 리포트 글을 만든다.
6. TUI 가 오늘 스냅샷과 `report_YYYYMMDD.txt` 를 쓴다.
7. TUI 가 리포트를 화면에 보인다.

주의할 점이 세 가지 있다.

- TUI 는 지금 설정 파일을 읽지 않는다. 이 기능이 처음으로 읽는다.
- `loadConf` 를 쓰지 않는다. `loadConf` 는 경로가 빈 값이면 stderr 에 `설정 파일:` 줄을 내고, 이 줄은 TUI 화면을 깨뜨린다. `os.ReadFile(st.ConfPath)` 와 `parseConf` 를 직접 쓴다.
- `ConfPath` 가 빈 값이면 벤더 규칙이 없는 것으로 본다.

현재 값은 워커가 마지막으로 판정한 값이다. TUI 는 판정을 새로 하지 않는다. 화면의 리포트 위에 `runState.Updated` 시각을 보인다. 리포트 글에는 넣지 않는다.

### 3.2 설정 키 (신규 2종)

`parseConf` 의 `switch key` 는 지금 이름이 정확히 같은 키만 받는다. `default` 갈래를 더해 `VENDOR_` 로 시작하는 키를 받는다.

샘플(new_setup.conf.sample 에 넣을 줄):

```
# ---- -run 화면의 리포트(p 키) 용 ----
# 벤더 규칙(여러 줄 가능): VENDOR_<이름>=<패턴>,<패턴>
# 패턴은 호스트 이름 전체에 대한 glob(* ? [abc]) 이고 대소문자를 구분하지 않는다.
# 한 호스트가 여러 벤더에 맞으면 먼저 적은 벤더가 이긴다. 어느 규칙에도 맞지 않으면 '기타'.
#VENDOR_HPE=hpe*,dl3*
#VENDOR_DELL=dell*
# 부하테스트 완료예정일 = 오늘 + 이 일수(0 이상의 정수, 기본 2)
#REPORT_ETA_DAYS=2
```

`config` 에 더할 필드(신규):

```go
type vendorRule struct {
	Name     string   // 리포트에 적을 이름(설정에 적은 글자 그대로)
	Patterns []string // 소문자로 바꾼 glob
}
// config
Vendors       []vendorRule // 설정 파일 순서
ReportETADays int          // 기본 2
```

해석 규칙:

- 이름은 `VENDOR_` 뒤의 글자 전체다. 적은 글자 그대로 리포트에 적는다.
- 값은 `unquote` 를 거친 뒤 `,` 로 나눈다. 각 패턴의 앞뒤 공백을 뗀다. 빈 패턴은 버린다.
- 패턴과 호스트 이름을 모두 소문자로 바꾼 뒤 `path.Match` 로 비교한다. 패턴은 호스트 이름 전체와 맞아야 한다.
- 같은 이름(대소문자 무시)의 줄이 두 번 나오면 패턴을 첫 줄에 합친다. 순서는 첫 줄의 자리다.
- `[` `]` 는 glob 의 문자 묶음이다. 호스트파일의 범위 표기(`node[01-10]`, `expandHostLine`)와 뜻이 다르다. 샘플 주석에 이 점을 적는다.

검사와 경고(모두 `config.Warnings` 에 넣는다. 지금 방식과 같다):

| 경우 | 처리 | 문구 |
|---|---|---|
| 이름이 빈 값(`VENDOR_=…`) | 줄을 무시 | `설정 VENDOR_ 줄에 벤더 이름이 없어 무시합니다(형식: VENDOR_<이름>=<패턴>,<패턴>)` |
| 이름이 `기타` | 줄을 무시 | `설정 VENDOR_기타 는 쓸 수 없는 이름이어서 무시합니다('기타' 는 규칙에 없는 호스트의 자리입니다)` |
| 패턴이 하나도 없음 | 줄을 무시 | `설정 VENDOR_<이름> 에 패턴이 없어 무시합니다(예: VENDOR_HPE=hpe*,dl3*)` |
| 패턴이 잘못됨(`path.Match` 가 `ErrBadPattern`) | 그 패턴만 버림 | `설정 VENDOR_<이름> 의 패턴 "<패턴>" 을(를) 읽을 수 없어 뺍니다` |
| `REPORT_ETA_DAYS` 가 0 이상의 정수가 아님 | 기본값 2 | `설정 REPORT_ETA_DAYS 값 "<값>" 을(를) 읽을 수 없어 기본값 2 를 씁니다(0 이상의 정수)` |

경고가 보이는 곳:

- `-run` 시작 때 stderr(run.go 160행 근처의 지금 반복문).
- worker.log(worker.go 1258행 근처의 지금 반복문).
- 리포트 화면 위쪽. `VENDOR_` 와 `REPORT_ETA_DAYS` 경고만 보인다.

벤더 판정 함수(신규): `func vendorOf(host string, rules []vendorRule) string`. 맞는 규칙이 없으면 `기타` 를 돌려준다.

### 3.3 스냅샷 파일

- 이름: 상태 폴더의 `report_YYYYMMDD.json`. 날짜는 리포트를 만든 날(서버의 지역 시각)이다.
- 쓰기: `writeFileAtomic` 을 쓴다. 같은 날 파일은 덮어쓴다.
- 쓰는 때: 리포트를 만들 때마다. 방식 1, 방식 2 모두 쓴다.
- 내용은 현재다. 기준은 넣지 않는다.

```go
type repSnapshot struct {   // (신규)
	Version int        `json:"version"` // 1
	Date    string     `json:"date"`    // "2026-11-12"
	Made    time.Time  `json:"made"`
	Hosts   []repHost  `json:"hosts"`   // 호스트파일 순서
}
type repHost struct {       // (신규)
	Host     string `json:"host"`
	Vendor   string `json:"vendor"`    // 저장할 때의 벤더(참고용)
	Status   string `json:"status"`
	StressOK bool   `json:"stress_ok"` // stress-ng 열이 O
}
```

규칙:

- 방식 1 의 기준은 날짜가 오늘보다 앞인 파일 중 가장 최근 파일이다. 날짜는 파일 이름에서 읽는다.
- 기준의 벤더는 저장된 `vendor` 가 아니라 지금 벤더 규칙으로 다시 정한다. 규칙을 고친 날에도 양쪽이 같은 규칙으로 나뉜다.
- `version` 이 1 보다 크면 읽지 않고 오류를 보인다.
- 옛 상태 폴더에는 이 파일이 없다. 그때 방식 1 은 "전일 저장본이 없습니다" 를 보인다. 그 밖의 동작은 바뀌지 않는다.
- state.json 에는 아무 필드도 더하지 않는다.

### 3.4 기준 만들기

두 방식 모두 같은 구조(신규)를 만든다. 리포트 작성기는 이 구조만 본다.

```go
type repBase struct {
	Label   string                    // 화면용: "저장본 2026-11-11" / "코멘트"
	Vendors map[string]*repBaseVendor // 키 = 벤더 이름 소문자
}
type repBaseVendor struct {
	OSDone, LoadDone, Unreach *int // nil = 전일 정보 없음
	Names    []string              // 접속불가서버 호스트 이름(디스크미인식 포함)
	HasNames bool                  // 이름 명단을 알고 있음
}
```

#### 방식 1: 전일 저장본

1. 상태 폴더에서 `report_YYYYMMDD.json` 을 찾는다. 날짜가 오늘보다 앞인 것 중 가장 최근 파일을 고른다.
2. 파일이 없으면 오류 화면을 보인다. 문구: `전일 저장본이 없습니다. 2(코멘트 입력)를 쓰십시오.`
3. 파일을 읽지 못하거나 형식이 틀리면 오류 화면을 보인다. 문구: `저장본 <파일 이름> 을(를) 읽을 수 없습니다: <사유>. 2(코멘트 입력)를 쓰십시오.` 더 옛 파일로 넘어가지 않는다.
4. 호스트 목록을 비교한다. 이름을 소문자로 바꾼 집합으로 비교한다. 순서는 보지 않는다.
5. 목록이 다르면 비교하지 않는다. 문구: `호스트 목록이 다릅니다. 저장본 <날짜> <N>대, 현재 <M>대. 저장본에만 있는 호스트 <a>대, 현재에만 있는 호스트 <b>대. 2(코멘트 입력)를 쓰십시오.`
6. 목록이 같으면 저장본의 호스트를 지금 벤더 규칙으로 나눠 `repBase` 를 만든다. 세 수와 이름 명단을 모두 안다. 상태가 `디스크미인식` 인 호스트는 접속불가서버로 센다(오늘의 규칙과 같다). 저장본의 형식은 그대로다. 상태가 저장되어 있기 때문이다.
7. 저장본 날짜가 어제가 아니면 화면에 `기준: 저장본 <날짜>(<n>일 전)` 을 보인다. 리포트 글의 `전일대비` 글자는 바꾸지 않는다.

#### 방식 2: 코멘트

입력 방법은 두 가지를 모두 받는다.

- 붙여넣기: 입력 화면에 글을 붙여넣고 `Ctrl-D` 로 끝낸다.
- 파일: 첫 줄에 `@<경로>` 만 적고 `Ctrl-D` 로 끝낸다. TUI 가 그 파일을 읽는다. 상대 경로는 `-run` 을 실행한 경로 기준이다.

해석기(신규): `func parseComment(text string, known []string) (*repBase, []string)`. 둘째 값은 화면에 보일 알림이다. `known` 은 설정의 벤더 이름과 `기타` 다.

해석 순서:

1. 글자를 맞춘다. 전각 숫자·영문·`：（），－` 를 반각으로 바꾼다. 탭과 전각 공백을 공백으로 바꾼다. `\r` 을 뗀다.
2. 줄마다 앞뒤 공백을 뗀다. 줄 맨 앞의 `-` `•` `·` `*` 와 그 뒤 공백을 뗀다. 빈 줄은 버린다.
3. 줄의 종류를 정한다. 비교할 때는 줄 안의 공백을 모두 없앤 글자를 쓴다.

| 줄 종류 | 조건(공백 없앤 글자 기준) | 읽는 값 |
|---|---|---|
| 벤더 제목 | `:` 로 끝나고 `대` 붙은 숫자가 없다. 또는 줄 전체가 `known` 의 이름과 같다(대소문자 무시, `:` 없어도 됨) | `:` 앞의 글자가 벤더 이름 |
| OS 줄 | `OS설치` 로 시작 | `(\d+)대완료` 의 첫 숫자 = OS 완료 |
| 부하 줄 | `부하테스트` 로 시작 | `(\d+)대완료` 의 첫 숫자 = 부하 완료 |
| 접속불가 대수 줄 | `접속불가서버` 로 시작 | `(\d+)대` 의 첫 숫자 = 접속불가 대수 |
| 명단 제목 | `접속불가` 또는 `접속불가:` 와 같다 | 없음. 다음 줄부터 명단이다 |
| 조치완료 줄 | `조치완료` 가 들어 있다 | 버린다 |
| 명단 줄 | 접속불가 대수 줄 또는 명단 제목 뒤에 나오고 위 종류가 아니다 | `,` 와 공백으로 나눈 토막 중 `[A-Za-z0-9._-]+` 전체와 맞는 것 = 접속불가 이름. 줄 끝의 `디스크 미인식` 은 이름 모양이 아니라서 읽지 않는다 |
| 그 밖 | 위에 없다 | 버린다 |

4. OS 줄, 부하 줄, 접속불가 대수 줄은 `전일대비` 글자가 나오면 그 앞까지만 본다. 그래서 `전일대비 +N대`, `완료예정`, 날짜 글자는 읽지 않는다.
5. 벤더 제목이 나오기 전의 줄은 버린다.
6. 같은 벤더 제목이 두 번 나오면 뒤의 블록이 앞의 값을 덮는다. 알림에 적는다.

값이 없을 때의 규칙(한 가지 규칙: 모르는 값은 `전일 정보 없음` 으로 적고, 숫자를 지어내지 않는다):

| 없는 것 | 기준 값 | 리포트에 적히는 것 |
|---|---|---|
| 벤더 블록 전체 | 세 수 모두 nil | 그 벤더의 전일대비 자리 세 곳이 모두 `전일 정보 없음`. 조치완료 줄 없음 |
| OS 줄 또는 그 숫자 | `OSDone` nil | 줄 1 의 괄호가 `(전일 정보 없음)` |
| 부하 줄 또는 그 숫자 | `LoadDone` nil | 줄 2 의 가운데가 `전일 정보 없음` |
| 접속불가 대수 줄(벤더 블록은 있음) | `Unreach` = 0, 명단은 빈 것으로 앎 | 전일 0대로 계산한다. 리포트는 접속불가가 0대이면 이 블록을 적지 않기 때문이다 |
| 접속불가 대수의 숫자만 없음, 명단은 있음 | `Unreach` = 명단의 이름 수 | 그 수로 계산한다 |
| 명단만 없음, 숫자는 있음 | `HasNames` 거짓 | 대수의 전일대비는 적는다. 조치완료 줄은 적지 않는다 |
| 숫자와 명단의 이름 수가 다름 | 대수는 숫자, 이름은 명단 | 그대로 쓴다. 알림에 `<벤더>: 접속불가 숫자 <n>대와 이름 <m>개가 다릅니다` 를 적는다 |
| 코멘트가 빈 글 | 벤더 없음 | 모든 벤더가 `전일 정보 없음`. 첫날에는 이 방법으로 리포트를 만든다 |

그 밖의 규칙:

- 코멘트의 벤더 이름은 설정의 벤더 이름과 대소문자를 무시하고 맞춘다.
- 코멘트에 있고 설정에 없는 벤더는 비교에 쓰지 않는다. 확인 화면에 `설정에 없는 벤더: <이름>` 을 보인다.
- 코멘트의 접속불가 이름이 현재 호스트 목록에 없으면 조치완료로 적지 않는다. 확인 화면에 `현재 목록에 없는 이름 <n>개` 를 보인다.
- 해석기는 어떤 글에도 오류로 끝나지 않는다. 읽을 수 없는 줄은 버린다.
- 코멘트는 2000줄 또는 256KB 까지 받는다. 넘으면 오류 화면을 보인다.

확인 화면: 해석한 내용을 벤더마다 한 줄로 보인다. 그 뒤 `y` 를 받는다. 다른 키는 취소다.

```

  HPE   OS완료 549  부하완료 480  접속불가 5 (hpe-0007 hpe-0101 hpe-0230 hpe-0312 hpe-0440)
```

### 3.5 리포트 작성기 (순수 함수)

```go
// (신규) 파일·시계·화면을 쓰지 않는다. 같은 입력이면 같은 글이 나온다.
func buildReport(cur []repHost, order []string, base *repBase, today time.Time, etaDays int) string
```

- `cur`: 현재 호스트(벤더 포함). `runState.Hosts` 에서 만든다. 제외(`Excluded`)·포기(`GaveUp`) 호스트도 넣는다.
- `order`: 설정 파일의 벤더 이름 순서. 작성기가 끝에 `기타` 를 붙인다.
- `base`: 기준. 벤더가 없거나 값이 nil 이면 그 자리는 `전일 정보 없음` 이다.

대수 계산(벤더마다):

| 이름 | 계산 |
|---|---|
| N | 그 벤더의 호스트 수 |
| D | 상태가 `완료` 인 수(OS 완료) |
| I | 상태가 `OS설치중` 인 수 |
| A | D 와 같다 |
| B | 상태가 `완료` 이고 stress-ng 열이 `O` 인 수(부하 완료) |
| U | 상태가 `접속불가` 이거나 `디스크미인식` 인 수(접속불가서버). `디스크미인식` 은 D 에 세지 않고 N 에는 센다 |

양식:

```
<벤더>:
    OS설치 <N>대 중 <D>대 완료, <I>대 OS 설치 중 (전일대비 <D−기준D>대)
    부하테스트 <A>대 중 <B>대 완료, 전일대비 <B−기준B>대, <완료예정일> 완료예정
    접속불가서버 <U>대 (전일대비 <U−기준U>대)
        - <조치완료 호스트> 조치완료
        접속불가
          - <접속불가 호스트>
          - <디스크미인식 호스트> 디스크 미인식
```

규칙:

- 들여쓰기는 4칸, 8칸, 10칸이다. 사용자가 준 틀과 같다.
- 전일대비 수는 늘 부호를 붙인다(`+5대`, `-2대`, `+0대`). 변화가 없으면 `+0대` 다.
- 기준 값이 nil 이면 `전일대비 <수>대` 자리에 `전일 정보 없음` 을 적는다. 줄 1 과 줄 3 은 `(전일 정보 없음)` 이다.
- 완료예정일은 `월/일` 로 적는다(예 `11/14`). 앞에 0 을 붙이지 않는다.
- A = N 이고 B = A 이면 `<완료예정일> 완료예정` 대신 `완료` 를 적는다. A < N 이면 B = A 여도 완료예정일을 적는다. A = 0 이고 N > 0 이면 B = 0 이므로 완료예정일을 적는다.
- 접속불가 블록(줄 3 이하)은 U 가 1 이상일 때 적는다. U 에는 디스크미인식 호스트가 들어 있다.
- U 가 0 이고 조치완료 호스트가 있으면 이 글은 두 본으로 나온다(아래 "두 본"). 본 A 는 줄 3 과 조치완료 줄만 적는다. `접속불가` 제목과 명단은 적지 않는다. 본 B 는 줄 3 이하를 모두 적지 않는다.
- U 가 0 이고 조치완료 호스트도 없으면 줄 3 이하를 적지 않는다.
- 조치완료 호스트는 기준의 접속불가서버 이름 중 현재 목록에 있고 현재 접속불가서버가 아닌 것이다(상태가 `접속불가` 도 `디스크미인식` 도 아님). 기준의 이름 순서로 적는다. 접속불가에서 디스크미인식으로 바뀐 호스트는 조치완료가 아니다.
- 접속불가서버 호스트는 호스트파일 순서로, 한 줄에 하나씩 적는다. 200대여도 줄을 합치지 않는다. `접속불가` 호스트와 `디스크미인식` 호스트를 한 명단에 섞어 적는다. `디스크미인식` 호스트는 이름 뒤에 ` 디스크 미인식` 을 붙인다.
- 두 본: 벤더 하나라도 "U = 0 이고 조치완료 호스트 있음" 이면 `buildReport` 는 글 두 개를 돌려준다. 본 A 는 위 규칙 그대로다. 본 B 는 그 벤더의 접속불가 블록(줄 3 이하)을 적지 않는다. 다른 벤더는 두 본이 같다. 그 경우가 없으면 글은 하나다.
- 두 본은 화면에서 `[본 A: 0대 줄과 조치완료 적음]` 과 `[본 B: 접속불가 블록 적지 않음]` 제목 아래에 위아래로 보인다. 제목 줄은 파일에 쓰지 않는다.
- 호스트가 0대인 벤더는 적지 않는다. `기타` 도 0대이면 적지 않는다.
- 벤더 사이에 빈 줄 하나를 둔다. 글 끝에는 개행 하나를 둔다.
- `설치정지` 는 1대 이상일 때만 줄 1 에 덧붙인다. 예: `…, 1대 OS 설치 중, 2대 설치정지 (전일대비 +5대)`. 0대이면 줄 1 은 틀과 같다.
- `디스크미인식` 은 줄 1 에 적지 않는다. 접속불가서버에 넣는다(6.2 에서 정했다). 분모 N 에는 들어 있고 완료(D)에는 들어 있지 않다.

출력 예(오늘 2026-11-12, `REPORT_ETA_DAYS=2`, 벤더 2개):

```

    OS설치 558대 중 554대 완료, 1대 OS 설치 중 (전일대비 +5대)

        - hpe-0230 조치완료

          - hpe-0007
```

### 3.6 TUI 바꿀 것

#### 키 고르기

`p` 를 쓴다. 확인한 것은 다음과 같다.

| 확인한 곳 | 지금 쓰는 키 |
|---|---|
| tui.go `handleKey` 의 `switch` | `q` `ctrl-c` `?` `f` `l` `v` `ctrl-l` `up` `down` `pgup` `pgdn` `home` `end` `s` `esc` |
| tui.go `normKey` | `g`(→home) `G`(→end) `Space`(→pgdn) `b`(→pgup) |
| state.go 선택지 상수 | `c` `r` `x` `s` `k` `y` `n` (`ansCont` `ansRetry` `ansExclude` `ansStop` `ansSkip` `ansYes` `ansNo`) |
| tui.go `isInputKey` | 숫자, `enter` `tab` `shift-tab` `left` `right` `backspace` `esc` |

- `p` 는 위 어디에도 없다. 지금은 `flashUnknownKey` 알림이 뜬다.
- `r`(Report)은 재시도 선택지라서 쓰지 않는다.
- 한글 자판: `jamoKey` 에 `ㅔ`→`p`, `ㅖ`→`P` 가 이미 있다. `normKey` 가 대문자를 소문자로 접는다. 그래서 `ㅔ` `ㅖ` `P` 가 모두 `p` 로 동작한다. 새 처리는 필요 없다.

#### 키 처리

`handleKey` 는 맨 앞에서 `normKey` 를 부른다. `normKey` 는 공백을 `pgdn` 으로, 대문자를 소문자로, 자모를 영문으로 바꾼다. 코멘트 입력에는 이 변환이 맞지 않는다. 그래서 `v.Rep` 가 빈 값이 아니면 `normKey` 보다 먼저 `handleReportKey`(신규)로 보낸다. `handleReportKey` 는 `input` 상태에서만 원래 키를 쓰고, 그 밖의 상태에서는 `normKey` 를 거친 키를 쓴다.

| 상태 | 키 | 동작 |
|---|---|---|
| 평소 | `p` | `st` 가 nil 이면 아무것도 안 함. 아니면 `pick` 으로 감 |
| `pick` | `1` | 방식 1. 기준을 읽는다. 성공하면 리포트를 만들고 `show`, 실패하면 `err` |
| `pick` | `2` | `input` 으로 감 |
| `pick` | 그 밖 | 닫는다. 알림 `취소했습니다` |
| `input` | 글자·공백 | 글에 더한다. `tab` 은 공백 하나로 더한다 |
| `input` | `enter` | 개행을 더한다 |
| `input` | `backspace` | 한 글자를 지운다 |
| `input` | `ctrl-d` | 입력을 끝낸다. 첫 줄이 `@` 로 시작하면 파일을 읽는다. 해석한 뒤 `confirm` 으로 감 |
| `input` | `esc` | 닫는다. 알림 `취소했습니다` |
| `confirm` | `y` | 리포트를 만들고 `show` |
| `confirm` | 그 밖 | 닫는다. 알림 `취소했습니다` |
| `show` | `up` `down` `pgup` `pgdn` `home` `end` | 리포트 스크롤 |
| `show` `err` | 그 밖 | 닫는다 |

- `pick` 의 `1` `2` 는 종료 시각 입력 질문의 숫자 칸과 겹친다. `v.Rep` 를 먼저 보므로 리포트가 열린 동안에는 숫자가 칸으로 가지 않는다. 지금의 `v.Help`, `v.Confirm` 과 같은 방식이다.
- `ctrl-d`(0x04)는 `parseKeys` 에 새 키 이름으로 더한다. 지금은 0x20 미만의 모르는 바이트를 버린다.
- `enterRaw` 는 `ISIG` 를 끄지 않는다. 그래서 `Ctrl-C` 는 입력 중에도 SIGINT 로 TUI 를 끝낸다. 지금 동작과 같다.
- 붙여넣은 글은 `readKeys` 가 256바이트씩 읽어 키로 나눈다. `runTUI` 는 `drainKeys` 로 쌓인 키를 모아 한 번만 그린다. 600줄 붙여넣기에도 구조를 바꾸지 않는다.
- 리포트가 열려 있어도 1초 틱의 `refresh` 는 계속 돈다. 리포트 글은 만든 때의 값으로 고정한다.

`renderRun` 의 `switch` 에 `view.Rep != ""` 갈래를 더한다. `view.Help` 처럼 화면 전체를 쓴다. 그리는 함수는 `reportLines`(신규)다.

- 리포트 글은 색을 쓰지 않는다. 복사한 글에 다른 글자가 섞이지 않게 줄 앞에 표시를 붙이지 않는다.
- `keyHints` 에 `p 리포트` 를 더한다. `helpLines` 의 `화면` 묶음에 한 줄을 더한다.

### 3.7 파일 출력

- `report_YYYYMMDD.txt`: 리포트 글 그대로. 상태 폴더에 `writeFileAtomic` 으로 쓴다. 같은 날 파일은 덮어쓴다.
- 두 본이 나오면 `report_YYYYMMDD.txt` 에 본 A 를, `report_YYYYMMDD_B.txt` 에 본 B 를 쓴다. 본이 하나이면 `_B` 파일은 쓰지 않는다. 같은 날 다시 만들어 본이 하나가 되면 옛 `_B` 파일을 지운다.
- `report_YYYYMMDD.json`: 3.3 의 스냅샷.
- 쓰기에 실패하면 리포트는 그대로 보이고, 첫 줄의 `저장:` 자리에 `저장 실패: <사유>` 를 보인다.
- 화면 복사는 한 화면 분량만 된다. 리포트가 화면보다 길면 파일을 쓴다. 파일 출력을 기본값으로 둔 이유다.

## 4. 경계 상황

| # | 상황 | 처리 |
|---|---|---|
| 1 | 설정에 `VENDOR_` 줄이 없음 | 거절하지 않는다. 모든 호스트를 `기타` 한 묶음으로 적는다. 리포트 화면 위에 `VENDOR_ 규칙이 없어 모두 기타 로 묶었습니다` 를 보인다 |
| 2 | 설정 파일이 없음(`ConfPath` 빈 값) 또는 읽기 실패 | 1 과 같다. 읽기 실패이면 사유를 화면 위에 보인다 |
| 3 | 한 호스트가 두 벤더에 맞음 | 먼저 적은 벤더. 알림 없음 |
| 4 | 호스트 목록이 비어 있음(`Hosts` 0개) | 오류 화면 `호스트가 없어 리포트를 만들 수 없습니다`. 파일을 쓰지 않는다 |
| 5 | `st` 가 nil(상태를 아직 못 읽음) | `p` 를 받지 않는다 |
| 6 | 스냅샷의 호스트 목록이 현재와 다름 | 비교하지 않는다. 대수 차이를 보이고 방식 2 를 안내한다(3.4) |
| 7 | 스냅샷 파일이 깨짐 | 오류 화면. 파일 이름과 사유. 방식 2 를 안내한다 |
| 8 | 스냅샷이 오늘 것만 있음 | `전일 저장본이 없습니다`. 오늘 파일은 기준으로 쓰지 않는다 |
| 9 | 스냅샷의 `version` 이 더 높음 | 오류 화면 `이 바이너리보다 새 형식의 저장본입니다` |
| 10 | 코멘트가 빈 글 | 확인 화면에 모든 벤더 `전일 정보 없음`. `y` 를 받으면 리포트를 만든다 |
| 11 | 코멘트에 있고 설정에 없는 벤더 | 비교에 쓰지 않는다. 알림에 적는다 |
| 12 | 설정에 있고 코멘트에 없는 벤더 | 그 벤더는 `전일 정보 없음` |
| 13 | 호스트 이름이 바뀜 | 방식 1 은 목록이 다르다고 본다(6번). 방식 2 는 대수는 숫자로 비교하고, 옛 이름은 조치완료로 적지 않는다 |
| 14 | 변화 없음 | `+0대` |
| 15 | 전일대비가 음수(완료였던 호스트가 접속불가가 됨 등) | 계산한 그대로 `-N대` |
| 16 | 접속불가 명단이 김(예 200대) | 한 줄에 하나. 줄을 합치거나 줄이지 않는다. 화면은 스크롤, 전체는 파일 |
| 17 | `REPORT_ETA_DAYS=0` | 완료예정일 = 오늘 날짜 |
| 18 | `REPORT_ETA_DAYS` 가 음수·소수·글자 | 경고 후 2 |
| 19 | A = 0(OS 완료 0대) | B = 0 이므로 A = N 이 아니다. 완료예정일을 적는다(`완료` 는 적지 않는다) |

### 5.2 시험 계획

단위 시험(report_test.go, main_test.go):

- 벤더 판정: 패턴 `hpe*,dl3*`, 대문자 호스트 이름, 겹침, 규칙 없음, 잘못된 패턴.
- 대수: 상태 5종과 stress-ng 열 3종을 섞은 호스트 표. N, D, I, A, B, U 를 확인한다.
- 전일대비: 양수, 음수, 0, nil.
- 두 본: 접속불가 0대 + 조치완료 있는 벤더에서 본 A·본 B 가 3.5 규칙대로 나오고, 없는 경우 글이 하나인지 확인한다. `완료` 표기는 A = N 일 때만 나오는지 확인한다(A < N, A = 0 사례 포함).
- 양식: 3.5 의 출력 예와 전체 비교. 벤더 순서, `기타` 마지막, 빈 줄 하나, 0대 벤더 생략.
- 접속불가 블록: U > 0, U = 0 이고 조치완료 있음, 둘 다 없음, 이름 명단 모름.
- 해석기: 3.4 의 표를 표 기반 시험으로 옮긴다.
- 왕복: `buildReport` 의 결과를 `parseComment` 에 넣으면 그날의 D, B, U, 접속불가 이름이 나온다. 방식 2 가 어제의 리포트를 그대로 읽는다는 보장이다.
- 스냅샷: 쓰고 읽으면 같은 값. 옛 폴더(파일 없음).

TUI 시험(report_tui_test.go). 지금 시험의 `sampleState`, `press`, `typeText`, `sent.actions` 방식을 따른다. `reportIO` 에는 가짜를 넣는다.

- `p` → `pick`. `ㅔ`, `P` 도 같다.
- `pick` 에서 `1`: 가짜 스냅샷이 있으면 `show`, 없으면 `err`, 목록이 다르면 `err` 와 대수 문구.
- `pick` 에서 `2` → `input`. 글자·공백·`enter`·`backspace` 가 글에 반영된다. 공백이 `pgdn` 으로 바뀌지 않는다. `q` 가 TUI 를 끝내지 않는다.

- `@경로` 한 줄 → 가짜 `readFile` 이 불린다.
- 입력 질문이 떠 있을 때 `p` → `1`: 숫자가 칸으로 가지 않는다. 닫은 뒤 칸 값이 그대로다.
- `show` 에서 스크롤 키. 다른 키로 닫힘.
- `renderRun`: 다섯 상태의 줄, 줄 수 = h.
- `keyHints` 에 `p 리포트` 가 있다.
- `parseKeys([]byte{0x04})` = `ctrl-d`.

데모(test.sh):

- 메뉴에 `5) 리포트 데모` 를 더한다. 가짜 호스트 60대(벤더 2개 + `기타`), 어제 날짜의 스냅샷, 어제 리포트 글 파일을 데모 폴더에 만든다.

## 6. 정해야 할 것과 위험

각 항목 끝의 "기본값" 은 답이 없을 때 이 계획이 쓰는 값이다.

1. (결정함) 현재 접속불가가 0대이고 기준에는 있을 때. 적용한 본 A 와 적용하지 않은 본 B 를 둘 다 출력한다. 사용자가 둘 중 하나를 골라 쓴다. 3.5 의 "두 본" 과 3.7 의 파일 이름을 따른다.
2. (결정함, 11-12) `디스크미인식` 과 `설치정지` 의 표시. `디스크미인식` 은 완료에 넣지 않고 접속불가서버에 넣는다. `접속불가서버 N대` 의 N 에 포함하고, 명단에 `- <호스트> 디스크 미인식` 으로 적는다. 줄 1 에는 적지 않는다. `설치정지` 는 처음 기본값 그대로다: 1대 이상일 때만 줄 1 에 `, N대 설치정지` 를 덧붙인다.
3. (결정함) `완료` 는 A = N 이고 B = A 일 때만 적는다. A < N 이면 날짜를 적는다.
4. 줄 2 의 정확한 글자. 틀은 `[전일대비 완료된 서버수량] [금일기준+2일] 완료예정` 이다. 기본값: `전일대비 +20대, 11/14 완료예정`. 날짜 양식(`11/14`, `11월 14일`, `2026-11-14`)을 확인해야 한다.
5. 변화가 0 일 때의 글자. 기본값: `+0대`.
6. (결정함) `-new` 와 스냅샷. `-new` 는 상태 폴더를 `<폴더>.old-<시각>` 으로 옮긴다(`archiveDir`). 스냅샷도 함께 옮겨진다. 그러면 방식 1 은 "전일 저장본이 없습니다" 를 보이고, 사용자는 방식 2 를 쓴다. `.old-*` 폴더는 찾지 않는다.
7. 현재 값의 시각. 리포트는 워커의 마지막 판정 값을 쓴다. `-auto` 가 아닌 작업은 판정 단계가 지난 뒤 상태 열이 오래된 값일 수 있다. 기본값: 화면 첫 줄에 `runState.Updated` 를 보인다. 리포트 글에는 넣지 않는다.
8. tty 가 아닌 환경(cron)에서의 리포트. 인터뷰 결정 1 은 TUI 키만이다. 매일 자동으로 스냅샷을 남기려면 명령줄 옵션이 필요하다. 기본값: 만들지 않는다.
9. 코멘트의 파일 입력 표기. 기본값: 첫 줄 `@<경로>`. 붙여넣기와 한 화면에서 받기 위해 골랐다.
10. 붙여넣기 끝 키. 리포트 글에는 빈 줄이 있다. 그래서 빈 줄로 끝을 알 수 없다. 기본값: `Ctrl-D`. 현장 터미널(PuTTY 등)이 `Ctrl-D` 를 0x04 로 보내는지 랩에서 확인해야 한다.
11. 붙여넣기 속도. 터미널이 큰 글을 한꺼번에 보낼 때 raw 입력이 빠지는지 코드만으로는 알 수 없다. 단계 7 에서 600줄을 붙여넣어 확인한다. 빠지면 `@경로` 를 쓰도록 안내한다.
12. 스냅샷 기준이 어제가 아닐 때(주말). 기본값: 가장 최근 파일을 쓰고 화면에 `n일 전` 을 보인다. 리포트 글은 `전일대비` 그대로다.
13. 방식 1 의 벤더 나누기. 기본값: 저장된 `vendor` 가 아니라 지금 규칙으로 다시 나눈다.
14. 제외(`Excluded`)·포기(`GaveUp`) 호스트. 기본값: 분모와 모든 대수에 넣는다. 호스트가 조용히 빠지지 않게 하기 위해서다.
15. 벤더 제목 판정의 오탐. `비고:` 처럼 쌍점으로 끝나는 메모 줄은 벤더 제목으로 읽힌다. 그 뒤의 줄은 그 "벤더" 에 붙는다. 설정에 없는 벤더라서 숫자가 틀리게 적히지는 않는다. 다만 원래 벤더의 뒤쪽 줄을 잃는다. 확인 화면에서 사용자가 볼 수 있다. 고칠 안: `known` 에 있는 이름만 제목으로 본다. 그때는 설정에 없는 벤더를 알릴 수 없다. 기본값: 지금 규칙.
16. `setup.sh` 가 설정 파일을 다시 쓸 때 `VENDOR_*` 줄을 남기는지 확인하지 못했다. `setup.sh` 의 `ALLKEYS` 에는 `AUTO_*` 도 없다. 단계 9 에서 확인한다.
17. 리포트 화면의 복사. 대체 화면에서는 마우스로 한 화면만 복사된다. 기본값: 파일을 쓴다. 다른 안: TUI 를 나올 때(`afterShow`) 마지막 리포트 경로를 한 줄 안내한다.
18. 실제 현장의 호스트 이름 규칙과 벤더 수. 랩은 가짜 호스트다. 패턴 예(`hpe*`, `dl3*`)는 인터뷰의 예다.

## 7. 배포

- 바꾸는 것은 `new_setup` 바이너리 하나와 설정 파일의 줄이다.
- 현장에서는 `bin/new_setup` 을 새 것으로 바꾼다. `new_setup.conf` 에 `VENDOR_<이름>=…` 줄을 더한다. `REPORT_ETA_DAYS` 는 2 가 아닐 때만 더한다.
- `stress-test` 바이너리와 그 설정은 바꾸지 않는다.
- 진행 중인 작업이 있어도 바꿀 수 있다. 워커와 state.json 은 그대로다. TUI 를 `q` 로 나갔다가 새 바이너리로 다시 붙으면 `p` 를 쓸 수 있다.
- 옛 상태 폴더는 그대로 쓴다. 첫 리포트는 방식 2 로 만든다. 그때 저장된 스냅샷이 다음 날 방식 1 의 기준이 된다.
- 옛 바이너리는 `VENDOR_*`, `REPORT_ETA_DAYS` 줄을 모르는 키로 보고 지나친다(`parseConf` 의 `switch` 에 `default` 가 없다). 설정 파일을 먼저 고쳐도 된다.
