# 계획서 v0.2 — 색상 줄 출력 · CSV · 제외 목록 · Go TUI 통합

인터뷰 확정일: 2026-10-15. 작업은 사용자가 "시작" 이라고 할 때 진행한다.

## 확정 사항

### 출력 줄 형식 (터미널·TUI 본문)
```
[태그] host<TAB>ip<TAB>vendor<TAB>model<TAB>bios_version<TAB>attribute<TAB>기준값<TAB>현재값<TAB>비고
```
- 태그 3개: `[OK]`(초록) / `[difference]`(노랑) / `[N/A]`(회색). 오류(접속 실패 등 호스트 단위)는 빨강.
- 기준값(프로파일 기대값 또는 비교서버 값) 칸은 항상 초록. 현재값 칸은 태그 색 규칙을 따름.
- 비고 = 원래 상태명 (OK, PENDING_OK, FAIL, UNVERIFIED, PENDING_EXISTS, PENDING_NO_JOB, MAPPING_MISSING, ONLY_REF, ONLY_HOST, UNREACHABLE ...).
- 태그 묶음: OK·PENDING_OK → OK / FAIL·UNVERIFIED·PENDING_EXISTS·PENDING_NO_JOB → difference /
  MAPPING_MISSING·NO_DUMP·대상에 속성 없음(ONLY_REF)·접속/조회 실패 → N/A.
  기준에 없고 대상에만 있는 속성(ONLY_HOST)은 기준값 `(없음)` 으로 difference.
- 결과의 `-`(값 없음)는 화면·CSV 에서 `(N/A)` 로 표시. **profiles/*.tsv 양식은 바꾸지 않는다** (현재 value 열에 `-` 를 쓰는 행은 없음).
- `NO_COLOR` 또는 tty 아님 → 색 없음.

### CSV (결과 폴더에 추가, UTF-8 BOM, 기존 result.tsv·all_diff.tsv 등 TSV 는 유지)
- `summary.csv` 호스트 1줄: 불일치 건수, 다른 속성 "대상값 / 기준값" 나열
- `wide_hosts_<벤더>_<그룹>.csv` 호스트=행, 속성=열, 첫 행 기준값
- `wide_attrs_<벤더>_<그룹>.csv` 속성=행, 호스트=열, "차이" 열(대수/제외)
- `long.csv` 위 줄 형식 그대로(태그·비고 포함)
- 그룹 = 벤더 안에서 관리망 버전별로 나누되 **BIOS 속성 이름 목록이 같으면 하나로 합침**.

### 제외 목록
- `bios.conf` 에 `exclude_attrs=A|B|*Uuid*` (`|` 구분, `*` 와일드카드, 대소문자 무시).
- 기존 `ignore_attrs.txt`(없으면 내장 기본 목록)와 **합쳐서** 적용. 프로파일 점검에도 적용(해당 행 점검 제외).

### 흐름 (bash bios.sh → Go TUI)
1. 대상 입력: 대상 파일 지정 또는 TUI 에서 붙여넣기 (auto_setup 규칙: Ctrl+D 완료, Ctrl+X 취소).
2. 프로파일 선택 (`-profile` 로 지정하면 생략).
3. 호스트당 1회 접속해 **BIOS 전체 속성 조회** (진행 표시).
4. TUI 1차 화면: 프로파일에 등록된 항목 결과.
5. 화면 탭 `[프로파일 점검] [전체 설정 비교]` 를 Tab 으로 전환 (2026-10-16 변경, 옛 "전체비교 결과를 볼까요?" 질문 대체).
   처음 `[전체 설정 비교]` 로 넘어가면 기준 선택: 비교서버 hostname 입력(그 서버만 추가 조회) 또는 `refs/` 의 JSON 선택(bios_export 로 추출한 파일, `-ref-json` 옵션도 제공). 빈 입력이면 diff.txt. `-ref` 를 주면 묻지 않음.
   → 그 탭에 전체비교 결과. 이후 Tab 은 두 결과를 오가며 탭마다 위치·필터 유지, `r` 로 기준 다시 선택. 같은 모델만 비교, BIOS 버전이 달라도 속성 이름 목록이 같으면 허용.
   기준 서버 자신(REFERENCE)은 속성마다 기준값 = 현재값 = 자기 값, [OK], 비고 REFERENCE.
6. 벤더 줄에서 q(또는 e) → 마지막에 "수정할까요? y/n" — 프로파일 difference(verified=Y 만) + 전체비교 difference(`allcheck_set=on` 일 때만)를 **함께** 설정.
   - 같은 속성의 목표값이 둘이 다르면 설정하지 않고 미리보기에 `[충돌]` 표시.
   - ignore·exclude·위험속성(reDangerAttr)·N/A 제외.
   - 남의 Pending 이 있는 장비는 목록(호스트·속성·Pending 값)을 보여 주고 y 포함 / n 제외 / Ctrl+X 취소.
   - Pending 까지만 설정(재부팅 없음), 설정 후 Pending 재조회로 반영 여부 표시.
7. 비대화형 `bash bios.sh -auto|-auto-check <user> targets.txt`: 1~4 단계만, **설정 없음**(-auto 도 점검만).
   결과 `check.res_<user>`(+ -auto 는 `_postapply` 에 같은 내용): `host: OK` / `host: FAIL difference N건 (...)` / `host: FAIL N/A 접속실패(...)`.

### TUI 키 (auto_setup 규칙)
Tab/Shift+Tab 화면 전환(어느 위치에서나) · ←→ 벤더 · Enter 벤더 안으로(←→ 가 관리망 그룹) · q/Esc 한 단계 뒤로(벤더 줄에서는 종료→수정 단계) ·
r 전체 설정 비교 기준 다시 선택 · ↑↓(k j) 한 줄 · PgUp/PgDn 한 화면 · a 전체 · o OK만 · f difference만 · n N/A만 · s 요약 ·
e 수정 메뉴 · ? 도움말 · Ctrl+C/Ctrl+Z 무시("종료는 q 를 누르세요") · Ctrl+X 진행 중 작업 취소.
탭 전환·필터는 제자리 갱신(in-place redraw, 대체 화면 안에서 다시 그리기). tty 아니면 평문 출력.

### 진행 표시
`[1/4 설정 확인] [2/4 접속·조회 123/1000 · OK 100 difference 20 N/A 3 오류 0 · 경과 00:12] [3/4 CSV 저장] [4/4 TUI]`, 설정 때도 호스트별 진행 줄. 비대화형은 10초마다 한 줄.

### 진입점
`bash bios.sh` 하나로 통합. `bios_check.sh`·`all_bios_check.sh` 는 bios.sh 를 해당 모드로 부르는 한 줄짜리로 남김.

## 단계
1. conf·판정 공통: `exclude_attrs`, `allcheck_set`, `refs_dir` 읽기, ignore 합치기, 태그 매핑·`(N/A)` 변환 함수
2. 수집 통합: 호스트당 1회 BIOS 전체 조회 → 프로파일 판정 + 전체비교 재사용, 기준(hostname / refs JSON / diff.txt), 모델·속성목록 조건
3. 출력: 색상 줄 렌더러, CSV 4종 + 그룹 분할(속성 이름 목록 병합), check.res_<user>
4. 진행 표시 (대화형 한 줄 갱신, 비대화형 10초)
5. TUI 코어: raw tty·대체 화면·키 파서(auto_setup 이식, syscall 만), 탭·스크롤·필터·도움말·Ctrl 키 규칙, 비 tty 평문
6. TUI 흐름: 대상 입력·프로파일 선택·1차 화면·전체비교 질문·기준 선택·수정 질문(충돌·Pending 묻기·재조회)
7. 전체비교 설정 엔진: set.go 재사용, 제외 규칙, allcheck_set 관문
8. 진입점 통합: bios.sh(-auto/-auto-check 포함), 기존 두 스크립트 한 줄 래퍼
9. 테스트·빌드: 단위 + mockbmc e2e(랩 .58), os6 바이너리(go1.20.14) 재빌드·커밋 준비
10. 문서: git-upload-sk 기준 README·사용법.txt·ARCHITECTURE·WORKFLOW(+svg)·CHANGELOG·PR_CHECKLIST
11. 코드 리뷰 (설정 경로 안전성 중심)

## 변경 2026-10-16 (수정 단계·보호 속성·종료 규칙·견고성)

코드 기준 확정 사항. 위 "흐름"의 6번(수정)과 "TUI 키"를 아래로 대체한다.

### 수정 확인 (한 번 → 두 단계)
- 확인 1: 차이 항목 **전부**를 호스트별로 `속성  현재값 -> 변경값 (수정대상)` / `... (수정제외: 사유)` 로 보이고(값은 자르지 않음) "위 수정대상을 적용할까요?" y/n.
- 확인 2: 수정제외 항목이 있을 때만, "아래 항목은 변경하지 않습니다" 와 그 항목만 다시 보이고 "수정제외 항목을 확인했습니다. 진행할까요?" y/n.
- 그다음 남의 Pending 질문(y 포함 / n 제외 / Ctrl+X 취소). 확인 1·2 에서 n / Esc / Ctrl+X 면 아무것도 쓰지 않고 결과 화면으로 돌아온다.
- `-profile`·`-user`·`-ref` 등을 줘도 확인은 항상 묻는다. 수정 단계는 벤더 줄 `q q`(설정할 항목이 있을 때) 또는 `e`(어디서든).

### 보호 속성 (절대 바꾸지 않음, protect.go)
- 서버 고유값(iSCSI·IQN·IP·네트워크·ServerName·자산번호·UUID), 부팅(BootMode·순서·PXE·URL/HTTP 부팅), 보안(SecureBoot·TPM·비밀번호·인증서), 스토리지(RAID·SATA·NVMe·VMD), NIC(LOM·OCP·WoL·OptionRom·Slot) 패턴을 내장. 프로파일·전체비교 어느 쪽 값이든 설정하지 않고 (수정제외)로 표시.
- 내장 목록은 `bios.conf`·`ignore_attrs.txt` 로 끌 수 없다. conf `protect_attrs=A|B|*패턴*` 은 더하기만.
- 막는 곳: ① 설정 계획(수정제외 표시) ② 적용(set.go): 하나라도 걸리면 그 호스트는 접속 없이 통째로 `PROTECTED_ATTR` ③ PATCH 직전 본문 재검사 ④ redfish.go `checkAttributes` 본문 거부.
- 패턴은 성능 속성을 막지 않게 좁힌다 (protect_test.go 가 profiles/*.tsv 속성이 막히지 않는지 확인).

### 설정 계획 규칙 보강 (setplan.go)
- 전체비교 항목은 비교서버와 BIOS 버전이 같은 호스트만 (`BIOS_VER_DIFF` 호스트는 수정제외). 비교서버 값은 적용 때 레지스트리 형식이 Enumeration·Integer·Boolean 일 때만 전송(문자열·형식 불명은 INVALID_VALUE).
- 시스템 프로파일 성격 속성이 한 호스트에 여러 개면 프로파일 행 항목만 보내고 나머지는 수정제외(적용 단계 DEPENDS_ON_PROFILE).
- Dell 은 설정 Job 이 남의 Pending 까지 적용하므로 남의 Pending 이 있는 호스트는 제외. 적용 중 Ctrl+X 로 시작 안 한 호스트는 CANCELED(apply_failed.txt).

### TUI 키·종료 (대체)
- Tab/Shift+Tab 화면 전환(`[프로파일 점검]` ↔ `[전체 설정 비교]`) · ←→ 벤더 · Enter 벤더 안으로(←→ 가 관리망 그룹) · r 비교 기준 다시 선택 · e 수정 단계로 바로.
- `q` 는 어디서나 한 단계 뒤로(그룹 줄→벤더 줄, 미리보기·설정 결과→결과 화면, 프로파일 고르기→대상 입력). 벤더 줄(홈)에서는 q 후 q 로 종료, q 후 Esc 는 계속(종료 확인 취소). 홈에서 N·Ctrl+X 로는 종료되지 않는다.
- 종료 때 설정할 항목이 있으면 먼저 수정 단계. 거절한 뒤 q q 는 다시 묻지 않고 종료(r 로 새로 비교하면 다시 물음). 적용한 뒤에는 같은 세션에서 다시 설정 불가("다시 점검한 뒤 설정"). Ctrl+C/Ctrl+Z 안내는 "종료는 q 를 두 번 누르세요".
- `-user`·`-profile` 은 해당 질문 생략. `-ref`/`-ref-json`/`-diff` 는 수집 직후 바로 전체 설정 비교까지 실행(첫 화면은 프로파일 점검, 실패·취소하면 다음 Tab 에 다시 시도).

### 견고성·출력 안전
- 흐름 중 패닉이어도 터미널 복구. 호스트 처리 중 패닉은 그 호스트만 BMC_ERROR 로 남기고 계속. 질문 전에 쌓인 키 버림. 취소 대기 중 두 번째 시그널은 터미널 복구 후 즉시 종료.
- `check.res_<user>`(·`_postapply`)는 비대화형 시작 때 이전 파일 삭제 + 임시 파일 rename 으로 원자적 기록. CSV 는 `= + @ TAB CR` 및 음수 아닌 `-` 시작 칸 앞에 `'`(수식 주입 방지). 화면·평문·check.res 는 제어 문자를 공백으로.
