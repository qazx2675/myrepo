# 수정 계획서 — 대표서버 자동 지정 · 대표서버 기준 맞추기 · 프로파일 추가 명령

대상: `biostool bios` 대화형 화면(TUI)과 그 뒤의 계획·비교 코드 (`cmd/biostool/`). 브랜치 `bios-collect`.
상태: **계획만** (코드 변경 없음). 7장의 인터뷰 질문을 확정한 뒤 구현한다.

## 1. 목적·범위

### 요청을 이렇게 읽었다 (가정 — 틀리면 인터뷰에서 바로잡는다)

| # | 요청 | 읽은 뜻 |
|---|---|---|
| A | 전체 BIOS 값 비교에서 대표서버 1대(태그 또는 모델별) 자동 지정, 1번에 올리고 기존 2개는 아래로 | `[전체 설정 비교]` 의 "전체비교 기준 선택" 메뉴 맨 위에 **대표서버 자동 지정**을 넣는다. 지금 메뉴는 `비교서버 hostname 입력` / (refs JSON 파일들) / `diff.txt` 인데, 이것들이 한 칸씩 내려간다. 사용자가 말한 "기존 2개" = hostname 입력과 diff.txt (refs JSON 은 폴더에 파일이 있을 때만 그 사이에 나온다) |
| B | 설정수정에 대표서버 기준으로 동일하게 맞추기, `[ ]BIOS` 로 선택, 선택한 것만 설정 | 수정 단계(`e`) 메뉴에 **대표서버 기준으로 맞추기**를 더한다. 대표서버와 값이 다른 BIOS 속성을 체크 목록으로 보이고 체크한 속성만 BMC Pending 으로 보낸다 |
| B' | 한쪽에만 있는 BIOS 값은 강제로 넣을 수 있는지 알려 주고, 안 되면 자동 제외 | 조사 결과를 3.B.4 에 적고, 불가능하므로 사유와 함께 자동 제외한다 |
| C | 시리얼·MAC 같은 고유값을 비교하지 않는지 재점검 | 지금 제외가 일어나는 곳을 찾아 빈틈을 적고(3.C) 보강안을 낸다 |
| D | [프로파일 점검] 에서 태그 또는 모델별로 설정을 추가 (커맨드로) | 프로파일 TSV(`profiles/<이름>.tsv`)에 모델 지정 행을 더하는 명령. 태그를 주면 그 태그 서버들의 **모델마다** 행을 만든다 |

### 바꾸는 것

- 전체비교 기준에 `대표서버 자동 지정` 추가 + 메뉴 순서
- 수정 단계에 `대표서버 기준으로 맞추기` + 체크 목록 화면(TUI 새 입력 상자 1종)
- 비교 제외(고유값) 보강
- 프로파일 행 추가 명령

### 바꾸지 않는 것

- **BMC 쓰기 경로**: `set.go`·`redfish.go` 는 고치지 않는다. 새 수정 방법도 `setPlan` → `applySetPlan` → `runHost` 를 그대로 탄다 (Pending 까지만, 재부팅 없음, 호스트당 PATCH 1회).
- **보호 속성**(`protect.go` `builtinProtect`): IQN·IP·ServerName·BootMode·SecureBoot·RAID·PXE·NIC 는 어떤 메뉴에서도 설정하지 않는다. 목록을 줄이지 않는다.
- 비대화형(`-auto`·`-auto-check`·`-plain`)에는 설정 경로를 만들지 않는다. `-ref-auto` 같은 새 플래그도 이번에는 넣지 않는다 (TUI 메뉴만).
- 기존 기준 3종(hostname·refs JSON·diff.txt)의 동작, 결과 파일 이름·열, `allcheck` 서브커맨드.
- Cisco(XML) 대상: 지금처럼 점검만 (전체비교·설정·프로파일 추가 대상 아님).

## 2. 현재 동작 조사 결과 (코드에서 확인한 것)

### 2.1 전체비교 기준 선택

- `tui_flow.go` `chooseRef`(655): 메뉴 = `비교서버 hostname 입력`(0) + `refs_dir` 의 읽을 수 있는 JSON 들 + `diff.txt (모델별 기준)`(마지막). hostname 을 비우면 diff.txt.
- `unified.go` `compareRef`(178): `Hosts` / `JSONPath` / `DiffFile` 중 정확히 하나(`count()`), `compareRefs`(265) 가 기준을 준비한다. **대상 목록에 있는 기준은 이미 읽은 스냅샷을 다시 쓴다**(같은 BMC 재접속 없음, 312~326).
- `allcheck.go` `classify`(733): 기준 후보 = 같은 모델 키(`vendor|normalizeModel(model)`) + 태그 모드면 같은 태그(`tagOK`, 기준의 태그는 기준 목록에 적은 값). 자기 자신은 후보에서 빠지고, 다른 후보가 없으면 `REFERENCE`. 후보가 여럿이면 BIOS 버전이 같은 쪽.
- 태그 모드 = 대상 중 태그가 하나라도 있음(`unified.go` `tagMode` 255). refs JSON 기준은 태그를 따지지 않는다.
- 모델이 다른 대상의 참고용 CSV(`x` 키, `xmodel.go` `xmodelPlanFor` 170)는 기준이 1대일 때만 나온다.
- 테스트가 메뉴 번호를 숫자 키로 누른다: `tui_flow_test.go`·`tui_recheck_test.go` 의 `{"ref","1"}`(12곳), `{"ref","2"}`(golden.json, 391행). 순서를 바꾸면 이 줄들을 함께 고쳐야 한다.

### 2.2 수정 단계

- `tui_flow.go` `flowEditMenu`(708) = `점검 결과 기준 수정`(`setStep` 733) / `BIOS 값 직접 입력`(`directStep` 838). 둘 다 확인 뒤 `applyStep`(772): 남의 Pending 질문 → 적용 → 결과 → 보낸 호스트만 재점검.
- `setplan.go` `buildSetPlan`(172) → `addHost`(225): 전체비교 차이는 **`bios.conf` `allcheck_set=on` 일 때만** 항목이 된다(기본 off). 호스트 단위 관문: 비교됨 · **속성 이름 목록이 기준과 같음**(`sameAttrNames`, `unified.go` 212 — ONLY_REF·ONLY_HOST 가 1건이라도 있으면 그 호스트의 비교 차이 전부 제외) · 같은 모델 키 · BIOS 버전 같음(`BIOS_VER_DIFF` 면 제외).
- `compareItems`(439): `DIFF` 만 항목. 순서는 보호 속성 → 제외 목록(`setIgnore`) → 위험 속성(`attrBlocked`) → 프로파일이 정하는 속성(값이 다르면 `[충돌]`, 둘 다 제외).
- `addItems`(334): 쓰기 벤더(Dell·HPE·Lenovo), Settings 경로, 모델명, 남의 Pending(Dell 은 호스트 제외).
- 적용 때(`set.go`): `verifyItem`(391) 비교 항목은 값 하나만, `planHost`(435) 가 재조회해서 **속성이 지금 BMC 에 없으면 `CHANGED`**(499~502), 비교 항목은 레지스트리 형식이 **Enumeration·Integer·Boolean 일 때만** 보냄(592~605, 레지스트리에 없으면 `INVALID_VALUE`), `typedValue`(704) 가 ReadOnly·허용값 검사.
- TUI 에는 여러 개를 고르는 상자가 없다. `tui_view.go` `Choose`(809)는 하나만 고른다 (`tuiPromptKind`: yes/no·한 줄·여러 줄·고르기).

### 2.3 고유값 제외가 일어나는 곳

| 단계 | 쓰는 목록 | 코드 |

| 설정 계획·적용·PATCH 본문 | 보호 속성(내장 ∪ `protect_attrs`) | `protect.go`, `setplan.go` `protect`(202), `set.go` `runHost`·`send`, `redfish.go` `checkAttributes` |

### 2.4 프로파일·태그

- 프로파일 = `profiles/<이름>.tsv`, 6열 `vendor model std_name attribute value verified`. 행은 **벤더+모델** 기준이고 태그 개념이 없다 (`profile.go` `parseProfile` 135, `rowsFor` 252: 모델 정확 일치 행 → 없으면 `*` 행).
- `verified=Y` 는 모델 지정 행에만 쓸 수 있고 **쓰기 허가**다 (`*` 행의 Y 는 로드 오류, `set.go` `verifyItem` 이 다시 확인).
- 같은 (벤더, 모델, std_name, 속성) 행이 둘이면 로드 오류. `# [redfish]` / `# [xml]` 구역 주석이 뜻을 가진다.
- 표준 4항목 이름 후보는 `inspect.go` `stdKeywords`(425)·`findStdCandidates`(460).
- 태그 = `user.txt` 둘째 칸. 결과 화면·CSV 묶음과 전체비교 기준 고르기에만 쓰인다.
- 지금은 프로파일을 고치는 명령이 없다 (서브커맨드: `main.go` 78~94, 래퍼 분기: `bios.sh` 23~32). 사람이 TSV 를 직접 고친다.

## 3. 설계안

### 3.A 대표서버 자동 지정 + 메뉴 순서

**메뉴** (`chooseRef`):

```
1. 대표서버 자동 지정 (태그·모델별 1대)
2. 비교서버 hostname 입력
3..n. <refs JSON 파일들>
n+1. diff.txt (모델별 기준)
```

**동작**

1. `compareRef` 에 `Auto bool` 을 더한다 (`count()` 에 포함, 넷 중 하나만).
2. `compareRefs` 의 Auto 분기: 읽기에 성공한 스냅샷을 묶음(태그 모드면 태그+모델 키, 아니면 모델 키)으로 나누고 4장의 규칙으로 묶음마다 1대를 고른다. 고른 스냅샷으로 `allRef{Entry:{Input, Tag: 대상의 태그}, Target, ID: targetID, Snap}` 를 직접 만든다 → **추가 접속 0회, 이름 재해석 없음**.
3. 그 뒤는 지금 코드 그대로다: `classify` 가 같은 태그·같은 모델의 대표와 비교하고, 대표 자신은 `REFERENCE`(자기 값이 기준값인 OK 줄), 묶음에 1대뿐이면 그 1대가 `REFERENCE` 로만 나온다.
4. 라벨 `대표서버 자동 (N대)`. 비교 직후 안내 줄에 `대표서버: [gold] R660 → host0001 · [silver] DL360 Gen11 → host0101 …` (길면 "외 N묶음"), 전체 목록은 결과 폴더 `compare_refs.tsv`(묶음·대표·대수·BIOS 버전·선정 사유)에 쓴다.
5. `x` 키(모델이 다른 참고 CSV)는 자동 지정에서는 켜지지 않는다 (모델마다 대표가 있으므로 — `xmodelPlanFor` 가 nil 을 돌려주는 조건 그대로).
6. `r` 로 다시 고르면 같은 메뉴. `-ref`·`-ref-json`·`-diff` 를 준 실행은 지금처럼 메뉴를 건너뛴다.

**영향**: 메뉴 번호가 바뀌므로 테스트의 `{"ref","1"}` → `"2"`, `{"ref","2"}` → `"3"`, README·사용법.txt 의 메뉴 설명.

### 3.B 수정 단계: 대표서버 기준으로 맞추기

#### 3.B.1 흐름

```
e → 수정 방법 선택 → "대표서버 기준으로 맞추기"
  → (전체비교를 아직 안 했으면) 대표서버 자동 지정으로 비교 먼저 실행
  → 체크 목록 화면: [ ] 속성  현재값들 -> 대표값  (대상 N대)   /  [-] 속성 (제외: 사유)
  → Enter (하나도 안 골랐으면 "고른 항목이 없습니다" 로 돌아감)
  → 수정 확인 1 "위 수정대상을 적용할까요?" (y)        ← 기존 화면 재사용 (ConfirmLines)
  → 수정 확인 2 (수정제외가 있을 때)                  ← 기존 (ExcludedLines)
  → 남의 Pending 질문 → 적용 → 설정 결과 → 보낸 호스트 재점검   ← 기존 applyStep
  → 맞추기 확인: 고른 속성의 현재값·Pending 이 대표값인지 (directCheck 와 같은 모양)
```

`-from-dump`, 재점검 못 한 호스트가 남은 상태(`f.unchecked`), XML 대상은 지금 규칙 그대로 막는다.

#### 3.B.2 계획 만들기 — 새 파일 `setalign.go`

`buildAlignCands(cfg, u, cmp)` 는 BMC 에 접속하지 않고 비교 결과(`cmp.Hosts[i].Diffs`)만 본다.

- 후보 = `DIFF` 줄. 출처는 `SetSrcCompare` 를 그대로 쓴다 → 적용 단계가 지금의 "비교서버 값" 규칙(값 하나, 레지스트리 형식 Enumeration·Integer·Boolean, ReadOnly·허용값 검사)을 그대로 적용하고 `set.go` 를 고칠 필요가 없다.
- 거르는 순서는 `compareItems` 와 같다: 보호 속성 → 설정 제외 목록(`setIgnore`) → 값 모양이 고유값(3.C) → 위험 속성(`attrBlocked`) → 프로파일이 정하는 속성(충돌이면 둘 다 제외) → 시스템 프로파일 성격 속성 1개 규칙(`oneProfile`).
- 호스트 관문: 비교됨(`SAME`/`DIFF`), 같은 모델 키, 쓰기 벤더, Settings 경로, 모델명 있음, 남의 Pending(Dell 제외) — `addItems` 재사용.
- **`sameAttrNames` 관문은 이 메뉴에서만 속성 단위로 바꾼다**: 한쪽에만 있는 속성은 그 속성만 제외하고, 같은 호스트의 나머지 `DIFF` 는 후보로 남긴다. (요청 "이런 케이스는 자동으로 제외" 의 뜻. 기존 `점검 결과 기준 수정` 경로의 호스트 통째 제외는 그대로 둔다.)
- BIOS 버전이 대표와 다른 호스트·`allcheck_set` 과의 관계는 인터뷰 5·8.

체크한 뒤 `alignPlan(cands, 선택)` 이 고른 것만 `setPlan.Items` 로, 고르지 않은 것은 버리고(수정제외로 세지 않음), 자동 제외는 `Protected`/`Excluded` 로 넣는다.

#### 3.B.3 체크 목록 화면 — `tui_view.go` 새 상자 `ChooseMulti`

- 줄 모양: `[ ] LogicalProc   Disabled -> Enabled   (12대)` · 값이 호스트마다 다르면 `Disabled(10) Auto(2) -> Enabled`.
- 묶음(태그·모델) 머리 줄 아래에 그 묶음의 속성 줄. 자동 제외 항목은 맨 아래 `[-] IscsiInitiatorName (제외: 보호 속성)` — 커서는 지나가지만 체크되지 않는다.
- 키: ↑↓·PgUp/PgDn·Home/End 이동, Space 체크, `a` 모두 선택 / `n` 모두 해제(지금 묶음), Enter 확정, Esc 뒤로, Ctrl+X 취소, Tab 은 다른 화면으로 접기(기존 `Choose` 와 같음).
- 맨 위에 `고른 항목 3 / 후보 41 · 자동 제외 17` 을 늘 보인다. 수백 줄이어도 스크롤만 한다 (검색·필터는 넣지 않음).
- 그리기는 `tui_render.go` 순수 함수로 두어 단위 시험한다.

#### 3.B.4 한쪽에만 있는 속성 — 강제로 넣을 수 있는가 (조사 결과)

**결론: 불가능하다. 두 경우 모두 자동 제외한다.**

| 경우 | 왜 안 되는가 | 이 도구에서 일어나는 일 |
|---|---|---|
| 대표서버에만 있음 (`ONLY_REF`) — 대상에 그 속성이 없음 | Redfish `Bios` 의 `Attributes` 는 그 서버 BIOS 펌웨어의 속성 레지스트리가 정한다. `Bios/Settings` PATCH 는 **이미 있는 속성의 값만** 바꾸며 속성을 만드는 요청이 없다. 레지스트리에 없는 이름을 보내면 BMC 가 요청 전체를 거절하거나 그 이름을 무시한다 | 계획: `compareItems` 가 `DIFF` 만 항목으로 삼음(445). 적용까지 가더라도 `planHost` 가 "속성이 지금 BMC 에 없음"(`CHANGED`), 레지스트리에 없으면 `INVALID_VALUE` 로 보내지 않음 |
| 대상에만 있음 (`ONLY_HOST`) — 대표서버에 없음 | 맞출 기준값이 없고, 속성을 지우는 요청도 없다 | 항목이 되지 않음 |

속성이 한쪽에만 있는 흔한 원인은 BIOS 버전 차이, 장착 하드웨어 차이(CPU 종류·NVDIMM·NIC·슬롯), 다른 설정에 딸려 숨겨지는 속성이다. 맞추려면 BIOS 업데이트·하드웨어 변경·상위 설정 변경 후 재부팅이 필요하고, 이는 이 도구가 하지 않는 일이다.

화면 표시: `[-] <속성> (제외: 대표서버에만 있음 — Redfish 로 속성을 추가할 수 없음)` / `(제외: 대상에만 있음 — 맞출 기준값 없음)`. 수정 확인 2 에도 그대로 나온다.

### 3.C 고유값 비교 제외 재점검

#### 확인된 것

- **설정은 안전하다.** 고유값은 보호 속성(계획·적용·PATCH 본문 3겹) + 설정 제외 목록(내장 항상 포함) + 형식 제한(문자열은 보내지 않음)으로 막힌다. `ServiceTag`·`SerialNumber`·`*Uuid*`·`*MacAddr*`·`*Iqn*`·`*Ipv4*`·`ServerName` 모두 해당.
- **비교에는 빈틈이 있다.** 보호 속성 목록은 비교에 쓰이지 않고, 비교 제외는 `ignore_attrs.txt`(없으면 내장 19개)뿐이다.

#### 빈틈 (속성 이름은 저장소 데이터에서 찾은 것)

| # | 빈틈 | 예 |

#### 보강안 (범위는 인터뷰 9)

1. **고유값 내장 목록 `uniqueAttrs`** 를 `protect.go` 에 둔다 — `builtinProtect` 의 "iSCSI·NVMe-oF 식별자 / IP·네트워크 주소 / 서버 이름·식별 정보" 세 묶음을 그대로 가리키고 `*SerialNum*`·`*Duid*`·`*ChipId*`·`*HostId*`·`*Wwn*`·`*Guid*` 를 더한다. 이 목록은 `ignore_attrs.txt` 유무와 상관없이 **비교에서도 항상 제외**한다 (`runUnified` 에서 합침 → `compareAttrs`·`compareLines`·건수 모두 반영, `ignored` 수로만 남음). 부팅·보안·RAID·NIC 속성은 고유값이 아니므로 지금처럼 비교는 하고 설정만 막는다.
2. **값 모양 검사 `looksUnique(v)`**: MAC(6쌍), UUID(8-4-4-4-12), IPv4/IPv6, `iqn.`·`nqn.` 시작. 비교에서는 제외로 세고, 맞추기 후보에서는 `(제외: 값이 서버 고유값 모양)`.
3. G3 정보성 속성은 목록에 넣지 않는다 (모델·펌웨어 차이를 보여 주는 값이라 가릴지 말지는 운영 판단). `ignore_attrs.txt.example` 에 주석으로 후보만 적어 둔다.
4. `protect_test.go` 에 표 시험: 위 G2 이름들이 비교 제외에 걸리고, `profiles/*.tsv` 의 속성과 `SubNumaCluster`·`LogicalProc`·`SysProfile` 같은 성능 속성은 걸리지 않는다.

### 3.D [프로파일 점검] 태그·모델별 설정 추가 명령

#### 하는 일

프로파일 TSV 에 **모델 지정 행**을 더한다. 대상 범위는 둘 중 하나.

- **모델**: 그 벤더·모델 1종에 행 추가.
- **태그**: 그 태그가 붙은 서버들이 보고한 (벤더, 모델)을 모아 **모델 1종마다** 같은 행을 만든다 (프로파일에는 태그 칸이 없으므로 태그는 "어느 모델들인지" 고르는 데만 쓴다).

#### 명령 모양 (형태는 인터뷰 10)

TUI — `[프로파일 점검]` 화면에서 `p`:

```
p → 범위 선택: 1. 지금 보는 태그 <gold> (모델 2종)  2. 지금 보는 모델 <DELL R660>  3. 태그·모델 직접 입력
  → 설정 입력 (여러 줄):  <속성 이름> <값>            예) LogicalProc Enabled
                          <std_name> <속성 이름> <값>  예) hyper_threading LogicalProc Enabled
  → 미리보기: 모델별로 추가될 행 / 건너뛰는 행(사유) / 이미 있는 행
  → "프로파일 VM 에 N행을 추가할까요?" (y) → 파일 쓰기 → 해당 호스트 재점검
```

CLI (같은 핵심 함수, `bios.sh profile add …` → `biostool profile add`):

```
bash bios.sh profile add -profile VM -tag gold  -set "LogicalProc=Enabled" [-set …] [-user user.txt]
bash bios.sh profile add -profile VM -model "DELL/R660" -set "hyper_threading:LogicalProc=Enabled"
```

CLI 에서 `-tag` 는 모델을 알아야 하므로 대상에 **읽기 전용으로 1회 접속**한다 (또는 `-from-dump`). `-model` 만 주면 접속하지 않는다.

#### 행을 만드는 규칙 — 새 파일 `profile_add.go`

- `vendor`·`model`: BMC 가 보고한 값(앞뒤 공백 제거). 중복 판단은 `vendorKey`+`normalizeModel` (로더와 같은 키).
- `attribute`: 입력 이름을 그 모델 호스트의 스냅샷에서 대소문자 무시로 찾아 **BMC 표기**로 쓴다(`lookupAttr`). 그 모델에 없는 속성이면 그 모델 행만 건너뛴다 `(건너뜀: 이 모델에 없는 속성)`.
- `std_name`: 주면 그대로(`^[a-z0-9_]+$`), 안 주면 `stdKeywords` 에 걸리는 표준 항목 이름, 그것도 아니면 속성 이름을 소문자·밑줄로 바꾼 이름.
- `value`: 입력값 (`A|B` 허용). 
- `verified`: **항상 `N`**. `Y`(쓰기 허가)는 지금처럼 사람이 파일을 직접 고쳐 승격한다.
- 보호 속성 이름은 행으로 만들지 않는다 (점검만 하는 행이라도 수정 화면에 늘 수정제외로 나와 혼란).
- 태그의 모델을 모를 때(그 태그 호스트가 모두 접속 실패): 아무것도 쓰지 않고 사유를 보인다.

#### 파일 쓰기·충돌

- 쓰는 곳: 고른 프로파일 파일의 `# [redfish]` 구역 끝(`# [xml]` 줄 바로 앞, 없으면 파일 끝). 주석·기존 행·구역은 건드리지 않는다. 새 파일을 만드는 방식은 인터뷰 11.
- 충돌(같은 벤더·모델·std_name·속성 행이 이미 있음): 값이 같으면 `이미 있음` 으로 건너뜀. 값이 다르면 TUI 는 미리보기에 `[충돌] 기존 X → 새 Y` 로 보이고 "덮어쓸까요?" 를 따로 묻는다(아니면 그 행만 건너뜀). CLI 는 `-force` 가 없으면 아무것도 쓰지 않고 끝낸다.
- 모델 지정 행을 더하면 그 std_name 의 `*` 행은 그 모델에 더 쓰이지 않는다(`rowsFor`) — 미리보기에 `※ 벤더 공통(*) 행 대신 이 행이 쓰입니다` 로 알린다.
- 쓰기 절차: 새 내용 만들기 → `parseProfile` 로 검증 → `<이름>.tsv.bak.<일시>` 백업 → 임시 파일 + rename (`checkres.go` `writeFileAtomic`), LF, 0644 유지.
- TUI: 쓴 뒤 프로파일을 다시 읽고 영향 받는 호스트만 재점검해 화면에 합친다 (`recheckHosts` 재사용).

## 4. 대표서버 선정 규칙 후보

| # | 규칙 | 장점 | 약점 |
|---|---|---|---|
| R1 | `user.txt` 입력 순서의 첫 정상 호스트 | 가장 단순, 예측 쉬움 | 첫 호스트가 틀리게 설정돼 있으면 그 값이 기준이 됨 |
| R2 | **다수결(최다 일치)**: 묶음 안에서 속성마다 가장 많은 값을 구하고, 그 값과 가장 많이 일치하는 호스트 | 소수의 이상 호스트가 대표가 되지 않음. 결정적(같은 입력 → 같은 결과) | 묶음 대부분이 틀리면 틀린 값이 대표. 계산 = 호스트 수 × 속성 수 (수천 대도 문제없는 크기) |
| R3 | 프로파일 점검이 전부 OK 인 호스트 우선 | 표준값을 지킨 서버가 대표 | 프로파일이 `verified=N`·`MAPPING_MISSING` 뿐이면 구별이 안 됨 |
| R4 | hostname 이 가장 앞선 호스트 | 입력 순서와 무관 | 이름과 설정 품질은 관계없음 |
| R5 | 직접 지정 (기존 2번 메뉴 hostname 입력, diff.txt) | 운영자 의도 그대로 | 자동이 아님 |

**권장: R2 를 기본으로, 좁히는 순서를 고정한다.**

1. 읽기 성공(`snap.ok()`), XML 대상 제외
2. 묶음에서 가장 많은 BIOS 버전의 호스트만 (버전이 다르면 설정 대상에서 빠지므로 대표가 다수 버전이어야 맞출 수 있는 호스트가 많다)
3. 프로파일 점검 difference 0건인 호스트 우선 (없으면 건너뜀)
4. 다수결 일치 수가 가장 큰 호스트 (제외·고유값 속성은 세지 않음)
5. 동률이면 `user.txt` 입력 순서

선정 사유(`BIOS 1.8.2 12/14대 · 다수결 일치 498/500`)를 안내와 `compare_refs.tsv` 에 남긴다. 자동이 마음에 들지 않으면 2번 메뉴(hostname 입력)로 직접 지정한다 (인터뷰 3).

### 위험·미해결

- **틀린 대표가 여러 대로 퍼질 위험**: 자동 대표 + 맞추기는 한 번에 많은 서버를 바꾼다. 선정 사유 표시, 기본 미체크, 확인 2단계로 줄이지만 대표값 자체가 맞는지는 사람이 본다.
- 체크 목록에는 적용 단계에서 막힐 항목(문자열·ReadOnly)이 섞일 수 있다. 점검 스냅샷에는 레지스트리가 없어 미리 가릴 수 없다 — 지금의 `※ 비교서버 값은 적용 때 레지스트리 형식을 다시 확인…` 안내를 체크 목록에도 붙인다.
- 값 모양 검사(`looksUnique`)가 진짜 설정을 가릴 가능성은 낮지만(설정값이 MAC·UUID 모양인 경우), 가려진 수는 `ignored` 로 남겨 확인할 수 있게 한다.
- 고유값을 비교에서 빼면 기존 `compare_*` CSV 의 difference 수가 줄어든다 (이전 결과와 건수 비교 시 주의, CHANGELOG 에 적음).
- 한쪽에만 있는 속성을 보냈을 때 벤더별 BMC 의 실제 응답(거절 코드·무시)은 실장비에서 확인하지 않았다. 도구가 보내지 않으므로 동작에는 영향이 없다.
- `bios_json/` 의 속성 이름은 조사용 레지스트리 자료다. G2·G3 의 이름이 실장비 `Bios.Attributes` 에 실제로 나오는지는 벤더·세대별로 다를 수 있다.
- `update.sh` 는 `profiles/` 를 파일별로 병합한다. 명령으로 고친 프로파일이 업데이트 때 어떻게 처리되는지 구현 전에 확인한다.

## 7. 인터뷰로 확정할 질문

각 질문의 첫 번째 선택지가 권장안이다.

1. **대표서버 선정 규칙**
   - (가) 다수결: 묶음에서 가장 흔한 값들과 가장 많이 일치하는 서버 (다수 BIOS 버전 → 프로파일 OK → 일치 수 → 입력 순서)
   - (나) `user.txt` 에 먼저 적힌 정상 서버
   - (다) 프로파일 점검이 전부 OK 인 서버 중 먼저 적힌 것 (없으면 나)
2. **한 태그 안에 모델이 여러 종일 때 묶음 단위**
   - (가) 태그+모델마다 대표 1대 (같은 모델끼리만 비교하는 지금 규칙과 맞음)
   - (나) 태그당 대표 1대만 — 대표와 모델이 다른 서버는 비교하지 않음(`NO_REFERENCE`)
3. **자동으로 고른 대표를 바꾸는 방법**
   - (가) 따로 두지 않음 — 바꾸려면 2번 메뉴 `비교서버 hostname 입력` 으로 직접 지정
   - (나) 선정 결과 화면에서 묶음별로 다른 서버를 고를 수 있게 함
   - (다) `user.txt` 에 대표 표시(예: 셋째 칸 `*`)를 적으면 그 서버를 대표로
4. **수정 방법 메뉴에서 `대표서버 기준으로 맞추기` 의 자리**
   - (가) 3번째에 추가 (1 점검 결과 기준 수정 · 2 BIOS 값 직접 입력 그대로)
   - (나) 1번으로 올리고 기존 둘은 아래로 (기준 메뉴와 같은 방식)
5. **`bios.conf` `allcheck_set` 과의 관계** (지금은 off 면 비교 차이를 설정하지 않음)
   - (가) 이 메뉴는 `allcheck_set` 과 무관하게 동작 — 메뉴 선택·체크·확인 2번이 명시적 동의
   - (나) `allcheck_set=on` 일 때만 메뉴를 쓸 수 있음 (off 면 안내만)
   - (다) 새 키 `align_set` 을 따로 둠 (기본 on)
6. **체크 한 줄의 단위**
   - (가) 묶음(태그·모델)별 속성 — 한 줄이 그 속성이 다른 서버 전부
   - (나) 서버×속성 — 서버마다 따로 고름 (대수가 많으면 줄이 매우 많아짐)
   - (다) 속성만 — 모든 묶음을 합쳐 한 줄
7. **체크 목록의 처음 상태**
   - (가) 모두 해제 — 바꿀 것만 직접 체크
   - (나) 모두 선택 — 빼고 싶은 것만 해제
8. **BIOS 버전이 대표와 다른 서버**
   - (가) 지금 규칙대로 맞추기 대상에서 제외 (`BIOS_VER_DIFF`)
   - (나) 경고를 붙여 목록에 보이고 고를 수 있게 함
9. **고유값 비교 제외 보강 범위**
   - (가) 고유값 내장 목록을 비교에도 항상 적용 + 값 모양(MAC·UUID·IP·IQN) 검사
   - (나) 고유값 내장 목록만 적용 (값 모양 검사 없음)
   - (다) 코드는 그대로, `ignore_attrs.txt.example` 과 문서만 보강
10. **프로파일 추가 명령의 형태** ("커맨드로 추가" 의 뜻)
    - (가) TUI `[프로파일 점검]` 화면의 `p` 키 + 같은 기능의 CLI `bash bios.sh profile add`
    - (나) TUI `p` 키만
    - (다) CLI 만
11. **태그로 추가할 때 쓰는 곳**
    - (가) 지금 쓰는 프로파일 파일에 모델별 행을 추가
    - (나) 태그 이름의 새 프로파일 파일을 만듦 (`profiles/<태그>.tsv`)
    - (다) 매번 묻기 (기존 파일에 추가 / 새 파일)
12. **추가할 설정값을 넣는 방법**
    - (가) 직접 입력 `<속성> <값>` (std_name 은 자동, 필요하면 앞에 적음)
    - (나) 대표서버의 현재값으로 표준 4항목을 자동으로 채움
    - (다) 둘 다 (자동으로 채운 뒤 고쳐서 확정)
