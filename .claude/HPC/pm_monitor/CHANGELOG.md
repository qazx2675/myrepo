# CHANGELOG

## [0.5.0] - 2026-11-17

### 추가
- **서버 설정 자동 조사**: 서버마다 OS커널(`uname -r`)·appl(`/etc/auto.appl` 의 `/appl` 마운트 위치)·dns(`resolv.conf` nameserver, 적힌 순서)·ldap_URI(`/etc/openldap/ldap.conf` 의 `URI` 줄, 호스트 이름만)·binddn·h/t(`lscpu`, ON/OFF)·ldap_check 결과(스크립트 출력, 여러 줄은 ` ; ` 로 이음)를 gossh 한 줄 명령으로 조사한다. **`bindpw` 는 읽지도 저장하지도 보여 주지도 않는다.** 수집 회차 안에서 서버당 한 번 자동으로 조사하고(회차당 최대 100대, 실패한 서버는 다음 회차에 다시 시도), `l` 을 누르면 대상 전체를 다시 조사한다(응답 없는 서버는 이전 값 유지).
- **조사 대상**: yum 서버는 `yum_update/접속가능`, **OS 설치 서버는 상태와 무관하게 전부**(이번 작업은 OS 설치 없이 yum update 와 설정 변경만 하기 때문). 자동 첫 조사는 OS 서버가 ping 이 닿는 동안만(확인전·ping X·완료후꺼짐 제외)이고 ping X 서버는 `l` 로만 조사한다.
- **oklist.txt**: `install_mn [-c conf] [-f] <호스트파일> [oklist.txt]` 의 두 번째 위치 인자(선택). 엑셀에서 붙여 넣은 탭 구분 7칸 `hostname OS커널 appl dns ldap_URI binddn h/t`. 머리줄(첫 칸 `hostname`)·빈 줄·`#` 줄 무시, 칸이 7개 미만이거나 hostname 이 중복인 줄은 무시하고 경고 줄로 센다. 비교는 대소문자·순서까지 구분한다(여러 값은 공백 구분). 읽을 수 없으면 시작 전에 한글 오류로 끝난다(코드 1). 데몬 지문에 oklist 의 절대 경로와 내용 해시가 들어가 oklist 를 바꾸면 수집을 다시 시작한다.
- **`l` 표 교체**: 제목 `LDAP·설정`, 열 `hostname | OS커널 | appl | dns | ldap_URI | binddn | h/t | ldap_check결과`, 호스트파일의 모든 서버를 호스트파일 순서로(조사 전은 빈 칸, 24칸 넘는 설정 값은 `…` 로 줄임). oklist 가 있으면 다른 칸을 **빨간색**(조사값이 비었는데 oklist 에 값이 있으면 `(없음)`), 머리줄에 `oklist N대 · 조사 M대 · 다름 K대 · 경고 W줄`, 패널 안의 **`m`** 으로 oklist 와 다른 서버만 보기(패널을 다시 열면 꺼짐).
- **res 파일** `<호스트파일 이름>.res`(실행한 디렉터리, 탭 구분 UTF-8 LF, `.gitignore` 에 `*.res`): 열 `hostname OS커널 appl dns ldap_URI binddn h/t 설치/yumupdate여부 설정동일여부`, 모든 서버를 호스트파일 순서로. 수집기가 시작할 때와 회차·조사가 끝날 때마다 내용이 바뀐 경우에만 임시 파일 → 이름 변경으로 쓴다. 엑셀에 붙여 넣는 용도이며 ldap_check 열은 없다. 쓰기 실패는 수집을 멈추지 않고 화면 오류 줄에 보인다.
  - `설치/yumupdate여부`: 한 번이라도 설치완료(OS)·`yum_update/접속가능`(yum)이었으면 `O`, 이후 ping X·완료후꺼짐·재부팅됨이 되어도 유지(`state.json` 의 `install_done`). yum 서버가 재부팅만 했다면 `X`. 이번 작업처럼 OS 설치를 하지 않는 OS 설치 서버는 `X` 가 정상이다.
  - `설정동일여부`: oklist 가 있고 서버가 oklist 에 있고 조사 결과가 있을 때만 `O`(여섯 값 모두 같음)/`X`, 아니면 빈 칸. 마지막으로 성공한 조사값 기준이다.
- 시험: 단위 테스트(`ldap_test.go`·`oklist_test.go`·`lpanel_test.go` 등, `l` 골든 폭 60/80/120), `test/daemon_check.py` 12번대(res 생성·자동 첫 조사·완료 뒤 꺼져도 O·oklist O/X·oklist 교체·없는 oklist 오류), `test/demo_yum_check.py`(oklist·res), `test/stub_gossh.sh` 의 `STUB_CFG`(호스트별 설정 값 파일), `test/load_run.sh`(oklist 를 같이 주고 끝에 gossh 호출 수·조사 대수·`.res` 행 수 확인, `LOAD_L_MAX`(`test/pty_drive.py`)로 `l` 을 누르는 횟수 조절).
- `demo/demo.sh`: oklist 를 만들어(거의 같고 4대만 일부러 다름) `install_mn hosts.txt oklist.txt` 로 실행하고 결과 파일 `/tmp/pm_demo/hosts.txt.res` 를 안내한다.

### 변경
- **`l` 의 동작이 바뀌었다**: v0.4.0 까지는 결과가 비어 있는 서버만 조사했지만 이제 열 때마다 대상 전체를 다시 조사한다. 자동 첫 조사 덕분에 평소에는 누를 필요가 없다. 대상 서버가 많을 때(8000대) `l` 을 자주 열면 데몬 CPU·메모리 순간 부하가 크다(아래 비고).
- **NTP·autofs 열과 NTP 비교를 없앴다**(NTP 는 DNS 와 같은 설정). `l` 표는 위 8열로 바뀌었고 옛 chrony·getent·wappl 조사는 하지 않는다.
- **`state.json` 형식 번호 2**(v0.4.0 은 1). v0.4.0 파일은 읽을 때 자동으로 옮기며 `설치/yumupdate여부` 를 OS 서버 설치완료·완료후꺼짐·재부팅됨, yum 서버 `yum_update/접속가능`(또는 완료 기록)으로 채운다. `Check` 에 새 필드가 늘었고 옛 형식의 조사 결과는 자동으로 다시 조사한다.
- **데몬 지문**: 프로그램 버전 `0.5.0` + 호스트파일·설정 내용 + oklist 절대 경로·내용 해시. 바이너리를 교체한 뒤 다시 실행하면 옛 데몬을 멈추고 새로 시작한다(상태 기록 유지).
- 스냅샷에 `HostOrder`(호스트파일 순서)·`Cmp`(서버별 비교 비트)·`Cfg`(집계)가 늘었다. oklist 도 res 도 없는 호스트파일의 `l` 이외 화면·코멘트는 v0.4.0 과 같다(기존 골든 그대로).

## [0.4.0] - 2026-11-17

### 추가
- **yum update 모드**: 호스트파일 한 줄을 `hostname [yum]` 으로 읽는다. 두 번째 칸이 `yum`(대소문자 무시, 공백·탭 여러 개 가능)이면 그 서버는 OS 설치가 아니라 `yum update` 후 재부팅·커널 변경을 확인하는 대상이다. 그 밖의 값·빈 칸은 OS 설치(기존 동작 그대로), 세 번째 칸부터는 무시한다. 서버의 모드가 이전 실행과 달라지면 그 서버의 기록만 새로 시작한다(`state.json` 의 `mode`, 옛 파일은 그대로 읽힘).
- **새 상태 2개**: `접속가능`(기준 커널 기록, 변화 없음, 필터 8), `yum_update/접속가능`(현재 커널이 기준 커널과 다름 = 완료, 필터 9). 흐름은 `접속가능` → `재부팅됨`(ping X 이거나 부팅 시각이 60초 넘게 바뀜) → `yum_update/접속가능`. 재부팅했지만 커널이 같으면 `재부팅됨` 에 머물고 비고에 `재부팅됨, 커널 동일 <커널>`. 기준 커널·부팅 시각은 ssh 가 처음 성공한 때 한 번만 기록해 `state.json` 에 저장한다. `c` 를 눌렀을 때 `yum_update/접속가능` 이 ping X 면 `완료후꺼짐`, 다시 켜지면 `yum_update/접속가능` 으로 돌아온다.
- **yum 지연**: 설정 `yum_delay_min`(기본 60분). 기준 커널을 기록한 뒤 그 시간이 지나도 완료(`yum_update/접속가능`·`완료후꺼짐`)가 아니면 yum 지연이며 `r`·`c`·`y` 에만 나타난다(상태 이름은 그대로).
- **`y` 키(yum 커널 표)**: hostname·벤더·상태·기준 커널·현재 커널·재부팅·비고. 스냅샷만 쓰고 ssh·ping 을 하지 않으며, yum 서버가 없으면 "yum 서버가 없습니다.".
- **`c` 설치현황**: yum 서버가 있을 때만 yum 요약 줄(`yum update N대 중 M대 커널 변경 완료(yum_update/접속가능), 접속가능 …, 재부팅됨 Y대(커널 동일 Z대), ping X …`, 지연이 있으면 `(지연 N대)`)과 목록(`yum 접속불가`·`yum 재부팅 대기`·`yum 재부팅 중`·`yum 재부팅됨 커널 동일`)이 붙는다. `재부팅됨 Y대(커널 동일 Z대)` 는 재부팅됨 Y대 중 재부팅 뒤 접속해 커널이 같음을 확인한 서버가 Z대라는 뜻이다.
- **`r` 점검요청**: 벤더마다 OS 설치 지연 블록 뒤에 yum 블록이 붙는다. A 재부팅 확인 안 됨, B 재부팅했지만 커널 변경 없음, C 재부팅한 뒤 접속되지 않고 있음.
- **상태 필터 8·9**, 머리줄 `전체 N대 (yum M대)`, 맨 아래 안내의 `1~9 필터`·`y yum` 은 yum 서버가 있을 때만 나온다. 긴 상태 이름 `yum_update/접속가능` 이 잘리지 않게 상태 칸을 넓힌다.
- **`install_mn --status`** 줄: yum 서버가 있을 때만 `서버 N대 중 설치완료 M · yum D/T · 회차 R`(N·M 은 OS 서버 기준).
- 시험: `test/daemon_check.py` 51 PASS(기존 28 + yum 23), `test/func_check.py` 26 PASS, 새 `test/demo_yum_check.py`(데모 스크립트를 가상 터미널로 돌려 확인, 20/20 PASS), `test/stub_gossh.sh` 에 yum 시나리오(바뀐 커널·바뀐 부팅 날짜·바뀐 부팅 시각·전환 시각 4칸), `test/load_run.sh` 의 세 번째 인자 yum 비율(`... 600 8000 5`)과 `LOAD_DIR` 환경변수.
- `demo/demo.sh`: yum 서버를 넣었다(`-n 27` 이면 6대를 더해 33대, 더 큰 `-n` 은 5% 를 yum 으로 바꿈, 데모 설정 `yum_delay_min=1`, 한 대는 ping 이 끊겨 재부팅 중을 보여 줌, 1000대 이상 데모는 240초 뒤 전환).

### 변경
- **설치완료 집계는 OS 서버만** 센다. `c` 의 "N대 중 M대 설치완료"·`재부팅됨 N대` 목록·`d` 대상은 OS 서버 기준이고, `l` 대상은 OS 서버의 설치완료·재부팅됨과 yum 서버의 `yum_update/접속가능` 이다. yum 서버가 없는 호스트파일은 화면·코멘트 출력이 v0.3.0 과 같다.

- 부하 규칙은 그대로이고 yum 서버가 있으면 gossh 를 **회차당 한 번 더**(`echo NS_YUM; uname -r; uptime -s`) 실행한다. 여전히 한 번에 하나, `nice -n 10`.

- **확인하지 못한 것**: 실제 서버에서 실제 `yum update`·실제 gossh 로는 시험하지 못했다(모두 스텁). yum 서버도 22번 포트 확인을 하며 `gossh -pm`·디스크 확인은 하지 않는다.
- **알려진 한계**: 바이너리 교체로 데몬이 다시 시작될 때도 화면 문구는 "호스트파일·설정이 바뀌어 수집을 다시 시작했습니다" 로 나온다(동작에는 영향 없음). 60칸 폭에서 `y` 패널은 오른쪽이 잘린다(`l` 과 같음). `y` 키에 한글 자판 대응 키는 없다. `yum update` 로 새 커널이 설치돼도 기본 부팅 커널이 옛것이면 커널 동일로 보인다.

## [0.3.0] - 2026-11-15

### 변경
- **백그라운드 수집**: 수집을 화면(TUI)이 아니라 데몬 프로세스가 한다. `install_mn <호스트파일>` 은 같은 호스트파일의 수집이 돌고 있으면 이어서 붙고, 없으면 시작한 뒤 붙는다. 화면은 소켓(`/run/install_mn/`)으로 스냅샷을 받아 그린다.
- `q`(기본 화면)·Ctrl+C·연결 끊김(SIGHUP)은 **화면만** 닫고 수집은 계속된다. 수집까지 끝내려면 `Q` 후 `y`, 또는 `install_mn --stop <호스트파일>`.
- **12시간 자동 종료**: 데몬은 시작 12시간 뒤 스스로 끝난다(시작 시각 고정, 다시 붙어도 연장 안 됨). 붙은 화면도 닫히고 상태 파일은 남는다. 머리줄에 `자동 종료 HH:MM`.
- 호스트파일·설정 파일 내용이 바뀌었으면 다시 실행할 때 수집을 다시 시작한다(상태 기록 유지).
- 옛 방식(수집이 화면과 함께 끝남)은 `-f` 로 남겨 두었다.

### 추가
- `install_mn --status [<호스트파일>]`(실행 중인 수집 보기), `install_mn --stop <호스트파일>`.
- `test/daemon_check.py`: 붙기·떼기·재접속·종료·12시간 만료를 실제 프로세스(pty)로 확인(28항목). `test/load_run.sh` 는 데몬 프로세스 기준으로 부하를 잰다.
