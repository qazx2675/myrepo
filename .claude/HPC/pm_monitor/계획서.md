## 3. 확정된 규칙

### 3.1 상태 분류

| 상태 | 판정 | 벤더별로 나누나 |
|---|---|---|
| 설치중 | gossh `-pm` 이 OS 설치중으로 판정, **또는** ping O 이고 22번 포트가 refused | 나누지 않음 |
| 지연 | 설치중으로 처음 본 뒤 `delay_min`(기본 **60분**)이 지나도 완료가 아님. 상태 표시만 한다 | 점검요청 코멘트에서만 나눔 |
| 디스크미인식 | 설치중인 서버의 `/tmp/anaconda.log` 에 `DISK_PATTERN` 문구가 있음 | **나눔** |
| 설치완료 | ssh 접속이 되고 anaconda 가 없음 | 나누지 않음 |
| ping X (접속불가) | ping 무응답 | **나눔** |
| 재부팅됨 | 완료후꺼짐으로 기록된 서버가 다시 ping O 가 됨. **완료 수에 포함** | — |
| 완료후꺼짐 | 설치완료였던 서버가 `c` 를 누른 시점에 ping X. 완료와 별도 분류로 저장 | 나눔 |

- 판정 우선순위: 디스크미인식 > 지연 > 설치중 (setup_check 와 같은 방식).
- 22번 포트가 refused 여서 ssh 로 들어갈 수 없는 서버는 anaconda.log 를 읽지 못하므로 설치중으로 남는다.
- 상태와 이력(처음 본 시각, 완료 시각, 꺼짐·재부팅 시각)은 실행 디렉터리의 `<호스트파일>.pm_state.json` 에 저장한다. 다시 실행해도 이력이 유지된다.

### 3.2 벤더 규칙

설정 파일의 `vendor` 줄에 hostname 정규식과 벤더 표시 이름을 쓴다. **위에서부터 처음 맞는 줄**을 쓴다. 표시 이름은 아무 문자열이나 되며 회사에서 바꿀 수 있다. 기본값은 config_check 순서에 사용자 이름을 붙인 것이다.

```
vendor=^(c|h|sh|s2h|s3h|s4h)=D
vendor=^s=sds
vendor=^p=L
vendor=^l=j
vendor=^d=t
vendor=^m=W
vendor_other=기타
```

### 3.3 설정 파일

기본으로 **실행한 디렉터리의 `pm_monitor.conf`** 를 읽는다. `-c <경로>` 로 다른 파일을 지정할 수 있다. 파일이 없으면 기본값을 쓰고 화면에 경고를 한 줄 띄운다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `gossh` | PATH 에서 찾음 | gossh 경로 |
| `interval_sec` | 60 | 갱신 주기 |
| `delay_min` | 60 | 지연 기준(분) |
| `yum_delay_min` | 60 | yum 지연 기준(분, v0.4.0, 4.8) |
| `disk_pattern` | setup_check 기본 문구 | 여러 줄 가능 |
| `vendor` / `vendor_other` | 3.2 참고 | 벤더 규칙 |
| `dhcp_server` | 비어 있음 | 비어 있으면 `d` 를 눌렀을 때 "dhcp_server 미설정"을 표시 |
| `ldap_check_sh` | 비어 있음 | ldap_check.sh 경로. 비어 있으면 `l` 을 눌렀을 때 "미설정"을 표시 |
| `ping_timeout_ms` | 1500 | raw ICMP 응답 대기 시간 |
| `ping_pps` | 500 | 초당 보내는 ICMP 패킷 수 상한(관리서버 부하 제한) |
| `tcp_parallel` | 100 | 22번 포트 동시 연결 수 상한 |

## 4. 동작 흐름

### 4.1 갱신 주기 (기본 1분)

1. **ping**: 완료·완료후꺼짐을 **제외한** 모든 서버에 raw ICMP 를 보낸다. 소켓 하나로 echo id·seq 로 매핑한다(auto_setup `icmp.go` 이식). 응답이 없으면 ping X.
2. **22번 포트**: ping O 인 미완료 서버에 TCP 연결을 시도한다. refused 이면 설치중(Go `net.DialTimeout`, 동시 연결 수 제한).
3. **gossh -pm**: 22번 포트가 열린 미완료 서버만 `gossh -pm -w <임시목록> "echo PM_OK"` 로 확인한다. `PM_OK` 가 찍히면 설치완료, OS 설치중 목록에 있으면 설치중.
4. **디스크 확인**: 설치중이고 ssh 가 되는 서버에 gossh(`-pm` 없이)로 setup_check 의 `buildRemoteCmd` 와 같은 명령을 실행한다. 표식이 나오면 디스크미인식.
5. 상태와 이력을 갱신하고 지연을 판정한 뒤 state.json 에 저장한다. 화면에 반영한다.

- 완료된 서버는 평소에 ping 하지 않고 ssh 도 다시 하지 않는다.
- gossh 가 1분을 넘기면 다음 회차는 앞 회차가 끝난 뒤에 시작한다(겹치지 않음).
- 수집은 백그라운드 고루틴이 하고, TUI 는 스냅샷만 받아서 그린다. 키 입력은 수집과 상관없이 즉시 반응한다.

### 4.2 TUI 키 (auto_setup 규칙: 소문자 키, 맨 아래 안내 줄, 다시 누르면 닫힘)

| 키 | 동작 |
|---|---|
| (기본 화면) | 위: 상태별 개수와 마지막 갱신 시각·회차 진행. 아래: hostname·벤더·상태·경과 시간 표 |
| ↑↓ PgUp PgDn Home End | 표 스크롤 |
| `/` | hostname 검색 |
| `1`~`9` / `0` | 상태 필터 / 필터 해제 (v0.4.0: 8 접속가능·9 yum_update/접속가능, yum 서버 전용, 4.8) |
| `y` | (v0.4.0) yum 커널 표 켜기/끄기. 스냅샷만 사용(4.8) |
| `c` | 설치현황 코멘트 켜기/끄기. 켤 때 **완료 서버에 ping** 을 보내 완료후꺼짐·재부팅됨을 판정한다 |
| `r` | 지연 서버의 벤더별 점검요청 코멘트 켜기/끄기 |
| `d` | DHCP 조회(ping X 서버를 `dhcp_server` 로 보냄) 결과 켜기/끄기 |
| `l` | 완료 서버의 LDAP·DNS·NTP·autofs·H/T 점검 결과 켜기/끄기 |
| `q` | 코멘트·결과 창(c r d l y)이 열려 있으면 **닫고 기본 화면으로 돌아감**(뒤로가기), 기본 화면이면 **화면만 나가기**(수집은 백그라운드에서 계속, 4.7). 검색 입력 중에는 Esc 로 취소 |
| `Q` | 수집까지 완전히 종료. "수집을 완전히 종료할까요?" 확인에서 `y` 만 종료, 나머지 키는 취소 |
| Ctrl+C | 어디서든 화면만 나가기(터미널 복구, 수집은 계속). 연결이 끊겨 SIGHUP 을 받아도 같다 |

### 4.3 설치현황 코멘트 (`c`)

```
설치현황
300대 중 30대 설치완료, 265대 설치중, 3대 디스크 미인식, ping X 2대
sds
디스크 미인식 3대
svr1 svr2 svr3
접속불가 2대
svr5 svr7
```

- 요약 줄의 설치중에는 지연이 포함된다(지연이 있으면 `(지연 N대)` 를 덧붙임). 완료후꺼짐이 있으면 `, 완료후꺼짐 N대` 를 덧붙인다.
- 벤더 블록은 디스크미인식·접속불가·완료후꺼짐이 하나라도 있는 벤더만, 설정 순서대로 나온다. 서버 목록은 공백으로 구분한 한 줄이다.
- 요약 줄에서 설치완료·설치중은 0대여도 항상 쓰고, 디스크 미인식·ping X·완료후꺼짐은 0대면 뺀다(순서: 설치완료, 설치중, 디스크 미인식, ping X, 완료후꺼짐). 확인전 서버는 전체 수에만 들어간다.
- 재부팅됨이 있으면 맨 끝에 `재부팅됨 N대` 와 목록을 붙인다(완료 수에는 이미 포함).

### 4.4 점검요청 코멘트 (`r`)

벤더별로 config_check 문구를 지연에 맞게 바꿔 출력한다.

```
안녕하세요 <벤더> 담당자님
하기서버 N대는 OS 설치가 지연되고 있습니다.
점검부탁드립니다.
감사합니다.
svrA svrB …
```

### 4.5 DHCP (`d`)

config_check 방식을 그대로 쓴다. ping X 목록을 stdin 으로 넘겨 `ssh -o ConnectTimeout=10 <dhcp_server> "cat > /root/off_server_list_<user>; bash /root/a.sh; rm -f /root/off_server_list_<user>"` 을 한 번 실행하고, 출력을 스크롤 창에 보여 준다. 로컬과 원격에 파일을 남기지 않는다.

### 4.6 LDAP·H/T (`l`) — v0.2.0 에서 표시 형식 변경 (v0.5.0 에서 4.9 로 바뀜: 아래는 옛 내용)

```
hostname	LDAP	DNS · NTP	autofs	H/T	비고
svr001	zxcv	10.1.1.10/10.1.1.11	nas01:/export/appl	ON
svr002	FAIL	다름	nas01:/export/appl	OFF	ldap_check UNDEFINED; DNS 10.1.1.10/10.1.1.11 NTP 10.1.2.20
```

- 대상은 설치완료·재부팅됨 서버 중 **결과가 아직 채워지지 않은 서버만**이다. 이미 채워진 서버는 state.json 의 값을 그대로 쓴다(v0.1.x 형식으로 저장된 값은 새 형식이 아니므로 다시 조사한다).
- 기존 코드 조사(graphify 그래프·전 브랜치·로컬 작업 폴더): DNS·NTP 를 `ip1/ip2` 로 묶어 보여주는 코드는 없어서 새로 만든다. 조사 명령은 pm_monitor 가 gossh 로 함께 보낸다(ldap_check.sh 는 고치지 않음). csh/tcsh 에서도 돌도록 변수·중괄호 없이 만든다.
- 열 규칙
  - **LDAP**: ldap_check.sh 출력 `INFO|OK\tLDAP\t<infra>[\t<site>]` 에서 **infra 만** 쓴다. `FAIL` 이면 `FAIL`, 비고에 `ldap_check UNDEFINED`. 출력이 없으면 `-`.
  - **DNS · NTP**: `/etc/resolv.conf` 의 `nameserver` IP 집합과 `/etc/chrony.conf`(없으면 `/etc/ntp.conf`)의 `server`·`pool` IP 집합을 **순서 무시**로 비교한다. 같으면 IP 를 **숫자 오름차순**으로 `ip1/ip2` 로 쓴다. 다르면 `다름` 이라 쓰고 비고에 `DNS a/b NTP c/d` 를 붙인다. 두 파일 모두 값이 없으면 `-`, 한쪽만 없으면 `다름`. NTP 값이 IP 가 아닌 호스트 이름이면 **그 노드에서 `getent hosts` 로 IP 로 풀어** 비교한다(이름 하나당 5초 제한, 짧은 이름과 FQDN 첫 마디는 같은 것으로 봄). 못 푼 이름은 그대로 두고 비고에 `NTP 이름 풀이 실패 <이름>` 을 붙인다(v0.2.1).
  - **autofs**: `/etc/auto.appl` 에서 키가 `/appl`·`/wappl`(앞의 `/` 는 있어도 없어도 됨)인 줄의 마지막 필드(마운트 위치, 예: `nas01:/export/appl`)를 읽는다. 두 줄이 같으면 `/appl` 값만 쓴다. 다르면 `다름` 이라 쓰고 비고에 `/appl <값> /wappl <값>` 을 붙인다. 한 줄만 있으면 그 값, 둘 다 없으면 `-`.
  - **H/T**: Thread(s) per core 가 2 이상이면 ON, 1 이면 OFF, 모르면 `-`.
  - **비고**: 위 원인들을 `; ` 로 이어 붙인다. 머리줄에 항상 `비고` 칸이 있다.
- 파일별 형식(옛 ldap_check README 형식)이 오면 LDAP 칸은 `ldap.conf` 줄의 infra(`/<infra>` 의 이름)를 쓰고 FAIL 이 하나라도 있으면 `FAIL` 이다.
- gossh 의 `/user/` 병렬 350 제한은 그대로 둔다.

### 4.7 백그라운드 수집 (v0.3.0, 2026-11-15)

화면(TUI)이 떠 있어야만 수집되던 방식을 auto_setup 의 데몬 방식처럼 바꿨다. 수집은 **데몬 프로세스**가 하고, 화면은 소켓으로 붙었다 떨어진다.

- `install_mn <호스트파일>`: 같은 호스트파일의 수집 데몬이 이미 있으면 그대로 붙고, 없으면 자기 자신을 `--daemon` 으로 다시 실행해(setsid, 터미널과 분리) 시작한 뒤 붙는다. 첫 화면부터 지금까지의 상태가 보이고 회차가 이어진다.
- **자동 종료**: 데몬은 시작한 시각부터 **12시간**이 지나면 스스로 끝난다(시작 시각 고정. 다시 붙어도 연장되지 않는다). 붙은 화면도 함께 닫히고, 상태 파일은 남는다. 끝난 뒤 다시 실행하면 새 12시간으로 시작한다. 머리줄에 `자동 종료 HH:MM` 이 보인다.
- **화면 닫기와 수집 종료**: `q`(기본 화면)·Ctrl+C·연결 끊김(SIGHUP)은 화면만 닫는다. 수집까지 끝내려면 화면에서 `Q` → `y`, 또는 `install_mn --stop <호스트파일>`.
- **데몬 식별**: 상태 파일의 절대 경로(= 실행 폴더 + 호스트파일 이름)로 구분한다. 호스트파일마다 데몬 하나, 다른 호스트파일은 따로 동시에 돌 수 있다. 같은 호스트파일의 데몬은 파일 잠금(flock)으로 둘이 되지 않는다.
- **바뀐 입력**: 호스트파일·설정 파일 내용이 데몬을 시작할 때와 달라졌으면 데몬을 멈추고 다시 시작한다(상태 기록은 유지, 12시간은 새로 셈). 화면 위쪽에 안내가 보인다.
- `install_mn --status [<호스트파일>]`: 실행 중인 수집(호스트파일·pid·시작·자동 종료·남은 시간). 호스트파일을 빼면 서버 전체의 수집을 보여 준다.
- 소켓·잠금·로그는 `/run/install_mn/`(root 전용 0700, 재부팅하면 비워짐)에 둔다. 소켓은 0600 이다.
- `-f`: 데몬 없이 이 프로세스가 수집하고 화면을 닫으면 끝나는 옛 방식(디버깅·시험용).
- 부하: 수집 부하 제한(5.1)은 데몬에 그대로 적용된다. 화면은 스냅샷을 받아 그리기만 하고, `l`·`d` 조회와 `c` 확인은 데몬이 하며 같은 종류는 동시에 하나만 돈다. 화면을 여러 개 붙여도 수집이 늘지 않는다.

### 4.8 yum update 모드 (v0.4.0, 2026-11-17)

호스트파일 **두 번째 칸이 `yum`** 이면 그 서버는 OS 설치가 아니라 **yum update 후 커널 변경(재부팅) 확인** 대상이다. OS 는 이미 올라와 있는 서버에서 `yum update` 를 돌린 뒤 재부팅이 되어 커널이 바뀌었는지 추적한다. 인터뷰 확정(2026-11-17).

**호스트파일 형식**

```
svr001            # 두 번째 칸 없음 -> OS 설치(기존 동작 그대로)
svr002 yum        # yum update 모드
svr003  YUM       # 대소문자 무시, 공백·탭 여러 개 허용
svr004 kickstart  # yum 이 아닌 값 -> OS 설치로 간주(두 번째 칸 무시)
```

- 첫 칸만 hostname 이고 두 번째 칸이 대소문자 무시로 `yum` 일 때만 yum 모드다. 세 번째 칸부터는 무시한다. 줄 전체가 `#` 이거나 빈 줄이면 건너뛴다(기존 규칙).
- 같은 hostname 이 두 번 나오면 처음 줄만 쓴다(기존 규칙). 호스트파일 내용이 바뀌면 지문이 달라져 데몬이 재시작한다(4.7). 서버의 모드가 state.json 의 모드와 달라졌으면 그 서버의 기록은 새로 시작한다.
- 모드는 `Record.Mode`(`""`=OS 설치, `"yum"`)로 state.json 에 저장한다(`omitempty`, 옛 파일 그대로 읽힘).

**상태와 전이 (yum 서버만)**

| 상태 | 판정 | 비고 |
|---|---|---|
| 확인전 | 아직 ssh 로 커널을 읽지 못함(ping O 인데 ssh 실패 포함, 이유 표시) | 기준 커널 없음 |
| ping X | **기준 커널을 기록하기 전**에 ping 무응답 | 기존 ping X 와 같은 상태·색 |
| **접속가능**(새, 필터 8) | ping O·ssh O 이고 기준 커널을 기록함. 기준 커널과 같고 재부팅 흔적 없음 | 진행중. 기준 시각 `YumSince` 기록 |
| 재부팅됨(기존 6) | 접속가능이던 서버가 ping X 가 되었거나, 부팅 시각이 바뀌었는데 **커널은 기준과 같음** | 진행중(**완료 아님**, 매 회차 계속 확인) |
| **yum_update/접속가능**(새, 필터 9) | ping O·ssh O 이고 현재 커널이 기준 커널과 **다름** | **완료**. 이전→현재 커널을 이유에 표시 |
| 완료후꺼짐 | yum_update/접속가능이던 서버를 `c` 로 확인했을 때 ping X | 기존 `c` 동작 재사용. 다시 켜지면 yum_update/접속가능으로 되돌림 |

- **기준 커널**: ssh 가 처음 성공한 회차에 `uname -r` 와 부팅 시각(`uptime -s`)을 **한 번만** 기록하고 `Record.YumKernel`·`YumBoot`·`YumSince` 로 저장한다. 다시 실행해도 유지된다. 기준 커널을 기록하기 전에는 `접속가능` 이 아니다.
- **재부팅 감지**: 접속가능·재부팅됨 서버가 ping X 가 되면 ping X 대신 **재부팅됨**(이유 `재부팅 중(ping 응답 없음)`)으로 바꾼다. ping 이 돌아와 ssh 가 되면 `uptime -s` 를 읽어 기준 부팅 시각과 **60초 넘게 다르면** 재부팅으로 본다(회차 사이에 빨리 재부팅된 경우도 잡는다. `uptime -s` 의 1초 오차는 허용). 재부팅됨은 한 번 되면 유지한다(`RebootedAt` 처음 시각).
- **커널 변경 판정**: ssh 가 되는 회차마다 `uname -r` 를 기준 커널과 문자열로 비교한다. 다르면 yum_update/접속가능(`YumDoneAt`). 같으면 접속가능(재부팅 흔적 없음) 또는 재부팅됨(재부팅 흔적 있음, 이유 `재부팅됨, 커널 동일 <커널>`)을 유지한다.
- **완료 이후**: yum_update/접속가능은 설치완료처럼 평소 회차에서 ping·ssh 를 하지 않는다. `c` 를 누를 때만 ping 해서 완료후꺼짐을 판정한다(재부팅이 다시 있어도 커널 비교는 다시 하지 않는다).
- **yum 지연**: 상태 이름은 바꾸지 않는다. `YumSince` 로부터 `yum_delay_min`(기본 60분)이 지나도 yum_update/접속가능이 아니면 **yum 지연**으로 보고 `r` 코멘트와 `c` 요약, `y` 표에만 올린다. 지연은 접속가능(재부팅 안 됨), 재부팅됨(커널 동일 확인), 재부팅됨(재부팅 뒤 접속 안 됨) 세 종류로 나눈다(`r` 의 A·B·C).
- 22번 포트 확인은 yum 서버도 똑같이 한다(refused·무응답이면 ssh 불가로 보고 이유만 남김). yum 서버는 `gossh -pm`·디스크 확인(anaconda)을 하지 않는다.
- 커널·부팅 시각 조회: ssh 가 가능한 yum 서버(완료·ping X 제외)에 gossh 를 **회차당 한 번**, `echo NS_YUM; uname -r; uptime -s` 한 줄 명령으로 보낸다(csh/tcsh 에서도 돌도록 변수·중괄호 없이). 부하 제한(5.1)은 그대로이고 gossh 는 여전히 한 번에 하나다. 완료된 yum 서버가 늘수록 대상이 줄어든다.

**표시·집계**

- 상태 컬럼·상단 개수·필터에 `접속가능`(8)·`yum_update/접속가능`(9)이 추가된다. 재부팅됨(6)은 OS 서버와 yum 서버가 같은 이름이며 필터에서 같이 나온다.
- **설치완료 집계는 OS 서버만** 센다. `Snapshot.Done()`·`c` 의 "N대 중 M대 설치완료"·`재부팅됨 N대` 목록·`l`·`d` 대상 판정은 모드를 보고 yum 서버를 구분한다(yum 서버의 재부팅됨은 완료가 아니다).
- **`c` 설치현황**: 기존 요약 뒤에 yum 서버가 하나라도 있을 때만 별도 줄을 붙인다. 호스트파일에 yum 이 없으면 출력은 v0.3.0 과 완전히 같다.
  ```
  설치현황
  300대 중 30대 설치완료, 265대 설치중, ...        <- OS 서버만(yum 서버는 전체 수 N대에 포함하지 않음, 아래 줄에 따로)
  yum update 12대 중 8대 커널 변경 완료(yum_update/접속가능), 접속가능 1대, 재부팅됨 2대(커널 동일 1대), ping X 1대 (지연 2대)
  yum 접속불가 1대
  svr010
  yum 재부팅 대기 1대
  svr011
  yum 재부팅 중 1대
  svr013
  yum 재부팅됨 커널 동일 1대
  svr012
  ```
  - 첫 줄의 "N대 중" 의 N 은 **OS 서버 수**다(yum 서버는 두 번째 줄에서 센다). 호스트파일에 yum 서버만 있으면 OS 요약 줄은 쓰지 않는다. 0대인 항목은 뺀다(yum update·커널 변경 완료만 항상 쓴다). 지연이 있으면 `(지연 N대)` 를 덧붙인다.
  - `재부팅됨 Y대(커널 동일 Z대)` 는 **재부팅됨 Y대 중 재부팅 뒤 ssh 로 접속해 커널이 같음을 확인한 서버가 Z대**라는 뜻이다. 나머지 Y−Z대는 아직 재부팅 중(재부팅 뒤 접속되지 않음)이다. 위 예시의 `재부팅됨 2대(커널 동일 1대)` 는 svr012(커널 동일 확인) 1대와 svr013(재부팅 중) 1대다.
  - 목록 줄은 해당 서버가 있을 때만 나온다(`yum 접속불가`=ping X, `yum 재부팅 대기`=접속가능, `yum 재부팅 중`=재부팅됨이지만 재부팅 뒤 아직 접속되지 않음, `yum 재부팅됨 커널 동일`=재부팅 뒤 접속해 커널이 같음을 확인). 순서는 이 순서다.
- **`r` 점검요청**: 기존 OS 설치 지연 블록 뒤에 벤더별로 yum 지연 블록을 붙인다. 블록 사이는 빈 줄 하나이고, 지연 서버가 없으면 기존 안내 문구 그대로다(OS·yum 모두 없을 때만).
  ```
  안녕하세요 <벤더> 담당자님
  하기서버 N대는 yum update 후 재부팅이 확인되지 않고 있습니다.
  점검부탁드립니다.
  감사합니다.
  svrA svrB

  안녕하세요 <벤더> 담당자님
  하기서버 N대는 yum update 후 재부팅은 되었으나 커널이 변경되지 않았습니다.
  점검부탁드립니다.
  감사합니다.
  svrC

  안녕하세요 <벤더> 담당자님
  하기서버 N대는 yum update 후 재부팅한 뒤 접속되지 않고 있습니다.
  점검부탁드립니다.
  감사합니다.
  svrD
  ```
  - 벤더마다 OS 블록 뒤에 yum 블록이 **A → B → C** 순으로 붙고 해당 서버가 없는 블록은 나오지 않는다. A = 재부팅 확인 안 됨(접속가능), B = 재부팅했지만 커널 변경 없음(재부팅됨, 재부팅 뒤 ssh 로 커널 동일 확인), C = 재부팅한 뒤 접속되지 않고 있음(재부팅됨이지만 아직 ssh 안 됨, 이유 `재부팅 중`). 예시는 한 벤더에 세 종류가 모두 있는 경우다.
  - yum 지연은 접속가능(A)·재부팅됨(B·C)만 해당한다(`yum_update/접속가능`·완료후꺼짐은 지연이 아니다).
- **`y` 새 키: yum 커널 표**(snapshot 만 쓰는 순수 렌더, ssh·ping 없음, 다시 누르면 닫힘):
  ```
  hostname	벤더	상태	기준 커널	현재 커널	재부팅	비고
  svr002	D	yum_update/접속가능	4.18.0-513.el8	4.18.0-553.el8	11-17 14:20	
  svr011	D	접속가능	4.18.0-513.el8	4.18.0-513.el8	-	지연 85분
  ```
  `재부팅` 칸은 재부팅이 감지된 시각(`MM-DD HH:MM`, 없으면 `-`)이고, 비고는 상태 이유(예 `커널 4.18.0-513.el8 → 4.18.0-553.el8`, `재부팅됨, 커널 동일 …`)에 yum 지연이면 `지연 N분` 을 `; ` 로 잇는다. 줄 순서는 스냅샷 순서(상태 번호 → hostname)다. yum 서버가 없으면 "yum 서버가 없습니다." 를 표시한다. `y` 는 화면에서 `c r d l` 과 같은 패널 키이고 `q` 로 닫는다.
- **`l`**: 대상은 설치완료·재부팅됨(OS 서버) + **yum_update/접속가능(yum 서버)** 이다. yum 서버의 재부팅됨·접속가능은 대상이 아니다. **`d`**: ping X 서버 중 **yum 서버는 제외**한다.
- 설정 키 `yum_delay_min`(기본 60, yum 지연 기준 분)을 추가한다(`pm_monitor.conf.sample`·README 설정표 갱신).
- 데몬·화면 호환: 스냅샷에 모드·yum 필드가 추가되므로 데몬 지문에 **프로그램 버전**을 넣어, 바이너리를 교체한 뒤 다시 실행하면 옛 데몬을 멈추고 새로 시작한다(상태 기록 유지, 12시간 새로 셈). 이미 같은 기능이 있으면 그대로 둔다.

### 4.9 서버 설정 조사·oklist 비교·res 파일 (v0.5.0, 2026-11-17)

이번 작업은 OS 설치 없이 **yum update 와 설정 변경**만 한다. 사용자 인터뷰로 정한 사양이다.

- **실행**: `install_mn [-c conf] [-f] <호스트파일> [oklist.txt]`. 두 번째 위치 인자가 oklist(선택)이다. 없거나 읽을 수 없으면 한글 오류로 시작 전에 종료(코드 1). `--status [호스트파일]`·`--stop <호스트파일>` 은 oklist 를 받지 않는다. 데몬에는 시작 인자(절대 경로)로 넘긴다. 데몬 지문 = 프로그램 버전(0.5.0) + 호스트파일·설정 내용 + **oklist 절대 경로·내용 해시** → oklist 를 바꾸면 수집을 다시 시작하고, 같으면 그대로 붙는다.
- **oklist.txt**: 엑셀에서 붙여 넣은 탭 구분 7칸 `hostname OS커널 appl dns ldap_URI binddn h/t`. 칸마다 앞뒤 공백 제거·안쪽 연속 공백 하나로. 빈 줄·`#` 줄 무시, 첫 칸이 `hostname`(대소문자 무시)이면 머리줄로 무시. 칸이 7개 미만·hostname 없음·앞에 나온 hostname 은 무시하고 **경고 줄**로 센다(처음 줄 사용). 8번째 칸부터 무시, CRLF 허용. 비교는 대소문자 구분.
- **조사 값**(원격 명령 하나, csh 안전, `PM_` 표식, 끝은 `echo PM_END`): OS커널 `uname -r` / appl `/etc/auto.appl` 의 `/appl` 줄 마운트 위치(`/wappl` 은 쓰지 않음) / dns `/etc/resolv.conf` nameserver **적힌 순서** / ldap_URI `/etc/openldap/ldap.conf` 의 첫 낱말이 정확히 `URI` 인 줄(소문자 `uri` 무시)의 값들을 파일 순서로, 스킴·포트·경로를 떼고 호스트 이름만(`URI ldap://server1/ ldap://server2/` → `server1 server2`) / binddn 첫 낱말이 정확히 `binddn` 인 줄의 나머지 / h/t `lscpu` threads per core ≥2 ON, 1 OFF, 모름 빈 칸 / ldap_check결과 `bash <ldap_check_sh>` 출력(한 줄이면 그대로·탭은 공백 하나, 여러 줄은 ` ; ` 로 이음, 미설정이면 `ldap_check_sh 미설정`). **`bindpw` 는 읽지 않는다**(ldap.conf 는 URI·binddn 패턴으로만 grep). 파일이 없으면 그 칸은 비운다. 옛 NTP·chrony·getent·autofs(wappl) 조사는 없앴다(NTP 는 DNS 와 같은 설정).
- **조사 대상**(사용자 추가 결정): `l` 재조사 대상은 **OS 모드(두 번째 칸이 yum 아님) 서버 전부(상태 무관)** + yum 서버의 yum_update/접속가능. **자동 첫 조사**(수집 회차 안, 상태 갱신 뒤): 현재 형식(Check.Ver=4) 결과가 없는 서버 중 OS 모드는 **ping 이 닿는 상태(확인전·ping X·완료후꺼짐 제외)**, yum 서버는 yum_update/접속가능. 회차마다 대수 제한 없이 대상 전부(제한은 gossh 가 건다), gossh 하나·nice 10 규칙 그대로. 실패한 서버는 결과가 비어 있으니 ping 이 닿는 동안 다음 회차에 다시 시도, 성공하면 자동으로 다시 조사하지 않는다. ping X 서버는 자동 재시도하지 않는다(`l` 로만).
- **`l` 키**: 대상 전체를 다시 조사하고 값을 갱신한다. 응답 없는 서버는 **이전 값을 그대로 두고**(비우지 않음) 비고에 `최근 조사 실패: 이유` 만 남긴다. 조사 중 안내 `LDAP·설정 점검중... (N대)`, 끝나면 `점검 완료 HH:MM:SS · 응답 N대 · 무응답 M대(이전 값 유지): 서버…`.
- **`l` 패널 표**: 열 `hostname | OS커널 | appl | dns | ldap_URI | binddn | h/t | ldap_check결과`, **호스트파일의 모든 서버를 호스트파일 순서**로. 조사 전 서버는 빈 칸(ldap_check결과 칸 `(조사 전)`). 설정 칸은 화면에서 24칸을 넘으면 `…` 로 줄인다(전체 값은 res·state.json). oklist 가 있으면 oklist 에 있고 조사 결과가 있는 서버의 다른 칸을 **빨간색**(조사값이 비었으면 `(없음)`), 머리에 `oklist N대 · 조사 M대 · 다름 K대 · 경고 W줄`(경고 0 이면 생략), 패널 안에서 `m` = oklist 와 다른 서버만 보기(다시 `m` 이면 해제, 패널을 다시 열면 꺼짐). oklist 가 없으면 색·집계·`m` 이 없다. 보이는 줄만 그린다(8000대).
- **설치/yumupdate여부**: `Record.InstallDone`(state.json `install_done`). 처음 설치완료(OS)·yum_update/접속가능(yum)을 보면 켜지고 ping X·완료후꺼짐·재부팅됨이 되어도 꺼지지 않는다. 모드(OS↔yum)가 바뀌어 기록을 새로 시작할 때만 꺼진다. state.json 형식 2(v0.4.0 은 1)이고, 1 을 읽을 때는 OS 서버 설치완료·완료후꺼짐·재부팅됨, yum 서버 yum_update/접속가능 또는 `yum_done_at` 있음이면 켠다(yum 의 재부팅됨만으로는 아님).
- **설정동일여부**: oklist 가 있고, 서버가 oklist 에 있고, 현재 형식 조사 결과가 있을 때만 `O`/`X`, 아니면 빈 칸. 6칸(OS커널·appl·dns·ldap_URI·binddn·h/t)이 모두 같아야 O(대소문자·순서 구분, 공백 다듬은 뒤 비교, 조사값이 빈데 oklist 칸이 있으면 다름). ldap_check결과는 비교하지 않는다. 마지막으로 성공한 조사값 기준이라 꺼짐·재부팅이 바꾸지 않는다.
- **res 파일** `<호스트파일 이름>.res`(state 파일과 같은 실행 폴더): 탭 구분 UTF-8·LF·BOM 없음, 머리줄 `hostname	OS커널	appl	dns	ldap_URI	binddn	h/t	설치/yumupdate여부	설정동일여부`, 모든 서버 호스트파일 순서(조사 전은 설정 칸 빈 칸, ldap_check결과 없음, 값 안의 탭·줄바꿈은 공백). 수집기(데몬·`-f`)가 시작할 때와 스냅샷을 낼 때마다(회차·조사 뒤) 내용이 바뀐 때만 같은 폴더 임시 파일 → 이름 바꾸기로 쓴다(0644). 쓰기 실패는 수집을 멈추지 않고 화면 오류 줄에 보이며 데몬 로그에는 한 번만 남긴다. `.gitignore` 에 `*.res`.
- **화면 프로토콜**: 스냅샷에 `HostOrder`(호스트파일 순서 인덱스)·`Cmp`(서버별 비교 비트: 비교함 0x80 + 다른 칸 6비트)·`Cfg`(집계)를 더했다. 같은 버전 안에서는 데몬·화면이 같은 구조다(버전이 바뀌면 지문으로 데몬 교체).
- oklist·res 가 없는 호스트파일의 `l` 이외 화면·코멘트는 v0.4.0 과 같다(기존 골든 그대로).

## 5. 성능 목표 (5천 대)

- 렌더는 화면에 보이는 줄만 만든다(가상 스크롤). 전체 정렬·집계는 수집 회차마다 한 번만 하고 스냅샷으로 넘긴다.
- 키를 누르면 바로 다시 그린다. 1초 tick 은 시계 표시용이고, 바뀐 것이 없으면 쓰지 않는다. 화면은 한 번의 write 로 출력한다.
- 목표: 5천 대 스냅샷에서 키 입력부터 화면 출력까지 50ms 미만(벤치마크 테스트로 확인), 메모리 50MB 미만.

### 5.1 관리서버 부하 제한

pm_monitor 는 여러 사람이 함께 쓰는 관리서버에서 돈다. 그래서 다른 작업에 영향을 주지 않는 것을 기능보다 먼저 지킨다.

- **회차 사이에는 쉰다**: 수집이 끝나면 다음 회차까지 아무것도 하지 않는다. 화면은 키 입력이나 새 스냅샷이 있을 때만 다시 그리고, 1초 tick 은 시계 글자만 바꾼다.
- **ICMP 송신 속도 제한**: 초당 `ping_pps`(기본 500)개를 넘지 않게 나눠 보낸다. 5천 대면 약 10초에 걸쳐 보낸다. 소켓은 하나만 쓴다.
- **TCP 동시 연결 제한**: 22번 포트 확인은 `tcp_parallel`(기본 100)개까지만 동시에 연다.
- **gossh 는 한 번에 하나**: 회차마다 대상이 있을 때만 gossh 를 최대 2번(-pm 확인, 디스크 확인) 차례로 실행한다. 대상이 없으면 실행하지 않는다. 병렬 수는 gossh 기본값을 따른다.
- **자식 프로세스 우선순위**: gossh·ssh 는 `nice -n 10` 으로 실행해 다른 사람 작업보다 뒤로 미룬다.
- **디스크 쓰기 최소화**: state.json 은 바뀐 것이 있을 때만, 회차 끝에 한 번 임시 파일에 쓴 뒤 이름을 바꿔 저장한다.
- **완료 서버 제외**: 완료 서버는 평소에 ping·ssh 를 하지 않으므로 설치가 진행될수록 부하가 줄어든다.
- **12시간 자동 종료**(v0.3.0): 백그라운드 수집은 시작 12시간 뒤 스스로 끝난다. 사람이 잊어도 공용 서버에 오래 남지 않는다.

## 7. 테스트 통과 기준

1. **기능**: 3~4장의 상태 7가지, 키 `c r d l / 숫자 q`, 코멘트 형식이 모두 구현되고 정상 동작한다. 스텁 gossh·ssh 로 각 상태를 만들어 확인한다.
2. **사용법**: `install_mn <호스트파일>` 하나로 실행된다. 인자가 없거나 파일이 없으면 사용법을 출력하고 종료 코드 2로 끝난다.
3. **TUI**: raw tty 진입·복구(정상 종료, Ctrl+C, 패닉 시), 창 크기 변경, 스크롤·검색·필터·토글이 동작한다. 골든 테스트를 통과한다.
4. **성능**: 5천 대 가짜 스냅샷에서 키 반응 50ms 미만(Go 벤치마크)이다. 랩에서 5천 대 가짜 상태로 10분간 돌려도 끊김이 없다(수동 확인과 지연 로그).
5. **관리서버 부하**: 랩에서 5천 대(127.x 주소로 실제 ICMP·TCP 수행, gossh 는 스텁)로 10분간 실행하면서 `test/load_check.sh` 가 1초마다 `/proc/<pid>` 를 기록한다. 다음을 모두 만족해야 한다.
   - pm_monitor 프로세스 CPU: 10분 평균 5% 미만(1코어 기준), 회차 중 최고값 30% 미만, 회차 사이 대기 중 1% 미만
   - RSS 50MB 미만, 열린 fd 200 미만, 스레드 수가 시간이 지나도 늘지 않음
   - ICMP 송신 속도가 `ping_pps` 를 넘지 않음, 22번 포트 동시 연결이 `tcp_parallel` 을 넘지 않음
   - 동시에 떠 있는 gossh 자식 프로세스는 최대 1개, nice 값 10
   - 측정 결과(평균·최고값)를 `test/load_report.txt` 로 남긴다
6. `go vet`, `go test ./...` 가 통과하고 os8 바이너리가 빌드된다.
7. **8000대 (v0.2.0)**: `demo/demo.sh -n 8000` 으로 8000대 데모가 뜨고, 스크롤·검색·필터·`c r d l` 패널이 끊김 없이 동작하며 표와 코멘트가 읽기 쉽다(긴 호스트 목록 줄바꿈 포함). 부하 측정도 8000대로 다시 해서 5번 기준을 통과한다(`test/load_report.txt` 갱신).

8. **백그라운드 수집 (v0.3.0)**: 랩에서 실제 프로세스·가상 터미널로 `test/daemon_check.py` 가 다음을 모두 확인한다 — q·SIGHUP·Ctrl+C 로 화면만 닫아도 데몬 생존, 다시 실행하면 같은 데몬에 이어 붙음(회차 이어짐), 화면 둘 동시, 데몬은 세션 리더이고 tty 없음, `Q`+`n` 취소·`Q`+`y` 수집 종료(상태 파일 유지), `--stop`·`--status`, 호스트파일 변경 시 재시작, 강제 종료로 소켓이 남아도 재시작, `PM_MAX_RUN_SEC` 로 줄인 시간이 지나면 데몬 종료·화면 닫힘·소켓 정리, 기본 만료는 시작 + 12시간, tty 가 아니면 데몬을 만들지 않음.

9. **yum update 모드 (v0.4.0)**: 랩에서 스텁 gossh·실제 ping(127.x)으로 다음을 모두 확인한다 — 호스트파일 두 번째 칸이 `yum`(대소문자·공백·탭 무시)인 서버만 yum 모드이고 그 밖의 값·없음은 OS 설치로 동작, 기준 커널은 첫 접속 때 한 번만 기록되고 다시 실행해도 유지, 접속가능→(ping X)→재부팅됨→커널 변경 시 yum_update/접속가능, 재부팅했으나 커널 동일이면 재부팅됨에 머묾, 회차 사이에 빨리 재부팅(부팅 시각만 변화)도 재부팅됨, yum 지연(기본 60분)이 `r`·`c`·`y` 에만 나오고 상태 이름은 그대로, yum 서버는 설치완료 수·`재부팅됨 N대` 목록·`d` 에 들어가지 않고 `l` 에는 yum_update/접속가능만 들어감, yum 이 없는 호스트파일의 출력은 v0.3.0 과 같음, 새 상태가 폭 60/80/120 화면과 필터 8·9 에서 깨지지 않음, 바이너리 교체 후 다시 실행하면 옛 데몬이 새 데몬으로 교체됨.

10. **서버 설정·oklist·res (v0.5.0)**: 단위 테스트(oklist 머리줄·주석·칸 부족·중복·CRLF·8번째 칸·공백 다듬기, 순서·대소문자 구분 비교, URI 여러 줄·ldaps·포트·끝 `/`·소문자 uri 무시, binddn 대소문자·명령에 bindpw 없음, dns 순서 유지, InstallDone 이 ping X·완료후꺼짐·재부팅됨·재시작에 유지되고 모드 변경 때만 꺼짐·v0.4.0 state 이행·yum 재부팅됨은 미완료, 자동 첫 조사·실패 재시도·성공 뒤 재조사 안 함·회차당 100대, 설치중·ping X OS 서버가 `l` 대상이고 ping X 는 자동 조사 안 함, `l` 실패 시 이전 값 유지, res 내용·원자적 쓰기·같으면 안 씀, `l` 골든 60/80/120(oklist 없음·있음·`m`), oklist 내용이 바뀌면 지문 변경, 인자 해석)와 랩 실제 프로세스(`daemon_check.py` 12번대: res 생성·자동 첫 조사·완료 뒤 꺼져도 O·oklist O/X·oklist 교체·없는 oklist 오류, `demo_yum_check.py` 의 oklist·res 확인)가 모두 통과한다.

## 8. 가정·한계

- 완료 서버는 `c` 를 누를 때만 ping 하므로, 두 번 누르는 사이에 꺼졌다 켜진 서버는 재부팅됨으로 잡히지 않는다(사용자 결정).
- gossh 로그인 계정과 키는 기존 gossh 설정을 그대로 쓴다. pm_monitor 는 비밀번호를 다루지 않는다.
- DHCP 서버의 `/root/a.sh` 와 ldap_check.sh 는 이미 현장에 있다고 가정한다.
- (v0.5.0) ldap_check 의 stderr 는 원격 명령에서 `2>` 를 쓸 수 없어(csh) 결과에 넣지 않는다(stdout 만). 원격 출력은 실제 gossh 가 호스트별 줄 순서를 지킨다고 가정한다(랩 스텁으로만 검증, 실장비 미확인).
- 데몬은 root 전용이며 같은 서버의 다른 root 사용자도 같은 호스트파일·폴더면 같은 수집에 붙고 `--stop` 할 수 있다. 서버를 재부팅하면 수집은 사라지고 상태 파일만 남는다.
- yum 모드는 **`yum update` 를 돌리는 일 자체는 하지 않는다**. 사람이 따로 실행하고, pm_monitor 는 커널·재부팅만 지켜본다. 기준 커널은 pm_monitor 를 처음 실행해 ssh 가 성공한 때의 커널이므로, 이미 `yum update`·재부팅을 끝낸 뒤에 시작하면 변화가 없어 `접속가능` 에 머문다(yum 지연으로 올라옴).
- yum update 로 새 커널이 설치돼도 기본 부팅 커널이 옛것이면 커널 동일로 보인다(재부팅됨에 머물고 코멘트에 표시).
- 랩에는 실제 anaconda 설치 서버가 없으므로 설치중·디스크미인식은 스텁 gossh 로 검증한다. 실장비 검증은 현장에서 한다.
