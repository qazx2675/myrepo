# stress-test 템플릿 실행 방식 변경 계획서

2026-11-06 인터뷰 확정. 대상: `.claude/HPC/stress-test`(단독 실행 유지) + `.claude/HPC/setup_check`(`new_setup -run` 연동).

## 바뀌는 사실 (사용자 확인)
1. CPU 테스트 템플릿 안에서 Intel/AMD 를 이미 구분한다 → **CPU 템플릿은 하나**. Intel/AMD 로 yaml·템플릿을 나누지 않는다.
2. 템플릿 실행 절차: 템플릿 편집 → 인벤토리를 **DEFAULT → conf 의 `username`(AWX 로그인 계정과 같은 이름의 인벤토리)** 으로 변경 → 실행 → 인벤토리를 **다시 DEFAULT** 로.
3. stress-ng 템플릿은 실행할 때 survey `end_year`, `end_month`, `end_day`, `end_hour`, `end_min` 5개 값을 넣어야 한다.
4. 각 항목의 key(survey 변수명 등)를 조사하는 기능이 필요하다 → `stress-test -inspect`.

## 결정 사항
### 설정 키 (stress-test conf)
- 없앰: `cpu_intel_template`, `cpu_intel_hostname_key`, `cpu_intel_extra_vars`, `cpu_amd_*`. 이 키가 conf 에 있으면 설정 오류(종료코드 2)로 "cpu_template 하나로 바뀌었습니다" 안내.
- 새로: `cpu_template`, `cpu_hostname_key`, `cpu_extra_vars`.
- `cpu_hostname_key`, `stress_hostname_key` 는 **선택**: 비우면 hostname 목록을 넘기지 않는다(인벤토리 전체 대상).
- 새로: `default_inventory = DEFAULT` (평소 템플릿 인벤토리 이름), `stress_end_keys = end_year,end_month,end_day,end_hour,end_min` (순서대로 5개).
- 바꿀 인벤토리 이름 = conf 의 `username`. 그 이름의 인벤토리가 없으면 오류.

### 템플릿 인벤토리 바꾸기·되돌리기
- 순서(묶음마다): 등록(yaml→custom_inventory→invsync, 기존과 같음) → 템플릿 조회 → **현재 인벤토리 이름이 `default_inventory` 인지 확인**
  - 아니면 "사용 중": `템플릿 <이름>(<id>) 인벤토리가 <현재 이름> 입니다(DEFAULT 아님) — 그 인벤토리 사용자에게 DEFAULT 로 바꿔 달라고 요청하세요` 출력 후 멈춤.
    - 대화형: `r=다시 확인, x=이 묶음 중단` 질문. r 이면 다시 확인(등록은 다시 하지 않음), x 이면 묶음 실패(비고 "템플릿 인벤토리 사용 중").
    - `-batch`: stdout 에 `[인벤토리사용중] <위 메시지>` 한 줄을 찍고 stdin 에서 한 줄을 읽는다. `r` → 다시 확인, 그 밖·EOF → 중단(x). (setup_check -run 이 이 줄을 보고 TUI 질문으로 바꿔 답을 stdin 으로 넣는다.)
  - DEFAULT 면: PATCH `/api/v2/job_templates/<id>/ {"inventory": <username 인벤토리 id>}` → 다시 GET 해서 username 인지 확인(다른 사람과 경합 감지) → launch → **곧바로 PATCH 로 DEFAULT 인벤토리 id 로 되돌림**(AWX 는 job 생성 때 인벤토리를 고정하므로 launch 응답 뒤 바로 되돌려도 실행엔 영향 없음). launch 가 실패해도 되돌린다.
  - 되돌리기 실패: 크게 경고(✗) + 이력 기록 + 결과 비고 "인벤토리 복원 실패 — 수동으로 DEFAULT 로". 
  - 바꾼 뒤 되돌리기 전 SIGINT/SIGTERM 을 받으면 되돌린 뒤 종료(setup_check 의 시간 초과 종료는 SIGTERM → 5초 뒤 SIGKILL).
- 실행 전 사전 확인: 단계 시작 전에 필요한 템플릿·인벤토리(username, DEFAULT)가 있는지만 확인(없으면 종료코드 2). 사용 중 여부는 launch 직전에만 본다.

### stress-ng 종료 시각 (5개 값)
- 대화형: `-steps` 에 b 가 있으면 **시작할 때** 키 하나씩 묻는다 (`end_year: ` → `end_month: ` …, 기본 제안 없음). 숫자만, 범위: 연 4자리(올해 이상), 월 1-12, 일 1-31, 시 0-23, 분 0-59, 합친 시각이 지금보다 뒤여야 함(아니면 다시 물음). 입력한 글자 그대로 쓴다.
- `-batch`: `-end <연>,<월>,<일>,<시>,<분>` 필수(b 가 있을 때). 없거나 잘못되면 종료코드 2.
- launch 때 survey_spec 을 조회해 그 변수의 type 이 integer/float 이면 숫자로, 아니면 입력 문자열 그대로 extra_vars 에 넣는다.
- 재실행 회차에서 종료 시각이 이미 지났으면: 대화형은 다시 묻고, batch 는 그 묶음을 실패("종료 시각이 지남").

### CPU 단계
- 접속체크(vendor_id)는 그대로(접속 여부·결과표 벤더 열). CPU 대상은 접속된 모든 호스트(unknown 벤더도 포함), 묶음 하나(`${user}_cpu.yaml`, 재실행은 `${user}_retryN_cpu.yaml`).

### stress-test -inspect (읽기 전용)
- `stress-test -inspect [-user <u> | -conf <파일>] [템플릿 ID/이름 ...]` — 인자 없으면 conf 의 cpu_template·stress_template.
- 출력: 템플릿 id/이름, 현재 인벤토리(이름/id, DEFAULT 여부), survey 사용 여부와 변수 표(variable, 질문, type, required, default, choices, min/max), conf 키 점검(`*_hostname_key`, `stress_end_keys` 가 survey 에 있는지), 인벤토리 목록(id/이름, DEFAULT·username 표시), `inventory` 의 소스 목록, conf 에 넣을 줄 예시.
- 종료코드 0 정상 / 1 점검 항목 불일치 / 2 설정·접속 오류.

### setup_check (`new_setup -run`) 연동
- 질문에 **입력 칸** 종류 추가: `question.inputs[]`(키 이름), answer.json 에 `values{키:값}`. TUI 에서 질문에 입력 칸이 있으면 키마다 차례로 숫자를 입력(Enter 다음, Backspace, Esc 취소). 검증은 stress-test 와 같은 범위.
- 부하 단계(새로 시작할 때)에 stress-ng 대상이 있으면, CPU launch 전에 5개 값을 묻는다. stress-ng 단계(4)도 실행 전에 묻는다. 값은 `stress-test -end` 로 넘긴다. 키 이름은 setup_check 에서는 고정 표시(end_year…), 실제 survey 키는 stress-test conf 가 정한다.
- stress-test stdout 에 `[인벤토리사용중]` 줄이 오면 단계 중간 질문(r=다시 확인 / x=이 묶음 중단)을 내고 답을 stress-test stdin 으로 쓴다. 답을 기다리는 동안 STRESS_TIMEOUT 은 멈춘다(답 뒤 다시 처음부터). 중지 요청이면 x. 동시에 두 질문(CPU·stress-ng)이 나오면 차례로 묻는다.
- fake_stress_test.sh 를 새 프로토콜에 맞추고 흐름 테스트 추가.

## 단계
1. stress-test 본체: 설정 키, CPU 단일 템플릿, 인벤토리 바꾸기·되돌리기·사용 중 질문(대화형/stdin), 신호 시 복원, 종료 시각 5값(대화형/-end/type 변환), hostname_key 선택, fake_awx 확장, 단위·e2e 테스트, setup.sh·README·ARCHITECTURE·sample conf·PR_CHECKLIST.
2. stress-test -inspect: 하위 명령·fake_awx survey/인벤토리 응답·테스트·README.
3. setup_check 연동: 입력 질문·TUI 입력·-end 전달·인벤토리 사용 중 단계 중간 질문·시간 제한 일시정지·테스트·문서.
