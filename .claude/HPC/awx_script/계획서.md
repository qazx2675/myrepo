## 5. 단계별 구현 설계

### 5-1. 최상단
```bash
#!/bin/bash
# AWX nodeinfo V2 - HPC 서버 등록 전처리 및 인벤토리/DHCP/PXE 등록
repohost=""
svr_dir=""                   # custom_inventory.sh 가 yml 을 쓰는 경로(로컬에서 보이는 공유 경로)
ai_server_list=""            # 예: "host01|host02"  (호스트명 정확 일치)
ldap_check_script=""
lacp_comment=""
inventory_delete_host=""     # 원문은 함수 안 → 최상단으로 이동
svr_idr="$svr_dir"           # git 블록 원문($svr_idr 오타)을 그대로 쓰기 위한 별칭
```
- 각 변수는 사용하는 단계 시작 시 비어 있으면 `[X] <변수> 가 비어 있습니다` 출력 후 종료.

### 5-2. user / 로그
```bash
user(){
}
```
- **본문은 비워 둔다**(사용자가 기존 코드를 붙여 넣음). bash 는 빈 `{}` 를 문법 오류로 보므로 개발 중에는 주석 한 줄 + `:` 를 넣고, 납품본 주석에 "현장 코드로 교체" 명시.
- 호출 후 `[[ -z $user ]] && { echo "[X] user 값이 없습니다 (user 함수 확인)"; exit 1; }` — 입력 프롬프트는 두지 않음.
- 로그: `mkdir -p LOG; exec > >(tee -a "LOG/${user}.log") 2>&1`, `log(){ echo "[$(date '+%F %T')] $*"; }`, 시작/종료/각 단계 로그.

### 5-3. download_txt (원문 + 보정 2건)
```bash
download_txt(){
read -p " awx nodeinfo 사용여부 Y|N : " awx_yn
	if [[ $awx_yn == [Yy] ]]; then
		bash awxkit/nodeinfo.sh -user ${user} -hosts "${start_pwd}/${user}.txt"
		cat awxkit/output/${user}_nodeinfo.yaml > ${user}.txt
	fi

	sed -i 's/1.1T/1200/g' ${user}.txt
	sed -i 's/7T/7600/g' ${user}.txt
	sed -i 's/test1234/offchip/g' ${user}.txt
}
```
- `start_pwd` = 스크립트 시작 시 `pwd` (git 블록의 `now_pwd` 는 원문 위치에서 그대로 정의).
- 파일명 `_nodinfo` → **`_nodeinfo`** (실제 저장명). sed 3줄은 원문 유지.
- nodeinfo 실패(종료코드≠0) 시 `${user}.txt` 를 덮어쓰지 않고 종료 — 입력 호스트 목록 보호.

### 5-4. msg 파싱
```bash
if grep -q 'msg' "${user}.txt"; then
	sed -i -n 's/^.*"msg"[[:space:]]*:[[:space:]]*"\([^"]*\)".*$/\1/p' "${user}.txt"
fi
# 검증: 모든 줄이 12필드인지. 아니면(호스트명만 등) 안내 후 종료
awk 'NF != 12 { bad=1; print "[X] 12필드 아님: " NR ": " $0 } END { exit bad }' "${user}.txt" || exit 1
```
- 원문 `cat … | grep msg | awk … > ${user}.txt` 는 읽기 전에 파일을 비워 빈 파일이 되는 버그 → 위 방식으로 대체(결과 동일, 임시파일 없음).

### 5-5. MAC 짝수 보정 (검증 완료)
```bash
content=$(awk '
($4 ~ /^(spice|pice|dspr|pspr)/) && ($4 !~ /ev/) {
	c = substr($6, length($6), 1); i = index("13579bdfBDF", c)
	if (i) $6 = substr($6, 1, length($6)-1) substr("02468aceACE", i, 1)
}
{ print }' "${user}.txt") && printf '%s\n' "$content" > "${user}.txt"
```
- 샘플 검증: `spice01 …:01→…:00`, `dspr05 …:FF→…:FE`, `pspr02 …:0b→…:0a`, `spice01ev02`·`node01` 불변.

### 5-6. 등록 대상 다단 출력 (검증 완료)
```bash
awk '{print $4}' "${user}.txt" | awk '
{ a[NR]=$0; if (length($0)>w) w=length($0) }
END{
	rows = (NR<20 ? NR : 20); cols = int((NR+19)/20)
	for (r=1; r<=rows; r++) {
		line = ""
		for (c=0; c<cols; c++) { i = c*20 + r; if (i<=NR) line = line sprintf("%-" w "s ", a[i]) }
		sub(/ +$/, "", line); print line
	}
	print "총 " NR "대"
}'
```
- 번호 없이 호스트명만, 하단 총 대수. 45대 샘플로 1행 `host01 host21 host41` 확인.

### 5-7. inventory_delete (작업진행 Y 이후)
```bash
inventory_delete(){
	ssh $inventory_delete_host "bash /root/server/delhost_${user}"
}
```
- `inventory_delete_host=""` 는 최상단으로 이동, 원문의 닫는 `"` 누락 보정.

### 5-8. 분할 파일 + 전체 파일 (검증 완료)
- **분할 키(확정)**: `infra($3) + nic($7) + disk($8) + 용량($10) + os($11) + boot($12) + splunk`
  - part($9)는 키에서 제외
  - splunk(호스트명 기준): **ev 포함 → `no`** > **s 로 시작 → `Cloud`** > 그 외 **`On-premise`** (ev 규칙 우선)
  - boot: `레거시` → `legacy`, 그 외 그대로
- 내용: 가공된 12필드 줄을 그룹별로 그대로 담음(yml 변환은 custom_inventory.sh 담당). 전체 파일 = 모든 줄.
- 파일은 `mktemp -d` 안에 생성하고 scp 후 삭제(로컬 잔여 없음).
```bash
splitdir=$(mktemp -d)        # trap 에 rm -rf 등록
awk -v d="$splitdir" -v u="$user" '
function splunk(h) { if (h ~ /ev/) return "no"; if (h ~ /^s/) return "Cloud"; return "On-premise" }
{
	b = ($12 == "레거시") ? "legacy" : $12
	key = $3 "|" $7 "|" $8 "|" $10 "|" $11 "|" b "|" splunk($4)
	if (!(key in n)) { n[key] = ++g; print n[key] "|" key > (d "/groups") }
	print > (d "/" u "_" n[key] ".yaml")
}' "${user}.txt"
cp "${user}.txt" "$splitdir/${user}_all.yaml"
```
- `groups` 파일(`번호|infra|nic|disk|용량|os|boot|splunk`)도 `splitdir` 안에만 존재 → 아래에서 연관배열로 읽어 들임.

### 5-9. DHCP 삭제 정보
```bash
mkdir -p dhcp_pool
awk '{print "tmp tmp SEC", $4, $5, $6, "eth0 sda sda5 960 7.9"}' "${user}.txt" >> dhcp_pool/dhcp_pool_delete_info.txt
```
- 뒤 5개는 **고정값**, 누적(`>>`).

### 5-10. scp → custom_inventory.sh → yml 수집
- custom_inventory.sh 가 `${user}.txt` 형식 입력을 받아 **svr_dir 에 `<infra>_inventory-<시각(초)>_<N>ea.yml`** 을 생성(이름은 custom_inventory 가 결정).
- 01 은 파일별로: 실행 전 `svr_dir` 의 yml 목록 저장 → ssh 실행 → 실행 후 목록과 비교해 **새로 생긴 yml 1개**를 수집.
  - 새 파일이 0개/2개 이상이면 오류로 중단.
  - 이름의 `<N>ea` 가 입력 줄 수와 다르면 경고.
  - 이름에 초 단위 시각이 들어가므로 **같은 infra·같은 대수 그룹이 같은 초에 생성되면 덮어쓸 위험** → 실행 사이에 `sleep 1`.
```bash
declare -A yml_opt            # yml 파일명 → "infra os boot splunk"
declare -A yml_boot           # yml 파일명 → boot (ls 표시용)
yaml=""; group_yml=""
scp "$splitdir"/*.yaml "$repohost:/root/Inventory/" || exit 1
for i in 각 분할 파일(번호순) + ${user}_all.yaml; do
	before=$(ls "$svr_dir"/*.yml 2>/dev/null)
	ssh "$repohost" "bash /root/Inventory/custom_inventory.sh /root/Inventory/$i" || exit 1
	new=$(comm -13 <(printf '%s\n' "$before") <(ls "$svr_dir"/*.yml 2>/dev/null))
	(새 파일 1개 검증) → yaml 에 파일명 추가, 분할 파일이면 group_yml 에도 추가 + yml_opt/yml_boot 기록
	sleep 1
done
rm -rf "$splitdir"            # 로컬 분할 파일 삭제 (trap 에도 등록)
```
- 원격 `/root/Inventory/` 에 남는 입력 파일은 로컬 제약(C1) 대상 아님. 파일명은 `${user}_<번호>.yaml` / `${user}_all.yaml`.

### 5-11. git 업로드
- 원문 블록을 **그대로** 삽입(`$yaml` = 생성된 yml 전체, 전체 파일 포함).
- 블록 바로 뒤에 `cd "$now_pwd"` 한 줄 추가(원문은 저장만 하고 복귀하지 않아 이후 상대경로가 깨짐).

### 5-12. AI / LDAP / LACP 점검
```bash

if [[ -n $ai_server_list ]] && grep -Eqx "($ai_server_list)" "$hostfile"; then
	echo "AI GPU서버는 power limit설정이 필요합니다. cat .power_limit_setting.txt를 참고하세요."
	cat .power_limit_setting.txt
fi
mkdir -p tmp
gossh -script -w "$hostfile" "bash $ldap_check_script;cat /proc/net/bonding/bond0 |grep -i mod" > "tmp/all_${user}"
lacp_hosts=$(grep -i 'Bonding Mode' "tmp/all_${user}" | grep -i '802.3ad' | cut -d: -f1 | sort -u)
[[ -n $lacp_hosts ]] && { echo "$lacp_hosts" | paste -sd' '; echo "$lacp_comment"; }
ldap_vals=$(grep -vi 'Bonding Mode' "tmp/all_${user}" | sed 's/^[^:]*: //' | sort -u)
if [[ $(printf '%s\n' "$ldap_vals" | grep -c .) -eq 1 ]]; then
	echo "모든 호스트의 LDAP이 ${ldap_vals}으로 동일함"
else
	grep -vi 'Bonding Mode' "tmp/all_${user}" | sort -t: -k2      # 값별로 호스트 나열
fi
# 응답 없는 호스트: hostfile 과 결과 호스트 목록 comm 비교 후 "응답 없음" 출력
```
- `ai_server_list` 는 호스트명 **정확 일치**. `tmp/all_${user}` 는 보존.

### 5-14. 02 호출 (01 쪽)
```bash
for ((;;)); do

	args=(); for f in $group_yml; do args+=("$f=${yml_opt[$f]// /,}"); done   # yml=infra,os,boot,splunk
```

### 5-15. 02.source_dhcp_pxe.sh 변경
```bash
user=$1; shift
if [[ -z $user ]]; then
	read -p ".txt를 제외한 user 입력 : " user
fi
# 인자: <yml>=<infra>,<os>,<boot>,<splunk> ...
# 인자가 없으면 기존 방식(대화형 1개)으로 동작 — 단독 실행 호환
```
1. **옵션 확인표를 최초 1회 출력**: `번호 | yml | infra | os | boot | splunk | 호스트 수`
2. `옵션이 맞습니까 (Y|N)` → N 이면 yml 별로 각 값을 다시 입력(Enter = 현재값 유지)
3. yml 별 순차 실행
   ```bash
   bash awxkit/invsync.sh -user ${user} -file $yml
   bash awxkit/dhcp.sh    -user ${user} -infra $infra
   bash awxkit/pxe.sh     -user ${user} -infra $infra -os $os -boot $boot -splunk $splunk
   ```
   - 한 단계 실패 시 해당 yml 의 나머지 단계는 건너뛰고 다음 yml 진행, 끝에 성공/실패 요약, 실패가 있으면 `exit 1`.
- infra/os 는 nodeinfo 값 그대로 전달. AWX conf 의 `*_choices` 와 다르면 awxkit 이 오류를 내므로 → 확인표 단계에서 수동 수정.

## 8. 결정 사항 (§3 원문보다 우선)

1. `user(){}` 는 빈 함수 유지, `$user` 가 비면 오류 종료(프롬프트 없음)
2. nodeinfo: `-hosts "<시작경로>/${user}.txt"` 추가, 결과 `awxkit/output/${user}_nodeinfo.yaml`, 실패 시 `${user}.txt` 보호
3. 입력: msg 있으면 파싱, 없으면 12필드 검증(아니면 종료)
4. MAC 보정: 접두어 `spice|pice|dspr|pspr` + `ev` 미포함
5. inventory_delete: 작업진행 Y 이후, 변수는 최상단
6. 분할 키: `infra+nic+disk+용량+os+boot+splunk` (part 제외), splunk = ev→no > s 시작→Cloud > On-premise, boot 레거시→legacy
7. 분할/전체 입력 파일은 mktemp 디렉터리에서 만들고 scp 후 삭제
8. yml 은 custom_inventory.sh 가 svr_dir(공유 경로)에 생성, 01 은 전후 비교로 이름 수집, 실행 사이 `sleep 1`
9. dhcp 기록: `tmp tmp SEC $4 $5 $6 eth0 sda sda5 960 7.9` (뒤 5개 고정), 누적
10. git 블록 원문 + `svr_idr` 별칭 + 블록 뒤 `cd "$now_pwd"`
11. 보존: `tmp/all_${user}`, `awxkit/output/${user}_nodeinfo.yaml`
12. 02: `<yml>=<infra>,<os>,<boot>,<splunk>` 인자로 그룹 yml 만 전달, 옵션 확인표 1회 + 수동 수정, yml 별 invsync→dhcp→pxe, 실패 요약 후 exit 1, 01 은 실패 시 재시도 질문
13. 모델 실행: 로컬 `jev-plan-router`, 클라우드는 Agent model 지정
