# 로컬 세션용 지침 — 사설 IP 서비스를 클라우드 세션에서 접근 가능하게 만들기

> 이 문서는 **로컬 Windows PC에서 실행하는 Claude Code 세션**(또는 사람)이 그대로 따라 하도록 작성했습니다.
> 스크립트: 같은 폴더의 `Start-LocalTunnel.ps1`

## 목표

클라우드 세션(원격 컨테이너)은 `192.168.0.58`, `192.168.0.50`, `192.168.0.60` 같은 사설 IP에 직접 갈 수 없습니다.
로컬 PC에서 터널을 열어 각 서비스에 **공인 HTTPS 주소**를 발급받고, 그 주소를 클라우드 세션에 전달합니다.

```
[클라우드 세션] --HTTPS--> https://xxxx.trycloudflare.com --> [로컬 PC의 cloudflared] --> 192.168.0.5x:포트
```

터널을 실행하는 PC 한 대가 세 IP에 모두 접근할 수 있으면, 그 PC 한 대에서만 실행하면 됩니다.

## 제약 (먼저 확인)

- **HTTP/HTTPS 서비스만** 지원합니다 (웹 UI, REST API 등). SSH·RDP·DB 같은 TCP 서비스는 이 스크립트 범위가 아닙니다.
- Cloudflare Quick Tunnel 주소는 **실행할 때마다 바뀝니다**. 재시작하면 새 주소를 다시 전달해야 합니다.
- 발급된 주소는 **인증 없이 인터넷 누구나 접근 가능**합니다. 로그인 없는 관리 화면은 노출하지 말고, 작업이 끝나면 즉시 중지하세요.
- PC가 절전/종료되면 터널도 끊깁니다.

## 로컬 세션이 할 일

### 1. 대상 포트 확인

사용자에게 각 IP에서 어떤 서비스(포트)를 열어야 하는지 묻습니다. 모르면 흔한 포트를 점검해 봅니다.

```powershell
foreach ($ip in '192.168.0.58','192.168.0.50','192.168.0.60') {
  foreach ($port in 80,443,8080,8443,3000,5000,8000,9090) {
    if (Test-NetConnection $ip -Port $port -InformationLevel Quiet -WarningAction SilentlyContinue) { "$ip`:$port OPEN" }
  }
}
```

열린 포트가 있어도 실제 HTTP 서비스인지는 `Invoke-WebRequest http://IP:포트 -UseBasicParsing` 로 확인하세요.

### 2. 스크립트 실행 (Cloudflare, 계정 불필요 — 기본)

```powershell
cd <이 폴더 경로>
powershell -ExecutionPolicy Bypass -File .\Start-LocalTunnel.ps1 -Target 192.168.0.58:80, 192.168.0.50:8080, https://192.168.0.60:443
```

- `IP:포트` 형식이면 HTTP, `https://IP:포트` 형식이면 HTTPS(자체서명 인증서 허용)로 연결합니다.
- `cloudflared.exe`가 없으면 `tunnel-work\bin\`에 자동으로 받습니다.
- 이 PC에서 접속되지 않는 대상은 점검 단계에서 자동으로 제외됩니다.

### 2-1. ngrok을 쓰는 경우 (선택)

ngrok 무료 계정의 authtoken이 필요합니다 (https://dashboard.ngrok.com 에서 확인).

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-LocalTunnel.ps1 -Provider ngrok -NgrokAuthToken <토큰> -Target 192.168.0.58:80
```

- 무료 플랜은 동시 엔드포인트 수 제한이 있어 대상 3개가 모두 열리지 않을 수 있습니다.
- 브라우저로 접속하면 ngrok 경고 페이지가 먼저 뜹니다. `curl`은 헤더 `ngrok-skip-browser-warning: 1`을 붙이면 됩니다.

### 3. 결과를 클라우드 세션에 전달

실행이 끝나면 `tunnel-work\tunnels.txt`가 생깁니다.

```
192.168.0.58:80 -> https://aaaa-bbbb.trycloudflare.com
192.168.0.50:8080 -> https://cccc-dddd.trycloudflare.com
```

이 내용을 **그대로 클라우드 세션에 붙여넣어** 달라고 사용자에게 안내합니다.
클라우드 세션은 `curl https://...trycloudflare.com` 으로 도달 여부를 확인합니다.

### 4. 상태 확인 / 중지

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-LocalTunnel.ps1 -Status
powershell -ExecutionPolicy Bypass -File .\Start-LocalTunnel.ps1 -Stop
```

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `[점검] ... 연결 불가 - 제외` | 이 PC에서 대상 IP/포트로 접속되는지, 대상 PC의 Windows 방화벽 인바운드 규칙 |
| `주소 발급 실패` | `tunnel-work\logs\cloudflared_N.log` 확인. 회사망이면 아웃바운드 443/7844 차단 여부 |
| 다운로드 실패 | 프록시/백신 차단. `cloudflared.exe`를 수동으로 받아 `tunnel-work\bin\`에 두면 됨 |
| `이미 실행 중인 터널 기록이 있습니다` | `-Stop` 먼저 실행 |
| 스크립트 실행 차단 | `Unblock-File .\Start-LocalTunnel.ps1` 후 재실행 |

## 완료 기준

- [ ] `tunnels.txt`에 대상별 `https://...` 주소가 있다
- [ ] 클라우드 세션에서 해당 주소로 `curl` 시 서비스 응답(HTTP 200/302/401 등)을 받는다
- [ ] 작업 종료 후 `-Stop`으로 터널을 중지했다
