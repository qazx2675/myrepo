# VM_setup 태그 설정 단계 추가 계획서 (확정)

## 목표 및 범위
- `vm_setup.sh`에 태그 설정 단계를 추가한다. 위치는 **라이선스 할당 다음, 스펙 체크 앞**.
- 값은 `SPEC_DIR/<폴더>/<폴더>_spec.txt` 의 `tag-*` 줄에서 가져온다.
- 태그 = vCenter 사용자 지정 특성 3개: `DEPT_NAME`, `PURPOSE`, `VM_TYPE` (`tag_setting` 기준. vSphere Tag(카테고리)는 대상 아님).
- 스펙에 태그가 들어가도 **스펙 체크(vm-param-check)에는 영향이 없어야 한다**(태그는 체크하지 않음).
- 제외: 문서/SVG 갱신 — 모든 작업이 끝나고 사용자가 요청할 때 진행.

## 결정 사항
- 스펙 입력 형식은 **B안(태그당 한 줄 + 기본값/범위 예외)** 으로 확정.

```
tag-DEPT_NAME=영업팀                      # 값만 쓰면 모든 ev 에 적용
tag-PURPOSE=ev01:DB, ev02-ev03:WAS        # evNN:값 또는 evNN-evMM:값 (콤마로 나열)
tag-VM_TYPE=ev01-ev03:가상서버, ev04:테스트   # 뒤에 쓴 항목이 앞 항목을 덮어씀
```
- 태그 3개는 줄이 따로라 서로 다른 값을 줄 수 있고, 같은 값은 범위로 묶는다.
- ev 개수를 넘는 번호는 오류. 줄을 안 쓴 태그는 건드리지 않는다. 값에 공백·콤마·`:` 는 쓰지 않는다(공백은 `_`).
- (사용자 확인 전 기본값으로 채택) vCenter 에 특성이 없어 설정이 실패하면 경고하고 계속 진행한다 — VM 은 이미 만들어졌으므로.
- (같은 기본값) `tag_setting` 은 비어 있는 태그는 건너뛰도록 보완한다.
- `tag_setting` 의 ev 상한: 소스(V2)는 이미 `-vmCount` 1~99 를 받는다. 값 목록은 ev 개수만큼 필요할 뿐 ev03 제한은 없다. 구 `VM/VM_setup` 판은 상한 검사가 없는 대신 같은 구조. 확장 작업은 "99개까지 값 목록을 만들어 넘기는 쪽(vm_setup.sh)" 과 99 검증에 해당한다.

## 구현 단계
1. **스펙 해석(vm-param-check)**: `-specExport` 가 `tag-*` 줄을 읽어 ev 별로 펼친다(범위 확장·문법/범위 초과 검증). 체크 쪽은 `tag-*` 를 읽되 아무것도 검사하지 않는다(`specSettableFlags` 검사 앞에서 걸러냄).
2. **vm_setup.sh**: `build_flags` 가 `TAG_ARGS`(`-deptNames/-purposes/-vmTypes`)를 만들고, `step_tag <k>` 를 스펙별로 추가(대상 `vmbase_<k>.txt`, `-vmCount`=ev 개수). 실행 계획·모니터 요약에 반영. 태그가 없는 스펙은 건너뜀.
3. **스펙 입력 편의**: vim 템플릿과 `spec_key_list` 에 `tag-*` 안내 주석 추가.
4. **tag_setting 보완**: 비어 있는 태그 건너뛰기, 일부 실패 시 종료코드 반영, ev99 검증. OS6 재빌드.

## 검증 기준
- 태그가 있는 스펙/없는 스펙으로 같은 VM 을 체크했을 때 결과가 완전히 같다(단위 테스트 + CSV 비교).
- vcsim 전체 실행: 종료코드 0, 재실행 시 이미 설정된 값은 통과, ev99 범위 지정 동작.

## 리스크
- vCenter 에 사용자 지정 특성이 미리 정의돼 있어야 함(없으면 실패 → 경고 후 계속).
- 값의 콤마·공백 제약(스펙 파서가 공백으로 토큰을 나눔).
- 구 `VM/VM_setup` 쪽 `tag_setting` 은 이번 범위에서 수정하지 않음(V2 기준).
