# gossh

`pdsh` 스타일로 다수 서버에 동시에 SSH 명령을 실행하고 호스트별 결과를 `호스트명: 출력줄` 형태로
출력하는 병렬 SSH 실행 도구. 저장소 안의 [`esxi-log-check`](../../VM/esxi-log-check/), `OS 환경설정 체크`,
`ip_change`, `조사` 등 여러 도구가 내부적으로 이 바이너리를 서브프로세스로 호출한다.

> ⚠️ **주의사항 (Disclaimer)**  
> 본 도구 및 스크립트는 100% 신뢰하기보다는 참고용(보조 도구)으로 사용하는 것을 권장합니다.
> 설정 변경 목적으로 실행하는 경우에는 작업 후 무작위로 서버 몇 대를 직접 접속해 의도한 대로
> 변경되었는지 확인하는 절차가 반드시 필요합니다.

## 1. 빌드 및 설치 방법

### 1.1 폐쇄망(오프라인) 빌드

이 저장소에는 의존성(`golang.org/x/crypto`, `golang.org/x/sys`)을 미리 내려받아 둔 **`vendor/` 디렉토리가
포함**되어 있습니다. 인터넷이 연결되지 않는 폐쇄망(air-gapped) 환경에서도 즉시 빌드할 수 있습니다.

```bash
# 1. 디렉토리 이동
cd ".claude/공통/gossh"

# 2. 실행 편의 스크립트로 빌드 (내부적으로 go build -mod=vendor -o gossh . 실행)
./setup.sh
```

수동으로 빌드하거나 오프라인 환경을 강제하려면:

```bash
GOPROXY=off GOFLAGS=-mod=vendor go build -o gossh .
```

빌드가 끝나면 현재 디렉토리에 `gossh`(Windows는 `gossh.exe`) 단일 실행 파일이 생성됩니다.

### 1.2 RHEL 6 / CentOS 6 (OS6) 호환 정적 바이너리

구형 커널(2.6.32) 및 glibc 환경인 RHEL/CentOS 6을 위해 Go 1.20 정적 링크(`CGO_ENABLED=0`)로 빌드된
**`gossh_os6` 바이너리가 기본 포함**되어 있습니다. 별도의 컴파일 과정 없이 대상 서버에 이 파일만
복사해 바로 실행할 수 있습니다.

```bash
./gossh_os6 -w hosts.txt "uname -r"
```

### 1.3 전역 명령어로 사용하기 (선택 사항)

빌드된 실행 파일을 PATH 환경 변수에 포함된 디렉터리로 이동하면 어디서든 명령어처럼 사용할 수 있습니다.

```bash
sudo cp gossh /usr/local/bin/
# 또는 pdsh 이름으로 심볼릭 링크/복사하여 사용 가능
sudo ln -sf /usr/local/bin/gossh /usr/local/bin/pdsh
```

### 1.4 `update.sh`로 배포하기

특정 서버(대상서버) 위에서 직접 실행해서, 그 서버 환경 기준으로 새로 빌드한 일반 빌드와 저장소에
포함된 OS6용 사전 빌드 바이너리(`gossh_os6`)를 시스템 경로 여러 곳에 한 번에 배포하는 스크립트입니다.

```bash
# update.sh 상단의 TARGET_SERVER/DEST1/DEST2/DEST3 값을 먼저 채운 뒤 실행
./update.sh
```

- `TARGET_SERVER`(대상서버)와 다른 서버에서 실행하면 즉시 거부됩니다(호스트명/IP로 확인).
- `DEST1`(복사될위치1): OS6 사전 빌드 바이너리를 `gossh`라는 이름으로 복사.
- `DEST2`(복사될위치2, 기본 `/usr/local/bin`): 이 서버 환경 기준 일반 빌드를 `gossh`라는 이름으로 복사.
- `DEST3`(복사될위치3, 기본 `/usr/bin/`): 같은 일반 빌드를 `pdsh`라는 이름으로 복사.
- 모두 강제 복사(기존 파일 삭제 후 새로 복사)라서, 이미 실행 중인 바이너리를 덮어써도 실행 중이던
  프로세스에는 영향이 없습니다.

## 2. 기본 사용 방법

### 2.1 빠른 시작

```bash
./gossh -w hosts.txt "cat /etc/os-release"
```

- `hosts.txt`는 호스트명을 한 줄에 하나(또는 쉼표 구분)씩 작성하며, `#` 주석이 가능합니다.
- **주의**: 명령어는 항상 **따옴표로 묶어야** 합니다. 따옴표를 쓰지 않으면 셸이 파이프(`|`)나 리다이렉션(`>`, `<`)을 먼저 해석합니다.

### 2.2 인증 방식 (SSH 키 우선 정책)

- **SSH 키 최우선 탐색**: 비밀번호(`-p`)를 지정하더라도 **SSH 키 인증을 항상 먼저 시도**합니다.
  키로 접속이 성공하면 `-p`로 넘긴 비밀번호는 사용되지 않습니다. 키가 없거나 키 인증에 실패한 호스트만
  비밀번호로 폴백(Fallback) 접속합니다.
- 키 경로(`-i`)를 직접 주지 않으면 `~/.ssh/id_ed25519` → `id_ecdsa` → `id_rsa` 순서로 자동 탐색합니다.

### 2.3 pdsh 스타일 유연한 `-w` 문법

Go의 기본 flag 패키지 제약을 보완하여 `pdsh` 스타일의 다양한 표기법을 모두 지원합니다:

```bash
./gossh -w hosts.txt "uptime"      # 공백 구분 (기본)
./gossh -w=hosts.txt "uptime"     # 등호 구분
./gossh -w^hosts.txt "uptime"     # pdsh 스타일 붙여쓰기 (^ 접두어 지원)
./gossh -whosts.txt "uptime"      # 공백 없이 붙여쓰기
```

## 3. 핵심 고급 기능

### 3.1 진행률 실시간 표시 (Progress)

작업 대상 서버가 많을 경우, 1초 간격으로 처리 완료된 호스트 수와 비율을 표준에러(stderr)에 실시간으로
표시합니다 (`\r`로 동일 행 갱신):

```text
진행: 1230/3000 (41%)
```

- 진행률은 터미널 맨 아래 줄에 고정되어 줄바꿈 없이 제자리에서 갱신되고, 결과·오류 줄은 그 위로 쌓입니다.
- 줄을 지웠다가 다시 쓰지 않고 글자를 덮어쓴 뒤 남는 부분만 지우며, 내용이 바뀔 때만 다시 그리고, 진행 중에는
  커서를 숨겨서 깜빡이지 않습니다. 터미널 폭보다 길면 잘라서 한 줄을 넘지 않게 합니다.
- 표준에러가 터미널일 때만 표시되므로 `> result.txt`, `2> error.log` 어느 쪽으로 리다이렉션해도 파일에 진행률 문자열이 섞이지 않습니다.
- 실행 파일 이름이 `pdsh`인 경우에는 기존 `pdsh`와의 호환성을 위해 진행률 출력이 자동으로 비활성화됩니다.

### 3.2 표준출력(stdout)과 표준에러(stderr)의 완전한 분리

일반 CLI 관례에 맞춰 **순수 실행 결과(데이터)**와 **상태/진단/오류 메시지**가 엄격하게 분리되었습니다:

- **표준출력(stdout)**: 정상 실행된 호스트들의 실행 결과 본문만 출력
- **표준에러(stderr)**: 접속 불가/타임아웃/오류 메시지, 진행률, `[안전장치]` 안내, 작업 요약 블록 등

```bash
# 순수 성공 데이터만 result.txt에 저장 (실패/요약 메시지 배제)
./gossh -w hosts.txt "uptime" > result.txt

# 데이터와 에러 로그를 완전히 분리하여 수집
./gossh -w hosts.txt "uptime" > result.txt 2> error.log
```

### 3.3 `-b` 옵션: 동일 결과 호스트 그룹화 (clush 스타일 Bunch Mode)

결과 본문이 동일한 호스트들을 하나로 묶어서 요약 출력합니다 (`clush -b` 형태):

```bash
./gossh -w hosts.txt -b "cat /etc/redhat-release"
```
```text
--------------------
esxi[0001-0010],esxi0015
--------------------
Rocky Linux release 8.10 (Green Obsidian)
```

- 접속 실패(Timeout/Refused)된 호스트는 결과 비교 없이 **`접속불가 (Timeout/Refused)` 그룹**으로 자동 분류되어 별도 표시됩니다.
- `-script` 모드와 함께 사용하는 경우 `-b`는 자동으로 비활성화되고 호스트별 단독 결과가 출력됩니다.

### 3.4 호스트명 범위 확장 및 결과 압축 표기 (clush/NodeSet 호환)

- **입력 파일 표기**: 한 줄에 호스트 하나, 또는 쉼표(`,`)나 공백으로 여러 개를 나열(`hostA hostB hostC`도 각각 별도 호스트로 인식) 모두 가능합니다.
- **입력 시 범위 자동 확장**: `esxi[0001-0020]`(단순 범위)뿐 아니라 clush(ClusterShell NodeSet)와 동일한 콤마+범위 혼합 표기 `qwer[2660,2671,2676,2826-2829]`, `hostname[0001-0002]ev[01-03]`(여러 괄호 그룹)까지 그대로 확장합니다 (0-padding 자릿수 자동 유지).
- **화면 요약/`-b` 그룹 출력만 clush와 동일하게 압축**: 콘솔에 찍히는 `-b` 그룹 헤더나 Ctrl+C 진행 중 목록 등에서, 접두어가 같은 호스트들의 번호를 clush와 동일한 규칙으로 압축합니다.
  - 숫자 하나뿐이면 괄호 없이 그대로: `qwer5000`
  - 여러 개면 `[콤마+범위]`: `asdf[1346-1348]`, `qwer[2660,2671,2676,2826-2829]`, `zxcv[1231-2222,5555-5800,5900,6000-6100]`
  - 숫자 사이에 글자(`ev` 등)가 있으면 다차원으로도 접습니다: `hostname0001ev01`~`hostname0002ev03` 6대 → `hostname[0001-0002]ev[01-03]`. 곱집합이 아니면 `hostname0001ev[01-03],hostname0002ev[01-02]`처럼 나뉩니다. 숫자 바로 뒤에 범위가 붙거나 구분 기호만 있는 경우(`node1-[01-02]`)는 헷갈리므로 합치지 않고, `node101`~`node103`은 `node[101-103]`처럼 단일 축으로만 압축됩니다.
  - **결과 파일(`_res_off`, `_res_refsed` 등)은 압축하지 않고, 호스트명을 줄바꿈으로 한 줄에 하나씩 그대로 기록**합니다. `-w`에 그대로 다시 넣으면 재실행됩니다.

### 3.5 autofs 안전장치 (`/user/` 경로 보호 및 동시성 제한)

대량의 노드가 `/user` 하위의 autofs 공유 스토리지를 동시에 참조할 때 발생하는 마운트 스톰(Mount Storm)을
방지하기 위한 안전 가드가 내장되어 있습니다:

- 명령어에 `/user/` 경로 패턴이 포함되어 있으면 **동시 접속 수(`-c`)가 자동으로 450으로 제한**됩니다.
- 우회가 필요한 경우 `-cf <숫자>` 플래그를 사용해 원하는 동시성을 강제로 지정할 수 있습니다.

```bash
# /user/ 경로 감지 시 자동으로 450 병렬 제한 발동 (-c 1000 무시됨)
./gossh -w hosts.txt "bash /user/scripts/check.sh"

# -cf 옵션으로 안전장치를 우회하여 500 병렬 실행
./gossh -w hosts.txt -cf 500 "bash /user/scripts/check.sh"
```

### 3.6 위험 명령 가드

실수로 대량의 노드에 시스템 종료나 재부팅을 날리는 사고를 방지합니다.
명령어에 `reboot`, `poweroff`, `shutdown`, `halt`, `init 0`, `init 6`, `ddc` 문자열이 포함되어 있으면
실행이 즉시 차단됩니다.

실제 실행하려면 오타 방지 플래그인 `-dnlgjawkrdjqghkrdls`를 추가하고 프롬프트 확인을 거쳐야 합니다:

```bash
./gossh -dnlgjawkrdjqghkrdls -w hosts.txt "reboot"
# ==> 대상 호스트 목록 출력 후 (y/N) 최종 확인 단계 진행
```

### 3.7 대량 실행 시 DNS 조회 안정화

수천 대 규모(예: 5000대)를 짧은 시간에 동시 실행하면 시스템 리졸버(glibc `getaddrinfo`)의 내부
스레드풀 제약으로 DNS 조회가 간헐적으로 실패/지연되어, 실제로는 접속 가능한 호스트가
"접속불가"로 잘못 분류될 수 있습니다. 이를 완화하기 위한 두 가지 장치가 내장되어 있습니다:

- **순수 Go 리졸버 강제 사용**: `net.DefaultResolver`에 `PreferGo: true`를 적용해 glibc 리졸버의
  스레드풀 병목을 우회합니다.
- **DNS 조회 선행 + 짧은 재시도**: `ssh.Dial`보다 먼저 호스트명 해석만 수행하고, 실패 시 (전체
  접속 타임아웃 `-t`가 아니라) 250ms 간격으로 최대 2회만 짧게 재시도합니다. 최종 실패 시
  `DNS 조회 실패`로 분류되어 `_res_off` 파일에 기록됩니다. IP 주소로 지정한 호스트는 이 과정을
  건너뜁니다.
- DNS 조회 자체도 SSH 접속 동시성(`-c`, autofs 감지 시 450)과 별개로 자체 동시성 제한(50)을 둬서,
  대량 동시 실행 시 리졸버/DNS 서버에 걸리는 순간 부하를 줄입니다.
- 이 재시도는 진짜 접속 불가 호스트의 대기 시간을 늘리지 않습니다 — DNS가 실제로 죽은 게 아니라
  혼잡으로 인한 일시적 실패인 경우에만 짧게(최대 약 0.5초) 추가로 흡수하고, 그 외에는 기존과 동일하게
  `-t` 타임아웃 한 번으로 판정됩니다.

### 3.8 접속불가 호스트 재검증

대량으로 짧은 시간에 동시 실행하면 DNS/접속 혼잡으로 실제로는 접속 가능한 호스트가 일시적으로
"접속불가"(타임아웃/Refused)로 분류되는 경우가 있습니다. 1차 실행이 끝나면, 접속불가로 분류된
호스트만 모아서 훨씬 낮은 동시성(최대 50)으로 **명령어까지 실제로 다시 실행**합니다.

- 이미 성공한 호스트는 건드리지 않고, 접속불가 대상만 재검증하므로 실패 대상이 적은 일반적인
  경우엔 전체 소요 시간에 미치는 영향이 거의 없습니다. 다만 실제로 다운된 호스트가 많다면 그만큼
  재검증에도 시간이 걸립니다(원래부터 불가피한 부분).
- 재검증에서 실제로 접속/실행에 성공하면 그 결과가 정상 출력(stdout, `-b` 그룹 등)에 그대로
  반영되고 "정상 접속 가능" 수치에도 포함됩니다. 요약에 회수된 대수가 별도로 표시됩니다.
- 재검증 후에도 실패하는 호스트만 최종적으로 `_res_off`/`_res_refsed`에 기록됩니다.
- Ctrl+C 3회로 전체 중단한 경우에는 재검증을 하지 않습니다.

### 3.9 원격 출력의 이스케이프 코드 제거

원격 서버 명령의 출력에 ANSI 색상/OSC 코드(컬러 `ls`, 커스텀 프롬프트, 팔레트를 바꾸는 이스케이프
등)가 섞여 있으면, 우리 쪽에서 다시 초록색으로 감싸더라도 그 안의 이스케이프가 완전히 닫히지 않아
터미널 전체 색이 바뀌어 버리는 문제가 있었습니다. 이제 원격 출력은 우리 색으로 감싸기 전에 이스케이프
코드를 전부 제거합니다. 원격 출력 내용 자체(글자)는 그대로 유지되고, 제어 코드만 사라집니다.

### 3.10 Ctrl+C 동작 (pdsh 방식)

실행 중 Ctrl+C를 누르면 즉시 종료되지 않고, 누른 횟수(마지막 입력 후 1초 이내 연속 입력만 누적)에 따라 동작합니다:

| 횟수 | 동작 |
|---|---|
| 1회 | 지금 진행 중인(접속/명령 실행 중) 호스트 목록을 stderr에 표시하고 계속 진행 |
| 2회 | 현재 걸려 있는 호스트들의 접속/실행을 취소하고 **다음 호스트를 계속 진행**. 취소된 호스트는 `<hostfile>_res_cancel`에 저장 |
| 3회 | 전체 작업 중단. 지금까지의 결과로 요약 출력 및 결과 파일 저장 후 종료(미실행 호스트는 어떤 결과 파일에도 넣지 않고 요약에 "미실행 N대"로만 표시) |

- 3회 중단 후에도 멈춰 있으면 한 번 더 누르면 즉시 종료(exit 130)됩니다.
- 대기열에 있던(아직 시작 안 한) 호스트는 2회 취소의 대상이 아니며 그대로 이어서 실행됩니다.
- `-pm` 사용 시 추가 점검 단계에서 취소한 호스트도 `_res_cancel`에 기록되며 정상 접속 수에서는 제외됩니다.
- 행리스트 화면(`-m`)을 보고 있을 때 Ctrl+C를 누르면 원래 화면으로 먼저 돌아온 뒤 안내가 표시됩니다.

### 3.11 `-m` 옵션: 행리스트보기 (오래 걸리는 호스트 확인)

```bash
./gossh -m -w hosts.txt "yum -y update"
```

진행률 줄에 `[Enter: 행리스트보기 - 60초 이상 실행 중 N대]` 안내가 붙고, **Enter**를 누르면 행리스트
화면으로 바뀝니다. 다시 **Enter**를 누르면 원래 화면으로 돌아옵니다.

```text
=== 행리스트: 60초 이상 실행 중이거나 실행했던 호스트 ===  경과 00:01:11
진행: 2/3 (66%)  ...   실행 중 1대 / 끝남 1대

  호스트명   상태    진행시간
  node0001   실행중  00:01:11
  node0002   끝남    00:01:08
(Enter: 원래 화면으로 돌아가기)
```

- 동시 실행 슬롯을 잡고 실제로 시작한 시점부터 60초가 넘은 호스트만 표시합니다(대기열에서 기다린 시간은 제외).
- 보는 도중 끝난 호스트는 **끝난 시각에서 시간이 멈춘 채** "끝남"으로 남습니다. 실행 중인 호스트가 위, 오래 걸린 순입니다.
- 화면 높이를 넘으면 위에서부터 보이는 만큼만 표시하고 `... 외 N대`로 알려줍니다.
- 행리스트를 보는 동안 나온 결과는 버려지지 않고, 원래 화면으로 돌아올 때 한꺼번에 출력됩니다.
- 행리스트는 대체 화면 버퍼(vim/less와 같은 방식)에 그려서 원래 화면과 스크롤백을 건드리지 않습니다.
- 입력/표준에러가 터미널이 아니면(파이프, `</dev/null` 등) 안내를 한 줄 출력하고 `-m` 없이 동작합니다. 실행 파일 이름이 `pdsh`여도 `-m`을 주면 동작합니다.
- 1차 실행 동안만 동작하며, 이후 재검증 단계와 요약 출력 전에 자동으로 원래 화면으로 돌아오고 터미널 입력 모드도 원래대로 복원됩니다(Ctrl+C 4회, SIGTERM/SIGHUP 종료 시에도 복원).

## 4. 옵션 전체 목록

| 플래그 | 기본값 | 설명 |
|---|---|---|
| `-w <hostfile>` | (필수) | 호스트 목록 파일. `esxi[0001-0020]` 범위 표기 지원. `-w^파일`, `-w파일` 등 붙여쓰기 지원. 중복 호스트 자동 제거. |
| `-u <계정>` | `root` | SSH 접속 계정. |
| `-p <비밀번호>` | (없음) | SSH 비밀번호. SSH 키 인증이 우선 시도되며, 키 인증 실패 시에만 폴백으로 동작. |
| `-i <경로>` | (자동탐색) | SSH 개인키 경로. 미지정 시 `~/.ssh/id_*` 자동 탐색. |
| `-P <포트>` | `22` | SSH 포트 번호. |
| `-c <N>` | `1000` | 동시 접속 수 (명령어에 `/user/` 감지 시 자동으로 450으로 제한됨). |
| `-cf <N>` | `0` | `/user/` autofs 안전장치를 우회하여 강제로 지정할 동시 접속 수. |
| `-b` | `false` | clush 스타일 동일 결과 그룹 출력 (접속불가 호스트 별도 그룹화). |
| `-m` | `false` | 행리스트보기. 실행 중 Enter로 60초 이상 실행 중/실행했던 호스트와 진행시간 확인, 다시 Enter로 복귀 (3.11 참고). |
| `-script` | `false`* | 작업 요약 및 ANSI 색상을 끄고 순수 호스트 결과만 출력 (`*`실행 파일명이 `pdsh`일 때는 기본값이 `true`로 동작). |
| `-t <초>` | `15` | SSH 연결 타임아웃(초). |
| `-pm` | `false` | `~/.profile` 내 anaconda 감지 시 "OS 설치중" 제외 및 특정 autofs 계정 접근 점검. |
| `-dnlgjawkrdjqghkrdls` | `false` | 위험 명령(재부팅, 종료 등) 강제 실행 승인 플래그. |

## 5. 결과 파일 안내

실행 완료 후 특이사항이 발생한 호스트가 있을 때만 `-w` 파일명을 기준으로 생성됩니다. 압축 없이
호스트명이 줄바꿈으로 한 줄에 하나씩 그대로 기록되므로, 그대로 `./gossh -w <hostfile>_res_off "명령어"`
형태로 재실행할 수 있습니다:

| 생성 파일명 | 설명 |
|---|---|
| `<hostfile>_res_off` | 연결 타임아웃 및 네트워크 불가 호스트 |
| `<hostfile>_res_refsed` | Connection Refused (포트 닫힘) 호스트 |
| `<hostfile>_os_install` | `-pm` 옵션 사용 시 OS 설치 중으로 분류된 호스트 |
| `<hostfile>_nosvrauto` | `-pm` 옵션 사용 시 특정 autofs 계정 미마운트 호스트 |
| `<hostfile>_res_cancel` | Ctrl+C 2회로 사용자가 취소한 호스트 |

같은 위치에서 다시 실행하면, 이번 실행이 만들 수 있는 위 5개 파일명과 완전히 일치하는 파일만(다른
파일은 건드리지 않음) 실행 시작 시점에 먼저 지웁니다. 그래서 이번 실행에 해당 유형의 호스트가 하나도
없으면 이전 실행이 남긴 파일이 그대로 남아 헷갈리는 일 없이 파일이 없는 상태가 됩니다.

## 6. 디렉토리 구조

```
gossh/
├── README.md          # gossh v2 통합 상세 설명서 (본 문서)
├── PLAN.md            # 개발 및 기능 개선 계획 문서
├── CHANGELOG.md       # 버전별 상세 변경 이력 (v2 개발 히스토리 포함)
├── main.go            # gossh v2 메인 소스코드 (진행률/stdout 분리/키 우선/autofs 가드 내장)
├── term_linux.go      # 터미널 크기 조회·키 입력 모드(-m) — Linux 전용
├── term_other.go      # Linux 외 OS용 대체 구현(-m 미지원, 빌드만 가능하게)
├── go.mod / go.sum      # Go 모듈 정의 (Go 1.20 호환)
├── setup.sh           # vendor 의존성을 이용한 오프라인 빌드 스크립트
├── update.sh          # 대상서버 전용 배포 스크립트
├── gossh_os6          # RHEL 6 / CentOS 6 대상 사전 정적 빌드 바이너리
├── vendor/            # 오프라인 빌드용 Go 서드파티 패키지 모음
└── old/               # 구버전(v1) 소스 및 테스트 파일 아카이브
    ├── main.go        # gossh v1 레거시 소스코드
    ├── go.mod / go.sum
    ├── vendor/
    └── hosts_*.txt
```

> **구버전(v1) 아카이브 안내**:  
> 이전 버전의 `gossh` 소스코드와 파일들은 `old/` 디렉터리에 그대로 보존되어 있습니다.
