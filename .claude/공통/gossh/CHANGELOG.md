## 2026-09-18 — 대량 실행 시 DNS 조회 안정화

- **원인**: 5000대 규모를 17초 만에 동시 실행하면 `ssh.Dial`이 내부적으로 쓰는 시스템 리졸버(glibc
  `getaddrinfo`)의 스레드풀 제약 때문에 DNS 조회가 간헐적으로 실패/지연되어 실제로는 접속 가능한
  호스트가 "접속불가"로 오분류되는 현상 발생.
- **변경(`main.go`)**: ① `net.DefaultResolver`에 `PreferGo: true` 적용(glibc 리졸버 우회, 순수 Go
  구현 사용). ② `lookupHostWithRetry()` 신규 — `ssh.Dial` 전에 이름 해석만 선행, 실패 시 (전체
  접속 타임아웃이 아니라) 250ms 간격으로 최대 2회만 짧게 재시도. IP 주소는 건너뜀. ③ DNS 조회
  전용 동시성 제한(`dnsLookupConcurrency = 50`)을 SSH 접속용 세마포어(최대 350)와 별개로 추가.
- **분류**: DNS 조회 최종 실패는 `SSH 접속 실패`와 구분되는 `DNS 조회 실패` 메시지로 표시되며,
  기존과 동일하게 `failedHosts`(`_res_off`)에 기록됨.
- **영향 범위**: `.claude/공통/gossh/main.go`, `gossh_os6`(재빌드).
- **검증**: 존재하지 않는 호스트명/접속 불가 IP/정상 호스트를 동시 실행해 DNS 실패가 별도 분류되고
  `stdout`(res)에 안 섞이는 것, Go 자체 리졸버가 실제로 사용된 것(에러 메시지의 DNS 서버 주소로
  확인), 재시도가 전체 실행 시간에 영향을 주지 않는 것(총 소요시간이 `-t` 타임아웃 값에 수렴)을
  192.168.0.58에서 확인. 192.168.0.60(Go 1.20)에서 OS6 바이너리 재빌드 확인.
