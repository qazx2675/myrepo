# gossh 계획서

작성일: 2026-08-16 / 대상 저장소: `qazx2675/myrepo` `.claude/공통/gossh`

## 배경

이미 완성되어 실제로 쓰이고 있던 코드(`main.go`)를 그대로 저장소에 올리는 작업. 로직 자체는
변경하지 않았고, 저장소의 다른 도구들과 같은 방식으로 **오프라인 빌드가 되도록 패키징**
(`go.mod`/`go.sum`/`vendor/` 추가)하고 같은 문서 양식(README/PLAN)만 새로 작성함.

## 왜 `공통/`인가

`ESXi 로그점검`(`-gosshPath`), `OS 환경설정 체크`(`gossh -pm`) 등 `VM/`와 `HPC/` 양쪽 도구가
전부 이 바이너리를 서브프로세스로 호출한다. 특정 업무 폴더 하나에 종속시키지 않고, 두 영역 모두에서
공유하는 기반 도구라는 의미로 최상위에 `공통/gossh/`로 배치함.

## 한 일

1. 사용자가 준 `main.go`를 그대로 이 폴더에 저장 (로직 변경 없음).
2. `go mod init gossh` → `go mod tidy`로 `golang.org/x/crypto/ssh` 의존성 확정 (`go.mod`/`go.sum` 생성).
3. `go mod vendor`로 `vendor/`에 의존성 전체 내려받음 — 이후 인터넷 없이 빌드 가능.
4. Rocky Linux(192.168.0.58)에서 실제로 빌드 검증:
   - `go build -mod=vendor -o gossh .` — 정상 빌드
   - `GOPROXY=off GOFLAGS=-mod=vendor go build -o gossh .` — **완전 오프라인(폐쇄망 시뮬레이션) 빌드도 성공**
   - `go.mod`의 `go` 지시자를 저장소의 다른 도구들과 맞춰 `1.21`로 낮춤(기본값은 `go mod init`이 잡은 현재 툴체인 버전 `1.26.5`였음) — 낮춘 뒤에도 오프라인 빌드 재확인함
5. 저장소의 다른 도구(`ESXi 로그점검` 등) 문서 양식에 맞춰 README.md 작성 (플래그 표, 위험 명령 가드,
   결과 파일 4종, 사용 예시, 알려진 한계).

## 검증 범위

빌드(컴파일)까지만 확인했고, 실제 SSH 접속·명령 실행 등 기능 테스트는 하지 않음 — 요청자가 이미
운영 중인 완성 코드임을 확인해준 것을 근거로 함.

## v2: autofs 안전장치 추가 (2026-08-22 ~ 08-23)

### 배경

`gossh`로 수천 대 서버에 동시에 명령을 실행할 때, 명령어가 autofs로 마운트되는 `/user` 하위 경로를
건드리는 경우 마운트 스톰 등으로 autofs 맵 서버/스토리지 서버에 순간 부하가 몰릴 수 있다는 논의를
거쳤다. 결론적으로 파일 존재 체크(`test -f`, `[ -d ... ]`) 같은 가벼운 작업은 수천 대 동시 실행도
문제없지만, 검증되지 않은 상태에서 무조건 큰 동시 접속 수를 기본값으로 쓰는 건 리스크가 있으므로
"`/user/` 경로가 감지되면 자동으로 병렬 수를 낮추고, 필요하면 명시적으로 우회할 수 있게" 하는
안전장치를 요청받음.

### 요구사항 (요청자 원문 기준)

- 기본 동시 접속 수(`-c`)는 그대로 1000 유지.
- 명령어에 `/user`가 포함되면(경로로서, 예: `/user/asdf/...`) **무조건 500대로 자동 변경**.
- 이때 `-c` 옵션으로 지정한 값은 무시.
- `-cf <숫자>` 신규 옵션을 주면, `/user`가 포함되어 있어도 그 숫자만큼 병렬 실행(안전장치 우회).
- `"echo 'user'"`처럼 `/user/...` 형태의 실제 경로가 아닌 경우(단어로서의 "user")는 안전장치 대상이
  아님 — 반드시 `/user/`로 시작하는 경로 패턴일 때만 인식.

### 왜 기존 `main.go`를 직접 고치지 않고 `v2/`로 분리했는가

요청자가 폐쇄망 환경에서 먼저 테스트해보고 문제없으면 기존 운영 버전에 반영하겠다는 방침을
명확히 함. 이미 운영 중인 `main.go`(1~4장 대상)를 건드리지 않고, `v2/` 하위에 `go.mod`/`go.sum`/
`vendor`/`setup.sh`까지 통째로 복사해 **완전히 독립적으로 빌드되는 별도 디렉토리**로 구성했다.
같은 디렉토리에 `main.go`와 `main_v2.go`를 함께 두는 방식(빌드 태그로 분리)도 검토했으나, 두 바이너리가
같은 소스 트리를 공유하면 폐쇄망 검증 중 실수로 운영 버전이 함께 영향받을 여지가 있어 배제하고
디렉토리 단위 분리로 결정함.

### 구현

- `v2/main.go`: 기존 `main.go` 로직은 그대로 두고 아래만 추가.
  - `-cf` 플래그 추가 (`flag.Int("cf", 0, ...)`, 기본값 0 = 미지정).
  - `/user/`로 시작하는 경로 감지용 정규식: `` `(^|[\s"'])/user/` `` — 명령어 시작 또는 공백/따옴표
    뒤에 오는 `/user/`만 인식해서, `echo 'user'`처럼 슬래시 없는 단어와 구분됨.
  - 병렬 수 결정 순서: `-cf`가 0보다 크면 그 값 사용 → 아니면 `/user/` 경로 감지 시 500 강제 →
    아니면 `-c` 값(기본 1000) 그대로 사용.
  - 안전장치가 발동하면 실행 시 콘솔에 `[안전장치] ...` 로그를 남겨 사용자가 인지할 수 있게 함.
  - 작업 요약 출력에 실제 사용된 동시 접속 수(`동시 접속 수 : N`)를 추가해 사후 확인 가능하게 함.

### 검증

1. 록키 리눅스(192.168.0.58, root SSH)로 `v2/` 폴더 전체를 전송.
2. `GOPROXY=off GOFLAGS=-mod=vendor go build -o gossh_v2 .`로 **완전 오프라인 빌드 성공** 확인.
3. 실제 존재하지 않는 IP(`10.255.255.1`)를 대상으로 4가지 케이스 실행 테스트, 작업 요약의
   "동시 접속 수" 값으로 검증:
   - `/user/asdf/qwer.sh` 명령, 옵션 없음 → 500 (안전장치 로그 출력됨)
   - 동일 명령 + `-c 2000` → 500 (`-c` 무시됨)
   - 동일 명령 + `-cf 2000` → 2000 (강제 지정 적용됨)
   - `/user/` 경로가 아닌 `echo 'user'` → 1000 (기본값 유지, 오탐 없음)
   → 4가지 모두 요구사항대로 동작 확인.
4. 원격 서버의 테스트/빌드용 임시 디렉토리(`/tmp/gossh_v2_verify`)는 검증 후 정리(삭제)함.

### 검증 범위 / 한계

- SSH 접속·명령 실행 자체의 성공/실패 판정 로직은 기존 `main.go`와 동일한 코드라 이번 검증에서
  별도로 재확인하지 않음(로직 변경 없음).
- 실제 대량(수백~수천 대) 서버를 대상으로 한 운영 환경 부하 테스트는 아직 하지 않음 — 폐쇄망에서
  소규모(300~500대)로 먼저 실사용 테스트 후 문제없으면 기존 `gossh`(main.go)에 반영 예정.
- `/user/` 감지는 문자열 패턴 매칭 기반이라, 실제로 autofs가 아닌 경로가 우연히 `/user/`로
  시작하는 경우에도 안전장치가 걸릴 수 있음 — 이 경우 `-cf`로 우회하면 된다(README 5.6 주의사항 참고).

## v2 2번째 업데이트: pdsh 호환 문법 + -b 그룹출력 + 버그수정 + 색상 + OS6 빌드 (2026-09-04)

### 요청 내용 (요청자 원문 기준)

1. `-w`에 pdsh 스타일로 값이 붙는 표기(`-w^file`, `-w file`, `-w ^file` 전부)를 지원 — 기존
   `pdsh`를 삭제하고 gossh로 대체할 예정이라 pdsh와 동일한 호출 문법이 되어야 함.
2. clush의 `-b`(결과가 같은 호스트를 묶어서 출력)와 동일한 기능 추가. `-script`와 같이 오면
   묶음 출력은 나오면 안 됨.
3. 버그: `gossh -w a -script "cat test |grep 'asdf'"`처럼 명령어 끝이 따옴표로 끝나면 실행이
   깨짐(끝에 공백을 하나 더 넣어야만 됨).
4. 가독성 좋게 색상 추가.
5. 기존 내용(운영 중인 `main.go`, v2의 기존 동작)은 절대 변경하지 말 것.
6. 이 내용을 담은 OS6(RHEL/CentOS 6)용 빌드 결과물도 저장소에 같이 올릴 것. 수정 작업은
   192.168.0.58에서, OS6 빌드는 Go 1.20이 설치된 192.168.0.60에서.
7. (선택) 빌드 파일명이 `pdsh`면 `-script`가 켜진 상태로 동작하게.

### 착수 전 확인한 것 (애매했던 부분)

- "192.168.0.59에서 수정 작업"이라고 하셨으나 .59는 ESXi 호스트라 Go 개발환경이 없어서, 지금까지
  모든 gossh/vc-test-env 작업을 진행해온 .58(록키 리눅스)이 맞는지 확인 → **.58 확정**.
- `-b` + `-script` 조합 동작 → **`-b`를 무시하고 기존처럼 호스트별 결과만 출력** (요청자 확정).
- 색상 범위 → **상태별 색상(성공=초록/에러=빨강/경고=노랑) + 작업 요약 헤더 강조** (요청자 확정).
- `-w` 붙여쓰기 지원 범위 → **`-w`에만 적용** (요청자가 예시로 든 `-w^file`/`-w ^file`/`-w file` 세
  가지 형태 모두 지원. 다른 플래그로는 확장하지 않음).

### 구현 (전부 `v2/main.go`에만 반영, 운영 중인 `main.go`는 무수정)

- **① pdsh 붙여쓰기**: `flag.Parse()` 대신 `preprocessArgs()`로 `os.Args[1:]`를 전처리해서
  `-w^file`/`-wfile` 형태를 `-w`, `값` 두 토큰으로 분리한 뒤 `flag.CommandLine.Parse()`에 넘김.
  `-w=value`(Go 관용 표기)와 `-w` 단독은 그대로 둠.
- **② `-b` 그룹출력**: `runSSHCommand`에 `bunchMode`/`bunchOutputs`(host→렌더링된 결과 텍스트)를
  추가. `bunchMode`가 켜지면(= `-b`이고 `-script`가 아닐 때만) 즉시 출력하는 대신 맵에 저장해뒀다가,
  `wg.Wait()` 이후 `printBunched()`로 동일 텍스트인 호스트를 묶어서 한 번에 출력. `-script`가 같이
  오면 `bunchMode`가 애초에 꺼진 채로 계산되므로 기존과 동일하게 즉시 호스트별 출력됨(요청대로).
- **③ 버그 수정**: `command = strings.Trim(command, "\"'")` 줄을 통째로 제거. 쉘이 이미 실제
  따옴표를 벗겨서 넘겨주므로 이 처리 자체가 불필요했고, `grep 'asdf'`처럼 명령어가 실제로 따옴표로
  끝나는 경우 그 따옴표까지 잘라내 명령어를 깨뜨리고 있었음.
- **④ 색상**: ANSI 색상 상수 + `colorize()` 헬퍼 추가, `colorEnabled = !*scriptMode`로 스크립트
  모드에서는 색상 코드를 아예 넣지 않게 함. 성공=초록, 에러=빨강, 경고(OS설치중/안전장치 메시지)=노랑,
  작업 요약 헤더=굵은 청록.
- **⑤ (선택) pdsh 이름 감지**: `-script` 플래그의 기본값을 `filepath.Base(os.Args[0]) == "pdsh"`
  여부로 계산해서 넘김. `-script=false`로 명시적으로 덮어쓸 수 있음.
- **OS6 빌드 호환성**: 최신 `golang.org/x/crypto`(v0.55.0)가 Go 1.25+ 전용 표준 라이브러리
  기능(`crypto/fips140`, `crypto/mlkem`)을 써서 Go 1.20으로 빌드가 안 됨 → `golang.org/x/crypto`를
  자체 `go.mod`가 정확히 `go 1.20`을 요구하는 최신 버전인 `v0.31.0`으로, `golang.org/x/sys`도
  `v0.28.0`으로 다운그레이드. `go.mod`의 `go` 지시자도 `1.20`으로 낮춤. 이렇게 하면 최신 Go
  툴체인(.58, 1.26)과 Go 1.20 툴체인(.60, `/opt/go1.20`)이 같은 `go.mod`/`vendor/`를 공유해서
  둘 다 빌드된다.

### 검증 (192.168.0.58에서 전부 실행 테스트)

- `-w^h.txt` / `-w ^h.txt` / `-w h.txt` 세 형태 전부 동일하게 동작 확인.
- `-b`로 두 호스트에 동일 명령 실행 → `호스트1,호스트2` 형태로 한 번만 묶여서 출력됨을 확인. 출력이
  다르면 그룹도 분리됨을 확인.
- `-b -script` 조합 → 그룹화 없이 호스트별로만(색상도 없이) 출력됨을 확인.
- `cat test |grep 'asdf'`(끝에 공백 없음)가 더 이상 깨지지 않고 정상 실행됨을 확인(예전엔 이 경우
  깨졌었음).
- 색상: `cat -v`로 raw 출력을 찍어서 성공(초록)/요약헤더(굵은 청록) ANSI 코드가 실제로 들어가는 것,
  `-script` 모드에서는 코드가 전혀 없는 것을 확인.
- 실행 파일을 `pdsh`로 복사해서 `-script` 없이 실행 → 요약 블록/색상 없이 순수 결과만 출력됨을 확인.
- OS6 빌드: `/opt/go1.20/bin/go build -mod=vendor`로 `.60`에서 빌드 성공, `file`로 정적 링크
  확인, 실제로 `./gossh_os6 -w host cat ...` 실행해서 SSH 접속·명령 실행까지 정상 동작 확인.
- 다운그레이드한 `x/crypto`/`x/sys`로 최신 Go 툴체인(.58, 1.26) 빌드도 재확인(정상).

### 검증 범위 / 한계

- OS6 빌드는 실제 RHEL/CentOS 6 서버에서 실행해보지는 못했음(정적 링크 + Go 1.20 툴체인이라는
  간접 근거로 호환성을 확보한 것) — 실제 OS6 서버가 생기면 한 번은 직접 실행 확인 필요.
- `-b`는 성공적으로 명령이 실행된 결과(정상 세션 생성 이후)만 묶는다. SSH 접속 실패/세션 생성
  실패 같은 연결 단계 에러는 (호스트마다 실패 사유 문자열에 IP가 다르게 박혀 사실상 그룹화가 안
  되는 경우가 많아서) 기존처럼 항상 즉시 개별 출력한다.

## v2 3번째 업데이트: 호스트명 압축 표기 + -b 접속불가 그룹 + autofs 350 (2026-09-04)

### 요청 내용 (요청자 원문 기준)

### 착수 전 확인한 것

## v2 6번째 업데이트: 표준출력/표준에러 분리 (2026-09-07)

### 요청 내용 (요청자 원문 기준)

`gossh`/`pdsh` 이름 둘 다에서, "접속불가"나 "no such directory" 같이 일반적으로 파일 리다이렉션 시
기록되지 않는 메시지는 실제로도 기록되면 안 됨. 예: `gossh -w a "uptime" > res` 실행 시 a가
접속불가면 res에는 아무것도 안 남아야 하고, 명령어 오타로 나는 에러 메시지도 res에 안 남아야 함.

### 범위 판단

"res에는 아무것도 안 나와야 한다"는 예시를 만족하려면 접속불가/오타 에러 메시지 하나만 옮겨서는
안 되고(그러면 요약 블록이 여전히 표준출력에 남아 res가 비지 않음), **데이터가 아닌 모든 상태·진단
출력**(요약 블록, `[안전장치]`, 위험 작업 경고, 사용법 오류, 위험작업 확인 프롬프트, 호스트 없음
경고, 접속불가 그룹)을 표준에러로 옮겨야 한다고 판단. 실제 명령 실행 결과(성공한 호스트의 출력,
`-b`로 묶인 성공 그룹)만 표준출력에 남긴다.

### 구현 (`v2/main.go`)

`fmt.Println`/`fmt.Printf`로 찍던 위 메시지들을 전부 `fmt.Fprintln(os.Stderr, ...)`/
`fmt.Fprintf(os.Stderr, ...)`로 변경. 핵심 분기점 두 곳:
- `printPdshStyle`: `err != nil`이면 표준에러, 아니면(정상 결과) 표준출력.
- `runSSHCommand`: `bunchMode && err == nil`일 때만 `bunchOutputs`에 담아 나중에 묶어서
  표준출력으로 내보내고, 그 외(비-`-b` 정상/에러, `-b`+에러 전부)는 `printPdshStyle`로 즉시 처리—
  에러면 자동으로 표준에러로 감.
`printUnreachableGroup`(접속불가 그룹)도 통째로 표준에러로 이동.

### 검증 (192.168.0.58)

- 접속불가 호스트만으로 `> res 2>err` → `res` 0줄, `err`에 요약+에러 전부.
- 정상 호스트에 오타 명령(`cattt ...`) → `res` 0줄, `err`에 "command not found" 포함.
- 정상 명령(`echo hello`) → `res`에 결과 그대로, `err`에 요약.
- `pdsh` 이름 + 접속불가 → `res` 0줄(동일하게 적용됨).
- `-b` + 정상 명령 → `res`에 그룹 출력 남음. `-b` + 오타 명령 → `res` 0줄, `err`에 에러.
- 192.168.0.60(Go 1.20)에서 OS6 바이너리 재빌드 후 확인.

## v2 8번째 업데이트: 대량 실행 DNS 조회 안정화 (2026-09-18)

### 요청 내용

5000대를 17초 만에 실행하다 보니 DNS 쿼리가 간헐적으로 안 되는 현상이 있음. DNS 조회 불가 시
접속불가로 분류되는데, 접속불가 서버에 대해 재시도를 하면 타임아웃 시간만큼 더 늘어날 것 같음 —
좋은 방법이 있는지 문의.

### 원인 분석 및 방안 제시

`ssh.Dial` 내부에서 시스템 리졸버(glibc `getaddrinfo`)로 이름 해석을 하는데, 대량 동시 실행 시
glibc 리졸버의 내부 스레드풀 제약으로 간헐적 실패/지연이 나는 것으로 판단. 세 가지 방안을 제시:
① 순수 Go 리졸버(`PreferGo`)로 교체(근본 원인 완화), ② DNS 조회만 분리해서 (전체 접속 타임아웃이
아니라) 짧게 재시도, ③ DNS 조회 전용 별도 동시성 제한. "1000대씩 실행해도 DNS 서버에 부하가 없을지"
추가 질문을 받아, ①+②만으로는 DNS 서버로 나가는 순간 부하 자체는 줄지 않는다는 점을 설명하고
①+②+③ 전부 적용하기로 확정.

### 구현 (`main.go`)

- `net.DefaultResolver = &net.Resolver{PreferGo: true}` — `main()` 시작부에서 한 번 설정.
- `lookupHostWithRetry()` 신규: `ssh.Dial` 전에 호스트명만 먼저 해석. IP는 건너뜀. 실패 시 250ms
  간격으로 최대 2회 재시도(총 3회 시도), 각 시도는 2초 컨텍스트 타임아웃.
- DNS 조회 전용 세마포어 `dnsSem`(동시성 50, `dnsLookupConcurrency` 상수) — SSH 접속용 세마포어
  (`sem`, 최대 350)와 별개로 운용.
- `runSSHCommand`에 `dnsSem` 파라미터 추가, DNS 조회 실패 시 `SSH 접속 실패`와 구분되는
  `DNS 조회 실패` 메시지로 `failedHosts`에 기록(기존 `_res_off` 파일 포맷 그대로 재사용).

### 설계 근거: 왜 재시도가 전체 지연을 늘리지 않는가

기존 우려("접속불가 서버 재시도 시 타임아웃만큼 늘어남")는, 재시도를 SSH 접속 자체(수 초~15초
타임아웃)에 걸었을 때의 얘기다. 이번 구현은 재시도를 DNS 조회 단계(수 ms~2초)에만 걸었고, 최대
재시도 비용은 약 0.5초(250ms × 2회 대기)에 불과하다. 게다가 모든 호스트가 병렬로 처리되므로, 이
0.5초는 진짜 접속 불가 호스트가 어차피 기다리는 `-t` 타임아웃(기본 15초)에 묻혀 전체 실행 시간에는
거의 영향이 없다.

### 검증 (192.168.0.58)

## v2 9번째 업데이트: Ctrl+C를 pdsh 방식으로 (2026-09-19)

### 요청 내용

pdsh는 조사 중 Ctrl+C를 2번 누르면 현재 걸린 호스트를 취소하고 다음 호스트를 계속 진행하고, 3번이면
명령 전체가 취소된다. gossh는 1번에 즉시 종료되므로 동일하게 맞춰달라.

### 확정한 동작 (질문으로 확인)

- 1회: 진행 중 호스트 목록만 stderr에 출력(계속 진행).
- 횟수 창: 마지막 입력 후 1초 이내면 누적, 지나면 1회로 리셋.
- 2회: 현재 진행 중(접속/실행 중) 호스트 취소 후 계속. 취소 호스트는 `_res_cancel` 별도 파일.
- 3회: 전체 중단 후 지금까지 결과로 요약+결과파일 저장하고 종료(미실행은 요약에 개수만).

### 구현 (`main.go`)

- 호스트별 `hostCtl`(context + 연결) 등록. 취소 시 컨텍스트 취소 + 연결 close로 DNS/접속/명령 실행 중
  어느 단계든 끊음. 대기열(세마포어 대기) 호스트는 대상 아님.
- `ssh.Dial` → `net.Dialer.DialContext` + `ssh.NewClientConn`/`NewClient`로 분해(동작·에러 메시지 동일).
- `os/signal` 핸들러(`startInterruptHandler`)에서 횟수 판정. 3회는 `abortCh` 닫아 대기열 호스트 미실행 처리.
  4회째는 즉시 `exit 130`(멈춤 대비 안전장치).

### 검증 (192.168.0.58)

Ctrl+C 1회(목록만, 결과 정상 완료) / 2회(2대 취소, 대기 호스트 계속 진행, `_res_cancel` 생성) /
3회(전체 중단, 미실행 1대, 요약 출력) 확인. OS6 바이너리 재빌드(.60, Go 1.20).

|---|---|
| gossh 기본, 동시 1개 | 호스트당 154ms |
| 같은 조건 OpenSSH(`ssh host true`) 순차 | 호스트당 215ms |

- 응답 없는(타임아웃) 호스트가 1대라도 있으면 1차 실행이 `-t`만큼, 재검증이 다시 `-t`만큼 걸림 → 전체 시간이 `-t` 기준 약 2배. 재검증 전용 짧은 타임아웃/더 높은 동시성으로 줄일 수 있으나 요청자 확인 후 적용.

### 버그 재점검 결과

- **수정함**: 호스트 파일 한 줄이 64KB를 넘으면(가로로 수천 대 나열) 스캐너가 조용히 멈춰 호스트가 0대로 처리됨 → 한 줄 최대 64MB 허용 + 읽기 오류 시 알림. 12000대 한 줄 재현 → 수정 후 12000대 정상 인식.
- **수정함**: IPv6 주소(`::1`, `fe80::1`)를 호스트로 주면 "host:port"로 오인해 DNS 조회/접속이 깨짐 → IP 주소는 `[주소]:포트`로 처리. `::1` 실행 확인.
- **수정함**: 진행률 줄이 터미널 폭보다 길면 줄이 넘어가서 매 갱신마다 새 줄이 쌓임 → 폭에 맞춰 자름(한글 2칸 계산).
- **확인 필요(미수정)**: `-t`는 TCP 연결 단계에만 적용되고 SSH 핸드셰이크/인증 단계에는 제한이 없음. TCP만 받고 응답 없는 서버(멈춘 sshd, LDAP 지연 인증 등)에서 `-t 2`를 줘도 무한 대기 재현됨. 핸드셰이크에도 타임아웃을 걸면 해결되지만 인증이 느린 정상 서버가 실패로 분류될 수 있어 확인 후 적용.
- **확인 필요(미수정)**: 색상 코드가 파일로 리다이렉션해도 결과 파일에 들어감(`-script` 아닐 때). `grep "^host:"` 등이 안 맞을 수 있음. 터미널일 때만 색상을 쓰게 바꿀지 확인 후 적용.

### 구현

- **깜빡임**: 매초 "줄 지우기(\033[K) → 다시 쓰기" 하던 것을 "덮어쓰기 → 남는 오른쪽만 지우기"로 변경, 내용이 같으면 다시 그리지 않음, 진행 중 커서 숨김. 결과 줄이 터미널로 나갈 때는 결과+진행률을 한 번의 write로 처리하고, 파일로 리다이렉션된 출력일 때는 진행률을 건드리지 않음.
- **-m**: `term_linux.go`에서 입력 줄버퍼/에코만 끄는 모드(ICANON/ECHO off, 출력 처리와 Ctrl+C는 그대로 — 참고 프로젝트에서 겪은 raw 모드 줄바꿈 깨짐 회피). Enter로 대체 화면 버퍼(`\033[?1049h/l`) 진입/복귀, 행리스트는 전체 지우기 없이 덮어써서 깜빡임 없음. 호스트별 시작/종료 시각을 기록해 끝난 호스트는 시간이 멈춤. 행리스트를 보는 동안 나온 결과는 모아뒀다가 복귀 시 출력. 종료/Ctrl+C 4회/SIGTERM/SIGHUP 때 터미널 상태 복원.
- **의존성**: 기존에 쓰던 `golang.org/x/sys` v0.28.0에서 `unix` 패키지만 추가 vendoring(버전 변경 없음). Linux 외 OS는 `term_other.go`로 빌드만 되고 `-m`은 안내 후 무시.
