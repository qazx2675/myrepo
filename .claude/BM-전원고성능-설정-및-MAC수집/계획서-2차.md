## 1. 요청

1. 작업 시작 전에 **설치할 OS 버전**을 묻는다 → MAC 목록의 `argStr` 자리에 들어간다 (`8.10` 입력 → `... sda5 <정수> 8.10 uefi`).
2. 작업 시작 전에 **인프라**도 묻는다(`인프라 입력 : `) → MAC 목록의 `arg1` 자리(3번째 칸).
3. `./vm_setup.sh` 실행 흐름에 **power_setting(BM 전원 고성능)** 을 넣는다. 실패하면 중단, 이미 고성능인 호스트는 정상. 오류 없이 도는지 검증하고 `사용법.txt` 갱신.
4. MAC 목록의 `sda5` 다음 정수를 **ev별 스펙 Disk 값**에 따라 고정 용량 `480 600 960 1200 1900 7600` 중 **가장 가까운 값**으로 넣는다. 거리가 같으면 **큰 값**.
5. 추가된 빌드(power_setting)도 **OS6 용 실행파일**을 만들어 다른 도구와 똑같이 동작하게 한다.

## 3. 변경 설계

### 3-1. 시작 시 입력 (OS 버전 · 인프라)

- 위치: user 선택 직후, 스펙 할당 전 (= "작업 시작 전"). `-n`(계획만 보기)에서도 묻는다 — 실행 계획에 값이 찍혀야 확인이 되므로.
- 화면:
  ```
  === 설치 정보 (MAC 목록에 들어갈 값) ===
  OS 버전 (예: 8.10): 8.10
  인프라 입력 : <값>
  ```
- 형식 검사 (틀리면 다시 묻는다):
  - OS 버전: 숫자와 점만 (`^[0-9]+(\.[0-9]+)*$`, 예 `8.10`, `9.4`)
  - 인프라: 비어 있지 않고 공백 없음 (MAC 목록이 공백으로 칸을 나누므로)
- `MAC_ARGSTR` / `MAC_ARG1` 환경변수가 이미 있으면 그 항목은 묻지 않는다(비대화식 실행용 — 기존 동작 유지).
- 두 값이 항상 채워지므로 "비어 있으면 mac_info 건너뜀" 분기는 삭제 → **mac_info 는 항상 실행**.
- 실행 계획에 `OS 버전 : 8.10 / 인프라 : <값>` 한 줄 추가.

### 3-2. 실행 순서 (스펙마다 반복)

```
vswitch_setting (1회)
스펙 k 마다:
  vm_create
  mac_info        ← 끝에서 여기로 이동 (worklist_k.txt 의 BM 만)
  power_setting   ← 신규 (worklist_k.txt 의 BM 만)
  affinity_setting
  lpage_setting
스펙 체크 (vm-param-check)
MAC 목록 합치기 → awx_route/<user>.txt 복사
```

- power_setting 결과 처리:
  - 이미 고성능 → **스킵 = 정상** (도구가 이미 그렇게 동작, 종료코드 0)
  - 1대라도 실패(종료코드 1) → 다른 단계와 똑같이 **중단**(`run` 사용). 다시 실행하면 이미 만든 VM/포트그룹·이미 고성능인 호스트는 건너뜀.
- 실행 파일 확인 목록(`ensure_bin`)에 `power_setting` 추가.
- 실행 계획에 `전원 정책     : power_setting (BM N대 → 고성능)` 한 줄 추가.

### 3-3. MAC 목록 디스크 용량 (sda5 다음 정수)

- 스펙 k 의 `-evNNDisk` 값 → 고정 용량으로 변환해 ev 별 표를 만든다.
- 변환 규칙(확정): `480 600 960 1200 1900 7600` 중 |Disk − 용량| 이 가장 작은 값, 같으면 큰 값.
  | 스펙 Disk | 결과 | 비고 |
  |---|---|---|
  | 200 | 480 | 480 보다 작으면 모두 480 |
  | 400 | 480 | 요청 예시 |
  | 500 | 480 | 가장 가까운 값 (확정) |
  | 540 | 600 | 480·600 차이가 60 으로 같음 → 큰 값 |
  | 800 | 960 | 요청 예시 |
  | 10000 | 7600 | 7600 보다 크면 모두 7600 |
- 적용 방법: **mac_info(Go) 는 고치지 않고**, vm_setup.sh 가 mac_info 출력 줄의 VM 이름 끝 `evNN` 을 보고 10번째 칸(정수)을 바꾼다(awk).
  - 이유: Go 를 고치면 OS6 용 `bin_os6/mac_info.gz` 도 다시 만들어야 함. bash 쪽 변환이면 재빌드 불필요.
  - mac_info 단독 실행(`-argInt`)은 지금처럼 그대로 동작.
- 스펙마다 mac_info 가 같은 이름(`Provisioning_List_<vCenter>.txt`)으로 쓰므로, 호출 직후 변환해서 합본 파일에 이어 붙인다 → 마지막에 합본을 `awx_route/<user>.txt` 로 복사.
- `MAC_ARGINT` 환경변수는 더 이상 쓰지 않으므로 제거.
- 실행 계획의 vm_create ev 표에 변환 결과 표시: `ev01: Cpu=16 Mem=64 Disk=500 (MAC 480) Share=8000`.

### 3-4. awx_route

- 실제 경로는 정해져 있으나 이번엔 **테스트 경로로 복사만 확인**. 코드 기본값은 지금처럼 빈 값 유지(`awx_route="${awx_route:-}"`, 1차 수정분), 검증은 `awx_route=/tmp/awx_test` 로.

### 3-5. OS6 빌드 (power_setting)

- `build_os6.sh` 대상에는 1차 때 이미 추가됨 → **빌드 서버(.60, `/opt/go1.20`)에서 `bash build_os6.sh` 실행 → `bin_os6/power_setting.gz` 생성 → 커밋.**
- mac_info 는 Go 를 안 고치므로 기존 `mac_info.gz` 그대로.
- govmomi Go 1.21+ 패치가 power_setting 에서 쓰는 코드(`HostPowerSystem`)에도 통하는지 빌드로 확인. 막히면 그 부분만 추가 패치.
- OS6 동작 확인: .58 의 podman `centos:6` 컨테이너에서 `bash setup.sh --os6` → `power_setting -h` 실행 확인(1차 OS6 검증과 같은 방식).

### 3-6. 사용법.txt · 테스트 스크립트

- "3. VM 만들기" 실제 실행 순서에 입력 단계 추가:
  `VM 표 y → CAE 번호 Enter → OS 버전 8.10 → 인프라 입력 → vCenter 번호 1 → 실행 확인 y`
- MAC 목록(결과 파일 위치, `awx_route`, 디스크 용량 변환 규칙) 한 단락.
- power_setting 이 흐름에 포함됐다는 것 + vcsim 에서는 "이미 고성능 → 스킵"이 정상이라는 설명 + 단독 실행 예시.

2. `vcsim.sh restart` 로 깨끗한 상태에서 `./vm_setup.sh -u lsh` (메뉴 입력 그대로):
   - OS 버전 `8.10`, 인프라 입력 → 실행 계획에 OS 버전·인프라·전원 정책·MAC 디스크 표시 확인
   - 종료까지 **오류 없이** 끝나는지 (vswitch → vm_create → mac_info → power_setting → affinity → lpage → 스펙 체크)

4. 같은 명령 재실행 → 이미 있는 VM/포트그룹 스킵, power_setting 스킵(정상), MAC 목록 다시 생성 확인.
