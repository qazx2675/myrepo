1. 개요 및 아키텍처 · 연계 통신 경로

auto_setup은 HPC/서버 OS 배포 직후 수동으로 수행하던 설치 완료 확인, LDAP 설정 백업/복원, os_check(config_check) 일괄 점검·설정 적용, 결과 공유(code) 과정을 하나의 데몬과 양방향 TUI/CLI로 자동화합니다. 추가로 TUI 안에서 01 AWX 실행·신규 설치 양식 작성(w), gossh 일괄 작업 이력 관리(s), IP/LDAP 변경·원복(m)까지 연계합니다.

1.2 os8_mgmt vs os6_mgmt 양방향 구조 및 연계 도구 역할

구성요소 / 연계 도구 위치 / 모드 통신 경로 및 연계 동작
auto_setup 데몬 os8_mgmt 전용 (단일 원본) /tmp/auto_setup(또는 $AUTO_SETUP_DIR) 상태 관리, raw ICMP ping, 준비확인, LDAP 백업/복원, os_check 실행, 2차 체크, requests/*.req 수거를 전담합니다.
auto_setup 원격 클라이언트 os6_mgmt (os8_mgmt 설정 시) 상주 데몬 금지. status·snapshot·code·cancel·done·request·TUI는 gossh -pm -script 원샷으로 os8_mgmt에 요청합니다(RHEL6 ssh 호환 문제 및 세션 부담 방지, TUI는 10초 폴링). 단, 화면 2의 g·c·t와 s(gossh 작업)는 os6_mgmt에서 직접 실행합니다.
os8_mgmt → os6_mgmt 경로 전환 데몬 자동 전환 (단방향) 첫 ping 무응답 또는 설치 중 무응답 시 ssh -o BatchMode=yes로 os6_autosetup/auto_setup probe -i 10s 장기 세션 및 os6_gossh 경유로 전환합니다(local → os6). 원격 명령은 모두 remoteBash(bash -c, ! 포함 시 base64)와 shq로 감싸 csh/tcsh 로그인 셸에서도 동작합니다.
01.AWX_nodeinfo_V2.sh (awx_script) os8_mgmt 또는 os6_mgmt 02 성공 직후 프롬프트 없이 queue/*.job(user, time, 호스트, 그룹 yml 메타)을 자동 전달합니다. 반대로 auto_setup TUI의 w→1/w→2에서 AWX_AUTO*·AWX_USER·AWX_VERIFY_FILE·AWX_DNS_CHECKED 환경변수를 넘겨 01을 직접 기동할 수 있으며, DNS 점검(dnscheck.go)은 01의 [4-1] dns_check와 동일 규칙을 공유합니다.
os_check / config_check.sh os_check_sh · os6_os_check_sh 자동 흐름과 수동 c는 -auto <user> <목록>으로 실행하고, 수동 t는 -auto-check <user> <목록>으로 점검만 수행합니다. ############### 결과 리포트 ############### 블록을 발췌해 codes/<code>.txt를 만들고, 정상 종료 시 auto_done_dir/auto_done_host로 완료기록(done/<host>)을 남깁니다.
ip_change · ldap_setting os8_mgmt TUI m 메뉴 소스를 흡수하지 않고 ip-change-engine·ldap-config-engine 바이너리를 호출합니다. LDAP 호출(dry-run·적용·원복)은 항상 -no-restart를 강제하고, 무응답 호스트는 임시 래퍼를 -gossh로 넘겨 os6_mgmt를 경유합니다.
gossh os8_mgmt 및 os6_gossh 원격 클라이언트 중계, -pm uptime 준비확인, LDAP 백업/복원, os6 os_check 래퍼, s gossh 작업 기록(script -q -f -c)의 기반 전송 계층입니다. 출력 해석은 parseGossh로 통일되어 FQDN과 짧은 이름을 함께 매칭합니다.

1.3 호스트 단계(Stage) 전이

각 호스트는 상태에 따라 대기(queued) → 배포중(deploying) → 설치중(installing) → 부팅확인(booting) → READY(ready) → LDAP확인(ldap) → 체크중(checking) → 2차체크(second) → 완료(done) 순으로 전이합니다. 부가 상태로 정체(stuck)(seen_down 후 installStuck 60분 초과, 화면 표시만)와 실패(failed)(os_check 비정상 종료 연속 maxFails 3회)가 있습니다.

3.2 표준 자동 연계 및 주요 대화형 기능 흐름

  • 자동 배포 → 체크 흐름: 01.AWX_nodeinfo_V2.sh가 02 등록 성공 시 queue/*.job을 전달하면 데몬이 ping 감시 → READY 판별 → LDAP 백업 비교/복원 → os_check -auto 실행 → (필요 시) os6_mgmt 2차 체크 → codes/<code>.txt 생성까지 무인 진행합니다. 결과 확인은 TUI h→v(최근 결과) 또는 auto_setup code <4자리>를 사용합니다.
  • 체크스크립트 단독 실행 (x): TUI 어디서나 x 입력 → user 선택 → 호스트 붙여넣기(Ctrl+D) → t(체크만, -auto-check) 또는 c(체크+수정, -auto) 즉시 실행. 임시 디렉터리에서 실행 후 삭제하며 auto_setup.log·codes·runs에 기록을 남기지 않습니다.
  • AWX 실행 (w→1 / ww) 및 신규 설치 양식 (w→2 / auto_setup newhost):
    • w→1(또는 ww·w Enter): 프로파일(awx_profile_N)이 있으면 AWX auto 실행? [y/n] 질문(yml마다 OS 버전이 다르면 n) → user 및 서버 목록 붙여넣기(awx_dir/<user>.txt 덮어씀) → 01.AWX_nodeinfo_V2.sh 실행(Ctrl+X로 즉시 SIGINT 취소).
    • w→2 / auto_setup newhost(os8_mgmt 전용): 5단계(hostname ip mac [템플릿] [13번째태그] 붙여넣기 → 템플릿/미니언어 지정 및 이력 추천 → dnscheck.go DNS 점검 5종 판정 → 미리보기 → awx_dir/<user>.txt 저장 및 백업) 후 AWX 연동. 프로파일을 고른(y) 경우에만 AWX_AUTO_NODEINFO=n을 강제하고, 고르지 않으면(n 또는 프로파일 없음) 일반 실행으로 01 질문에 직접 답합니다.
  • gossh 작업 기록 (s / auto_setup s): n으로 호스트 붙여넣기(Ctrl+D로만 종료, 빈 줄 무시) → 목록 파일 /tmp/auto_setup/lists/<3자리> 생성 → script -q -f -c로 실제 tty 유지 실행. 대상 대수가 work_os6_over(기본 1000) 이하면 os8 실행 후 접속불가만 os6_mgmt 자동 재실행, 초과면 전량 os6_mgmt 경유 실행. 요약은 work/<user>/index.jsonl(영구), 출력은 out/<id>.log.gz(7일·200MB)에 보관됩니다.
  • IP/LDAP 변경 메뉴 (m, os8_mgmt 전용): 1 IP 변경 / 2 LDAP 변경 / 3 IP+LDAP / 4 원복 / 5 auto.appl 원복. 대상 입력(Ctrl+D) → (LDAP 시) dry-run 미리보기 → 정확히 yes 입력 시만 실행(ip-change-engine, ldap-config-engine -no-restart). 무응답 호스트는 os6_mgmt 경유 재시도하며 실행 기록을 changes/<user>/<시각>_<kind>.json(0600)에 저장합니다.
  • os6_mgmt 직접 실행 (g·c·t): os6_mgmt 원격 TUI 화면 2에서 g·c·t를 누르면 데몬에 요청을 보내지 않고 os6_mgmt에서 직접 1회 실행하며, <os6_autosetup>/os6_run/의 잠금(active/*.lock, 3분 미갱신 시 무시)·완료기록(done/<host>)으로 os8_mgmt 데몬과 중복을 방지합니다.

5.2 운영 제약사항 및 주의사항

  • 보조 도구(Disclaimer) & 실서버 교차 검증 필수: 본 도구는 100% 신뢰하기보다 참고용으로 사용하십시오. os_check 설정 변경, LDAP 복원, 2차 체크, m 변경 메뉴 실행 후에는 반드시 무작위 서버 몇 대에 직접 접속해 실제 반영 여부를 확인하십시오.
  • 2차 체크(이중 체크) 설정 재적용 주의: os_check의 set 단계가 포함된 경우 2차 체크가 같은 호스트에 설정을 한 번 더 적용할 수 있습니다. 원치 않으면 os6_os_check_sh="-"로 비활성화하십시오.
  • m 변경 메뉴 제약: IP 변경은 ifcfg만 수정하며 네트워크 재시작을 하지 않습니다. LDAP는 항상 -no-restart로 동작하고 auto.appl은 메뉴 5를 실행해야 반영됩니다(반영 전 ldap_check FAIL 가능). 또한 LDAP 엔진 호출 시 gossh 명령줄에 base64 스크립트(bindpw 포함)가 실리므로 ps에 잠깐 보일 수 있습니다.
  • 자동 삭제되지 않는 민감/누적 디렉터리: /tmp/auto_setup/ldapbak/(평문 bindpw 포함 원본), requests/rejected/, jobs/done/, runs/*/second/는 자동 삭제되지 않으므로 작업 완료 후 ldapbak/ 등은 수동 정리하십시오.
  • 운영 제약사항 요약: ① /tmp/auto_setup 소유자 검증이 없으므로 root 전용 환경에서 운영, ② AUTO_SETUP_NOW는 테스트 전용(운영 설정 금지), ③ 원격 클라이언트(os6_mgmt)의 os8_mgmt 조회 gossh에는 타임아웃 제한 없음, ④ os6_mgmt 원격 인자 128KB 상한(수만 대 작업 시 실패 가능) 및 os6_mgmt 직접 실행 시 autofs 공유 경로·양 서버 간 NTP 5분 이내 동기화 필수, ⑤ 데몬은 항상 os8_mgmt에 1개만 실행(pgrep -af 'auto_setup daemon').
