2. 처음 사용하기 전에 무엇을 준비하나?

  1. os8_mgmt 에 auto_setup 실행 파일을 /usr/local/bin/auto_setup 으로 둡니다.
  2. 설정 파일 auto_setup.conf 를 만듭니다. 가이드 스크립트 bash conf/setup_guide.sh --no-setup 을 사용하면 쉽습니다.
  3. os8_mgmt 에서는 설정 키 os8_mgmt 를 비웁니다. os6_mgmt 에서는 os8_mgmt=<os8_mgmt 호스트명> 을 씁니다.
  4. cron 에 매분 auto_setup ensure 를 등록합니다. cron 이 데몬을 자동으로 시작합니다.
  5. 01.AWX_nodeinfo_V2.sh 와 config_check.sh 에 연계 변수를 씁니다 (아래 표).

2.1 설정 파일은 어디에서 읽나?

auto_setup 은 아래 순서로 처음 찾은 파일 1개만 읽습니다.

  1. $AUTO_SETUP_CONF/auto_setup.conf
  2. <실행 파일 디렉터리>/conf/auto_setup.conf
  3. /etc/auto_setup/auto_setup.conf

2.2 연계 스크립트에 어떤 변수를 쓰나?

파일변수내용
01.AWX_nodeinfo_V2.shauto_setup_hostos6_mgmt 에서 01 을 실행할 때 os8_mgmt 호스트명을 씁니다. 비어 있으면 로컬 queue 에 작업을 씁니다.
config_check.shauto_done_dir완료 기록(done/<host>)을 쓰는 로컬 디렉터리입니다. 보통 /tmp/auto_setup/done 입니다. os8_mgmt 전용 사본에서만 씁니다.

autofs 로 config_check.sh 를 공유할 때: os8_mgmt 와 os6_mgmt 가 같은 파일을 씁니다. auto_done_host 만 쓰고 auto_done_dir 은 비우십시오. auto_done_dir 을 쓰면 os6_mgmt 에서 실행한 완료 기록이 os6_mgmt 에만 남습니다. 그러면 os8_mgmt 데몬이 완료를 알지 못합니다.

3. auto_setup 은 어떤 순서로 자동 진행하나?

  1. 01.AWX_nodeinfo_V2.sh 의 02 등록이 성공하면 작업 파일(queue/*.job)이 os8_mgmt 에 전달됩니다.
  2. 데몬이 5초마다 queue 를 읽어 작업(jobs/*.json)을 만듭니다. 이때 ping 이 되는 서버의 LDAP 설정을 백업합니다 (ldapbak/).
  3. 데몬이 10초마다 ping 을 보냅니다. 2회 연속 응답이 없으면 설치 시작(seen_down)으로 판정합니다.
  4. 데몬이 30초마다 준비확인(gossh -pm uptime)을 합니다. 응답하면 READY 입니다. 기존 OS 를 새 OS 로 잘못 판정하지 않도록 anaconda-ks.cfg 시각(48시간)을 확인합니다.
  5. READY 직후 LDAP binddn uid 를 백업과 비교합니다. 다르면 ldap_share_dir 공유 경로로 LDAP 설정을 복원합니다.
  6. 첫 READY 뒤 7분(bootWait), 늦게 READY 된 서버는 3분(lateWait) 기다립니다. 그 다음 config_check.sh -auto(설정체크 + 설정수정)를 실행합니다.
  7. 접속불가·FAIL 서버는 os6_mgmt 를 경유해 2차 체크를 실행합니다.
  8. 결과를 codes/<4자리>.txt 로 저장합니다. 모든 서버가 완료되면 작업을 jobs/done/ 으로 옮깁니다.

3.1 서버(호스트) 단계는 무엇이 있나?

단계뜻
대기 (queued)작업을 받았습니다. 아직 설치가 시작되지 않았습니다.
배포중 (deploying)AWX 배포를 진행합니다.
설치중 (installing)ping 이 끊겼습니다. OS 를 설치하고 있습니다. 60분까지는 설치중입니다 (RHEL7 은 약 1시간 걸립니다).
부팅확인 (booting)ping 이 다시 됩니다. 준비확인을 기다립니다.
READY준비확인(uptime)이 응답합니다.
LDAP확인 (ldap)LDAP 백업과 비교하고 필요하면 복원합니다.
체크중 (checking)config_check.sh 를 실행합니다.
2차체크 (second)os6_mgmt 경유로 다시 실행합니다.
완료 (done)끝났습니다.
정체 (stuck, 빨강)설치 시작 뒤 60분이 지나도 READY 가 아닙니다. 화면 표시만 합니다.
보류 (held, 노랑)설치 시작 뒤 stuck_hold_hours(기본 24시간)를 넘겨 READY 가 되었습니다. LDAP 복원과 자동 run 을 하지 않습니다. 4절을 보십시오.
실패 (failed)config_check.sh 가 3회 연속 비정상 종료했습니다.

4. "보류" 서버는 무엇이고 어떻게 처리하나? (늦은 READY 보류)

며칠 동안 정체되다가 갑자기 켜진 서버는 상태를 알 수 없습니다. 그래서 auto_setup 은 이런 서버에 설정을 자동으로 넣지 않고 보류 로 둡니다.

  • 기준: 설치 시작(처음 ping X, READY 뒤 재부팅이면 그 재부팅)부터 stuck_hold_hours 시간(기본 24)을 넘겨 READY 가 된 서버입니다. ping X 를 보지 못한 서버는 작업 전달 시각부터 셉니다.
  • 화면 표시: 노란 보류 단계, 비고 보류(정체 N시간, h→u 해제), 상단 합계 보류 N, 막대 !
  • 로그: 늦은 READY 보류: <호스트> (정체 N시간, 기준 stuck_hold_hours=24, …)
  • 보류 서버만 보기: 화면 2 에서 f (정체·보류·실패 서버만 표시)

서버 상태를 직접 확인한 뒤 아래 중 하나를 고르십시오.

방법키 또는 명령결과
보류 해제 (자동 흐름으로)화면 2 에서 h → u → y, 또는 auto_setup request release <jobid> <yml 또는 *>즉시 준비확인을 다시 합니다. 응답하면 LDAP 복원 → bootWait/lateWait 대기 → 설정체크 + 설정수정을 자동으로 진행합니다.
지금 수동 실행화면 2 에서 h → c실행 직전에 LDAP 비교·복원을 1회 하고 설정체크 + 설정수정을 실행합니다.
수동 완료화면 2 에서 h → d체크 없이 완료로 처리합니다.
  • h → u 메뉴는 보류 서버가 있을 때만 보입니다.
  • 실행 중인 run 이나 os6 직접 실행에 든 서버는 해제하지 않습니다. 로그 [!] 보류 해제 보류 가 남습니다.
  • 보류는 job 파일에 저장됩니다. 데몬을 재시작해도 유지됩니다. 보류 중 재부팅되어 다시 READY 가 되어도 풀리지 않습니다.
  • 보류 서버가 있는 작업은 끝나지 않습니다(jobs/done 으로 가지 않습니다).
  • stuck_hold_hours=0 이면 보류 기능을 끕니다(이전 동작). 값을 바꾸면 데몬을 재시작하십시오.

6. 추가 기능은 어떻게 사용하나?

6.1 임의의 서버에 config_check.sh 를 한 번 실행하려면? (x)

  1. TUI 에서 x 를 누릅니다.
  2. user 를 고릅니다.
  3. 서버 목록을 붙여 넣고 Ctrl+D 를 누릅니다.
  4. t(설정체크만, -auto-check) 또는 c(설정체크 + 설정수정, -auto)를 고릅니다.

x 는 작업 기록(auto_setup.log, codes, runs)을 남기지 않습니다.

6.2 AWX 를 실행하려면? (w → 1)

  1. TUI 에서 w → 1 (또는 ww)를 누릅니다.
  2. 설정에 프로파일(awx_profile_N)이 있으면 "AWX auto 실행? [y/n]" 질문이 나옵니다. yml 마다 OS 버전이 다르면 n 을 고르십시오.
  3. user 와 서버 목록을 붙여 넣습니다. 목록은 awx_dir/<user>.txt 에 덮어씁니다.
  4. 01.AWX_nodeinfo_V2.sh 가 실행됩니다. Ctrl+X 로 즉시 취소합니다.

6.3 신규 설치 양식을 작성하려면? (w → 2, auto_setup newhost)

  1. TUI 에서 w → 2 를 누르거나 auto_setup newhost 를 실행합니다 (os8_mgmt 에서만).
  2. hostname ip mac [템플릿] [13번째] 형식으로 붙여 넣습니다.
  3. 템플릿을 고릅니다. 공용 템플릿은 설정 키 newhost_template_1 ~ 9 입니다.
  4. 내장 DNS 점검 결과를 확인합니다.
  5. 미리보기를 확인하면 awx_dir/<user>.txt 에 저장하고 AWX 실행으로 이어집니다.

6.4 여러 서버에 gossh 명령을 실행하고 기록을 남기려면? (s)

  1. TUI 에서 s 를 누르거나 auto_setup s 를 실행합니다.
  2. n 을 누르고 서버 목록을 붙여 넣습니다. Ctrl+D 로만 끝납니다.
  3. 목록 파일 /tmp/auto_setup/lists/<3자리> 가 생깁니다. 이 목록으로 gossh 를 실행합니다.
  • 서버 수가 work_os6_over(기본 1000) 이하이면 os8_mgmt 에서 실행하고, 접속불가 서버만 os6_mgmt 에서 다시 실행합니다. 초과하면 전부 os6_mgmt 에서 실행합니다.
  • 요약은 work/<user>/index.jsonl 에 영구 저장합니다. 출력은 out/<id>.log.gz 에 7일(user 당 200MB) 보관합니다.

6.5 IP 또는 LDAP 설정을 변경·원복하려면? (m)

  • os8_mgmt 에서만 사용합니다. 설정 키 enable_ip_change / enable_ldap_change 를 켜거나 auto_setup --admin 으로 엽니다.
  • 메뉴: 1 IP 변경 / 2 LDAP 변경 / 3 IP+LDAP / 4 원복 / 5 auto.appl 원복
  • 대상 서버를 입력하고(Ctrl+D), LDAP 이면 dry-run 미리보기를 확인합니다. 정확히 yes 를 입력해야 실행합니다.
  • IP 변경은 ip-change-engine(ip_change) 으로 ifcfg 만 수정합니다. 네트워크를 재시작하지 않습니다.
  • LDAP 변경은 ldap-config-engine(ldap_setting) 을 항상 -no-restart 로 실행합니다. auto.appl 은 메뉴 5 를 실행해야 반영됩니다.
  • 실행 기록은 changes/<user>/<시각>_<kind>.json 에 저장합니다.

10. 문제가 생기면?

  • 진행 상황과 오류를 보려면: tail -f /tmp/auto_setup/auto_setup.log
  • 중요한 로그만 보려면: grep -E '경로 전환|os6 probe|준비확인 실패|gossh hang|호스트 키 변경|늦은 READY 보류' /tmp/auto_setup/auto_setup.log | tail -30
  • 수동 요청이 거부되었다: /tmp/auto_setup/requests/rejected/ 파일의 마지막 reason= 줄을 보십시오.
  • 데몬이 2개 이상 떠 있다: pgrep -af 'auto_setup daemon' 이 1줄이어야 합니다. 1개만 남기십시오.
  • 데몬을 완전히 멈추고 싶다: auto_setup --stop 만으로는 cron 이 1분 안에 다시 시작합니다. cron 의 auto_setup ensure 를 지우십시오.
  • 서버가 READY 인데 아무것도 진행되지 않는다: 단계가 보류 인지 확인하십시오. 보류이면 4절의 방법으로 처리합니다.
  • 정체 서버가 실제로는 접속된다: r 을 누르십시오. ping 과 상관없이 즉시 다시 확인합니다.
  • os6_mgmt 경유가 느리거나 진행되지 않는다: os8_mgmt 에서 root 로 ./os6_truble.sh 를 실행하십시오 (읽기 전용 9단계 점검).
  • os6_mgmt 재설치 뒤 os6 경유가 조용히 실패한다: 호스트 키가 바뀌었습니다. ssh-keygen -R <os6_mgmt> 를 실행하고 ssh <os6_mgmt> true 로 한 번 접속하십시오.
  • 완료 기록이 os8_mgmt 에 오지 않는다: config_check.sh 의 auto_done_host 를 확인하십시오 (2.2절).

주의:

  • 2차 체크는 같은 서버에 설정을 한 번 더 적용할 수 있습니다. 원하지 않으면 os6_os_check_sh=- 로 끄십시오.
  • /tmp/auto_setup/ldapbak/ 에는 bindpw 원본이 있습니다. 자동으로 지우지 않습니다. 작업이 끝나면 직접 정리하십시오.
  • requests/rejected/, jobs/done/, runs/*/second/ 도 자동으로 지우지 않습니다.
  • /tmp/auto_setup 의 소유자를 검사하지 않습니다. root 전용 환경에서 운영하십시오.
  • os6_mgmt 직접 실행을 쓰려면 autofs 공유 경로가 필요하고, 두 서버의 시간 차이가 5분 이내여야 합니다.

11. 자주 묻는 질문 (FAQ)

Q. auto_setup 은 무엇을 하는 도구인가요?
A. AWX 로 OS 를 설치한 서버를 감시하다가, READY 가 되면 LDAP 복원과 config_check.sh(설정체크 + 설정수정)를 자동으로 실행하는 도구입니다. 진행 상황은 auto_setup 명령의 TUI 로 봅니다.

Q. 작업은 어떻게 등록하나요?
A. 따로 등록하지 않습니다. 01.AWX_nodeinfo_V2.sh 의 02 등록이 성공하면 작업이 자동으로 전달됩니다.

Q. 설치가 끝났는지 어떻게 확인하나요?
A. auto_setup 을 실행하고 그룹에서 Enter 를 누릅니다. 서버마다 단계(설치중, READY, 체크중, 완료 등)가 보입니다.

Q. 서버가 READY 인데 설정체크가 실행되지 않습니다.
A. 단계가 보류 인지 확인하십시오. 설치 시작부터 24시간(stuck_hold_hours)을 넘겨 READY 가 된 서버는 자동으로 진행하지 않습니다. 서버 상태를 확인한 뒤 화면 2 에서 h → u 로 해제하거나 h → c 로 수동 실행합니다.

Q. 보류 기능을 끄려면?
A. auto_setup.conf 에 stuck_hold_hours=0 을 쓰고 auto_setup --restart 로 데몬을 재시작합니다.

Q. 결과 code 를 받았습니다. 내용을 어떻게 보나요?
A. auto_setup code <4자리> 를 실행합니다. 화면 2 에서 h → v 로 최근 수동 실행 결과를 볼 수도 있습니다.

Q. 특정 그룹에 설정체크를 다시 실행하려면?
A. 화면 2 에서 h → c(체크 + 수정) 또는 h → t(체크만)를 누르고 y 로 확인합니다.

Q. 작업과 관계없는 서버에 config_check.sh 를 실행하려면?
A. TUI 에서 x 를 누르고 서버 목록을 붙여 넣습니다. 이 실행은 작업 기록을 남기지 않습니다.

Q. 설치하지 못한 서버를 완료로 처리하려면?
A. 화면 2 에서 h → d 를 누르거나 auto_setup done <host> 를 실행합니다. 체크스크립트는 실행하지 않습니다.

Q. os6_mgmt 에서도 사용할 수 있나요?
A. 네. os6_mgmt 의 설정에 os8_mgmt=<호스트명> 을 쓰면 같은 TUI 가 열립니다. 데몬은 os8_mgmt 에서만 실행합니다.

Q. auto_setup 과 pm_monitor 는 무엇이 다른가요?
A. auto_setup 은 AWX 작업을 자동으로 받아 설치 감시부터 LDAP 복원·설정체크까지 자동으로 진행합니다. pm_monitor 는 호스트파일로 PM 서버의 설치 진행을 감시만 하는 화면입니다.

Q. auto_setup 과 setup_check 는 무엇이 다른가요?
A. auto_setup 은 상시 실행되는 데몬입니다. setup_check 는 사용자가 실행할 때 한 번 판정하고 필요하면 설정수정·부하테스트까지 진행합니다.
