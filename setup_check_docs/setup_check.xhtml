도구명: setup_check (new_setup / new_setup.sh) — 신규 OS 배포 후 설치 상태 판정 및 config_check · stress-test 자동 연계 도구

양식 유형: T2 (설치 판정 · 파이프라인 연계형)

원본 경로 (origin/master): .claude/HPC/setup_check/

주요 파일: bin/new_setup (os8 정적 바이너리), bin/new_setup_os6 (옛 RHEL6용), new_setup.sh, setup.sh, troubleshoot.sh, new_setup.conf.sample

연계 도구: gossh (1차/2차 원격 수집), config_check (-auto-check 점검 / -auto 설정수정), stress-test (-batch / -yaml-state 부하 실행)

한 줄 요약: 신규 OS 배포 후 gossh로 장비별 설치 상태 5종(완료/디스크미인식/설치정지/OS설치중/접속불가)과 설정체크·CPU·stress-ng·H/T·OS 8열 표를 산출하고, -run 모드로 config_check 설정수정부터 stress-test 부하테스트까지 TUI/자동 진행으로 이어 주는 Go 도구입니다.

참고용 판정 한계 및 실서버 교차검증 필수:

  • 본 도구는 100% 신뢰하기보다 참고용 보조 도구로 사용하세요. OS설치중·디스크미인식·설치정지·CPU/stress-ng 판정은 로그 문구와 접속 상태에 기댄 추정이므로, 중요한 장비는 무작위로 몇 대를 골라 직접 접속해 실제 상태를 확인하시기 바랍니다.
  • -run 모드는 config_check.sh -auto(설정 변경) 및 stress-test -batch(AWX 부하 실행·템플릿 인벤토리 임시 변경)를 호출합니다. 또한 -run / -auto / STRESS_REMOTE의 상당 부분은 랩의 가짜(fake) 대역으로 검증되었으며, 실제 AWX·실장비 45분 CPU 테스트·실장비 재부팅 경로는 현장에서 직접 확인해야 합니다.

1. 개요 및 전체 판정 · -run 파이프라인 흐름

new_setup은 크게 두 가지 방식으로 사용합니다.

  • 기본 모드 (읽기 전용 8열 판정): bash new_setup.sh <호스트파일> — 2단계 gossh 호출과 config_check.sh -auto-check를 통해 장비별 설치 상태와 완료 항목을 파이프(|) 구분 8열 표로 출력합니다.
  • -run / -run -auto 모드 (원스톱 자동 진행 TUI): bash new_setup.sh -run <호스트파일> — 접속 가능한 완료 서버의 설정체크 / CPU테스트 / stress-ng 세 열이 모두 O가 될 때까지 config_check.sh -auto와 stress-test -batch를 순차(또는 -auto 무인 스케줄)로 실행하며 TUI로 제어합니다.

3.1 호스트파일 및 장애 목록 (error_list.txt)

  • 호스트파일: gossh -w와 동일한 형식(공백/# 주석 무시, 쉼표·공백 분리, node[01-10] 범위 확장, 중복 제거). 단, 파일 파싱 시 쉼표 분리가 먼저 일어나므로 a[1,3,5-7] 같은 괄호 내 쉼표 표기는 사용하지 마세요.
  • 장애 목록(-er <파일>): 줄마다 hostname<TAB>장애사유 형식(탭으로만 구분, 사유 내 |는 /로 치환). 생략 시 현재 경로에 error_list.txt가 있으면 자동 사용됩니다.

4.2 -run 연계 세부 규칙 (config_check + stress-test)

  • 2단계 설정수정 (config_check): 1차 판정에서 상태가 완료이고 설정체크가 O가 아닌 호스트(OS_CHECK_SH가 지정됐는데 -인 실패 포함)를 대상으로 관리서버에서 config_check.sh -auto <user> <목록>을 실행한 뒤 -auto-check로 재판정합니다.
  • 3·4단계 부하테스트 (stress-test):
    • CPU 대상: 설정체크 O + CPU NOTRUN (단, 이전 실행 중단 등으로 CPU X인 완료 호스트가 있으면 시작 시 cat /proc/loadavg를 확인해 1분 로드 < 3인 후보만 일괄 재실행 포함 여부 y/n 질문).
    • stress-ng 대상: 설정체크 O + CPU O + stress-ng != O. (3단계에서 CPU를 돌린 호스트는 CPU가 O가 된 뒤 4단계에서 실행.)
    • 대화형 -run에서는 stress-ng 대상이 있을 때 종료 시각 5개 값(end_year~end_min)을 TUI에서 입력받거나 k 키로 stress-ng만 건너뛸 수 있습니다. -run -auto에서는 launch 당일 + 2일 00:00으로 자동 설정됩니다.
    • CPU/stress-ng 실행 중 stress-test가 [인벤토리사용중] 줄을 출력하면 TUI가 이를 가로채 r(다시 확인)/x(묶음 중단) 질문을 띄우며, 대기 중에는 STRESS_TIMEOUT 타이머가 일시정지됩니다.
  • -run -auto 특이 동작: 환경 실패([job] 생성 전 실패·설정수정 명령 오류·SSH 실패 등)는 호스트 시도 횟수(최대 3회 포기)에 세지 않고 5분 → 10분 → 20분 → 30분 간격으로 재시도합니다. 사용자가 답할 질문은 ① -yaml-state 불일치 시 덮어쓰기(y/s) ② [인벤토리사용중](r/x) 두 가지뿐입니다.

6. 해석상 한계 및 운영 주의사항

  • gossh 위험어 검사: DISK_PATTERN/ERROR_PATTERN 등 설정 문구에 reboot, poweroff, shutdown, halt, init 0, init 6, ddc가 들어가면 gossh 가드에 의해 시작 시 오류(exit 2)로 차단됩니다.
  • 저장 파일 엑셀 열기 주의: > result.txt로 저장한 파일을 엑셀에서 더블클릭하면 CP949로 열려 한글이 깨집니다. 반드시 데이터 > 텍스트/CSV에서 가져오기에서 65001: 유니코드(UTF-8) 및 구분 기호 |를 지정해 여세요.
  • 검색 범위 제약: 기본 판정은 로드 에버리지를 사용하지 않으며, stress-ng 흔적은 /var/log/messages* 비압축 일반 파일만 검사합니다(.gz 제외). 설치정지는 ERROR_PATTERN을 채워야만 판정됩니다.
