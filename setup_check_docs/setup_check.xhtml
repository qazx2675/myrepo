2. 처음 사용하기 전에 무엇을 준비하나?

  1. bash setup.sh 를 실행합니다. 기본·부하(-run)·고급 항목을 차례로 묻습니다. Enter 는 현재 값 유지, - 는 비우기입니다.
  2. setup.sh 는 기존 설정을 <설정파일>.bak 으로 백업하고 저장합니다. 설정 폴더 밖(/etc 등)에는 쓰지 않습니다.
  3. 다른 설정 파일은 bash setup.sh -c /경로/my.conf 로 만듭니다. 질문 없이 저장하려면 --yes 를 씁니다.
  4. 설정 파일 없이 new_setup.sh 를 실행하면 setup.sh 실행을 제안합니다. 끄려면 NEW_SETUP_NO_PROMPT=1 을 씁니다.
  5. 호스트 파일을 만듭니다 (2.1절).
  6. -run 을 쓰려면 OS_CHECK_SH(config_check.sh), STRESS_TEST(stress-test) 경로를 설정합니다.

2.1 호스트 파일과 장애 목록

  • 호스트 파일: gossh -w 와 같은 형식입니다. 빈 줄과 # 주석은 무시합니다. 쉼표·공백으로 나눕니다. node[01-10] 범위를 펼칩니다. 중복은 뺍니다.
  • 주의: 쉼표를 먼저 나누므로 a[1,3,5-7] 처럼 괄호 안에 쉼표를 쓰지 마십시오.
  • 장애 목록: -er <파일>. 한 줄에 hostname<TAB>장애사유. 지정하지 않으면 현재 폴더의 error_list.txt 를 씁니다. 사유는 비고 열에 나옵니다.

3. 기본 판정은 어떻게 하나?

  1. gossh -pm -script 로 모든 서버의 정보를 수집합니다. 시작 전에 지난 결과 파일(_res_off 등)을 지웁니다.
  2. 접속하지 못한 서버(_res_off, _res_refsed, _res_cancel)는 접속불가 입니다.
  3. OS 설치 중인 서버(_os_install)는 /tmp/anaconda.log 를 한 번 더 봅니다. DISK_PATTERN 이 있으면 디스크미인식, ERROR_PATTERN 이 있으면 설치정지, 그 밖에는 OS설치중 입니다.
  4. 그 밖의 서버는 완료 입니다. 완료 서버는 아래를 판정합니다.
    • 설정체크: 관리 서버에서 config_check.sh -auto-check new_setup targets.txt 를 실행합니다.
    • CPU테스트: CPU 벤더(vendor_id)별 로그(CPU_INTEL_* / CPU_AMD_*)를 봅니다.
    • stress-ng: /var/log/messages* 에 stress-ng 가 있는지 봅니다.
    • H/T: lscpu 의 Thread(s) per core. OS: uname -r(KERNEL_NAME 로 이름 바꾸기 가능)

4. -run 은 어떤 순서로 진행하나?

-run 은 완료 서버의 설정체크·CPU테스트·stress-ng 세 열이 모두 O 가 될 때까지 진행합니다.

  1. 판정: 3절의 기본 판정을 합니다.
  2. 설정수정: 완료 이고 설정체크가 O 가 아닌 서버에 config_check.sh -auto <user> <목록> 를 실행합니다. 그다음 -auto-check 로 다시 판정합니다.
  3. CPU 테스트: 설정체크 O 이고 CPU NOTRUN 인 서버에 stress-test -steps a -batch 를 실행합니다. CPU 결과와 재부팅(btime)을 감시합니다.
  4. stress-ng: 설정체크 O, CPU O, stress-ng 가 O 가 아닌 서버에 stress-test -steps b -end ... -batch 를 실행합니다.
  5. 완료: 결과를 ./<호스트파일>_run/result.txt 에 저장합니다.
  • 이전 실행이 중단되어 CPU X 인 완료 서버가 있으면, 시작할 때 1분 로드가 3 미만인 서버만 골라 다시 실행할지 묻습니다(y/n).
  • 대화형 -run 은 stress-ng 종료 시각 5개 값(end_year~end_min)을 화면에서 입력받습니다. k 를 누르면 stress-ng 만 건너뜁니다.
  • -run -auto 는 종료 시각을 "실행 당일 + 2일 00:00" 으로 자동 설정합니다.
  • stress-test 가 [인벤토리사용중] 을 출력하면 화면에서 r(다시 확인) / x(묶음 중단)를 묻습니다. 기다리는 동안 STRESS_TIMEOUT 은 멈춥니다.
  • -run 은 백그라운드 작업자로 동작합니다. 터미널이 끊겨도 작업은 계속합니다. 같은 폴더에서 다시 실행하면 화면에 다시 붙습니다.
  • -new 는 기존 ./<호스트파일>_run 폴더를 .old-<시각> 으로 보관하고 새로 시작합니다. 작업자가 살아 있으면 거부합니다.

4.1 -run -auto 는 무엇이 다른가?

  • 사람 입력 없이 끝까지 진행합니다. 전체 제한 시간은 AUTO_LIMIT(기본 12시간)입니다.
  • 환경 실패(job 생성 전 실패, 설정수정 명령 오류, SSH 실패 등)는 서버 시도 횟수에 세지 않습니다. 5분 → 10분 → 20분 → 30분 간격으로 다시 시도합니다.
  • 서버는 최대 3번 시도한 뒤 포기합니다.
  • 사용자에게 묻는 것은 2가지뿐입니다: ① -yaml-state 불일치 때 덮어쓰기(y/s), ② [인벤토리사용중](r/x).

7. 문제가 생기면?

  • 원인을 모르겠다: bash troubleshoot.sh(환경), bash troubleshoot.sh hosts.txt(-run 상태), bash troubleshoot.sh -host node01 -check(서버 1대 판정 근거)를 실행합니다. 모두 읽기 전용입니다.
  • 시작하자마자 종료 코드 2 로 멈춘다: DISK_PATTERN/ERROR_PATTERN 같은 설정 문구에 reboot, poweroff, shutdown, halt, init 0, init 6, ddc 가 있으면 gossh 가 차단합니다. 문구를 바꾸십시오.
  • 엑셀에서 한글이 깨진다: 파일을 더블클릭하지 마십시오. 엑셀의 데이터 > 텍스트/CSV에서 가져오기에서 65001: 유니코드(UTF-8)와 구분 기호 | 를 고르십시오.
  • stress-ng 를 했는데 NOTRUN 이다: /var/log/messages* 중 압축하지 않은 파일만 봅니다. .gz 로 압축된 로그는 보지 않습니다.
  • 설치정지 가 나오지 않는다: ERROR_PATTERN 을 채워야 판정합니다.
  • -run -new 가 거부된다: 이전 작업자가 아직 실행 중입니다. 화면에서 S 로 중지한 뒤 다시 하십시오.

8. 자주 묻는 질문 (FAQ)

Q. setup_check(new_setup) 는 무엇을 하는 도구인가요?
A. 새로 OS 를 설치한 서버의 설치 상태를 5종으로 판정하고, 설정체크·CPU·stress-ng·H/T·OS 를 8열 표로 보여 주는 도구입니다. -run 을 쓰면 설정수정과 부하테스트까지 이어서 진행합니다.

Q. OS 설치가 끝났는지 한 번에 확인하려면?
A. bash new_setup.sh hosts.txt 를 실행합니다. 상태 열이 완료 인 서버가 설치가 끝난 서버입니다.

Q. 설치 후 설정·CPU·stress-ng 까지 자동으로 하려면?
A. bash new_setup.sh -run hosts.txt 를 실행합니다. 사람 없이 하려면 -run -auto 를 씁니다.

Q. -run 화면을 닫으면 작업이 멈추나요?
A. 아니요. q 는 화면만 닫습니다. 같은 폴더에서 bash new_setup.sh -run hosts.txt 를 다시 실행하면 화면에 다시 붙습니다.

Q. 디스크미인식 은 무슨 뜻인가요?
A. OS 설치 로그(/tmp/anaconda.log)에 DISK_PATTERN 문구가 있다는 뜻입니다. 설치할 디스크를 찾지 못한 상태입니다.

Q. CPU테스트 NOTRUN 은 무슨 뜻인가요?
A. 그 CPU 벤더의 테스트 로그 파일이 없다는 뜻입니다. CPU 테스트를 아직 실행하지 않았습니다.

Q. 설정 파일은 어떻게 만드나요?
A. bash setup.sh 를 실행하고 질문에 답합니다.
