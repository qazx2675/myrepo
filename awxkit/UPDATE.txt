awxkit-invsync 현장 업데이트 방법
==================================

대상: 빌드된 바이너리만 사용하는 현장 (현장에는 Go 빌드 환경이 없음)
대상 파일: awxkit-invsync (404 시 인벤토리 소스 ID 재입력 기능이 들어간 새 버전)

----------------------------------------------------------------
① 바이너리 교체
----------------------------------------------------------------
# 압축을 풀거나 다운로드한 awxkit-update 안의 awxkit-invsync 를 현장 awxkit 폴더로 복사합니다.
# 기존 파일은 awxkit-invsync.bak 로 보관합니다 (-p: 권한·시간 유지).
cd /path/to/awxkit
cp -p awxkit-invsync awxkit-invsync.bak

# 새 파일을 복사합니다. (경로는 압축을 푼 위치에 맞게 바꾸세요)
cp /path/to/awxkit-update/awxkit-invsync ./awxkit-invsync

# 실행 권한을 줍니다.
chmod 755 awxkit-invsync

----------------------------------------------------------------
② 확인
----------------------------------------------------------------
# 도움말이 정상으로 출력되면 실행 가능한 상태입니다.
./awxkit-invsync -h

----------------------------------------------------------------
③ 되돌리기 (문제가 생겼을 때)
----------------------------------------------------------------
# 백업해 둔 기존 파일을 원래 이름으로 되돌립니다.
mv awxkit-invsync.bak awxkit-invsync

----------------------------------------------------------------
④ 동작 설명
----------------------------------------------------------------
invsync 가 conf 의 s2_inventory_source(고정 인벤토리 소스 ID)로 요청했을 때 AWX 가 HTTP 404 를
돌려주면(AWX 웹에서 소스 ID 가 바뀐 경우) 바로 실패하지 않습니다. 안내에 따라 새 소스 ID 를
입력하고, "s2_inventory_source 를 <기존> → <새> 으로 업데이트할까요? (y/n)" 에 y 를 입력하면
conf 의 s2_inventory_source 줄만 새 값으로 고친 뒤 같은 작업을 한 번 다시 시도합니다.
n, 빈 입력, 재시도 실패는 종전과 같이 종료 코드 1 로 끝납니다. 변경 내역은 이력 파일(history_file)에
action=invsync status=source_updated 로 남습니다.

Disclaimer
본 도구는 보조 도구로 사용하세요. 소스 ID 를 바꾼 뒤에는 변경 후 무작위로 서버 몇 대를 골라
실제로 등록되었는지 직접 확인하는 절차가 반드시 필요합니다.
