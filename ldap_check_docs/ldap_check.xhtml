도구명: ldap_check (ldap_check.sh) — 노드 로컬 LDAP · DNS · NTP · autofs 설정 정합성 검사 스크립트

양식 유형: T1 (단일 스크립트형 · 빌드 불필요)

원본 경로 (origin/master): .claude/HPC/ldap_check/ (ldap_check.sh, ldap_config.conf.sample, test_check.sh)

동작 환경 및 의존성: RHEL 6 ~ 10 (bash, awk, sed 기본 도구만 사용, jq 불필요)

연계 도구: ldap_setting (설정 일괄 적용 짝), pm_monitor (install_mn TUI l 키 연계), gossh (전 노드 일괄 점검)

한 줄 요약: 대상 노드의 LDAP · DNS · NTP · autofs 설정 파일을 읽기 전용으로 3중 교차 검증해 인프라·사이트 정합성을 검사하는 단독 Bash 스크립트입니다.

1. 개요: 이게 뭐하는 도구인가요?

ldap_check.sh는 HPC 노드의 DNS · NTP · LDAP · autofs 관련 핵심 설정 파일이 정의된 인프라 및 사이트 기준값과 일치하는지 읽기 전용으로 점검하는 단독 Bash 스크립트입니다. 설정을 변경하지 않으며, jq 같은 추가 패키지 없이 bash/awk/sed만으로 RHEL 6 ~ 10 전체에서 동일하게 동작합니다.

1.1 3중 교차 검증 방식

단순히 파일 한 개만 보는 것이 아니라, 아래 세 축이 모두 같은 인프라를 가리키는지 교차 검증합니다. 하나라도 다른 인프라 값을 가리키면 인프라 혼재로 판단해 실패 처리합니다.

검증 축 참조 파일 및 근거 비교 방식
1축: infra_dnsntp /etc/resolv.conf의 nameserver + /etc/chrony.conf(또는 /etc/ntp.conf)의 server·pool 순서 무관 집합 비교
2축: infra_ldap /etc/openldap/ldap.conf의 URI 집합 + BINDDN + BINDPW 집합/문자열 일치 비교
3축: infra_appl /etc/auto.appl의 /appl storage 이름 사이트 판별 키 겸용 (URI 순서는 a1/a4가 겹칠 수 있어 판별에 쓰지 않음)

1.2 관련 도구와의 연계 구조

연계 도구 관계 및 역할 연계 방식
ldap_setting
(.claude/HPC/ldap_setting)		 설정을 실제로 바꾸는 적용 엔진과 검사 스크립트의 짝 구조
  • ldap_check.sh의 ldap_config.conf는 ../ldap_setting/conf/ldap_config.conf와 동일한 기준 파일을 사용해야 합니다.
  • ../ldap_setting/internal/render/apply_body.sh가 쓰는 설정 형식을 수정하면 ldap_check.sh도 함께 맞춰야 합니다.
  • ../ldap_setting/scripts/deploy_ldap.sh(전체 적용 및 -check-only)와 test_all.sh가 ldap_check.sh 출력(INFO/FAIL)을 집계해 OK_CNT/NG_CNT를 계산합니다.
  • 점검에서 FAIL이 난 호스트만 ng_hosts.txt로 추려 ldap_setting으로 재적용합니다.
pm_monitor
(install_mn)		 OS 설치 완료 서버의 LDAP/H/T 일괄 점검 패널(l 키)
  • pm_monitor.conf에 ldap_check_sh=/경로/ldap_check.sh를 지정하면 TUI에서 l 키를 눌렀을 때 설치 완료 서버를 대상으로 ldap_check.sh를 실행합니다.
  • 출력 INFO<TAB>LDAP<TAB><infra><TAB><site>에서 <infra> 값을 읽어 LDAP 열에 표시하고, FAIL이면 FAIL(비고 ldap_check UNDEFINED)로 표시합니다.
gossh
(.claude/공통/gossh)		 수백 대 노드 동시 점검 실행기 gossh -script -w hosts.txt "bash /user/asdf/ldap_check.sh" 형태로 실행해 호스트별 1줄 결과를 수집합니다.

2. 사전 준비 및 파일 배치 (빌드 불필요)

ldap_check는 순수 Bash 스크립트이므로 빌드 과정이 없습니다(빌드 불필요). 내려받은 뒤 실행 권한을 주고 설정 파일 ldap_config.conf만 채워 배치하면 됩니다.

  1. 실행 권한 부여 bash
  2. 설정 파일 생성 및 권한 잠금 — ldap_config.conf.sample을 복사해 실제 인프라/사이트 값을 채우고 chmod 600을 적용합니다. bash
  3. 표준 배치 (autofs 공유 관리자 경로) — 전 노드가 마운트하는 관리자 경로(예: /user/asdf/)에 스크립트와 설정 파일을 함께 배치합니다. 기본적으로 ldap_check.sh는 자기와 같은 디렉터리의 ldap_config.conf를 읽습니다. bash

    autofs 마운트가 안 된 노드라도 ../ldap_setting/scripts/deploy_ldap.sh 실행 시 해당 노드의 /root로 스크립트를 밀어 넣어 검사한 뒤 삭제하므로 동일하게 점검할 수 있습니다.

  4. 설치 확인 (회귀 테스트) — 실제 장비 없이 fixture로 10개 시나리오를 검증합니다. bash
  5. 전역 명령어 등록 (선택) — 심볼릭 링크로 /usr/local/bin/ldap_check를 등록할 경우 스크립트가 자기 옆의 설정 파일을 자동으로 찾지 못하므로 LDAP_CONFIG 환경변수를 함께 지정해야 합니다. bash > /etc/profile.d/ldap_check.sh # 해제 시 sudo rm -f /usr/local/bin/ldap_check]]>

4. 환경변수 · 설정 키 및 검사 대상

4.1 명령행 인자 및 환경변수

ldap_check.sh는 명령행 인자를 받지 않으며, 아래 환경변수로 동작을 제어합니다.

환경변수 기본값 설명
LDAP_CONFIG 스크립트와 같은 디렉터리의 ldap_config.conf 기준값이 정의된 평문 key = value 설정 파일 경로
ROOT 빈 값 (실제 /etc 기준) 검사 대상 루트 경로. ROOT=/tmp/fixture처럼 지정하면 $ROOT/etc/...를 검사

4.2 ldap_config.conf 설정 키

키 설명
default_site (ldap_setting 공용 항목) 자산현황에서 못 찾은 호스트에 적용할 기본 site (infra.<이름>.site.<site> 중 하나여야 함)
s4.enabled true이면 hostname 접두사 예외 규칙 활성화
s4.prefix 예외를 적용할 hostname 접두사 (예: s4)
s4.services RHEL 8 이상이라도 강제 적용할 서비스 목록 (nslcd,ntp)
infra.<이름>.dns 1차 인프라 판별 키 1 (쉼표 구분, 순서 무관 집합 비교)
infra.<이름>.ntp 1차 인프라 판별 키 2 (쉼표 구분, 순서 무관 집합 비교)
infra.<이름>.uri1~3 LDAP 서버 URI. NONE이면 설정·검사에서 제외
infra.<이름>.binddn / bindpw 바인드 DN 및 비밀번호 (파일 내용과 문자열 일치 비교)
infra.<이름>.site.<사이트>.uri_order 해당 사이트의 URI 순서 (예: uri1,uri2,uri3 — ldap.conf·autofs.conf·sssd/nslcd.conf에서 순서까지 엄격 비교)
infra.<이름>.site.<사이트>.storage /etc/auto.appl의 storage 이름 (인프라 내 고유값, 사이트 판별 키)
infra.<이름>.site.<사이트>.mountpoint /etc/auto.appl의 /appl 원격 경로
infra.<이름>.site.<사이트>.wappl_mount (선택) /etc/auto.appl의 /wappl 원격 경로. 비우거나 생략하면 검사 건너뜀

4.3 OS / s4 분기 및 검사 대상 파일

조건 인증 설정 파일 시각 동기화 설정 파일
RHEL 7 이하 /etc/nslcd.conf /etc/ntp.conf
RHEL 8 이상 (일반) /etc/sssd/sssd.conf /etc/chrony.conf
hostname이 s4로 시작 (RHEL 8 이상 포함, s4.enabled=true) /etc/nslcd.conf (s4.services에 nslcd 포함 시) /etc/ntp.conf (s4.services에 ntp 포함 시)

인프라·사이트 판별이 통과하면 아래 핵심 7개 파일(+ 선택 2개 항목)을 순서대로 검증합니다.

  1. /etc/resolv.conf (nameserver 집합)
  2. /etc/chrony.conf 또는 /etc/ntp.conf (server/pool 집합)
  3. /etc/openldap/ldap.conf (URI 순서 엄격 일치 + BINDDN + BINDPW)
  4. /etc/autofs.conf (ldap_uri 순서 일치)
  5. /etc/autofs_ldap_auth.conf (user, secret 일치)
  6. /etc/sssd/sssd.conf ([domain/... 섹션의 ldap_uri, ldap_default_bind_dn, ldap_default_authtok) 또는 /etc/nslcd.conf (uri, binddn, bindpw)
  7. /etc/auto.appl (/appl의 storage와 mountpoint)
  8. (선택) /etc/auto.appl의 /wappl (wappl_mount가 설정된 사이트인 경우)
  9. (선택) /etc/sudo-ldap.conf (노드에 해당 파일이 존재하는 경우 URI 일치)

5. 출력 형식 및 종료 코드

현재 ldap_check.sh는 gossh 대량 집계, ldap_setting/scripts/deploy_ldap.sh의 OK_CNT/NG_CNT 집계, pm_monitor의 l 키 연계를 위해 호스트당 최종 요약 1줄만 표준출력으로 출력합니다. (내부 report() 함수는 파일별 결과를 화면에 찍지 않고 종료 코드만 추적합니다.)

text
종료 코드 의미
0 3중 교차 검증 및 검사 항목 전부 OK (INFO<TAB>LDAP<TAB><infra><TAB><site> 출력)
1 인프라 불일치(3축 혼재), 사이트 미판별, 또는 7개(+ 선택 2개) 검사 항목 중 불일치 발생 (FAIL<TAB>LDAP<TAB>UNDEFINED)
2 판별 불가 — 설정 파일(ldap_config.conf) 없음, 정의된 인프라 없음, OS 버전 판정 실패

README.md 예시에는 파일별 상세 줄(OK\t/zxcv\tresolv.conf 등)이 함께 소개되어 있으나, 실제 스크립트(ldap_check.sh 및 ARCHITECTURE.md)는 여러 노드의 출력을 한 줄씩 모으기 위해 최종 1줄 요약(INFO/FAIL)만 출력하도록 변경되어 있습니다. 어느 파일이 틀렸는지 세부 원인이 필요할 때는 대상 노드에 직접 접속해 설정 파일을 대조하거나 ldap_setting의 -dry-run으로 차이를 확인하세요.

6. 주의사항

  • 참고용 도구 & 실서비스 확인: 본 스크립트는 설정 파일의 텍스트 내용만 검사하며, sssd/nslcd/autofs 데몬이 실제로 기동 중인지 또는 LDAP 서버에 실제 바인드가 되는지까지는 확인하지 않습니다. 최종 확인은 대상 서버에서 id <계정>, ls /appl, systemctl status sssd 등으로 직접 검증하세요.
  • 평문 자격증명 보안: ldap_config.conf에는 bindpw가 평문으로 들어갑니다. 반드시 chmod 600을 유지하고 Git 저장소에 커밋하지 마세요(공유 경로 배치 시 접근 권한 확인 필수).
  • 대량 FAIL 발생 시 원인 확인: 정상 노드까지 대거 FAIL로 나오면 ldap_config.conf의 기준값(특히 ../ldap_setting/conf/ldap_config.conf와의 동기화 여부)이 실제 환경과 어긋나지 않았는지 먼저 점검하세요.
  • jq 금지: 대상 노드에 jq가 없으므로 향후 유지보수 시에도 JSON 파서를 도입하지 마세요.
