표준 프로세스(AWX)를 먼저 쓰십시오. LDAP 점검은 표준 프로세스(AWX)로 하는 것이 원칙입니다. ldap_check 는 너무 바쁘거나 AWX 로 실행할 수 없는 서버에만 쓰십시오.

이 문서는 질문-답변(Q&A) 형식입니다. 각 절은 다른 절을 읽지 않아도 이해되도록 도구 이름·명령·파일 이름을 반복해서 적었습니다. 도구 이름은 ldap_check 이고, 실행 파일은 ldap_check.sh 입니다.

0. 도구 요약 (핵심 사실)

항목내용
도구 이름ldap_check (실행 파일 ldap_check.sh)

설정을 바꾸는 짝 도구ldap_setting 입니다. ldap_check 에서 FAIL 이 나온 서버에 ldap_setting 으로 다시 적용합니다.
실행 명령한 서버: bash /user/asdf/ldap_check.sh
여러 서버: gossh -script -w hosts.txt "bash /user/asdf/ldap_check.sh"

2. 처음 사용하기 전에 무엇을 준비하나?

  1. ldap_check.sh 와 기준 파일 ldap_config.conf 를 같은 폴더에 둡니다. 표준 위치는 모든 서버가 마운트하는 관리자 경로 /user/asdf/ 입니다.
  2. 기준 파일이 없으면 ldap_config.conf.sample 을 ldap_config.conf 로 복사하고 인프라·사이트 값을 채웁니다.
  3. 기준 파일의 권한을 600 으로 바꿉니다: chmod 600 ldap_config.conf. 이 파일에는 bindpw 가 평문으로 들어 있습니다.
  4. ldap_config.conf 는 ldap_setting 의 conf/ldap_config.conf 와 같은 내용이어야 합니다. 두 파일이 다르면 정상 서버도 FAIL 이 나옵니다.

ldap_check.sh 는 빌드가 필요 없습니다. 명령행 인자도 받지 않습니다.

3. ldap_check 는 무엇을 어떻게 점검하나?

3.1 인프라 판별: 3가지 기준이 같은 인프라를 가리켜야 한다

ldap_check.sh 는 아래 3가지 기준으로 서버의 인프라를 판별합니다. 3가지가 모두 같은 인프라를 가리켜야 통과합니다. 하나라도 다른 인프라를 가리키면 "인프라 혼재"로 보고 FAIL 을 출력합니다.

기준보는 파일비교 방법
1. DNS·NTP/etc/resolv.conf 의 nameserver, /etc/chrony.conf(또는 /etc/ntp.conf)의 server·pool순서와 관계없이 집합으로 비교
2. LDAP/etc/openldap/ldap.conf 의 URI, BINDDN, BINDPWURI 는 집합, BINDDN·BINDPW 는 문자열로 비교
3. appl 스토리지/etc/auto.appl 의 /appl 스토리지 이름사이트 판별에도 씁니다.

3.2 OS 에 따라 어떤 파일을 보나?

조건인증 설정 파일시간 동기화 설정 파일
RHEL 7 이하/etc/nslcd.conf/etc/ntp.conf
RHEL 8 이상/etc/sssd/sssd.conf/etc/chrony.conf
호스트 이름이 s4 로 시작 (s4.enabled=true)s4.services 에 nslcd 가 있으면 /etc/nslcd.confs4.services 에 ntp 가 있으면 /etc/ntp.conf

3.3 판별을 통과하면 어떤 파일을 점검하나?

  1. /etc/resolv.conf — nameserver 집합
  2. /etc/chrony.conf 또는 /etc/ntp.conf — server/pool 집합
  3. /etc/openldap/ldap.conf — URI 순서, BINDDN, BINDPW
  4. /etc/autofs.conf — ldap_uri 순서
  5. /etc/autofs_ldap_auth.conf — user, secret
  6. /etc/sssd/sssd.conf(ldap_uri, ldap_default_bind_dn, ldap_default_authtok) 또는 /etc/nslcd.conf(uri, binddn, bindpw)
  7. /etc/auto.appl — /appl 스토리지와 마운트 경로
  8. (선택) /etc/auto.appl 의 /wappl — 사이트에 wappl_mount 가 있을 때만
  9. (선택) /etc/sudo-ldap.conf — 서버에 이 파일이 있을 때만 URI 점검

URI 순서는 사이트마다 정해진 순서(uri_order)와 정확히 같아야 합니다.

6. 문제가 생기면?

  • 어느 파일이 틀렸는지 알고 싶다: ldap_check.sh 는 요약 1줄만 출력합니다. 그 서버에 접속해서 3.3절의 파일을 기준 파일과 직접 비교하십시오. 또는 ldap_setting 의 -dry-run 으로 바뀔 내용을 확인하십시오.
  • 정상 서버도 대부분 FAIL 이다: 기준 파일이 잘못되었을 수 있습니다. ldap_config.conf 가 ldap_setting 의 conf/ldap_config.conf 와 같은지 먼저 확인하십시오.
  • 종료 코드가 2 이다: ldap_config.conf 가 ldap_check.sh 옆에 있는지 확인하십시오. 다른 위치에 있으면 LDAP_CONFIG 로 경로를 주십시오.
  • gossh 실행이 느리다: 명령에 /user/ 경로가 있으면 gossh 가 autofs 보호를 위해 동시 실행 수를 450 으로 줄입니다. 정상 동작입니다. -cf 로 무리하게 올리지 마십시오.
  • 설정 파일 내용만 점검합니다. sssd/nslcd/autofs 서비스가 실행 중인지, LDAP 서버에 실제로 로그인되는지는 점검하지 않습니다. 대상 서버에서 id <계정>, ls /appl, systemctl status sssd 로 직접 확인하십시오.
  • 비밀번호가 평문입니다. ldap_config.conf 의 권한을 600 으로 유지하십시오. 이 파일을 다른 사람과 공유하지 마십시오.

7. 자주 묻는 질문 (FAQ)

Q. ldap_check 는 무엇을 하는 도구인가요?
A. 서버의 LDAP · DNS · NTP · autofs 설정 파일이 기준과 같은지 점검하고, 서버의 인프라·사이트를 판별하는 읽기 전용 Bash 스크립트입니다.

Q. ldap_check 와 ldap_setting 은 무엇이 다른가요?
A. ldap_check 는 점검만 합니다. ldap_setting 은 설정을 바꿉니다. 보통 ldap_check 로 FAIL 서버를 찾고 ldap_setting 으로 다시 적용합니다.

Q. 서버 수백 대를 한 번에 점검하려면?
A. gossh -script -w hosts.txt "bash /user/asdf/ldap_check.sh" 를 실행합니다.

Q. FAIL LDAP UNDEFINED 는 무슨 뜻인가요?
A. 인프라가 섞여 있거나, 사이트를 판별하지 못했거나, 점검 파일 중 하나가 기준과 다르다는 뜻입니다. 그 서버를 ldap_setting 으로 다시 적용하십시오.

Q. AWX 가 있는데 이 도구를 써도 되나요?
A. AWX 표준 프로세스를 먼저 쓰십시오. AWX 로 실행할 수 없거나 너무 바쁠 때만 ldap_check 를 쓰십시오.

Q. RHEL 6 서버도 점검되나요?
A. 예. RHEL 6 ~ 10 을 지원합니다.

Q. 결과가 INFO 이면 LDAP 로그인이 확실히 되나요?
A. 아니요. 설정 파일 내용만 같다는 뜻입니다. id <계정> 으로 직접 확인하십시오.
