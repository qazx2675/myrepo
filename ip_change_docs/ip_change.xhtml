표준 프로세스(AWX)를 먼저 쓰십시오. IP 변경은 표준 프로세스(AWX)로 하는 것이 원칙입니다. ip_change 는 너무 바쁘거나 AWX 로 실행할 수 없는 서버에만 쓰십시오.

이 문서는 질문-답변(Q&A) 형식입니다. 각 절은 다른 절을 읽지 않아도 이해되도록 도구 이름·명령·파일 이름을 반복해서 적었습니다. 도구 이름은 ip_change 입니다. 실행 파일은 bin/ip-change-engine(엔진)과 scripts/run_ip_change.sh(래퍼) 입니다.

0. 도구 요약 (핵심 사실)

항목내용
도구 이름ip_change (엔진 ip-change-engine)
하는 일여러 RHEL 서버의 IP 와 게이트웨이를 한 번에 바꿉니다. ifcfg-* 파일에서 IPADDR 와 GATEWAY 두 키만 바꿉니다. 다른 줄은 그대로 둡니다.
실행 명령./bin/ip-change-engine -targets conf/<계정명>.txt -u root -i ~/.ssh/id_rsa
입력 파일conf/<계정명>.txt — 한 줄에 호스트이름 새IP
게이트웨이새 IP 의 마지막 숫자를 1 로 바꾼 값입니다 (예: 3.3.3.3 → 3.3.3.1). /24 서브넷을 전제로 합니다.
네트워크 재시작하지 않습니다. 파일만 바꿉니다. 새 IP 는 네트워크 재시작 또는 재부팅 때 반영됩니다.
백업바꾸기 전에 <ifcfg파일>.bak.<STAMP> 를 만듭니다. -rollback 으로 되돌립니다.
미리보기(dry-run)없습니다. 그래서 1~2대에 먼저 적용합니다 (4절).
필요 환경관리 서버: bin/ip-change-engine(RHEL 6 은 bin/ip-change-engine_os6), gossh v2. 대상 서버: SSH 접속 가능, bash, awk, sed, hostname -I 또는 ip
다른 도구와의 관계auto_setup 의 m 메뉴(1 IP 변경, 3 IP+LDAP 변경, 4 원복)가 ip-change-engine 을 실행합니다.

SSH 로 접속할 수 없는 VM 은 이 도구를 쓸 수 없습니다. ip_change 는 gossh(SSH)로 접속합니다. IP 가 잘못 할당되어 네트워크가 끊긴 RHEL 8.10 VM 은 vm-ip-change(vCenter API IP 자동변경) 도구를 쓰십시오.

1. 어떤 일을 하려면 어떤 명령을 실행하나? (명령 찾기)

하고 싶은 일실행 명령서버 변경 여부
1~2대에 먼저 IP 를 바꾼다./bin/ip-change-engine -targets conf/canary.txt -u root -i ~/.ssh/id_rsa있음
목록 전체의 IP 를 바꾼다./bin/ip-change-engine -config conf/ip_change.conf -targets conf/testuser.txt -u root -i ~/.ssh/id_rsa있음
래퍼로 IP 를 바꾼다cd scripts; GOSSH_ARGS="-i ~/.ssh/id_rsa" ./run_ip_change.sh있음
가장 최근 백업으로 되돌린다./bin/ip-change-engine -targets conf/rollback_hosts.txt -rollback -u root -i ~/.ssh/id_rsa있음
특정 백업 시점으로 되돌린다./bin/ip-change-engine -targets conf/rollback_hosts.txt -rollback -rollback-to <STAMP> -u root -i ~/.ssh/id_rsa있음
auto_setup 화면에서 IP 를 바꾼다auto_setup TUI → m → 1 IP 변경 (5절 참고)있음
IP 와 LDAP 을 같이 바꾼다auto_setup TUI → m → 3 IP+LDAP 변경있음

2. 처음 사용하기 전에 무엇을 준비하나?

  1. 관리 서버의 ip_change 폴더로 이동합니다.
  2. 실행 권한을 줍니다: chmod +x bin/ip-change-engine bin/ip-change-engine_os6 scripts/*.sh
  3. gossh 가 v2 인지 확인합니다: gossh -h | grep -E '\-cf|\-b'. v1 은 명령의 따옴표를 잘라 원격 실행이 깨집니다.
  4. (선택) 설정 파일을 복사합니다: cp conf/ip_change.conf.sample conf/ip_change.conf. 파일이 없으면 기본값 /etc/sysconfig/network-scripts 를 씁니다.
  5. 대상 목록을 만듭니다: cp conf/testuser.txt.sample conf/<계정명>.txt. 한 줄에 호스트이름 새IP 를 적습니다.
text

래퍼(run_ip_change.sh)를 쓰려면 먼저 수정해야 합니다. select_user_context() 함수는 비어 있습니다. 이 함수에 계정 선택 코드를 넣고 RUN_USER 에 계정명을 넣으십시오. 그러면 래퍼가 conf/${RUN_USER}.txt 를 읽습니다.

3. ip_change 는 무엇을 어떻게 바꾸나?

항목내용
찾는 파일/etc/sysconfig/network-scripts(network_scripts_dir)의 ifcfg-* 중에서 IPADDR=<현재 IP> 인 파일. RHEL 9 이상에서 rhel9_path 를 지정하면 그 폴더를 씁니다.
현재 IP 판별서버 인터페이스에 실제로 할당된 주소를 읽습니다(hostname -I, 실패하면 ip -4 addr). /etc/hosts 와 DNS 는 쓰지 않습니다.
바꾸는 키IPADDR 와 GATEWAY 두 개만. BOOTPROTO, DEVICE, DNS1 등은 그대로 둡니다.
게이트웨이 계산새 IP 의 마지막 숫자를 1 로 바꿉니다. 넷마스크는 확인하지 않습니다.
네트워크 재시작하지 않습니다. SSH 연결은 끊기지 않습니다.
지원하지 않는 형식NetworkManager keyfile(.nmconnection)은 지원하지 않습니다. ifcfg(KEY=VALUE) 형식만 지원합니다.

4. 표준 적용 절차는 무엇인가? (안전 순서)

ip-change-engine 에는 -dry-run 이 없습니다. 아래 순서를 꼭 지키십시오.

  1. 대상 서버에 접속되는지 확인합니다: gossh -w conf/canary_hosts.txt "hostname -I"
  2. 1~2대만 담은 목록(conf/canary.txt)으로 먼저 적용합니다: ./bin/ip-change-engine -targets conf/canary.txt -u root -i ~/.ssh/id_rsa
  3. 그 서버에 접속하고 ifcfg-* 의 IPADDR, GATEWAY, 백업 파일(.bak.<STAMP>)을 확인합니다.
  4. 전체 목록으로 적용합니다: ./bin/ip-change-engine -config conf/ip_change.conf -targets conf/<계정명>.txt -u root -i ~/.ssh/id_rsa
  5. 서버 몇 대를 무작위로 골라 직접 확인합니다.
  6. 계획한 시간에 네트워크를 재시작하거나 재부팅합니다. 새 IP 로 통신되는지 확인합니다.

출력 예시 (성공은 초록, 실패는 굵은 빨강):

text 3.3.3.3 hostname2 -> 2.2.2.2 ------------------------------------------------------------ hostname1 192.168.1.10 -> 3.3.3.3 (GW 3.3.3.1) hostname2 192.168.1.11 -> 2.2.2.2 (GW 2.2.2.1)]]>

5. auto_setup 의 m 메뉴로 IP 를 바꾸려면? (os8_mgmt 전용)

  1. /etc/auto_setup/auto_setup.conf 에 enable_ip_change=y 를 씁니다. 또는 auto_setup --admin 으로 엽니다.
  2. (선택) ip_engine=/경로/ip-change-engine 을 씁니다. 비우면 auto_setup 과 같은 폴더, 그다음 PATH 에서 찾습니다. 보통 /usr/local/bin/ip-change-engine 에 둡니다.
  3. ip_change.conf 는 auto_setup.conf 와 같은 폴더 또는 /etc/auto_setup/ip_change.conf 에서 읽습니다.
  4. TUI 에서 m → 1 IP 변경(또는 3 IP+LDAP 변경)을 고릅니다.
  5. 실행 user 를 고릅니다.
  6. 호스트이름 새IP 목록을 붙여 넣고 Ctrl+D 를 누릅니다. 구분 기호는 공백·탭·쉼표·=·-> 를 씁니다.
  7. 미리보기에서 게이트웨이(.1)와 "진행 중 job 중복" 경고를 확인합니다.
  8. 정확히 yes 를 입력합니다.
  • auto_setup 은 os8_mgmt 에서 먼저 실행합니다. 응답하지 않은 서버만 os6_mgmt 를 거쳐 한 번 더 실행합니다.
  • 실행 중에 진행 화면(-monitor)이 나옵니다. Ctrl+X → y 로 멈춥니다.
  • 결과는 <상태폴더>/changes/<user>/<YYYYmmddHHMMSS>_ip.json 에 저장합니다.
  • 3 IP+LDAP 변경 은 IP 를 먼저 바꿉니다. IP 변경에 실패한 서버는 LDAP 을 건너뜁니다.

6. 잘못 바꿨으면 어떻게 되돌리나? (롤백)

  1. 되돌릴 서버 목록을 만듭니다. 한 줄에 호스트 이름만 적어도 됩니다.
  2. 가장 최근 백업으로 되돌립니다: ./bin/ip-change-engine -targets conf/rollback_hosts.txt -rollback -u root -i ~/.ssh/id_rsa
  3. 특정 시점으로 되돌리려면 -rollback-to <STAMP> 를 추가합니다.
  • 한 서버에 최신 STAMP 백업이 있는 ifcfg 파일이 둘 이상이면 -rollback-to 로 시점을 지정해야 합니다.
  • 롤백 뒤에도 .bak.* 백업 파일은 지우지 않습니다.
  • auto_setup 의 m → 4 원복 은 그 user 의 지난 IP 변경 기록으로 가장 최근 백업을 복원합니다. 원복한 기록에는 ip_rolled_back 표시를 붙이고 다음 목록에서 뺍니다. 과거 특정 시점은 엔진을 직접 실행하십시오.

8. 문제가 생기면?

  • "ifcfg 파일을 찾지 못함" 실패: 서버가 .nmconnection 형식만 쓰거나, ifcfg 의 IPADDR 가 현재 IP 와 다릅니다. 서버에서 hostname -I 와 ifcfg-* 를 직접 비교하십시오.
  • 게이트웨이가 틀렸다: 서브넷이 /24 가 아닙니다. 이 도구는 항상 .1 을 씁니다. 롤백한 뒤 직접 수정하십시오.
  • 적용했는데 IP 가 안 바뀌었다: 정상입니다. 네트워크를 재시작하지 않기 때문입니다. 네트워크 재시작 또는 재부팅 뒤에 반영됩니다.
  • 원격 실행이 이상하게 실패한다: gossh 가 v1 인지 확인하십시오. v2 를 쓰십시오.
  • OS 설치 감시 중인 서버를 바꿨다: auto_setup 의 상태 추적이 끊길 수 있습니다. 진행 중 job 과 겹치지 않게 하십시오.

결과를 직접 확인하십시오. 성공 출력(초록 OK)만 믿지 마십시오. 적용과 롤백 뒤에는 서버 몇 대를 무작위로 골라 ifcfg-* 의 IPADDR, GATEWAY, 백업 파일을 직접 확인하십시오.

9. 자주 묻는 질문 (FAQ)

Q. ip_change 는 무엇을 하는 도구인가요?
A. 여러 RHEL 서버의 ifcfg-* 파일에서 IPADDR 와 GATEWAY 만 바꾸는 도구입니다. 실행 파일은 bin/ip-change-engine 입니다.

Q. 서버 IP 를 바꾸려면 어떤 도구를 쓰나요?
A. 먼저 AWX 표준 프로세스를 쓰십시오. AWX 로 할 수 없으면 SSH 가 되는 서버는 ip_change, SSH 가 안 되는 VM 은 vm-ip-change 를 씁니다.

Q. 미리보기(dry-run)가 있나요?
A. 없습니다. 1~2대에 먼저 적용하고 확인한 뒤 전체에 적용하십시오. auto_setup 의 m 메뉴는 미리보기 화면을 보여 줍니다.

Q. 적용하면 바로 새 IP 로 바뀌나요?
A. 아니요. 파일만 바꿉니다. 네트워크 재시작 또는 재부팅 뒤에 새 IP 가 됩니다.

Q. 게이트웨이는 어떻게 정하나요?
A. 새 IP 의 마지막 숫자를 1 로 바꿉니다. /24 서브넷이 아니면 쓰지 마십시오.

Q. 되돌리려면?
A. ./bin/ip-change-engine -targets <목록> -rollback -u root -i ~/.ssh/id_rsa 를 실행합니다.

Q. RHEL 9 서버도 되나요?
A. ifcfg 파일을 쓰는 서버만 됩니다. .nmconnection 만 쓰는 서버는 지원하지 않습니다.
