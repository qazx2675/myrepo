도구명: ip_change (bin/ip-change-engine + scripts/run_ip_change.sh) — RHEL 노드 IP · 게이트웨이 일괄 변경 엔진

양식 유형: T3 (설정 변경 · 적용 엔진형)

원본 경로 (origin/master): .claude/HPC/ip_change/

동작 환경 및 의존성: 관리 노드 Go 1.26.5(외부 의존성 없음, 폐쇄망 bin/ip-change-engine_os6 내장) + gossh v2 필수 / 대상 노드 bash · awk · sed · hostname -I(또는 ip)

연계 도구: gossh v2 (원격 실행 전달), auto_setup (TUI m 변경 메뉴 1 IP 변경 · 3 IP+LDAP 변경 · 4 원복)

한 줄 요약: RHEL 대상 노드의 ifcfg 파일 전체를 덮어쓰지 않고 IPADDR · GATEWAY 두 키만 수술적으로 갱신·백업(.bak.<시각>)·롤백하는 병렬 IP 변경 도구입니다.

1. 개요 및 변경 대상 (실제 수정하는 파일·방식)

ip_change는 Red Hat Enterprise Linux(RHEL) 다수 노드의 서비스 IP 및 게이트웨이 설정을 일괄 변경하기 위해 설계된 Go 기반 엔진과 Bash 래퍼 세트입니다. 관리 노드에서 대상 전체를 포함한 단일 apply 스크립트를 생성한 뒤 gossh v2를 통해 대상 노드에 base64 인코딩 형태로 전송·실행합니다.

1.1 실제 수정 대상 및 동작 원칙

구분 세부 내용
수정 대상 파일 대상 노드의 network_scripts_dir(기본 /etc/sysconfig/network-scripts) 또는 RHEL 9+ 환경에서 설정된 경우 rhel9_path 아래의 ifcfg-* 파일 중 현재 인터페이스 IPv4와 IPADDR=<현재 IP>가 일치하는 파일
실제 변경 키 파일을 통째로 덮어쓰지 않고 IPADDR과 GATEWAY 두 키만 갱신 (BOOTPROTO, DEVICE, DNS1 등 운영자가 지정한 기존 지시자는 유지)
현재 IP 판별 기준 /etc/hosts나 DNS에 의존하는 getent hosts 대신, 노드 인터페이스에 실제 할당된 주소를 읽는 hostname -I(실패 시 ip -4 addr) 사용
게이트웨이 계산 규칙 새 IP 주소의 마지막 옥텟을 1로 치환하여 고정 계산 (예: 3.3.3.3 → 게이트웨이 3.3.3.1, /24 서브넷 전제)
서비스 재시작 여부 네트워크 서비스를 재시작하지 않음 (설정 파일 변경·재읽기 검증에만 집중하며, 실제 네트워크 반영은 운영자가 네트워크 재시작 또는 재부팅 시 수행)
미지원 형식 rhel9_path에서도 ifcfg(KEY=VALUE) 형식만 지원하며 NetworkManager keyfile(.nmconnection, [ipv4] 섹션) 형식은 미지원

1.2 관련 도구 연계 (gossh v2 및 auto_setup m 메뉴)

  • gossh v2 연동 (필수): ip-change-engine은 gossh를 서브프로세스로 호출합니다. gossh v1(구버전)에는 명령 앞뒤 따옴표를 잘라내 원격 주입이 깨지는 버그가 있으므로 반드시 gossh v2(gossh -h에 -cf, -b 옵션이 표시되는 버전)를 사용해야 합니다.
  • gossh 위험어 가드 회피 인코딩: internal/remote는 생성된 스크립트를 base64로 인코딩한 뒤 spaceOut(두 글자마다 공백 삽입)으로 감싸 전송하고 원격에서 tr -d ' '로 복원합니다. 이는 긴 base64 문자열에 reboot/halt/ddc 같은 gossh 위험 키워드 조각이 우연히 섞여 실행이 차단되는 현상을 방지합니다.
  • auto_setup TUI m 메뉴 통합: os8_mgmt에서 실행 중인 auto_setup의 변경 메뉴(m)에서 1 IP 변경, 3 IP+LDAP 변경(IP 먼저 실행하며 IP 실패 호스트는 LDAP 건너뜀), 4 원복을 선택하면 auto_setup이 ip-change-engine 바이너리를 직접 호출합니다.

SSH 불통 VM과의 구분: ip_change는 대상 노드에 gossh(SSH)로 접속할 수 있어야 동작합니다. IP 오할당 등으로 네트워크 접속 자체가 불가능한 RHEL 8.10 VM의 IP를 변경할 때는 vCenter Guest Operations API 기반의 vm-ip-change(.claude/VM/vCenter API IP 자동변경)를 사용해야 합니다.

4. CLI 플래그 · 설정 키 · 입력 파일 상세 표

4.1 bin/ip-change-engine CLI 플래그

플래그 기본값 설명
-targets (필수) 대상 목록 파일 경로 (hostname 변경될ip 형식, -rollback 시에는 hostname 1열만 있어도 동작)
-config ./ip_change.conf 설정 파일 경로 (파일이 없어도 기본값으로 동작)
-gossh gossh gossh 실행 파일 경로
-u root SSH 접속 계정
-p (없음) SSH 접속 비밀번호
-i (없음) SSH 개인키 파일 경로
-P 22 SSH 포트 번호
-c 0 (gossh 기본값) gossh 동시 접속 수
-t 0 (gossh 기본값) gossh 접속 타임아웃(초)
-remote-path /root/ip_change_apply.sh 원격 노드에 일시 생성할 스크립트 경로 (실행 완료 후 삭제됨)
-rollback false IP 변경을 되돌림 (각 노드의 <ifcfg>.bak.<STAMP> 복원)
-rollback-to (없음) 복원할 백업 STAMP 지정 (미지정 시 가장 최근 백업 복원)
-monitor false 60초 초과 시 /dev/tty에 호스트별 진행 화면(↑/↓ · ←/→ · Enter) 표시, Ctrl+C는 5초 안에 3회 입력 시 종료(종료코드 130, 롤백 없음). 통합 스크립트(change.sh) 및 auto_setup이 활성화

5. 백업 및 롤백 방법

ip-change-engine은 파일을 수정하기 직전 한 실행당 한 번 원본 ifcfg 파일을 <ifcfg파일경로>.bak.<STAMP> 형태로 백업합니다. 잘못된 IP/GW가 기록된 경우 수동 편집 대신 내장 롤백 기능(internal/render/rollback_body.sh)으로 원복하십시오.

bash -u root -i ~/.ssh/id_rsa]]>
  • 특정 STAMP 지정이 필요한 경우: 한 노드 안에 최신 STAMP 백업을 가진 ifcfg 파일이 둘 이상 발견되면 -rollback-to로 대상을 명확히 지정해야 합니다.
  • 백업 보존 정책: 롤백 후에도 .bak.* 백업 파일은 삭제하지 않고 남깁니다.
  • auto_setup m 메뉴 원복 (4 원복): auto_setup은 user의 이전 IP 변경 기록을 자동으로 채워 가장 최근 백업 기준으로 -rollback을 호출합니다. 특정 과거 STAMP를 고르려면 엔진을 단독으로 실행하십시오. 원복 성공 시 기록 파일에 ip_rolled_back이 표시되어 다음 원복 목록에서 제외됩니다.

6. 주의사항 및 랜덤 서버 실접속 교차검증 필수

[필수 경고 — 설정 변경 도구 · 랜덤 서버 실접속 교차검증]

  • 100% 신뢰 금지 (보조 도구로 사용): 엔진의 성공 출력(초록색 OK)만 믿지 말고, 적용 및 롤백 후 반드시 대상 서버 중 무작위로 몇 대를 직접 접속해 실제 ifcfg-* 파일의 IPADDR · GATEWAY와 백업 파일을 눈으로 확인하십시오.
  • /24 게이트웨이 고정 전제: 게이트웨이는 항상 새 IP의 마지막 옥텟을 1로 고정 계산합니다(넷마스크 미검증). /24가 아닌 서브넷 환경에서는 그대로 사용하면 잘못된 게이트웨이가 기록됩니다.
  • 네트워크 서비스 미재시작: 이 도구는 설정 파일만 수정하고 네트워크를 재시작하지 않습니다. 재부팅이나 네트워크 재기동 전까지는 기존 IP가 유지되며, 재기동 후 실제 통신이 되는지 추가 확인이 필요합니다.
  • RHEL 9+ NetworkManager keyfile 미지원: .nmconnection 형식만 사용하는 환경에서는 ifcfg 파일을 찾지 못해 실패하거나 누락될 수 있습니다.
  • 진행 중 auto_setup 작업 주의: OS 설치 감시 중인 호스트의 IP를 변경하면 이후 상태 추적이 끊길 수 있습니다.
