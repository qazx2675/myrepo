# AWX 노드정보 V2 스크립트 - 직접 칠 명령어 모음 (각 명령 위에 설명)

# ===== Step 0. 코드를 대상 서버로 가져오기 =====

# [작성 머신] master 에 올린 뒤 (이미 푸시했다면 생략)
git push origin master

# [대상 서버(랩 .58)] master 체크아웃으로 이동
cd /root/saccae-src

# [대상 서버] 최신 상태로 맞춤
git fetch && git reset --hard origin/master

# [대상 서버] 이 호스트는 sparse-checkout 이므로 새 폴더를 추가해야 파일이 생김 (awxkit 포함)
git sparse-checkout add ".claude/HPC/awx_script" ".claude/HPC/awxkit"

# [대상 서버] 작업 디렉터리로 이동
cd /root/saccae-src/.claude/HPC/awx_script

# (대안) 폐쇄망/다른 서버: 이 폴더만 담긴 단독 브랜치를 받기
git clone -b awx-script-standalone https://github.com/qazx2675/myrepo.git awx_script
cd awx_script

# ===== Step 1. awxkit 배치 (01/02 와 같은 디렉터리에 awxkit/ 가 있어야 함) =====

# awxkit 를 복사 (저장소 안이면 .claude/HPC/awxkit, 단독 브랜치면 따로 가져와야 함)
cp -r /root/saccae-src/.claude/HPC/awxkit ./awxkit

# awxkit 폐쇄망 빌드 (vendor 사용)
bash awxkit/setup.sh

# ===== Step 2. 현장 값 채우기 =====

# 최상단 빈 변수 7개(repohost, svr_dir, ai_server_list, day_print[선택], lacp_comment, inventory_delete_host, infra_alias[선택])와
# (선택) os6_mgmt 재조사: os6_host/os6_user/os6_dir/os6_gossh 네 개를 모두 채우면 os8_mgmt 접속 불가 호스트를 os6_mgmt 에서 다시 확인(os6_dir 은 두 서버 공유 경로, ssh 키 인증 필요). 비우면 생략
# user(){ } 는 info_mn.sh/info.sh 를 쓰는 현장 코드가 들어 있음: user_route="" 에 경로를 채움
vi 01.AWX_nodeinfo_V2.sh

# ===== Step 3. 사전 점검 =====

# 문법 검사
bash -n 01.AWX_nodeinfo_V2.sh && bash -n 02.source_dhcp_pxe.sh

# 정적 분석 (설치되어 있으면)
shellcheck -S warning 01.AWX_nodeinfo_V2.sh 02.source_dhcp_pxe.sh

# 목업 E2E 테스트 (실제 awxkit/ssh 를 호출하지 않음, 약 80초). 스크립트 원본에는 값을 넣지 않고 스크래치 복사본에만 주입
bash test/run_tests.sh

# ===== Step 4. 실제 실행 =====

# 호스트명(nodeinfo Y) 또는 12필드/msg 내용(nodeinfo N)을 ${user}.txt 에 준비
vi <user>.txt

# 01 실행: awx 사용여부 → 작업진행여부 → (메뉴) su → 02 자동 실행
bash 01.AWX_nodeinfo_V2.sh

# 02 단독 실행 (인자: <yml>=<infra>,<os>,<boot>,<splunk>)
bash 02.source_dhcp_pxe.sh <user> <yml>=<infra>,<os>,<boot>,<splunk>

# 02 단독 실행 (대화형, 인자 없음)
bash 02.source_dhcp_pxe.sh <user>

# ===== Step 5. 결과 확인 =====

# 실행 로그
cat LOG/<user>.log

# 가공된 등록 대상(12필드)
cat <user>.txt

# DHCP 삭제 정보(누적)
cat dhcp_pool/dhcp_pool_delete_info.txt

# LDAP/LACP 점검 원본 결과
cat tmp/all_<user>

# 설정 변경 후에는 임의의 서버 몇 대에서 실제로 반영되었는지 직접 확인할 것

# ===== Step 6. 다른 경로에서 실행 · auto 모드 · setup/ 가이드·업데이트 (0.6.0~) =====

# 다른 디렉터리에서 실행해도 된다 (01 이 자기 위치로 이동)
bash /path/to/awx_script/01.AWX_nodeinfo_V2.sh

# auto 모드: 01 의 nodeinfo 사용여부 = n, 02 의 OS 버전 = 2025 를 자동 답변 (AWX_AUTO 가 없으면 기존처럼 직접 묻는다)
AWX_AUTO=1 AWX_AUTO_NODEINFO=n AWX_AUTO_OS=2025 bash 01.AWX_nodeinfo_V2.sh
# AWX_AUTO_OS 는 2024 2025 2026 2026-OPC_MDP 2026-ECAD_TCAD default 중 하나 (그 밖의 값이면 auto 를 끄고 직접 묻는다)
# 자동 답변: 01 nodeinfo 사용여부 / 작업진행 Y / 인벤토리 소스 su, 02 OS 버전 / 옵션 확인 Y. user 메뉴는 직접 답한다
# (0.6.1~) AWX_USER=<user> : user 메뉴 생략 (영문/숫자/._- 만, 틀리면 경고 후 메뉴)
# (0.6.1~) AWX_VERIFY_FILE=<파일> : 등록 후 확인의 대상 서버 목록을 stdin 대신 파일에서 읽음 (없거나 비면 stdin)
AWX_AUTO=1 AWX_AUTO_NODEINFO=n AWX_AUTO_OS=2025 AWX_USER=hong AWX_VERIFY_FILE=/tmp/targets.txt bash 01.AWX_nodeinfo_V2.sh < /dev/null

# 빈 변수 입력 가이드 (setup/vars.manifest 기준, 생성물이라 직접 고치지 말 것)
bash setup/setup_guide.sh

# 현장 사본 업데이트: 미리보기 → 적용 → 되돌리기 (0.6.1 은 0.6.0 변경 포함 누적, 신규 변수 없음, 현장 값·주석 보존)
bash setup/update_v0.6.1.sh --dry
bash setup/update_v0.6.1.sh
bash setup/update_v0.6.1.sh --undo
