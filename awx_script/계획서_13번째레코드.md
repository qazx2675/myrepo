# 계획서 — AWX yml 분류용 "13번째 레코드" 추가

작성일 2026-11-04 · 대상 `01.AWX_nodeinfo_V2.sh` / `02.source_dhcp_pxe.sh` · 연동 `auto_setup`(별도 세션에서 진행)

## 1. 배경·목적

- awxkit 의 OS 설치년도 선택(1~5)만 다르고 스펙(infra·nic·disk·용량·os·boot·splunk)이 같은 서버는 지금 한 그룹(yml)으로 묶여 분리되지 못한다.
- `${user}.txt` 에 **선택 항목인 13번째 레코드**를 두고, 이 값이 다르면 yml 을 따로 나누도록 한다. 13번째 값은 **순수 분류용**이라 어떤 문자열이든 상관없다(예: `rhel810(TEST/SR)`, `/`·`(`·`)` 포함).

## 2. 확정 사항 (인터뷰 결과)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 13번째의 출처 | nodeinfo **N**(12필드를 직접 준비)에서만 지원한다. nodeinfo **Y** 는 항상 12필드만 나오므로 변경 없음 — 사용자가 Y 로 한 번 돌려 **Ctrl+C 로 중단하고**, 정렬된 `${user}.txt` 뒤에 13번째를 직접 붙여 N 으로 다시 실행한다 |
| 2 | 형식 | **공백 없는 한 단어** (필드 13개째). `( ) / , .` 등 어떤 문자도 허용. 14필드 이상은 오류 |
| 3 | 선택 여부 | 모든 줄에 있을 필요 없음. 13번째가 없는 줄은 "값 없음"으로 보고, 같은 스펙이라도 값이 다르면(있음/없음 포함) 서로 다른 그룹 |
| 4 | repohost 전송 | 분류에만 쓰고 **12필드로 잘라** 보낸다(`custom_inventory.sh` 불변). 13번째는 yml 에 들어가지 않는다 |
| 5 | 화면 표시 | 01 메뉴 `ls` 줄 끝, 02 옵션 확인표에 13번째를 표시(없으면 `-`) |
| 6 | `.job`(auto_setup 전달) | 그룹 줄 형식 **불변**(13번째 미포함) |
| 7 | 반영 | 랩(.58) 목업 E2E 통과 → master 커밋·푸시 → `awx-script-standalone` 갱신 |
| 8 | auto_setup | 이 세션에서 하지 않고 "HPC auto_setup 구현" 세션에 요구사항 전달: 신규 설치 `hostname ip mac [템플릿] [13번째]` → 템플릿 12필드 + 13번째를 붙인 **13필드 한 줄**을 `<user>.txt` 로 생성 |

## 3. 변경 설계

### 3-1. 01.AWX_nodeinfo_V2.sh

1. **[3] `parse_msg` 필드 검사**: `NF != 12` → `NF != 12 && NF != 13`. 오류 문구에 "12필드(13번째는 선택)" 안내.
2. **값 치환(`download_txt` 의 sed 3줄)**: 13번째에 `7T`·`test1234` 같은 글자가 있어도 변형되지 않도록 **1~12필드에만** 적용(13번째는 원문 유지).
3. **[8] `split_files`**:
   - `tag = (NF >= 13) ? $13 : ""` 를 구해 그룹 키 끝에 `|` + tag 를 추가(키 구분자 `|` 가 tag 에 있어도 키 충돌이 없도록 tag 는 맨 끝).
   - `groups` 파일에 tag 를 **마지막 필드(9번째)** 로 기록: `번호|infra|nic|disk|용량|os|boot|splunk|tag`.
   - 그룹별 `${user}_N.yaml` 과 `${user}_all.yaml` 은 **1~12필드만** 기록(13번째 제거) → scp 대상은 항상 12필드.
4. **[10] `gen_inventory`**: `groups` 읽기에서 9번째 필드(tag)를 `g_tag[$num]` 로 받는다(마지막 변수라 tag 안의 `|` 도 보존). 새 연관배열 `yml_tag[yml]` 에 저장. `yml_opt`(4개 값, 공백 구분)는 **그대로 둔다** — `as_group_lines` 가 `read -r i o b s` 로 읽으므로 5번째를 넣으면 깨진다.
5. **[13] 메뉴 `ls`**: `echo "${yml} [boot]"` 뒤에 tag 가 있으면 ` {tag}` 를 덧붙인다.
6. **[14] 02 호출 인자**: `yml=infra,os,boot,splunk` 뒤에 `,tag` 를 **마지막**에 붙인다(tag 가 있을 때만). 02 가 `read -r` 의 마지막 변수로 받으면 tag 안의 쉼표도 보존된다.
7. 불변 유지: `show_targets`·`dhcp_info`·`fix_mac`·`dns_check`·`check_servers`·`.job`·`verify_hosts`(모두 `$3..$6` 만 사용, `day_print` 는 `$3..$NF` 라 13번째도 자연히 출력).

### 3-2. 02.source_dhcp_pxe.sh

1. 인자 파싱: `IFS=, read -r f_infra f_os f_boot f_splunk f_tag` → 배열 `tags[]`.
2. `print_table`: 표 마지막에 `13번째` 열 추가(없으면 `-`). N 으로 재입력하는 경로는 tag 를 바꾸지 않는다(표시 전용).
3. dhcp/pxe/invsync 호출·`--all`·os6 재조사 등은 **변경 없음**(tag 는 호출에 쓰이지 않음).

### 3-3. 테스트(`test/run_tests.sh`) — 변경 부분만

- 신규 케이스(목업 E2E, 실제 01/02 실행):
  - 13필드(특수문자 `rhel810(TEST/SR)`·`a|b`·`x,y` 포함) 줄이 같은 스펙이어도 tag 가 다르면 **다른 yml 로 분리**되고, 같은 tag 는 한 yml.
  - 일부 줄만 13번째가 있는 혼합 입력(없음 vs 있음 = 서로 다른 그룹).
  - repohost 로 scp 된 입력 파일은 **모두 12필드**(13번째 없음).
  - `ls` 줄과 02 옵션 확인표에 tag 표시(없으면 `-`).
  - 14필드 → 오류 종료, 기존 12필드만 입력 → 종전과 동일(회귀).
  - 13번째에 `7T` 포함 → 변형 없이 유지.
  - `.job` 그룹 줄에 13번째가 없음.
- 기존 12필드 관련 어서션 문구(오류 메시지)만 새 문구에 맞게 수정.
- 랩 .58 에서 실행: 전체 PASS + shellcheck 0.

## 4. auto_setup 세션에 전달할 요구사항 (그 세션에서 구현)

- 신규 설치 양식 입력: `hostname ip mac [템플릿] [13번째]`.
- 템플릿에서 만든 **12필드 줄 뒤에 13번째 값을 붙인 13필드 한 줄**을 `<user>.txt` 로 만든다. 13번째를 쓰지 않으면 종전과 동일(12필드).
- 13번째는 공백 없는 한 단어이며 어떤 문자(`( ) / , |` 등)도 허용 — 분류에만 쓰이므로 값을 해석·검증하지 않는다.
- 화면(양식·목록)에는 "템플릿 + 13번째"로 표시한다.
- `.job` 그룹 줄은 바꾸지 않는다(01 이 13번째를 넘기지 않음).
- 01 은 13필드 `<user>.txt` 를 N(nodeinfo 사용 안 함)으로 읽는다 — auto_setup 이 nodeinfo 자동 답변을 `n` 으로 넘기는 경로와 호환된다.

## 6. 위험·주의

- 13번째가 `|` 를 포함해도 그룹 키가 깨지지 않도록 tag 는 키·`groups` 의 **맨 끝 필드**로만 다룬다.
- `yml_opt`(4값)를 확장하면 `as_group_lines` 의 `read` 가 깨지므로 tag 는 별도 배열로만 둔다.
- 13번째를 쓰지 않는 기존 사용은 어떤 출력도 달라지지 않아야 한다(표의 `-` 열 추가는 제외).
- 설정을 바꾸는 작업이므로 완료 후 임의의 서버 몇 대를 직접 확인한다(Disclaimer 유지).
