1. 개요 및 전체 수집 흐름

survey는 리눅스(RHEL) 서버 자산대장(표2) 항목을 수집하기 위해 표1(자산양식) 파일의 hostname 열 전체를 gossh로 병렬 조회하고, 판정 규칙을 적용해 엑셀에 바로 붙여넣을 수 있는 탭 구분 TSV 파일로 저장하는 도구입니다.

  • 단독 바이너리(./survey) vs 통합 래퍼(./run_survey.sh): ./survey만 실행하면 필터링·재조사 없이 conf/conf.toml의 asset_file을 그대로 조사합니다. ./run_survey.sh는 자산 필터링 → B 서버 전체 조사 → 타임아웃/접속불가 호스트의 A 서버 재조사 → 병합까지 한 번에 수행합니다.
  • 모든 호스트 1행 출력: 접속에 실패하더라도 표1의 모든 hostname이 1행씩 기록되며(실패 사유는 특이사항), 출력 파일 간 호스트 중복이 발생하지 않습니다.
text hostname상태위치) ↓ [run_survey.sh] [asset_filter] include/exclude 정규식 필터링 (설정 시) ↓ [B 서버] ./survey → gossh 병렬 조사 (1차: 설정값 auto.appl, 인프라망 infra_net + fallback binddn) ↓ [판정] ESXi(uname == VMkernel) 판별 → ev01~ev03 DNS 해석 가능 VM 2차 조사 ↓ [run_survey.sh] ([server_a].enabled=true 이고 타임아웃/접속불가 존재 시, DNS 미등록 제외) → 공유 dir/.resurvey.XXXXXX 생성 → ssh A "./survey-rhel6" 1회 재조사 → hostname 기준 병합 ↓ 최종 TSV 생성 (최대 3종, 호스트 중복 없음): - result_YYYYMMDD_HHMM.tsv (항상 생성) - result_vm_YYYYMMDD_HHMM.tsv (ESXi ≥ 1대이고 VM 행이 있을 때만) - result_sdc_YYYYMMDD_HHMM.tsv (인프라망 == SDC 호스트가 있을 때만 분리)]]>

2.3 A·B 서버 연동 사전 조건 (run_survey.sh 전용)

  • B 서버(전용)에서 전체를 조사하고, 타임아웃·접속불가로 남은 소수만 A 서버(공용, 일부 대상망 전용)에서 1회 재조사합니다(DNS 미등록 제외).
  • A·B 서버가 [server_a].dir 경로를 autofs 등으로 동일 절대경로로 공유해야 합니다.
  • 공유 디렉터리 안에 RHEL 6용 바이너리([server_a].bin, 예: survey-rhel6)와 conf/conf.toml이 함께 있어야 합니다.
  • B → A 간 [server_a].user(기본 root)로 패스워드리스 SSH가 가능해야 하며, A 서버에도 gossh가 설치되어 있어야 합니다(경로가 다르면 [server_a].gossh_bin 지정).

3.2 conf/conf.toml 전체 설정 키

섹션 / 키 샘플 기본값 설명
[input].asset_file "/root/HPC/조사/asset_list.txt" 표1 텍스트 경로 (탭 구분)
[gossh].bin "/usr/local/bin/gossh" gossh 실행 파일 경로
[gossh].concurrency 4000 gossh 동시 실행 수(-c). 설정값(appl) 조사에만 적용
[gossh].timeout 10 gossh 타임아웃 초(-t). 설정값·인프라망 조사 모두 적용
[gossh].retry_timeout 30 일반 서버 DNS 미등록/타임아웃 내부 재조사 시 사용할 긴 타임아웃 초 (VM 제외)
[gossh].extra_args "" gossh에 전달할 추가 플래그 (공백 구분)
[scripts].config_value "cat /etc/auto.appl | grep -v '#' | grep -w '/appl'" 설정값 조사 명령 (gossh ... -script "<값>")
[scripts].infra_net "/usr/local/bin/infra_survey.sh" 인프라망 조사 스크립트 경로 또는 명령 (gossh -w <hosts> -script "bash <값>"). 비우면 인프라망 열 공란
[scripts].infra_regex '^INFO\s+\S+\s+(\S+)' 인프라망 출력(여러 줄이면 줄마다 시도해 처음 매칭된 줄)에서 캡처 그룹 1 추출 정규식
[scripts].infra_fallback_cmd "cat /etc/openldap/ldap.conf | grep -i binddn" infra_regex 매칭 실패 또는 스크립트 미배포 시 재실행할 폴백 명령
[scripts].infra_fallback_regex 'uid=([^,\s]+)' 폴백 출력에서 값 추출 정규식 (미매칭 시 binddn 원본 줄 기록)
[[mountpoint]].name / .location nas-a / A센터 등 설정값 이름:/경로의 : 앞부분과 매칭할 정상 위치 (표1 위치와 비교)
[asset_filter].source / .include / .exclude "/root/HPC/조사/asset_list.txt" / "" (run_survey.sh 전용) 원본 표1을 egrep -E로 필터링해 [input].asset_file 생성
[server_a].enabled / .host / .user false / "a-server" / "root" (run_survey.sh 전용) true이면 타임아웃/접속불가 호스트를 A 서버에서 1회 재조사
[server_a].dir / .bin / .gossh_bin "/user/autofs1/조사" / "survey-rhel6" / "" A·B 공유 autofs 경로, A 서버용 RHEL6 바이너리명, A 서버의 gossh 경로

5. 판정 규칙 · 출력 컬럼 및 결과 파일

5.1 7개 출력 컬럼 (TSV)

컬럼 값 및 생성 규칙
1. hostname 표1의 hostname (또는 2차 조사된 VM 이름 <esxi>ev01~03)
2. 위치 표1의 위치 값 (VM은 소속 ESXi의 위치 상속)
3. 상태 표1의 상태 값 (VM은 소속 ESXi의 상태 상속)
4. 설정값 auto.appl에서 /로 시작하는 매칭 행의 마지막 필드(이름:/경로). 출력 없음이면 없음, 접속 실패 시 공란
5. 인프라망 infra_regex 또는 infra_fallback_regex 추출값. 값이 정확히 VIP이면 SLSI_VIP로 치환. ESXi면 없음, 실패 시 공란
6. appl설정유무 O([[mountpoint]].location == 표1 위치) / X(불일치 또는 mountpoint 미정의) / 없음(설정값 없음 또는 ESXi) / 공란(접속 실패)
7. 특이사항 접속불가, 타임아웃, DNS 미등록, gossh 실행 실패, mountpoint 미정의, 인프라 스크립트 없음, 인프라 확인필요(...), esxi

5.2 ESXi 및 VM 2차 조사 규칙

  1. 1차 조사에서 설정값 = 없음으로 나온 호스트에만 uname을 실행해 출력에 VMkernel이 포함되면 ESXi 물리장비로 판정합니다(설정값/인프라망/appl설정유무는 모두 없음, 특이사항은 esxi).
  2. ESXi 호스트마다 고정 규칙 <esxi_hostname>ev01, ev02, ev03 이름을 생성해 survey 실행 서버에서 직접 DNS(/etc/hosts 포함) 조회를 수행합니다.
  3. DNS에 해석되는 VM만 조사 대상에 포함하며(없는 ev03 등은 행 자체를 남기지 않음), 해석되지만 SSH 실패 시 접속불가로 남기고, 조사 가능한 VM이 하나도 없으면 ESXi 이름으로 접속불가 1행을 남깁니다. 타임아웃 VM은 1회 재조사합니다.

5.3 생성 파일 (최대 3개, 호스트 중복 없음)

파일명 생성 조건 및 내용
result_YYYYMMDD_HHMM.tsv 항상 생성. 표1 전체 호스트 조사 결과 (SDC 분리 대상 제외)
result_vm_YYYYMMDD_HHMM.tsv ESXi가 1대 이상이고 기록할 VM 행이 있을 때만 생성
result_sdc_YYYYMMDD_HHMM.tsv 인프라망 값이 정확히 SDC인 호스트가 있을 때만 생성 (타 결과 파일에서 이동)

6. 해석상 한계 및 주의사항

  • 참고용 보조 도구: 본 수집 도구는 100% 신뢰하기보다 참고용으로 활용하세요. 만약 설정 변경 스크립트를 함께 운용할 경우 변경 후 무작위로 몇 대의 서버에 직접 접속해 반영 여부를 검증해야 합니다.
  • 원격 셸 csh 호환성: infra_net은 bash <경로>로 실행되고 config_value/uname/binddn 명령은 csh에서도 동작합니다. 인프라망 값이 비거나 이상할 때는 셸 문제보다 infra_regex 패턴이 실제 스크립트 출력과 맞는지 먼저 확인하세요.
  • gossh 출력 형식 의존: 결과 파싱은 pdsh 형식(hostname: 결과)을 전제로 하므로 gossh 출력 포맷이 바뀌면 cmd/survey/collect.go의 parsePdshLine을 확인해야 합니다.
  • 엑셀 활용 팁: 생성된 TSV 파일 내용을 복사해 엑셀에 붙여넣으면 탭 구분으로 셀이 자동 분리됩니다.
